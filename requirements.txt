# 한 줄로 설치 (Python 3.12 · 저장소 맨 위 폴더에서):
#     python -m pip install -r requirements.txt
#   = 서버(base) + 시험·린트(dev). 서버 실행 · 시험 · 사용자 콘솔(final_project_ui)이 이것만으로 돈다.
#
# 목록은 requirements/ 폴더에 나눠 두고 여기서 묶는다. 판(버전)은 한 곳에서만 고친다.
#
#   requirements/base.txt                 서버 실행에 쓰는 것 — 웹 · DB · LLM · MCP · 파일 읽기 · 평가 통계. CI 가 이 판으로 시험한다
#   requirements/dev.txt                  시험(pytest) · 린트(ruff)
#   requirements/tools.txt        [선택]  브라우저 자동 조작 도구(playwright)
#   requirements/ml.txt           [선택]  로컬 분류 모델 · 요식 유사도 학습/추론(torch · transformers) — 용량이 크다
#   requirements/mobility-data.txt   [별도 환경]  이동 자료 수집·가공 기기 전용. ★여기와 같은 환경에 깔지 않는다(numpy 등 판이 다르다)
#   requirements/mobility-data.lock.txt   이동 담당 원본 pip freeze (옛 requirements-mobility.txt)
#
# 폴더별 진입점 — 경로는 그대로 두었다(CI · 문서가 쓴다):
#   final_project_cs/requirements.txt       base + dev 를 가리키는 얇은 파일. `cd final_project_cs` 뒤 `pip install -r requirements.txt` 도 같은 결과다
#   final_project_ui/requirements.txt       콘솔 전용(fastapi · uvicorn · psycopg 는 base 에 모두 있다). acop-composer-ui 는 경로로 깐다 — 그 파일 머리 참고
#   final_project_sample/requirements.txt   참고 구현체 + Docker 빌드용. Docker 빌드가 그 폴더 안만 보므로 따로 둔다(numpy 등 판이 조금 다르다)
#
# 이 환경에서 따로 깔아야 하는 것
#   acop_composer(설정 변경 관리 채널)는 pip 로 안 깔린다 — 소스가 final_project_sample/acop_composer/ 에 있다.
#   final_project_cs 폴더에서 실행할 때 PYTHONPATH 에 final_project_sample 을 붙인다(자세한 이유: final_project_cs/wiki/operations/local-setup.md).
#   PowerShell:   $env:PYTHONPATH = (Resolve-Path ..\final_project_sample).Path
#
# ★모든 requirements 파일의 첫 줄 `# -*- coding: utf-8 -*-` 은 지우지 않는다 — 한국어 Windows(cp949)의 pip 은 이 표시가 없으면
#   한글 주석을 못 읽고 UnicodeDecodeError 로 설치가 시작도 못 한다. 새 requirements 파일을 만들 때도 첫 줄에 넣는다.
#
# 선택 목록을 함께 깔려면 아래 줄의 # 을 지운다(또는 `pip install -r requirements/tools.txt` 처럼 따로 실행한다).
