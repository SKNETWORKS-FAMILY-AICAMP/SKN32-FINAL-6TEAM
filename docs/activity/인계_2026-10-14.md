## 6. 지켜야 할 규칙 (사용자 지시)

- 코어 코드와 wiki는 고치지 않는다. 코어 몫은 전달 문서로만 부탁한다.
- `.env` · `.env.apikeys`의 **값은 읽지 않는다**(코드가 로드만).
- OpenAI 실호출은 중요한 시험에만, 되풀이하지 않는다(10-13 「무조건 아끼자」). 지난 작업에서 임베딩 비교를 한 번에 세 모델로 돌린 것은 과했다.
- 보고서에는 **실측값만** 쓴다. 양식의 샘플 수치를 쓰지 않고, 안 잰 것은 「미측정/해당 없음」. sLLM 장은 쓰지 않는다.
- 보고서 작성 동안 코드를 더 바꾸지 않는다(보고서와 코드 일치).
- 쇼핑몰 시절 자료·코드·데이터는 재료로 쓰지 않는다.
- 규정을 이유로 지우거나 끄기 전에 사용자에게 먼저 묻는다.

## 7. 이어서 시작하는 법

1. `docker ps`로 `acop_db`가 떠 있는지 본다(없으면 Docker Desktop 실행 후 `docker start acop_db`).
2. `git status -sb`로 브랜치와 원격 일치 여부를 본다. 팀원이 먼저 push했으면 `git pull --rebase --autostash` 후 push.
3. 보고서를 다시 만들 때(숫자가 바뀐 경우):
   ```
   cd final_project_cs
   PYTHONPATH=. python ../docs/activity/산출물_작업/build_vectordb_report.py "<양식.docx>" "<결과.docx>"
   python ../docs/activity/산출물_작업/build_test_report_merged.py "<양식.docx>" "<팀원.md>" "<결과.docx>"
   ```
4. 시험 결과 JSON을 새로 만들 때: `pytest ... -m "not live" --junitxml=결과.xml` 실행 후 `python 산출물_작업/junit_to_json.py 결과.xml 산출물_작업/test_run_results_<날짜>.json` (보고서 스크립트가 읽는 파일 이름은 `test_run_results_2026-10-14.json`).
