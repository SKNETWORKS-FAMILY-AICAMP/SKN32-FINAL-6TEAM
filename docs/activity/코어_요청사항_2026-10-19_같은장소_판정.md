# 코어 협의 메모 — 같은 장소 판정 · 어순/오타 이름 찾기 (2026-10-19, 활동 팀)

> 활동 팀이 활동 코드 안에서 만든 것과, **코어(공유 파일)에서 정해 주셔야 켜지는 것**을 나눠 적습니다. 코어 파일은 고치지 않았습니다.

## 1. 증상 (테스트하면서 발견)

일정에 「N서울타워」와 관광공사의 「남산서울타워」가 **다른 장소**로 찍혀 같은 곳이 두 번 나온다.

접수 `resolve()` 를 카카오 좌표가 관광공사와 다른 가정으로 돌린 결과(가짜 카카오 · 관광공사 CSV):

| 입력 | 결과 |
|---|---|
| 남산타워 · 남산서울타워 · 서울타워 | 카카오 「N서울타워」 · `content_id=None` (별칭 `SEED_ALIASES` 가 모두 「N서울타워」로 바꾼다) |
| 엔서울타워 | 못 찾음 |

관광공사 정식 제목은 「남산서울타워」(contentid 126535)라 일정 장소가 원장 행과 **연결되지 않는다**. 활동 대체 후보는 원장에서 읽으므로 같은 곳이
다른 이름으로 또 나온다. ※ 카카오 키가 없는 환경이라 실제 카카오 응답의 이름 · 좌표는 확인하지 못했다(가정).

## 2. 활동 팀이 만든 것 (활동 파일만 — 이미 반영)

| 파일 | 내용 |
|---|---|
| `instances/activity/place_identity.py` (신규) | 같은 장소 판정: 규칙(`same`/`different`/`ambiguous`) → 애매한 쌍만 LLM → 프로세스 메모리 기억 |
| `instances/activity/replacement.py` | 「이미 일정에 있는 곳」 제외에 연결(`_drop_same_places`). 기본(`kind_modes` 에 없음 = `rule`)은 **LLM 을 부르지 않고**, 규칙이 같다고 한 것만 빼고 애매한 후보는 남긴다 + 경고 |
| `instances/activity/name_match.py` (신규) | 어순이 다른 이름 · 오타 비교 도구 (원장 · CSV 이름 찾기가 공용) |
| `db_search/place_by_name.py` · `place_lookup.py` · `csv_places.py` | `fuzzy=True` 로 어순 · 오타도 찾는다. **기본 꺼짐**(결과가 `needs_review`) |

판정 규칙: 같은 contentid 거나 정규화한 이름이 같으면 `same`. 300m 안이고 이름(공통 부분열 ÷ 짧은 이름)이 0.8 이상 닮았는데 이름이 다르면 `ambiguous`.
그 밖은 `different`. ★이름 유사도만으로는 가를 수 없다(실측: 백화점 입점 매장 22,274쌍이 0.8 이상 · 남산도서관/용산도서관 0.92 = 다른 곳,
남산서울타워/N서울타워 0.80 = 같은 곳). 그래서 규칙은 「물을 쌍을 좁히는 것」까지만 한다.

## 3. 코어에서 정해 주실 것 (이 중 하나도 안 해도 기본 동작은 안전하다)

1. **접수 쪽 별칭 값** — `intake/pipeline.py` `SEED_ALIASES` 가 「남산타워 → N서울타워」인데 관광공사 정식 제목은 「남산서울타워」다.
   값을 정식 제목으로 맞추거나, 카카오로 찾은 장소를 **좌표 · 이름이 가까운 원장 행에 잇는** 단계가 필요하다(일정 장소가 `source_content_id` 를 갖게).
   이게 풀리면 일정에 두 항목이 따로 들어가는 문제도 접수 단계에서 사라진다. 활동 쪽 제외 로직은 그 전의 안전망이다.
2. **LLM 판정을 켜려면** (`kind_modes.same_place: llm`):
   - `read_tools.ALLOWED_PROMPT_KEYS` 에 `activity_judge.same_place` 추가 + `prompts/activity_judge/same_place.v1.md` 프롬프트(활동이 작성 가능)
   - 상한 키 `travel.activity_judge.same_place_timeout_seconds` (지금은 `alternative_order_timeout_seconds` 를 빌려 쓴다)
   - 호출 예산 줄(`external_call_budget`)에 이 종류를 포함할지
   - 모델 입력은 이름 · 분류 · 거리(m)뿐이다(좌표 · 주소 없음). 실제 OpenAI 호출은 하지 않았다(시험은 가짜 LLM).
3. **영구 기억** — 지금은 프로세스 메모리(재기동하면 사라짐). 판정한 이름 쌍을 DB 에 저장하려면 표(마이그레이션)가 필요하다.
4. **어순 · 오타 이름 찾기 연결** — 접수의 관광공사 조회(`TourApiPlace.find` · `CatalogNames`)는 정확 일치뿐이다. 활동 원장 조회가
   `fuzzy=True` 를 받으므로 접수에서 못 찾았을 때 한 번 더 부르게 할 수 있다. 결과는 `needs_review` 로 다뤄야 한다.

## 4. 확인하지 못한 것

- 실제 카카오 응답(이름 · 좌표). 키가 없어 가짜 카카오로 재현했다.
- LLM 판정의 정확도(가짜 LLM 시험뿐 — 라벨 · 실호출 없음). 켜기 전에 라벨로 재야 한다.
- 일정 항목(`read.itinerary`)의 장소가 항상 좌표를 갖는지. 좌표가 없으면 이름이 같을 때만 같다고 본다.
