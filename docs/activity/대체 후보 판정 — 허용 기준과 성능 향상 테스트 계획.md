|---|---|---|---|
| F1 | **이유 문장 지어냄** — 장소 특성 추측 · 분류 오인 · 숫자 비교 오류 · 고객 말 뒤집기 | 고객 요청 26/155, 감시 2/58 | M5(전환 막음) |

### 2-2. 실험

한 번에 하나씩 바꾸고, 같은 dev 자료로 앞판과 견준다. 프롬프트 · 입력을 바꾸면 운영 판(v3)으로 DB 에 다시 등록한다.

| 실험 | 바꾸는 것 | 겨냥 | 판단 지표 | 성공 기준(dev) |
|---|---|---|---|---|
| **E1 분류 이름 넣기** | 입력 후보에 `class` 코드와 함께 **분류 이름**(「역사관광 > 궁궐」)을 싣는다(`candidate_rows`) | F3 · F1 · F5 | M1 · M5 분류 오인 수 | 분류 오인 0, M1 ≥ 앞판 |
| **E2 이유 규칙 강화(프롬프트 v3)** | 「이유는 후보 이름 · 분류 · 거리 숫자 · 설문 · 고객 문장에 있는 말만」, 「장소 특성 추측 금지」, 「거리 비교는 숫자로」, 「고객이 거부한 유형(말고 · 싫다)은 1순위로 두지 않는다」 | F1 · F4 | M5 심각 · 경미, C 묶음 위험 | 심각 0 · 경미 ≤ 5% · C 위험 ≤ 앞판 |
| **E3 받은 순서 지키기** | 프롬프트에 「`distance_km` 로 다시 정렬하지 말 것 — 취향 차이가 없으면 받은 순서 그대로」 · 또는 입력에서 `distance_km` 를 빼고 `code_reason` 만 둔다(두 판을 견줌) | F2 | 섞은 판 폐기 · M8 | 섞은 판 폐기 0 · M8 ≥ 60% |
| **E4 이유를 코드가 쓰기** | 모델은 `reason_basis`(쓴 근거: 설문 칸 · 고객 말 · 분류)만 고르고, 문장은 코드가 틀에 넣어 만든다 | F1 근본 해결 | M5 | 지어냄 0(구조상) · 사용자가 읽기에 자연스러운가 사람 확인 |
| E5 생각 깊이 | `activity_judge_reasoning_effort` low → medium | F1 · F4 | M5 · M1 · 지연 · 비용 | 지어냄 감소, p95 < 시간 제한 8초 |
| E6 첫 호출 데우기 | 실행 · 운영 시작 때 프롬프트 · 클라이언트를 미리 읽음, 또는 첫 호출만 시간 제한 여유 | F6 | 시간 초과 | 0 |

- 순서: **E1 + E2 + E3 를 v3 한 판으로**(셋 다 입력 · 프롬프트라 함께 바꿔도 지표가 겹치지 않는다 — F3 · F1 · F2 를 따로 센다) → 결과가 모자라면 E4 → 비용 여유가 있으면 E5. E6 은 평가 도구 · 운영 설정 일이라 따로 한다.
- E4 는 M5 를 구조로 없애지만 이유가 딱딱해진다. E2 로 경미 ≤ 5% 가 되면 E4 는 하지 않는다.

### 2-3. 자료 — holdout 을 다시 쓰지 않는다

지금 holdout 80 · 감시 21 은 **결과를 이미 봤다.** 그것으로 프롬프트를 고치면 과적합이다(계획서 3절 · [8]).

| 자료 | 무엇 | 만드는 법 | 쓰는 곳 |
|---|---|---|---|
| **dev 40**(계획서에 있던 몫) | 새 원래 장소 · 새 후보로 결합한 카드 + 템플릿 문장 · 설문만 판 | `bind_candidates.py` 로 holdout 과 겹치지 않는 원래 장소에서 결합 · 라벨은 Claude 제안 → 사람 확인 | E1 ~ E5 반복 |
| **확인용 holdout-2** | 새 카드 40 + 사람 문장(고객 요청) · 설문만(감시) | 작성자 2명 · 1회만 연다 | v3 최종 판정 |
| 기존 holdout v2 · 감시 v2 | 앞판 기준값 | 그대로 | v3 와 나란히 적는 참고(같은 자료라 「개선」의 증거로 쓰지 않는다) |
