> 코드 기준: `instances/activity/team.py`(`ActivityTeam.execute` · `_check_feasible`) · `replacement.py`(대체 후보) · `alternative_order.py`(LLM 순서) · `live_store.py`(웹 공지 저장값).

## 1. 유스케이스 다이어그램

```mermaid
flowchart LR
    C([고객])
    W([감시 작업])
    O([운영 담당자])

    subgraph A[Activity 에이전트]
        direction TB
        U1[성립 점검<br/>activity.check_feasible]
        U2[취소 가능 확인<br/>activity.check_cancelable]
        U3[변경 제안 · 대체 후보<br/>activity.propose_change]
        U4[일정 질문<br/>activity.itinerary_question]
        U5[일정 제출 안내<br/>activity.submit_itinerary]
        U6[일정 관리 · 재점검<br/>activity.itinerary]
        U7[고객 확인 질문<br/>실내외 · 운영 정보 모름]
    end

    C --> U1
    C --> U2
    C --> U3
    C --> U4
    C --> U5
    W --> U6
    U1 -. include .-> U7
    U1 -. 대체 후보 .-> U3
    U6 -. 대체 후보 .-> U3
    U1 -. 장소 모름 · 소스 실패 .-> O
    U6 -. 처리 못함 .-> O

    subgraph S[사용하는 것]
        S1[(장소 원장 DB)]
        S2[재난문자 · 기상]
        S3[웹 공지 저장값<br/>배치가 장소·날짜당 1회]
        S4[판정 LLM<br/>섀도]
    end
    U1 --> S1 & S2 & S3 & S4
    U3 --> S4
```

| 유스케이스 | 언제 | 하는 일 | 쓰는 것 |
|---|---|---|---|
| 성립 점검 | 고객이 「이 일정 가능해?」 · 예약 점검 | 시작됨 · 정원 → 재난 · 날씨 → 휴무 · 운영시간 → 웹 공지 저장값 → 모르면 질문 → 성립 | DB 원장 · 재난/기상 · 웹 공지 저장값 |
| 취소 가능 확인 | 「취소하면 위약금?」 | 예약의 취소 조건과 남은 시간으로 계산(금액은 근거 있을 때만) | 예약 조건 · 규정 |
| 변경 제안 · 대체 후보 | 「바꿔 주세요」 · 위 점검에서 문제 발견 | 변경 제안(승인 대기) + 대체 후보 3곳 | 관광공사 목록(DB) · LLM 순서 |
| 일정 질문 | 규정 · 일정 질문 | 규정을 읽어 답(면제 아님) | 규정 검색 |
| 일정 제출 안내 | 일정 제출 요청 | 일정을 만들지 않고 여행 접수로 안내 | — |
| 일정 관리 · 재점검 | 감시 작업이 연 Case · 지연/휴무/품절 신고 | 그 항목을 다시 점검하고 깨졌으면 대안을 계산해 제안 | 위와 같음 |
| 고객 확인 질문 | 실내외를 모르는데 야외 위험형 재난 · 운영 정보가 비어 있음 | 선택지로 묻고, 답으로 다시 판정 | `choices` |

## 2. 성립 점검 판정 플로우

```mermaid
flowchart TD
    S([코어가 Case 전달]) --> R[1. 예약 · 장소 읽기<br/>DB 도구]
    R -->|예약 없음 · 장소 모름| ESC[운영 담당자에게 넘김]
    R --> A[2. 이미 시작됨 · 정원 초과<br/>규칙]
    A -->|해당| NO[불가 답변]
    A --> D[3. 재난 · 날씨<br/>분류표 규칙, 모르는 문자는 LLM]
    D -->|막는다| CP
    D -->|실내외 모름 + 야외 위험형| Q
    D --> H[4. 휴무 · 운영시간<br/>DB 요일표 + 휴무 규칙]
    H -->|닫힘| CP
    H -->|운영 정보 비어 있음| Q
    H --> L[5. 웹 공지 저장값<br/>live_lookup, 읽기만]
    L -->|닫혔다 · llm 모드만| CP
    L --> OK([6. 성립 답변 + 경고 + 근거])

    Q[고객 확인 질문<br/>선택지] -->|고객 답| R
    CP[변경 제안 · 승인 대기]
    CP --> CAND[대체 후보<br/>코드가 10곳 → 화면 3곳]
    CAND --> ORD[LLM이 3곳 순서 + 1순위 이유<br/>실패 시 코드 순서]
```

## 3. 어디까지 켜져 있나

| 구성 | 상태 | 이유 |
|---|---|---|
| 규칙 · DB 판정(2 · 3 · 4) | **켜짐** | 기본 동작 |
| 판정 LLM(휴무 · 재난 · 실내외 · 순서) | `shadow` — 고객 답은 코드 판정 | 정확도 라벨 미측정. `.env` 의 `ACOP_ACTIVITY_JUDGE_MODE=shadow` 로 켜서 기록만 쌓는다 |
| 웹 공지 저장값(5) | 꺼짐 | 코어가 `live_lookup` 을 꽂고 배치를 돌려야 켜진다 |
| 대체 후보 LLM 순서 | `shadow` → 검증 뒤 `llm` | 후보는 코드가 고정, LLM 은 3곳의 순서만 |
