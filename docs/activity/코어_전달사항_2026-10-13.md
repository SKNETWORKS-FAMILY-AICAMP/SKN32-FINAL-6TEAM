## 1. 저장된 실시간 운영 상태 읽기 함수를 꽂아 주세요

- **지금**: 웹 공지로 확인한 임시휴무 · 폐업은 장소 · 날짜당 한 번 배치가 `activity.ac_live_status`(마이그레이션 `304`)에 저장한다. 고객 요청은 웹을 부르지 않고
  `ActivityTeam.live_lookup` 으로 읽기만 한다. **그 함수가 꽂히지 않으면 이 확인은 꺼져 있고 경고도 없다.**
- **활동 쪽 준비됨**: `instances/activity/live_store.py` — `build_lookup(connection_factory)` 가 `(tenant_id, place_id, 방문 날짜) -> 저장된 값 | None` 을 돌려준다.
- **제안**(`judge_budget` 을 꽂는 자리 옆, `app/composition.py` `build_registry` — 회신 7번 때와 같은 방식):

```python
from app.domains.travel_ops.instances.activity import live_store
...
if hasattr(team, "live_lookup"):
    team.live_lookup = live_store.build_lookup(get_connection)
```

- 시험 환경(`tools` 를 주입한 조립)에서는 꽂지 않는다 — 판정 LLM 과 같은 이유로 운영 조립에서만.

## 2. 웹 확인 배치를 돌릴 시간을 정해 주세요

- **배치**: `python scripts/activity/check_live_status.py` — 앞으로 `travel.activity_judge.live_status_within_hours`(72시간) 안에 시작하는 활동 일정 항목의 (장소, 날짜)만 확인한다.
  6시간 안에 확인한 곳은 건너뛰고, 웹 예산이 다 차면 멈춰 남은 곳을 출력한다. `--dry-run` 은 웹을 부르지 않고 대상만 센다.
- **요청**: 코어의 15시 정기 점검 직전(활동 판정이 그 점검에서 불리는 흐름이면 가장 신선하다) 또는 `catalog_hours` 와 같은 새벽 창에 실행해 주세요.
  어느 쪽이 코어 일정과 맞는지는 코어가 정해 주세요.
- 켜는 조건: `kind_modes.live_status` 가 `rule` 이면 배치가 돌지 않고, 전역 `ACOP_ACTIVITY_JUDGE_MODE` 가 `rule` 이면 판정 LLM 이 없어 아무것도 하지 않는다(3번).

## 3. 판정 LLM 을 켜 주세요(섀도)

- 전역 `ACOP_ACTIVITY_JUDGE_MODE` 의 기본이 `rule` 이라 **지금은 어떤 LLM 도 불리지 않는다.** `shadow` 로 두면 비교 기록이 쌓이고 고객 답은 그대로다.
- 종류별 기본(`guardrails.yaml travel.activity_judge.kind_modes`): `closure` · `weather_sensitive` · `disaster_effect` · `live_status` · `alternative_order` 는 `shadow`, `operating_hours` 는 `rule`.
- `llm`(고객 답에 쓰기)은 정확도 라벨을 잰 뒤에 올린다 — 코어 회신 9 · 11번과 같다.

## 4. 고객의 실내 · 야외 답을 저장할 곳

- **지금**: 활동은 질문에 선택지(`choices`)를 붙이고, 재개 때 `customer_input` 이 선택지와 같으면 그 값으로 다시 판정한다(회신 5번). 그 Case 안에서만 쓴다.
  팀은 DB 에 쓸 수 없어 **저장되지 않는다** — 같은 장소로 다른 Case 가 열리면 다시 묻는다.
- **활동 쪽 준비됨**: `ac_indoor` 에 `decided_by='customer'` 로 쓰는 `indoor_store.record(conn, content_id, outdoor, 'customer')`. 읽기 우선순위는 operator > customer > llm > class.
- **요청**: 팀 결과의 `decisions[].indoor = {"value": …, "source": "customer"}` 를 코어가 재개 완료 뒤 `indoor_store.record` 로 쓸지, 활동이 받는 쓰기 도구를 둘지 정해 주세요.
  쓰기 도구는 `allowed_tools` · 승인 경계에 걸리므로 코어 몫으로 본다.
