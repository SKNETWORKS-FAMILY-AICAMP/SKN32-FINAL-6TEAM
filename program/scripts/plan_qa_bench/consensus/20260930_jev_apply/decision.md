# 결정 기록 — 일정 질문 인식에 Jev·앙상블·평가 방법론을 어떻게 적용할 것인가 (2026-09-30)

**정한 것**: 일정 질문 인식 단계의 설계 후보(A~F) 선택과 확정 전 실험 순서.

**결론**
- **기본 설계(확정 후보) = A**: 화면 버튼 문구·날짜·시간대·종류는 규칙이 먼저 읽고, 로컬 Gemma 4 26B 가 일정 목록에서 **항목 번호만** 고르며, 규칙으로 되확인한다. 못 찾으면 「못 찾았다 + 일정 요약」. 답 값은 DB 에서만 읽는다.
- **Jev**: 확정 전에 한국어 **실제 스타일 보류 세트**에서 규칙·A 와 쌍 비교. 통과하면 A **다음 재확인·기권 층**(C)으로 추가. 탈락 조건 = 오지목 증가 · 개인정보를 가린 뒤 성능 하락 · 약관·보관 조건 확인 불가.
- **로컬 다중 모델 합의(D)**: 채택하지 않음(이 표본에서 이득 없음 — 아래). 실제 스타일 세트에서 오지목이 기준을 넘으면 되돌아볼 레버로 보관.
- **로그확률 기권(E)**: 실험 후보로 유지(추가 비용 0에 가까움).
- **증류(F)**: 서비스 서버 GPU 에서 지연·팀당 비용이 한도를 넘을 때 사용.

**합의 방식**: 1회차 일치. Codex 는 `A`, Claude 는 `C`(로컬 기본 + Jev 시험 후 층 추가)로 적었으나 내용은 같다 — 기본은 A, Jev 는 시험 통과 시 층으로 추가. 서로의 `risks` 에 막히는 것이 없다.

**두 입장 요약**
- Codex: A 를 확정 후보로, Jev 는 실제형 보류 세트에서 규칙·A·Jev 를 쌍으로 비교한 뒤 결정. 판정은 오지목 최우선. 서비스 GPU 에서 50항목 p95 지연·동시 요청 비용을 재고 팀당 기계 비용 10,000원·사람 1건 15분 안에서만 확정.
- Claude: 같은 방향. 추가로 오프라인 앙상블·로그확률 기권을 저렴하게 먼저 재고, 판정 기준을 사전에 고정할 것을 제안.

**Claude 가 바꾼 점(Codex 가 짚은 사실이 맞아서)**
1. **0/90 오지목 ≠ 1% 미만.** 오류 0건일 때 95% 상한은 3/N 이라 N=90 에서 3.3%. 「엉뚱한 답 ≤1%」를 주장하려면 N≈300 이 필요하다(계산으로 확인). Claude 초안의 「엉뚱한 답 0~1%」 기준은 N 을 못 박지 않아 약했다.
2. **사람 라벨링 시간은 평가 비용으로 따로 기록**하고 운영 한도(팀당 사람 1건·15분)와 섞지 않는다.
3. Jev 의 250ms 와 26B 의 8.7초(16GB 서버)는 **실제 배치 성능이 아니다** — 서비스 GPU 에서 50항목 p95 를 다시 잰다.
4. Jev 확률(probability·margin·auto/review)은 **ECE 또는 확신 구간별 오지목률을 확인한 뒤에만** 문턱으로 쓴다.

**기각한 Codex 근거**: 없음.

**남은 반대 의견**: 없음. Codex 는 「가림 입력으로 평가한 Jev 가 보류 세트에서 오지목을 늘리지 않으면서 못 찾음을 줄이고 한도를 만족하면 C 로 바꾼다」를 `would_change_if` 로 명시했다.

**Claude 가 합의 뒤에 확인한 사실(오프라인, 비용 0)**: 저장된 모델 번호로 다중 합의를 재계산(같은 90문항, 1회, 모델 선택이 이 90문항 성적에 기댄 낙관적 값).
26B + 규칙 되확인 86/90·오지목 0·못 찾음 4 ↔ 26B·12B 같을 때만 85/90·0·5 ↔ 3모델 2표 88/90·0·2 ↔ 4모델(+gpt-oss) 92%. → 합의는 오지목을 이미 0 으로 만든 A 위에 얹어도 2문항 차이라 **이득이 표본 오차 안**이고 비용은 2~3배(Qwen3.8 은 45초/질문). 그래서 D 는 채택하지 않는다. 약한 모델을 섞으면 오히려 나빠지는 것은 yok3x fork 의 관찰(전부 섞으면 감성 93.0 < 상위 6개 94.8)과 같은 방향.
