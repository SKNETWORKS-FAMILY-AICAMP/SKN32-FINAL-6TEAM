# 질문: 「12B 는 소형이 아니다」 — 소형(≤4B 활성) 전문가만으로 Gemma 4 26B 급 정확도를 내려면 무엇을 해야 하나

파일을 만들거나 고치지 마라. 명령은 읽기만. 한 번에 답하라. 사실표와 어긋나는 주장은 근거를 대라. 이 밖의 저장소 파일은 읽지 마라(필요한 사실은 아래에 모두 넣었다).

## 정할 것 (한 문장)
사용자 지적: 지금 구조가 결국 12B(밀집 11.9B) LLM 을 호출하므로 「소형 조합」이라 부르기 어렵다 — **4B 재평가·규칙(코드)·E4B 정도만으로** 26B 급 정확도를 내야 의미가 있다. 이 목표를 **A~F 중 어떻게 추구할지**(또는 목표를 어떻게 다시 정의할지) 정하라.

## 선택지 (빠진 것이 있으면 `OTHER:` 로 제안)
- **A**: 지금 구조에서 12B 를 E4B 로 교체만 한다(아래 수치).
- **B**: E4B 를 **짚기 전용으로 LoRA 미세조정**(합성 자료 6.4만 쌍이 이미 있음. 재평가 모델 학습은 정확도를 못 올렸지만 확신도는 개선했다).
- **C**: 재평가·규칙으로 후보를 상위 5~10개로 줄이고 E4B 가 **그 목록 안에서만** 고르게 한다(재현율@10 이 86~93% 라 상한이 낮아진다).
- **D**: E4B 가 문장에서 조건(날·순서·끼니·앞뒤·기준 항목)을 뽑는 「질문 계획」을 한 번 호출하고 코드가 실행한다(규칙이 못 읽는 표현용).
- **E**: 12B 를 유지하고 「상주 메모리 절반·LLM 호출 12~14%」를 성과로 주장한다.
- **F**: 「26B 를 이긴다」를 포기하고 목표를 「26B −3%p 이내 정확도를 활성 4B 이하로」로 재정의한다.

## 제품 제약 (사용자 결정 — 바꿀 수 없음)
1. 합의·투표 금지(여러 모델의 일치 여부로 정하지 않는다). Jev(유료)는 사용자가 요청할 때만. 26B 는 기준선일 뿐 쓰지 않는다.
2. 모델은 값(시각·장소)을 만들지 않고 항목 번호만 낸다. 답은 DB 값 + 문장 틀.
3. 서비스 GPU 사양 미정. 실험 서버 GPU 16GB. 최종발표 2026-10-26(약 26일).
4. 실제 고객 표본 0개(팀원이 친 132문장은 라벨 없음). 시험 세트는 모두 합성이고 문장·규칙·일정을 같은 사람(Claude)이 썼다. 학습 자료는 Codex 가 썼다.

- 「구조」= 절 분석(말고·요청 둘) + 규칙 자리표 + 관계 조회 코드(모델 호출 0). 순서·상대 위치·날·끼니·부정·요청 둘 유형은 코드가 풀고, 앞 대화 문제는 LLM 몫.
- 유형별(176문제 중 유형당 16) 26B 대비: 구조가 이긴 유형은 요청 둘(+6)·일정 밖(+2)뿐(설계 덕), 나머지 9유형은 26B ≥ 소형.
### 그 밖에 측정한 것
- 재평가/검색 모델 제로샷 1위 정확도 69~76%, 후보 재현율 @5 81~90% · @10 86~93%. 원 점수 기준 「없음」 판정: 재평가4B 는 정답 없음을 18/19·18/18 잡고 맞는 답의 14~16% 를 잘못 거름.
- 학습시킨 재평가0.6B: 합성 검증(학습에서 뺀 장소) 93.9%, 사람이 쓴 세트 재현율 72~73%(제로샷과 거의 같음), 대신 확신도가 뚜렷해져 넘김 비율 45% → 14%. 이름 기반 유형 85문제 정답: 학습 0.6B 76 · 제로샷 0.6B 74 · 제로샷 4B 78.
- 알려진 오류 원인: 검증 전문가(12B)가 정확한 이름도 거부하는 오탐, E4B 기준 항목 오류(「먹어」에 끌림), 관문이 앞 대화 대상 무시, 「N번째 방문」·같은 장소 형제 항목 규칙 미구현.
- 재평가(교차) 모델은 질문당 항목 51개를 따로 계산해 0.6B ≈ 4.3 B·k토큰, 4B ≈ 28 B·k토큰(추정), 26B 직접 ≈ 6.0. 임베딩(양방향) 판 학습 재시도 중.

## 확인 못 한 것
- 처음 보는 새 세트에서의 성능(mix4 는 이미 여러 번 봄), 반복 편차, 실제 고객 표현, 서비스 GPU 에서의 속도·메모리.
- E4B 짚기 LoRA(B)·후보 제한 목록(C)·질문 계획(D)의 효과 — 아직 안 재봄.
- E4B 의 실제 GPU 상주 메모리(파일 9.6GB 중 층별 임베딩을 CPU 에 둘 수 있는지).
