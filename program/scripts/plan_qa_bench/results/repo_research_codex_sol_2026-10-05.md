**지금 당장 할 수 있는 작은 실험 3개**

1. **여행 기억 조회, 반나절:** Postgres에 여행별 `선호 / 이전 문의 / 이미 알린 사건` 샘플을 넣고, 고객 질문 10개에 필요한 기록만 붙이는 작은 조회 경로를 만든다. 다른 여행 기록이 섞이지 않고, 중복 알림 사례 10개를 모두 걸러내면 성공이다. Hindsight 도입 여부는 이 기준선과 비교한다.
2. **Case 실행 타임라인, 반나절:** 기존 감사·Case·outbox 데이터를 한 Case ID로 묶어 운영 화면 한 장에 `감지 → Team 판정 → Case 전이 → 배달 시도`를 표시한다. 사건 하나의 현재 상태와 알림이 안 간 이유를 화면에서 바로 찾을 수 있으면 성공이다.
3. **Next.js 화면 검사, 반나절:** 여행계획서 링크와 운영 화면의 대표 화면을 Impeccable `audit`로 점검하고 모바일 폭·긴 한국어 문장·빈 값·실패 상태를 브라우저에서 확인한다. 재현 가능한 문제 목록과 수정 전후 화면을 남기고, 심각한 가독성 문제가 해소되면 성공이다.

**반영하지 않는 편이 나은 것:** Paperclip 전체 Control Plane과 사람 승인 체계, Hindsight를 규정·영업시간의 진실 공급원으로 쓰는 방식, 금융 서비스의 유료 MCP 커넥터, 전체 학습 커리큘럼 일괄 수강, VoiceStudio 도입은 이번 범위에서 제외하는 것이 좋습니다. 각각 기존 Core와의 중복, 오래된 기억의 오류, 업무 불일치·비용, 남은 일정, 실행 환경 제약이 큽니다. 특히 **VoiceStudio라는 이름의 다른 저장소도 검색되므로** 음성 검토를 다시 할 때는 저장소 소유자와 라이선스를 먼저 확정해야 합니다.
