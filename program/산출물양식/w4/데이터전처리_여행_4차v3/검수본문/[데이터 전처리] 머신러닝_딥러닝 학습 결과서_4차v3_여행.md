개요
코어(진입·분류 층)
목표 : 고객 메시지 분류(요청 종류 5종·문제 코드 17종)를 로컬 모델로 수행할 수 있는지 검증하고, 고객 계획 읽기에 쓸 모델·방식을 정한다
문제 정의 : 여행 고객 메시지 한 건에 대해 요청 종류 5종과 문제 코드 17종을 예측한다(제품의 문제 코드는 18종, 제출 모델은 17종). 계획 읽기는 사진·파일을 값과 근거가 붙은 일정 항목으로 바꾼다
사용 프레임워크 : scikit-learn, PyTorch, Hugging Face Transformers, Ollama(교사 라벨·계획 읽기)
라벨 지침은 2026-09-17.v2에서 2026-09-22.v3으로 바뀌었다. booking_revert_request(이미 바꾸거나 취소한 예약을 되돌려 달라는 요청)가 더해져 제품의 문제 코드는 18종이지만, 학습 데이터와 제출 모델은 v2의 17종 그대로다. 2026-09-17 이후 재학습은 없다. 로컬 학습 모델은 어댑터와 계약 시험까지 구현했고 제품 분류 조립에는 연결되지 않았다. 제품의 인라인 분류는 Gemma 4 12B(Ollama)가 맡고, 없으면 OpenAI를 쓴다(2026-09-28 코드 확인).
이동 에이전트(mobility)
목표 : 시간표를 보지 않고 입력 특징만으로 이동 판정(성립·불가·근거없음)을 배울 수 있는지 대조한다. 판정 경로에 ML을 넣을지 정하는 근거다
문제 정의 : 특징 27개에서 현행 판정을 맞히는 분류. 데이터는 자기점검 탐침 8,648건(라벨은 현행 판정), 구간 단위 GroupKFold 5폴드 x 시드 5
사용 프레임워크 : scikit-learn(logreg, HistGradientBoosting, MLP), numpy
요식업 에이전트(dining)
목표 : 대체 식당 추천에서 「비슷한 곳」을 태그 규칙보다 잘 고를 수 있는지 시험한다
문제 정의 : 같은 가게의 두 모습(상호+대표메뉴, 취급메뉴)을 짝으로 놓고 가까이 끌어당기는 대조학습으로 문장 임베딩을 미세조정한다. 정답 라벨이 없어 사람 판정은 별도 시트로 받는다
사용 프레임워크 : PyTorch, Hugging Face Transformers(AutoModel, 평균 풀링, 최대 96토큰), intfloat/multilingual-e5-small, 스크립트 ml/dining_similarity.py
액티비티 에이전트(activity)
액티비티 팀 전용 학습은 찾은 범위(team/role-activity 저장소 코드·문서) 안에서 못 찾았다. 저장소 공통 분류 모델(위 코어)의 의도 라벨에 activity 4종이 포함될 뿐이다.

2.3 실험 파이프라인
코어 · 분류
같은 과제·같은 실험판의 후보 모델은 동일한 검증·시험 조각과 seed(7)를 사용했다. 전체판은 실제 글 학습 조각에 합성 문장을 더했다. 인코더는 NVIDIA RTX 5090 32GB 공유 GPU 서버(학습 프로세스당 GPU 메모리 7GB 상한)에서 bfloat16 자동 혼합정밀도로 학습했다(ml/train_labels_gpu.py).
선정 규칙: 기준선을 포함한 후보 가운데 검증 조각 교사 일치도가 가장 높은 모델을 고른다. 인코더의 검증 점수는 저장한 모델인 마지막 에폭 기준이며, 에폭 중간의 최고점 체크포인트는 저장하지 않았다. 점수가 같으면 더 단순한 기준선을 택한다. 시험 조각은 선정이 끝난 뒤 성능 보고에만 쓴다. GPU 처리량은 실행 결과 JSON에 기록된 참고값이며, 같은 GPU를 쓰던 다른 프로세스의 동시 실행 조건은 통제하지 않았다.

3.2 과적합 · 과소적합 관리 및 개선 방향
코어 · 분류
요청 종류·문제 코드의 첫 판(빈도 역수 가중 상한 20, 4에폭)에서 문제 코드 인코더가 다수 라벨을 거의 예측하지 않고 검증 점수가 기준선보다 크게 낮았다. 학습 손실이 계속 내려가던 점을 근거로 과소적합과 과한 가중을 원인으로 보고, 제곱근 가중(상한 5)·8에폭·배치 16으로 조정했다(문제 코드 A.X 검증 0.3333에서 0.7383, 요청 종류 A.X 검증 0.7980에서 0.8344). weight decay 0.01과 기울기 절단 1.0은 학습 스크립트의 고정값이다.
요청 종류·문제 코드는 교사 라벨의 오류가 그대로 학습되므로, 사람 검수 표본으로 교사 라벨의 정확도를 재는 것이 다음 과제다. 2026-09-28 기준 사람 검수 라벨은 0건이고, 팀 브랜치의 홀드아웃 자료는 템플릿이다.
다음 과제: v3 지침(18종)으로 다시 라벨을 붙여 재학습, 사람 정답 홀드아웃 확보, 로컬 모델을 제품 분류에 연결할지 결정(현재 미연결), 여행 도메인 감정 학습 데이터 확보(미확보).
코어 · 계획 읽기
값 변조 3.4%(12/350)가 목표 0에 못 미쳤다. 전부 사진·스캔 받아쓰기의 글자 오독이며, 반쪽 받아쓰기 검사는 빠진 줄만 잡고 바뀐 글자는 못 잡는다. 놓친 10개 중 6개가 한 이름(긴 가게 이름)이다. 후보는 전체·반쪽 받아쓰기가 서로 다른 줄을 확인 필요로 표시하는 것과 장소 조회로 고친 이름을 제목 옆에 보이는 것이며, 해 보지 않았다. 사람 라벨 평가셋과 실제 사진 평가는 아직 없다.
이동 에이전트(mobility)
HGB가 지하철(0.992)은 잘 맞히지만 버스(0.405)는 못 맞힌다. 근거없음을 성립으로 잘못 바꾸는 오류가 남는 것이 미채택의 이유다. 판정은 코드와 시간표 조회를 유지하고, 소요시간 추정에는 통계 프로파일을 썼다.
요식업 에이전트(dining)
분류 일치는 대리 지표다(분류도 같은 메뉴에서 규칙으로 뽑았다). 「대체 가능한가」에 대한 사람 판정 시트 237행(시험 40곳 x 이웃 3곳)은 아직 비어 있어 방법별 적합률을 내지 않는다. 시험은 1회이고 신뢰구간이 없다. 제품에는 적용하지 않았고, 사람 판정을 채운 뒤 정한다.
