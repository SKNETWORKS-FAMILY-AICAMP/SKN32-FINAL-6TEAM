모델 개요
제출 모델, 시험·비교 모델, 제품에서 쓰는 모델을 구분해야 한다. 제출 모델은 아직 제품 분류에 연결되지 않았다.
표 1. 팀별 모델 현황

| 팀 | 모델 | 유형 | 적용 상태 |
|---|---|---|---|
| 코어 | kf-deberta-base 2종(요청 종류·문제 코드) | 제출 학습 모델 | 제품 미연결(어댑터·계약 시험까지) |
| 코어 | Gemma 4 12B, bge-m3 | 학습 없이 쓰는 모델 | 제품 사용(분류·계획 읽기·규정 검색) |
| 이동 | HistGradientBoosting v1·v2 | 시험·비교(미채택) | 판정 경로에 없음 |
| 액티비티 | 없음 | 해당 없음 | 전용 학습 없음(팀 저장소 검색 범위) |
| 요식업 | multilingual-e5-small 미세조정 | 시험 모델 | 제품 미적용, 파일은 저장소 밖 |

담당 태스크 : 로컬 분류 시험(요청 종류 5종·문제 코드 17종, 제품 18종), 요식 대체 유사도 시험, 이동 판정 대조 실험
로컬 학습 모델은 어댑터와 계약 시험까지 구현했고 제품 분류 조립에는 연결되지 않았다. 제품의 인라인 분류는 Gemma 4 12B(Ollama)가 맡고, 없으면 OpenAI를 쓴다(2026-09-28 코드 확인).

제품 분류는 app/composition.py의 build_classifier가 조립하며 로컬 모델을 연결하지 않는다(2026-09-28 코드 확인).
2.2 입 · 출력 스펙
모델을 부르려면 아래 입력을 주고 반환값을 받는다. 분류 모델의 어휘 밖 출력은 분류 실패로 처리한다.
표 3. 입 · 출력 스펙

| 모델 | 필드 | 타입 · shape | 설명 |
|---|---|---|---|
| 분류 모델 | text | str, 메시지 1건 | 마스킹된 고객 입력 |
| 분류 모델 | input_ids | int64, [1, 최대 96] | 인코더 토크나이저 출력 |
| 분류 모델 | score / probability | float32, [1, 라벨 수] | 인코더 logits(요청 종류 5, 문제 코드 17) |
| 분류 모델 | label, confidence | str, float(1개, 0~1) | 제품 어휘 라벨과 최대 확률 |
| 요식 e5 | text | str, 가게 한 곳의 한 모습 | 상호+대표메뉴 또는 취급메뉴 |
| 요식 e5 | embedding | float32, [1, 384] | 평균 풀링 뒤 정규화한 벡터 |
| 이동 HGB | features와 label | float / str, [1, 27]과 1개 | 성립·불가·근거없음 |

e5-small의 차원 384는 공개 모델 설정(hidden_size 384, 2026-09-28 조회)의 값이다. 학습된 파일은 요식 담당 작업 PC의 datasets/ml/dining_sim/에 있고 이 저장소와 이 PC에는 없다.
