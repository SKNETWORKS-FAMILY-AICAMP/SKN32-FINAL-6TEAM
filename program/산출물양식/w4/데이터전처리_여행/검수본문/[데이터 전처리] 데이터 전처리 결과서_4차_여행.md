전처리 개요
전처리 목적 : triPilot의 분류 모델 학습·평가 데이터와 고객 계획 운영 입력을 정제하고, 장소 조회 및 이동 시간표의 근거를 관리한다
전처리 범위 : 기존 감정·요청 종류·문제 코드 학습 데이터, 고객 계획 읽기, 외부 장소 처리, 이동 팀 시간표 전처리
사용 도구 : Python 3.12(csv, json, re, unicodedata, hashlib), scikit-learn, 제품 개인정보 마스킹 모듈, Ollama Gemma 4 12B(교사 라벨), python-docx(docx), openpyxl(xlsx), PyMuPDF(fitz, PDF), Pillow(사진), Ollama gemma4:12b(사진 받아쓰기·남은 줄 원문 인용, 온도 0·생각 끔), 관광공사·카카오 장소 조회 API
원천 데이터 분석
2.1 데이터 출처 및 현황
팀 A-COPilot이 만드는 여행 운영 서비스 triPilot의 데이터 전처리와 분류 모델을 다룬다. 기존 학습 데이터는 유지하고 운영 입력과 이동 팀 보고를 함께 정리한다.
라벨 지침은 2026-09-17.v2에서 2026-09-22.v3으로 바뀌었다. booking_revert_request가 추가되어 제품 문제 코드는 18종이지만, 학습 데이터와 제출 모델은 v2의 17종 그대로다. 2026-09-17 이후 재학습은 없다. 취소와 되돌림을 구분하려면 v3 지침으로 다시 라벨을 붙이고 학습해야 한다(ml/label_with_gemma.py, 커밋 36cc1b99).
고객 계획은 글·사진·PDF·docx·xlsx를 받는다. 파일 종류는 바이트로 가리며 파일 5개·10MB·글 20,000자 한도를 적용한다. 값마다 rule·llm_span·lookup·customer 방법과 원문 위치 또는 조회 출처를 남긴다(계획 읽기 API 문서).
이동 팀 보고(2026-09-16) 기준이다. 팀 브랜치 team/role-mobility의 docs/mobility/2026-09-16_Mobility_데이터전처리결과서_v2.md 및 2026-09-16_Mobility_ML학습결과서_v1.md를 인용하며 이번 문서 작성에서 재실행하지 않았다.
이동 팀 수집 규모는 지하철 시간표 463,326행 중 판정 대상 444,915행, 출발 없음 18,411행이다. 공항 리무진 8,949행·180노선, 시내버스 717노선·정류장 41,820행, 역 순서 777간선·793역, 환승 도보 213쌍·74역, 혼잡도 65,169행, 공휴일 46일이다(이동 팀 보고, 2026-09-16).
감정 데이터는 네이버쇼핑 리뷰 공개 말뭉치(Public Domain, 수집 보고서에서 라이선스 확인) 199,908건이다. 별점 1·2점은 부정, 4·5점은 긍정으로 라벨이 붙어 있고 원 말뭉치에 3점(중립)은 없다. 수집 단계에서 원문 중복 92건을 뺀 판을 입력으로 썼다.
요청 종류·문제 코드 데이터는 공정거래위원회 소비자상담 공개 데이터 2종(온라인 상거래, 지역별) 1,236,805행에서 항공·해외여행·숙박·공연·외식·철도·버스 등 여행 서비스 18개 품목을 허용 목록으로 적용했고, 실제로 데이터가 있던 품목은 16개였다(렌터카, 자동차대여는 해당 데이터 0건). 사용한 공정위 공개 데이터에는 제품 라벨 어휘(요청 종류 5종, 문제 코드 17종)가 없어 교사 모델(Gemma 4 12B)로 라벨을 붙였다.
평가 전용 데이터는 팀 확정 시나리오와 같은 성격의 여행 문장이다(감정 41건, 요청 종류·문제 코드 51건). 학습에는 쓰지 않았고, 라벨은 작업 세션에서 부여했으며 사람 검수는 하지 않았다. 따라서 방향 확인용으로만 쓴다.

3.1 학습 / 검증 / 테스트 분할
분할 기준 : 라벨 기준 층화 추출(seed=7). 요청 종류·문제 코드는 라벨별 8:1:1, 3건 미만 라벨은 학습에만 둔다
감정은 학습 159,913건, 검증 19,988건, 시험 19,988건이고 세 조각의 부정·긍정 비율이 모두 0.50이다(소수 둘째 자리 반올림). 요청 종류는 학습 4,859건, 검증 604건, 시험 604건이며 시험 조각은 실제 사건제목으로만 구성한다(합성 문장 제외).
