| 머신러닝 / 딥러닝 모델 학습 (ML / DL Training) |

개요
목표 : 고객 메시지 분류(요청 종류 5종·문제 코드 17종)를 자체 학습 모델로 할 수 있는지 검증하고, 이동 판정과 요식 대체 추천에 학습 모델이 도움이 되는지 비교한다
문제 정의 : 코어는 메시지 한 건의 요청 종류와 문제 코드를 예측한다. 이동은 입력 특징만으로 현행 판정을 맞히는지, 요식은 비슷한 식당을 태그 규칙보다 잘 고르는지 본다
사용 프레임워크 : scikit-learn, PyTorch, Hugging Face Transformers, Ollama(Gemma 4 12B)
코어 분류: kf-deberta-base를 선정했다. 시험 조각 일치율은 요청 종류 0.831, 문제 코드 0.802이며, 사람 정답이 아니라 기준 모델(Gemma 4 12B)이 붙인 라벨과의 일치율이다. 제품 분류에는 아직 연결하지 않았다
선정 규칙: 같은 과제의 후보는 같은 검증 조각으로 비교해 검증 점수가 가장 높은 모델을 고르고, 시험 조각은 선정 뒤 보고에만 쓴다
코어 계획 읽기: 모델을 학습하지 않고 쓰는 방식을 비교해 「사진을 한 줄씩 받아쓰고 규칙으로 읽기」를 채택했다
이동: 학습 모델(HistGradientBoosting)이 이전 규칙 판정을 라벨로 한 비교에서 0.848 맞혔으나(사례를 늘린 v2는 다른 사례 모음에서 0.893) 근거가 부족한 경우를 「성립」으로 바꾸는 오류가 있어 채택하지 않았다
요식업: 문장 임베딩을 미세조정해 비슷한 식당 고르기의 대리 지표(분류 일치@3)를 규칙 0.767에서 0.915로 올렸다(시험 1회, 사람의 대체 가능 판정은 아직 없음). 제품에는 아직 적용하지 않았다. 액티비티는 전용 학습이 없다(해당 없음)

3.2 과적합 · 과소적합 관리 및 개선 방향
코어 · 메시지 분류
관찰: 첫 판(빈도 역수 가중 상한 20, 4에폭)에서 문제 코드 인코더가 다수 라벨을 거의 예측하지 않아 검증 점수가 기준선보다 낮았다(A.X 검증 0.3333)
대응: 학습 손실이 계속 내려간 점을 근거로 과소적합과 과한 가중을 원인으로 보고 제곱근 가중(상한 5)·8에폭·배치 16으로 바꿨다. A.X 검증은 문제 코드 0.7383, 요청 종류 0.8344가 되었다
후속: 사람이 단 정답 평가 데이터를 만들어 기준 모델 라벨의 정확도를 잰다(현재 0건). 제품 분류 체계(18종)에 맞춰 다시 라벨을 붙이고 재학습한 뒤 제품 연결을 검토한다
코어 · 계획 읽기
관찰: 값 변조 3.4%(12/350)로 목표 0에 못 미쳤다. 전부 사진·스캔 받아쓰기의 글자 오독이며 놓친 10개 중 6개가 긴 가게 이름 하나였다
후속: 두 번 받아쓴 결과가 다른 줄을 「확인 필요」로 표시하고, 장소 조회로 확인한 이름을 제목 옆에 보인다. 실제 고객 사진으로 만든 사람 라벨 평가셋을 만든다
이동
관찰: 지하철(0.992)은 잘 맞히지만 버스(0.405)는 못 맞힌다. 근거가 부족한 경우를 「성립」으로 바꾸는 오류가 남는다
대응: 판정은 규칙과 시간표 조회를 유지하고, 소요시간 추정에는 통계표를 쓴다. 규칙에 없는 기능을 더할 때 학습 모델을 다시 검토한다
요식업
관찰: 분류 일치는 대리 지표이고(분류도 메뉴에서 규칙으로 뽑았다) 시험은 1회다
후속: 대체 추천 결과를 사람이 「대체 가능한가」로 판정하는 시트(237행)를 채운 뒤 제품 적용을 정한다
