## 프로젝트 주제

A-COP는 외국인 자유여행자의 서울 여행 일정을 검증하고, 여행 중 변화에 맞춰 남은 일정을 조정하는 여행 지속관리 서비스다. 고객의 개인 에이전트나 외부 서비스가 만든 초기 일정을 받아 실행 가능성을 판단한다. 변경 시에는 판단 근거, 변경 내용, 최신 일정과 다음 행동을 고객에게 안내한다.

기준 상품은 서울, 최대 7일, 최대 4인, 팀당 49,000원(VAT 포함)이다. 알림과 여행계획서 링크는 고객이 선택한 언어로 생성해 보낸다. 지원 언어 목록은 미리 고정하지 않으며, 고객이 선택하지 않으면 한국어와 영어를 사용한다. 시각, 날짜, 금액, 고유명사, 예약번호는 번역하지 않고 원값을 유지한다. 개인 에이전트용 API는 한국어 결과를 제공하며, 연결된 에이전트가 고객 언어로 번역한다.

대표 고객은 K-콘텐츠를 계기로 서울을 찾은 대만인 여성 친구 2명이다. 여행 목적은 쇼핑과 식도락이다. 한 명은 한국 식자재, 디저트, 마트 쇼핑에, 다른 한 명은 향수, 화장품, 쇼룸에 관심이 있다. 이 팀의 1인당 부담은 24,500원이다.

프로젝트는 2026-10-26 최종 검토까지 실증에 필요한 개발과 구매 검증 준비를 마친다. 개발 단계의 현금 상한은 500만원, 인력은 기존 팀원 6명, 공수는 720시간이다. 완료 기준은 자동 시험 20개, 아키텍처 시험 4개, 측정 2개로 구성한 DoD 26개다. 최종 검토에서 항목별 충족 여부를 공개한다. 이후 유료 현장 실증은 완료 여행 20~30팀을 목표로 결제, 사용, 환불, 지원을 측정한다. 실측 기여이익Ⅱ가 양수이면 상용 확장을 검토한다.

## 문제 정의

핵심 문제는 여행 중 일정이 바뀔 때 내부 일정, 업체 예약, 고객의 실제 이동 상태가 일치하지 않는다는 점이다. 우선 고객은 서울에서 예약 일정과 자유 방문을 함께 소화하는 외국인 개인과 친구 그룹이다. 대표 동선은 호텔에서 출발해 잠실 스카이타워, 성수동 쇼핑과 점심, 경복궁, 저녁 식사, 롯데마트 서울역점을 거쳐 호텔로 돌아오는 하루다. 아래 사건 6개를 개발, 시연, 회귀 시험의 기준으로 삼는다.

사건 6개 중 시스템이 먼저 감지하는 사건은 3개, 고객의 경험이나 질문으로 시작하는 사건은 3개다. 두 경로는 같은 절차로 처리하되 성과는 따로 집계한다. 선제 감지 성공률은 시스템 시작 사건을, 신고 처리 성공률은 고객 시작 사건을 분모로 계산한다.

현재 여행자는 지도, 시설 공지, 예약 확인서와 번역 결과를 대조해 문제와 대안을 찾는다. 이후 이동 시간과 다음 예약을 다시 계산하고, 업체에 연락하며, 동행자에게 변경 내용을 전달해야 한다. 이 과정에서 네 가지 문제가 발생한다. 변경한 식당이나 이동편이 다음 예약과 충돌하고, 휴무나 운행 중단을 늦게 알아 재탐색을 반복한다. 번역 안내에서 시각이나 예약 미완료의 의미를 놓치거나, 업체에 같은 정보를 다시 설명하기도 한다.

예약 없는 방문도 관리한다. 경복궁 일반 관람은 예약 없이 가능하지만 유료이며, 외국인 일반 성인 관람료는 3,000원이다. 한복 착용 시 무료관람은 별도 조건으로 판정한다. 유료 여부, 예약 필요 여부, 조건부 면제 여부를 각각 관리한다. ([궁능유적본부 관람요금](https://royal.khs.go.kr/ROYAL/contents/R703000000.do))

고객 성과는 네 가지로 측정한다. 최종 적용 일정의 필수 조건 위반 0건, 다음 행동 결정까지 고객 작업 시간의 기존 방식 대비 중앙값 30% 감소, 확정 여부·다음 행동·업체 미완료 상태에 대한 이해도 90% 이상, 업체 인계 시 같은 정보의 반복 제출 중앙값 1회 이하를 목표로 한다. 작업 시간 감소율은 `(기존 시간 - 당사 이용 시간) ÷ 기존 시간`, 이해도는 `정답 문항 수 ÷ 전체 확인 문항 수`로 계산한다. 최근 여행 변경을 겪은 인바운드 여행자를 인터뷰해 손실, 이용 포기, 가격 거절 사유를 기록한다.

**구매자와 가격**

기본 수익모델은 여행 대표자에게 공동 일정 관리 이용권을 판매하는 방식이다. 개인 에이전트는 서비스 이용 경로이며, 구매자는 여행 대표자다. 대표 고객인 대만인 친구 2명은 인당 `49,000 ÷ 2 = 24,500원`, 최대 인원 4명은 인당 12,250원을 부담한다. 에이전트 사업자 대상 판매는 기본료에 일정 여행량을 포함하고 초과분을 종량 과금하는 방식으로 검토한다. 숙박·체험 사업자는 고객 소개 채널로 검토하며, 소개 보상은 고객 획득비(CAC)에 포함한다.

가격은 고객의 시간 절약과 실패 손실 감소를 기준으로 설정한다. 절약 시간 2시간을 시간당 20,000원으로, 실패 확률 20%p 감소를 실패 손실 100,000원으로 환산하면 `2 × 20,000 + 0.2 × 100,000 = 60,000원`이다. 판매 전에 관리 항목, 사람 지원 상한, 업체 예약 변경의 책임 범위를 설명한다. 기본 관리를 제공하지 못하면 고객에게 전액 환불 선택권을 준다.

| 기여이익Ⅰ `m` | `m = 순매출 - 제공 변동비` | 22,749원 |
| 기여이익Ⅱ | `m - C` (C는 CAC) | CAC에 따라 달라진다. |
| 손익분기 CAC 0원 | `180,000,000 ÷ 22,749` 올림 | 연 7,913건 |
| 손익분기 CAC 8,500원 | `180,000,000 ÷ 14,249` 올림 | 연 12,633건 |
| 손익분기 CAC 12,000원 | `180,000,000 ÷ 10,749` 올림 | 연 16,746건 |

[그림: F2 기여이익 폭포]

[그림: F1 CAC-손익분기]

연간 손익은 `Q × (m - C) - F`로 계산한다. Q는 연간 판매량, F는 연간 고정비 1억 8천만원이다. CAC가 `m`보다 작으면 판매 건마다 고정비를 회수하며, 판매량이 손익분기를 넘어야 조직 전체가 흑자로 전환한다.

획득 시나리오의 연 1,200건은 커뮤니티, 콘텐츠·검색, 숙박·체험 소개 세 채널에서 각 400건을 확보하고 획득비 1,440만원을 쓰는 가정이다. CAC는 `14,400,000 ÷ 1,200 = 12,000원`이다. 이 판매량에서는 CAC가 0원이어도 고정비를 회수하지 못한다. 따라서 파일럿에서는 판매량 확대가 가능한 채널과 실제 제공 원가를 우선 측정한다.

장소 상세 조회의 기업용 등급은 1,000건당 20달러(건당 30원), 텍스트 검색의 전문가용 등급은 1,000건당 32달러(건당 48원), 경로 행렬 조회의 기본 등급은 1,000요소당 5달러(요소당 7.5원)다. ([공급자 공식 가격표](https://developers.google.com/maps/billing-and-pricing/pricing)) 유료 장소 조회를 2분마다 반복하면 장소 한 곳에 `7일 × 24시간 × 60분 ÷ 2분 = 5,040회`, `5,040 × 30원 = 151,200원`이 들어 상품가를 초과한다. 2분 주기 감시는 무료 소스에만 적용하고, 유료 조회는 변경 감지 후 재확인과 출발 경로 조회에 사용한다. 여행당 사람 검토는 1건·총 15분으로 제한한다. 상한에 도달하면 선택적 탐색을 중단하고 필수 감시는 유지한다.

## 시스템 구성 기획

시스템은 외부 일정의 검증, 변경 감지, 재조정, 고객 안내를 연결하고 내부 일정 적용과 업체 예약 변경을 구분한다. 고객이나 개인 에이전트가 일정, 예약, 필수 조건을 제출하면 장소와 대상을 식별하고 사실 근거를 조회한다. 시간, 이동, 예산, 동행 조건은 코드로 판정한다. 검증을 통과한 일정은 버전별로 저장한다. 시스템 감지와 고객 신고는 같은 경로로 처리하며, 변경의 영향을 받는 항목을 묶어 전체 일정을 재검증한다. 업체 예약 변경은 링크로 인계하고 승인 절차를 거친다.

고객은 개인 에이전트용 인증 API나 여행별 토큰이 포함된 여행계획서 링크로 서비스를 이용한다. 링크는 별도 로그인 없이 최신 일정을 확인하는 기준 화면이다. 서비스는 최적안 하나를 먼저 적용한 뒤 알린다. 고객은 API나 웹에서 이전 일정으로 되돌리거나 다른 안으로 교체하도록 요청할 수 있다.

판정과 안내에 필요한 영업, 기상, 이동 시간, 경로 값마다 대체 소스를 지정한다. 1차 소스가 응답하지 않으면 대체 소스를 조회하고 출처와 조회 시각을 기록한다. 대체 소스도 실패하면 치명 결함으로 처리해 서버를 중단한다. 대안은 필수 조건을 위반한 후보를 제외한 뒤 하나를 선택해 적용한다. 동률일 때도 하나를 선택하며, 선택 근거와 확인 시각을 남긴다.

알림은 세 시점에 보낸다. 첫째는 일정 변경 시점이다. 외부 일정의 최초 검증 통과, 감지 후 조정, 고객 재요청 반영을 포함한다. 여행계획서 링크는 최초 검증 통과 시 보낸다. 둘째는 여행과 하루의 시작이다. 오늘 일정과 첫 항목의 출발 시각을 안내하고, 전날 저녁에도 준비 안내를 한 번 보낸다. 셋째는 각 항목의 출발 시각이다. 출발 시각은 `항목 시작 시각 - 이동 시간 - 여유`로 역산하며 목적지, 출발 시각, 경로를 안내한다. 출발 전에 경로를 조회해 이동 시간과 발송 시각을 갱신하고, 출발 안내 시 다시 조회한다.

두 번째와 세 번째 알림은 별도 처리 건이나 발송별 LLM 호출 없이 제공한다. 언어별 안내 양식은 처음 한 번 생성해 재사용하고 시각, 금액, 고유명사, 예약번호를 원값으로 채운다.

## 모델링 계획

모델링은 일정의 필수 조건을 지키고 고객의 다음 행동 결정 시간을 줄이는 데 집중한다. 계산 가능한 제약은 코드로 판정하고, LLM은 요청 해석, 대안 후보 생성, 설명, 번역에 사용한다. 안내에서는 확인한 사실과 확인하지 못한 내용을 구분한다. 자체 모델은 학습하지 않는다.

과제는 다섯 가지로 구성한다. 요청·대상 해석에서는 일정, 신고, 질문에서 의도와 객체, 대상을 추출한다. 단일 모델 방식과 사전 정의 어휘 검증을 결합한 방식을 비교하며, 대상이 모호하면 고객에게 다시 묻는다. 일정 성립 판정에서는 예약, 시간, 경로, 예산, 조건을 규칙으로 검사한다. 무예약 방문은 예약 누락으로 처리하지 않는다.

대안 조합에서는 영향받은 항목과 변경이 제한된 예약을 기준으로 후보를 생성하고, 코드로 재검증해 하나를 선택한다. 정책·인계에서는 구조화된 정책 수치와 같은 버전의 원문을 연결해 조건, 차액, 변경 링크를 제공한다. 원문과 수치가 다르면 자동 판정을 중단한다. 안내·번역에서는 정형 안내에 언어별 양식을 사용하고, 자유 문장은 검증된 사실에 근거해 생성·번역한다. 시각, 금액, 장소, 예약번호, 업체 처리 미완료 의미의 누락을 검사한다.

비교군은 단일 모델, 고정 처리 절차와 검색, A-COP 세 가지다. 모델 버전, 입력, 외부 응답, 호출 제한, 응답 대기 시간을 고정해 처리 구조의 효과를 비교한다. 평가셋은 개발용 60건과 최종 보류 평가용 30건으로 구성하며, 합성 여행 20~30건은 별도로 사용한다. 확정 시나리오는 시연과 회귀 시험에 사용한다. 평가셋에는 단독·복합 변경, 무예약, 동률, 소스 장애, 번역 오류를 포함한다. 업무 담당자가 원문, 조건, 허용 행동, 금지 행동으로 정답을 작성하고 검증·화면 담당이 독립 검수한다.

통과 기준은 최종 적용 일정의 조건 위반 0건, 불가능 일정 탐지 95% 이상(분모는 실제 불가 사례), 과잉 거절 10% 이하(분모는 실제 가능 사례)다. 대상이 모호할 때 되묻는 비율은 95% 이상, 불필요한 되묻기는 10% 이하로 관리한다. 소스 장애·동률 사례에서 대체 소스나 근거를 남기고 하나를 선택한 비율은 100%, 번역 중대 의미 오류는 0건, 이해도는 90% 이상을 목표로 한다.

비용과 지연은 여행 전체 비용, 사람 작업 시간, 감지·처리·발행 지연의 분포로 보고한다. LLM 채점은 사람 판정과 대조하는 교정 사례 20건에서 중대 오류 누락 0건을 확인한 뒤 보조 수단으로 사용한다. 금액, 예약 충돌, 권한, 실행 범위는 코드와 사람 검수로 판정한다.

언어 평가는 한국어, 영어, 번체 중국어를 우선하며 언어별 검수자와 평가셋을 확보한다. 시연에는 되돌림 또는 다른 안 선택 장면 1회를 포함해 이력 보존과 재검증을 확인한다. 모델, 프롬프트, 정책, 소스를 변경하면 보류 평가와 회귀 시험을 다시 실행한다.

## 데이터 수집 전략

데이터는 방문 시점의 상태와 판정 근거를 검증할 수 있도록 수집한다. 수집 대상은 API로 받는 현재 상태, 검색으로 찾는 적용 규정, 합성·재생 평가 자료, 구매·운영 로그다. 장소 기본정보와 방문 시점의 영업, 이동, 재고 상태를 구분해 관리한다.

소스는 공개 API(기상, 관광정보, 장소, 이동), 공개 사이트 공지, 업체 정보 순으로 연결한다. 공개 API만 연결한 단계에서도 대표 시연이 가능하도록 구성한다. 확정 시나리오에 필요한 신규 소스 영역은 대기질, 실시간 운행, 도로 통제, 당일 임시휴무, 재고의 다섯 가지다.

신규 소스의 공개 여부, 사용 조건, 갱신 주기, 비용은 2026-09-24 데이터 검토까지 확인한다. 필수 사건의 전체 처리 과정 검증은 통합 검토 전에 마친다.

감시 작업은 실행마다 대상 5개를 확인한다. 대상 360개를 2분 간격으로 순회하면 `360 ÷ 5 × 2 = 144분`이 걸린다. 작업 주기와 대상별 갱신 간격을 구분하고, 무료 감지로 처리 가능한 사건을 먼저 판별한다. 부족한 최신성은 캐시, 유료 재확인, 업체 공지를 조합해 보완한다. 장소 데이터는 공급자의 표시 조건을 준수한다. ([장소 데이터 공식 정책](https://developers.google.com/maps/documentation/places/web-service/policies))

데이터 품질 목표는 지원 항목의 필수 필드·출처 충족 100%(분모는 공개 지원 항목), 판정 근거의 원천 시각·조회 시각 구분 100%, 정책 수치와 원문 일치 100%, 잘못 연결된 장소 0건이다. 장소는 공급자 ID와 좌표를 대조해 연결한다. 지원 장소는 모두 이 기준을 충족해야 하며, 충족하지 못한 장소 유형은 지원 목록에서 제외한다. 개인정보는 목적별로 최소 수집하고 여행별 접근 권한과 철회를 적용한다.
