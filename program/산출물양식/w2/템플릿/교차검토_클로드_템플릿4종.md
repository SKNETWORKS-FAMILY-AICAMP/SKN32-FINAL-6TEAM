## 0. 한 줄

**넷 다 쓸 만하다. 대부분 동의한다.** 반대하는 곳은 **하나**(요구사항의 G열 병합)이고, **다섯 템플릿을 가로지르는 통일이 하나** 빠져 있다(상태 표시 어휘).

---

## 1. 다섯을 가로지르는 것 — ★상태 표시를 하나로

**템플릿마다 상태 표시를 따로 정의했다.** 같은 사실이 문서마다 다른 표시로 나가면 심사자가 두 문서를 대조할 수 없다.

| 템플릿 | 정의한 표시 |
|---|---|
| 기획서 | 근거 `[실측]·[외부]·[추정]·[미확보]` + 실행 `[제안]·[결정]·[미구현]·[구현]·[검증완료]` + 시험 `[합성]·[Mock]·[재생]` + `[해당 없음]` — **가장 완전하다** |
| 수집 데이터 | 성격 `실데이터 / 합성 / Mock / 실응답 재생` + 확보 `확보 / 일부 확보 / 확보 예정 / 확보 불가·중단` |
| DB | 「근거의 종류와 구현 상태를 분리한다」 — 단계 이름은 자체 정의 |
| 요구사항 · WBS | 비고·상태 열에 각자 |

→ ★**제안: 기획서 템플릿의 「모든 절에 적용할 상태 표시 규칙」 표를 다섯 산출물의 공통 규칙으로 올린다.** 수집 데이터의 「확보 4단계」는 그 위에 얹는 **데이터 전용 축**으로 둔다 — 충돌하지 않는다.

## 2. 템플릿별

### 2-1. 요구사항 정의서

| 처방 | 판정 | 이유 |
|---|---|---|
| 7열 유지 · 요구 내용은 `소분류·추가설명`, 관리 정보는 `비고` | **동의** | 양식 열의 뜻과 맞다 |
| 문서 공통 정보를 G5 에 `문서공통: …` 으로 | **동의** | 열을 안 늘리고 판·기준일을 붙인다 |
| ★**`G16:G18` 병합을 유지하고 세 행의 비고를 한 셀에 ID 를 붙여 적는다** | ★**반대** | 아래 |
| 요구사항별 우선순위(MoSCoW) 부재 지적 | **동의** | 54개에 우선순위가 없다. 절삭 판단 근거가 된다 |

★**`G16:G18` 에 대한 반대 이유.** 그 병합은 **빈 양식의 예시 내용에서 온 흔적**이다. 우리 16~18행에는 **서로 무관한 요구사항 셋**이 들어간다. 병합을 유지하면 **셋이 한 묶음인 것처럼 보이고**, 엑셀에서 행 단위로 거르거나 정렬할 때 둘은 비고가 빈 행이 된다.

`[실측 2026-09-10]` 병합을 유지한 채 쓰던 빌드 스크립트가 **REQ-013·014 의 근거를 실제 파일에서 빈칸으로 내보냈다.** 지금은 G열 병합을 풀고, 다시 병합되면 멈추는 가드를 넣었다.

→ **대분류·중분류(A~C열) 병합은 우리 묶음대로 다시 잡고, G열은 행마다 둔다.** 템플릿의 「병합을 풀거나 재구성하는 것을 전제로 삼지 않는다」는 **A~C 에는 맞고 G 에는 안 맞는다.**

### 2-2. WBS

| 처방 | 판정 | 이유 |

| 작업 하나에 산출물 · 완료 기준 · 선행 · 공수 · 담당 · 기한 | **동의** | 템플릿의 「사람 투입량과 달력 경과를 분리한다」가 특히 좋다 — 외부 응답을 기다리는 3일은 사람의 3일이 아니다 |
