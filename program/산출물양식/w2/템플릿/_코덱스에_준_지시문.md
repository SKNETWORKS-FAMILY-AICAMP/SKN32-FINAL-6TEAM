너는 **실무 기획서 설계자**다. 부트캠프 제출용이 아니라 **실제 회사에서 투자·경영진
검토에 올리는 프로젝트 기획서**의 내용 템플릿을 만든다.

## 만들 것

**프로젝트 기획서의 「내용 템플릿」** — 각 절에 **무엇이 · 왜 · 어떤 형태로** 들어가야
하는지의 명세. 지금 우리 프로젝트 내용을 채우는 것이 **아니라**, **어떤 프로젝트에도
쓸 수 있는 틀**을 만드는 것이다.

## ★넘을 수 없는 제약 — 양식이 절 7개로 고정돼 있다

`program/산출물양식/[기획] 프로젝트 기획서_양식.docx` 의 절 제목은 이 일곱뿐이고
**바꿀 수 없다.**

```
1  프로젝트 주제
2  문제 정의
3  시장조사 및 BM 분석
4  시스템 구성 기획
5  모델링 계획
6  데이터 수집 전략
7  역할분담(R&R)
```

**절을 늘리거나 이름을 바꾸는 안을 내지 마라.** 실무 기획서에 있어야 하는 것들을
**이 일곱 안에 어떻게 배치하는가**가 이 일의 핵심이다.

## 템플릿에 반드시 담아야 하는 것

각 절마다 이렇게 적어라.

| | |
|---|---|
| **이 절이 답하는 질문** | 한 문장 |
| **반드시 들어가는 것** | 목록. 빠지면 기획서가 성립하지 않는 것만 |
| **형태** | 표인가 · 문단인가 · 그림인가. 표면 **열 이름**까지 |
| **분량 기준** | 대략 몇 자·몇 표 |
| **흔한 실패** | 이 절에서 사람들이 자주 저지르는 잘못 |
| **판정 기준** | 이 절이 잘 됐는지 **어떻게 확인하나** |

## ★특히 답해야 하는 것

1. **PGBBB(Pain·Gap·Buyer·Build·Business)를 어느 절에 어떻게 넣나.**
   다섯 파트가 절 하나에 다 들어가나, 나뉘나? **근거를 대고 정하라.**
2. **시장 규모(TAM/SAM/SOM)와 경쟁 분석**의 자리와 **깊이**.
   숫자를 어디까지 요구하나. 출처 등급은 어떻게 표시하나.
3. **수익 구조** — 가격·원가·기여이익·CAC·손익분기·하방 시나리오를
   **기획서에 어디까지** 넣나. 상세는 별도 문서로 미루는 기준은?
4. **아직 모르는 것(미확보)을 기획서에 어떻게 적나.**
   실무 기획서는 모르는 것을 숨기면 나중에 신뢰를 잃는다. **표시 규칙**을 정하라.
5. **기술 내용과 사업 내용의 비중.** 지금 우리 기획서는 기술 쪽으로 크게 기울어 있다.
   **실무 기획서의 적정 비중**은 얼마이고 근거는 무엇인가.
6. **역할분담(R&R)** 절이 실무에서 실제로 쓰이려면 무엇이 있어야 하나.

## 규칙

- **파일을 만들지 마라.** 최종 메시지 하나에 마크다운으로.
- 한국어 문서체("~한다").
- **일반론을 늘어놓지 마라.** 각 항목마다 **왜 그래야 하는지**를 붙여라.
  "중요하다"로 끝나는 문장은 쓰지 마라.
- 이 프로젝트의 실제 내용을 채우지 마라 — **틀만** 만든다.
  다만 **예시가 필요하면 이 프로젝트에서 가져와도 된다.**
- 마지막에 **「지금 기획서가 이 템플릿에서 벗어난 곳」**을 표로 적어라.
  실측으로 확인한 것만.
