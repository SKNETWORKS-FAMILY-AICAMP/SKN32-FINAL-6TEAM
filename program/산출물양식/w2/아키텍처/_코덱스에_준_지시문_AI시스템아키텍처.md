## ★넘을 수 없는 제약

1. **양식의 절·표 구조를 바꾸지 않는다.** 절을 늘리거나 이름을 바꾸지 마라. **양식의 질문 칸(라벨·열 이름)은
   그대로 두고 답은 값 칸에 적는다.** 양식에 없는 우리 항목은 행을 덧붙인다.
2. ★**양식의 예시 문구를 옮기지 마라.** 양식은 다른 주제(영업 실적 분석)의 예시로 채워져 배포됐다 — Supervisor
   Agent · SQLChain · MySQL · 유사도 0.7 · Recursion Limit 같은 말이 들어 있다. **우리 것이 아니면 한 글자도 쓰지 마라.**
3. ★**2.3 절 제목에 「LangGraph」가 박혀 있다.** 제목은 못 바꾼다. **본문 첫 문장에서** 우리는 LangGraph 를 쓰지
   않는다는 것(의존성에만 있고 import 0곳)과 **무엇이 그 일을 하는지**(Controller + Case 상태기계 12종 +
   되잡기 작업)를 적어라. 양식의 State Schema 자리에는 **우리 계약**(`Case`·`TeamTask`·`TeamResult`·`ContextPack`·
   `ActionProposal`)을 코드에서 칸 이름을 꺼내 적는다.
4. ★**설계와 구현을 갈라 적는다.** v11 이 정했지만 코드에 없는 것(여행계획서 링크 · Trip 표 · 여행 감시 되잡기 ·
   알림 발송 · 이동 시간 조회 · 결정 15 의 서버 중단)을 **구현된 것처럼 쓰면 틀린 것이다.** 합의본 42~78행의
   `[결정]`/`[구현]`/`[미구현]`/`[미확보]` 로 주장마다 표시한다. 문서 전체에 한 번에 붙이지 않는다.
5. **상태를 색이나 기호로만 쓰지 않는다** — 글자로 쓴다(재설계안 §3).
6. **줄 번호를 적으려면 네가 직접 연 것만.** 사실표에 없는 새 사실은 `[실측 · 정적 확인]` + 파일:줄.
