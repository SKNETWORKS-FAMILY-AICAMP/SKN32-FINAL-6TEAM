3. 그림 읽는 법

모양뜻
타원 (짙은 녹색 실선)시작 · 끝
빨간 점선 타원오류로 끝남 (고객 알림 없음 — 운영 기록만)
회색 점선 타원 ⏸고객이 고르거나 답할 때까지 기다리는 자리
흰 상자정해진 규칙대로 하는 코드
파란 점선 상자 [LLM]언어 모델이 돕는 자리 — 정해진 보기 안에서만 고르고, 결과는 코드가 다시 확인
굵은 상자담당 에이전트 (자기 일감과 허락된 도구만 씀, 언어 모델 없음)
갈색 긴 점선 상자공용 도구 (에이전트가 아니라 여러 곳이 부르는 함수)
노란 마름모코드의 판단 — 화살표 옆 글이 조건
노란 화살표 (곡선)되돌아가는 반복 — 옆에 상한
작은 밑줄 칸칸 이름 — 마우스를 올리면 설명 상자

그림 읽는 법 · 타원 = 시작 · 끝(짙은 녹색 실선) · 빨간 점선 타원 = 오류로 끝남 · 회색 점선 타원 ⏸ = 고객이 답할 때까지 기다림 · 흰 상자 = 정해진 규칙대로 하는 코드 · 파란 점선 상자 = 언어 모델이 돕는 자리 · 굵은 상자 = 담당 에이전트 · 갈색 긴 점선 상자 = 공용 도구(에이전트가 아님) · 노란 마름모 = 코드의 판단(화살표 옆 글이 조건) · 노란 화살표 = 되돌아가는 반복(옆에 상한) · 상자에 마우스를 올리거나 누르면 설명이 뜹니다.

4. 정할 것 · 설계와 코드가 다른 곳

  • 이동의 자리: 설계는 이동을 에이전트가 아닌 공용 도구로 정했지만(2026-10-02 팀 결정), 코드에는 아직 mobility 담당으로 등록돼 있습니다 — 09 · 05 참조.
  • MCP 도구 개수: 계획 v26 는 14개(읽기 7 · 쓰기 7), 루트 CLAUDE.md 사실표는 「읽기 5 · 쓰기 7」, 코드 등록은 15개(읽기 8 · 쓰기 7)입니다 — 15 참조.
  • 외부 정보 6종: 발표 자료의 6종(날씨 · 특보 · 단기예보 · 재난문자 · ITS · UTIC)과 코드의 6종(예보 · 특보 · 재난문자 · 교통 통제 · 대기질 · 지진)이 다릅니다 — 06 참조.
  • 미연결 판정: 계획 v26 는 「미연결 → 문제 없음」이라고 적지만 결정 15 는 「확인하지 못한 것을 문제 없음으로 읽지 않는다」고 적습니다 — 06 참조.
  • 알림 세 시점: 결정 ②·③(여행 시작 · 항목 출발 시각)이 코드에 있는지 확인하지 못했습니다 — 12 참조.
  • 채팅과 에이전트: 채팅에서 요식 · 액티비티 에이전트로 가는 길은 아직 없습니다 — 14 참조.
  • 숙박 · 항공 · 예약 인계: 등록만 돼 있고 이번 묶음에서 일하지 않습니다(계획 v26 부록 C 「그대로 둠」). 이 묶음에서 뺐습니다.

5. 근거 등급

각 칸의 근거는 세 등급으로 적었습니다. 근거 있음 = 코드 줄이나 실행 기록으로 확인 · 부분 근거 = 일부만 확인 · 근거 없음 = 계약 문서의 값이거나 기록이 없음. [미확보] = 이 세션에서 확인하지 못함. [확인 필요] = 코드 경로를 다시 봐야 함.
