15 개인 AI 입구 (MCP) — 고객이 연결한 개인 AI가 여행 도구를 부른다

고객이 연결한 개인 AI가 여행 도구를 고르고 부르는 입구입니다. 읽기 도구는 늘 열려 있고, 쓰기 도구는 기본적으로 꺼져 있습니다. 본인 여행만 보입니다.
목차로 ← 14 고객 채팅 (결정 모델)
  • 결론: 개인 AI는 본인 여행에 한해 도구를 부릅니다. 읽기는 저장된 점검 결과를 먼저 읽고, 쓰기는 채팅 · 등록과 같은 검사를 거칩니다.
  • 입력: 개인 AI의 도구 호출(고객 키). 출력: 도구 결과(여행 · 점검 · 판정) 또는 쓰기 결과(검사 후 반영).
  • 그래서 달라지는 것: 고객이 자기 AI에게 「내 여행 괜찮아?」라고 물으면 같은 점검 결과를 받습니다.
  • 정할 것 · 한계: 도구 개수 문서는 14개, 코드 등록은 15개입니다(아래 7절). 쓰기 도구를 켤지는 정하실 것입니다. 실제 개인 AI 접속은 확인하지 못했습니다.
  • 근거 범위: 2026-10-12 코드 확인(modules/mcp/mcp_server.py) · 계획 v26 §3 · 부록 C · cs 프로젝트 문서 「mcp-tools」.

2. 주 성공 시나리오

  1. 개인 AI가 도구 목록을 본다(읽기 도구는 항상, 쓰기 도구는 스위치가 켜졌을 때만).
  2. 개인 AI가 도구를 고른다. 우리 쪽은 도구를 고르지 않습니다.
  3. 읽기면 기본 호출은 저장된 점검 결과를 읽는다(바깥 호출 없음). 새로 부르기는 한도 안에서만 한다.
  4. 이동 판정이면 시간표 기준 판정을 돌려준다(09).
  5. 쓰기면 채팅 · 등록과 같은 검사와 반영을 거친다(11 · 13).

3. 확장 · 예외 — 주 시나리오에서 갈라지는 길

  • 3a 새로 부르기 한도 초과: 「확인 불가」로 답한다. 문제 없음으로 답하지 않는다.
  • 3b 모니터링 결과가 없음(개발 환경): 기본 호출은 대부분 「확인 불가」가 된다.
  • 4a 판정기 꺼짐 · 갈 방법 없음 · 판단 못 함 · 서울 밖: 그 사실을 그대로 돌려준다.
  • 5a 쓰기 스위치 꺼짐: 쓰기 도구가 목록에 없다(보이지도 않음).

7. 미확정 · 한계 · 정할 것

  • 도구 개수가 다릅니다: 계획 v26 는 「읽기 7 · 쓰기 7 = 14」라고 적고, 루트 CLAUDE.md 사실표는 「읽기 5 · 쓰기 7」이라고 적습니다. 코드 등록은 읽기 8 · 쓰기 7 = 15입니다. 정하실 것: 문서 기준 한 가지로 맞출지.
  • 쓰기 도구를 켜면 개인 AI가 일정을 바꿀 수 있습니다. 기본은 꺼짐입니다. 켜기 전에 정하실 것: 누가 어떤 범위까지 쓸지.
  • 실제 개인 AI 연결과 바깥 접속은 확인하지 않았습니다. 이동 판정은 시간표 기준이며 실시간 운행을 확정하지 않습니다.
