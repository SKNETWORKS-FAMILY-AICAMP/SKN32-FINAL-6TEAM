03 작업 지시서 (TeamTask) — 코어가 에이전트에게 맡기는 한 번의 일

코어(중앙 처리기)가 담당 에이전트에게 일을 한 번 맡길 때 보내는 종이입니다. 모든 기능의 공통 입력입니다. 값을 어디서 정하는지는 표의 오른쪽 칸입니다.
목차로 ← 02 처리 건 열기 · 담당 고르기 04 처리 결과지 (에이전트 → 코어) →
  • 결론: 처리 건 번호 · 실행 번호 · 담당 · 일감 종류 · 고객 문장 · 쓸 수 있는 조회 도구 · 마감 시각 · 근거 묶음을 한 장에 묶어 보냅니다.
  • 입력: 처리 건(customer_cases) · 담당 등록(registry) · 상태 · 근거 묶음(context). 출력: 에이전트가 받는 한 장의 지시서(검사를 통과해야 보냄).
  • 그래서 달라지는 것: 에이전트는 이 종이에 적힌 것만 보고, 적힌 도구만 씁니다. 마감을 넘으면 코어가 멈춥니다.
  • 정할 것 · 한계: 고객 문장 상한 12,000자를 접수 창이 막지 않습니다. 「이어서 하는 실행」(resume)은 여행 일정 관리에서 쓰지 않습니다.
  • 근거 범위: 2026-10-12 코드 경로 확인(app/core/contracts.py:165-193) · 사용자가 준 1절 표 · w5 v7 오버레이 [3]·[8]·[9].

성공 보장에이전트가 같은 처리 건 번호 · 담당 이름의 지시서를 받아 결과지(04)를 돌려준다

2. 주 성공 시나리오

  1. 코어가 실행 번호(run_id)와 일감 번호(task_id)를 새로 만든다.
  2. 코어가 처리 건의 번호 · 판 번호 · 담당 이름 · 일감 종류를 넣는다.
  3. 코어가 고객 문장과 쓸 수 있는 조회 도구 목록을 넣는다.
  4. 코어가 마감 시각(지금 + 90초)을 넣는다.
  5. 코어가 근거 묶음(상태 · 근거 · 12,000 토큰 상한)을 붙인다.
  6. 검사기가 재개 여부와 재개 위치가 짝인지, 근거 묶음의 번호와 담당 이름이 지시서와 같은지 확인한다.
  7. 검사를 통과한 지시서를 에이전트에게 보낸다.

3. 확장 · 예외 — 주 시나리오에서 갈라지는 길

  • 검사 실패: 정의하지 않은 칸이 있거나 번호가 맞지 않으면 보내지 않고 오류로 기록한다.
  • 근거 묶음 초과: 상한(12,000 토큰)을 넘으면 자르지 않고 오류를 낸다.
  • 고객 문장이 1~12,000자를 넘음: 지시서를 만들다 실패 → 실행 실패 → 처리 건이 실행 중에 멈춤(되잡기는 이 상태를 못 잡음 — 현재 한계).

7. 미확정 · 한계 · 정할 것

  • 사용자가 준 1절 표의 「deadline_at: 지금 + 90초」는 config/guardrails.yaml:46 과 맞습니다. 다만 로컬 에이전트는 이 칸을 읽지 않고, 실제 중단은 코어의 90초 제한이 맡습니다.
  • 고객 문장 상한 12,000자는 계약 문서의 값이며 근거 기록이 없습니다 [근거 없음]. 정하실 것: 접수 창에서 막을지, 지시서 단계에서 잘라 쓸지.
  • 근거 묶음의 칸별 예산(1,800 · 2,400 · 3,600 · 1,200 · 600)은 계약 문서에만 있고 실측은 없습니다.
