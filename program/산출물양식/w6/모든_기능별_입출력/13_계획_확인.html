13 여행 계획 확인 — 고객이 올린 계획을 읽고, 확인받고, 검사를 거쳐 등록한다

고객이 글 · 사진 · 파일로 올린 여행 계획을 코드가 읽고, 못 읽은 줄만 언어 모델이 돕고, 고객이 확인 화면에서 고친 뒤 등록을 요청하면 검사 후 저장합니다. 정석 UC-1 흐름입니다.

  • 입력: 고객이 올린 계획(글 · 사진 · 파일). 출력: 등록된 여행 한 개와 계획서 링크 알림 — 또는 이유와 고칠 방법이 붙은 확인 화면.
  • 그래서 달라지는 것: 시간이 겹치거나 이동이 안 되는 계획은 등록되지 않고, 이유와 고치는 방법이 확인 화면에 나옵니다.
  • 정할 것 · 한계: 고친 횟수 상한은 확인하지 못했습니다. 등록 요청 하루 한도 기능은 꺼져 있습니다. 개인 AI가 낸 계획은 확인 화면 없이 바로 검사합니다.
  • 근거 범위: 계획 v26 §1 · 부록 A 「계획 읽기 보조」 · 2026-10-12 경로 확인(components/intake · components/conversation/trip_intake.py).

2. 주 성공 시나리오

  1. 고객이 계획을 올린다(글 · 사진 · 파일).
  2. 코드가 날짜 · 시각 · 장소를 규칙으로 읽는다.
  3. 규칙이 못 읽은 줄이 있으면 계획 읽기 도우미가 그 줄의 위치를 짚고, 사진 글자를 받아 적는다. 코드가 원문에 있는 조각인지 검사한다.
  4. 확인 화면에 읽힌 일정을 보여 준다(⏸ 고객이 고른다).
  5. 고객이 고치면 다시 검사하고 확인 화면으로 돌아간다.
  6. 고객이 등록을 요청하면 겹침 · 이동(09) · 필요한 정보를 검사한다.
  7. 검사를 통과하면 여행 · 판 · 항목을 저장하고 계획서 링크 알림을 보낸다(12).

3. 확장 · 예외 — 주 시나리오에서 갈라지는 길

  • 2a 읽지 못함(파일 형식 · 받아 적기 실패): 이유를 보여 주고 다시 올리게 한다(읽기 fatal).
  • 3a 도우미 모델 실패: 그 도움만 건너뛰고 오류로 기록한다. 규칙으로 읽은 것은 그대로 쓴다.
  • 5a 등록 검사 실패: 등록하지 않고 확인 화면에 이유와 고칠 방법(예: 이동 30분)을 보여 준다.
  • 4b 떠남: 등록하지 않고 끝낸다.
  • 개인 AI 입력: 확인 화면 없이 바로 검사한다. 실패하면 문제 목록을 개인 AI에게 돌려준다(15).
