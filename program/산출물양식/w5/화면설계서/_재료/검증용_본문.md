1. 화면 목록과 사용자
1.1 이 문서가 정의하는 화면
guguroute 은 여행자가 직접 짠 서울 여행 계획을 받아 확인하고, 여행 중에는 일정에 문제가 생겼는지 살펴 대안을 알려 주는 서비스입니다. 이 문서는 여행자가 휴대폰 브라우저로 쓰는 고객 웹의 화면을 정의합니다. 운영자 콘솔과 개발 팀 콘솔은 고객 화면이 아니라서 다루지 않습니다.
화면은 휴대폰 폭(390px)을 먼저 맞추고, 넓은 화면(1280px)에서는 같은 화면을 가운데 놓거나 지도 · 시트를 나란히 펼칩니다. 웹 코드는 final_project_cs/frontend/apps/web (Next.js 16 · React 19)에 있고, 서버(cs 프로젝트 서버)의 /v1/web/* 를 부릅니다.
1.2 사용자
● 자유여행자: 국적과 상관없이 스스로 계획을 짜는 여행자. 로그인 없이 시작하고(브라우저 세션), 필요하면 소셜 계정을 연결합니다.
● 여행자의 개인 AI 앱: 화면이 아니라 API(MCP)로 들어오는 입구라 이 문서에서는 다루지 않습니다. 같은 여행을 웹 화면에서도 봅니다.

2. 화면 흐름
2.1 기본 흐름
처음 온 사람은 소개 화면에서 「내 일정 시작하기」를 누르고, 약관에 동의한 뒤 계획을 올립니다. 「계획 확인하기」를 누르면 항로 지킴이 카드(여행 중 문제가 생기면 먼저 바꿔 둘지)를 한 번 고르고, 서버가 계획을 읽는 동안 진행 막대와 질문 카드가 뜹니다. 읽기가 끝나면 지도와 목록으로 결과를 확인 · 수정하고 「여행 등록」을 누릅니다. 등록하면 여행 화면으로 넘어가 여행이 끝날 때까지 이 화면을 씁니다.
그림 1. 화면 흐름. 실선은 기본 흐름, 점선은 처음 온 사람 · 메뉴 · 알림 링크로 들어오는 길입니다.
2.2 다른 입구
● 메뉴: 모든 화면 오른쪽 위 메뉴에서 내 여행 · 마이페이지 · 여행 취향 설문 · 언어 · 테마를 엽니다.
● 알림 링크: 디스코드 · 텔레그램으로 받은 알림 글의 링크(/trips/{여행번호}?guardian=on)를 누르면 여행 화면에서 항로 지킴이 카드가 바로 열립니다.
● 소셜 로그인: 마이페이지에서 업체 로그인 화면으로 나갔다가 /auth/done 으로 돌아와 세션을 만듭니다.
● 옛 주소: /trips/{여행번호}/verification · /results 는 여행 화면으로 돌려보냅니다.
3. 공통 규칙
3.1 화면 구성 규칙
● 폭: 휴대폰 390px 를 기준으로 만들고 1280px 에서도 가로 스크롤이 생기지 않게 합니다. 넓은 화면에서는 카드가 오른쪽 위에 뜨고, 좁은 화면에서는 아래 시트로 올라옵니다.
● 테마: 초록 · 흰색 두 가지(메뉴에서 고름). 어두운 테마는 없습니다.
● 언어: 한국어 · 영어(메뉴에서 고름). 서버가 한국어로만 주는 진행 단계 문구는 알려진 단계 이름에 한해 웹이 영어 문구를 둡니다.
● 세션: 로그인 없이 브라우저 세션(서버가 주는 쿠키)으로 시작합니다. 화면에 토큰을 보여 주지 않습니다.
3.2 공통 요소
● 약관 동의 게이트: 필수 동의(서비스 이용약관 · 개인정보 수집)가 없으면 소개 · 설문 · 로그인 완료 화면을 뺀 모든 화면을 동의 화면이 덮습니다.
● 메뉴 사이드바: 마이페이지 · 내 여행 · 여행 취향 설문 · 언어 · 테마 · 떠 있는 단추 켜기.
● 사람 확인: Cloudflare Turnstile. 사이트 키가 설정된 배포에서만 나타납니다(mock 서버 시험에서는 꺼짐).
● 오류 · 없는 주소: 작은 안내 화면. 서버가 준 오류 문구(code · message)는 바꾸지 않고 그대로 보입니다.
3.3 서버와 이어지는 방식
● 실시간 진행: 오래 걸리는 일(채팅 · 일정 짜기 · 계획 읽기)은 실시간 진행(SSE)으로 받아 서버 단계와 경과 시간을 보입니다. 7초 동안 소식이 없으면 끊긴 것으로 보고 다시 붙습니다.
● 없는 기능: 서버에 아직 없는 기능은 단추를 남기되 누르면 「준비 중」이라고 말합니다. 화면이 결과를 지어내지 않습니다.
● 충돌: 저장 충돌(409)이면 최신 판을 다시 읽고, 다시 읽기도 실패하면 고친 내용을 지키고 다시 시도 단추를 줍니다.

5.2 검증 범위
● mock 서버 시험(화면 반응): 모든 화면은 서버 웹 API 모양만 흉내 내는 mock 서버로 띄운 브라우저 시험을 통과했습니다. 이 문서의 캡처도 전부 mock 서버 화면입니다.
● 실서버 확인(서버 응답): SCR-08 의 읽기 · 결과 · 수정 · 등록은 2026-10-03 에 로컬 실서버로 확인한 기록이 있습니다. 그 뒤 바뀐 화면(읽는 기준 · 항로 지킴이 · 로딩 중 질문 · 재난 정지)은 실서버로 확인하지 않았습니다.
● 서버에 아직 없는 기능: 여행 삭제 · 디스코드로 연결 · 텔레그램 연결 · 위치 기록은 웹만 계약대로 만들어 두었고, 서버가 없으면 화면이 그렇다고 말합니다.
