# 수정 요청: 요구사항 변경 목록 2차 (2026-10-06)

너의 1차 결과 `program/산출물양식/w5/요구사항정의서/_재료/코덱스_변경목록.md` 를 Claude 가 검토했다. 아래만 고쳐 **같은 모양의 JSON 전체(changes · adds · doubts)** 를 다시 내라. 파일은 고치지 말고 최종 답으로 JSON 하나(코드 블록 없이).

1. **D-018 은 draft 다**(`wiki/decisions/D-018-decision15-stop-paths.md` 5행 · 63행: 확인 전까지 결정이 아니라 현행 동작의 기록). 그러니 요구사항 문장(E · F)은 **결정 15 그대로**(1차 소스 → 대체 소스 → 대체까지 안 되면 치명 결함, 서버를 끈다 · 모르는 값을 지어내지 않는다)로 둔다. 「층별 중단」「해당 판정만 중단」「서버 전체 중단이 아니다」 같은 표현을 요구 문장에서 빼고, **현행 코드가 세 층(기동 거부 · 배치 실패 종료 · 요청은 치명 기록)으로 동작한다는 사실은 status_basis 에만** 적는다. 해당: REQ-017 · 018 · 020 · 021 · 023 · 039 · 040 · 046 · 054 · 059 · 061 · 062 등 네가 바꾼 곳 전부. 그 밖의 정당한 갱신(공용 이동 도구 · 먼저 묻기 · 감시 3분 · 사람 인계 제거 등)은 유지한다.
   - 단, 「사람에게 넘긴다(인계)」는 결정 15 와 별개로 **사용자 결정(2026-09-28, 고객 건을 사람에게 넘기지 않는다, 사람은 오류 리포트만)** 이라 요구 문장에서 빼는 것이 맞다. D-018 표의 「사람에게 넘긴다」는 따르지 않는다.
2. **기간**: REQ-001 의 「기준 기간은 기존 최대 7일을 유지한다」를 「기간 상한은 계획서 v11 의 최대 7일이며, 발표 · 화면 표기는 결정 대기」로. 인원 상한 · 가격은 지금처럼 넣지 않는다.
3. 한자(예: REQ-055 reason 의 「不確실」)나 일본어 글자가 섞인 곳을 한글로. 줄표(—, –) · 말줄임표(…) · 별 · 체크 표시 금지.

5. adds 의 각 항목은 B(대분류: 기능 | 비기능) · C(중분류) · E(요구사항명) · F · G · status · status_basis 를 다 갖게(1차에 C 자리에 대분류가 들어간 듯하면 바로잡는다 — 기존 시트의 B 는 「기능」「비기능」, C 는 묶음 이름이다. 기존 묶음 이름을 먼저 쓰고, 없으면 새 묶음).
6. doubts 는 그대로 두되 1번 변경을 반영해 문장을 고친다.
