### 1-2. 어떻게 했나

1. 문서 글을 뽑아 코덱스 5개를 동시에 돌려, 처음 보는 사람이 모를 말과 고칠 문장을 찾게 했습니다.
2. 코덱스가 낸 고친 문장은 아래 자동 검사를 통과한 것만 썼습니다.
   - 원문의 숫자가 고친 글에 모두 남는지
   - 금지 표현(「Jev」 단독 · 목 서버 · 줄표 · 국적 · 인원 제한)이 새로 생기지 않는지
3. 코덱스가 문서 안에 남긴 검토 메모(「별도 명시가 필요」 등)는 지웠습니다.
4. 사실이 틀린 것은 직접 고쳤습니다.
   - 예: 요구사항 정의서에서 Activity 를 「일정 항목」으로 잘못 푼 것 → 액티비티 팀 모듈로 바로잡음
   - 예: 아키텍처 문서의 분모 설명(110 = A 60 · B 50, 115 = 120건 중 검사를 통과해 발송된 수)

## 3. 상용 AI 비교를 「출제자 제외 · B/C 채점」으로 다시 셈

**결론: 문제를 낸 AI 를 그 문제에서 빼고 다시 재도 상용 모델이 B · C 모두 가장 높았습니다.** 파인튜닝한 E4B(약 4B)는 B 채점에서 Qwen3.8 27B 와 같았습니다.

- 저장된 문제별 풀이를 다시 센 것이고, 모델을 새로 부르지 않았습니다.
- B 채점: 복수 항목 질의는 하나라도 맞으면 정답.
- C 채점: 낸 항목 묶음이 정답 묶음과 완전히 같아야 정답.

| Codex 가 쓴 mix8~11 (659문제) · Codex 제외 | B | C |
|---|---|---|
| Claude Fable 5.1 | 653 (99.1%) | 647 (98.2%) |
| Claude Opus 5.5 | 649 (98.5%) | 643 (97.6%) |
| Qwen3.8 27B (파인튜닝 없음) | 642 (97.4%) | 593 (90.0%) |
| Gemma 4 E4B 파인튜닝 | 642 (97.4%) | 592 (89.8%) |
| Gemma 4 26B-A4B (파인튜닝 없음) | 625 (94.8%) | 576 (87.4%) |

| Claude 가 쓴 mix12 (176문제) · Claude 제외 | B | C |
|---|---|---|
| Codex Sol · Astra | 175 (99.4%) | 175 (99.4%) |
| Gemma 4 E4B 파인튜닝 | 174 (98.9%) | 158 (89.8%) |
| Gemma 4 26B-A4B · Qwen3.8 27B | 172 (97.7%) | 156 (88.6%) |
| Codex Luna | 170 (96.6%) | 170 (96.6%) |

**남는 치우침**
- 복수 항목 질의의 정답 묶음은 Claude 가 만들었으므로, mix8~11 의 C 채점에서도 Claude 는 정답 키와 같은 손입니다.
- 파인튜닝 E4B 의 학습 자료도 Claude 가 만들었습니다.
- mix12 는 176문제라 1~2문제 차이는 구분되지 않습니다.
- 로컬 모델의 C 가 낮은 것은 항목을 하나만 내는 구조라 복수 항목 질의(mix8~11 50문제 · mix12 16문제)를 모두 놓치기 때문입니다.

## 5. 확인 범위 · 남은 것

**검사 결과(5종 모두)**: 「Jev」 단독 0 · 줄표 0.

**남은 「§」 표기**: 출처 줄의 파일 경로 뒤 절 번호이며, 일부러 남겼습니다.

**남은 낱말**: 「독립적으로 채점」 같은 일반 낱말과, 발표 산출물 장에서 「이런 말을 바꿨다」고 예로 든 한 곳입니다.

**고친 문장 중 원문을 못 찾아 그대로 둔 것**
- 멀티 에이전트 보고서 · 벡터DB 결과서: 대부분 되돌리기로 빠진 절의 문장입니다.
- 아키텍처 문서: 표 머리처럼 원문 모양이 달라 못 맞춘 몇 개입니다.

**하지 않은 것**
- 화면설계서는 이번 정비 대상이 아니어서 손대지 않았습니다.
- 코덱스 판 발표 v2 는 만들지 않았습니다.

**검토 범위**: 문서를 사람이 처음부터 끝까지 다시 읽지는 않았습니다. 「읽기 전에」 표 쪽과 그림 몇 장을 눈으로 확인했습니다.
