일정이 깨지면 오케스트레이터(흐름을 정하는 서버 코드 — 우리 문서에서 「코어」라고 부르던 것)가 담당 에이전트 하나에게 맡기고, 에이전트는 대체 후보를 통과할 때까지 다시 점검해 제안만 돌려줍니다. 코어가 검사해 새 일정 판과 알림을 내고, 이것을 여행이 끝날 때까지 되풀이합니다. 시스템은 휴대폰 웹 · 개인 AI 비서 앱으로 들어와 백엔드 한 곳에서 처리되고, 공유 State 와 알림 큐는 PostgreSQL 하나에 둡니다.

3. 양식 예시에는 있지만 우리는 쓰지 않는 것

양식 예시우리
LangGraph쓰지 않는다 — 같은 역할(상태 · 노드 · 분기 · 반복)을 컨트롤러와 상태기계 12종이 한다
Redis · MySQL쓰지 않는다 — 상태 · 대기열 · 데이터 모두 PostgreSQL 하나
GraphDB(Neo4j)쓰지 않는다 — 문서 검색은 규정 조각 벡터 검색(pgvector) 하나
평가 에이전트 · 복구 에이전트따로 없다 — 검사는 오케스트레이터의 검증기(코드), 복구는 안쪽 루프 · 대체 소스
고객 건을 사람에게 넘기기없다 — 운영자는 오류 알림만 받는다
