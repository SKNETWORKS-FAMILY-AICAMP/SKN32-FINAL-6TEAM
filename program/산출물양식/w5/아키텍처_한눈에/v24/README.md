## 멘토링 「멀티에이전트 플로우」 네 가지

| 피드백 | 반영 |
|---|---|
| 3분 주기 · 실무 용어 | 모니터링(3분 주기) · 케이스 · 태스크 · 컨텍스트 · 라우팅 · 기능 검증 · 체크리스트 · 반영 · 아웃박스 워커 — 그림 1~4 와 문서 본문 · 부록을 같은 말로 통일 |
| 분류 모델이 있으면 적기 | 그림 3 「결정 모델 — gemma4:12b」(채팅 한 문장의 할 일 · 대상 · 질문 종류) + 「갈래 나누기」(일정 계산 · 규칙 답 · RAG · 대체안 · 되묻기). 학습 분류 모델은 코드만 있고 미연결이라고 문서에 적음 |
| 체크리스트 + 기능 검증 | ④ 구역을 기능 검증 ①근거 대조 ②반영 전 확인 + 체크리스트 검증으로 나눔. 체크리스트의 목적(에이전트 수행 평가)과 평가 기록이 아직 없다는 것(구현 예정) 표시 |
| 「초안 3개 돌려준다」처럼 | 「변경 초안 최대 3개(1순위 + 다른 안 2) — 일정마다」 |

## 추가 요청

- 분류 모델이 일을 걸러 나누는 것: 문서 3절 「앞단 나누기 · 검증 · 초안」 + 표 「길마다 누가 일을 가르나」(모니터링 · 채팅 · 계획 확인 · 일정 짜기).
- 계획 짤 때도 공통인가: 다섯 갈래 나누기는 채팅에만 있다. 공통인 것은 원칙(언어 모델은 보기 안에서만 고르고 값은 서버가 채우고 검사).
