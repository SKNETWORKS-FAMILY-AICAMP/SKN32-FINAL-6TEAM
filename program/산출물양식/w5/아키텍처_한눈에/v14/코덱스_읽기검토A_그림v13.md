**판정: UC-1은 큰 흐름이 읽히지만, UC-2는 발표자의 설명 없이는 변경 권한과 종료 조건을 이해하기 어렵습니다.** 첫 화면에서는 ‘등록 → 문제 감지 → 대안 확인 → 변경·알림’ 네 덩어리가 먼저 보여야 합니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 지정 자료·두 그림 읽기 검토 | 완료 | 2/2장 = 100% |
| 필수 항목 판정 | 완료 | 6/6개 = 100% |
| 한 장 축약안 | 완료 | 1/1안 = 100% |

아래는 이해도 검토이며, 동작의 사실 정확성을 재판정하지 않았습니다. 파일은 수정하지 않았습니다.

## 1. 처음 보는 사람이 막히는 곳

심각도는 **발표의 핵심을 오해하면 Blocker, 읽는 흐름이 끊기면 Major, 국소 표현 문제면 Minor**로 매겼습니다. 바꿀 글의 줄바꿈은 상자 안 줄바꿈입니다.

## 2. PDF의 ‘반드시 넣을 것’ 6개가 드러나는가

| 필수 항목 | UC-1 | UC-2 | 처음 보는 사람 기준 근거 |
|---|---|---|---|
| 시작과 끝 | **드러남** | **안 드러남** | UC-2는 항목 처리 종료·이번 점검 중단·계속 대기·그림 밖 이동 처리가 모두 비슷한 타원이다. 종료 범위가 다르다. |
| 종류 구분: AI·코드·사람·분기 | **드러남** | **안 드러남** | UC-2의 종류는 범례에 있지만, ‘워커 에이전트·규칙+도구·LLM 안 씀’을 함께 해독해야 한다. |
| 화살표의 분기 조건 | **안 드러남** | **안 드러남** | UC-1은 ‘수행 불가·한도’, UC-2는 코드 이름·보호·동의 요청을 이해해야 조건을 읽을 수 있다. |
| 병렬 분할·합류 | **해당 없음** | **드러남** | 6개 조회 상자가 갈라졌다 합쳐지는 배치는 명확하다. 두 담당의 합류와 혼동하지 않도록 담당 선택을 강조하면 된다. |
| 반복 종료·최대 횟수·상한 도달 경로 | **안 드러남** | **안 드러남** | UC-1은 상한 확인 불가 메모만 있다. UC-2는 숫자와 일부 중단 경로는 보이지만 정상 종료와 후보 소진 경로가 한눈에 연결되지 않는다. |
| 사람 개입 지점과 선택지 | **드러남** | **안 드러남** | UC-1의 수정·등록은 읽힌다. UC-2는 ‘안 번호·바꿔 줘’의 차이를 먼저 해석해야 한다. |

상자와 화살표가 없는 ‘나쁜 예’ 수준은 아닙니다. 다만 **UC-2는 “정보가 들어 있다”와 “질문에 바로 답할 수 있다” 사이에 간격이 큽니다.**

## 3. 한 장으로 줄인다면

**목표: 주요 도형 14개 이내, 큰 구간 4개, 상자당 제목과 설명 합계 2줄 안팎.**

| 큰 구간 | 남길 것 |
|---|---|
| 계획 등록 | 고객 제출 → 읽기 → 고객 확인 → 등록 검사 → 저장 |
| 여행 중 문제 확인 | 주기 실행 → 6종 동시 조회 → 결과 합치기·문제 판단 |
| 대안 찾기 | 프로그램의 담당 선택 → 식당 담당 / 활동 담당 → 변경안 확인 |
| 적용과 알림 | 필요할 때 고객 선택 → 저장·알림 |

분기 이름표로 **“문제 없음·확인 불가: 유지”**, **“담당을 정할 수 없음·검사 실패: 중단”**, **“응답 없음: 대기”**를 남깁니다. 첫 등록 저장에서 주기 점검으로 이어지는 연결도 반드시 보여 줍니다.

- **카드로:** 담당별 책임·입력·출력·도구 이름, 검사 체크리스트, 고객에게 묻는 세부 조건, 후보 반복의 종료·상한.
- **부록으로:** 개인 AI 제출 경로, 이동 문제 별도 처리, 중복 문제 구분, 통신 방식, 일정 버전 저장, 오류 전파, 알림 재시도·자동 만료의 현재 상태.
- **본그림에 유지:** 누가 다음을 정하는지, 실제 병렬 구간, 반복 한도와 초과 시 중단, 고객 선택, 유지·중단·대기의 차이.
