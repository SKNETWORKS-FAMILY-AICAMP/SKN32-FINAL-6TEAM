guguroute 멀티 에이전트 흐름 v1

2026-10-02 · 참고 구조(층마다 받는 것 · 돌려주는 것, 도구 층, 검사 · 복구 순환)의 모양으로 우리 실제 구조를 그렸다 · 사실 기준: final_project_cs 코드 · 줄 근거는 w5/코어_에이전트_입출력 v3

일정이 깨지면 코어가 처리 건을 열고, 담당 에이전트 하나(요식 · 액티비티 · 이동)에게 일감을 줍니다. 에이전트는 조회 도구로만 값을 읽어 다시 점검하고, 대체 후보를 차례로 다시 점검해 통과한 안을 제안으로 돌려줍니다. 코어가 그 제안을 코드로 검사하고, 통과하면 새 일정 판과 알림 1번을 냅니다. 이 일을 감시(1분) · 새벽 점검 · 신고가 여행이 끝날 때까지 되풀이합니다.
참고 구조와 다른 점 셋 — 판정은 AI 가 아니라 코드가 합니다(세 에이전트는 AI 모델을 부르지 않음) · 검사와 복구는 별도 에이전트가 아니라 코어가 합니다 · 에이전트끼리 서로 부르지 않습니다(코어를 거침).

2. 층마다 받는 것 · 돌려주는 것

층누가받는 것돌려주는 것지금 상태
① 처리 건 열기코어 · 감시깨진 일정 항목 · 원인처리 건 1건 · 분류 값(요청 종류 · 문제 코드)구현
② 담당 고르기코어 · 컨트롤러처리 건일감(담당 · 일감 종류 · 도구 목록 · 마감 90초) + 근거 묶음(12,000 토큰)구현
③ 요식 에이전트에이전트일감 · 근거 묶음결과지 — 그대로 / 대체 식당 제안(+다른 안) / 못 함구현
③ 액티비티 에이전트에이전트일감 · 근거 묶음결과지 — 그대로 / 대체 활동 제안 / 「바꿀까요?」 / 못 함구현
③ 이동 에이전트에이전트일감 · 근거 묶음결과지 — 그대로 / 다른 경로 제안 / 못 함구현 · 고객 신고는 처리 안 함
조회 도구 층도구도구 이름 · 값일정 · 영업 · 외부 점검 · 교통 사건 · 규정 조각 — 못 읽으면 「모름」구현 · read.route · read.transit 미구현
④ 결과 검사코어결과지통과 / 막음(근거 · 실제 고객 것 · 판 번호)구현
⑤ 못 했을 때코어막힘 · 못 함 · 시간 초과오류 기록 · 일정 그대로 · 운영자 오류 알림구현
⑥ 적용코어 · 적용기일정 변경 제안새 판 1개 또는 묻기(보류 제안)구현
⑦ 알림코어 · 배달 일꾼새 판 · 알림 문구디스코드 알림 1번 · 여행계획서 새 판구현 · 채널은 팀 시연용 하나

4. 입구마다 — 에이전트를 거치는 것과 안 거치는 것

에이전트를 거치는 것은 감시 · 새벽 점검 · 사건 접수 API 로 열린 여행 건뿐이다. 고객 채팅은 여행 창구가 처리하지만 에이전트와 같은 계산 함수를 써서 결과가 갈리지 않는다.

입구받는 것처리에이전트AI 모델이 하는 일
계획 올리기글 · 사진 · 파일(5개 · 10MB · 글 20,000자)계획 읽기(코어) — 규칙이 먼저 읽고, 남은 줄만 AI 가 원문 위치를 가리킴 → 장소 하나로 정하기 → 확인 화면 → 등록거치지 않음AI: 사진 받아쓰기 · 원문 위치(시험 중)
일정 짜 줘빈 계획 · 「일정 짜 줘」일정 짜기(코어) — 후보는 우리 장소 표 · 관광공사 목록에서만, AI 는 줄 번호 순서만 냄 → 판정 통과 → 등록거치지 않음AI: 순서(시험 중) · 없으면 규칙 순위
채팅 — 묻기 · 바꿔 줘 · 늦어요 · 다른 안 · 되돌리기고객 문장분류 → 여행 창구 → 에이전트와 같은 계산 함수로 대체 고르기 → 설문 확인 → 새 판 · 알림거치지 않음(같은 계산을 공유)AI: 분류 · 신고 뽑기(시험 중)
감시 · 새벽 점검 · 사건 접수 API깨진 항목 · 여행 건그림 1 — 처리 건 → 담당 고르기 → 에이전트 → 검사 → 적용 → 알림거침AI 안 부름
일정 알림 — 하루 시작 · 다음 일정 · 출발시각저장된 최신 판을 읽어 「지금 할 일」을 알림 — 처리 건을 만들지 않음거치지 않음AI: 문구틀 번역만, 언어마다 처음 한 번

5. 참고 구조와 우리 구조 대응

참고 구조우리 구조있나
Identity & Delegation브라우저 사용자 키 · 여행계획서 링크 토큰 · 고객 번호 조건으로 다시 읽기있음 — 로그인은 없다
TARA++ (신뢰 · 비용 · 확신도로 에이전트 선택 · 재라우팅)② 담당 고르기 — 문제 코드 × 요청 종류로 하나를 고른다있음 — 단 신뢰 · 비용 점수로 고르지 않는다. 규칙으로 고르고, 받는 에이전트가 하나가 아니면 오류
A2A 에이전트 네트워크에이전트끼리 직접 부르지 않는다 — 코어를 거친다. A2A 원격 실행 통로는 코드에 있으나 시뮬레이터이고 꺼져 있다없음(쓰지 않음)
Planner Agent계획 읽기 · 일정 짜기 — 코어의 처리 단계에이전트 아님
Knowledge / Domain Agent③ 요식 · 액티비티 · 이동 — 영역마다 하나, 판정은 코드있음
MCP Tool Server조회 도구 층(허용 목록 · 횟수 한도) — 같은 서버 안 호출. MCP 는 바깥 AI 앱의 입구로만자리는 있음 · 규약은 다름
Vector RAG (pgvector)규정 조각 검색(bge-m3) — 규정 질문 답에만있음
GraphRAG (Neo4j)—없음
Evaluator Agent④ 결과 검사 — 코어의 코드(근거 · 실제 고객 것 · 판 번호) + 적용기 검사에이전트 아님 · 코드
Recovery Agent에이전트 안 「다음 후보로 다시」(최대 3곳) · 대체 소스 · 판이 밀리면 다음 감시에 다시 · 고객의 다른 안 · 되돌리기별도 에이전트 없음
Collusion Monitor에이전트가 한 건에 하나뿐이라 서로 맞춰 줄 여지가 없다해당 없음
Trust Update실행 중 신뢰 점수 갱신은 없다. 품질은 평가셋 → 재측정 루프(계획 읽기 90.2% → 97.0% 등)로 밖에서 본다없음

6. 설계와 코드가 다른 곳 — 발표 · 문서에서 구현된 것처럼 쓰지 않는다

설계 · 자료에 있는 것지금 코드
외부 소스를 3분마다 한 번 모아 여러 여행에 나눠 씀설계(D-017) · 미구현 — 지금은 1분마다 90분 앞 항목을 하나씩 점검
한 사건을 액티비티 → 요식 → 이동 차례로 넘기며 앞 에이전트의 초안을 넘김설계(피그마 공통 흐름) · 미구현 — 지금은 처리 건 하나에 에이전트 하나, 앞뒤 이동은 적용기가 다시 계산
이동 에이전트가 고객 신고(늦음 등)를 처리미구현 — 이동 신고는 오류로 끝남(채팅 창구는 별도로 처리)
고객마다 알림 받을 곳미구현 — 디스코드 채널 하나(팀 시연용)
낮 임시휴무를 시스템이 스스로 찾기결정(2026-09-29) · 미구현 — 지금은 고객 신고로
