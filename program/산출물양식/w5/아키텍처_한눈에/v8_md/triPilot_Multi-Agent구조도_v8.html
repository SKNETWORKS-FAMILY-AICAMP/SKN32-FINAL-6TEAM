triPilot 의 Multi-Agent 구조는 다음처럼 정리할 수 있습니다. 핵심은 오케스트레이터가 문제 하나마다 담당 에이전트 1개(요식 또는 액티비티)를 고르고, 에이전트는 허용된 툴로만 데이터를 읽어 대체 후보를 통과할 때까지 다시 점검하며(안쪽 루프), 결과는 검증 · 반영 · 알림을 거쳐 여행이 끝날 때까지 다시 트리거를 기다리는(바깥 루프) 구조입니다. 이동은 에이전트가 아니라 두 에이전트와 반영 단계가 함께 부르는 공용 판정 툴입니다.

이 구조에서 에이전트 사이의 연결은 오케스트레이터(에이전트끼리 직접 부르지 않음), 에이전트와 데이터의 연결은 툴 레이어(허용 목록 · 12회 상한), 데이터는 PostgreSQL + 외부 API 6종 + 시간표, 담당 선택과 결과 검증은 오케스트레이터가 담당하는 구조입니다. AI 모델은 계획서 줄 위치 찾기 · 분류 · 문장에만 쓰고(모델은 로컬 · API 비교 시험 중), 일정 판정에는 쓰지 않습니다.

시스템 구성도에서는 이를 트리거 → 오케스트레이터 → Worker Agent(후보 재점검 루프) → 검증 · 반영 → 알림 → 여행 끝? → 트리거의 순환형 구조로 표현하면 triPilot 의 핵심 — 계획을 받아 여행이 끝날 때까지 지킨다 — 이 가장 명확하게 드러납니다.
