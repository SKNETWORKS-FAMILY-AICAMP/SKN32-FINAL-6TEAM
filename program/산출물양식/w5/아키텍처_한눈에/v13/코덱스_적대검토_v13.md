**2. 사실·흐름 오류 — 틀림 / 과장 / 빠짐**

**2-1. 감시와 라우팅**

먼저 의심했지만 **깨뜨리지 못한 주장**을 분명히 한다.

- 기본 감시는 `DisruptionCheck(sources).check`를 실제로 사용한다. 여섯 작업은 `ThreadPoolExecutor`로 병렬 실행된다. `failed` 범주가 있으면 `fatal`, 그렇지 않고 `disruptions`가 있으면 `disrupted`, 나머지는 `clear`다.  
  근거: `scripts/run_sweepers.py:225–248`; `app/infrastructure/travel/disruptions.py:102–134`.
- 기본 감시에서 `fatal`은 집계 후 해당 항목을 건너뛴다. 그 결과로 변경·고객 알림을 생성하지 않는다. **“확인 불가→이번 항목은 변경하지 않음”은 맞다.**  
  근거: `app/modules/travel_ops/trip_watch_cases.py:88–95`.
- 감시가 만든 식사·활동 문제 코드의 접두로 해당 워커를 고르는 설명도 맞다. 개인 AI의 `tripilot_submit_itinerary`가 원문 읽기·웹 확인 화면을 건너뛰고 서버 등록 검사를 받는 선도 맞다.
