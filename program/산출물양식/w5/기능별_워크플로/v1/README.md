## 어떻게 만들었나

1. 코덱스가 cs 프로젝트 코드(`final_project_cs` 9e99c46c)를 읽고, 유스케이스 v7을 출발점으로 기능마다 자세한 흐름을 뽑았습니다. 상자마다 코드 줄 근거가 붙어 있습니다.
2. 자세한 흐름은 상자가 16개, 선이 40개에 이르러 그림이 엉켰습니다. 그래서 코덱스가 같은 내용을 「그림용 흐름」으로 줄였습니다. 규칙은 상자 11개 · 선 13개 이하, 위에서 아래로 큰 줄기 하나, 거꾸로 가는 선 없음, 오류 상자 하나입니다.
3. Claude가 그림을 검토해 5장의 흐름을 고쳤습니다([`src/patch_flows.py`](src/patch_flows.py)에 까닭과 함께 적음). 외국 글자 10곳도 고쳤습니다. 그림 속 숫자 4개(키 기한 90일, 키 10개, 시험 알림 20초 간격, 연속 실패 3번)는 설정 파일 · 코드와 직접 대조했습니다.
4. 자리 잡기는 Graphviz가 하고, 그리기는 「아키텍처 한눈에 v26」의 그림판(`dd.py`)이 합니다. 그래서 색 · 글꼴 · 범례가 v26과 같습니다.

다시 만드는 법:

```bash
cd src && python patch_flows.py && python build_figs.py && python build_doc.py
```

## 알아 둘 것

- 시험은 돌리지 않았습니다. 표의 「시험」 칸은 시험 파일을 읽어 적은 것입니다.
- 운영 설정 값(예: 해석 모드), 배포 상태, 실제 외부 서비스 응답은 확인하지 못했습니다. 기능마다 「확인 못 한 것」에 적었습니다.
- 기능 사이의 경계(예: F06의 「후보만 요청」이 F08로 이어지는 것)는 기능마다 「시작」 · 「관여자」와 표에 적었습니다.
