# guguroute 5주차 진행 경과 대본 (코덱스 판)

## 1장

5주차에는 자유여행자의 계획 접수부터 여행 중 이용까지 화면과 기능을 확장했습니다. 작은 모델 학습과 규정 검색도 검증했지만, 바뀐 화면의 실제 응답과 가르친 모델의 제품 연결은 남아 있습니다.

## 2장

웹 화면을 cs 프로젝트 서버에 붙였고 cs 프로젝트 전체 자동 시험은 4,245개가 통과했습니다. 모델 시험 문제는 모두 합성이며 사람 평가는 아직 없으므로, 높은 시험 성적을 실제 사용 성능으로 단정하지 않겠습니다.

## 3장

계획 올리기, 항로 지킴이 카드, 여행 화면을 포함해 화면 12개를 cs 프로젝트 서버에 붙였습니다. 여기 보이는 캡처는 모두 mock 서버 화면이며, 실제 응답은 10월 3일 계획 확인 화면의 읽기·결과·수정·등록만 확인했습니다. 그 뒤 바뀐 화면은 실제 응답을 다시 확인해야 합니다.

## 4장

개인 AI용 MCP 여행 도구와 웹 실시간 진행 시험은 각각 모두 통과했습니다. 팀 재배분은 mock 서버에서 확인했고, 여행 삭제와 디스코드·텔레그램 연결은 cs 프로젝트 서버 코드에 구현했습니다. 이 기능들의 x600 서버 반영과 실제 연결은 아직 확인하지 않았습니다.

## 5장

Gemma 4 E4B를 QLoRA로 가르치자 같은 769문제에서 정답이 688개에서 750개로 늘었습니다. 시드만 바꾼 재시험에서는 760개를 맞혔지만, 문제는 모두 모델이 만든 합성입니다. 아래 그림은 주간 사실에 있는 전체 시험 묶음만 발췌했습니다.

## 6장

가르친 E4B는 같은 769문제에서 학습 없는 큰 로컬 모델들보다 높은 정답 수를 보였습니다. 같은 방법으로 가르친 Winnow-E4B는 Jev 계열 모델이며 756개를 맞혔지만, E4B와 순위를 구분하려면 시드 3개 이상이 필요합니다. 상용 CLI 결과는 출제자 편향 때문에 이 비교에서 제외했습니다.

## 7장

GPU 서버 C에서 문제마다 실제 호출한 시험에서는 가르친 E4B 하나가 748개를 맞혔습니다. 규칙과 ML로 거르면 745개로 구분되지 않았고 E4B 호출은 19% 줄었습니다. 학습 없는 Winnow-E4B를 판정에 넣은 구성은 학습 조건이 달라 공정한 모델 비교가 아닙니다.

## 8장

학습한 e5-base 분류 인코더의 긴급도는 CX 400에서 88.4%였습니다. 제품 코드 그대로의 규정 검색은 10월 6일 독립 질문 48문제에서 정답 규정을 상위 3개 안에 30번 넣어 목표에 미달했습니다. 고객용 색인은 정답 노출을 늘렸지만 불필요한 규정 노출도 늘려 운영 반영을 결정하지 않았습니다.

## 9장

5주차 산출물 4종과 6주차 서비스 테스트 문서 1종을 만들었습니다. 요구사항 85개 중 구현 끝은 24개이고 일부 구현은 58개, 결정 대기는 3개입니다. 산출물은 모두 코덱스와 교차 검증하고 지적을 반영했습니다.

## 10장

사람 평가가 없고 가르친 모델도 제품에 아직 연결하지 않았습니다. 계획 읽기 값 변조와 일정 항목의 빈 답은 원인을 더 확인해야 하며, 엉뚱한 대상 변경과 일본어 알림의 금액 단위 변조도 발견했습니다. 바뀐 화면 대부분은 실제 응답을 확인하지 않았습니다.

## 11장

다음 주에는 바뀐 화면의 실제 응답을 확인하고 준비한 시트로 사람 평가를 진행합니다. 가르친 모델의 제품 연결을 검토하고 시드 3개 이상으로 순위를 확인하며, 규정 색인 개선도 분류기 뒤에서 다시 측정합니다. GPU 서버 B 대기열에 있는 다른 Jev 계열 후보도 같은 방법으로 가르쳐 비교합니다.
