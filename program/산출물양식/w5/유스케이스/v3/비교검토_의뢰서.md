# 검토 의뢰 — triPilot 유스케이스 「전체 한 장」 v2 와 v3 중 무엇이 나은가

두 그림은 같은 시스템(triPilot)의 유스케이스를 한 장에 그린 것이다. 사용자가 「v3 는 v2 와 비교하면 내용이 좀 다른 것 같은데 뭐가 더 나은가」를 물었다. **독립적으로** 비교해 의견을 내라. 그림을 만든 쪽(Claude)의 설명을 믿지 말고 파일을 직접 보고 판단하라.

## 자료(이 폴더)
- `v2_onepage.png` — v2 그림. 생성 코드 `v2_make_onepage.py`(구역 넷을 `v2_make_usecase.py` 의 `D` 클래스 · Graphviz 로 그려 위아래로 쌓고 구역 사이 선을 직접 그음)
- `v3_onepage.png` — v3 그림. 생성 코드 `v3_make_hand.py`(좌표를 손으로 잡은 SVG, 「유스케이스 2026-10-02 v6」 브리핑의 「한눈에」 그림 스타일)
- `v2_doc.html` — v2 문서(액터 표 · 유스케이스 목록 · 명세). 사실의 기준으로 쓴다
- `교재_유스케이스장.txt` — 표기 규칙의 기준(액터 · 경계 · 연관 · include · extend · 일반화 · 함정 3가지 · 시나리오)

## 해 줄 것
1. **내용 차이 목록** — 두 그림에서 노드(액터 · 유스케이스 · 세부 단계) · 관계(연관 · include · extend · 일반화) · 문구가 **다른 곳을 전부** 표로. 코드(`v2_make_*.py` vs `v3_make_hand.py`)의 노드 · 선 정의를 대조해 빠짐없이 센다. 「같다」고 하려면 대조 범위를 적는다.
2. **교재 규칙으로 판정** — 각 차이가 교재 규칙에 맞는가(예: 실선은 액터 ↔ 유스케이스만, 점선은 유스케이스끼리, 일반화는 같은 종류끼리, include 방향 = 기본 → 공통, extend 방향 = 추가 → 기본, 순서를 그리지 않는다, 같은 액터를 두 번 그리는 것 · 「참조 상자」로 다른 구역 유스케이스를 가리키는 것이 허용되는가).
3. **읽기 쉬움** — 선 겹침 · 엇갈림 · 글자 넘침 · 시선 흐름. 그림 PNG 를 직접 보고 판정.
4. **결론** — 기준별(정확성 · 규칙 준수 · 읽기 쉬움)로 어느 쪽이 나은지, 그리고 **최종 채택안**과 **채택안에서 고쳐야 할 것** 목록(구체적으로: 어느 노드 · 어느 선 · 무엇으로). 다른 쪽에서 가져올 장점이 있으면 적는다.

## 결과
마크다운 하나로 최종 답에 낸다. 추측과 확인한 것을 구분해 적는다.
