## 5. 세트별 한계 (한 줄씩)

- **769**: 전부 모델이 쓴 합성이고 일정이 5개뿐이라 문항끼리 독립이 아니다(고유 일정 항목 206쌍, 군집을 고려한 신뢰구간은 안 구함). mix8~11 은 Codex 출제 · mix12 는 Claude 출제라 **같은 계열이 푼 칸은 출제자 편향**이다. 같은 장소가 일정에 두 번 나오는 문제는 정답이 모호해 일부를 사전에 뺐고 남은 것도 라벨 모호가 있다.
- **요청 둘 66**: 정답 집합을 Claude 가 만들어 Claude 가 푼 「둘 다 찾기」는 불공정하다. 한 항목만 내는 모델은 구조상 0점이다.
- **D**: 잡담 1,300은 정답이 「없음」이라고 가정한 라벨(사람이 확인하지 않음)이고 일정 5개를 반복한다. 「일정 안 장소」 질문 300은 틀린 66건 중 59건이 같은 장소의 다른 방문을 고른 것이라 라벨 모호가 크다(baseline 리포트 §3-4).
- **D2**: 잡담뿐이라 정답 있는 질문의 정확도는 못 잰다. 오지목이 0~0.4% 로 바닥이라 더 줄이는 효과를 재기 어렵다.
- **D3**: 잡담 240을 Claude 가 써서 같은 계열 모델에 문체가 닮았을 수 있다. 정답 있는 120은 D 에서 뽑은 것이라 D 와 겹친다. 작아서 구간이 넓다.
- **H 시험용**: 문장을 솔 6.1 이 쓰고 루나 6.0 이 라벨해 둘 다 Codex 계열이며 사람 점검이 없다. 이견 64개(N1 32 · N6 13 · P2 10 · P3 7 · P1 2)는 뺐다. 일정 머리 30개에 **모두 앞 대화가 붙어 있어** 「그거」 같은 말(N4)의 정답이 앞 대화 때문에 달라질 수 있는지는 확인하지 못했다.
- **H 학습용**: 이견이 226개(N1 120 · N6 71)로 라벨이 갈리는 유형이 뚜렷하다. 시험용과 글자까지 같은 문장이 18개 있다.
- **검토자 입력**: 가르친 E4B 변형들이 실제로 고른 답만 모은 것이라 모델이 바뀌면 입력이 바뀐다. 맞은 답 · 틀린 답의 라벨은 D·D2·D3 정답에서 나온다.
- **CX 400**: 같은 합성 분포이고 두 라벨러가 어긋난 칸을 빼서 칸마다 표본이 353~398 이다. 학습 CL 과 글자까지 같은 문장이 4개 있다.
- **G96**: 사람 검수 전 Claude 초안 라벨이고 표본이 96 이라 구간이 넓다. 이 독립 자료에서는 학습한 분류기가 학습 없는 모델보다 낫다고 말하지 못한다(baseline 리포트 §2).
- **결정 단위 172**: 정답이 사람 검수 없이 Claude · cs · ui 세션이 단 표기다. 이름이 `cases_real` 이어도 실제 고객 자료로 볼 수 없다(기존 문서에도 같은 경고). 제품 지시문이 이 사례로 다듬어졌을 수 있다.
- **계획 읽기 60**: 합성이고 사람이 단 라벨이 아니다. 실제 사진 · 손글씨 · 저해상도를 대표하지 못하고 예약 문서 충돌은 넣지 않았다.
- **시나리오 10**: 일정 하루 1종 · 서울 1도시이고 모델은 흉내다. 다른 일정을 대표하지 않는다.
- **RAG A**: 정답 문장을 보고 쓴 질문이라 쉽다(개선 폭이 부풀려짐). **B**: 합성이고 정답 줄 1~3개 라벨에 같은 뜻의 다른 줄을 틀림으로 세는 모호함이 있다. **H**: 작성·라벨이 둘 다 Claude 계열이다. 규정 코퍼스가 130조각뿐이라 정답 조각 종류가 적다(B 32 · H 42).
- **RAG 다국어**: 합성 번역이고 의미 보존은 5개만 눈으로 확인했다. **일정 사실 질문 281**: 규칙 경로의 값이라 채팅 항목 짚기 성능으로 읽으면 안 된다. **섞은 입력**: KLUE-WoS 300 에는 규정 라벨이 없어 「규정을 보임 22.3%」를 오인으로 단정할 수 없다.
- **알림 번역**: 합성 알림 40개를 1회 돌린 값이다. **사람 평가**: 평가자가 1명이라 일치도(κ · α)를 못 내고, 화면에 Claude 의견이 같이 보였고, 틀리기 쉬운 쪽을 일부러 많이 뽑았다. 폴더의 [human_eval/README.md](../scripts/rag_gate/human_eval/README.md) 첫 줄은 「아직 평가하지 않았다」로 낡았다(CSV 에는 35행 판정이 있다).
- **이동 카카오 40쌍**: 정답이 아니라 비교 기준이고 한 번 읽은 값이다. **이동 회귀 186**: 정확도 시험이 아니라 판정기 출력을 잠근 표다.
- **옛 · 개발용 7세트**: 문턱·규칙을 고른 세트라 조합 값이 낙관적이다. 판정은 mix8 이후로 한다(결과표 README).
- **공격 사례 23**: 환불 금액 모양이라 지금 프로젝트에서 쓰는지 확인하지 못했다.

## 7. 확인하지 못한 것

- GPU 서버 A · B · C 에 있는 사본(학습 원본 train.jsonl, 모델별 결과 jsonl)은 열지 않았다. 서버 쪽과 비교한 것은 없고, 로컬의 두 사본(저장소 안 · 임시 폴더) train.jsonl 이 같음만 확인했다.
- 어느 세트에서도 **문장 하나하나를 사람이 검수한 기록**을 찾지 못했다(G96 은 「사람 검수 전」이라고 스스로 적음). 사람이 정답을 본 것은 사람 평가 35행뿐이다.
- D 의 `all_prompts.json` 을 쓰는 코드는 찾지 못했다(`chain_e2e.py` 의 `build()` 와 형식은 같으나 파일을 쓰는 줄은 못 봄). 관광지 질문 틀 516개는 baseline 리포트 인용이고 직접 세지 않았다.
- CX · CL 의 작성 원본(주제 묶음별 jsonl)은 저장소 안에서 찾지 못했다(`fixtures/cls/` 에는 조립본만 있다).
- 요식(dining) · 액티비티(activity) 팀 폴더의 평가 자료와 `tests/` 의 나머지 fixture 는 열어 세지 않았다. 이동 회귀 186 은 파일을 열어 센 값이고, 기대값 칸의 내용은 보지 않았다.
- 자동 시험 pytest 4,251개(통과 4,245)는 baseline 리포트 인용이고 이번에 다시 돌리지 않았다. 옛 쇼핑몰 시절 `eval/reports/` 결과 jsonl 도 열지 않았다.
- MX 세트는 생성 중이라 개수·위치를 확정하지 못했다.
- 사용자가 말한 「두 세트 합 296개」는 디스크에서 맞는 수를 찾지 못했다. 확인한 RAG 질문 수는 A 180 + B 160 = 340(답 있음 100 + 48 = 148)이고 보류 H 140 은 따로다.
- 학습과 시험 사이 겹침은 **글자 일치와 3-gram 자카드**로만 봤다. 뜻이 같은 의역은 못 잡는다.
- git 항목은 로컬 저장소의 추적·무시 상태이고 원격에 push 됐는지는 보지 않았다. `eval/datasets/_backup/` 폴더는 추적 여부를 따로 보지 않았다.
- 일정이 5개뿐인 세트의 군집을 고려한 신뢰구간은 계산하지 않았다.
- `chat7_d12.json`(369)과 `attack_fixtures.jsonl`(23)의 정확한 출처와 현재 사용처, `datasets/ml/` 자료의 여행 적합성은 확인하지 못했다.
- mix4 · ord2 · ord3 의 작성자는 스크립트에 적혀 있지 않다(결과표 README 도 mix4·mix5·heavy 를 「미확인」으로 적음). heavy · mix5 만 스크립트에 Claude 로 적혀 있다.
