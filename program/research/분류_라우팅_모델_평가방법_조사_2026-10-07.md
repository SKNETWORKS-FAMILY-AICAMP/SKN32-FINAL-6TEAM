# 「질의를 분석해 알맞은 에이전트에 넘기는 모델」을 상업용으로 내기 전 보통 무엇을 시험하나 — 2026-10-07 기준 조사

> 질문(사용자 2026-10-07): 우리가 할 일은 사용자 질의를 분석해 어떤 문제인지 파악하고 알맞은 에이전트에 일감을 넘기는 것이다. 이런 모델을 논문·실무에서는 **상업용으로 쓸 수 있게 파인튜닝됐는지, 성능이 얼마나 나오는지 어떤 시험으로 보나.**
> 조사 방법: 웹 검색 12건(2026-10-07) + 논문 1편 원문 직접 읽기. **원문을 읽은 것은 ★표시**, 나머지는 검색 요약만 봤다 `[원문 미확인]`. 법률 항목은 법률 자문이 아니다.

## 한눈에

- **맞다.** 우리 일은 「의도·문제 유형 분류 + 담당 에이전트 라우팅 + 범위 밖이면 넘기지 않기」이고, Jev 계열 · 임베딩 · ML · 규칙은 그것을 푸는 수단이다. 일정 항목 짚기는 라우팅 뒤의 한 단계다.
- **성능 시험은 여섯 층이다**: ①정확도(표본·통계) ②범위 밖·기권 ③보정·일관성 ④견고성 ⑤실제 트래픽·사람 라벨 ⑥운영(지연·비용·감시). 우리는 ①②는 했고 ③④는 일부, **⑤는 비어 있다**(전부 합성 · 사람 평가 0건).
- **「상업용으로 쓸 수 있나」는 성능과 별개의 세 가지다**: 기반 모델 라이선스(Gemma 4 는 2026-04-02 부터 Apache 2.0 — 문제 없음) · **학습 자료의 약관**(우리 합성 자료는 Codex · Claude 가 썼다 — 두 회사 약관에 「경쟁 모델 학습 금지」 조항이 있어 확인이 필요하다) · 규제(한국 AI 기본법 2026-01-22 시행, EU AI Act 챗봇 고지 2026-08-02).

## 1. 외부에서 보는 평가 항목

| 층 | 무엇을 보나 | 근거(출처 등급) |
|---|---|---|
| ①정확도·통계 | 시험 세트 정확도, **거시 F1 과 가중 F1 을 같이**(가중−거시 > 0.10 이면 소수 클래스 붕괴 신호), 클래스별 정밀도·재현율, 혼동행렬, **부트스트랩 95% 구간 + 짝지은 검정(McNemar)**. 클래스당 100~200개 골든셋(실제 빈도로 층화) | ★Rodrigues & Vas 2026(arXiv 2608.20371): ATIS 893 · CLINC150 5,500 에서 부트스트랩 구간·짝지은 검정으로 RoBERTa 대 LLM 비교. 골든셋 크기·F1 차이 기준은 실무 블로그(Future AGI)라 약한 근거 `[블로그]` |
| ②범위 밖·기권 | 「이 시스템이 다룰 일이 아님」을 알아보는 비율(OOS 재현율 · F1), 도구 호출 평가의 **무관성(irrelevance) 탐지** = 맞는 도구가 없으면 호출하지 않기 | ★CLINC150 OOS: 학습한 RoBERTa OOS 재현율 58.1 대 Claude 제로샷 85.6. BFCL v4(Berkeley Function Calling Leaderboard, 갱신 2026-04-12)가 무관성 탐지를 별도 항목으로 둔다. 총점은 공식 페이지에 「모든 하위 범주의 가중치 없는 평균」이라 적혀 있다(2차 요약은 10/10/10/30/40 가중치라 해 **서로 다르다** `[충돌]`) |
| ③보정·일관성 | 확신도가 맞는 비율(ECE, **클래스별 보정**), 확신 낮으면 기권·되묻기·큰 모델 위임, **pass^k**(같은 일을 k번 시켜 k번 모두 맞은 비율) | τ-bench / τ²-bench(Sierra · Princeton)가 고객 응대 에이전트를 pass^k 와 최종 DB 상태·정책 준수로 본다 `[검색 요약]`. arXiv 2609.00949 「Calibration is the Bottleneck」: 집계 정확도가 행동 종류(도구 호출 · 되묻기 · 거절 · 확인)별 보정 실패를 가려, 맥락만 바꿔도 정확도가 +11.5 ~ −21.0 포인트 움직인다 `[검색 요약]` |
| ④견고성 | 오타·말투·잡음·패러프레이즈에서의 하락. 음성이면 TTS→잡음→ASR 로 WER 구간별 | ★같은 논문: SNR 0 dB(평균 WER 28.9%)에서 TF-IDF 80.0 · Claude 92.5. 행동 검사(CheckList)류 시험은 오래된 표준이다 |
| ⑤실제 트래픽·사람 라벨 | **실제 분포로 점수**(균형 세트 F1 은 「극장용」), 사람 라벨의 일치도(κ), 출시 후 월별 오류 군집 · 혼동행렬 재감사, shadow/카나리 배포 | Future AGI 블로그 `[블로그]` · 일반 실무 관행 |
| ⑥운영 | 지연 p50·p95, 건당 비용, 처리량, CI 의 거시 F1 회귀 감지, 분포 이동 감시 | ★같은 논문: RoBERTa 2.4 ms 대 Claude Haiku API p50 981 ms · p95 1,787 ms(약 10³배) · 1,000건 $0.25 |

**모델을 고르는 법(★같은 논문의 결론)**: ①정해진 클래스 · 라벨 많음 · 지연 중요 → 학습한 인코더가 정확도 · 속도 · 비용 모두 이김(ATIS 95.9 대 84.1) ②클래스 많고 라벨 보통 → 동률(CLINC150 89.1 대 88.5, p=0.24) ③**배포마다 클래스가 바뀜 · 라벨 없음 → 프롬프트로 스키마를 주는 LLM**(학습한 분류기는 새 앱의 클래스에서 정확히 0%, LLM 은 두 앱 모두 약 94%) ④범위 밖 처리가 안전에 중요 → LLM 또는 빠른 분류기 위에 LLM 기권 ⑤확신 낮을 때만 LLM 으로 넘기는 혼합이 이득 대부분을 가져간다(Arora 2024와 같은 방향).

**라우팅 전용 벤치**(「어느 LLM 에 보낼까」이지 「어느 에이전트」는 아니다): RouterBench(약 40.5만 추론 결과 · 모델 11개 · 과제 7개), LLMRouterBench(40만+ 질의-모델 쌍 · 데이터 21 · 모델 33 · 방법 10), RouterEval, TwinRouterBench — 지표는 정확도 · 비용 곡선 · 파레토 · 지연 `[검색 요약]`.

## 2. 우리 프로젝트에 대응

| 층 | 우리가 한 것 | 비어 있는 것 |
|---|---|---|
| ① | 769문제(요청 둘 제외) 엄격 계수 · 부트스트랩 · McNemar · 시드 3개(평균 752.7, 범위 748~760) · 분류 네 축 거시 F1 · 긴급도 표본 353 분모 명시 | 클래스별 표본이 적은 칸(대상 종류 flight 등 약한 클래스)의 구간 |
| ② | 잡담 · 관광지 · 범위 밖 유형을 넣은 D 시험 2,735문제(가르친 E4B 오지목 4.4%, 학습 없는 12B 17.1%) · 일상 대화 1,300개 오지목 5.3% | 라우터 단계의 OOS 재현율을 따로 표로 낸 적 없음 |
| ③ | ECE(CX 에서 0.014~0.042) · 결정 단위 pass^3 91.3% · 확신도 되묻기 설계(§89) | 클래스별 보정 곡선, 서비스 실행기에서의 보정 |
| ④ | 오타·구어체·헷갈리는 이름 등 유형별 시험 · 양자화(Q4 손실 0) · 실행기별 비교(HF 4비트 대 llama.cpp) | 말투 변형 체계 시험(패러프레이즈 묶음), 음성 잡음(우리 입력은 문자) |
| ⑤ | **없음** — 모든 질문 · 정답이 모델이 쓴 합성이고(Codex · Claude), 사람 평가 0건(사용자 결정으로 v2 안 함) | **출시 후 실제 질문 로그로 같은 시험 다시 재기**, 사람 라벨 일치도 |
| ⑥ | 지연 p50·p95 · 처리량(서버 A GPU 동시 4 시간당 15,159건) · 비용 비교 | shadow/카나리, 분포 이동 감시, CI 회귀 감지 |

**시험 방법에서 이미 외부 권고와 맞는 것**: 같은 문장 짝지은 비교 + 구간, 시드를 여러 개, 읽기 실패를 오답으로 세기, 출제자 편향 표시, 학습-시험 2-gram 겹침 제거. **외부 권고와 다른 것**: 균형 합성 세트 점수를 주 지표로 쓴다는 점(「극장용」 경고) — 출시 전에는 실제 빈도로 가중한 값을 함께 낸다.

## 3. 「상업용으로 쓸 수 있나」 — 성능 밖의 세 가지

1. **기반 모델 라이선스**: Gemma 4 는 2026-04-02 부터 **Apache 2.0**(이전의 Gemma 전용 약관 폐기). 파인튜닝 · 상업 배포 · 재배포가 허용되고 조건은 저작권 고지 유지 정도다 `[검색 요약 · 2차 자료 다수, 공식 LICENSE 본문은 올라마 모델 정보에서 Apache 2.0 으로 확인]`.
2. **학습 자료의 약관 — 확인 필요**: 우리 학습 · 시험 자료는 Codex(OpenAI)와 Claude(Anthropic)가 쓴 합성 문장이다. OpenAI 이용약관은 출력으로 **자사와 경쟁하는 모델을 개발하는 것**을 금지하고, Anthropic 상업약관 §D.4(2025-06-17 판)는 **경쟁 제품·서비스(경쟁 AI 모델 학습 포함)**를 만드는 것을 금지한다 `[검색 요약]`. 우리의 일정 항목 짚기용 소형 모델이 「경쟁 모델」에 해당하는지는 법적 판단이고 우리가 결론 낼 수 없다 — **상업 전환 전에 약관 원문과 법무 확인이 필요하다.** 학업용 단계에서는 문제가 아니라고 단정하지도 않는다. 또 **AI Hub 데이터 약관(상업 이용 · 재배포 · 국외 반출)은 검색으로 확인하지 못했다** `[미확보]` — 시험에 쓴 일상 대화 문장의 출처 약관을 원문으로 확인해야 한다.
3. **규제**: 한국 **AI 기본법**(2026-01-22 시행)은 생성형 AI 서비스의 사전 고지 · 결과물 표시, 고영향 AI 의 위험 평가 · 사람 감독, 국내 대리인 지정을 요구하고 과태료(최대 3천만 원)는 1년 계도기간 뒤에 적용한다. EU AI Act 의 챗봇 투명성(제50조: AI 와 대화 중임을 알림)은 2026-08-02 부터이고 고위험 AI 는 2027-12-02 로 미뤄졌다 `[검색 요약, 로펌·블로그 2차 자료 — 실제 서비스 지역에 맞춰 원문 확인]`. 고객 응대에서 모델이 사람 대신 판단을 내리는 범위(예: 환불)는 사람 감독 요건과 맞물린다 — 우리 설계는 「팀은 제안만, 실행은 승인」이다.

## 4. 이 조사의 한계

- 검색 요약은 원문과 다를 수 있다. 원문을 직접 읽은 것은 arXiv 2608.20371 하나다(영어 ATIS · CLINC150, Claude Haiku 한 모델 · RoBERTa 한 모델, 저자도 한계로 적음). 한국어 · 다중 의도 · 여행 도메인에서는 값이 다르다.
- 한국어 의도 분류 공개 시험 세트(MASSIVE ko-KR: 의도 60 · 슬롯 55, 3i4k 6.1만 문장 7클래스 · KLUE-TC)는 있으나 **우리 도메인(여행 일정 · 요식 · 이동)에 맞는 라우팅 시험 세트는 공개돼 있지 않다** — 그래서 합성 세트를 쓴 것이고, 이것이 ⑤층의 빈 칸이다.
- 안 해본 것: 원문 확인(BFCL 가중치 충돌 · τ²-bench · RouterBench 의 세부), 한국 AI 기본법 · EU AI Act 조문 원문, Gemma 4 공식 LICENSE 원문, OpenAI · Anthropic 약관 현재 판 원문.
