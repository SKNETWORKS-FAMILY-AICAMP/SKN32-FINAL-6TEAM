# Claude Sonnet 5.5 검토 반영 판단

검토자: Claude Code CLI의 `claude-sonnet-5-5`, Codex. 두 차례 읽기 전용 설계 검토입니다. Claude는 전달한 사실·문서 발췌와 수정 계획을 읽었고 저장소 도구·실제 앱·DB에는 접근하지 않았습니다. 사람이 검수했거나 제품 시험을 통과했다는 뜻이 아닙니다.

## 합의한 설계 방향

- 고객 웹·개인 AI 연동·공유 계획서는 같은 여행 상태를 이용하며 역할과 인증 수단을 명시합니다.
- 웹 쿠키·개인 AI 키·공유 토큰·외부 시스템 키를 구분하고, 여행 소유자와 허용 작업을 매 요청 검사합니다. 개인 AI OAuth는 후속 단계입니다.
- 항로 지킴이의 일반 자동 변경, 고정 일정 확인, 재난 일정 정지를 구분합니다.
- 실시간 상담원 대기와 건별 수동 처리를 전제로 삼지 않습니다. 자동 해결, 고객 보완 입력, 개발자·QA의 사후 분석을 분리합니다.
- 외부 자료 실패는 해당 기능·요청에서 격리하고, 근거 없는 변경은 보류합니다. 다른 정상 항목은 계속 처리합니다.

## 2차 검토 후 구체화한 사항

| 항목 | 반영 판단 | 근거·한계 |
|---|---|---|
| 미응답 여행의 기본값 | 직접 켠 기록이 없으면 꺼짐·제안을 기본안으로 선택. 문구 정정이 아닌 동작 변경으로 표시 | `guardian.set_enabled`는 `survey_answered`에 명시 선택을 저장하고 `survey.auto_on_disruption`은 그 기록을 확인합니다. 실제 전체 경로·옛 데이터 호환성은 미검증입니다. |
| 재난 정지 종료 | 고객 명시 재개 원칙 유지. 여행 종료 후 남은 일정이 없으면 감시·재안내만 종료하고 정지 이력 보존 | 최신 REST 계약의 정지 우선 규칙을 사용합니다. 종료 처리의 구현 완료는 주장하지 않습니다. |
| 조회 실패 안내 | 주자료·대체 자료의 예산 소진으로 영향 확정 시 장애 회차별 안내, 정상 재검증 후 복구 안내 | D-017의 점검 소스 실패 무통지 문장을 대체하는 제품 정책 변경입니다. 사용자 위임에 따른 기본 추천안이며 아직 코드 반영 전입니다. |
| 유지보수 권한 | 고객 상담 관리자는 두지 않음. 개발자 설정·배포·QA 권한은 별도 유지보수 역할 | 설정 조정 기능이 있다는 사실을 실시간 상담 조직이 있다는 뜻으로 해석하지 않습니다. |
| 기존 고객 문의 화면 | 건의·문제 신고 기록 화면과 응답 계약으로 개편 | 실제 `support.tsx`의 운영팀 답변 대기 문장과 `web_cookie.py`의 운영자 문의 안내를 확인했습니다. 이번에는 수정 대상에 등록했습니다. |
| 진단 저장 실패 | 제한된 마스킹 영속 대기 파일과 같은 발생 ID 재전송, 포화·유실 관측 | DB와 대기 파일이 모두 실패하면 영속 기록을 보장할 수 없습니다. 수집 성공으로 세지 않습니다. 신규 구현 계획입니다. |
| 공유 토큰 수명·폐기 | 여행별 공유 중지·재발급·만료 보강을 계획 | 현 생성 모듈은 HMAC이며 자체 만료·개별 폐기 정보가 없습니다. 전체 경로와 배포 상태를 확인한 뒤 보강합니다. |
| 쿠키+키 동시 요청 | 기존 400 `ambiguous_credentials` 거부 규칙 유지 | `web_cookie._identify`에서 직접 확인했습니다. 이번 실행 시험은 하지 않았습니다. |

## 그대로 채택하지 않은 의견

- 1차 검토의 “대기열이나 외부 관측 도구는 상담원 큐를 만든다”는 단정은 채택하지 않았습니다. 진단 자료 처리 대기열과 상담원 인계 큐는 역할이 다릅니다. 세 선택지 모두 상담원 없는 운영을 유지합니다.
- Team이 읽기 도구를 쓰는 것과 변경을 직접 실행하는 것을 같은 위반으로 취급하지 않았습니다. 허용된 Port, 예산, 소유 범위, 근거 반환을 계약으로 강제하는 읽기를 추천합니다.
- Case 상태 변경과 여행 일정 버전 저장의 진입점을 혼동하지 않습니다. `transition_case`는 Case 상태를, 일정 실행기는 기존 버전·멱등·동시성 계약을 따릅니다.
- `escalated`의 전역 의미나 상태 이름을 문서 편집만으로 바꾸지 않습니다. 고객 응답 대응표를 먼저 정하고, 상태기계 변경이 필요하면 계약 판올림·이관을 별도로 수행합니다.
- 외부 조회 장애를 고객 입력 부족으로 바꾸지 않습니다. 고객이 고칠 수 있는 입력만 보완 요청합니다.

## 초기 정책 제안과 검증 제한

상세 진단 30일·집계 90일, 공유 만료 여행 종료+7일, 기록 쓰기 p95 100ms 또는 배경 대기 p95 60초가 15분 지속이라는 확장 조건은 Codex가 구체화한 **초기 정책 제안**입니다. Claude와 합의한 표준 의무값이나 실측 최적값이 아닙니다. 서비스 기존 보존 정책·부하 시험·자료 삭제 시각과 대조한 뒤 적용합니다. 이번 작업은 자료를 삭제하거나 제품 설정을 바꾸지 않습니다.

공식 원문은 인증·권한·로그·장애 격리·재시도·대기열 부하 완충 원칙의 근거입니다. 해당 원문이 triPilot의 자동 변경 정책이나 위 숫자를 규정하지는 않습니다.
