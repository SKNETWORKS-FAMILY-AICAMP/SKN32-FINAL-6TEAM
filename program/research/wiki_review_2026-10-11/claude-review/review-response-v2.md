# guguroute 아키텍처 독립 검토 (검토 전용, 구현 증거 아님)

전제: 파일 경로는 제공된 사실에 이름만 있어서 문서명으로 적었다. 구현 시 `Grep`으로 실제 경로를 확인해야 한다. 아래 수치와 만료값 중 "(가정)" 표시는 실측이나 결정 전 정책 가정이다.

## 1. W04 인증/권한

**결론**: 선택지 A를 추천한다. 주체 4종을 한 표에 묶되 인증 수단은 합치지 않는다.

| 선택지 | 내용 | 판정 |
|---|---|---|
| **A (추천)** | 공유 토큰 / 쿠키 세션+CSRF / 고객 에이전트 키 / 테넌트 `require_scope` 키를 분리 유지하고 권한표만 통합 | 기존 소유자 격리와 일치 |
| B | 에이전트 키와 외부 시스템 키를 한 키 체계로 통합 | 고객 권한과 테넌트 권한이 섞여 격리가 깨질 위험 |
| C | OAuth를 지금 필수 범위로 | OAuth는 설계뿐이고 확장 기능을 필수로 만들지 말라는 제약에 어긋남 |

**신뢰경계와 권한표**

| 주체 | 인증 | 가능 | 금지 | 만료/폐기 | 구현 상태 표기 |
|---|---|---|---|---|---|
| 공유 계획서 열람자 | 여행별 토큰 | 해당 여행 읽기 | 쓰기, 타 여행 | 만료·재발급은 근거 없음 → "미정" 표기 | 확인 필요 |
| 웹 회원 | HttpOnly 세션+CSRF | 본인 여행 읽기/쓰기 | 타인 여행 | 세션 만료값 미확인 | 문서 명시 |
| 웹 게스트 | 세션 쿠키 | 여행 1개, 감시 불가 | 항로 지킴이, 2번째 여행 | 세션 종료. 회원 로그인 시 10-09 문서대로 이관 | 문서 명시 |
| 고객 에이전트 | 별도 키 (해시 저장) | read / write 분리 | 계정관리, 타 여행 | 기본·최대 90일, 개별 폐기 | rest-endpoints: 12개 시험·구현 파일 존재 |
| 외부 시스템 | 테넌트 `require_scope` 키 | 스코프 내 | 고객 에이전트 경로 | 기존 정책 | 기존 |

- MCP 쓰기는 별도 스위치이고 기본은 꺼짐이다.
- 권한은 서버가 매 요청마다 자원 단위로 판정한다 (OWASP Authorization). LLM은 스코프나 권한을 결정하지 않는다.

**반영 문장**
- D-CS-012 상단: "상태: 구현 파일과 시험 12개의 존재가 rest-endpoints에 기록됨. 실행 통과·배포 여부는 이번 검토에서 미확인. OAuth는 설계만 있고 출시 범위가 아니다."
- 옛 안내 문서: "D-CS-011·012로 대체됨 (2026-10-11 기준)"
- 권한표에는 "공유 토큰은 소유자 편집 권한과 무관하다"를 명시한다.

**구현작업**: 위 표를 인증 허브 문서 1곳에 두고, 옛 안내에는 대체 표지와 링크만 남긴다. 공유 토큰 만료·폐기는 현 코드 확인 후 "있음/없음"만 기록한다. 없으면 갭 항목으로 올린다.

**완료기준 (검증사례)**
- 타 회원 여행 접근이 거부된다.
- 공유 토큰으로 쓰기가 거부된다.
- read 키로 write가 거부된다.
- 폐기한 키가 즉시 거부된다.
- 에이전트 키로 계정관리가 거부된다.
- 테넌트 키로 고객 여행 접근이 거부된다.
- MCP 스위치가 꺼져 있으면 쓰기가 거부된다.
- CSRF 없는 POST가 거부된다.
- 로그에 키·토큰 평문이 없다 (OWASP Logging).

**근거와 한계**: OWASP Session/Authorization/Logging, MCP authorization 2026-07-28. 표준은 guguroute의 만료 수치를 정해주지 않는다. 실행 결과는 미조회다.

## 2. W05 자동복구 → 고객 보완입력 → 사후분석

**결론**: 선택지 B를 추천한다.

| 선택지 | 내용 | 판정 |
|---|---|---|
| A | 로그 파일만 남김 | 집계·영향 고객 산출 불가 |
| **B (추천)** | 일반 스키마의 이벤트 테이블과 지문 집계 테이블. 소비자는 개발자·QA 배치 조회뿐 | 현재 규모에 맞음 |
| C | 외부 티켓·큐 시스템 | 실시간 운영자 큐를 만들게 되어 금지 방향과 충돌 |

**흐름**: 자동복구 시도 → 실패하면 고객 보완입력 요청 → 입력되면 재검증 → 근거가 되는 추천안은 가능한 만큼 생성 → 이벤트는 사후분석용으로만 기록한다.

**최소 필드**: `event_id`, `occurred_at`, `tenant_id`, `trip_id`, `kind`(unresolved_place / bug / outage), `error_code`, `fingerprint`, `stage`, `recovery_outcome`(auto_recovered / input_requested / input_done / abandoned), `build_version`, `idempotency_key`, `payload`(마스킹된 불투명 값).

- Core는 도메인 어휘를 모르므로 `kind/code/fingerprint`만 일반 필드로 두고 장소명 등은 payload에 둔다.
- Team은 `ActionProposal`만 반환하고, 기록은 Core/실행기가 outbox로 쓴다.

**지문과 집계**
- 지문은 `error_code + stage + 정규화한 질의 또는 예외 타입`의 해시다.
- 집계 테이블은 `fingerprint, first_seen, last_seen, event_count, distinct_trips, distinct_customers, status(new/triaged/fixed)`를 둔다.

**데이터 문제**

| 문제 | 규칙 |
|---|---|
| 신뢰 | 고객 입력은 비신뢰 입력이다. 검증 후 사용하고 LLM이 일정 DB에 쓰지 않는다. |
| 보존 | 원본 이벤트 N일, 집계는 장기 (N은 정책 가정, 개인정보 규칙과 대조) |
| 폭주 | 지문별 쓰기는 카운터 증가만 하고 샘플 payload는 K개까지 (가정) |
| 중복 | `(trip_id, fingerprint, 회차)` 멱등키 |
| 재처리 | 수정 배포 후 개발자가 재현용으로 재실행할 수 있다. 일정 변경은 `transition_case`로 새로 제안하고, 과거 이벤트로 자동 재적용하지 않는다. |

**확장**: 현재는 같은 DB 테이블에 일 단위 집계를 둔다. 트리거는 "이벤트 쓰기가 본 트랜잭션 지연에 영향" 또는 "집계 지연이 하루 초과"이며, 수치는 실측 전 가정이다. 이후 큐로 평탄화(Queue-Based Load Leveling)하고 `tenant_id`/날짜로 파티션하며 관측 지표를 추가한다.

**반영 문장**: "처리 실패는 기록되며 사람이 실시간으로 대응하지 않는다. 고객은 보완 입력으로 직접 진행하고, 기록은 개발자·QA의 사후 분석에만 쓰인다."

**완료기준**
- 동일 실패 100건이 집계 1행(count=100)이 된다.
- 개인정보 필드가 payload에 없다.
- 소비 경로가 대시보드·배치뿐이다.
- 같은 요청 재전송으로 중복 이벤트가 생기지 않는다.

**한계**: 실제 DB 규모는 조회하지 않았다. 모든 수치는 가정이다.

## 3. W06 장애 격리/재시도/복구

**결론**: 선택지 B를 추천한다.

| 선택지 | 내용 | 판정 |
|---|---|---|
| A | 옛 결정15, 한 여행 실패 시 앱 전체 정지 | 격리 원칙(Bulkhead) 위반 |
| **B (추천)** | 자료·여행 단위 격리, 재시도 후 회로 차단, 일정 유지, 상태별 1회 알림 | |
| C | D-018 그대로 (사람이 처리) | 미합의 초안이고 사람이 없음 |

**상태 3분리**

| 상태 | 일정 | 표시 |
|---|---|---|
| 외부 조회 오류(일부) | 유지, 검증 불가 변경은 적용하지 않음 | "이 항목은 확인하지 못했습니다" |
| 고객 필수입력 없음 | 오류가 아님, 질문 상태 | 입력 요청 |
| 재난 정지 / 무결성 실패 | 별도 정지 | 정지 사유. 재난은 명시 재개까지 유지 |

- 조회가 실패해도 이미 걸린 재난 정지는 해제되지 않는다.
- 기동 시 필수 자료가 없으면 그 기능만 비활성화하고 앱 전체를 내리지 않는다. 옛 결정15는 "대체됨"으로 표시한다.
- 재시도는 지수 백오프+지터에 상한 횟수를 둔다 (횟수·간격은 가정). 연속 실패하면 Circuit Breaker로 차단하고 반개방으로 복구한다.

**알림 중복 방지**: 키는 `(trip_id, source, 에피소드id, 전이종류)`로 한다. 에피소드당 장애 1회, 복구 1회만 outbox로 발송한다.

**D-CS-014**: `escalated`는 "처리 불가 기록됨"으로 의미를 재정의하거나 이름을 바꾼다. 배경 경로는 고객 알림을 추가한다. LLM 재배분 횟수 제한은 유지한다.

**반영 문장**
- D-018 상단: "이 문서는 합의되지 않은 초안이다. 아래 방향은 검토 제안이며 확정 시 별도 결정으로 승격한다."
- 본문의 "사람이 처리"는 "기록 후 개발자 사후 분석"으로 바꾼다.

**완료기준**
- 자료 하나를 실패시켜도 일정이 유지되고 "검증 불가" 표시가 뜬다.
- 같은 에피소드의 알림이 1회다.
- 필수입력 누락과 조회 오류가 서로 다른 코드와 문구로 나온다.
- 재난 정지 중 조회 실패에도 정지가 유지된다.

**근거와 한계**: Azure Bulkhead, Circuit Breaker, Retry. 표준은 guguroute 숫자를 정해주지 않는다.

## 4. W02/W03 정리

**W02 선택지**: A 접점 4개를 이름으로 나열한 현재 범위표(추천), B 기능 매트릭스만 둠, C 현행 유지.

대체 문장: "사용자는 ① 웹 화면(회원·게스트) ② 외부 에이전트(REST/MCP) ③ 공유 계획서(읽기 전용)로 쓰고, 외부 시스템은 테넌트 키로 연동한다. 최초 일정 구성은 제품이 책임지고, 변경 후보 생성은 근거 있는 추천안까지만 만든다."

상담원 관련 표현은 삭제한다.

**W03 미응답 기본값 선택지**: **A (추천)** 미응답=꺼짐(`ask_first`), B 미응답=켜짐, C 옛 여행만 replace 유지.

사용자 방향이 "고객이 켜면 자동 적용"이므로 A가 표시와 동작을 일치시킨다. 조건표(위가 우선):

1. 재난/지진: 모드와 무관하게 일정 정지+공식 대피 안내, 명시 재개까지 유지
2. 고정한 일정: 켜도 묻는다
3. 항로 지킴이 `enabled=true`: replace (자동 적용 후 결과 제시)
4. `false` 또는 미응답: `ask_first`

기존 fixed·재난 조건은 삭제하지 않는다. rest-endpoints 908줄의 자정 자동해제 문장은 "대체됨: 재난 정지는 사용자 명시 재개까지 유지"로 표시한다.

**별도 호환성 결함 (W03-b)**: 옛 미응답 여행은 표시가 false인데 기존 replace 동작이 남는다. 이는 migration 또는 기본값 정렬 항목으로 따로 올린다. 추가 확인한 `guardian.is_on`(→`survey.auto_on_disruption`, 직접 선택 기록이 없으면 False)과 `pending.decide`(`on_disruption`을 따로 읽음)의 기준 차이는 정합성 검사 대상일 뿐 실행 버그로 확정하지 않는다.

**완료기준**
- 조건표 1곳이 정본이고 `grep "자정"`에서 대체 표지 없는 줄이 0이다.
- 정합성 시험: `survey_answered` 없음 × `on_disruption` 값 조합에서 `is_on`과 `decide` 결과를 표로 비교한다. 이 시험은 아직 실행하지 않았다.

## 5. 추천을 그대로 반영하면 위험한 항목

- **W12**: Team의 읽기 도구 직접 사용은 "Team은 ActionProposal만 반환" 원칙과 충돌할 수 있다. 읽기도 Core 조회 경유와 `tenant` 범위 검사를 계약에 넣고, 부수 효과 없음은 시험으로 확인한다.
- **W16**: "최종 담당"을 운영 담당자로 읽으면 사람 운영 구조가 부활한다. 개발 소유 기준임을 명시한다.
- **W08**: "항목별 질문·실패 결과"에 `escalated`를 재사용하지 않는다. W05/W06의 상태 어휘로 통일한다.
- **W09**: 낮 휴무 감지가 불확실할 때 근거 없는 자동 변경을 하지 않는다. 호출 예산 수치는 가정으로 표시한다.
- **W07**: 5분/10분은 "검증 전 목표"로 유지한다.
- **W18**: 원격 서비스·DB를 조회하지 않았으므로 "확인 시각" 칸에 추정값을 채우지 않는다. 미확인으로 둔다.
- **W11**: D-CS-012의 12개 시험은 존재 기록이다. 통과를 완료로 쓰지 않는다.
- **W13**: 대조군 시험은 삭제하거나 단순 비활성화하지 않는다.
- **W20**: 이번 사용자 확정 방향은 출처와 날짜를 붙여 별도 결정으로 기록하고, 일괄 accepted 승격은 하지 않는다.
