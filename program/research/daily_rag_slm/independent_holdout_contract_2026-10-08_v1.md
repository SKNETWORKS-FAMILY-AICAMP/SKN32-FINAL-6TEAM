# 독립 보류 자료 준비 계약 — 2026-10-08 초안

새 일정과 새 문구로 정상 요청 240개·기존 항목 선택 없음 480개를 준비하되, 정답 검수와 중복 확인을 마치기 전에는 최종 검증에 쓰지 않습니다. 이 파일은 **지역 준비 초안이며 문서 정본이나 채택된 새 합격 기준이 아닙니다.** 아래 구성 비중·복합 출력·검수 절차는 **검토 대기 제안**입니다. 기존 합격 기준을 사후 바꾸지 않습니다.

## 확인한 기존 계약과 경계

`[실측: 파일 확인]` [당일 요구](2026-10-08.json)의 `holdout`은 `not_created`이며, 정상 240·부정 480, 일정·문구 분리, 정답 검수, exact/near 중복 검사, 답안 생성 전 해시 고정, 보류 자료로 튜닝하지 않음을 요구합니다.

`[실측: 소스 확인]` B/C는 같은 문항을 다르게 채점합니다. B는 정답 집합 중 하나를 맞히는 기준, C는 전체 집합 정확 일치입니다. D와 H의 주 비교는 단일 번호 또는 없음이며, E는 실행 이름 MX에 해당합니다. 기존 MX의 실제 두 항목 요청은 `MX6b` 도전용으로 분리되어 주 합산에 들어가지 않습니다. 새 보류 자료의 복합 요청 결과를 기존 MX 단일 요청 합산과 같은 수치처럼 비교하지 않습니다.

이 계약은 일정 항목 인식만 다룹니다. 검색 근거의 정확성, 고객별 데이터 격리, 도구 실행·실제 일정 변경·장시간 무료 운영의 합격을 대신하지 않습니다. 여행 도메인만 사용하고 쇼핑몰 시절 자료를 가져오지 않습니다. 실제 고객 개인정보나 제3자 소개글을 복사하지 않습니다.

## 기본 720문항의 구성 — 검토 대기

| 정답 층 | 세부 유형 | 목표 |
|---|---|---:|
| 정상 요청 | 기존 항목 하나의 정보·확인 | 100 |
| 정상 요청 | 기존 항목 하나의 변경·취소·교체 | 80 |
| 정상 요청 | 두 항목을 말하되 최종 요청은 하나 | 20 |

| 합계 | 정상 240 + 선택 없음 480 | 720 |

‘선택 없음’은 서비스가 응답하면 안 된다는 뜻이 아닙니다. 예를 들어 전체 일정 변경 요청은 유효한 여행 요청이지만 기존 항목 하나로 오지목하면 틀립니다. `has_service_request`와 `gold_item_ids`를 분리해 기록합니다. 지시어의 대상이 불명확한 문장도 일정 항목 선택 없음으로 채점하며, 올바른 후속 안내는 별도 서비스 시험에서 확인합니다.

모든 기본 문항은 고객이 보낼 수 있는 평문으로 작성합니다. 최소 480개는 잡담·상황 설명 안에 요청 또는 요청처럼 보이는 표현이 자연스럽게 포함된 문장으로 정합니다. 기존 문장에 잡담 조각을 기계적으로 붙이는 생성 방식은 사용하지 않는 제안입니다. 720개는 목표 수이며 실사용 분포의 추정값이 아닙니다.

교차 층은 서로 겹칠 수 있으므로 위 합계에 더하지 않습니다. 언어 구성은 한국어 576·영어 72·일본어 36·중국어 36, 각 언어에서 정상:선택 없음=1:2를 제안합니다. 한국어 576개는 존댓말144·짧은 구어체144·메신저/오타144·장문/서툰 한국어144로 나눕니다. 별칭·오타, 날짜·순서·시간, 같은 장소의 반복 방문, 설명만으로 특정하기, 인용·철회·유사 지명 함정을 태그로 표시합니다. 다국어 검수 가능 인력을 확보하지 못한 언어는 ‘검수 대기’로 남기며 다른 언어로 몰래 대체하지 않습니다. 다국어는 인식 진단이며 현재 제품 언어 범위 확대를 뜻하지 않습니다.

## 일정·문구를 분리하는 방법 — 검토 대기

1. 최소 60개 신규 서울 여행 일정을 먼저 작성합니다. 일정은 날짜·시각·장소·유형·방문 순서를 포함하고, 원값을 보존합니다. 같은 일정을 표현만 바꾸거나 번호를 섞는 것은 신규 일정으로 세지 않습니다.
2. `schedule_family_id`를 부여해 같은 구조를 변형한 일정과 같은 질문의 말투·번역 변형을 같은 가족으로 묶습니다. 가족 전체를 한 분할에만 둡니다. 학습·개발·기존 평가에서 쓴 가족은 보류셋에 넣지 않습니다.
3. 익숙한 서울 장소 이름 자체가 등장하는 것은 허용하되, 일정의 항목 조합·순서·시각과 요청 문구의 재사용을 검사합니다. 새로운 고유명사로 바꿨다는 이유만으로 독립성을 인정하지 않습니다.
4. 작성자에게 기존 실패 답안·모델 점수·보류 모델 답안을 보여 주지 않습니다. 기존 실패 유형은 추상 범주만 안내하고 기존 문장을 고쳐 쓰는 방식은 금지합니다. 합성 자료는 합성으로 표시하며 실제 고객 표본이라고 부르지 않습니다.

## 저장 필드와 출력 계약 — 검토 대기

기본 레코드는 `id`, `schedule_id`, `schedule_family_id`, `item_ids`, `schedule`, `query`, `language`, `style`, `category`, `has_service_request`, `gold_item_ids`, `request_spans`, `gold_reason`, `ambiguity`, `source`, `review_state`, `author_id`, `reviewer_ids`를 포함합니다. 작성·검수 기록과 판별 대상 모델 답안을 분리합니다. 사용자나 기계의 실제 접속 정보를 기록하지 않습니다.

- 단일 요청의 정답은 항목 ID 하나입니다. 선택 없음은 빈 집합입니다. 후보별 어댑터는 단일 번호/`null`을 같은 집합 표현으로 변환합니다.
- 복합 40문항의 정답은 두 항목 ID 집합입니다. **전체 집합 정확 일치(C)**를 주 지표로 삼고, 일부 일치(B)는 진단용으로만 냅니다. 단일 번호만 반환하는 실행기는 40문항을 제외하지 않고 표현 한계로 실패를 기록합니다. 복합 출력 경로를 추가할 때 보류 자료를 보지 않고 개발 자료에서 먼저 고정합니다.
- 다른 항목 ID·여분 항목·중복 ID·잘못된 형식·미완료는 사전 parser 계약으로 실패 처리합니다. 허용된 JSON 집합 형식과 순서 무관 여부를 실행 전에 고정하며, 모델별로 답을 본 뒤 예외를 넣지 않습니다.
- 과거 MX와 연결하는 점수는 단일 정상 200개와 선택 없음 480개로 분리합니다. 복합 포함 정상 전체 240개의 정확 집합 일치는 새 확장 지표이며 기존 95% 기준의 적용 여부는 **검토 대기**입니다. 전체 240개 점수로 단일 200개의 회귀를 숨기지 않습니다.

## 정답 검수와 모호함 처리 — 검토 대기

각 기본 문항을 두 사람이 서로의 라벨이나 모델 출력을 보지 않고 검수합니다. 둘은 일정에서 근거가 되는 항목과 요청 구절을 표시하고, 선택 없음은 왜 기존 항목을 고를 수 없는지 적습니다. 불일치는 제3자가 판정합니다. 모델끼리 합의했다는 이유로 사람 검수를 완료 처리하지 않습니다.

실제로 여러 정답이 가능한 문장은 원래부터 그럴 목적인 복합 유형과 구분합니다. 의도한 단일 정답이 검수로 확정되지 않는 문장은 **해시 고정 전에** 격리하고 새 독립 문항으로 채웁니다. 격리 이유·원문·검수 이력을 보존합니다. 모델 결과를 본 후 어렵다는 이유로 제거하거나 정답을 바꾸지 않습니다. 해시 고정 후 정답 결함이 발견되면 원판 결과와 영향 문항을 공개하고 새 버전으로 별도 재검증합니다.

각 기본 문항에는 의미를 유지한 요청/핵심 내용만의 대조 문장을 하나 연결합니다. 정답 집합은 두 문장이 같아야 합니다. 선택 없음도 감상·전체 변경·일정 밖 질문 등 본래 의미를 유지하며, 삭제해서 엉뚱한 문장을 만들지 않습니다. 대조 문장도 두 사람이 검수합니다. 따라서 검수할 입력은 **기본 720 + 대조 720 = 1,440개**이며, 두 사람이 맡는 독립 검수는 총 2,880건입니다. 이는 준비 목표이고 완료 수가 아닙니다.

## exact/near 중복 검사 — 검토 대기

검사 대상 파일 목록과 SHA-256을 먼저 manifest로 남깁니다. 범위는 기존 학습 원본·`train.jsonl`·`train_oos.jsonl`·`train_oos2.jsonl`·새 후보가 사용한 모든 확장 학습자료, B/C fixtures와 gold, D/D2/D3 입력, H의 학습/시험 생성·라벨·합의 자료, MX의 요청·자연 혼합·라벨·전체 자료, 혼합 시험·독립 개발 자료입니다. 실제 포함 파일과 읽지 못한 파일을 로그에 남기며, 누락이 있으면 ‘전체 검사 통과’로 표시하지 않습니다.

일정·질문·요청 구절·대조 구절을 각각 원문과 Unicode NFC/공백 정규화 값으로 exact 검사합니다. 문자 3-gram Jaccard ≥0.6을 near 후보로 올립니다(기존 D2 방식과 연결). 장소·날짜·시각을 자리 표시로 바꾼 문장도 별도 검사해 명사만 바꾼 복사를 잡습니다. near 경보는 의미 독립성 검수를 거치며, 번역·짧은 공통 표현·동일 장소 때문에 자동으로 전부 제외하지 않습니다. 검사 설정은 출력 전에 고정합니다.

near 검사 하나가 의미상 중복을 모두 검출했다고 주장하지 않습니다. 보류 내부의 중복·대조 짝·번역 가족도 검사하며 대조 짝과 같은 가족의 의도적 유사성은 별도 표시합니다. 중복 후보 수·실제 제거 수·검수한 수·미해결 수를 분리합니다. 미해결은 해시 고정의 차단 사유입니다.

## 해시 고정과 학습 접근 차단 — 검토 대기

저장은 git 제외 데이터 구역인 `datasets/travel/<새 보류셋 이름>/` 아래 raw·processed·scripts·REPORT 규칙을 따릅니다. 실제 경로와 등록은 구현 담당자가 정하며 이 초안에서는 폴더를 만들지 않습니다.

720/720 기본 작성, 1,440/1,440 입력 정답 검수, 일정 가족 분리·중복 검수, 720쌍 의미 일치, schema·ID 검사 후 원문/가공/정답·대조·parser·프롬프트·판별 문턱·manifest의 해시를 **첫 모델 답안 생성 전** 고정합니다. 고정 시각, 검수자, 검사 로그, 모델 revision·양자화·엔진·시드·반복 계획을 기록합니다.

학습 도구에는 허용된 학습 파일 manifest만 전달하고 보류셋 경로는 기본 탐색 대상에서 제외합니다. 학습 입력 manifest와 보류 manifest의 교집합을 실행 전에 확인하는 실패 차단이 필요합니다. 학습 담당자는 정답을 읽지 않으며 평가 담당자는 모델·프롬프트·문턱을 고정한 뒤 실행합니다. 아직 이 접근 차단은 **구현·검증 전**입니다. 경로를 다르게 두었다는 사실만으로 차단 완료라고 쓰지 않습니다.

첫 결과를 본 이후에는 보류 자료로 학습·프롬프트/문턱 조정을 하지 않습니다. 결과를 개선 재료로 사용한 판은 ‘개발 자료로 전환’ 표시 후 새 독립 자료가 필요합니다. 반복 실행은 신뢰성·편차 확인이지 새 독립 표본이 아닙니다.

## 분모와 합격·구간 해석

기존 정본의 사전 기준은 **정답 선택 ≥95%, 선택 없음 오지목 ≤1%, 혼합에 따른 선택률 손실 ≤2%p, 오지목 증가 ≤1%p**이며 지정 부류의 오지목 ≤3%도 확인합니다. 새 시험의 의미·분모·복합 계약이 다른데 기존 통과와 같다고 쓰지 않습니다. 단일200·부정480에 이 기준을 적용하는 연결 방식과 층별 배분은 검토·고정 전입니다.

정상 정답률 분모는 단일200, 복합40, 합계240을 따로 유지합니다. 부정 오지목 분모는480, 성공한 없음 응답도480 기준으로 냅니다. 잘못된 형식·누락·시간초과·호출 실패는 정상에서는 오답, 부정에서는 없음 정답으로 인정하지 않습니다. **관측된 오지목 수와 실패 수를 각각 공개**하고 오지목이 적다는 이유로 오류가 많은 판을 합격시키지 않습니다. 미완료 판은 최종 합격·순위를 대기합니다. 혼합/대조의 실패를 쌍째 삭제하지 않고 고정한 전체 분모와 양쪽 실패 수로 보수적으로 보고하며 실패 처리에 따른 구간을 별도 표시합니다.

관측 비율에는 Wilson 95% 구간, 섞임 차이에는 일정 가족 단위 군집 부트스트랩 구간, 같은 문항 비교에는 짝지은 정확검정을 함께 냅니다. 보류 문항이 같은 일정·언어 가족에 속하면 독립 표본 720개로 단순 가정하지 않습니다. 반복은 run별 결과·범위·실패를 따로 내고 합쳐 분모를 늘리지 않습니다. 여러 모델·층의 비교 횟수를 밝히며 작은 p값 하나로 최종 우열을 선언하지 않습니다.

**관측 95%가 실제 모집단 정답률 95%를 입증하는 것은 아닙니다.** 480개에서 오지목 4개면 관측 기준 ≤1%에는 맞지만 95% 구간의 상한이1%보다 클 수 있습니다. 신뢰구간 전체가 기준을 충족해야 한다는 추가 승격 규칙은 현재 정본에 확정된 요구가 아니므로 **검토 대기**로만 제안합니다. 자료가 적어 구분되지 않으면 우열·상용 적합성을 확정하지 않습니다.
