# Claude 인계 — Winnow·Saluki 학습 및 E2 비교

이번 세션의 작업큐 등록은 끝났습니다. 학습·평가 결과가 완료된 것은 아닙니다. 현재 실행과 수치의 근거는 [등록 보고서](../../../final_project_cs/wiki/records/reports/2026-10-12_winnow-saluki-queue-registration-and-handoff.md)와 보고서가 연결한 비공개 상태 원본입니다.

## 바로 이어서 할 일

1. 루트·cs 프로젝트의 `AGENTS.md`, `RULE.md`, 문서 관리 규칙과 [GPU 운영 정본](../../../final_project_cs/wiki/operations/gpu-work-queue.md)을 먼저 읽습니다. GPU 작업은 기존 A4000 한 기계만 사용합니다. ADA2000을 재시작하지 않습니다.
2. 작업 폴더에서 다음 명령을 실행합니다. 개인 연결 설정은 검사기가 git 밖 설정에서 읽습니다. 이 명령은 A4000의 작업을 시작·중단하지 않습니다.

   ```powershell
   python program/scripts/plan_qa_bench/inspect_model_queue_20261012.py
   ```

   결과의 관측 시각·선행 실행 생존 여부·등록 수·남은 공간을 확인합니다. 이전 보고의 진행 수치를 현재 값으로 사용하지 않습니다. 선행 HF 장시간 시험이 끝날 때까지 기존 dispatcher가 대기하는 것은 정상입니다. 별도 GPU worker를 만들지 않습니다.
3. 완료·실패가 생겼으면 다음 명령으로 원본 답안·어댑터·로그를 로컬에 회수합니다. 같은 종료 상태는 중복 회수하지 않습니다. 보관 파일의 해시와 목록도 함께 저장하며 압축 파일을 자동으로 풀지 않습니다.

   ```powershell
   python program/scripts/plan_qa_bench/inspect_model_queue_20261012.py --collect
   ```

   로컬 파일은 [비공개 인계 자료 폴더](../../../datasets/travel/model_queue_handoff_20261012/)에 생깁니다. 실제 접속 별칭·기계 경로·manifest 백업·등록 상세는 이 폴더와 [Winnow 등록 원본](../../../datasets/travel/winnow_upgrade_20261012/)·[Saluki 등록 원본](../../../datasets/travel/saluki_training_queue_20261012/)에서 확인합니다. 공용 문서에 복사하지 않습니다.

## 실행 순서와 조건

큐의 순서와 입력을 다시 만들지 않습니다. 먼저 부분 읽기 로직 진단, Winnow 원본 준비·기존 판 비교·새 학습·추론 연결 확인·추가 비교가 등록돼 있습니다. 그 뒤 보존된 기존 비교와 Saluki 학습·변환·추론 연결 확인·추가 평가가 이어집니다. 정확한 현재 순서는 검사기의 manifest 스냅샷으로 확인합니다.

Winnow는 기존 기반을 보존하고 첫 보강 자료의 `oos`와 두 번째 보강 자료로 새로 학습하는 `oos2_cosine_s20261019`를 비교합니다. 새 레시피는 자료뿐 아니라 학습률도 다르므로 개선 원인을 자료 하나로 단정하지 않습니다. Gemma는 비교군이며 Winnow가 우선 후보입니다. E2는 어떤 모델의 학습에도 넣지 않습니다.

Saluki는 실제 약27B 원본의 혼합 IQ 가중치를 고정한 맞춤 LoRA 실험입니다. CPU 검증과 합성 변환 검증만 통과했고 전체 GPU 학습은 미검증입니다. CUDA 계산·원문 스모크·전체 학습·변환·동일 추론기 활성 확인을 모두 통과해야 후속 평가가 준비됩니다. 자세한 구현과 한계는 [Saluki 실행기 검증](../../../final_project_cs/wiki/records/reports/2026-10-12_saluki-packed-lora-executable-and-cpu-validation.md)을 읽습니다.

기반 캐시와 변환 파일 일부는 메모리 파일시스템에 있어 재부팅하면 사라집니다. 끝난 학습 어댑터와 변환 파일은 조기에 로컬로 회수합니다. A4000 디스크 3GiB 잔여를 유지하며, 가드 실패를 풀기 위해 기존 모델을 삭제하거나 실패 작업을 반복하지 않습니다. 실패 원인을 고치고 새 시도와 사전 조건을 명시한 뒤 기존 단일 큐에 추가합니다.

## E2 결과를 읽는 방법과 남은 구현

- E2 원시 모델 계획은 현재 제품 프롬프트와 다른 진단 계약입니다. 엄격한 JSON 일치 실패를 곧바로 의미 오답으로 세지 말고 동등한 표현을 먼저 검토합니다. HTTP·로딩·출력 형식 실패와 의미 오류 후보를 구분하고 실패·누락도 계획 분모에 남깁니다.
- 정답 계획을 실제 앱의 읽기 함수에 넣는 부분 진단이 등록돼 있습니다. 시작 시각·체류 시간의 명시적 대상만 지원합니다. 그 밖의 요청은 지원 밖으로 보존하며 통과로 세지 않습니다. 이 시험은 DB 변경·대화 문맥 해결·일정 CRUD 전체를 검증하지 않습니다.
- 다음 구현은 격리 DB와 실제 앱 실행기로 정답 계획을 주입하는 대조 시험입니다. 시간/날짜/장소, 복수 쓰기, 조건·의존성, 권한, 잠금, 실패 후 부수효과까지 실제 결과를 기록해야 합니다. E2의 합성 목표 계약과 현재 앱 계약이 다른 부분은 별도 차이로 표시합니다. 특히 E2의 오후 범위와 현재 앱의 오후 범위가 다르므로 이를 모델 오답으로 돌리지 않습니다.
- 모델 계획이 틀리고 정답 주입은 맞으면 모델 오류 후보, 계획이 맞아도 정답 주입이 실패하면 로직 오류 후보입니다. 양쪽 실패·표현 검토 미완료·실행 미지원·자료 누락은 미확정으로 남깁니다. 전체 사실 답변·사람 정답 검수·독립 보류 검증·제품 채택은 별도입니다.

## 보고·보존

기존 6시간 예약과 일일 연구 예약을 유지하고 새 예약을 만들지 않습니다. 새 결과는 한국어 존댓말·관측 시각·분자/분모로 보고합니다. 기존 집계·문서를 바꾸기 직전에 같은 폴더의 `_backup/날짜_사유/`에 백업합니다. 공개 게시·push·새 결제·새 임대·자동 제품 교체는 이번 인계 범위가 아닙니다. 이전에 거절된 Codex CLI 내부 경로·수치 외부 전송 검토를 우회 재시도하지 않습니다.

이 인계는 파일과 실행 명령의 준비입니다. 별도 Claude 세션을 자동 시작하거나 이미 Claude가 후속 계산을 수행했다고 표시하지 않습니다.
