# D/E 이후 대상 선택·근거·답변 통합 시험 계획

**방향은 맞습니다. 다만 D/E 문장을 이어 붙이기보다, 새로운 일정과 질의에서 ‘대상 선택→근거 검색→정확한 답변’을 단계별·전체로 재는 편이 좋습니다.** 기존 선택 점수가 높은 모델도 답변에 잘못된 시간이나 근거 없는 변경 완료를 넣을 수 있기 때문입니다.

| 작업 | 상태 | 진행 |
|---|---|---|
| 최근 직접 관련 논문 방법·조건·한계 검토 | 완료 | 4/4 =100% |
| 이전 연구·공식 평가 참고 | 완료 | 4/4 =100% |
| 평가 계약·개발 예시 | 초안·구조 검사 | 24/24 =100% |
| 예시 사람 검수·모델 평가 | 대기 | 각각0/24 =0% |
| 별도 개발480·독립 보류720 | 계획 수량 | 각각0/480·0/720 =0% |

확인일은2026-10-09입니다. 최근 검색과 연결된1차 출처를 확인한 범위이며 그날까지의 모든 논문을 망라한 조사는 아닙니다. 논문에서 나온 효과는 우리 여행 프로젝트 실측 효과로 쓰지 않습니다.

## 왜 새 시험이 필요한가

기존 D/E는 여행 요청의 대상 인식을 검사하는 개발 진단입니다. 답변 사실성·출처·복합 요청 전체 해결을 증명하지 못합니다. E의 혼합 요청도 코드로 이어 붙인 문장과 자연 작성 문장을 나눠 봐야 하며 사람 정답 검수와 별도 보류 검증이 남아 있습니다.

Saluki-27B 원본은 E 정상 요청997/1033이지만 기존 대상 없는 문장의 오지목157/974입니다. Winnow-E4B 여행 보강 학습판은 같은 부분1000/1033·20/974입니다. 둘 다 현재 E 오지목 기준을 만족하지 못합니다. 이 수치는 대상 선택 진단이며 답변 품질은 아직 측정하지 않았습니다. [재계수 원본과 모든 A~E 표](../../../program/scripts/plan_qa_bench/results/comparison_abcde_20261009_111621/comparison-complete.md).

## 추천 설계와 대안 비교

| 방법 | 얻는 것 | 놓치는 것 | 선택 |
|---|---|---|---|
| D/E 그대로 합친 뒤 답변 점수 하나 | 빨리 실행 가능 | 이미 본 질문의 누수·선택/검색/답변 원인 혼합 | 기존 회귀 진단으로만 유지 |
| 새 질문에 모델 답변을 다른 모델이 단일 점수로 판정 | 표현 다양성 | 평가자 편향·비슷한 장문에 높은 점수·날짜/숫자 오류 누락 | 보조 진단만 |
| **새 일정군+사실별 정답+단계별 조건+전체 통과** | 어떤 부분이 좋아졌는지와 실제 해결 여부 | 자료 작성·검수 비용 | **본 평가로 추천** |
| 실제 사용자 질의만 평가 | 현실성 | 초기 충분한 유형/정답 확보 어려움·고객 데이터 처리 필요 | 가상 시험과 별도 새 사람 작성 패널을 병행 |

판정과 자료 구성의 정본은 [통합 평가 계약](../../../final_project_cs/wiki/quality/selection-grounded-answer-evaluation.md)입니다. 새 계약은 제안 상태이며 기존 E 기준을 바꾸지 않습니다.

예: ‘어제 사진을 정리했어요. 오늘 전시관 마감과 저녁 예약 시간을 각각 알려 주세요.’는 두 대상과 두 사실을 모두 답해야 통과합니다. ‘기존 일정 말고 새 실내 장소 추천’은 기존 대상은0개여도 여행 요청입니다. 기존 일정 바꾸기 도구를 실행하지 않았다면 ‘변경 완료’라고 답할 수 없습니다.

## 자료와 공정한 실행

개발480개, 별도 보류720개를 제안합니다. 보류는 기존 항목 요청240개와 기존 항목 없는480개로 구성하되 후자에 전체 여행·새 장소 요청을 넣습니다. 학습/개발/보류를 일정군·장소/별칭·템플릿·출처 단위로 먼저 분리합니다.

현재 만든 [개발 예시24개](../../../datasets/travel/selection_answer_bench/2026-10-09_pilot_v3/REPORT.md)는 가상 사실과고유 일정1개의8유형×3문장(명목 범위ID3개이며 독립 일정3개가 아님)입니다.24/24 형식·근거 연결 검사와 기존 학습/평가 정규화 완전 일치0/24를 확인했습니다. 근접 의미·일정군 독립성·사람 검수·모델 실행은 미완료이며 독립 최종 검증으로 쓰지 않습니다.

두 사람이 정답·필요 사실·금지 주장을 독립 검수하고 합의한 뒤 자료/시드/프롬프트/판정 문턱/출처 해시를 잠급니다. 현실성 패널은 실제 고객 기록 대신 새 사용자가 여행 질문을 직접 작성하게 합니다. 확보 전에는 대기 상태로 둡니다.

선택 전용 모델은 동일 고정 답변기를 사용해 대상 선택의 영향을 재고, Saluki/Gemma 등의 자체 생성 답변은 별도 비교합니다. 원본·우리 학습판·개발사 결정 학습 여부를 표에 적습니다. 속도는 엔진/양자화/스레드/캐시를 고정하고 A/B를 교대로 실행합니다. 같은 문항 반복은 독립 정확도 분모를 늘리지 않습니다.

모델 수M과 진단 조건3개를 모두 돌리면 보류 기본 호출은720×3×M입니다.120개에3회 반복을 하면 첫 회를 뺀 추가 호출은240×M입니다. 세 조건 중 전체 조건을 모든 모델에, 원인 진단 조건을 최종 후보에만 적용해 비용을 줄일 수 있습니다. 토큰·벽시계·GPU메모리는 실제 스모크로 측정하고 비용 예상과 분리합니다. 출처 이상/대조 짝은 추가 호출로 따로 셉니다.

같은 질문을 여러 번 성공시켜도 사람 검수나 새 일정군 검증을 대체하지 않습니다. 새 기준을 통과해도 이것만으로 상용화 완료가 되지 않습니다. 실제 검색 출처 안정성·사용자 격리·승인·실패 복구·부하/제품 회귀·운영 절차가 별도로 필요합니다.

## Saluki·Jev 비교의 연결

Saluki는 사용자 명시 승인에 따라 [전담 추가 학습 계획](saluki_finetune_plan_2026-10-09.md)으로 진행합니다. 배포27B 원본과 정확히 같은 학습 표현을 확보하고 기존16GB GPU에서 역전파/공간을 검사한 뒤 새 어댑터로 스모크→본학습→동일 원본과 독립 검증을 수행합니다. 다른 checkpoint를 Saluki로 대신 부르지 않습니다.

Jev 계열 모델 중 Winnow-E4B와 Jevify의 과거 여행 학습판은 단일/요청없음769개에서 동률입니다. 최신 Winnow 보강판은 기본760/769이나 전체/복합/답변의 최고 모델 판정은 아닙니다.
