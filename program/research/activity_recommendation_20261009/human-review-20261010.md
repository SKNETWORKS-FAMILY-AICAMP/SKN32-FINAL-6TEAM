# 개발 문제 사람 검수 안내

기존24개 개발 문제를 두 사람이 독립 검수하는 자료를 준비했습니다. API 비용은 무료($0)이며 검수자2명과 불일치 조정자1명이 필요합니다. 검수 소요 시간은 아직 측정하지 않았습니다. 현재 완료된 사람 판정은0/48 = 0%입니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 정답을 뺀 검수 문제 | 준비 | 24/24 = 100% |
| 두 사람 독립 판정 | 대기 | 0/48 = 0% |
| 불일치 조정 | 대기 | 분모 확정 전 |

이 자료는 기존 모델 시험에 사용했던 문제의 ID·시설 이름·제시 순서를 바꾼 **개발 검수 자료**입니다. 새 문제나 미사용 평가 자료로 세지 않습니다. 검수자는 합성 정답·이전 모델 답·서로의 답을 보기 전에 판정합니다. 실제 운영 자료와 비교할 별도 사람 문제는 아직 수집하지 않았습니다.

## 준비할 자료와 결과

| 자료 | 무엇을 하는가 | 완료 후 확인 |
|---|---|---|
| [문제24개](../../../datasets/travel/activity_recommendation_bench_20261009/audit-20261010-v1/human-review-development/cases.json) | 고객 취향·중요도·방문 조건·후보 설명을 읽음 | 문제의 `case_id`와 후보 `id`를 확인 |
| [빈 판정 양식](../../../datasets/travel/activity_recommendation_bench_20261009/audit-20261010-v1/human-review-development/labels.blank.json) | 검수자마다 새 파일로 복사 | `labels.reviewer-a.json`, `labels.reviewer-b.json` 두 사본 |
| [후속 실행 기준](followup-plan-20261010.md) | 사람 검수와 새 모델 비교의 차이를 확인 | 기존24개는 개발 자료로만 표시 |

원본 양식과 기존 응답을 덮어쓰지 않습니다. 검수자별 사본은 문제와 같은 로컬 자료 폴더에 두고 공유 저장소에 올리지 않습니다. 정답 연결표는 검수를 배정하는 담당자만 관리하며 검수자에게 주지 않습니다.

## 문제 하나를 판정하는 순서

1. 고객 원문에서 좋아하는 것·기피하는 것·필수 조건을 구분합니다. 후보 설명의 성격이 실제로 드러나는 문장을 `trait_annotations`에 기록합니다. 사실이 부족하면 임의로 확정하지 않고 `uncertain`과 부족한 이유를 씁니다.
2. 방문 조건을 통과하는 후보들 중 선호하는 순서의 ID를 `preferred_top3`에 최대3개 넣습니다. 중요도와 이동·유사도를 함께 고려하고, 후보가 부족하면 가능한 수만 씁니다. 같은 순위로 허용되는 후보 집합은 `acceptable_ties`에 기록합니다. ID 문자열 자체를 추천 이유로 쓰지 않습니다.
3. `evidence_notes`에 후보 ID별 판단 근거와 고객 원문의 연결을 씁니다. 설명에 없는 성격을 보태지 않습니다. 필수 조건 위반과 단순 기피를 구분합니다.
4. 실제 사람이 수행했을 때만 해당 검수자 칸에 익명 `reviewer_id`, `is_human: true`, 시간대 포함 `reviewed_at`, `status: completed`를 씁니다. 다른 검수자 칸은 그대로 둡니다. 자동 생성 결과에 사람 완료 표시를 붙이지 않습니다.

아래 값은 양식의 예시이며 실제 문제의 답이 아닙니다. 기존 양식에는 구체적인 후보 ID를 복사합니다.

```json
{
  "reviewer_id": "reviewer-a",
  "is_human": true,
  "reviewed_at": "2026-10-10T15:00:00+09:00",
  "trait_annotations": {"<후보 ID>": {"quiet": "uncertain"}},
  "preferred_top3": ["<후보 ID>"],
  "acceptable_ties": [["<동점 후보 ID>", "<동점 후보 ID>"]],
  "evidence_notes": {"<후보 ID>": "설명 문장과 고객 선호를 인용하거나 위치를 적고 판단 이유를 기록"},
  "status": "completed"
}
```

## 독립 판정이 끝난 뒤

배정 담당자가 두 사본을 새 병합 파일로 합칩니다. 문제별 성격 판정 일치와 최상위 허용 집합 일치를 각각 세어 분자·분모로 보고합니다. 제3자가 불일치만 읽고 `adjudication`에 최종 판단·근거·조정자를 기록합니다. 두 원본 판정은 보존합니다.

사람 완료 여부는 JSON의 표시만 믿지 않고 실제 검수 수행 기록으로 확인합니다. 사람 검수 결과로 개발 규칙을 고칠 수 있지만, 같은24개로 수정 후 성능을 미사용 평가 성능처럼 발표하지 않습니다. [연구 전체 순서](followup-flow-20261010.html)는 검수와 후속 모델 비교의 대기 조건을 보여 줍니다.
