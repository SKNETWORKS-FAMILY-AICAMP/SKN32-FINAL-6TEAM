# 개선 실제 재시험 사전 기준

이번 시험의 주 질문은 **정해진 활동 후보 중 선택할 때 Jev API(유료)만으로 충분한가**입니다. 2026-10-10 사용자 요청에 따라 새 합성 원본과 새 실행기로 실제 호출합니다. 결과를 보기 전에 이 기준을 저장했습니다. 실제 사람 선호 검수와 장소 정보 조회를 수행한 시험은 아닙니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 새 합성 원본 | 생성 | 72/72 = 100% |
| 개발·평가 분리 | 고정 | 2/2 = 100% |
| 실제 API 시험 | 시작 전 | 분모 확정 전 |
| 사람 검수 | 미수행 | 0/48 = 0% |

## 예산과 범위

새 시험 전체(예비·개발·평가·반복)의 US$0.50·600호출 중 먼저 도달한 상한을 적용합니다. 이전$0.349834632를 더한 누적 예상 상한은$0.849834632입니다. 지정된 로컬 개발용 환경 파일의 cs 프로젝트 API용 OpenAI 키와 TypeSafe 키만 사용하며 키 값은 결과에 저장하지 않습니다. 기존 SDK2.44.0을 유지합니다. 실패에 자동 재시도하지 않습니다. 사용량을 모르면 예약 상한을 지출로 유지하고 실제 사용량이 예약을 넘으면 이후 호출을 잠급니다. 결제 명세서의 확정 청구액은 조회하지 않습니다.

## 고정 자료와 개선점

개발24개·평가48개이며 각 부분의 ID·명칭·제시 순서 난수 흐름을 속성과 분리했습니다. 원본은 [raw/v2](../../../datasets/travel/activity_recommendation_bench_20261009/retest-20261010/raw/v2/)입니다. 개발 해시는 `9d59df52439f8219522a518862645566c824dfc9543fb71dc92049969b6c2f7c`, 평가 해시는 `9a06effb7a9aa13bc3bc0e234be365068352cc654a7d57ede8369ea9246e8fe6`입니다.

서로 다른14갈래로 명시 선호·부정·동행자·중요도·동점·후보0/1/2개·누락·오래됨·미래 시각·외부 지시·잘못된 수치·필드를 포함합니다. 후보16·64·256개를 포함하되 대부분은16개로 비용을 제한합니다. 공예 제작과 직접 체험, 조용함과 혼잡의 문장 충돌을 사전에 고쳤습니다. 원문 인용을 정답 주장마다 보관합니다. 이 원문·정답도 AI가 작성·검수한 합성이며 고객 모집단을 대표하지 않습니다.

후보 없음·정보 불명·오류는 코드가 명시적 상태를 반환하고 API를 호출하지 않습니다. 가능한 후보1개는 모든 경로가 코드로 반환합니다. 이런 경계 문제의 통과를 모델 의미 이해 점수로 세지 않습니다. 주 품질·비용 비교 분모는 평가 자료 중 방문 가능한 후보가2개 이상인 문제입니다.

## 비교 계약

한 곳 선택과 상위3 순위는 다른 작업으로 나눕니다.

- **한 곳 선택:** Jev API(유료) Choice와 nano/Luna의 `none` 단일 ID 출력을 비교합니다. Choice의 선택 확률을 순위 효용으로 해석하지 않습니다. 후보가128개를 넘으면 묶음별 선택 후 승자끼리 비교하는 계층 선택이며 호출 수·비용·지연을 합칩니다.
- **상위3:** Jev API(유료)의 후보별 Score와 코드 순위, nano/Luna의 동일 프롬프트·`none/low`·출력 한도4096을 비교합니다. Score는 선호 제공과 기피 제공을 적용하고0~1로 제한한 취향값의0/.25/.5/.75/1 등급입니다. 모델이 반환한 기대 등급을4로 나눠 거리·분류 유사도와 코드로 결합합니다. 보정된 만족 확률이나 정확한 참 효용으로 부르지 않습니다.
- **선별+Luna:** Score 상위8개에 규칙 상위2개를 보호합니다. 선별 자체의 최고 후보 보존과 보호 후 보존을 따로 기록합니다. 후속 입력 순서는 원래 독립 난수 순서를 유지합니다. 개발 결과에서 골라 고정한 Luna 설정을 사용합니다.

개발24개에서 각 모델의 none/low를 같은 문제·설정 탐색 수로 비교하고 평균 순위 점수가 큰 설정, 동점이면 평균 비용이 낮은 설정을 선택합니다. 평가 자료에서는 네 설정 모두 보고하되 개발에서 선택한 설정의 비교를 별도로 표시합니다. Jev의 기준 문구는 이번 고정된 공식 형식이며 가능한 모든 문구·학습·보정을 탐색한 최적 모델 시험이 아닙니다.

규칙 기준은 별도 키워드 연구 기준입니다. 실제 Activity 고객 경로의 추천 구현을 그대로 재생했다고 표시하지 않습니다. ID만 정렬하는 대조군도 함께 기록합니다.

## 채점·반복·해석

형식·정확한 개수·중복·허용 후보·원문 인용·근거 ID 오류는 실패로 포함합니다. 같은 효용의 후보는 복수 정답으로 인정합니다. 출력 이유는 새 자유 사실 문장 대신 후보 설명의 정확한 인용을 반환합니다. 인용 존재와 추천 이유의 의미 타당성은 별개이며 사람 의미 검수는 미수행입니다.

최고 후보 적중, 순위 점수, 허용 상위후보 회수, 필수 조건 위반, 정상 출력, 실제 토큰·캐시 사용량·비용과 지연p50/p95를 보고합니다. Choice의순위 지표는k=1이며 상위3 지표와 섞지 않습니다. 비용은 경로별 합계와 실제 고유 호출 총액을 구분하여 공유 선별 호출을 중복 청구한 것처럼 합치지 않습니다. 캐시 사용량은 실제 응답값을 따르며 cold/warm을 통제한 실험이라고 부르지 않습니다.

평가의 조건을 만족하는 작은 문제 중 ID 순서로8개를 고르고 같은 입력 재실행·ID 전단사 변경+제시 순서 변경을 각각 한 번 추가합니다. 모델 답을 보고 선정하지 않습니다. 이16개 변형은 독립 표본을 추가한 것이 아닙니다. 순서 변형에는 일반 생성 변동도 포함되므로 단독 순서 편향의 인과 효과로 확정하지 않습니다.

평가 문제를 단위로5,000회 짝 재표집하여95%구간을 보고합니다. 기본 질문은 Choice 단독과 단일ID Luna의 최고 후보 적중 차이입니다. 추가 비교는 탐색적으로 표시합니다. 표본이 작고 공유 생성 틀이 있으므로 서비스 채택이나 실제 고객 정확도 우위를 확정하지 않습니다. 기존 후속 계획의 연구 채택 관문을 만족하지 못한 항목은 그대로 남깁니다.
