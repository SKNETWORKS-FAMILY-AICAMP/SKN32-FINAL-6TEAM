Jev API(유료)의 기존 구성은 성격 제공 여부의 Noul 확률을 가중합하고 0~1로 제한한 **보정하지 않은 확률 가중합 휴리스틱**입니다. 취향 강도나 정확한 기대 효용이라고 부르지 않습니다. 일반적으로 `clip(E[X])`와 `E[clip(X)]`는 다릅니다. 예를 들어 이진 혜택 X, 기피 Y가 독립이고 각각 확률0.5일 때 `clip(0.5-0.5)=0`이지만 `E[clip(X-Y)]=0.25`입니다. 후속 비교에서는 이진 사실 판정과 정의된 등급의 취향 적합도를 구분합니다. ## 차기 모델 비교를 실행하기 전 고정할 조건

1. ID·시설 이름을 효용과 무관한 난수로 생성합니다. 동일 문제의 ID 전단사 변경·후보 순서 변경·동일 입력 반복을 따로 배치하고, 반복을 독립 고객 표본처럼 늘리지 않습니다.
2. 두 비교를 분리합니다. 하나는 같은 프롬프트·출력 계약·`none/low` 교차 조건의 통제 비교이고, 다른 하나는 같은 조정 문제 수·같은 탐색 비용으로 모델별 최적 설정을 고른 비교입니다. 출력 한도는 조정 자료에서 충분히 끝나는지 확인하고 고정합니다. [nano 공식 설정](https://developers.openai.com/api/docs/models/gpt-5.4-nano), [Luna 공식 설정](https://developers.openai.com/api/docs/models/gpt-6-luna).
3. 핵심 대조군은 실제 Activity 규칙 재생, 독립 규칙 기준, nano 직접, Luna 직접입니다. 선별 후보는 Jev API(유료)의 명확한 이진 질문과 정의된 Score, 의미 점수+코드, 필요 시 재정렬을 구분합니다. 후보16·64·256개는 동일 후보 목록을 사용하고 검색 회수율은 별도 측정합니다.
4. 캐시 상태는 실제 응답 사용량으로 나눕니다. 첫 호출이라고 캐시 없음으로 가정하지 않습니다. cold/warm 조건을 통제할 수 없으면 관측 캐시 비율별 결과와 가정 계산을 분리합니다. 네트워크·실패·재시도·선별을 포함한 전체 p50/p95와 비용을 기록합니다.
5. 유료 실행 전 공유 비용 장부의 단일 실행 잠금·원자적 예약과 동시 시작·비정상 종료·사용량 누락 시험을 통과해야 합니다. 신규 예산과 호출 상한은 실행 전에 명시합니다. 현재 새 호출 예산은0입니다.

2026-10-10 공식 문서에서는 Luna의 별도 Decisions API도 확인했습니다. 고정 선택·조건 확률·등급에 대한 API이며 Responses로 긴 설명을 생성하는 경로와 다릅니다. 후속 등급 평가 대조 후보로 등록하되 한국어 여행 성능·계정 접근·지연을 시험하지 않았습니다. 기존 실행 환경의 SDK를 자동으로 교체하지 않습니다. 공식 문서의 속도 주장을 우리 실측으로 옮기지 않습니다.
