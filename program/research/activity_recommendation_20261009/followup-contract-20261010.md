이번 작업은 기존 실측의 채택 근거를 보완하는 독립 연구입니다. 운영 코드·DB·배포·키·기존 결과를 변경하지 않습니다. 신규 유료 API 호출은 하지 않으며 기존 비용·호출 수 상한을 늘리지 않습니다.

## 담당 범위

- 루트: 계획 재검토, 기존 응답의 비용 민감도 분석, 사람이 검수할 블라인드 자료 준비, 그림·최종 보고와 검수.
- recommendation_dataset: `program/scripts/activity_recommendation_followup/`의 새 코드·단위 시험과 `datasets/travel/activity_recommendation_bench_20261009/followup-20261010/`의 새 개발 시험 결과만 작성합니다. 기존 코드·자료·응답·보고는 읽기 전용입니다.
- recommendation_research: 기존 계획·실행기·보고서를 읽기만 하고, 실제 서비스 채택을 가로막는 오류·누락을 근거 위치와 함께 루트에 보고합니다. 파일을 쓰거나 API를 호출하지 않습니다.

## 개발 시험의 필수 계약

1. 비용이 없는 순수 Python 연구 모듈입니다. 운영 앱과 제공자 SDK를 import하거나 자격 정보를 읽지 않습니다. 네트워크를 사용하지 않습니다.
2. 실제로 준비된 사실인지 확인합니다. 최신성 기준은 명시한 aware timestamp와 `max_age_seconds`로 계산합니다. 누락·미래 시각·오래된 사실은 정상 추천으로 바꾸지 않습니다.
3. 방문 가능 여부를 코드로 계산하고 필수 요구와 취향을 구분합니다. 예산·이동+체류 시간·폐쇄·위험·무단차·야외 금지 조건을 확인합니다. 음수·NaN·bool 숫자·중복 ID·알 수 없는 필드를 거부합니다.
4. 실행 상태는 `ready`, `no_feasible_candidates`, `facts_unresolved`, `invalid_input`으로 구분합니다. 가능한 후보 0개를 정상 3개 추천으로 만들지 않습니다. 1·2개이면 남은 후보 수만큼 요청할 수 있게 반환합니다. 이는 연구 상태이며 운영 앱의 고객 메시지 정책을 변경하지 않습니다.
5. 모델 결과 검사는 후보 ID·중복·정확한 개수·근거 ID를 검사합니다. 근거 ID의 존재 확인과 설명문 의미의 사실성 검증은 구분합니다. 근거 ID만 맞는 설명을 사람 검수 완료로 표시하지 않습니다.
6. 동점은 복수 정답을 인정합니다. 후보 순서·ID 변경, 거리가 늘어남·예산 축소·선호 가중치 반전의 변화 관계를 시험합니다. 정답 계산기는 의미 이해 모델이 아닙니다.
7. 후보 수 16·64·256에서 필터와 검증을 실제 실행하되 LLM 품질·지연·검색 품질의 실측이라고 부르지 않습니다. 코드 연산 시간은 별도로 측정합니다.
8. 개발 자료·정답은 자체 합성이라고 표시합니다. 사람이 작성한 원문이나 미사용 보류 평가 자료라고 표시하지 않습니다. 사람 판정은 0건으로 남깁니다.
9. 생성·실행 결과는 새 경로에만 저장하고 존재하는 경로의 덮어쓰기를 거부합니다. 코드 변경이 필요하면 수정 직전에 `_backup/`에 복사합니다.
10. README에 재현 명령·입출력·경계·실행한 시험 수와 미검증 사항을 남깁니다. 루트가 별도로 실행하여 결과를 검수합니다.

## 종료 기준

기존 결과를 보존하고, 실제 서비스 적용은 보류합니다. 사람 정답 자료·별도 미사용 평가·모델별 설정·큰 후보 목록·캐시 조건·근거 사실성 검증의 통과 기준을 계획에 명시합니다. 준비된 코드 시험만 완료로 보고하며 사람 검수나 유료 모델 비교를 수행했다고 쓰지 않습니다.
