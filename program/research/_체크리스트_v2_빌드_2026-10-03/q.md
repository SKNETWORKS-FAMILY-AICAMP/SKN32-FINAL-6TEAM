# 정할 것
`여행자 확인 체크리스트`(사람이 일정표를 믿으려고 직접 하는 확인 72가지) 문서가 **서버 현황**을 주장한다. 그중 **「아직 없음」 34가지는 정말 코드에 없는가**, **「서버가 이미 판정」 5가지는 과장이 아닌가**를 코드를 읽어 **반증**하라.
(「아직 없음」은 「찾았고 안 나왔다」는 뜻으로 적혔다. 이름을 바꿔 구현된 것은 놓쳤을 수 있다 — 그것을 찾는 것이 이 질문의 목적이다.)

# 선택지 (항목마다 하나를 고른다)
- FOUND_FULL — 이 확인을 하는 코드가 있다(어느 경로에서든). 경로와 `파일:줄` 을 댄다.
- FOUND_PARTIAL — 일부 경로·일부 조건에서만 한다. 어느 경로 · `파일:줄` · 빠진 부분을 댄다.
- NOT_FOUND — 아래 읽을 곳에서 찾았고 안 나왔다. 무엇을 찾아봤는지(검색어)를 적는다.
- (「이미 판정」 5가지에만) CONFIRMED / OVERCLAIM(과장 — 이유).
OTHER: 빠진 선택지가 있으면 제안하라.

# 「경로」의 뜻 — 같은 확인도 어느 길에서 도는지가 다르다
- 생성 = 우리 일정 생성기가 일정을 **짤 때**(app/modules/travel_ops/planner.py)
- 등록 = 고객·외부 에이전트가 만든 일정을 **받을 때** 판정(app/modules/travel_ops/itinerary_checks.py 의 check_itinerary, trip_api.py 의 등록, intake/ 의 읽은 일정 확인)
- 감시 = 여행 중 **점검·대체**(trip_watch*.py, itinerary_changes.py, replan.py, dawn_check.py, trip_reminders.py, activity/ · dining/ · mobility/ 팀 코드, pending.py, itinerary_actions.py)
- 응답 = 결과가 **고객 화면·API 응답**에 나가는가(trip_api.py 의 응답 만드는 곳, place_info.py, 알림 문구)
