# 외부 저장소 6종 조사 — 우리(guguroute)가 참고·반영할 내용이 있는가

조사일 2026-10-05(조사 기준 2026-10-04) · 요청: 사용자(저장소 이름 6개 + 「반영할 만한 것 리서치, 코덱스 솔도 시켜」) · 조사자: **Claude 하위 작업(Opus)** 과 **Codex `gpt-6-sol`**(웹 검색 켬, 읽기 전용)에게 **같은 의뢰서**를 따로 맡겼다. 두 보고서의 의견이 갈린 곳은 표에 둘 다 적었다. 사실 표기: [열어서 확인함] = 보고자가 저장소 원문을 웹으로 열어 읽음 · [요약만 봄] · [확인 못 함]. **우리가 직접 연 것은 없고 두 보고서를 맞춰 본 것이다** — 별 개수·갱신일은 보고자 값이며 검색 요약과 실제 페이지가 어긋난 곳이 있었다(ai-engineering 별 31,940 ↔ 페이지 63.6k).

## 한 줄 결론
**둘 다 가치가 있다고 본 것: Impeccable(웹 화면 자동 검사)·Hindsight(여행별 기억).** 한쪽만 강하게 본 것: Anthropic Financial Services(Claude 상 / Codex 중), Paperclip(Claude 하 / Codex 상). **둘 다 이번 범위에서 뺀 것: VoiceStudio.** 어느 것도 통째로 들이지 않고 패턴만 작게 옮기는 쪽으로 의견이 같다(발표 2026-10-26, 비용 상한 건당 10,000원, 사람 대기 없음).

## 지금 당장 할 수 있는 작은 실험(각 반나절 이내) — 두 보고서에서 겹치거나 가치가 큰 것
1. **웹 화면 자동 검사(Impeccable) — 합의.** 웹 소스 폴더와 개발 서버 주소에 `detect --json`(모바일 폭 375×812 포함)을 돌려 결과만 저장. 성공 = API 키 없이 2분 안에 끝나고 상위 20건 중 진짜 문제가 절반 이상이면 CI 에 「알림만」 단계로 넣는다. `[패키지를 내려받는 일이라 실행 전에 사용자 허락을 받는다]`
2. **고객 메시지 속 지시 문장 막기(Financial Services 구조) — Claude 제안.** 「쓰기 도구를 불러라」 「팀을 바꿔 넘겨라」를 섞은 시험 문장 20개로, 분류가 도구 없이 5라벨 JSON 만 내는지·Team→Core 넘김이 허용 목록과 형식 검사를 통과한 것만 받는지 시험. 성공 = 쓰기 도구 호출 0건·이상한 넘김 통과 0건.
3. **여행별 기억 기준선(Hindsight 도입 전) — 양쪽 제안의 공통분모.** Postgres 에 여행별 `선호 / 이전 문의 / 이미 알린 사건` 샘플을 넣고 고객 질문 10개에 필요한 기록만 붙이는 조회를 만든다. 성공 = 다른 여행 기록이 섞이지 않고 중복 알림 사례 10개를 모두 거른다. 이 기준선보다 Hindsight 가 나은지는 그다음에 본다.
4. (화면팀 몫) **Case 실행 타임라인 한 장(Paperclip 아이디어, Codex 제안).** 기존 감사·Case·outbox 데이터를 Case ID 로 묶어 `감지 → Team 판정 → 전이 → 배달 시도` 표시.

## 반영하지 않는 것(두 보고서 일치)
Paperclip 앱 전체와 사람 승인 체계 · Hindsight 를 규정·영업시간의 정본으로 쓰는 것(`reflect`·mental model 문장은 「근거 없는 문장 금지」와 충돌) · 금융 커넥터와 Managed Agents 배포(유료·사람 승인 전제) · 커리큘럼 전체 수강 · VoiceStudio.
