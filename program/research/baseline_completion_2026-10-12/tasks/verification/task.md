# 공통·여행 전체 시험과 환경·모델 근거 검증 — W02·W07·W13·W15·W18·W24 및 통합

다른 세션의 기능을 재구현하지 않고 실행 증거로 검증합니다. 작업 시작부터 우선 테스트 범위·격리 환경·기존 결과·빠진 요구를 준비하고, 구현 세션 완료 전에는 전체 통과를 선언하지 않습니다.

## 담당 범위

- `final_project_cs/scripts/run_test_suite.py`, `tests/test-suites.json`의 분리 범위를 확인하고 공통·여행 시험을 실제로 각각 실행합니다. collection 수를 통과 수로 쓰지 않습니다. 누락·중복·새 테스트 미등록을 확인하고 자기 범위에서 실행 목록만 보완합니다. 실제 업무 DB 대신 격리 DB를 사용하고 외부 알림·유료 모델/공공 API 호출이 섞이는 시험은 실행 전 분리합니다. skip·실패를 숨기거나 기준을 낮추지 않습니다.
- SQL 안전 세션·auth·orchestration·operations 결과를 자기 소스 해시와 함께 대조합니다. 기능 수정이 필요하면 실패를 재현하는 시험과 정확한 파일/원인/접합안을 남겨 최종 통합 담당이 수정하도록 합니다. 이미 다른 세션이 같은 결함을 고치는 중이면 새로 구현하지 않습니다.
- 모니터링 툴 실행 간격·수집 시각·원문 게시 시각·캐시·판정·통지 지연은 기존 관측 기록에서 계산할 수 있는 부분부터 측정합니다. 실제 경보 수집/28건 재현 세션을 중복 실행하지 않습니다. 없는 원문 시각은 추정하지 않고, 관측 구간 밖 사건 전체를 확보했다고 말하지 않습니다. 새 외부 호출·수집 자동화 재개는 하지 않습니다.
- 모델 판본·학습 여부·평가 조건·독립 보고서 링크와 실제 채택/환경별 로딩 증거를 대조합니다. 기존 runpod RAG 세션의 점검 기록을 재사용하며 모델 학습·다운로드·추론 부하 시험을 중복 실행하지 않습니다. 원본 모델과 추가 학습 모델을 같은 상태로 표기하지 않습니다.
- 로컬 개발 환경·x600 서버·오라클 ARM 환경은 현재 wiki와 기존 실행 기록을 구분합니다. 기존 보고서의 시점을 표시하고 실제 현재 가동은 별도 읽기 전용 확인 가능 범위에서만 적습니다. 새 고객·접수·여행 생성/변경·알림 발송을 하지 않습니다. 외부 연결값 누락·장소 오연결 등 기존 세션의 확인 문제는 중복 수정하지 않고 최종 판정에 포함합니다.
- ODsay 제품 미사용과 별도 연구 범위를 현재 코드·자료와 공식 이용 조건으로 대조합니다. 외부 자료는 1차 출처·확인일을 기록합니다. 약관 해석만으로 기존 데이터·기능을 삭제하지 않습니다.

## 결과와 대기

자기 status.json은 구현 세션이 진행 중이면 waiting_dependency로 두고 기다리는 세션/조건을 구체적으로 씁니다. 각 실행 결과·재현 실패·필요 자격 증명·미실행 고객 흐름을 report.md 및 원본 로그로 남깁니다. 이 세션에는 후속 확인이 설정될 예정이므로 대기 뒤에도 상태를 파일에 보존하세요. 코드/설정 해시가 바뀌면 영향받는 검증만 다시 수행합니다. 최종 통합 담당이 검사 결과를 검토한 뒤 통합 완료를 판정합니다.
