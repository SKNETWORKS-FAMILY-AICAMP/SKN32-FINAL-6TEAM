# 무인 운영 구현의 접합 인계

전용 설정·진단 API와 화면, DB 저장·내구 보관·재전송 서비스는 구현했습니다. 실제 식당 자료 조회와 공통 실행 흐름의 접합은 아래 담당 범위와 겹쳐 직접 수정하지 않았습니다. W05·W09 전체 완료로 처리하지 않습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 정책·진단 서비스 | 구현·격리 검증 | 2/2 = 100% |
| 운영·고객 화면 | 구현·화면 검증 | 2/2 = 100% |
| 공통·식당 접합 | 인계 대기 | 0/2 = 0% |

위 분모는 이 문서에 나눈 구현 묶음 수입니다. 개별 요구 전체나 운영 배포의 진행률이 아닙니다.

## 식당 자료 공급부 담당에게

현재 [새벽 작업 생성](../../../../../final_project_cs/scripts/run_sweepers.py)의 `_run_trip_dawn`은 `GooglePlaces`를 직접 만들고, [새벽 확인](../../../../../final_project_cs/app/domains/travel_ops/components/watch/dawn_check.py)의 `_check`는 장소 검색과 영업 판정을 직접 호출합니다. 여기에 [정책 서비스](../../../../../final_project_cs/app/application/operations_policy.py)의 `select`를 접합해야 실제 새벽 작업에 운영 화면 설정이 반영됩니다. 현재 이 호출 경로는 연결하지 않았습니다.

1. 여행의 tenant·고객·여행 UUID를 호출마다 명시적으로 넘깁니다. 여러 여행이 공유하는 자료 공급 객체에 현재 고객이나 여행을 가변 상태로 저장하지 않습니다.
2. `free`는 무료 자료 공급 어댑터입니다. `Verdict(status, source, checked_at, valid_until)`로 정규화합니다. 단순 영업시간 표를 읽었다는 사실을 실제 개점 확인으로 바꾸지 않습니다. 출처·시각·유효기간이 성립하지 않으면 `unverifiable`로 반환합니다. 고객 원문은 결과에 붙이지 않습니다.
3. 유료 판정은 `paid_provider="google"`, `context="dawn"`으로 호출합니다. 서비스는 한국 시각 03:00~08:00, 설정 허용·하루 전체 및 여행별 상한·같은 장소 최소 간격을 확인합니다. API 요청 원문이 이 문맥을 임의로 고르게 하지 않습니다.
4. `provider_reserve`는 기존 공급자 예산에서 실제 호출 권한을 먼저 확보하는 함수여야 합니다. `lambda: True`를 운영 코드에 연결하지 않습니다. 현재 [GooglePlaces](../../../../../final_project_cs/app/domains/travel_ops/ports/data_sources/google_places.py)의 `_call`도 `CallBudget.try_reserve(meter)`를 호출하므로 그대로 이중 예약하면 같은 HTTP 호출을 두 번 셉니다. 첫 호출의 meter를 정하고 확보한 예약을 한 번 소비하는 어댑터를 작성하거나, 동등한 사전 예약 계약을 공급부 내부에서 구현해야 합니다. 원래 예산 검사를 빼거나 상한을 늘리지 않습니다.

장소 ID가 없으면 검색(`METER_SEARCH`) 후 상세 판정(`METER_DETAILS`)이 각각 예산을 씁니다. 이번 정책 상한의 단위는 **논리 재조회 시도**이고 기존 `CallBudget`의 단위는 **실제 HTTP 호출**입니다. 하나의 논리 재조회가 두 HTTP 호출이 될 수 있으므로 두 상한을 동일한 값으로 설명하지 않습니다. 공급부를 교체하는 인계 시험에서는 첫 예약의 중복 차감 방지, 두 번째 HTTP 호출의 별도 예약, 예산 거절 시 외부 호출 0회, 낮 구글 호출 0회를 반드시 확인합니다. 현재 정책 서비스 시험의 공급자 콜백은 시험용 대역이며 이 접합을 검증한 것이 아닙니다.

미해결 장소는 `kind="place_unmatched"`로 별도 수집합니다. 일반 자료 조회 실패는 정책 서비스가 이미 `processing_error`로 기록하므로 같은 발생을 추가 수집할 때 발생 UUID를 공유해 중복 집계를 피합니다. 호출부에서 요청·사건 UUID를 알고 있으면 `select(request_id=..., case_id=...)`로 전달합니다.

## 공통 실행 흐름 담당에게

[진단 서비스](../../../../../final_project_cs/app/application/operations_diagnostics.py)의 `record(Event(...), connection_factory=...)`를 실행 실패 경계에 연결합니다. 고객 건의와 정책 서비스의 검증 불가 결과는 이미 연결했지만, 다른 공통 실행 오류 전체를 수집하는 훅은 연결하지 않았습니다.

- 핵심 실행기는 여행 도메인 객체를 직접 import하지 않고 콜백·기존 주입 경계를 사용합니다. Team의 제안 반환·외부 실행·outbox·감사 트랜잭션을 바꾸지 않습니다.
- `Event`는 허용한 코드·UUID·판본만 받습니다. 예외 문자열·HTTP 응답·토큰·고객 원문을 그대로 전달하지 않습니다. 배포 판본은 `ACOP_DEPLOYMENT_VERSION`으로 주입합니다. 미설정·형식 오류는 `unrecorded`로 남으며 실제 배포 판본을 추정하지 않습니다.
- `record`는 독립 트랜잭션을 사용합니다. 호출부의 실패 중인 DB 트랜잭션을 재사용하지 않습니다. 반환값 `stored`, `spooled`, `rejected`, `expired`, `collection_degraded`를 구분합니다. 특히 `collection_degraded`를 성공이나 정상 운영으로 숨기지 않습니다. 고객 일정의 해결 여부와 진단 저장 성공은 다른 상태입니다.
- 이미 재전송 대기 중인 발생은 같은 UUID를 유지합니다. 새 UUID를 매번 만드는 재시도는 서로 다른 발생으로 집계됩니다.

[재전송 CLI](../../../../../final_project_cs/scripts/replay_operations_diagnostics.py)는 한 번에 처리할 수를 제한하고 `--prune`으로 만료 연결을 정리합니다. 아직 기존 주기 작업에 등록하지 않았습니다. 통합 담당이 스케줄 경계에 연결한 뒤, 재시작 후 복구·DB 커밋 직후 중단·디스크 포화·삭제된 고객의 대기 기록 폐기를 함께 검증합니다. [흐름 그림](diagnostic-flow.html)은 수집 한 회차와 다음 회차 시작 조건을 구분합니다.

## 인증 담당에게

[이용 제한 안내](../../../../../final_project_cs/app/domains/travel_ops/modules/web_account/web_cookie.py)의 `user_blocked` 문구는 아직 “운영자에게 문의해 주세요”라는 상담원 전제입니다. 인증 소유 파일을 직접 수정하지 않았습니다. 실제 제한 해제 정책에 맞는 자동 안내 경로로 바꾸고, 건의 화면은 기록 창구이며 답변 대기나 해제를 약속하지 않는다는 점을 유지해 주세요. 자동 제한 해제 기능이 없는 상태에서 해제가 자동으로 된다고 쓰면 안 됩니다.

고객 화면 공통 탐색 메뉴의 기존 “문의하기 · 내 문의와 답변” 라벨도 화면 담당의 접합 때 기록 창구의 의미로 정리합니다. 이번 담당은 support 화면 본문과 전용 API를 수정했으며 공통 탐색 메뉴는 수정하지 않았습니다.

## 통합·검증 담당에게

- [SQL 후보](../../../../../final_project_cs/app/infrastructure/db/migrations/902_unattended_operations.sql)는 격리 PGlite에 두 번 적용했습니다. 업무 DB에는 적용하지 않았습니다. 실제 전체 스키마·안전 SQL 실행기와의 통합은 담당 환경에서 검증합니다.
- PGlite 시험은 순차 단일 연결입니다. 실제 PostgreSQL의 서로 다른 프로세스·연결에서 같은 tenant의 동시 설정 변경·예산 예약 경쟁을 검증해야 합니다. 현재 시험 결과를 이 경쟁 조건의 측정값으로 쓰지 않습니다.
- `ACOP_DIAGNOSTIC_SPOOL`에 비공개 영속 볼륨의 파일을 지정하고 파일 권한·보존·백업을 확인합니다. 대기열의 건수·UTF-8 payload 합계가 설정 상한을 넘지 않게 제한하며 SQLite 파일·WAL의 물리 바이트가 그 값과 같다는 보장은 아닙니다. 포화 시 기존 기록을 덮지 않고 유실 수를 올립니다. 디스크까지 쓰기 실패하면 반환값·로그로 저하를 알립니다.
- [전용 운영 계약](../../../../../final_project_cs/wiki/operations/unattended-operations.md)은 구현·격리 검증과 실제 환경 반영을 구분합니다. 독립 검토·접합 완료 전 W05·W09를 최종 완료로 닫지 않습니다.

새 유료 호출·업무 DB 변경·배포·재시작·커밋·푸시는 수행하지 않았습니다.
