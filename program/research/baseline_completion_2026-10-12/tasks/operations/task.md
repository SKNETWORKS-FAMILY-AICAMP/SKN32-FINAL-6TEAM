# 상담원 없는 운영·자료 조회 정책 설정 — W05·W09

관리자가 고객 문제를 대기하며 직접 수정하는 구조는 없습니다. 시스템이 자동 복구·추천하고, 꼭 필요한 경우 고객이 직접 입력합니다. 개발자/QA는 나중에 누적된 장소 미해결·결함·장애 코드·영향받은 고객을 조회·분석합니다. 운영자 웹앱의 설정·사후 분석과 상담원 역할을 구분하세요.

## 소유 범위

- 현재 오류·서비스 개선 기록 기능(229_service_improvement.sql 포함)을 먼저 읽고 재사용합니다. 오류 코드·사건/요청 식별자·마스킹·중복 집계·영향 고객·보존/복구·페이지 조회/색인을 실제 규모 확장에 맞게 구현·검증합니다. 사용자 정보는 접근 권한을 검사하고 공용 산출물에 실제 고객 목록을 복사하지 않습니다.
- 무료 자료 우선·검증 불가 표시, 유료 재조회 허용/상한·확인 간격 등 현재 wiki에서 허용한 설정을 운영자 웹앱에서 저장·조회 정책까지 연결합니다. `frontend/apps/admin/src/features/operations/`와 해당 전용 API·서비스·설정 저장이 주 수정 범위입니다.
- `modules/web_account/admin_customer_api.py`의 사후 분석 기능은 이 세션, 같은 폴더의 인증·세션·OAuth 구현은 auth 세션 소유입니다. 고객 support 화면에 상담원 전제를 제거하고 입력/추천 경로를 연결하되 plan-check·지도·채팅·공통 UI 스타일은 기존 connect uiux/채팅 세션 범위라 수정하지 않습니다.
- Dining 내부/수집 어댑터는 기존 요식업 통합 세션 소유입니다. 도메인 중립 정책 조회 서비스를 제공하고 필요한 Dining 접합부는 패치·계약으로 인계합니다. 유료 호출을 실제 실행하거나 Google 기존 호출 제한·공공 API 수집 예산을 확대하지 않습니다.
- D-CS-014·운영 설정의 전용 wiki와 이번 작업의 새 보고서를 소유합니다. D-017/018/020은 orchestration 담당, 인증 결정은 auth 담당이므로 필요한 참조만 사용합니다. 공유 스키마가 필요하면 자기 전용 새 `902_unattended_operations.sql` 후보를 확인하세요.

## 완료 기준

인증된 개발자/QA의 설정 조회·변경·감사, 권한 없는 변경 거부, 설정 변경 후 실제 선택 정책에 반영, 예산 소진/조회 실패 시 검증 불가 표시, 조회 실패와 정상 운영 구분을 실행 시험으로 보입니다. 진단 저장 실패 시에도 마스킹된 내구성 있는 로컬 보관·재전송 등 현재 계약의 데이터 유실 방지 경로를 검증합니다. 단순 목록 화면이나 메모리 설정만 만들어 연결 완료로 보고하지 마세요.

자기 status.json과 report.md에 구현·화면 반응·실제 외부 연결 여부를 구분해 기록합니다.
