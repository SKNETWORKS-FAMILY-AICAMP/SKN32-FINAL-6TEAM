# 개인 AI OAuth·권한 연결 구현 — W02·W04·W12 인증 경계

W04는 사용자가 B안(개인 AI OAuth까지 이번에 구현)을 선택했습니다. OAuth 서버/리소스 계약, 로그인·동의·허용 작업, 코드 교환·만료·폐기, 고객·여행 소유권을 구현·검증하세요. 기존 웹 소셜 OAuth와 개인 AI가 여행 도구를 호출하도록 위임받는 OAuth는 같은 기능이라고 추정하지 마세요. MCP 연결의 실제 공식 인증 요구를 확인하세요.

## 소유 범위

- `final_project_cs/app/domains/travel_ops/modules/web_account/`의 인증·세션·개인 AI 위임 경로, 인증 전용 새 모듈, MCP 인증 경계, 여행별 읽기 권한 검사, 관련 보안·계약 시험.
- 현재 `D-CS-011`, `D-CS-012`, `web-auth-transfer`, `mcp-tools` 계약. 공용 rest-endpoints 본문은 인증 절의 최소 변경만 준비하고 다른 세션 변경을 보존합니다.
- 새 DB SQL이 필요하면 전용 이름 `901_personal_ai_oauth.sql`을 우선 후보로 검토하세요. 이미 존재하거나 부적합하면 사용 가능한 새 이름을 확인해 선택하고 원문 과거 SQL은 수정하지 않습니다. SQL 실행기·requirements·배포 파일은 SQL 안전 세션 소유이므로 의존성 추가는 별도 요청 파일로 남깁니다.
- 실제 앱 라우터·공통 설정·trip_api의 같은 줄을 다른 세션이 변경 중이면 새 모듈과 접합 패치를 준비해 최종 통합 담당에게 인계합니다. 고객 웹 전체 화면과 채팅/취향 구현은 기존 세션 범위입니다. 동의 화면이 필요하면 인증 전용 화면만 작은 범위로 추가하고 현 UI 작업과 충돌하는 공통 스타일은 수정하지 않습니다.
