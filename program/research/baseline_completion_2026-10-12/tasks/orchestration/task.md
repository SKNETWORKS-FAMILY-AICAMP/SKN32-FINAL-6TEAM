# 분류 에이전트·항로 지킴이·장애 격리 — W03·W06·W08·W12 실행 경계

분류 모델이 들어 있는 분류 에이전트가 고객 질의·여행 계획·상황·이미 확보된 고객 성향을 바탕으로 에이전트 팀, 실행 순서와 우선순위를 결정해야 합니다. Activity 에이전트 팀을 조정자로 두는 설명·고정 호출 순서를 요구 구현으로 오인하지 마세요. Controller는 검증된 계획을 실행하는 장치이며 새로운 Controller 팀을 만들지 않습니다. Core에는 여행 도메인 어휘를 넣지 않습니다.

## 소유 범위와 중복 제외

- `app/application/classification.py`, 관련 분류 계획 계약, 여행 도메인의 새 실행 계획 모듈, `components/watch/trip_watch_batch.py`, `components/team_hooks/watch_planners.py`, `components/core_hooks/verification_policy.py` 등 실제 경로를 먼저 확인합니다. 공통 Controller는 꼭 필요한 도메인 중립 접합만 변경합니다.
- D-017·D-018·D-020와 composition/팀 경계의 현재 실행 계약. 전체 rest-endpoints·quality/invariants 공용 파일에 필요한 변경은 자기 보고서에 접합안으로 남깁니다.
- 기존 채팅 세션이 `components/conversation/`의 대상 해석·취향 수집을 진행 중입니다. 그 모델·기억 저장·채팅 처리는 새로 만들거나 덮지 말고 기존 분류 모델/인터페이스와 실제 성향 입력을 재사용합니다. 이용할 수 없는 성향은 지어내지 않습니다.
- Mobility 내부 계산·출발 안내, Dining 내부 계산·통합, 고객 웹 plan-check/지도/채팅 화면은 기존 세션 소유입니다. 등록된 Port/계산 계약을 사용하고 내부 함수 구현을 중복 수정하지 않습니다.

## 필수 구현·검증

1. 모델 출력의 팀·순서·우선순위·의존 관계를 엄격히 검증하고 허용 팀·도구·예산을 제한합니다. 모델 실패를 조용한 고정 순서 성공으로 위장하지 않습니다. 실제 조립 경로에 연결된 것을 실행 증거로 보입니다.
2. 같은 여행의 여러 문제를 최신 초안에 적용하고 전체 재검증 후 일정 버전·알림 중복을 막습니다. 실행 순서의 근거는 분류 에이전트 계획이며 Activity 고정 조정이 아닙니다. 재시도·경합·오래된 초안·부분 실패를 검증합니다.
3. 항로 지킴이 켜짐이면 허용 범위의 검증된 변경을 자동 적용·저장·통지합니다. 꺼짐·미응답 기본값·고정 일정·재난 후 수동 재개·업체 예약 거래 승인 조건은 현재 wiki 그대로 지킵니다.
4. 자료 조회 실패는 그 자료에 의존하는 변경만 보류하고 기존 일정·정상 기능을 유지합니다. 대체 조회·재시도·자동 복구·고객 안내와 오류 근거 기록을 의미 있는 인수 시험으로 확인합니다. 진단 저장 서비스는 operations 담당이 만드므로 자기 범위에서는 이벤트 계약·호출 위치를 제공하고 같은 서비스를 중복 구현하지 않습니다.
