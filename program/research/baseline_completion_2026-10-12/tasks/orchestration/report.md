# 분류 에이전트·항로 지킴이·장애 격리 구현 확인

담당 범위 W03·W06·W08·W12의 로컬 구현과 허용된 격리 검증을 마쳤습니다. 실제 업무 DB 변경·원격 배포·재시작·고객 전송·유료 호출·커밋·push는 하지 않았습니다. **전체 제품 완료 또는 운영 배포 완료 보고가 아닙니다.**

| 할 일 | 상태 | 진행 |
|---|---|---|
| 분류 실행 계획·실제 조립 접합 | 구현 | 1/1 = 100% |
| 자동 변경 기본값·정지 적용 경계 | 구현 | 1/1 = 100% |
| 자료 실패 격리·안내·재시도 | 구현 | 1/1 = 100% |
| 단위·Core 경계 검증 | 통과 | 179/179 = 100% |
| 격리 DB 인수·회귀 | 마지막 결과 통과 | 129/129 = 100% |

## 반영 내용

1. 모델이 질의·최신 일정·발견 상황·직접 답한 설문을 받아 담당 팀·순서·우선순위·의존 관계를 출력합니다. 스키마·항목 정확한 커버·소유 팀·도구 허용 목록·단계 및 총 호출 상한·의존 순서를 실행 전에 검증합니다. 실제 분류 모델 제공자 설정을 재사용하며 실패를 고정 순서로 대신하지 않습니다. 시험에서는 명시적 모델 대역을 주입했습니다.
2. 로컬 TeamExecutorPort에 여행 묶음 실행기를 연결했습니다. Activity를 조정자로 두지 않고, 각 계산은 등록된 해당 팀 객체·도구 권한·예산으로 수행합니다. 최신 초안에 누적 적용 후 전체 재검증하고 제안 하나를 기존 Controller 트랜잭션에 넘깁니다. Core에 여행 어휘나 새 팀을 넣지 않았습니다.
3. 항로 지킴이는 직접 켠 기록만 자동 변경합니다. 미응답·옛 기본 replace만 있는 여행은 먼저 묻습니다. 예약 정보 자체는 고객 고정으로 오인하지 않으며 고객 고정·locked는 보호합니다. 적용 때 여행 행을 잠근 뒤 최신 설정·소유권·버전·재난 정지를 확인합니다. 계산 중 설정이 바뀐 묶음은 낡은 안내를 저장하지 않고 재계산 대상으로 거절합니다. 옛 until_at가 지나도 재난 정지는 수동 재개까지 유지합니다. 업체 거래 승인 경로는 변경하지 않았습니다.
4. 자료 실패는 해당 항목과 의존 작업을 보류하고 독립 항목은 처리합니다. 초기 조회 예외도 항목별로 격리합니다. 기존 일정 유지·재확인·시각·오류 코드를 고객 안내에 남깁니다. 같은 항목·같은 오류 안내는 중복 저장하지 않습니다. 기존 대체 조회 Port와 제한된 재시도 경로를 쓰며 복구 시 최신 상태로 다시 계산합니다. 최종 재검증에서 선행 변경이 빠지면 의존 변경·제안·변경 없음 판정도 보류합니다.

## 계약·진단 접합

- [새 실행 계획 계약](../../../../../final_project_cs/wiki/teams/classification-execution-plan.md): 독립 검토자는 미배정이며 작업자가 계약 검토를 겸했습니다.
- 운영 진단 저장기를 중복 구현하지 않았습니다. `travel_execution_diagnostic` 로그의 `diagnostic` 객체를 수집하면 됩니다. 공통 필드는 event, tenant_id, customer_id, trip_id, case_id, item_id(항목 단계일 때), code, error_code, checked_at, plan_sha256입니다. `classification_failed`, `source_failed`, `error`, `retry`, `retry_recovered` 등을 구분합니다. 원문·예외 응답 본문·접속 비밀은 싣지 않습니다. 초기 조회 실패에는 계획 해시가 null입니다.
- 공용 rest-endpoints/quality/invariants 접합안: 미응답 자동 변경 금지, 계산 중 설정 변경 시 재계산, 만료 시각에 의한 재난 자동 재개 금지, 조회 실패 항목의 안내·독립 처리·복구를 계약 및 관문에 추가하십시오. 이 공용 파일은 담당 경계에 따라 수정하지 않았습니다.
- 공용 tests/test-suites.json에는 새 단위·인수 시험 파일 2개를 travel 목록에 편입해야 합니다. 검증 담당 소유 파일을 직접 고치지 않았습니다.
- SQL 추가 불필요: 새 진단 표나 실행 계획 표를 만들지 않고 기존 결정 기록·적용 요약·outbox를 사용했습니다. 전용 903 번호를 사용하지 않았습니다.

## 검증 상태

검증용 [실행기](isolated_checks.py)는 매번 이 작업 전용 PostgreSQL 클러스터를 생성하고 기존 마이그레이션을 적용하며, 외부 통신과 해당 클러스터 밖 DB 연결을 차단합니다. 시험 끝에 이 클러스터만 종료합니다. 모델·장소·이동은 명시적 재생 입력이며 실제 실행·저장·경합 경로를 시험합니다. 다른 세션의 DB를 사용하지 않았습니다.

단위·대체 조회·Core 경계 179/179 = 100%, 격리 DB 인수·회귀의 중복 제거 후 마지막 결과 129/129 = 100%입니다. 분모는 실제 실행 결과에서 센 시험 수입니다. [요약과 시험별 근거](acceptance-summary.json), [단위 JUnit](unit-final.xml)을 확인할 수 있습니다. DB 첫 회귀 94/97, 인수·추가 회귀 53/56 뒤 실패 3개 최종 3/3을 재실행했습니다. 먼저 실패한 시험은 스레드의 조립 문맥 주입·재개 via의 허용값을 바로잡았고, 미응답을 자동 변경한다고 기대한 옛 시험 4개는 현재 확정 사양으로 정정했습니다. 실패 실행도 runs에 보존했습니다. 외부 통신 차단 발생은 0건입니다. 실제 외부 소스나 모델에 성공적으로 연결했다는 의미가 아닙니다.

mock 서버 시험: 해당 없음 — 함수·모델 대역, 재생 자료, 전용 PostgreSQL을 사용했습니다.

실서버 확인(서버 응답): 안 했음 — 운영 cs 프로젝트 서버·외부 자료·실제 모델·고객 전달은 확인하지 않았습니다.

Windows 제한 실행에서는 asyncio의 로컬 socketpair가 생성 단계에서 대기했습니다. 로컬 루프백 권한을 받은 실행에서 정상 진행했습니다. 첫 통합 실패는 read.itinerary가 고객 소유권 확인 후 고객 id를 생략하는 계약을 새 실행기가 잘못 해석한 문제였고 이를 수정했습니다. 자료 실패 안내의 키가 일정 버전에 따라 반복되는 문제도 통합 시험으로 찾아 수정했습니다.

## 범위와 남은 접합

- 실제 분류 모델의 품질·지연·실패율은 측정하지 않았습니다. guardrails의 12초·72호출 등은 구성 상한이며 실측값이 아닙니다. 외부 소스 응답, 원격 A2A 다중 팀 조정, 고객 실제 수신, 운영 진단 저장기 연결, 원격 반영은 확인하지 않았습니다.
- 실행 계획 적용 범위는 한 여행의 감시 묶음입니다. 일반 고객 채팅의 다중 업무 분해나 새 성향 기억 서비스는 만들지 않았습니다. 채팅·Mobility 내부·Dining 내부·고객 화면 작업을 덮지 않았습니다.
- 초기 조회 실패 안내는 동일 항목·동일 오류 지문에 한 번 저장합니다. 정상으로 돌아왔다 같은 항목이 다시 같은 오류로 실패하는 별도 사건의 재안내 정책은 운영 진단 수집기 접합 시 확정할 사항입니다. 각 회차의 실패·정상 점검 기록은 별도로 남습니다.
- 공유 폴더의 다른 작업 변경은 이 보고서의 완료 범위에 포함하지 않습니다.

## 백업

[변경 전 사본](../../../../../final_project_cs/_backup/2026-10-12_035959_orchestration/)에 기존 코드·시험을 보존했습니다. feedback.py 사본은 system 프롬프트 매개변수·ask_json을 추가한 직후이고, 시간 상한을 넣기 전 사본입니다. 그 파일에 대해서는 원래 상태의 완전한 사전 백업이 아니므로 별도로 표시합니다. 새로 만든 계약·모듈·시험·실행기는 최초 원본이 없습니다.

## 최종 판정·변경 범위

로컬 접합 준비 완료(ready_for_integration)입니다. 실제 고객 질의를 임의 분해하는 기능·원격 실행·운영 반영까지 완료라고 보지 않습니다. 단위 최종 179/179, DB 중복 제거 마지막 결과 129/129이며 확인 시각은 2026-10-12T04:43:59.881485+09:00입니다. 원격 배포, 실제 업무 DB, 커밋·push는 하지 않았습니다.

6개 새 인수 시험은 초기 자료 장애와 독립 처리·조회 예외·분류 실패 후 복구·동시 제안 한 번 저장·계산 중 설정 변경 거절·만료된 옛 정지의 수동 재개를 확인했습니다. 기존 묶음 시험은 판 하나·알림 하나·부분 실패 후 재시도·고정 보호를, 기존 웹 시험은 본인 권한·CSRF·설정 기록·안전 해제 후 정지 유지 등을 확인했습니다.

구현·시험·계약 파일 목록과 최종 해시는 [scope-sha256.json](scope-sha256.json)입니다. 공유 파일에 포함된 다른 작업자의 변경을 이 작업의 작성분이라고 주장하지 않습니다. 로컬 DB 로그·파일과 백업은 작업별 .gitignore로 게시 대상에서 제외했습니다. 중단한 초기 실행 두 개는 pg_ctl status에서 실행 중이 아님을 확인했고, 정상 종료 실행은 stop.log를 남겼습니다.
