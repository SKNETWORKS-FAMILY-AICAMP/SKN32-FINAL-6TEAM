# 제품 전체 단일 기준선 — 작성 준비본

이 골격은 최종 기준선 작성에 필요한 필드를 준비한 것입니다. 현재 확정 사양은 wiki에 있으며, 아래 목록은 구현·검증·배포 완료 선언이 아닙니다.

## 기준선 식별과 책임

최종 산출 경로는 `program/baseline/triPilot-baseline-2026-10-12.md`와 같은 내용의 검토용 HTML입니다. 실제 완료가 다음 날짜로 넘어가면 본문에 완료 시각(KST)과 파일명에 남은 기준 날짜를 함께 씁니다. 기준선 ID는 제품 전체에 하나를 부여하고, 완료 시점의 wiki·코드·자료·모델·시험·환경 상태를 연결합니다.

wiki가 확정 사양을 소유합니다. 기준선은 그 시점의 요구·구성·검증·환경 차이를 묶은 기록입니다. 기능별 담당자가 다르다는 이유로 별도의 제품 정본을 만들지 않습니다. 하위 에이전트 구축·학습 보고서는 근거 링크로 연결합니다.

## 최종 파일에 채울 필드

| 필드 | 출처 | 작성 조건 |
|---|---|---|
| 기준선 ID·작성 KST·대상 제품 | 통합 완료 기록 | 날짜를 실제 값으로 남김 |
| 사양 정본·원문 SHA-256 | 현재 wiki 원문 | 검사 뒤 변경 여부 재확인 |
| 결정·요구 ID | W01~W25 사용자 결정·현재 계약 | 사용자 선택 변경 금지 |
| 기능별 인터페이스 | REST·MCP·Team·실행·자료 계약 | 실제 호출 경로와 대조 |
| 자료 판본·해시·정책 | 현재 여행 자료·데이터 안내 | 과거 쇼핑몰 자료 제외 |
| 모델 판본·학습 여부 | 모델 평가·독립 실험·환경 로딩 증거 | 학습 완료·채택·배포 분리 |
| 구현 파일·해시 | 담당 변경·최종 소스 목록 | 동시 변경·공유 접합 확인 |
| 검증 명령·결과·시각 | 원본 로그·JUnit·검사 출력 | 실패·건너뜀·분모 보존 |
| 환경별 적용·확인 시각 | 로컬·x600·ARM·GPU 근거 | 미배포·미확인 명시 |
| 미해결 필수 요구 | 통합표·실패 재현 | 임의 예외로 완료 처리 금지 |
| 변경 절차 | wiki 작성·검토 규칙 | 요구→구현→영향 검증→새 판본 |

## 요구 추적

[25개 통합표](integration-table.md)와 [기계 판독 자료](integration-table.json)를 바탕으로 결정·문서·구현·시험·환경 상태를 따로 기록합니다. `TRP-REQ-W01`~`TRP-REQ-W25`는 이번 통합 보고서에서 W01~W25를 가리키는 추적 별칭입니다. 기존 프로젝트의 별도 요구 ID를 대체하거나 새로운 제품 사양을 추가하지 않습니다.

문서 전용 항목은 문서·링크·현재/과거 경계 확인으로 판정합니다. 기능 항목은 실제 호출·권한·실패·동시성·멱등성 등 관련 시험을 확인합니다. 다른 채팅의 요약만으로 완료를 판정하지 않습니다.

## 인터페이스 묶음

| 경계 | 확인할 계약 |
|---|---|
| 고객 웹·개인 AI·공유 링크 | 인증 수단, 본인 여행, 읽기·쓰기, 만료·폐기 |
| 분류 에이전트→실행 장치 | 담당·순서·우선순위·의존 관계·거부 조건 |
| 실행 장치→에이전트 팀 | 활성 등록, 입력·출력, 허용 도구·예산 |
| 변경 제안→일정 적용 | 재검증, 고객 설정, 고정 항목, 버전·중복·감사 |
| 모니터링→알림 | 한 회차 범위, 자료 시각, 상태 전환별 중복·실패 |
| 자료 조회→정책 설정 | 무료 우선, 승인된 자료, 예산·저장·출처 |
| 진단→개발자·QA | 고객 연결·마스킹·보관·유실 지표·쓰기 권한 |

## 검증·환경 기록

최종본은 공통·여행 전체 시험, 계약·보안·현재 관문, wiki·자동 생성물 검사와 직접 연결합니다. 소스 해시가 바뀌면 영향 시험을 다시 수행합니다. 외부 계정·실제 클라이언트·모델이 필요한 미실행 범위를 격리 시험으로 덮지 않습니다.

mock 서버 시험(화면 반응)과 실서버 확인(서버 응답)은 별도 줄로 기록합니다. 기존 원격 보고서의 실행 시점과 이번 확인 시점을 구분합니다. 이 분담은 실제 업무 DB 변경·배포·재시작·커밋·푸시·고객 알림을 포함하지 않습니다.

## 기준선 작성 방법의 외부 근거

기존 다운로드 출처의 [무결성 대조](source-audit.json)를 먼저 수행했습니다. 이 검사 자체는 원문 주장 검토나 최신 웹 재확인이 아닙니다.

[NASA 기술 관리 안내 §6.5](https://www.nasa.gov/reference/6-0-crosscutting-technical-management/)는 기준선 식별, 변경 통제, 상태 기록, 구성 검증을 구분합니다. 이를 참고해 이 프로젝트의 기준선에는 사양과 구성의 식별값, 승인된 변경과 실제 구현, 검증 근거를 연결합니다. NASA의 조직·승인 체계 전체를 우리 프로젝트 규칙으로 새로 도입하지 않습니다.

[DORA 버전 관리 안내](https://dora.dev/capabilities/version-control/)는 소스뿐 아니라 설정·자동화 자료의 재현성과 추적을 다룹니다. 이 프로젝트에서는 키·접속값을 버전 관리하지 않고, 공용 설정·코드·재현 명령·판본 해시를 연결하는 데 참고합니다.

원문 확인 범위는 2026-10-10 내려받은 NASA §6.5와 DORA Version control 본문입니다. 현재 제품 사양·실행 상태의 근거는 외부 참고문헌이 아니라 현재 wiki와 실측 결과입니다. 최신성이 필요한 외부 기술 규칙은 최종 사용 시 공식 원문으로 재확인합니다.

## 최종 확정 절차

[최종 통합 흐름](finalization-flow.html)에서 필수 근거 부족과 코드 변경에 따른 재검증 경로를 구분했습니다. 모든 필수 구현·검증 상태를 판정한 뒤 최종 파일을 완료본으로 표시합니다. 필요한 외부 조건 때문에 실행하지 못한 항목이 있으면 구체적인 조건을 남기며 완료 조건을 임의로 낮추지 않습니다.
