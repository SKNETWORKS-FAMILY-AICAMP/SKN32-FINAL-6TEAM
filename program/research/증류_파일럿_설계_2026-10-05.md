# 증류 파일럿 설계 — Claude 가 만든 한국어 문제·정답으로 작은 모델(학생)을 학습시켜 로컬 최고 수준 따라가기

작성 2026-10-05 · 요청: 사용자(「증류 파일럿 설계, 우선 진행」) · 상태: **설계 + 학습 자료 생성 시작**(학습은 자료 검증 뒤)

## 한 줄
규칙 없이도 풀 수 있는 문제(769)에서 Claude 는 99.3%, 로컬 최고는 97.4%(§66-2)다. 그 격차를 **Claude 가 만든 새 문제 약 1,760개(여행자 10종)로 작은 모델을 학습**시켜 줄일 수 있는지 본다. 학생은 **CPU 배포를 염두에 둔 4B 급(Gemma 4 E4B)을 먼저**, 12B 4비트는 위쪽 기준으로 둔다.

## 왜 4B 급이 먼저인가 — 배포 제약(사용자 2026-10-05)
GPU 없는 서버(예: 오라클 ARM 4코어·RAM 24GB)에 올릴 수 있는 모델 크기가 상한이다. DB·API 가 같은 기계에 있으면 모델에 쓸 수 있는 메모리는 약 14~16GB 이하, 4코어 CPU 에서 질문당 일정 전체(약 1.7k 토큰)를 읽어야 해서 **26B 이상은 사실상 불가**, 12B 는 빠듯, **4B 급이 현실적**이다. 지금까지 연구는 정확도 중심이었고 **CPU 속도·메모리는 직접 재 본 적이 없었다** → 이번에 같이 잰다(§ 아래 「CPU 실측」).

## 학습 자료 생성 계획
| 항목 | 값 |
|---|---|
| 여행자 | 10종(신혼·3대 가족·교포 친구·등산 동호회·미식 직장인·알뜰 대학생·반려견 가족·사진 촬영·쇼핑 뷰티·문화유산 체험), 계절·날짜를 달리함(2027-03 ~ 2028-02) |
| 규모 | 여행자당 일정 40~50항목 + 11유형 × 16 = 176문제 → **약 1,760문제** |
| 작성 | Claude 하위 작업(Opus) 10개, 각자 의뢰서 한 파일만 읽음(우리 코드·평가 세트 못 봄) |
| 피할 것 | 평가 세트 mix8~12 · 이전 세트 · 학습 풀의 장소 748곳(의뢰서에 목록) |
| 정답 | 먼저 말한 항목(요청 둘은 `gold_set` 말한 항목 전부도 함께) |
| 형식 | 평가와 같은 모양(일정 + 질문 + 앞 대화 → 번호 하나 또는 null) |

## 검증(학습에 쓰기 전)
1. **형식·키 검증**: 유형별 16개, 정답 키 존재, 문장 중복 없음, 정답 null 비율 약 20~26%.
2. **평가와 겹침 제거**: 평가 세트 mix8~12 와 문장·장소가 같거나 거의 같은 것은 뺀다.
3. **독립 풀이**: 다른 Claude 하위 작업(문제를 쓴 쪽과 분리)이 정답 없이 풀어 **정답과 어긋난 문제는 제외**(모호·오류 후보). 어긋난 비율과 유형을 기록한다.
4. 주 대화 Claude 가 제외 목록을 훑어 사유를 적는다(문장·정답은 고치지 않음).

## 학습(서버 A 의 16GB GPU, 설계 · 실행은 자료 검증 뒤)
- 방식: QLoRA(4비트 NF4 + LoRA), 입력 = 평가와 **글자 하나까지 같은 질의문**, 학습 목표 = 정답 JSON 한 줄. 손실은 정답 토큰에만, 질의문 일정 부분에는 걸지 않는다.
- 학생: ① **Gemma 4 E4B**(올라마 QAT 6.1GB 로 서비스 가능, CPU 후보) ② Gemma 4 12B(위쪽 기준) ③ 필요하면 Qwen3.5-4B.
- 메모리·시간 계산은 `[예상]` — 서버 GPU 는 **RTX A4000 16GB**(B 서버에서 확인). 12B NF4 가중치 약 7GB + 활성값(기울기 체크포인트, 1.9k 토큰, 배치 1) + 선택 손실(마지막 몇 토큰만 로짓) 약 3~4GB → **16GB 에 들어간다**. 속도는 12B 가 E4B 의 약 3배: 한 예제당 `[예상]` E4B 3~5초 · 12B 10~15초 → 1,600예제 × 3에폭 ≈ E4B 4~7시간 · 12B 13~20시간. 실측으로 대체한다.
- **평가는 mix8~12(835문제)에서만**, 학습에서 완전히 분리. 비교 대상: 같은 학생의 무학습 값(E4B QAT 직접 91.2% 요청 둘 제외 기준 · 12B 91.4%), 로컬 최고(Qwen3.8 97.4%), 교사(Claude 99.3%). 판정 기준(사전): **무학습 학생 대비 +3%p 이상이고 짝지은 정확 McNemar p<0.05** 이면 「증류가 먹힌다」.

## 위험
- 교사(Claude)가 만든 문제를 Claude 가 풀어 검증하므로 **같은 습관이 정답에 스며들 수 있다**(분포 편향). 평가 세트가 Codex·Claude 둘이 쓴 것이라 부분적으로 완화됨.
- 학습 문제가 평가 문제와 닮으면 점수가 부풀 수 있어 장소·문장 겹침을 막고, 평가에서 학습 여행자 유형(예: 가족·미식)을 따로 보고한다.
- 학생이 요청 둘 유형에서 「먼저 말한 항목」 규칙을 외우는 것은 의도된 목표가 아니므로, 판정은 **요청 둘 제외 769문제 점수를 주 지표**로 하고 요청 둘은 B(말한 항목이면 정답)로 따로 본다.

## CPU 실측(진행 중)
GPU 서버 B 의 CPU 4코어(AMD EPYC 7702, x86)로 llama.cpp 를 GPU 끄고 돌려 4B(Q8) · 12B(Q8)의 **일정 전체 프롬프트 처리 시간 · 다음 질문(일정 앞부분 캐시) 시간 · 생성 속도**를 잰다. x86 은 ARM(Neoverse N1 급)보다 빠르므로 **상한**으로 읽는다. 결과는 `results/export/cpu_bench_*.json` 과 §69 에 적는다.
