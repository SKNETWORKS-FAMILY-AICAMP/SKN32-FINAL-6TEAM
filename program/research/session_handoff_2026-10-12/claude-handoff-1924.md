## 2. 결정사항 — 기존 코드를 이유로 뒤집지 말 것

- 제품은 guguroute, 팀은 A-COPilot입니다. 현재 도메인은 여행 CS입니다. 과거 커머스 자료는 기록으로 보존하고 현재 판단·시험·평가·시연 재료로 사용하지 않습니다.
- 현재 사양 정본은 wiki의 확정 결정·계약입니다. v11은 2026-09-10 당시 기록으로 보존합니다. v12는 wiki를 이해하기 위한 안내서입니다.
- 분류 모델이 들어간 **분류 에이전트**가 고객 질의·계획·상황·성향을 보고 에이전트 팀, 실행 순서, 우선순위를 결정합니다. Activity 에이전트 팀을 다른 팀의 조정자로 만들지 않습니다. Controller 등 코드 식별자는 실제 책임과 구분해 설명합니다.
- ‘팀’은 문맥에 따라 에이전트 팀인지 실제 개발 팀원인지 명시합니다. ‘감시 묶음’, ‘3분 감시’, ‘PC 콘솔’, ‘콘솔 시점’, ‘별도 접점’ 같은 불명확한 표현을 반복하지 않습니다. 사용자가 정한 명칭은 **모니터링 툴**입니다.
- 항로 지킴이를 켠 고객은 현재 확정 계약의 조건에 따라 자동 변경하고 결과를 안내합니다. 고정 일정·고객 설정·재난 후 재개·거래 승인 경계는 실제 wiki 계약을 확인합니다.
- 상주 상담원이 고객 문제를 직접 수정하는 구조는 없습니다. 자동 해결과 최대한의 추천을 우선하고, 불가피할 때 고객이 직접 입력합니다. 오류·미발견 장소·장애 코드는 저장하여 개발자·QA가 사후 분석합니다. 운영자 웹앱은 이러한 설정·분석 용도입니다.
- 외부 자료 실패는 해당 자료에 의존하는 기능·요청에서 격리합니다. 오래된 문구를 근거로 cs 프로젝트 서버 전체 종료 방식을 되살리지 않습니다.
- 개인 AI OAuth는 **W04 B안: 이번 범위에 구현**을 선택했습니다.
- 장소 상태 조회는 **W09 A안: 무료 자료 우선·확인 불가 표시**를 선택했고 운영자 웹앱에서 정책을 바꿀 수 있어야 합니다.
- 시험은 **W13 C안: 공통/여행 분리**입니다.
- 모델 관리는 판본표와 현재 평가 절차를 유지하고, 실험별 독립 보고서를 따로 보관하여 판본표에서 링크합니다. 중앙 모델 등록 제품 도입과 같은 뜻이 아닙니다.
- 기능 책임 설계와 디렉토리 경계를 정리하되 실제 팀원 배정을 임의로 만들지 않습니다.
- wiki 작성은 기존에 정한 OpenWiki·OKF 방식과 프로젝트 작성 지침을 따릅니다. 상태 필드·현재 계약·과거 기록·근거 링크를 분리합니다. 구체 규칙은 저장소의 현행 지침을 먼저 읽습니다.

### 커밋·푸시

- 사용자는 기존 ‘git commit push’ 채팅에서 커밋·푸시하라고 승인했습니다. 그 채팅에 이번 변경 검토·양쪽 `role-manager` 반영·보안 검사·제외 범위·원격 해시 확인을 전달했습니다.

- 최신 커밋 채팅 메모에는 **추가 UIUX 매니저 푸시 2/2 완료**가 있습니다. 기존 develop 화면 시험은 **774/775 통과, 1개 실패, 18개 건너뜀**으로 나왔습니다. 이 관측을 이번 W01~W25 전체 커밋·푸시 완료 증거로 확대하지 마세요. 이번 인계에서는 원격 해시·diff를 독립 대조하지 않았습니다.
