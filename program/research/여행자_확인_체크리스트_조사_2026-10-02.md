# 여행자가 일정표를 믿기 위해 직접 하는 확인 — 체크리스트와 서버 현황 (2026-10-02)

> 보고 페이지(비공개 아티팩트)와 같은 내용이다. 화면 시안은 세 장면(일정 타임라인 · 항목 상세 · 확인 항목 전체 목록)이며 이 문서에는 싣지 않았다.

> 멘토 피드백 「Validation 내용 보강하기 — 사람이 체크하는 것을 다 모아 체크리스트로 만들기」에 대한 조사.
> 목록은 Claude 초안 + Codex(gpt-6-sol) 독립 초안을 합쳤다. 서버 현황은 `final_project_cs` 코드를 읽어 센 것이다(라이브 DB·서버는 조회하지 않았다).

## 한눈에

- 사람이 일정표를 확인할 때 하는 일을 **72가지**로 모았다. 서비스 범위 안은 **66가지**, 숙소·항공·통신 같은 범위 밖이 6가지다.
- 범위 안 66가지 중 서버가 **이미 판정하는 것 5가지(8%)**, **일부 상황에서만 판정하는 것 23가지(35%)**, **아직 없는 것 34가지(52%)**, **고객만 아는 값 4가지(6%)**다. (분모 66 = 범위 안 항목. 퍼센트는 반올림이라 합이 101%다.)
- ★가장 큰 틈: **서버가 항목별 확인 결과를 화면에 내보내는 응답 칸이 없다.** 판정은 하지만 고객은 「어느 항목을 무엇으로 확인했나」를 볼 수 없다.
- ★그다음 틈: 영업시간 판정(문이 닫혔는지·마감을 넘기는지)은 구현돼 있지만, **고객이 올린 일정에는 영업시간이 실려 있지 않아 대개 건너뛴다**(값이 없으면 통과). 외부 연구가 가장 흔한 오류 둘로 꼽은 것이 바로 이 둘이다.

## 방법과 한계

1. Claude가 먼저 33개를 적고(코덱스 답을 보기 전에 파일로 못 박아 두었다), 그 답을 보여 주지 않은 채 Codex에게 같은 질문을 던져 70개를 받았다. 합치니 72개다(둘 다 낸 것 29, Claude만 7, Codex만 36). Codex의 70개는 모두 합본에 흡수됐다.
2. 서버 현황은 `app/`·`scripts/`·`wiki/`를 읽은 서브 조사의 결과다. 「불린다/안 불린다」는 호출처 검색으로 판단했다.
3. 한계: ① 여행자·상담사에게 직접 묻거나 실제 일정표 표본으로 센 것이 아니다 — 항목 수 72는 「빠진 것이 없다」는 증명이 아니다. ② 외부 근거는 아래 두 건이다. ③ 「아직 없음」은 조사 범위에서 찾았고 안 나왔다는 뜻이다(이름을 바꿔 구현된 것은 놓칠 수 있다). ④ 라이브 DB의 채움 정도, 1분 작업이 지금 돌고 있는지, 공공데이터 서비스별 승인 여부는 확인하지 못했다.
