# 확정 시나리오 — 설계가 어디서 받치고 어디서 모자라나

`[2026-09-10]` 팀이 대표 시나리오와 페르소나를 정했다 — [`team_branch/jh/확정_시나리오.md`](../../team_branch/jh/확정_시나리오.md).
이 문서는 **그 시나리오를 기준선 v11 과 실제 코드에 대 보고**, 무엇이 되고 무엇이 모자라는지 적는다.

★**시나리오를 고치지 않는다.** 팀이 확정한 것이다. **모자라는 쪽은 설계와 코드다.**

---

## 0. 결론 먼저 — 다섯 줄

1. **사건 여섯 중 셋은 「먼저 감지」가 아니라 「물으면 답한다」다.** 요식-P3·요식-P7·액-08 은 고객이 겪거나 물어서 시작된다. 제품이 파는 「먼저 알아챈다」가 대표 시나리오에서 **절반만** 보인다.
2. **시나리오가 「최고 안 하나 적용」과 다른 동작을 두 번 요구한다.** 이동-B1 은 대안 둘을 **순위 없이 나란히**, 요식-P3 는 **대안 둘 중 고객이 고른다.** v11 §6-C 에 이 경우의 규칙이 없다.
3. **새 데이터 소스 다섯이 필요하다** — 대기질 · 실시간 지하철 운행 · 도로 통제 · 식당 당일 휴무 · 매장 재고. v11 §7-C 1단계 목록(기상·관광정보·장소·이동)에 **하나도 없다.**
4. ★**지금 감시 코드는 이 시나리오의 사건을 하나도 못 잡는다.** `watch.py` 의 fingerprint 는 장소명·좌표·주소·분류 다섯뿐이다(아래 §3).
5. **페르소나가 대만인인데 기본 알림 언어는 한국어·영어다**(v11 결정 11). 번체 중국어가 없다.

## 3. ★감시 코드가 시나리오의 사건을 못 잡는다

`[실측 2026-09-10]` `final_project_cs/app/modules/travel_ops/watch.py:201~207` — 변화를 판정하는 값이 이 다섯뿐이다.

```python
watched = {
    "title": ...,           # 장소명
    "latitude": ..., "longitude": ...,
    "address": ...,
    "content_type_id": ..., # 관광공사 분류
}
```

★**여섯 사건 중 어느 것도 이 다섯 값을 바꾸지 않는다.** 식당이 임시휴무여도 이름·주소·좌표·분류는 그대로다. 역사 화재·도로 통제·기상은 장소 정보가 아니다.

| 그러면 무엇을 봐야 하나 | 어디서 | 지금 |
|---|---|---|
| 영업시간 · 당일 휴무 | Places `currentOpeningHours` · 업체 공지 | fingerprint 에 없다 |
| 실시간 지하철 운행 | 서울교통공사 · 공공데이터 | `read.transit` 미구현 |
| 도로 통제 | 서울시 교통 통제 공지 | 소스 없다 |
| 대기질 · 강수 | 에어코리아 · 기상청 | 강수만 |
| 매장 재고 | 업체 | 소스 없다 — MVP 밖(§7-C 3단계) |

★**계획서 v11 §0-1 은 「상황 변화를 먼저 감지한다」고 약속한다.** 지금 코드가 감지하는 변화는 **장소 정보가 바뀐 것**(이름·주소·분류)이고, 시나리오의 사건은 **운영 상태가 바뀐 것**이다. 둘은 다르다.

## 4. 설계에 더해야 할 규칙 — 선택지를 언제 보이나

★**시나리오는 두 방식을 섞어 쓴다.**

| 방식 | 사건 |
|---|---|
| **한 안 적용 후 통지** | 액-02 · 이동-A6 · 요식-P7 |
| **선택지 제시 — 고객이 고름** | 이동-B1(순위 없음) · 요식-P3 · 액-08(추천) |

v11 §6-C 는 「최고 안 하나를 적용한다」만 적었다. **시나리오에 맞추려면 언제 선택지로 넘기는지의 규칙이 필요하다.** 이동-B1 이 그 이유를 스스로 보여 준다 — *"어느 쪽이 빠를지는 버스 배차 사정에 따라 갈리므로 순위를 매기지 않은 채"*.

**제안하는 규칙** `[제안 — 팀 확인 필요]`

> **비교 기준(§6-C-2)을 판정하는 데 필요한 값이 `[미확인]` 이면 순위를 매기지 않는다.**
> 탈락 조건을 통과한 후보를 **나란히** 보이고 고객이 고르게 한다.
> 판정할 수 있으면 최고 안 하나를 적용한다.

★**이건 새 원칙이 아니라 §4-D 의 연장이다** — 모르는 것을 모델이 채우지 못하게 한다. 버스 배차를 모르는데 한쪽을 「최고」로 고르면 **모르는 값을 지어낸 것**이 된다.

★**요식-P3 는 다른 이유다.** 두 대안이 비교 기준으로 갈리지 않을 만큼 비슷하면(도보 6분, 둘 다 브레이크타임 없음) 취향의 문제라 고객에게 넘기는 것이 맞다. **동률이면 선택지** — 이것도 규칙에 넣는다.

**앞 판 원칙 중 계속 쓰는 것**

- **기상은 Mock 이 기본이고 실물도 한 번 보인다.** 액-02 가 기상 사건이다
- ★**재생임을 표시한다.** 사후 관측을 당시 예보로 둔갑시키지 않는다(§4-D)
