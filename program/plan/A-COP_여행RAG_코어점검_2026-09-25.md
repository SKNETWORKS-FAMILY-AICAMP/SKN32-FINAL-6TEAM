# 여행 RAG — 코어 경로 점검

`[실측 2026-09-25]` 코어(Controller · Context Broker · 검색기) 쪽에서 여행 RAG 가 어떻게
불리고 무엇을 돌려주는지 다시 본다.

★**쇼핑몰은 범위 밖이다**(2026-09-25 사용자 — "사실상 접은 상태"). 쇼핑몰 코퍼스
25문서·306청크는 DB 에 남아 있지만 여행 Team 은 `travel_*` scope 로만 검색하므로
**섞여 나오지 않는다.** 지우지는 않았다.

## 1. 코어가 RAG 를 부르는 길

```
Case (subject = 고객 문장)
  → Controller._task()
      policy_required = Team 이 required_context 에 "policy" 를 선언했고
                        그 capability 가 policy_optional_capabilities 에 없다
      필요하면  search_policy(tenant, case.subject, manifest.knowledge_scope)
      예외면    retrieval_failed=True
  → ContextBroker.build()
      정책 청크 → Evidence(source_type="policy")
      degraded = 조회 실패  또는  (필요한데 결과 0건)
  → Team.execute(task)
      Activity·Booking Handoff 는 여기서 read.policy 를 또 부른다
```

`[실측]` 여행 Team 의 RAG 필요 여부 — manifest 를 읽어 셌다.

| Team | RAG 를 켜는 capability | 면제 |
|---|---|---|
| activity | `check_cancelable` · `check_feasible` · `propose_change` | `activity.itinerary` |
| dining | `check_open` · `check_conditions` | `dining.itinerary` |
| mobility | `check_route` · `status` · `exception` | `mobility.itinerary` |
| booking_handoff | `verify` · `prepare_change` · `prepare_cancel` · `prepare_revert` | — |

**12개 capability 가 RAG 를 켠다. 면제는 `*.itinerary` 셋.**

## 2. ★대표 흐름은 RAG 를 안 탄다

`itinerary_team.py:63` — Case 상태에 `subject_ref.kind == "trip"` 이 있으면 `*.itinerary` 로 간다.

```python
return ref.get("kind") == "trip" and bool(ref.get("id"))
```

그리고 `*.itinerary` 는 세 Team 모두 **RAG 면제**다. 즉 **여행을 가리키는 Case 는 규정을
한 번도 안 본다.**

`case_engine.py` (시나리오 모드·하루 대조 시험의 조립)는 이것을 전제로 **도구 경로와
Controller 경로 둘 다에 `_no_policy`(부르면 예외)**를 꽂는다.

```python
tools = ReadToolbox(get_connection, policy_search=_no_policy, …)
self.controller = composition.build_controller(…, policy_search_fn=_no_policy)
```

★**지금은 맞다** — 그 조립이 여는 Case 는 전부 여행 참조라 RAG 가 불릴 일이 없다.
**다만 그래서 시연과 대조 시험은 RAG 를 증명하지 못한다.** 같은 파일 머리말이
"따로 짠 Controller 를 쓰면 대조가 운영을 증명하지 못한다"고 적었는데, RAG 에
한해서는 그 조립이 운영과 다르다.

`[미확보]` 대표 흐름에 **취소 문의**("비 와서 취소되나요")가 들어오면 어느 길로 가나.
여행을 가리키면 `*.itinerary` 라 규정을 안 보고, 안 가리키면 `check_cancelable` 로 간다.
**코퍼스가 가장 잘 답하는 질문이 대표 흐름에서는 규정 없이 처리될 수 있다.**
시나리오에 그 질문을 넣어 어느 capability 로 가는지 확인해야 한다.

## 3. ★실제 기록 — 140건이 근거 없이 사람에게 갔다

`[실측 2026-09-25]` 살아 있는 DB(`127.0.0.1:5433/acop_cs`).

| | 건수 |
|---|---:|
| 여행 Team 이 맡은 Case | 144 (mobility 141 · activity 3) |
| 여행 참조 있음 → `*.itinerary` → `completed` | **4** |
| 여행 참조 없음 → RAG 필요 → `guardrail_escalated` · `degraded_context` | **140** |

| 시각 | |

| 여행 코퍼스 적재 | **2026-09-22 22:11** |

★**원인은 코퍼스가 없던 때 돌았기 때문이다.** 그때 mobility 가 선언한 scope
(`mobility`·`transit`·`route_exception`, 09-10 실측)는 DB 에 문서가 없었다.

★**그래서 "지금은 된다"는 기록이 아니라 오늘의 직접 실행이다.** 아래 §4 의 두 질의가
전부다. **여행 코퍼스가 있는 상태로 Case 가 끝까지 돈 기록은 아직 없다.**

## 5. ★점수 문턱이 없다 — 엉뚱한 질문도 근거 8건

검색 SQL 은 `ORDER BY 거리 LIMIT top_k` 뿐이다(`retriever.py`). scope 에 청크가 8개 이상이면
**어떤 질문에도 8건**이 온다.

`[실측 2026-09-25]` activity scope, 질의 6건.

| | 질의 | 건수 | 최고 점수 | 1위 |
|---|---|---:|---:|---|
| 관련 | 비 오면 한강 카약 예약 취소되고 위약금 있나요 | 8 | 0.641 | t_doc_02 |
| 관련 | 공연 당일 취소하면 환불되나요 | 8 | 0.610 | t_doc_01 |
| 관련 | 경복궁 휴관일에 가도 되나요 | 8 | 0.568 | t_doc_03 |
| 무관 | 제 비밀번호를 바꾸고 싶어요 | 8 | 0.510 | t_doc_11 |
| 무관 | 오늘 환율이 얼마예요 | 8 | 0.486 | t_doc_01 |
| 무관 | ㅋㅋㅋ 안녕 | 8 | 0.423 | t_doc_05 |

★**「정책 근거 없음 → degraded」가 사실상 scope 가 비었을 때만 켜진다.** 무관한 질문도
근거 8건을 달고 "근거 있음" 으로 넘어간다. 근거 없는 확정을 막으려고 둔 장치가
**관련성은 안 본다.**

`[미확보]` 문턱을 어디 둘지는 이 6건으로 못 정한다. 관련 최저 0.568 과 무관 최고
0.510 사이가 벌어져 있지만 **표본이 여섯이다.** 질의 묶음을 만들어 재야 한다.
문턱을 넣으면 `degraded` 가 지금보다 자주 켜진다 — 사람에게 가는 비율이 오른다.

## 6. 같은 검색을 두 번 한다

`[실측 — 코드를 읽어]` Activity(`activity.py:143`)·Booking Handoff(`booking_handoff.py:97`)는
`read.policy` 를 부른다. 그 도구는 **ContextPack 의 `knowledge_scope`** 와 **`task.input_text`**
(= `case.subject`)로 검색한다(`read_tools.py:64,107`). **Controller 가 방금 한 검색과 질의·
scope 가 같다.**

- 임베딩 호출은 한 번이다 — `_embed_query` 가 `lru_cache(maxsize=64)` 로 캐시된다
- DB 검색은 두 번이고, 근거가 **같은 청크로 두 벌** 실린다(ContextPack 8 + 도구 8)

`[미확보]` 두 벌이 판정·검증(근거 대조)에서 문제를 일으키는지는 안 돌려 봤다.

2026-09-24 보고에서 **"provider 를 openai 로 되돌리면 여행 검색이 0건으로 조용히 떨어진다"**
고 했다. **틀렸다.** 09-22 에 이미 막혔다 — 고른 provider 의 벡터 칸이 비어 있으면
`search_policy` 가 **예외**를 내고, Controller 가 받아 `retrieval_failed` → ContextPack 에
`policy_rag:retrieval_failed` 가 붙는다. 조용하지 않다.

남는 것은 **코드 기본값이 `openai`**(`settings.py:86`)이고 여행 코퍼스는 그 칸이 0/130 이라는
사실 하나다. `.env` 에 `ACOP_EMBEDDING_PROVIDER=ollama` 가 없는 환경에서는 **여행 RAG 가 전부
실패로 뜬다** — 드러나긴 하지만 안 돈다.
