03구성요소 — Team 공통 내부

코드 확인 · 세 가드는 첫 실패에서 반환한다(_base.py:57~64). Controller의 규정 검색이 실패하거나 결과가 0건이면 degraded가 참이 되어 모든 팀이 도구 조회 전에 ESCALATE(degraded_context)로 끝난다(controller.py:86, context.py:252~261, _base.py:63~64). _unknown은 모름 사유를 가진 ESCALATE이며, 기준선 결정 15와의 차이는 8장 참조(_base.py:146~156).

코드 확인 · 실행기는 과제의 allowed_tools가 manifest 허용 목록의 부분집합인지 검사하고, 벗어나면 ToolScopeViolation을 낸 뒤 통과한 과제만 Team에 전달한다(executor.py:24~30, executor.py:31). _read는 허용 목록·호출 기록·예산을 전달하며, 허용 목록 밖이나 미등록 도구는 ToolNotAllowed로 차단된다(_base.py:68~78, read_tools.py:291~292, read_tools.py:298~299).

ToolScopeViolation·ToolNotAllowed·ToolLoopExceeded·ToolBudgetExceeded와 계약 검증 오류는 Team 결과로 바뀌지 않는다(executor.py:24~30, read_tools.py:291~306, contracts.py:272~274). run_case는 실행을 failed로 닫고 예외를 다시 던지며, 접수 백그라운드는 로그만 남겨 Case는 routing에 남는다(controller.py:256~260, cases.py:92~97).

코드 확인 · routing 상태의 실행 팀은 resolve() 결과를 그대로 쓰며, 저장된 owner_team_id는 재개 등 routing이 아닌 상태에서만 쓴다(controller.py:175, controller.py:187~188). capability는 ROUTED 기록용으로 한 번(controller.py:178, input_text 없음), 과제용으로 한 번(controller.py:75, controller.py:96, subject 전달) 계산한다. 등록이 바뀌어 저장된 소유 팀과 재해석한 팀이 달라지면 가드 1을 통과해도 가드 2에서 막힐 수 있다(_base.py:57~62).

04구성요소 — 팀별

아래 도해는 가드 셋을 통과한 경우다. 각 capability를 지정했을 때의 구현을 나타낸다. 분류된 intent는 itinerary_submit·incident_report·confirm_request·adjust_reject·other이며, 이 밖의 값은 ClassificationFailed로 거부된다(feedback.py:50~56, feedback.py:144~145).

선택 순서는 훅 → 네임스페이스 매칭 → 기본 capability → 첫 capability다(registry.py:105~119). select_capability 훅은 Mobility에만 있고, 분류된 다섯 intent에는 None을 반환한다(mobility.py:38~40). Activity·Booking Handoff·Dining에는 훅이 없으며 intent도 팀 네임스페이스와 맞지 않아 기본 capability를 쓴다. 따라서 분류 경로의 Activity와 Booking Handoff는 각각 activity.check_feasible과 booking.verify만 선택하며, 승인 대기 제안을 만드는 activity.propose_change·booking.prepare_change·booking.prepare_cancel에는 도달하지 못한다(activity.py:44, booking_handoff.py:36, registry.py:115~119).

예약 조회를 쓰는 네 팀은 case_id만 넘긴다(activity.py:66, dining.py:46, booking_handoff.py:45, locked_bookings.py:27). read.booking은 이를 무시하고 booking_id가 없으면 고객 예약 중 starts_at가 가장 이른 1건을 반환한다. 종류·과거·취소 여부는 걸러내지 않는다(read_tools.py:143~162). 결함과 완료 기준은 8장 참조.
