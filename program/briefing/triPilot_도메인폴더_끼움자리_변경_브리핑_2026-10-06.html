여행 코드의 자리를 정리했습니다 — 파일을 옮기고, 서로 부르는 방향을 뒤집었습니다

기능은 바뀌지 않았습니다(라우팅 재배분 하나만 새 동작). 다만 파일 경로가 거의 전부 바뀌었습니다. 각자 브랜치에서 작업 중이면 합칠 때 import 가 깨집니다 — 아래 2번이 대응표입니다.

가장 급한 것

내 코드에서 app.modules.travel_ops… 를 부르고 있다면 전부 바뀝니다.

새 뿌리는 app.domains.travel_ops 이고, 그 아래가 여섯 칸으로 갈렸습니다. app/infrastructure/travel/(관광공사 · 기상청 · 교통 등 외부 소스)도 여행 묶음 안으로 들어왔습니다. 대응표는 바로 아래에 있고, 못 찾는 파일은 git show --name-status 0d0b96c0 | grep 파일이름 으로 찾습니다.

1. 무엇을 왜 했나

한 폴더에 69개 파일이 섞여 있어서, 무엇이 끌 수 있는 기능이고 무엇이 꼭 있어야 하는 부품인지 코드만 봐서는 알 수 없었습니다.

한 일왜
① 파일을 칸으로 나눴다 업무 영역 하나를 폴더로 묶고 그 안을 역할별로 가르는 방식(모듈러 모놀리스). 어떤 파일이 어떤 성격인지 자리로 드러나게 했습니다.
② 서로 부르는 방향을 뒤집었다 필수 부품이 「끌 수 있는 기능」과 「팀 내부」를 직접 부르고 있었습니다(20곳). 그러면 그 기능을 끄거나 팀을 빼는 순간 부품이 깨집니다 — 「꽂고 뺄 수 있다」가 거짓이었습니다.
③ 라우팅이 어긋나면 한 번 더 고른다 받는 팀이 없으면 Case 가 escalated 로 끝났는데, 우리 제품에는 사람 운영자 큐가 없습니다 — 그 Case 는 아무도 받지 않습니다.
④ 시험 10건의 컴퓨터 의존을 없앴다 일정 생성기 시험이 개발 DB 에 요식 원장 자료가 있는 사람에게만 붉었습니다. 원인을 찾아 고정했습니다.

3. 칸이 여섯입니다 — 새 파일은 어디에 두나

app/domains/travel_ops/
├─ modules/      끌 수 있는 기능    꺼도 나머지가 돈다 (web_account · mcp · live_progress)
├─ instances/    에이전트 팀        팀 하나 = 폴더 하나 (activity · dining · mobility · booking_handoff · locked · _shared)
├─ components/   필수 부품          빼면 여행 서비스가 안 돈다 (itinerary · planning · places · intake ·
│                                       conversation · actions · booking · watch · customer · core_hooks · team_hooks)
├─ ports/        바꿔 끼우는 자리    구현을 갈아 끼운다 (data_sources — 관광공사 · 기상청 · 교통 …)
├─ entry/        고객 입구          HTTP 경로
└─ scenarios/    시연 · 하루 대조 시험용 조립
이런 걸 만들면여기에 둡니다

★ 팀이 다른 팀 안을 직접 부르면 시험이 막습니다(tests/architecture/test_travel_ops_cells.py). 팀끼리는 플랫폼 코어를 거쳐서만 만납니다.

4. 끼움 자리 — 부품이 우리 팀을 부르는 방식이 바뀌었습니다

여기가 이번 변경에서 가장 중요한 대목입니다. 실무에서는 의존성 역전(DIP) · 포트와 어댑터라고 부릅니다.

전 — 부품이 팀 이름을 알았다 
# components/watch/dawn_check.py
from ...instances.dining.ledger \
     import dining_states

states = dining_states(conn, tenant, slots)

요식 팀을 빼면 감시가 import 단계에서 죽는다

후 — 부품은 자리만 안다 
# components/watch/dawn_check.py
from ...components.team_hooks \
     import dining_ledger

states = dining_ledger.states(conn, tenant, slots)

요식 팀이 없으면 None(모름) — 안 죽는다

꽂는 쪽은 조립 한 군데 — app/composition.py 
def wire_domain_teams():
    dining_ledger.register(add_nearby=…, states=…, state=…, find_by_name=…)
    legs.register(leg_planner=…, disruptions_from_events=…, walk_limit_m=…)
    similarity.register(score=…, preference_of=…, distance_first=…)
    watch_planners.register("dining", …)   # 활동 · 이동도 같은 모양

자리 일곱

자리부품이 묻는 것꽂는 쪽안 꽂으면
team_hooks/legs이동 시간 · 노선 · 사고 · 도보 상한이동 팀계산기 None(어림값)
team_hooks/dining_ledger근처 식당 · 시간대 영업 판정 · 이름 찾기요식 팀판정 None(모름)
team_hooks/similarity활동 유사도 · 설문 선호 · 거리 우선활동 팀점수 None(거리만)
team_hooks/watch_planners항목 종류별 감시 판정세 팀None — 그 종류는 안 함
itinerary/trip_scope감시 · 안내 대상 좁히기웹 계정TRUE — 전부 감시
settings_hook운영자가 화면에서 바꾼 값웹 남용 방어None — 가드레일 기본값
progress_hook진행 알림 포장(SSE)실시간 진행[] — 실시간 화면만 없음
★ 안 꽂혔을 때의 답은 「새로 만든 기본값」이 아닙니다. 일곱 모두 그 팀 · 기능이 조립에 없을 때 부품이 원래 가던 길 그대로입니다. 영업 여부를 모르면서 「열었다」로 답하지 않고, 다른 팀 계산으로 대신하지도 않습니다 — 값을 지어내지 않는다는 규칙 그대로입니다.

5. 라우팅이 어긋나면 한 번 더 고릅니다 (새 동작)

분류가 붙인 대상 종류를 받는 팀이 없으면 Case 는 escalated 로 끝났습니다. 「모르는 것을 아무 팀에나 보내지 않는다」는 맞지만, 우리에겐 사람 운영자 큐가 없습니다. 그래서 그 Case 는 아무도 받지 않습니다.

들어온 길escalated 가 되면
고객이 웹 · 계획서에서 말을 걸었다답이 바로 화면에 나갑니다 — 「말씀을 제대로 알아듣지 못해 일정은 바꾸지 않았어요」 + 할 수 있는 일 예시. 사람 대기 약속은 하지 않습니다.
감시 루프 · 에이전트 API 가 Case 를 열었다아무 말도 안 나갑니다 — 알림을 만들지 않습니다. 여기가 구멍이었습니다.

어떻게 고르나 — 지어내지 않습니다

  • 고를 수 있는 값은 지금 등록된 팀이 실제로 받는 종류뿐입니다(목록은 코어가 넘깁니다 — 어휘를 재배분기에 적어 두지 않았습니다).
  • 목록 밖을 내면 한 번만 다시 묻고, 그래도 밖이면 포기합니다.
  • 돌려받은 답도 그대로 믿지 않습니다 — 그 종류로 팀 등록부에 다시 물어 실제 받는 팀이 있을 때만 넘깁니다.
  • Case 당 한 번만. 포기하면 종전대로 escalated 입니다(그 길을 없애지 않고, 그리로 가는 수를 줄입니다).
  • 끄는 스위치: travel.routing.reroute_enabled(기본 켬). 모델 호출은 라우팅이 실패한 Case 에만 최대 2회입니다.

★ 실서버 확인(서버 응답): 안 했습니다. 이 PC 는 OpenAI 크레딧이 없고 로컬 Ollama 도 떠 있지 않아 실제 모델이 어떤 팀을 고르는지는 아직 못 봤습니다. x600 서버의 cs 프로젝트 서버에 배포한 뒤 확인합니다. 지금까지는 mock 시험 10/10(동작 규칙)입니다.

6. 시험을 돌릴 때 알아 둘 것 셋

무엇내용
시험도 조립된 상태로 돈다 tests/conftest.py 가 매번 팀 배선을 꽂습니다. 단위 시험은 조립을 거치지 않아서, 안 꽂으면 「팀이 하나도 없는 상태」를 재게 됩니다. 팀이 없는 상태를 재려면 그 자리의 clear() 를 직접 부릅니다.
팀 함수를 바꿔 끼울 때 부품 모듈이 아니라 팀 쪽 함수를 patch 합니다 — 예: dawn_check.dining_states(✕) → instances.dining.ledger.dining_states(○). 자리는 부를 때 모듈에서 읽으므로 그대로 먹습니다.
일정 생성기 시험은 원장을 끈다 tests/e2e/test_trip_planner.py 가 요식 원장을 끄고 돕니다. 원장은 테넌트와 무관한 공용 표라, 자료를 넣은 기계에서는 후보가 12곳이 아니라 1,778곳이 되어 10건이 그 기계에서만 붉었습니다(이 PC 실측 1,766곳).

★ 큰 묶음을 한 번에 돌리면 개발 DB 가 겹쳐 간헐 실패가 납니다 — 나눠 돌리세요(구조 · 계약 · 단위 · 보안 / 통합 / e2e · 시나리오).
