# 오라클 서버 접속을 유지하는 배포 계약

2026-10-18 사용자 지시: 오라클 서버는 서비스가 멈추지 않게 업데이트한다. 아래는 구현 전에 확정한 배포 요구이며, 현재 구현 완료 선언이 아니다.

## 배포 순서와 보존 조건

1. 실행 중인 고객 API·웹을 유지한 채 새 판을 별도 내부 포트에 먼저 띄운다. 기존 이미지·설정·DB·자료를 보존한다. 빌드 실패·메모리 부족·상태 검사 실패면 접속 경로를 바꾸지 않는다.
2. 새 판의 API·웹, 실제 DB 연결·인증·권한·교통 조회·모델 대체 호출을 점검한다. 단순 생존 응답만으로 고객 경로 성공을 선언하지 않는다. 모델 단독 응답·합성 여행·실제 고객 결과를 각각 기록한다.
3. 기존 접속 프로그램은 재시작하지 않고 설정 검증 뒤 다시 읽는다. 배포 잠금과 변경 전 설정 해시 대조로 동시 작업을 막고, 실패 시 기존 유효 설정을 보존한다. 요청을 처리하던 이전 앱은 연결이 끝날 때까지 유지한다.
4. 기존/새 판이 함께 쓸 수 있는 DB 확장만 먼저 적용한다. 고객 자료 삭제·기존 열 제거·의미 변경은 같은 회차에서 하지 않는다. 실제 백업·복원 검증과 버전 호환 확인을 따로 남긴다.

## 중복 실행·연결 보호

- 감시·알림 worker는 동시에 두 개를 돌리지 않는다. 이전 회차를 정상 완료한 뒤 새 worker가 이어받는다. 고객 API와 웹은 그동안 계속 응답한다. 처리 중 작업을 강제 종료하거나 동일 알림을 재발송해 인계하지 않는다.
- 관리 화면은 고정 포트를 별도로 사용하는 현재 구조이므로 고객 API/web의 병행 기동 성공만으로 관리 화면까지 무중단이라고 보고하지 않는다. 운영 API·관리 웹도 별도로 확인한다.
- 실패한 연결 재시도를 설정한다. 이미 요청이 전달된 뒤 실패한 쓰기 요청은 무조건 재시도하지 않는다. 고객 변경의 멱등성·동시성·CSRF·인증은 유지한다. GET/HEAD의 안전한 재시도와 연결 전 실패를 구분한다.
- 실시간 진행 연결·MCP 연결은 전환 시 즉시 끊지 않는다. 기존 앱 연결을 자연스럽게 마칠 때까지 보존하고, 앱의 정상 종료 시간을 실제 측정한다. 현재 Caddy2.6.2에는 최신 문서의 stream_close_delay 항목이 없으므로 그대로 추가하지 않는다. 지원되는 설정 검증·정상 다시 읽기와 실제 스트림 지속 측정으로 확인한다. 새 웹으로 전환한 뒤에도 이전 페이지가 요청하는 정적 파일을 보존한다.
- 상태검사·연결 실패 시 이전 정상 앱으로 보낼 수 있어야 한다. 후보의 포트 충돌·이미지/설정 지문 불일치·동시 배포를 감지하면 기존 앱을 유지하고 중단한다.
- 이 계약은 에이전트 예약·새 반복 작업을 만드는 승인이 아니다. 배포 후 원본·자료·이미지를 임의 정리하거나 새 유료 인프라를 만들지 않는다.

## 12:48~12:56 실제 점검 범위

읽기 전용으로 현재 Caddy2.6.2, API 메모리약1.01GiB·물리여유약4.93GiB·스왑0을 확인했다. 후보 API/web상한합2GiB 외에 최대2GiB빌더의 동시사용을 고려해야 한다. 실제 worker에는 정상종료 최대600초·회차완료 대기가 반영돼 있다. 현재 오라클 서버의 API·웹·worker·관리자 앱4개가 실행 중이고 API·웹2/2가 응답하는 것을 확인했다. 접속 설정은 API와 웹 각각 하나만 연결하는 구조였다. 따라서 이 확인만으로 무중단 배포 설정이 완료됐다고 하지 않는다.

별도 작업 「오라클 서버 우천 알림 점검」은 사용자에게 새 API 별도 기동→세 경로 검증→접속 전환→기존 요청 완료 유지를 약속하고 구현 중이다. 이 작업은 해당 소스·설정·운영 경로를 동시에 변경하지 않고 실제 반영 뒤 독립적으로 점검한다. 기존 배포 스크립트에 대한 참고본과 실행본은 지문이 달라 참고본으로 덮어쓰지 않는다.

공식 근거: [Caddy의 상태검사·재시도·스트림 처리](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy). 현재 확인과 미확인·실패는 [현장 복구 기록](../records/reports/2026-10-18_festival-traffic-alert-recovery.md)에 보존한다.

## 13:06 KST — 교차 검토와 담당 전달

사용자 직접 전달 지시에 따라 오라클 작업 담당에게 본 계약·최종 의미수정 manifest·UTIC 원문을 보냈고 담당의 읽기를 확인했다. 읽기 전용9항목 검토는 완료했으나 실제 전환·연결 유지 시험은0/1로 남는다.

추가 확인: 기존 고객세션은 같은 Postgres와 비밀키를 사용해야 한다. Caddy 기본 연결 유지와 API앱의 연결 유지 시간이 다르면 쓰기 요청이 연결 초기화 오류를 만날 수 있으므로 실제값을 맞추고 POST 전체 재시도로 숨기지 않는다. 서로 다른 웹 빌드의 이전 정적파일 보존과 배포 잠금·활성설정 동시성도 별도 확인한다.
