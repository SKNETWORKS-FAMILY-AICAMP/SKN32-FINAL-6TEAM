# 남은 것(막는 결함 아님, 제품 판단)

1. **P2 — S7:** 고객이 체크아웃 줄을 숙박으로 고르면 `ends_at` 없는 숙박이 problems 없이 등록 본문에 들어갑니다. 등록을 막는 것이 없습니다. 인계 「남은 것 3」을 실제로 확인한 것입니다. 원문 「…체크아웃」은 `_said_kinds`가 숙박 하나로 보기 때문에 종류 확인 질문이 생기지 않습니다. 따라서 이 경우는 확인 화면에서 고객이 직접 고칠 때만 생깁니다.
2. **P3:** 바뀐 종류의 안내(`filled` 안의 `items[n].kind`)는 `review._time_line`에 나오지 않습니다. 이 함수는 `starts_at`·`ends_at`만 그립니다. 안내는 `view.check.filled` 원본 목록에만 실립니다. 화면에서 「규칙으로 채움」으로 보이는지는 아직 확인하지 못했습니다.
3. **P3 — S6:** 시각 없는 짝 없는 체크아웃은 일반 활동 배치 규칙에 따라 09:00에 놓입니다. 숙박 기본값 11:00(`STAY_OUT`)과 다릅니다. 기준 트리는 이 줄을 본문에서 빼 버렸으므로, 이 처리는 개선입니다.
4. **P3:** 저장소 새 시험의 입력 제목은 실제 읽기 형태와 다릅니다. 동작은 원문 줄(`text`)로 판정하므로 실제 형태에서도 성립하는 것을 확인했습니다.
5. 기존 보안 HOLD(보호 XML)와 독립 검토 P2(좌표 차이 167 m인 같은 호텔)는 그대로입니다. 실제 모델 실행과 화면 수락 확인은 하지 않았습니다.
