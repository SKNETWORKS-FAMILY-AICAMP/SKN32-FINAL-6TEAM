- Git 기준 `405f970682cbc832cd3835589ae65a0f444fd48d`에 알림 v5와 정상 종료 실행기를 격리 통합했다. 후보 트리는 `a6cd5113c8aaca8de353641ff5ffa28cc0a37423`이며 아직 원격 Git에 게시한 새 커밋은 아니다.

## 배포 중 발견한 결함과 처리

- 첫 이미지에 추가한 빈 알림 문구 파일이 객체 `{}`라 발송 실행기가 거절했다. 독립 로컬 회귀 시험만으로 실제 이미지의 초기 파일 형식을 확인하지 못한 배포 입력 결함이다. 원래 실행기 코드는 목록을 요구하며 잘못된 파일을 거절하는 것이 맞다.
- 원본 이미지·실패 기록을 보존하고 빈 목록 `[]`를 넣은 새 이미지 층을 제작했다. 새 API·관리자 이미지에서 실제 `PhraseCache.load()`가 0개로 정상 종료하는 것을 각각 확인했다. 수정 태그는 `notice-a6cd5113c8aa-r3`이며 소스 코드 트리는 바뀌지 않았다.
- 수정용 전체 빌드 입력 해시는 `a5806807ecc43858c31b63ba83319b203d1090692900f391b9d8c84d206715d0`이다. 환경 파일·고객 자료·데이터셋은 포함하지 않았다.
- 첫 Linux 시험의 고정 종료 코드 가정도 보완했다. Bash와 dash의 실제 쓰기 실패 코드 차이를 독립 비교하는 v2 시험을 사용하며 실행기 코드는 그대로다.
- 자동 HTTP 도구 요청은 외부 진입단에서 거절됐지만 실제 브라우저로 공개 웹앱에 접속했다. 보안 차단 설정은 완화하지 않았다.

## 남은 일

- 수정 이미지 적용 후 알림 작업이 반복 정상 실행되는지 최종 확인한다. 기존 실패·발송 제외 메시지는 임의 재전송하지 않는다.
- 실제 Google 로그인 진입에서 `redirect_uri_mismatch`를 확인했다. 인증 제공처에 새 환경의 콜백 주소를 추가해야 한다. 현재 콘솔은 로그인 화면이라 사용자 직접 로그인·주소 추가 승인을 기다린다. 기존 환경의 허용 주소는 유지한다.
- 고객이 새 환경에서 로그인하고 알림 채널을 직접 연결한 뒤 실제 시험 발송 수신을 확인해야 한다. 당시 새 환경의 연결 채널은 0건이었다. 기존 고객 채널/DB를 복사하지 않았으며 실제 외부 알림 수신을 확인했다고 보고하지 않는다.
- 로컬 구현·시험과 오라클 ARM 실행 앱 반영, 실제 외부 제공처 확인을 구분한다. 고객 경로의 미확인 항목을 위 시험 통과 수치로 대체하지 않는다.
