# G 학습 모델 허깅페이스 비공개 백업 인계

> 2026-10-17 23:47 KST 사용자 지시로 이 채팅의 백업 예약을 삭제했습니다. 새 명시적 예약 설정 지시 없이 heartbeat·반복 확인을 다시 등록하지 않습니다. 아래 등록 이력은 당시 기록이며 현재 활성 상태를 뜻하지 않습니다. 기존 GPU 학습·평가 큐는 변경하지 않았습니다.


사용자가 두 학습 완료 후 학습된 모델을 허깅페이스에 백업하라고 요청했습니다. [전체 실행 안내](../../datasets/core/travel_tasks/20261017_audited_G/hf_backup_after_training_G/README_G.md)와 [작업 기록](../records/reports/2026-10-17_G_trained_model_hf_backup.md)을 먼저 확인합니다.

## 한 일

- 우리 자료로 학습하는 Winnow-E4B(Jev 계열)와 Gemma-4-E4B-it QAT 각각 전용 비공개 허깅페이스 저장소 생성, 쓰기·비공개 상태 확인. 현재는 대기 안내와 명시한 작은 합성 연결 시험만 있고 실제 학습 모델은 아직 백업되지 않았습니다.
- 모델 백업에는 실제 기반 가중치·새 어댑터·체크포인트·토크나이저·설정·라이선스·재현 코드·완료 증명·지문 포함. 원문 데이터·사람 답·SSH/HF 인증 제외. 로컬 검사 20/20과 실제 SFTP/비공개 업로드 2/2 통과.
- 허깅페이스 토큰의 A4000 저장이 자동승인 검토에서 거부되었습니다. **실행하지 않았고 우회하지 않았습니다.** 인증은 로컬 PC에 유지합니다. A4000에는 비밀 없는 파일 목록 준비 코드만 전달했습니다. 원격 토큰을 요구하는 초기 초안은 실행하지 않습니다.
- 로컬 여유 공간이 18:45 조회 약 0.54GiB여서 큰 모델의 로컬 사본을 만들지 않는 제한된 메모리 SFTP 전송기를 사용합니다. 인증은 이 PC에서 허깅페이스에만 사용하며 A4000에 전달하지 않습니다. 작은 검증 파일만 로컬 캐시에 보존합니다. 원본을 지워 공간을 만들지 않습니다.
- 기존 A4000 큐에 두 학습 성공 후 지문을 준비하는 CPU 작업 두 건 추가. 기존 작업 52개·Winnow PID·후속 평가 작업 보존. 원본 Git 상태 전환·원본 자료 삭제·모델 교체·새 GPU 실행기 없음.

## 이어서 확인할 것

1. [로컬 시작 도구](../../datasets/core/travel_tasks/20261017_audited_G/hf_backup_after_training_G/start_stream_backup_G.py)의 `--status`로 두 학습·파일 준비·로컬 프로세스·완료 영수증을 확인합니다. 실제 모델 업로드는 이 PC에서 실행합니다.
2. 파일 준비가 완료되고 실행 중인 프로세스·완료 영수증이 없으면 같은 도구를 옵션 없이 실행합니다. 숨김 로컬 프로세스로 시작하며 오래 걸리는 전송을 채팅 도구 한 호출에서 기다릴 필요가 없습니다.
3. 완료 뒤 [영수증 검사](../../datasets/core/travel_tasks/20261017_audited_G/hf_backup_after_training_G/verify_receipts_G.py)로 두 저장소의 비공개 상태·완료 커밋·파일을 확인하고 링크를 보고합니다. 실패이면 로그·부분 백업을 보존하고 원인을 확인하며 다른 내용으로 덮거나 원본을 삭제하지 않습니다.
4. 두 백업이 모두 실제 검증되면 이 백업용 후속 확인만 종료합니다. 기존 모델 결과 평가 작업과 다른 자동화는 유지합니다. 주기적인 변화 없는 알림은 보내지 않습니다.

커밋·푸시·제품 배포는 하지 않았습니다. 접속 정보와 실행 증거는 git 밖 데이터 폴더에만 있습니다.
