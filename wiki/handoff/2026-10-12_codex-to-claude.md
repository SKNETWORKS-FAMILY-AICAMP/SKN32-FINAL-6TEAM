# Codex에서 Claude로 이어받기 — 2026-10-12

제품 사양은 최신 확정 결정과 계약이 정본이고, 구현·배포 상태는 현재 코드와 해당 환경의 실행 기록이 정본입니다. 과거 계획·동결 인계·아래 수치를 현재 상태로 대신하지 마십시오.

## 확인된 범위

| 항목 | 상태 | 확인된 내용 |
|---|---|---|
| 독립 재검증 | 완료 | 이전 실패 영향 22/22 통과 |
| 수정 영향 검사 | 완료 | 로그인·권한·보안 156/156, 이력 단계 분류 14/14 통과 |
| 전체 시험 대조 | 완료 | 통합 원본 7/7 집계·해시 일치 |
| 제품 전체 인수 | 미완료 | 고유 시험 집계에 실패 2, 준비 오류 14, 건너뜀 7이 남음 |
| 실제 환경·사용자 경로 | 미완료 | 실제 개인 AI 종단, 운영 PostgreSQL, 외부 제공처, 운영 영속 저장소 인수는 별도 |
| 모델 큐 | 등록됨 | 학습·평가 완료가 아님. 현재 상태는 큐 검사기로 다시 확인 |

시험 수치는 해당 인계 보고서에서 합친 고유 시험 식별자 기준이며, 한 번의 전체 실행에서 모두 통과했다는 뜻이 아닙니다. 시험 결과를 제품 완료율로 바꾸지 마십시오. mock 서버 시험과 실서버 확인도 보고서에서 구분합니다.

## 이어서 할 일

1. 작업 직후 `git status --short`와 필요한 `git diff -- <경로>`를 확인합니다. 현재 작업 폴더에는 여러 작업에서 나온 수정·신규 파일이 함께 있습니다. 작성자를 추측하거나 한꺼번에 되돌리지 말고, 맡은 범위의 변경만 살펴봅니다.
2. 사용자가 요청한 구체 작업이 있으면 관련 현재 wiki 계약, 호출 경로, 시험을 읽고 그 작업을 이어갑니다. 검증·문서 정합성을 요청받으면 [문서 검사기](../../program/scripts/check_wiki.py) 사용법과 [문서 정합성 점검 일정](../../program/research/index.md)을 먼저 확인합니다.
3. Winnow·Saluki 큐를 이어갈 때는 전용 인계의 순서·제약을 따르고, 큐 검사기로 상태를 다시 읽습니다. GPU 작업을 새로 만들거나 기존 작업을 다시 등록하지 않습니다.
4. 시험이 필요하면 사용자가 요청한 범위에서 실행하고, 실행하지 않은 항목·실패·준비 오류·건너뜀을 그대로 보고합니다. 문서나 산출물을 덮기 전 같은 폴더의 `_backup/<날짜_사유>/`에 원본을 복사합니다.
5. 변경 기록은 새 날짜별 보고서로 추가하고, 정본 wiki에는 결론과 링크만 반영합니다. 배포·재시작·외부 전송·commit·push는 이번 인계 문서가 승인한 것으로 보지 않습니다.
