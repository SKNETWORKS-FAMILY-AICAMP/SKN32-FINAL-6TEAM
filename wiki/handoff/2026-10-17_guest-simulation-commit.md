# 게스트 여행 시뮬레이션 커밋·배포 인계

2026-10-17 사용자 요청: 커밋 담당 채팅에서 이번 변경을 매니저 브랜치로 커밋·푸시하고 운영 환경에 반영한다. develop 반영 요청은 아니다.

## 완료한 일

- 게스트 전용 여행 선택상자, 한국 날짜 범위 조회, 10개 단위 페이지 이동을 구현했다. 기존 감시 대상 목록과 구분하고 날짜·페이지 변경 때 선택을 해제한다.
- 끝난 게스트 여행은 조회만 허용한다. 관리자가 켠 유효한 시험의 해당 게스트만 감시 대상에 잠시 포함하고, 중지·만료·판 변경 시 예외를 끝낸다. 재난 정지 중 새 시험 거부와 외부 시험 알림 발송 차단을 유지한다.
- 로컬 격리 DB/API·구조 시험 91/91, 전체 관리자 앱 mock 서버 화면 시험 4/4, 빌드·타입·린트 검증을 완료했다. 375px·1280px 화면을 확인했다. 상세는 [검증 기록](../../final_project_cs/wiki/records/reports/2026-10-17_0944_guest-simulation-catalogue.md)에 있다.

## 커밋 담당자가 이어서 할 일

이번 기능의 변경만 추린 [13개 파일 패치](../../.tmp/guest-simulation-20261017/guest-simulation.patch)를 준비했다. 기존 파일은 [작업 시작 시 백업](../../final_project_cs/_backup/2026-10-17_0918_guest_simulation/)과 현재 파일의 차이만 포함했다. 특히 감시 구현 파일에는 작업 시작 전에 다른 변경이 있었으므로 파일 전체를 교체하거나 현재 저장소 전체 변경을 한꺼번에 커밋하지 않는다.

팀·개인 최신 매니저 브랜치 위에서 기존 변경을 보존해 통합·검증한다. 운영판의 재난 정지 표시·새 시험 거부 등 후속 수정을 되돌리지 않는다. 관리자 앱·목록 API·감시 작업 규칙이 함께 반영되어야 한다. 신규 DB 마이그레이션은 없다.

기여·게시 규정과 저장소 전체 비공개 접속정보 검사를 완료한 뒤 팀·개인 `role-manager`에 모두 푸시한다. `develop`·`main`은 이번 요청 범위에 포함하지 않는다. 매니저 브랜치에 CI를 추가하지 않는다. 양쪽 반영 해시와 운영 배포 판본, 게스트 목록·날짜·페이지의 읽기 전용 확인 결과를 각각 남긴다. 실제 고객 여행에 재난 입력을 켜는 운영 시험은 수행하지 않는다.
