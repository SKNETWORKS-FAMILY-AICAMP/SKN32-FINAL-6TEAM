## 남은 일

- GPU 전용 비밀키의 EKS Secret 저장·비공개 연결 앱 배포는 자동 승인 검토가 차단했다. 구체적 승인 질문을 보냈으며 우회하지 않는다.
- 외부 운영 키·웹훅·관리자 로그인 설정·임베딩 키 이전은 별도 명시적 승인을 기다린다.
- API 정상화·지식/장소 자료 준비·실제 고객 여행/알림 경로·도메인/HTTPS는 미완료다. 원래 빈 관광공사/기상 키도 있다.
- 모델 연결 전에 API에 도달하지 않는 주소를 넣어 정상처럼 표시하지 않는다. 기존 GPU 학습/실행을 중단하거나 모델을 다시 올리지 않는다.
- 새 예약·자동화·제품 CronJob·커밋·푸시·원본 삭제는 수행하지 않았다.


## 승인 적용 후 현재 상태

앞의 세 항목 대기는 해결됐다. DB 비밀번호 교체·외부 운영 키/관리자 설정·최초 GPU 전용 키 저장과 배포를 적용했다. API 정상 기동과 RunPod 실제 추론, 장소 사실 정보 6,138행을 확인했다. 배포 tenant 행 누락에 따른 모니터링 외래키 오류도 fatal=0으로 해결했다.

현재 승인 대기는 별개의 두 항목이다: 새 x600 전용 키의 EKS 저장·자동 전환 설정, 정책/안내 19문서 141절의 OpenAI 임베딩 전송. 각각 구체적 승인 질문을 보냈다. 기존 oracle-arm 연결과 GPU 실행기는 유지했다. x600 Ollama 관리 앱은 SSH 세션 밖에서 복구했다. 준비된 자동 전환 스크립트는 개인 격리 작업 경로에 있으며 임시 폴더 권한 수정까지 반영했다. 승인 전 실행하지 않는다.


### x600 연결 준비 수정

직접 외부 SSH는 AWS에서 시간 초과였다. x600→oracle-arm의 별도 역방향 모델 통로를 실제로 준비했고 로컬 전용 키 조회를 확인했다. 기존 RunPod 연결은 유지됐다. 역방향 비밀키는 x600에만 있다. AWS 전용 키의 EKS 저장은 여전히 승인 대기다. 승인 뒤에는 개인 격리 경로의 [자동 전환 적용기](../../.tmp/eks-private-20261018/apply_x600_fallback.py)를 사용한다. 이전의 세 Deployment 분리 준비안은 사용하지 않는다. 기존 모델 Service를 유지하고 연결 Pod 안에 대체 연결을 넣는 최종안이다.


### 재개 순서

1. 대기 중인 두 승인 답변의 범위를 확인한다. x600 전용 키 EKS 저장과 자동 전환, 정책/안내 본문 OpenAI 전송이 각각 필요하다.
2. x600 승인이 오면 [최종 자동 전환 적용기](../../.tmp/eks-private-20261018/apply_x600_fallback.py)를 실행한다. 역방향 통로는 준비·로컬 조회가 끝났다. 기존 모델 Service를 유지한다. AWS 전용 연결만 대상으로 장애 전환과 복귀를 검증하며 기존 oracle-arm RunPod 연결을 중단하지 않는다.
3. 문서 전송 승인이 오면 [여행 지식 적재기](../../.tmp/eks-private-20261018/ingest_travel_knowledge.py)를 실행한다. 승인한 19문서 141절과 개인정보 없음 표기를 검사하고, 고객/여행/대화 표를 읽지 않는다.
4. [개인 운영 도구](../../.tmp/eks-tools-20261018/manage.ps1)로 현재 상태·관리자 내부 연결·SSH를 수동 실행할 수 있다. 새 예약을 등록하지 않는다.


### 서비스 도메인 HTTPS 완료

사용자 지정 도메인과 ACM 검증 DNS 등록 후 기존 NLB에 TLS 443을 연결했다. 공개 웹·API health·HTTP 리디렉션 완료 3/3. [확인 범위와 기록](../records/reports/2026-10-18_eks-domain-https.md). x600 자동 전환은 사용자 지시로 나중에 진행한다. 정책 문서 OpenAI 전송은 별도 승인 대기를 유지한다.
