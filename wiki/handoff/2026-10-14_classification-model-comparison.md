# 학습 분류 모델(kf-deberta) 미연결 이유와 제품 모델 비교

작업일 2026-10-14, 정리 2026-10-18. 세션 「요청 분류 모델 연결 확인」 종료 인계입니다.

## 결론

- 학습 분류 모델이 제품에 연결되지 않은 것은 **연결 코드가 처음부터 없었기 때문**입니다.
- 같은 여행 정답 96문장에서 `feedback.classify` 경로의 제품 모델(x600 서버의 `tripilot-pointer:e4b-ft`)과 견주니 학습 모델은 **낫지 않았습니다.** 그래서 이 경로에는 연결하지 않기로 했습니다.
- 다만 이 비교가 잰 경로는 **웹 채팅의 주 경로가 아닙니다.** 채팅은 결정 단위(모델이 할 일과 대상 일정을 고르고, 요청 종류·문제 코드는 `decision_unit.labels()` 고정 규칙이 만든다)로 처리됩니다.

## 남은 일 (사용자 결정 또는 다음 세션)

1. **x600 서버의 운영 설정 `chat.decision_mode` 가 지금 `on` 인지 확인하지 못했다.** 이 값에 따라 `feedback.classify` 경로가 쓰이는 비중이 달라진다.
2. **산출물 `.docx` · `.pdf` 는 다시 만들지 않았다.** 원본 스크립트만 고쳤다. 같은 파일 구성 표의 「문장 분류」 행은 채팅 경로 설명과 맞는지 다시 봐야 한다. 다시 만들 때는 기존 `.docx` · `.pdf` 를 `_backup/` 에 먼저 복사한다.
3. **분류 시험 묶음을 작업큐에 올릴지는 사용자 결정 대기.** 올리려면 실제 여행 문장에 사람이 정답을 단 자료(요청 종류 5종 · 문제 코드 18종 · 심각도)와 큐 담당 세션 의뢰서가 필요하다. 이 세션은 의뢰서를 보내지 않았다.
4. **커밋 · 푸시는 하지 않았다.** commit 세션이 오프라인이어서 경로 목록만 남긴다(아래).

## 확인 범위와 한계

- 정답 96문장은 사람 검수 전 초안이며 각 모델 1회 실행이다. 72건은 제품 프롬프트를 다듬는 데 쓰인 자료라 제품 모델에 유리하다. 따로 둔 24건은 한 건 차이라 두 모델을 구분할 수 없다.
- 제품 모델 쪽 실행이 유료 대체 경로로 새지 않았는지는 확인하지 못했다. 지연(p50 1.4초)만 로컬 모델 값에 가깝다.
- 작업큐 상태는 2026-10-14 03:25(UTC) 읽기 전용 조회 기준이며 오늘 값이 아니다.
