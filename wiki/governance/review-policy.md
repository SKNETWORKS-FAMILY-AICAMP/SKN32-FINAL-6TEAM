# 리뷰 정책

## 소유 원칙

**문서 하나에 소유자 한 명.** 공동 소유는 최대 2명까지만 허용한다. 셋 이상이면 아무도 안 고친다.

소유자는 front matter의 `owners`에 적는다.

```yaml
owners: [human:서유현]
```

소유자가 하는 일은 셋이다.

1. 내용이 낡았는지 판단한다
2. 다른 사람의 수정을 검토한다
3. `draft` → `stable` 승격을 결정한다

## 영역별 소유

| 영역 | 소유 |
|---|---|
| `product/` | 기획 담당 |
| `business/` | 기획 담당 |
| `architecture/` | Core 담당 |
| `delivery/` | 팀 리드 |
| `evaluation/` | 평가 담당 |
| `research/` | 조사한 사람 |
| `decisions/` | 결정한 사람 |
| `governance/` | 팀 리드 |

`[미확보]` 실제 담당자 이름은 팀에서 배정한 뒤 채운다.

## draft → stable 승격

`stable`은 **"믿고 인용해도 된다"**는 뜻이다. 다음을 전부 만족해야 올린다.

| 조건 | 확인 방법 |
|---|---|
| front matter 필수 필드가 채워짐 | CI가 검사 |
| 모든 `[실측]`·`[외부]` 주장에 근거가 연결됨 | 소유자 확인 |
| `[미확보]`에 "무엇이 필요한지"가 적힘 | 소유자 확인 |
| 소유자 아닌 1명이 읽고 이해함 | 리뷰어 승인 |
| 인접 문서로 링크가 걸림 | CI가 링크 검사 |

**이관해 온 문서는 무조건 `draft`로 시작한다.** 옛 문서가 새 구조에 들어왔다는 이유로 권위가 생기면 안 된다.

## 리뷰가 필요한 것과 아닌 것

| 변경 | 리뷰 |
|---|---|
| 새 `decision` 문서 | **필수.** 결정은 되돌리기 비싸다 |
| `contract` 문서 수정 | **필수.** 다른 저장소가 의존한다 |
| `stable` 문서의 결론·수치 변경 | **필수** |
| 불변식 추가·삭제 | **필수.** 테스트와 짝이라서 |
| `draft` 문서 작성·수정 | 불필요 |
| 오탈자·링크 수정 | 불필요 |
| `index.md`에 항목 추가 | 불필요 |

## 충돌 방지

**하나 — 한 문서는 한 사람이 고친다.** 동시에 고쳐야 하면 먼저 말한다.

**둘 — 새 문서는 `index.md`에 먼저 등록한다.** 제목과 `description`만 올려두면 다른 사람이 중복 작성하지 않는다.

**셋 — 큰 문서를 쪼갤 때는 미리 알린다.** 파일이 사라지면 남의 링크가 깨진다.

## 낡음 판정

`stale_after` 같은 자동 만료는 지금 쓰지 않는다. 이관 직후 수백 개가 한꺼번에 만료로 뜨기 때문이다.

대신 사람이 판정한다. 다음 세 시점에 확인한다.

| 시점 | 확인 대상 |
|---|---|
| 마일스톤 직전 | `delivery/`, `product/` |
| 계약 변경 시 | 그 계약을 참조하는 모든 문서 |
| 근거 등급이 바뀔 때 | 그 수치를 인용한 문서 |

**근거 등급이 `[추정]`에서 `[실측]`으로 바뀌면 결론이 바뀔 수 있다.** 그때는 인용한 문서를 전부 확인하고 `log.md`에 적는다.

## 현재 정합성 점검

마일스톤 직전에는 현재 wiki 결정·계약과 코드·제출물의 반복 사실을 대조합니다. 계약 변경 때는 인용 문서를 확인합니다. v11 등 옛 계획은 그 시점의 기록이며 현재 결정을 재승인하는 근거로 쓰지 않습니다.

| 대조 항목 | 확인 범위 |
|---|---|
| 변경 경로·기준선 링크 | 현재 wiki 정본과 실제 파일 |
| 에이전트 팀 집합·완료 기준 | 현재 결정의 적용 범위. 참고 구현과 제품을 구분 |
| 절 번호·인용 수치 | 실제 제목·정의 표·실행 기록 |
| 구현·검증·배포 상태 | 해당 변경·환경·확인 시각·근거. 미확인은 unverified |

정본 / 충돌 문서 / 판정 / 확인자 / 날짜를 기록합니다. 자동 검사 오류가 없다는 사실만으로 의미상 사양 일치·시험 통과·독립 검토 승인을 선언하지 않습니다. 이번 현재 대상은 [상태 적용 목록](implementation-inventory.generated.md)에서 자동 열거합니다.

## 병합과 과거 기록

[문서 병합 지침](../../program/research/_prompts/문서병합_지침.md)의 보완·중복·모순 분류를 따릅니다. 이미 승인된 후속 결정을 옛 문서와 다르다는 이유로 다시 승인 대기로 돌리지 않습니다. 의미가 미확정인 모순은 근거와 확인 필요 사항으로 남깁니다.

8~9월의 정본 포인터·도구·DoD 실측과 사고 사례는 [정리 전 원문](../records/reports/2026-10-12_review-policy-before-followup.md)에 보존했습니다. 과거 시점의 “현재”·미결정·집계 숫자를 오늘 지시처럼 사용하지 않습니다.

## 변경 이력

결론·수치·검토 상태·소유자가 바뀌면 저장소별 `log.md`에 기록합니다. 이번 분담의 변경·검사 결과·백업은 [후속 결과](../../program/research/baseline_completion_2026-10-12/tasks/wiki/report.md)에 연결하고 최종 통합 때 저장소 이력에 반영합니다.
