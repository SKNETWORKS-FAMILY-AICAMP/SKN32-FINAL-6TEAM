# 현재 여행 제품 범위

## 승인된 현재 범위 — 2026-10-12

고객이 이용하는 화면과 연결 경로는 아래 세 가지이며 같은 고객·여행·최신 일정 상태를 사용합니다. 각각 독립 제품을 만드는 뜻이 아닙니다.

| 고객 이용 방식 | 하는 일 | 접근 범위 |
|---|---|---|
| 고객 웹 앱 | 여행 입력·최초 일정 구성·검증 결과·변경 요청·설정 | 로그인한 고객 본인 여행 |
| 개인 AI 연동(API/MCP) | 고객 AI가 일정 제출·조회·질의·허용된 변경 요청 | 인증된 고객·도구 권한 범위 |
| 공유 여행계획서 링크 | 공유받은 최신 일정·변경 이유 열람 | 해당 공유 계약의 읽기 범위 |

최초 일정 구성과 여행 중 재계획을 구분합니다. 둘 다 지원 지역·장소 자료·시간·이동·예산을 검증하고 저장된 결과만 제시합니다. 항로 지킴이의 변경 조건은 [현재 설문 결정](../decisions/D-020-trip-survey-and-ask-first.md)을 따릅니다. 이 절은 승인된 제품 범위이며 OAuth를 포함한 모든 경로의 구현·배포 완료 선언이 아닙니다.


triPilot은 여행 일정을 검증하고 진행 중 변화를 확인해 조정하는 여행 CS 제품입니다. **현재 사양은 wiki의 후속 확정 결정·계약**이며 v11은 2026-09-10 당시 계획 기록입니다. 아래 범위 설명을 구현·배포 완료 주장으로 읽지 않습니다.

## 제품 범위와 업무

| 구분 | 기준 |
|---|---|
| 검증 대상 | 서울 여행을 우선 검증하며 도시 지원 주장을 검증한 범위 밖으로 확대하지 않음 |
| 에이전트 팀 | Activity·Dining·Mobility가 MVP, Booking Handoff는 다음 단계, Lodging·Flight는 잠긴 예약 취급 |
| 활동 범위 | 여행지에서 하는 활동. 백화점·시장 등 쇼핑 장소를 상품 주문·배송 업무와 혼동해 제외하지 않음 |
| 일정 처리 | 입력·검증·감시·변경·통지·재요청·이력·복구의 현재 계약을 따름 |
| 고객 접속 | [현재 REST](../../final_project_cs/wiki/external/rest-endpoints.md)·[MCP](../../final_project_cs/wiki/external/mcp-tools.md)·고객 웹 계약 확인 |
| 실행 경계 | 우리 일정 변경과 업체 예약·결제·환급 거래를 구분하고 필요한 고객 승인·권한을 유지 |

## 후속 결정과 코드 차이를 표시하기

항로 지킴이는 켜진 상태와 설정된 변경 조건에 따라 필요한 조정을 제시·처리합니다. 상주 상담원·운영 관리자가 대기하며 고객 문제를 대신 수정하는 구조를 전제하지 않습니다. 추천안을 최대한 만들고 불가피한 입력·선택은 고객이 수행합니다. 결함·미확인 장소는 개발자·QA의 사후 분석용 기록과 구분합니다.

옛 계획의 ‘계획 생성은 하지 않는다’·‘접점 둘뿐’·‘로컬에서만 실행’은 후속 코드·계약과 대조해야 합니다. 현재 MCP의 `tripilot_plan_trip` 등 구현을 지우거나 없는 기능이라고 단정하는 근거로 사용하지 않습니다. 후속 제품 범위 확정과 환경별 운영 반영 여부는 따로 기록합니다.

## 사양·완료의 근거

[Team 계약](../../final_project_cs/wiki/teams/team-contract/index.md)·[현재 구현 wiki](../../final_project_cs/wiki/index.md)·[평가 안내](../evaluation/index.md)에서 구체 조건을 확인합니다. 과거 도메인 데이터·대조군·시연·비용을 현재 제품의 판단·평가·완료 증거로 사용하지 않습니다. 모르는 값·원격 배포 상태·실고객 성능을 만들어 채우지 않습니다.

## 과거 기록

[수정 전 문서](../records/commerce_2026-10-11/wiki--product--scope.md)는 당시 기록입니다. 현재 여행 제품의 사양·평가·시연·완료 증거로 사용하지 않습니다. 원문 바이트는 같은 폴더의 백업에도 보존했습니다.
