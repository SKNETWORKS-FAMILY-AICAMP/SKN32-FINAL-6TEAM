# 고객 공지 저장과 알림 발송

2026-10-18 계약: 공지 저장과 고객 알림 발송은 별도 선택이다. 기존 종료 공지는 기록으로 저장할 수 있지만, 종료한 공지를 고객에게 새 알림으로 발송하지 않는다.

- 공지는 항상 시작보다 종료가 늦어야 한다. 고객 발송을 요청한 경우 종료 시각이 현재보다 뒤여야 한다. 발송하지 않고 기록으로만 저장하는 종료 공지는 기존 게시판의 종료 상태로 남긴다.
- 발송 요청은 대상 고객·테넌트·차단 상태·요청 중복을 확인하고, 공지 저장과 같은 트랜잭션에서 고객별 앱 알림을 저장한다. 디스코드 미등록·외부 발송 꺼짐은 앱 저장을 막지 않는다. 운영자 채널로 우회하지 않는다.
- 실제 외부 전달은 배달 작업이 담당한다. 성공·대기·미발송·실패를 분리하며, 전달 성공을 고객 열람으로 해석하지 않는다. 고객별 발송 설정은 발송 직전 테넌트별 DB 값으로 확인한다.
- 여행 변경 신호는 초기 상태를 보낸 뒤 확인된 상태 변화만 알린다. 신호 시험은 초기 상태 관찰과 제안 생성 관찰을 먼저 확인한 뒤 다음 변경을 수행한다. 고정 지연 시간만으로 두 변경의 선후 관계를 추정하지 않는다.

구현·배포·실제 고객 확인 범위는 [날짜별 기록](../records/reports/2026-10-18_notice-resend-and-service-delivery.md)을 따른다.
