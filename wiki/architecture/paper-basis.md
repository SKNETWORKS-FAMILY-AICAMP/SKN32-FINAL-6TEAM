# 아키텍처의 논문 근거

`[2026-09-24]` **"우리 아키텍처 베이스 논문이 뭐였지"에 답하는 문서다.**
검증 경위는 [재설계안 §2](../../program/plan/A-COP_아키텍처브리핑_재설계안.md) 에 있고,
여기는 **밖에 말해도 되는 문장과 안 되는 문장**을 정리한다.

## 한 줄

**arXiv:2601.03328** — *LLM-Enabled Multi-Agent Systems: Empirical Evaluation and
Insights into Emerging Design Patterns & Paradigms* (2026-01).

★★**다만 「베이스 논문」이라는 말은 정확하지 않다.** 설계의 출발점이 아니라
**이미 만든 구조를 대조해 본 논문**이다.

## 성격 — 출발점이 아니라 대조용

`[실측]` 팀 회의록([_회의_2026-09-09.md](../../program/research/_회의_2026-09-09.md) —
09-08~09-09 작업 기록)이 이렇게 적었다.

> 이 논문을 **보고 기존 아키텍처에서 부족한 지점들을 보완**하여 작업 중.
> 기반 패턴 4가지는 **이미 구현되어** 있음

Core·Team·Registry·Controller 구조는 이 논문보다 **먼저** 있었다. 논문은 2026-09-09 에
**빈 곳을 찾는 데** 쓰였고, 실제로 둘을 찾았다.

| 대조로 찾은 것 | |
|---|---|
| **출력 검증이 꺼져 있었다** | 다섯 점검 항목 중 하나가 비어 있다는 것이 이 대조로 드러났다 |
| **`max_steps` 가 선언만 되고 아무도 안 읽었다** | `[실측 2026-09-09]` 계약 정의·화면 표시·introspection 뿐이고 **실행 경로에 0곳**이었다 |

## ★인용이 틀렸다 — 밖에 이렇게 말하면 안 된다

`[실측 2026-09-10]` Claude 와 Codex(gpt-6-astra)가 **각각 따로** arXiv 를 받아 확인했다.

| 우리가 써 온 표현 | 실제 |
|---|---|
| 「논문이 정리한 **다섯 패턴**」 — 역할·능력 선언 / 도구 권한 좁히기 / 조정 대 자율 / 사람 승인 경계 / 출력 검증 | ★**논문의 패턴 목록이 아니다.** 논문 §4.2 Table 1 의 분류 차원은 **Control Flow · Interaction Styles · History Sharing · Network Configurations · Human Interaction** 이다. 우리 다섯과 겹치는 것은 **사실상 둘** |
| 「**최대 반복 횟수를 강제하라**」를 직접 인용 | ★**논문에서 찾지 못했다.** 반복 상한·종료 조건 요구가 없다 |
| Reflection 정의 · 「다른 주체가 검증한다」 | **논문에 없다.** 논문이 강조하는 것은 **사람의 관여**다 |

### 그래서 이렇게 적는다

| 쓰면 안 되는 말 | 쓸 수 있는 말 |
|---|---|
| "논문이 정리한 다섯 패턴" | **"논문의 논의를 우리 점검 항목 다섯으로 재구성했다"** |
| 반복 상한을 논문 인용으로 | **우리 설계 요구사항으로.** 인용을 떼고 우리가 왜 필요하다고 봤는지 적는다 |
| Reflection 정의를 논문 인용으로 | 동. 논문은 **사람 관여**를 말한다 |

★**심사에서 논문을 열면 바로 걸린다.** 없는 문장을 직접 인용으로 적는 것이 가장 위험하다.

### 확인 범위

`[미확보]` **arXiv HTML 판 기준이다.** PDF 본문 전체를 줄 단위로 훑지는 않았다.
**「못 찾았다」와 「없다」는 다르다** — 두 경로가 각각 못 찾았다는 것까지가 확인된 것이다.

## 같이 인용된 논문 하나 — 아키텍처와 무관하다

**arXiv:2606.19544** — *Reliability without Validity: A Systematic, Large-Scale
Evaluation of LLM-as-a-Judge Models* (2026-06). 채점 모델을 다룬 **평가용** 논문이다.

`[외부]` 9개 제공사 21개 채점자 · 약 54만 판정. 우리에게 쓰인 곳 —

- 평가에서 **"채점자가 긴 답변을 좋아해서 졌다"** 는 가설을 **약하게** 만들었다
  (2026년 채점자 21개 전부 장황함 편향 0.011 미만).
- 일치도를 잴 때 **정확일치와 kappa 의 격차**(33~41%p)를 미리 알아 두라는 근거.
- **분산이 0 인 축은 kappa 를 못 만든다** — 축을 만들 때 변별하는지부터 본다.
