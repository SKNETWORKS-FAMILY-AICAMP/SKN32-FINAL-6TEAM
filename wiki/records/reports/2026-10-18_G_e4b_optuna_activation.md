# Winnow 완료 뒤 E4B Optuna 탐색·선택 설정 본 학습 연결

## 2026-10-18 02:10 KST — 구현 전 실행 계약

사용자 승인: focal loss 제외, Winnow 성공 뒤 E4B Optuna 탐색부터 수행하고 탐색 범위에서 가장 나은 설정으로 본 학습한다. 원본 데이터·기존 모델 보존, 새 예약 생성 금지. 과거 최근 학습 Winnow와 최근 학습 E4B의 모든 테스트 우열도 확인한다.

- 기존 E4B 작업 한 건의 진입점만 새 별도 판으로 변경한다. Winnow·다른53개 작업·작업 순서·기존 실행기를 보존한다. 새 GPU 실행기·새 큐 작업·heartbeat·cron은 만들지 않는다.
- Winnow 전체 성공 증명 → 같은 슬롯 안에서 E4B Optuna 후보 탐색 → 탐색 개발 점수 최저 후보와 초기 기준 후보의 별도 개발 확인 → 선택 설정으로 CE 기존/통합 계산 교대 검증 → 검증한 계산 방식으로 원래 기반의 새 어댑터 전체 학습 → 기존 평가·백업 순서다. 전체 학습을 먼저 실행하거나 짧은 후보 어댑터를 전체 학습 완료본으로 취급하지 않는다.
- 탐색 범위는 앞서 안내한 학습률1e-5~1e-4(log), rank8/16/32, 12회×최대100단계. 기존5e-5/rank16 첫 시도 포함, TPE startup3, MedianPruner50단계. dropout0.05·alpha2r·누적8·정답만 CE. 최종 본 학습은18,478행·2회·4,620단계로 유지한다.
- 선택 목표는 개발4과제의 문항별 정답 NLL을 과제별로 평균한 뒤 같은 비중으로 평균한 값이다. 이는 자유 생성 정확도·모든 과제의 최적값이 아니다. family_id를 분리한 후보 확인32개에서 초기 기준보다2% 넘게 나빠지면 초기 기준을 선택하는 사전 규칙을 둔다. 최종 테스트·사람 답·기존 최종 평가 묶음은 선택에 쓰지 않는다.
- 후보마다 디스크 어댑터를 남기는 대신 모든 설정·점수·실패 로그를 보존하고, 탐색 중 최선·기준 어댑터의 새 가중치는 CPU 메모리에 유지한다. 최종 선택한 짧은 후보만 새 경로에 저장한다. 기존 파일이나 이미 저장된 후보를 삭제하지 않는다. 본 학습 복구 체크포인트는 각 회차 끝에 새로 저장해 여유 공간을 보존한다. 학습 계산·반복 수는 그대로다.
- 새 코드는 별도 폴더에만 준비하고 기존 세 코드·모델·자료를 교체하지 않는다. 기존 Python 환경은 바꾸지 않고 Optuna와 필요한 새 의존성은 새 전용 경로에서 사용한다. 실제 CUDA 비교·탐색은 Winnow 성공 전 실행하지 않는다.
- 준비 검사·실제 GPU 실행·최종 정확도를 구분한다. 배포 전에 미완료 Winnow 및 잘못된 큐 소유권 거부를 GPU import 이전에 검사한다. 큐와 백업 도구를 수정하기 직전에 각 기계의 _backup에 보존하고 다른 작업·Winnow PID·원본 지문을 대조한다.

### 준비 중 실패와 보존

- 초기 새 사본 업로드의 Windows 경로 구분자가 Linux 파일명으로 전달돼 CPU 검사가 거부됨. 실패 사본을 지우지 않고 새 올바른 경로에 추가 복사한 뒤 검사 통과. 해당 단계의 새 benchmark·명세를 먼저 백업.
- 최초 연결 시 로컬 새 명세의 CRLF/LF 차이로 지문 검사에서 중단됨. 큐 변경 전에 거부됐으며 로컬 명세를 백업하고 전달 바이트를 맞춘 뒤 연결 성공.
