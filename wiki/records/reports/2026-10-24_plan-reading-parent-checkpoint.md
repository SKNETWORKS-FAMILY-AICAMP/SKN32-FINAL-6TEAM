# 계획 읽기 복원 재검증

[실측] 부모가 현재 파일로 intake·계획 읽기·작성기 지정 unit을 네트워크/DB 차단 상태에서 재실행했습니다. 결과 285/285 = 100%, exit 0이며 로그는 현재 프로필 cache/scratch/plan-reading/parent-final-green.log입니다. 문의153건과 중복되므로 합산하지 않습니다.

신규 순수 모델읽기·사실검사·빈칸/제안 경계와 pipeline의 명시적 agent 주입 경계를 복원했습니다. 현재 정상 고객 API 활성화·실제 공급자 스트림·DB 제약 적용·prefill 적용·공통 라이팅 최종 응답 연결은 완료하지 않았습니다. 기존 고객 운영시간을 보존한 단위 시험을 포함하지만 실DB·화면·운영 확인은 아닙니다.

다음 절은 실제 계획서 API→process에 기존 설정·공급자 배선을 연결하는 새 child와, 감시 실행후 고객 안내 한 경로에 공통 응대 계약을 연결하는 새 child로 나눠 인계했습니다. 기존 정기 안내 비용·승인 경계와 다른 child의 메시지 투영/날씨 수정 파일을 보존합니다. 사용자에게 현재 추가 확인을 요구할 운영 변경은 없습니다. 서비스·DB 적용·외부 모델·배포·커밋·푸시는 하지 않습니다.
