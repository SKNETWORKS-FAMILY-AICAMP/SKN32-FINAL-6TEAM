# E4B Optuna 탐색 준비와 focal loss 적합성 확인

## 2026-10-18 01:15 KST — 실행 전 범위·예상 비용

- 사용자 요청: Winnow는 유지하고 E4B Optuna 탐색을 별도로 준비한다. 탐색 설정과 추가 시간을 먼저 알린다. 원본 데이터·기존 모델 보존, 예약 생성 금지. 이어서 focal loss가 무엇이며 파인튜닝에 도움이 되는지 질문했다.
- 현행 학습 코드와 10-17/18 G 인계·실측 기록에서 학습률5e-5·rank16·2회를 비교 실험으로 선정한 근거를 확인하지 못했다. 현행 코드는 고정 설정이며 Optuna를 사용하지 않는다. 이 설정을 최적값·검증된 값이라고 주장하지 않는다.
- 01:14 KST 일회성 조회: 우리 G 자료를 학습 중인 Winnow-E4B(Jev 계열) 2,250/4,620단계, E4B 대기. 조회만 수행했으며 현재 프로세스·큐·모델·자료는 변경하지 않았다.
- 준비할 1차 탐색: 학습률1e-5~1e-4(log), LoRA rank8/16/32, alpha=2×rank, dropout0.05 고정. 12시도×최대100최적화 단계, 동일800학습 예시·동일초기화·누적8. 기준 설정5e-5/rank16을 첫 시도로 포함. TPE startup3, 이후 결과 기반 탐색. MedianPruner로 50단계 이후 조기 중단 가능. 처음 비교에서는 focal loss를 제외한다.
- 이는 짧은 후보 선별이다. 2회 전체 학습의 최적값이나 최적 반복 횟수를 증명하지 못한다. 100단계 전용 warmup5·cosine을 사용하며 전체 학습 warmup231·총4,620과 다르다. 상위 후보의 더 긴 학습·최종 평가 검증은 별도다.
- 시간: Winnow의 최근 측정15.3초/단계를 대리값으로 쓸 때 12×100×15.3=18,360초, 계산만5시간6분. 로딩·검증을 더한 추가6~9시간은 계획용 예상이다. E4B 속도·rank 차이·검증 비용은 실측 전이며 상한 보장이 아니다. 조기 중단 이득은 미리 반영하지 않는다. 최종 본 학습·결과 평가·백업 시간은 제외한다.
- 현행 실행 흐름에는 연결하지 않고 로컬 새 준비 폴더에만 구현한다. GPU 탐색·추가 본 학습·예약·새 작업 등록은 실행하지 않는다.

## 데이터와 설명 확인 범위

- 원본 G 학습18,478행을 읽어 셌다: 일정 작업8,712 / 전체 생성5,992 / 항목 지목2,534 / 정규화664 / 자유글 추출215 / 종료 통지197 / 영향 통지164. 빈도 차이는 있으나 그것만으로 focal loss의 효과를 증명하지 않는다.
- 원본 개발2,705행은 4과제뿐이다. 전체 생성1,536 / 일정 작업1,056 / 정규화88 / 자유글 추출25. 일정 작업의 family_id는8개이므로 변형 문장을 서로 독립인 검증 사례로 주장하지 않는다. 탐색용·후보 확인용은 family_id 전체를 분리한다. 나머지3학습 과제의 일반화는 이 개발 자료만으로 검증할 수 없다.
- 현재 정답만 대상으로 하는 CE와 통합 CE는 같은 목적함수를 계산한다. Focal loss는 (1-p)^gamma로 쉬운 정답 토큰의 손실 비중을 낮춰 학습 목적함수를 바꾼다. 기존 통합 CE 커널의 단순 설정 변경으로 취급하지 않는다. 오답 표기·희귀 고유명사에도 상대적으로 집중할 가능성은 우리 생성 과제에 대한 추론이며 현재 모델에서 실측하지 않았다.
- [원 논문](https://arxiv.org/html/1708.02002v2) §3.2의 공식·실험은 객체 검출의 불균형에 대한 근거다. 우리 E4B 생성 품질·학습 속도 개선의 근거로 확장하지 않는다. [Optuna TPE](https://optuna.readthedocs.io/en/stable/reference/samplers/generated/optuna.samplers.TPESampler.html)와 [MedianPruner](https://optuna.readthedocs.io/en/stable/reference/generated/optuna.pruners.MedianPruner.html) 공식 문서를 확인했다.
