# EKS 실제 서빙 속도 후속

2026-10-29 KST, 사용자 요청을 이어받은 Codex. 루트·CS AGENTS/CLAUDE/RULE, wiki 목차·개발 역할·이전 EKS 진단과 scalar 전후 보고를 확인했습니다. 새 격리 main 사본은 `C:/_proj/eksserve1029/repo`, 기준 `57f3d2f004d0600f781599a6a92e8691b49bef82`입니다. 협업 NOTICE에 소유 범위와 운영 쓰기 0을 게시했고 두 독립 읽기 검토 작업자가 병목 구간·중복 계산을 확인했습니다. 기존 다른 작업자 사본·DB·프로세스는 변경하지 않습니다.

## 원인 확인 중간 기록

기존 전3/후3회는 모두 review까지 도달했지만 전체 성능 인과 개선은 입증하지 못했습니다. 원시 JSON을 새로 계산한 checking→review 합계는 181.60/319.43초 = 56.85%입니다. 이 비율은 여섯 회의 done 시간 합계에 대한 클라이언트 관측 구간 비율이며 CPU·운영 전체 비율이 아닙니다. pipeline.process의 최초 검사·위험 조회·먼저 채우기·해석 답 반영이 섞여 있으므로 정밀 원인 귀속은 아직 불가능합니다. GET 지연도 0.68~20.12초로 흔들려 CPU 경합·DB 대기도 분리해야 합니다.

새로 운영 접수를 만들거나 유료 모델·외부 provider를 호출하지 않았습니다. aws/kubectl/docker 실행 도구는 현재 PATH에서 발견되지 않았고 직접 pod/RDS 계측은 없습니다. 기존 비밀값을 출력하거나 권한 확대를 시도하지 않았습니다.

## 격리 후보·시험 중간 기록

이동 계획기의 `_mixed_sources`에서 동일 후보의 `_in_service`를 두 번 부르는 분할을 한 번의 안정 분할로 바꿉니다. 운행창 밖 후보도 뒤에 보존하고 순서·상한·물질화·대안 삽입은 유지합니다. 공개 API·설정·DB·시간 한도는 바꾸지 않습니다. 최초 새 시험은 기존 MIX_VERIFY_MAX=3을 놓쳐 3건이 틀린 기대값으로 실패했습니다. 실패 증거를 보존하고 순서 검사 시험에만 상한10을 명시해 동일 시험 바이트의 기준/후보 재실행 중입니다.

독립 작업자의 실제 MixedGenerator 합성 그래프(2노선·7정류장) 1,000쌍은 결과 1,000/1,000=100% 같았습니다. 전체 service 호출은 3,000→2,000이고 생성기 내부 호출은 남습니다. 계측 포함 메서드 중앙값0.0871→0.0841ms로 미세하며 수십 초 지연 개선으로 해석하지 않습니다. 남은 시험·판정은 후속 절에 추가합니다.


## 최종 판정과 재측정

**운영 통합 HOLD입니다. 가장 큰 관측 구간은 checking→review이지만, 그 안의 정확한 병목과 EKS 전체 속도 개선은 입증하지 못했습니다.** 작은 중복 제거는 격리 후보로 보존합니다. main/CD를 움직여 측정 잡음과 비용을 더할 만큼의 개선 근거가 없습니다. 최종 원격 main도 기준57f3d2f004d0입니다. 최초 scalar 전후의 원시 증거를 고치거나 재작성하지 않았습니다.

이전 [80초 진단](2026-10-28_eks-browser-80s-reading-latency-readonly.md)은 API BackgroundTasks 안 CPU 작업과 SSE/GET의 자원 공유를 의심했습니다. 현재 코드에서도 API 실행·메모리 진행 보관소를 확인했습니다. 이는 유력한 조사 방향이며 EKS pod CPU 제한·throttling·RDS 대기를 이번에 측정한 사실은 아닙니다. 이미 반영된 beat 분리는 현재6회 최대 간격약3초와 양립하므로 다시 구현하지 않았습니다.

시간 한도 축소·먼저 확인 화면 공개·무조건 병렬화·전역 캐시 확대는 택하지 않았습니다. autofix._fit_window가 결과 시각을 버리는 keep_times에서도 이동 검사를 하는 것은 후보의 가능한 창을 검증하기 때문입니다. 그 계산을 그냥 빼면 후보 선택 의미가 달라집니다.

### 같은 조건의 격리 시험

Python3.12.15/Windows, 기존 설치 환경의 의존성, dummy/mock 설정입니다. 새 DB·PG·도커·모델·네트워크 provider를 사용하지 않았습니다. 이동 전체 시험은 사본에 없는 공공 시각표/그래프 관련126건을 skip했고 기본 제외222건은 수집 실행 범위 밖입니다. Linux·전체 서울 그래프·EKS end-to-end를 실행하지 않았습니다.

새 회귀 최초 실행은 상한을 놓친 기대값 오류가 있었고 로그를 보존했습니다. 정정 뒤 기준 AST의 실제 _mixed_sources를 모듈에 주입해 정확한 같은 시험 바이트에서 중복 호출5실패를 확인했습니다. 제품 후보는 새 시험7개와 기존 이동 전체 시험을 통과했습니다. raw XML·warning·실패로그는 사본 밖 scratch에 그대로 있습니다. 계약·보안·DoD·전체 main CI/Docker 관문은 이번에 다시 실행하지 않았으므로 운영 병합 준비 완료라고 하지 않습니다.
