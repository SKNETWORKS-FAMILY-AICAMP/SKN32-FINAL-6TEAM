# 에이전트 간 소통을 프롬프트로 바꾸는 아이디어

`[2026-10-14 사용자 아이디어]` 미채택 · 결정 아님. 이 문서는 아이디어와 그날 확인한 사실만 남깁니다. 제품 결정은 [결정 목록](../decisions/index.md)이 정본입니다.

## 아이디어

지금은 모델에게 정해진 형식으로 데이터를 주고 정해진 형식으로 받는다(GET/POST 식 구조화 요청·응답). 그 때문에 고객 질의를 전달하고 받는 중에 새로 생긴 정보를 놓치는 일이 생긴다. 그러니 에이전트끼리는 프롬프트를 전달하고, 결과도 프롬프트로 받고, 최종 고객에게 주는 정보나 화면에 뿌리는 정보만 형식을 맞춰 작성하면 되지 않는가. 에이전트 소통에 기존 FastAPI 서버 식 주고받기를 쓸 이유가 있는가.

## 그날 확인한 사실

- 채팅 해석 단계는 이미 원문과 상태를 함께 받고, 응답 형식에 자유 글칸이 있다. 변경 범위에 시간·날짜·섞임·불분명도 있다. 일정을 바꾸는 확정은 서버가 검증한 뒤에만 한다. 아이디어의 상당 부분(원문 전달 + 확정만 구조화)은 이미 이 구조다. 근거: [decision_unit.py 응답 형식](../../final_project_cs/app/domains/travel_ops/components/conversation/decision_unit.py), [trip_messages.py 실행](../../final_project_cs/app/domains/travel_ops/components/conversation/trip_messages.py).
- 시간 변경·항목 추가·삭제는 모델이 알아듣지만 채팅 실행 기능이 없어 정해진 안내로 끝난다(x600 서버 웹 채팅 시험 2026-10-13: 시간 변경 58건 실행 0, 추가·삭제 26건 정상 0). 정보를 놓친 것이 아니라 실행 기능이 없는 것이다. 근거: 같은 파일의 `UNSUPPORTED` 주석.
- 외부 개인 AI는 MCP로 붙고, `tripilot_ask`는 자유 문장을 그대로 전한다. 쓰기 도구는 웹 API를 그대로 부르며 새 규칙을 만들지 않는다. 근거: [mcp-tools.md](../../final_project_cs/wiki/external/mcp-tools.md).
- 전부 프롬프트로 바꾸면 근거·인용 대조, 값 지어내기 금지, 변경 한 번만 반영(CAS·멱등 키) 같은 검증 자리가 사라진다. Claude와 Codex(gpt-6-sol)가 독립으로 같은 판단(전부 자연어 반대)을 했다. 단 이 합의는 사실표가 불완전했던 상태의 것이라 근거가 약하다.

## 확인 못 한 것

- "새 정보를 놓친다"가 실제로 어느 경로에서 생기는지: 채팅 해석 / 외부 개인 AI의 일정 제출 API / 감시가 새 사건을 각 팀에 넘기는 내부 구간. 세 번째는 이번에 코드를 보지 않았다.
- 자연어 전달 방식을 이 시스템에서 시험한 적이 없다(재현성·비용·지연·시험 가능성 수치 없음).
