# 여행자 속성 데이터 소스 실측

`[실측 2026-09-22]` [여행자 프로필](../product/traveler-profile.md)에서 **무엇을 물어볼지 정하기 전에** 그 값에 대응하는 데이터가 실제로 오는지 부른 기록이다. 결론(무엇을 받고 무엇을 안 받는가)은 그쪽에 있다.

## 한 줄 결론

**알러지와 할랄은 다섯 소스 어디로도 안 된다. 채식은 구글에 가능성이 있고 확인 전이다. 유모차·접근성은 필드가 비어 있다.**

## 실측 1 — 식이 제약(채식·할랄·알러지)

`[실측 2026-09-22]` 네 곳을 확인했다. 결론은 **알러지와 할랄은 못 한다, 채식만 조건부**다.

### 한국관광공사 TourAPI (KorService2) — 호출함

키는 `ACOP_TOUR_API_KEY`가 비어 있어 `ACOP_DATA_GO_KR_KEY`로 불렀다. 대조군(`searchKeyword2` 경복궁 12건)이 정상이라 키 문제는 아니다.

| 키워드 (전국) | totalCount | 내용 |
|---|---|---|
| 할랄 | **1** | 「비건·할랄뷰티페어」 — 행사(타입 15)다. 식당이 아니다 |
| 무슬림 | **0** | |
| 채식 | 6 | 서울은 「채식요리전문점 오세계향」 정도 |
| 비건 | 2 | 서울 1건(카페) |
| 사찰음식 | 2 | 발우공양 등 |
| 이슬람 | 1 | 「이태원 이슬람거리」 — 장소(타입 12) |

음식점 상세(`detailIntro2`, contentTypeId=39)가 주는 필드 **전부**다.

```
seat · kidsfacility · firstmenu · treatmenu · smoking · packing · infocenterfood
scalefood · parkingfood · opendatefood · opentimefood · restdatefood
discountinfofood · chkcreditcardfood · reservationfood · lcnsno
```

**할랄·채식·알러지 필드는 없다.** `treatmenu`(취급 메뉴)가 자연어로 오지만 「돈까스 / 육개장 / 생선까스」 수준이라 성분을 알 수 없다.

★**커버리지도 문제다.** 서울 등록이 **음식점 968건 · 관광지 382건**이다. 서울 식당 수에 비하면 TourAPI로 식당 대안을 고르는 것 자체가 무리다.

### 카카오 로컬 API — 호출함

서울시청 기준 반경 20km(최대값), 음식점 카테고리(`FD6`).

| 키워드 | total_count | 상위 결과 |
|---|---|---|
| 할랄 | 11 | 다샨 위구르 할랄 레스토랑, 할랄부산집 |
| 무슬림 | 0 | |
| 이슬람 | 0 | |
| vegan | 17 | 비건키친, 비건인사 |
| 사찰음식 | 17 | 발우공양, 산촌 본점 |
| 인도 | 12 | 구르카인도레스토랑 |
| 채식 | 405 | ★한가람 본점(한정식), 전주유할머니비빔밥집 |
| 비건 | 416 | ★위와 **동일** |
| 터키 | 248 | ★**써브웨이 시청점**이 1위 |

★★**앞의 세 줄이 이 API를 쓸 수 없다는 증거다.** 「채식」과 「비건」의 상위 결과가 같고, 「터키」에 써브웨이가 1위로 나온다. **상호가 아니라 관련도로 매기기 때문에 `total_count`는 필터로 못 쓴다.** 상호에 단어가 든 곳만 잡히는 검색(`할랄` 11건, `vegan` 17건)은 쓸 수 있지만, 그건 **가게 이름에 써 붙인 집만** 찾는 것이다.

응답 문서의 필드 전부 — 식이 속성은 없다.

```
address_name · category_group_code · category_group_name · category_name
distance · id · phone · place_name · place_url · road_address_name · x · y
```

### 구글 Places — **호출하지 못했다**

`[외부 2026-09-22]` 프로젝트에 **구글 API 키가 없다.** 릴리스 저장소의 `.env.apikeys`에 항목 자체가 없고, `.env.apikeys.example`에는 호출 한도 두 줄(`ACOP_RATE_GOOGLE_PLACES_PER_DAY` · `ACOP_RATE_GOOGLE_ROUTES_PER_DAY`)만 있다. 아래는 공식 문서만 본 값이다.

| 항목 | 값 |
|---|---|
| 필드 | `servesVegetarianFood` — 존재한다 |
| 요금제 | Place Details **Enterprise + Atmosphere** |
| 단가 | $25 / 1,000건 (0~10만 구간), 월 1,000건 무료 |
| 환산 | 건당 약 **37.5원** (환율 1,500원). 팀당 식당 후보 5곳이면 **188원** |
| 할랄 | 필드 없음 |
| 알러지 | 필드 없음 |

팀당 188원은 49,000원 상품에서 감당된다(기계 상한 10,000원). ★다만 **한국 식당에 이 값이 얼마나 채워져 있는지는 확인하지 못했다.** 키를 받아 서울 식당 30곳을 찍어 보기 전에는 「쓸 수 있다」고 적지 않는다.

**키 발급 조건** `[외부 2026-09-22]` — 카드가 등록된 Cloud Billing 계정이 **있어야** API가 켜진다. 대신 과금은 SKU별 월 무료 한도를 먼저 깎고, 신규 계정은 $300 체험 크레딧이 따로 붙는다. Place Details Enterprise + Atmosphere의 무료 한도는 **월 1,000건**이라 30곳 확인은 0원이다. 운영에서도 팀당 5곳이면 월 200팀까지 무료 한도 안이다.

★**계정 생성과 카드 등록은 AI 세션이 하지 않는다.** 사람이 발급해 `.env.apikeys`에 넣은 뒤 측정한다.

### 네이버 — **호출하지 못했다**

저장소 어디에도 네이버·NCP 키가 없다. `[외부]` 지역 검색 API 응답 필드는 `title · link · category · description · telephone · address · roadAddress · mapx · mapy`이고 **한 번에 최대 5건**이다. 식이 속성은 없다.

### 공공데이터포털 — 「할랄」로 다시 찾았다

★`[정정 2026-09-22]` 처음에 「무슬림」 한 낱말로만 찾고 **「서울을 주는 데이터가 없다」고 적었다.** 「할랄」로 다시 찾으니 **전국 무료 데이터가 나왔다.** 한 낱말로 찾고 없다고 말한 것이 잘못이었다.

| 데이터 | 제공 | 범위 | 형태 | 비용 |
|---|---|---|---|---|
| **한국문화정보원_전국 세계 음식점 데이터** | 한국문화정보원 | 전국 9,502건 | CSV·XML·JSON 내려받기 | **무료** |
| 무슬림 친화 식당 데이터 | 레드테이블(문화빅데이터플랫폼) | 전국 | CSV 61.35 KB | **유료 11,000,000원** (맛보기 5.58 KB는 0원) |
| 경기도 무슬림 친화 음식점 | 경기관광공사 | 경기도 | 파일 | 무료 |
| 할랄 메뉴 데이터 | 레드테이블 | 전국 | 연계데이터 | 확인 안 함 |
| 한국식품산업클러스터진흥원_인증 | 동 | 전국 | 오픈API | 확인 안 함 — 식품 제조 인증으로 보인다 |

레드테이블 것은 1,100만원이라 사는 것은 검토 대상이 아니다. ★`[정정 2026-09-22]` 앞서 「6,084건」이라고 적었는데 **그 숫자는 조회수로 보인다** — 상세 화면의 `2025.08.07 업데이트 6085 19`에서 뽑은 값이고, 건수는 화면에 없다. 파일이 61.35 KB이므로 **수백 건 규모로 추정**한다 `[추정]`.

### 다만 레드테이블 데이터는 라벨이 제대로다

`[실측 2026-09-22]` 상세 화면의 **미리보기**로 실제 20행을 봤다(로그인 없이 보인다). 컬럼이 이렇다.

```
RSTRNT_ID · HALAL_CRTFC_FLAG_NM(할랄인증구분명) · CRTFC_INSTT_NM(인증기관명)
RSTRNT_NM · 지번/도로명 주소 · 전화번호 · PRYRM_AT(기도실여부)
위도 · 경도 · 이미지URL · COUNTRY_NM · CTY_NM
```

미리보기 20행의 분포 — **할랄 공식 인증 1 · 무슬림 프렌들리 12 · 무슬림 자가인증 3 · 포크프리 3 · 외국인서포터즈추천 1**. 관광공사 분류제가 그대로 들어 있고, 기도실 여부는 Y 1 · N 19다. 도시는 seoul 9 · gyeongi 3 · daegu 2 등.

식당 이름도 「포렌 레스토랑(이태원)」 · 「수엠부 인도음식점」 · 「Ganga(롯데잠실)」처럼 **말이 되는 곳들이다.** 문화정보원 데이터가 맥주집을 할랄로 찍은 것과 대조된다.

★**인증기관명이 「한국관광공사」다.** 원천은 관광공사이고 레드테이블은 재판매하는 쪽이다. **관광공사에서 무료로 같은 목록을 얻는 길이 있는지는 아직 안 봤다** — 대한민국 구석구석 웹사이트의 무슬림 친화 레스토랑 목록이 후보다.

### 무료 데이터를 받아서 재 봤다 — 필드는 있고 값이 엉터리다

`[실측 2026-09-22]` 한국문화정보원 데이터를 내려받아(2.9MB, cp949) 전수 집계했다. **28개 열에 우리가 찾던 것이 다 있다** — `채식메뉴 보유여부` · `할랄음식 여부` · `글루텐프리 음식여부` · `유아의자 대여여부` · `휠체어 보유여부`.

| 항목 | 전국 Y | 비율 (Y/전체 9,502) | 서울 Y | 비율 (Y/서울 3,414) |
|---|---|---|---|---|
| 채식메뉴 | 55 | 0.6% | 33 | 1.0% |
| 할랄음식 | 22 | 0.2% | 11 | 0.3% |
| 글루텐프리 | 9 | 0.1% | 6 | 0.2% |
| 유아의자 대여 | 92 | 1.0% | 41 | 1.2% |
| 휠체어 보유 | 72 | 0.8% | 39 | 1.1% |
| **무료주차 가능** | **9,502** | **100.0%** | 3,414 | 100.0% |

★★**마지막 줄이 이 데이터를 못 쓰는 이유다.** 전국 세계음식점 9,502곳이 **한 곳도 빠짐없이 무료주차 가능**일 수는 없다. 플래그 열이 채워진 방식 자체를 믿을 수 없다는 뜻이다.

라벨을 직접 보면 더 분명하다. **서울에서 「할랄음식 Y」로 찍힌 11곳**에 이런 곳들이 있다.

> 까예데고미스(스페인) · **더 부스**(수제맥주) · 리틀하노이(베트남) · 마노디셰프(이탈리안) · **배키우동**(우동)

맥주집과 우동집이 할랄로 찍혀 있다. 「채식메뉴 Y」 서울 33곳에도 **라이너스즈바베큐**와 **나무이자카야**가 들어 있다. `카테고리2=동아시아음식`인데 `카테고리3=인도`인 행도 있다.

그리고 **데이터 기준일이 2022-10-10 · 2022-11-30**이다. 포털의 「수정일 2026-09-08」은 등록 정보가 바뀐 날이지 내용이 갱신된 날이 아니다.

→ **필드가 있다는 것과 값을 믿을 수 있다는 것은 다르다.** 이 데이터로는 식이 제약을 판정할 수 없다.

### 전국으로 넓히면 달라지나 — 아니다

`[실측 2026-09-22]` 서울 제한 때문에 표본이 작은 것인지 확인했다.

| 소스 | 전국 | 비고 |
|---|---|---|
| TourAPI 음식점 등록 | 13,435건 (서울 968) | 그중 「할랄」 검색 **0건** |
| 카카오 「할랄」 (음식점) | 49건 | 서울권 11건 |
| 카카오 「halal」 (영문) | 181건 | ★상위 결과에 그 낱말이 없다 — 관련도 잡음 |
| 카카오 「무슬림」 / 「이슬람」 | 4건 / 2건 | |
| 카카오 「vegan」 / 「사찰음식」 / 「글루텐프리」 | 39 / 62 / 34건 | 상호 매칭 |
| 문화정보원 「할랄음식 Y」 | 22건 | 라벨을 믿을 수 없음(위) |

전국으로 넓혀도 할랄 표본은 **수십 건**이고 그 라벨마저 틀려 있다. 서울이 문화정보원 데이터의 36%(3,414/9,502)를 차지하므로 **서울 제한이 표본을 깎은 주범도 아니다.**

### 그래서 식이 제약은 이렇게 다룬다

1. **자동 적용을 끈다.** 제약이 있다고 답한 여행자에게는 식당 대안을 자동 교체하지 않고 후보만 제시한다. 자동 교체는 불편이 아니라 사고가 될 수 있다
2. **카테고리 수준의 순위 강등은 한다.** 「해산물 전문」 분류는 있으므로 뒤로 민다. 단 **「여기는 안전하다」고는 말하지 않는다** — 틀리는 방향이 안전한 쪽일 때만 쓴다
3. **확인 수단을 붙인다.** 대안 카드에 업체 전화번호와 메뉴 링크를 싣고 「알러지 정보는 확인하지 못했습니다. 방문 전 업체에 확인하세요」를 붙인다

★**리뷰·메뉴 글을 LLM에게 읽혀 알러지를 판정하는 방법은 쓰지 않는다.** 틀렸을 때의 결과가 일정 불편이 아니라 응급실이다.

## 실측 2 — 유모차·무장애

`[실측 2026-09-22]` **결론: 받지 않는다. 쓸 데가 없다.**

### 무장애 전용 서비스는 못 부른다

`KorWithService2`(무장애 여행 정보)의 `areaBasedList2` · `detailWithTour2` · `areaCode2` 모두 **HTTP 403**이다. `[실측 2026-09-22]` 본문을 열어 보니 원인이 분명하다.

| 부른 것 | 결과 |
|---|---|
| `KorWithService2/*` | 403 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 「등록되지 않은 서비스키」 |
| `KorWithService1/*` | 400 `NO_OPENAPI_SERVICE_ERROR` 「해당 오픈API 서비스가 없거나 폐기됨」 |
| `KorService2/areaBasedList2` (대조군) | 200 OK |

**경로가 틀린 게 아니라 활용신청이 안 된 것이다.** 1판은 폐기됐고 2판이 살아 있다.

`[외부 2026-09-22]` 서비스 정보 — `data.go.kr` 의 **「한국관광공사_무장애 여행 정보」(`/data/15101897/openapi.do`)**.

| 항목 | 값 |
|---|---|
| 비용 | 무료, 이용허락범위 제한 없음 |
| 신청 | **개발단계 자동승인** / 운영단계 심의승인 |
| 일일 트래픽 | 개발계정 1,000건 (운영은 활용사례 제출 시 확대) |
| 규모 | 국내 관광정보 약 60,000건, 오퍼레이션 13종 |
| 형식 | JSON + XML |

→ **신청하면 개발단계는 바로 열린다.** 신청은 포털 로그인이 필요한 절차라 사람이 한다. 열린 뒤에 확인할 것은 **필드 채움률**이다 — 문화정보원 데이터처럼 열은 있는데 값이 비어 있을 수 있다.

### 일반 서비스의 관련 필드는 비어 있다

| 필드 | 표본 | 결과 |
|---|---|---|
| `chkbabycarriage` (서울 관광지) | 40건 | 빈칸 21 · 「없음」 16 · 「불가」 3 — **「있음/가능」 0건** |
| `kidsfacility` (서울 음식점) | 30건 | **30건 전부 `0`** |

값이 있는 것도 전부 부정이다. 게다가 이 필드는 이름이 **「유모차 대여」**다. 계단·엘리베이터 같은 접근성이 아니라 **대여 서비스 유무**를 재는 것이라 애초에 다른 것을 잰다.

### 지하철 승강기 데이터 — 있지만 경로 판정은 못 한다

`[외부 2026-09-22]` `data.go.kr` 에 후보가 셋 있다.

| 데이터 | 제공 | 형태 | 한계 |
|---|---|---|---|
| 서울특별시_지하철역 엘리베이터 위치정보 (`/data/15098148`) | 서울시 | 파일 CSV | 제목이 `_20220111` — **2022년 기준**. 로그인 없이 내려받지 못했다 |
| 서울시 지하철역 엘리베이터 위치정보 (`/data/15098158`) | 서울시 | 오픈API (**LINK 방식**) | 서울 열린데이터광장으로 연결된다 — **별도 키가 필요하다** |
| 역별 엘리베이터 이동경로 (`/data/15041689`) | 한국철도공사 | 오픈API | 도시·광역철도 대상. 서울 1~9호선을 다 덮는지 미확인 |

★**세 개 다 「이 역에 엘리베이터가 있다」까지다.** 우리가 알아야 하는 건 「**이 환승 경로를 계단 없이 갈 수 있나**」인데, 그걸 주는 건 셋째(이동경로)뿐이고 그것도 경로 탐색 엔진과 붙여야 뜻이 생긴다. 지금 우리 경로 조회는 ODsay 키가 비어 있고, 구글 Routes 에도 한국 대중교통의 계단 없는 경로 선택지는 없다.

→ **승강기 데이터는 지금 붙일 자리가 없다.** 넣으려면 경로 엔진부터 정해야 한다.

### 대신 경로 쪽에서 받는다

이동 제약은 **장소 속성이 아니라 경로**에서 판정할 수 있다. 도보 시간과 환승 횟수는 경로 API가 준다. 그래서 프로필에는 **「최대 연속 도보 시간(분)」 한 칸**만 둔다. 이 값은 지금 있는 데이터로 바로 탈락 조건이 된다.

## 다시 확인하는 법

키는 릴리스 저장소의 `.env.apikeys`에서 읽는다(참고 구현체에는 여행 API 키가 없다). 값은 여기 적지 않는다.

| 확인 | 요청 |
|---|---|
| TourAPI 키워드 | `GET {KorService2}/searchKeyword2` — `keyword` · `numOfRows` · `_type=json` |
| TourAPI 음식점 상세 | `GET {KorService2}/detailIntro2` — `contentId` · `contentTypeId=39` |
| TourAPI 서울 목록 | `GET {KorService2}/areaBasedList2` — `areaCode=1` · `contentTypeId` · `arrange=A` |
| 무장애 | `GET {KorWithService2}/areaBasedList2` — 지금은 403 |
| 카카오 | `GET https://dapi.kakao.com/v2/local/search/keyword.json` — `query` · `category_group_code=FD6` · `x` · `y` · `radius=20000`, 헤더 `Authorization: KakaoAK <키>` |

`{KorService2}` = `https://apis.data.go.kr/B551011/KorService2`, `{KorWithService2}` = 같은 자리의 `KorWithService2`.

TourAPI 일일 한도는 `ACOP_RATE_TOUR_API_PER_DAY=1000`이고, 이 문서를 만들 때 약 120건을 썼다.
