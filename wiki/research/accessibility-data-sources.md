# 무장애·이동 제약 데이터 소스 실측

`[실측 2026-09-22]` [여행자 프로필](../product/traveler-profile.md)에서 **무엇을 물어볼지 정하기 전에** 그 값에 대응하는 데이터가 실제로 오는지 부른 기록이다. 결론은 그쪽에 있다. 짝이 되는 문서는 [식이 제약 데이터 소스 실측](dietary-data-sources.md).

## 한 줄 결론

**무장애 API 는 활용신청 뒤 열렸고 휠체어·출입구 쪽은 쓸 만하다(서울 547곳). 유모차·수유실은 거의 비어 있다. 지하철 승강기는 붙일 자리가 없다.**

## 실측 2 — 유모차·무장애

`[실측 2026-09-22]` **결론: 받지 않는다. 쓸 데가 없다.**

### 무장애 전용 서비스는 못 부른다

`KorWithService2`(무장애 여행 정보)의 `areaBasedList2` · `detailWithTour2` · `areaCode2` 모두 **HTTP 403**이다. `[실측 2026-09-22]` 본문을 열어 보니 원인이 분명하다.

| 부른 것 | 결과 |
|---|---|
| `KorWithService2/*` | 403 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 「등록되지 않은 서비스키」 |
| `KorWithService1/*` | 400 `NO_OPENAPI_SERVICE_ERROR` 「해당 오픈API 서비스가 없거나 폐기됨」 |
| `KorService2/areaBasedList2` (대조군) | 200 OK |

**경로가 틀린 게 아니라 활용신청이 안 된 것이다.** 1판은 폐기됐고 2판이 살아 있다.

`[외부 2026-09-22]` 서비스 정보 — `data.go.kr` 의 **「한국관광공사_무장애 여행 정보」(`/data/15101897/openapi.do`)**.

| 항목 | 값 |
|---|---|
| 비용 | 무료, 이용허락범위 제한 없음 |
| 신청 | **개발단계 자동승인** / 운영단계 심의승인 |
| 일일 트래픽 | 개발계정 1,000건 (운영은 활용사례 제출 시 확대) |
| 규모 | 국내 관광정보 약 60,000건, 오퍼레이션 13종 |
| 형식 | JSON + XML |

### ★활용신청 완료 — 열렸고, 재 봤다

`[실측 2026-09-22]` 신청 뒤 같은 키로 `areaBasedList2`가 **200 / resultCode 0000**으로 돌아온다. 공통 키(`ACOP_DATA_GO_KR_KEY`)가 그대로 먹는다 — 별도 키는 발급되지 않는다.

| 범위 | 등록 수 |
|---|---|
| 전국 | 9,638 |
| 서울 | 547 |
| 서울 관광지(12) | 162 |
| 서울 음식점(39) | 105 |

서울 30건을 뽑아 `detailWithTour2`의 필드 채움률을 쟀다.

| 필드 | 채움률 | 필드 | 채움률 |
|---|---|---|---|
| `route` (내부 통로) | 83.3% | `elevator` | 33.3% |
| `exit` (출입구) | 83.3% | `braileblock` (점자블록) | 26.7% |
| `restroom` | 53.3% | `helpdog` (보조견) | 23.3% |
| `parking` | 50.0% | `wheelchair` (대여) | 10.0% |
| **`stroller` (유모차)** | **6.7%** | **`lactationroom` (수유실)** | **3.3%** |
| **`babysparechair` (유아의자)** | **0.0%** | `publictransport`·`audioguide` 등 10개 | 0.0% |

★**휠체어·출입구·계단 쪽은 쓸 만하고, 유아 쪽은 여전히 거의 없다.** 앞서 일반 서비스에서 본 것과 같은 결론이다.

★★**값이 불리언이 아니라 자연어 문장이다.**

> `exit` = "주출입구는 턱이 없어 휠체어 접근 가능함(수동문)"
> `route` = "출입구까지 턱이 없어 휠체어 접근 가능함"
> `handicapetc` = "의자식 테이블 있음_무장애 편의시설"

`usetime`·`restdate`와 같은 종류다 — **파싱해서 boolean 으로 만들지 않는다.** 원문을 그대로 싣는다.

### 커버리지가 진짜 제약이다

| 종류 | 무장애 정보 있는 곳 | 서울 전체 등록 | 비율 |
|---|---|---|---|
| 관광지(12) | 162 | 382 | **42.4%** |
| 음식점(39) | 105 | 968 | **10.8%** |

→ 탈락 조건으로 쓰면 **정보 없는 곳을 어떻게 할지**가 문제가 된다. 「정보 없음 = 탈락」이면 음식점 후보의 89%가 사라지고, 「정보 없음 = 통과」면 조건이 뜻이 없다.

**그래서 이렇게 쓴다** — 정보가 있는 곳은 **원문 문장을 그대로 보여주고 순위를 올린다.** 탈락 조건으로는 쓰지 않는다.

### 일반 서비스의 관련 필드는 비어 있다

| 필드 | 표본 | 결과 |
|---|---|---|
| `chkbabycarriage` (서울 관광지) | 40건 | 빈칸 21 · 「없음」 16 · 「불가」 3 — **「있음/가능」 0건** |
| `kidsfacility` (서울 음식점) | 30건 | **30건 전부 `0`** |

값이 있는 것도 전부 부정이다. 게다가 이 필드는 이름이 **「유모차 대여」**다. 계단·엘리베이터 같은 접근성이 아니라 **대여 서비스 유무**를 재는 것이라 애초에 다른 것을 잰다.

### 지하철 승강기 데이터 — 있지만 경로 판정은 못 한다

`[외부 2026-09-22]` `data.go.kr` 에 후보가 셋 있다.

| 데이터 | 제공 | 형태 | 한계 |
|---|---|---|---|
| 서울특별시_지하철역 엘리베이터 위치정보 (`/data/15098148`) | 서울시 | 파일 CSV | 제목이 `_20220111` — **2022년 기준**. 로그인 없이 내려받지 못했다 |
| 서울시 지하철역 엘리베이터 위치정보 (`/data/15098158`) | 서울시 | 오픈API (**LINK 방식**) | 서울 열린데이터광장으로 연결된다 — **별도 키가 필요하다** |
| 역별 엘리베이터 이동경로 (`/data/15041689`) | 한국철도공사 | 오픈API | 도시·광역철도 대상. 서울 1~9호선을 다 덮는지 미확인 |

★**세 개 다 「이 역에 엘리베이터가 있다」까지다.** 우리가 알아야 하는 건 「**이 환승 경로를 계단 없이 갈 수 있나**」인데, 그걸 주는 건 셋째(이동경로)뿐이고 그것도 경로 탐색 엔진과 붙여야 뜻이 생긴다. 지금 우리 경로 조회는 ODsay 키가 비어 있고, 구글 Routes 에도 한국 대중교통의 계단 없는 경로 선택지는 없다.

→ **승강기 데이터는 지금 붙일 자리가 없다.** 넣으려면 경로 엔진부터 정해야 한다.

### 대신 경로 쪽에서 받는다

이동 제약은 **장소 속성이 아니라 경로**에서 판정할 수 있다. 도보 시간과 환승 횟수는 경로 API가 준다. 그래서 프로필에는 **「최대 연속 도보 시간(분)」 한 칸**만 둔다. 이 값은 지금 있는 데이터로 바로 탈락 조건이 된다.

## 아직 안 해본 것

「불가」라고 적기 전에 남겨 두는 목록이다. 비어 있지 않으므로 위 결론은 **지금 가진 것 기준**이다.

| 안 해본 것 | 하면 무엇이 달라지나 |
|---|---|
| 구글 API 키 발급 → 서울 식당 30곳 `servesVegetarianFood` 채움률 | 채식을 진짜 탈락 조건으로 쓸 수 있는지 갈린다 |
| `KorWithService2` 활용신청 (`/data/15101897`, 개발단계 자동승인) | 무장애 상세가 열린다. **열린 뒤 필드 채움률을 재야** 쓸 수 있는지 안다 |
| 경로 엔진 결정(ODsay 키 또는 대안) | 정해야 승강기 데이터를 붙일 자리가 생긴다 |
| 대한민국 구석구석의 무슬림 친화 레스토랑 목록 | 레드테이블이 파는 것과 같은 원천을 무료로 얻을 수 있다 |
| 한국식품산업클러스터진흥원 인증 오픈API | 할랄 인증 업체 목록일 수 있다. 다만 식품 제조 인증으로 보인다 |
| 서울관광재단·제주관광공사 자체 공개분 | 관광공사 분류제 원본이 여기 있을 수 있다 |
| 네이버 키 발급 | 지역 검색 커버리지 비교. 단 식이 속성 필드는 없다 |

## 다시 확인하는 법

키는 릴리스 저장소의 `.env.apikeys`에서 읽는다(참고 구현체에는 여행 API 키가 없다). 값은 여기 적지 않는다.

| 확인 | 요청 |
|---|---|
| TourAPI 키워드 | `GET {KorService2}/searchKeyword2` — `keyword` · `numOfRows` · `_type=json` |
| TourAPI 음식점 상세 | `GET {KorService2}/detailIntro2` — `contentId` · `contentTypeId=39` |
| TourAPI 서울 목록 | `GET {KorService2}/areaBasedList2` — `areaCode=1` · `contentTypeId` · `arrange=A` |
| 무장애 | `GET {KorWithService2}/areaBasedList2` — 지금은 403 |
| 카카오 | `GET https://dapi.kakao.com/v2/local/search/keyword.json` — `query` · `category_group_code=FD6` · `x` · `y` · `radius=20000`, 헤더 `Authorization: KakaoAK <키>` |

`{KorService2}` = `https://apis.data.go.kr/B551011/KorService2`, `{KorWithService2}` = 같은 자리의 `KorWithService2`.

TourAPI 일일 한도는 `ACOP_RATE_TOUR_API_PER_DAY=1000`이고, 이 문서를 만들 때 약 120건을 썼다.
