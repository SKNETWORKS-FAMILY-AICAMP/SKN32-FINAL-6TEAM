# D-021 이메일 확인으로 키를 재발급한다

`[결정 2026-09-28]` 사용자 지시. 지금 상태는 매니저 세션이 코드에서 대조했다.

## 왜 필요한가

D-020 오전 정정 B 가 웹 인증을 **사용자 식별 키** 하나로 정했다. 키는 브라우저
저장소에 있고 서버는 SHA-256 만 갖는다. 그래서 **브라우저 저장소를 지우거나 다른
기기로 가면 그 사용자의 여행에 다시 들어갈 길이 없다.** 서버도 못 살린다.

D-020 은 이 구멍을 「사용자에게 한 번 보여 줘 따로 보관하게 한다」로 막기로 했는데,
**그 화면이 만들어지지 않았다**(아래 「지금 상태」). 보관할 기회조차 없는 상태다.

## 정한 것

### 1. 이메일 확인은 선택이다

안 넣으면 지금과 **완전히 같다.** 넣은 사용자만 재발급 경로가 생긴다.
`[2026-09-10]` 「여행계획서 링크는 로그인도 계정도 없다」를 깨지 않기 위해서다 —
계정을 만드는 것이 아니라 **되찾을 주소를 하나 남기는 것**이다.

### 2. 「복구」가 아니라 「재발급」이다

서버가 키 원문을 안 갖는다. 잃은 키 자체는 아무도 못 살린다.
이메일로 본인임을 확인하면 **새 키를 주고 옛 키를 전부 무효로 한다.**

사용자가 되찾는 것은 키가 아니라 **여행 접근권**이라 결과는 같다. 오히려 이쪽이
안전하다 — 유실 경로로 옛 키가 살아 있으면 그것이 또 새는 통로가 된다.

### 3. ★주소 원문을 저장하지 않는다

`customers.email_hash` 가 **최초 스키마부터 있다**(`001_schema.sql:12`). 지금은
아무 데도 안 쓴다. 이 칸에 **해시만** 넣는다.

| 때 | 하는 일 |
|---|---|
| 등록 | 사용자가 주소를 넣는다 → 그 주소로 확인 메일 → 눌러 확인되면 `email_hash` 에 해시만 저장. 원문은 안 남긴다 |
| 유실 | 사용자가 주소를 **다시 친다** → 해시해서 맞는 사용자를 찾는다 → **방금 사용자가 친 그 주소로** 새 키 링크를 보낸다 |

보관하지 않고도 성립한다. 보낼 주소는 그때 사용자가 주기 때문이다.

★**안 맞아도 화면은 똑같이 「보냈습니다」라고 한다.** 가입 여부를 알려 주지 않는다.
키 인증이 「없는 키와 거둔 키를 같게 다룬다」(`web_session.py:44`)고 하는 것과 같은
원칙이다.

### 4. 키 화면 셋은 이메일과 별개로 필요하다

D-020 이 이미 약속했고 아직 없다. 이메일을 붙이든 안 붙이든 만들어야 한다.

- 발급 직후 **키를 한 번 보여 주는 화면**(복사 단추)
- 다른 기기에서 **키를 다시 넣는 칸**
- **재발급 단추**(샜을 때 끊는 용도 — 서버 `rotate()` 는 이미 있다)

## 지금 상태 `[실측 2026-09-28]`

### 서버 — 되어 있다

`app/modules/travel_ops/web_session.py` · 저장 `web_user_keys`(마이그레이션 025).

| 하는 일 | 함수 | 상태 |
|---|---|---|
| 첫 방문에 사용자 + 키 발급 | `issue()` | 있다. 원문은 여기서만 나온다 |
| 키 → 사용자 | `resolve()` | 있다. 없는 키와 거둔 키를 같게 다룬다 |
| 새 키 + 옛 키 전부 무효 | `rotate()` | **있다.** 재발급에 그대로 쓸 수 있다 |

시험 `tests/e2e/test_web_api.py` **16건**(키·인증 11 · 문의 응답 5).
★`final_project_cs/wiki/external/rest-endpoints.md` 는 「10건」이라고 적었다 — 낡았다.
이 문서를 반영할 때 같이 고친다.

### 브라우저 — 키는 쓰고 있다

`frontend/apps/web/src/lib/live/client.ts`. `localStorage` 의
`tripilot.web.user-key.v1` 에 `acop_u_…` 하나. 요청마다 헤더 `X-User-Key` 로 보낸다.
401 이면 저장한 키를 지운다.

★**여행 데이터는 브라우저에 없다.** 서버 DB 에 있다. 브라우저에 있는 것은 키 문자열
하나뿐이라 저장 용량이 문제 되는 구조가 아니다.

`NEXT_PUBLIC_DATA_MODE` 가 `live` 일 때 이 경로가 돈다. `.env.local` 은 지금
**`live`** 다. `demo` 면 키를 안 쓰고 `sessionStorage` 의 시연 데이터로 돈다.

| 없는 것 | 확인 |

| 키를 보여 주는 화면 | `currentKey()` 가 `client.ts:46` 에 있는데 **부르는 곳이 `frontend/` 전체에 0건** |
| 키를 다시 넣는 칸 | 없다 |

## 아직 안 정한 것

- **무엇으로 보내나** — SMTP 직접 · 무료 티어 발송 서비스. 비용·한도·설정 난이도를 재고 고른다.
- **확인 링크 수명과 일회성** — resume token 이 쓰는 24시간·일회성 규칙을 따를지.
- **재발급 속도 제한** — `POST /v1/web/session` 이 주소마다 시간당 20개인 것처럼, 재발급도 막아야 한다.
- **여행 일행이 여럿일 때** — 지금 키는 사용자 하나를 가리킨다. 일행이 각자 키를 갖는지, 한 키를 나눠 쓰는지 이 문서 밖이다.
