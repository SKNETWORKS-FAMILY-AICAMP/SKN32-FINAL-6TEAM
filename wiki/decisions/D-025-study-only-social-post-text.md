# D-025 SNS 맛집 링크의 공개 게시물 글 읽기는 학업용으로만 유지한다

`[결정 2026-10-15]` 사용자 지시. 약관 확인 결과(아래 「알려진 위험」)를 보고 「학업용 한정으로 유지하고 결정 문서로 남겨 줘」.

## 무엇을 하나

| 항목 | 내용 |
|---|---|
| 기능 | SNS 맛집 링크 — 고객이 보낸 공개 게시물 링크에서 식당 이름을 찾아 일정의 식사에 넣는 변경안을 만든다 (계약: [social-dining-links](../../final_project_cs/wiki/external/social-dining-links.md)) |
| 서버가 읽는 것 | 공개 페이지 HTML 의 `<head>` 안 글만 — `og:title` · `og:description` · `twitter:*` · `description` · `<title>`. HTML 은 `</head>` 에서 읽기를 멈춘다 |
| 읽는 때 | **고객이 그 링크를 보낸 때 한 번만**. 주기 수집 · 대량 수집 · 크롤링 · 계정이나 해시태그 훑기는 하지 않는다 |
| 상한 | `config/guardrails.yaml` 의 `travel.social_dining` — 한 번에 링크 10개 · 8초 · 응답 1MB · 리디렉션 3번 · 글 6,000자 |
| 접근 방식 | 로그인 · 세션 · 쿠키를 쓰지 않는다. 접근 제한(로그인 요구 · 차단)을 우회하지 않는다 — 막히면 `inaccessible` 로 두고 고객에게 식당 이름 보완을 받는다 |
| 저장하는 것 | 출처 링크 · 확인 시각 · 모델이 뽑은 식당 이름 · 지역 · 메뉴 · **근거로 쓴 짧은 인용 구간**(본문 안에 실제로 있는 문구인지 서버가 확인한 것). 캡션 · 본문 전체는 저장하지 않는다 |
| 받지 않는 것 | **이미지 · 영상 · 자막은 서버가 받지 않는다.** 대표 이미지(`og:image`)를 받아 모델로 읽는 안은 이번에 채택하지 않았다(아래 「기각한 대안」) |
| 모델로 보내는 것 | 읽은 글과 고객 메모만 추출 모델(Ollama, 장애 때 서버 OpenAI 키)로 보낸다 |

## 알려진 위험 — 알고 정했다

2026-10-15 에 원문을 읽고 확인한 것이다. 법률 자문이 아니다.

- **Meta 자동 데이터 수집 약관**([원문](https://www.facebook.com/legal/automated_data_collection_terms)): 자동화된 도구로 Meta 제품의 데이터를 모으는 것은 **Meta 의 명시적 서면 허가가 있어야** 한다. 한 건인지 · 고객이 요청했는지를 구분하지 않는다. 허가 없이 허용된 쓰임은 검색 결과와 「사용자에게 Meta 주소의 미리보기를 보여 주는 것」뿐이다 — 글을 모델로 분석해 일정에 쓰는 것은 그 범위를 넘는다고 본다. Instagram 에 바로 적용되는지는 문서에 분명하지 않다.
- **Instagram 이용약관**: 허가 없이 자동화된 방법으로 정보를 수집하는 것을 금지한다([도움말](https://help.instagram.com/581066165581870)). 계약상 규칙이라 위반 시 접근 차단 · 계정 제한 · 민사 책임이 있을 수 있다.
- **YouTube · TikTok 약관은 이번에 원문을 확인하지 않았다** — 자동 접근을 제한하는 조항이 있는 것으로 알고 있으나 `[미확인]`.
- **저작권**: 캡션도 저작물일 수 있다. 저장은 짧은 인용 구간만 한다. 저작권법 제35조의2(일시적 복제)는 「그 이용이 저작권을 침해하는 경우」를 예외로 둬서 이것만으로 면책된다고 보지 않는다. 비영리 · 학업용 · 전문 미저장이 제35조의5(공정이용) 판단에 유리할 뿐이다.
- 사용자가 「학업용이라 유지」로 정했다 — **위반 소지가 없다는 판정이 아니다.**

## ★상업으로 넘어갈 때 — 반드시 할 것 (체크리스트)

상업 서비스 · 유료 전환 · 외부 배포를 정하는 순간 **먼저** 아래를 한다.

1. **서버의 게시물 읽기를 끈다**: `travel.social_dining.allowed_hosts` 를 비우면 모든 링크가 지원 밖(`unsupported_host`)이 된다. 고객 메모 · 「식당명 · 지역 보완」 입력으로만 식당을 받는다. (지금은 기능 스위치가 따로 없다 — 상업 전환 전에 스위치로 바꾸는 것을 권한다.)
2. **허가된 경로로 바꾸거나 다시 확인한다**: 플랫폼별 공식 API(Instagram oEmbed · YouTube Data API · TikTok 임베드)와 그 약관 · 심사를 확인한 뒤에만 다시 켠다.
3. **저장된 근거 인용을 검토한다**: `intake_dining_links.links[].restaurants[].evidence[].quote` — 상업 서비스에서 계속 보관할지 정하고, 아니면 지운다. 출처 링크 · 식당 이름 · 확인 시각은 사실 정보라 남길 수 있다.
4. **이 문서와 [계약 문서](../../final_project_cs/wiki/external/social-dining-links.md), 루트 `CLAUDE.md` · `AGENTS.md` 의 해당 행을 같이 고친다.**

## 기각한 대안

| 대안 | 기각한 까닭 |
|---|---|
| 대표 이미지(`og:image`)를 서버가 받아 이미지 모델로 읽기 | 남의 사진을 서버가 받는 일이라 같은 자동 수집 조항 · 저작권(복제) · 개인정보(얼굴, 국외 이전) 위험이 더 크다. 첫 장(릴스는 표지)만 보인다. 사진 · 영상 속 정보는 **고객이 직접 캡처를 올리는 방식**이 위험이 가장 낮다 — 별도 결정으로 검토한다 |
| 캡션도 고객이 붙여 넣게 바꾸기 | 약관 위험은 없지만 고객 손이 한 번 더 간다. 학업용 시연에서는 링크만으로 되는 쪽을 택했다 |
| 수집 대행 서비스(Apify 등) | 같은 약관 문제를 외부 업체에 맡길 뿐이고 비용 · 의존이 늘어난다(2026-10-14 검토) |
| Meta 서면 허가 · 공식 API 심사 | 발표(10-26) 전에 받을 수 없다. 상업 전환 때 체크리스트 2번으로 남긴다 |
