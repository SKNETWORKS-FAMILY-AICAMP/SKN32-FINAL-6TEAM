# D-018 외부 조회 실패는 의존 작업에서 격리하고 복구한다

## 맥락

외부 자료 한 종류의 실패가 다른 고객의 독립 기능까지 중단시키면 장애 범위가 커집니다. 상주 상담원에게 넘기는 운영 구조도 두지 않습니다.

## 결정

[사용자 확정 2026-10-11, W06 A안] 실패한 자료에 의존하는 작업만 보류하고 기존 일정·독립적으로 검증 가능한 기능을 유지합니다. 대체 자료까지 실패하면 확인 불가 상태·확인 시각·오류 코드를 남기고 고객에게 안내합니다. 근거 없는 정상 판정은 금지합니다.

## 처리와 재개

| 조건 | 행동 | 재개 조건 |
|---|---|---|
| 외부 조회의 일시 오류 | 횟수·시간 예산 안 재시도 후 대체 자료 사용 | 최신 자료 확보와 해당 일정 재검증 |
| 대체 자료까지 실패 | 의존 변경 보류, 기존 일정 유지, 고객 안내·결함 기록 | 자료 복구 후 고객 설정·최신 일정으로 재검증 |
| 독립 항목 처리 가능 | 해당 항목 처리 계속 | 합친 일정의 시간·이동 정합성 통과 |
| DB·인증·고객 격리 보장 불가 | 관련 준비 상태·쓰기 기능 실패 | 무결성과 접근 통제 복구 확인 |
| 안전 정책상 정지 | 해당 안전 정책의 정지·안내 | 일반 재시도가 아닌 안전 정책의 재개 조건 |

예: 식당 영업 상태 조회가 실패하면 그 식당의 변경만 보류합니다. 기존 일정 조회와 독립적으로 검증된 활동 변경은 계속할 수 있습니다. 활동 변경도 식당과 이동·시간이 충돌하면 적용하지 않습니다.

## 선택지와 이유

| 안 | 판단 | 이유 |
|---|---|---|
| 기능·요청 단위 격리 | 채택 | 실패에 의존하는 범위만 보류 |
| 해당 여행 변경 전체 보류 | 기본안으로 기각 | 독립적으로 검증 가능한 항목도 기다림 |
| 실패 소스 사용 작업 전체 중지 | 기본안으로 기각 | 광역 장애에서 별도 판단할 수 있으나 매 요청 기본 행동은 아님 |
| 상주 상담원 인계 | 기각 | 사용자가 정한 자동 운영 구조와 불일치 |

## 결과·구현 상태

정책과 문서 반영은 완료했습니다. [미확보] 자동 복구·회로 차단·고객 안내·결함 기록을 연결한 전체 인수 시험과 운영 반영은 아직 완료 근거가 없습니다. 기존 코드의 `escalated` 상태를 상담원이 대기한다는 뜻으로 설명하지 않습니다. 예전 초안의 “고칠 코드는 없다” 주장은 현재 완료 근거가 아닙니다.
