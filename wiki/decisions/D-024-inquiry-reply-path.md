# D-024 고객 문의·건의는 문의함 경로로 받고 운영자는 답변만 한다

`[2026-10-15 사용자 결정]` 운영자가 문의에 답변은 하되, 고객 일정은 대신 고치지 않는다.

## 무엇을 정했나

- 고객이 문제 신고·건의를 남기는 경로는 **필수**다. 서비스 개선 근거이므로, 건의를 AI가 처리하든 안 하든 일단 받아서 저장한다.
- 문의와 답변은 **이 경로 하나로만** 주고받는다: 사용자 웹의 문의 화면 → cs 프로젝트 서버 저장 → 관리자 웹앱의 문의함 → 운영자 답변 → 사용자 웹 문의 목록의 「운영팀 답변」.
- 그 밖의 화면·대화에서 「상담원에게 연결」「상담으로 넘긴다」식으로 처리하지 않는다. 일반 대화에서 해결 못 한 일은 고객에게 이유를 알리고 이 문의 경로를 안내하는 데서 끝난다.
- 운영자는 문의에 **답변과 상태·담당 기록만** 한다. 고객 일정·예약·결제는 대신 고치지 않는다.
- 답변을 나중에 에이전트가 쓰게 바꿀 수 있다. 지금은 사람 운영자가 쓰는 기능을 먼저 만든다.

## 이전 결정과의 관계

「고객 건을 사람 대기로 넘기지 않는다」(2026-09-28)와 「상주 상담원이 고객 문제를 대신 고치는 구조를 만들지 않는다」는 그대로다. 이 결정은 그 위에서 **문의 접수·답변 경로만 연다.** 2026-10-14 까지 cs 프로젝트 서버는 문의 상태 변경·답변을 막고 사용자 웹에는 빈 답변만 내려 보냈는데, 그 막음을 풀었다.

## 구현 상태 — 2026-10-15 로컬 보조 작업 사본(원격 role-manager e696274b 위)

- 사용자 웹: 문의 목록·작성·내역 화면과 「답변 완료」·「답변」 표시는 화면 팀 커밋으로 이미 원격에 있다(이 결정에서 다시 만들지 않았다).
- 서버: 답변·상태 변경 저장, 운영 기록 남김, 없는 문의는 404, 사용자 웹에는 운영자 ID 대신 답변 본문과 시각만 내려보내고 상태는 답변이 있으면 「답변 완료」.
- 관리자 웹앱: 실제 연결 모드의 문의함에서 문의 목록·상세·답변·상태·담당 변경. 결함 사후 분석은 별도 메뉴.
- 시험: 서버 단위 39/39, 관리자 앱 단위 22/22 · 시연 모드 e2e 22/22(390px 한 건은 부하로 한 번 시간 초과, 단독 재실행 통과), 사용자 웹 문의 시험 8/8. **실제 DB·x600 서버에서 문의→답변→사용자 웹 확인은 하지 않았다.**
