# 대기 업무와 새 문의 분리·초기 실패 재시도

작성: 2026-10-11 23:25 KST. Opus 5.5의 정적 지적을 실제 HTTP 시험으로 확인한 뒤 적용하는 최소 보완 계약입니다. 운영 반영 전입니다.

- 업무 ID를 명시한 답변과 같은 재개 요청 번호의 재전송은 해당 업무로 보냅니다. 업무 ID가 없는 새 메시지는 저장된 입력 스키마의 숫자·후보·확인 답변에 명확히 맞을 때만 자동 연결합니다. 새 사실 문의·새 변경 요청은 독립적으로 처리하며 이전 대기 입력을 소비하지 않습니다.
- 여러 대기 업무에 답변이 동시에 맞으면 대상을 지정하도록 409로 거절합니다. 관계없는 문의까지 막지 않습니다. 자유 답변은 업무 ID로 연결할 수 있습니다.
- 자동 연결한 답변이 만료된 경우 이전 업무에는 기존 WAIT_EXPIRED를 남기고, 그 메시지는 새 요청으로 해석합니다. 명시한 업무·토큰의 만료는 기존 오류를 유지합니다. 담당 비활성의 사전 거절은 이전 입력·토큰을 보존합니다.
- 초기 업무가 실행 전에 거절됐거나 실행 실패로 중단됐으면 같은 요청을 무조건 성공한 중복으로 표시하지 않습니다. 저장된 실행 입력으로 같은 업무를 재시도하며 모델을 다시 호출해 의도를 바꾸지 않습니다. 활성 실행·불명확한 옛 기록은 충돌로 거절하고, 완료·대기 중복은 그대로 보존합니다.

검증: 실제 Controller·등록 Team·로컬 합성 여행 DB의 HTTP로 새 문의 독립성, 비활성 담당, 만료, 여러 대기 업무, 같은 요청 복구·변경/알림 1회를 확인합니다. 모델 정확도·실제 이동 정확도·운영 반영을 이 시험으로 판정하지 않습니다.
