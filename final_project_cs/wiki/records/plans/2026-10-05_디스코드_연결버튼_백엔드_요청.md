# 「디스코드로 연결」 버튼 — 백엔드 요청 (웹 화면은 이 계약대로 이미 연결해 둠)

작성: ui 세션(웹) · 2026-10-05 · 대상: cs 백엔드 세션 · ★이 문서는 **계획서**다. 서버 코드는 고치지 않았다. 사용자가 「디스코드 알림을 진짜 디스코드랑 연동시킬 방법 없어? 지금은 웹훅이라 일반인 쓰기 어렵다」(2026-10-05)고 물었고, 비교한 뒤 「ㄱㄱ」로 이 방식(A안)을 정했다.

## 위층 — 한 번 읽고 알 수 있게

**결론.** 지금은 고객이 디스코드 설정에서 웹훅을 만들어 긴 주소를 복사해 붙여넣어야 한다(5단계). 디스코드의 공식 로그인(OAuth2)에 **`webhook.incoming`** 권한이 있다 — 고객이 버튼을 누르면 디스코드 창이 열려 「어느 서버, 어느 채널에 알림을 받을까요」를 묻고, 승인하면 **디스코드가 웹훅 주소를 우리 서버에 직접 돌려준다**(토큰 응답에 들어 있다). 고객은 3단계(버튼 → 고르고 승인 → 자동으로 돌아옴)로 끝난다.

**서버가 알림을 보내는 코드는 바뀌지 않는다.** 얻은 주소를 **지금 붙여넣은 주소와 똑같이** 저장하면 된다(`customer_profile.py` 의 검사·암호화·가림·`untested` 상태). 새로 생기는 일은 아래 엔드포인트 둘과 설정값뿐이다.

**웹(ui)이 이미 한 것**: 마이페이지 웹훅 칸에 「디스코드로 연결」 단추, 돌아온 뒤 안내문, 서버가 못 한다고 하면 단추를 숨김. 서버가 아래 계약을 내놓으면 따로 고치지 않아도 동작한다.

## 계약 (웹이 호출하는 모양 그대로)

모든 오류는 기존 `{"error": {"code", "message"}}`.

| 호출 | 인증 | 하는 일 |
|---|---|---|
| `GET /v1/web/profile` (기존) | 세션 | 응답에 **`"discord_connect": {"available": true}`** 를 더한다. 디스코드 앱이 서버에 설정돼 있을 때만 `true`. 이 칸이 없거나 `false` 면 웹은 단추를 **숨기고** 지금처럼 붙여넣기만 보인다(가짜 단추를 두지 않는다) |
| `POST /v1/web/profile/discord/connect/start` | 세션 + CSRF | 본문 없음. 서버가 `state`(무작위 · 이 사용자에 묶어 서버에 저장 · 수명 10분 · 한 번만)를 만들어 `{"authorize_url": "https://discord.com/oauth2/authorize?client_id=…&response_type=code&scope=webhook.incoming&redirect_uri=<아래 콜백>&state=…"}` 를 준다. 설정이 없으면 404 `not_found`. ★웹은 이 주소가 **`https://discord.com`(하위 도메인 포함)** 이 아니면 따라가지 않는다 |
| `GET /v1/web/profile/discord/connect/callback?code=…&state=…` | 없음(브라우저 이동 전용) | 디스코드가 고객 브라우저를 여기로 보낸다. 서버가 `state` 를 찾아 사용자를 알아내고(쿠키에 기대지 않는다 — 다른 사이트에서 오는 이동이다), `code` 를 `POST https://discord.com/api/oauth2/token`(`grant_type=authorization_code`)에 보내 토큰 응답의 **`webhook.url`** 을 얻는다. 그 주소를 `PUT /v1/web/profile` 의 `discord_webhook_url` 과 **같은 경로로** 저장한다. 끝나면 **웹으로 302**: `{WEB_ORIGIN}/mypage?discord=<결과>` |

**돌아가는 결과 낱말(웹이 읽는 것)**: `connected`(저장됨) · `cancelled`(고객이 디스코드 창에서 취소 — 콜백에 `error=access_denied`) · `expired`(`state` 가 없거나 만료·재사용) · `failed`(그 밖의 모든 실패: 토큰 교환 실패, 웹훅 없음, 주소 모양이 우리 검사에 안 맞음 등). 웹은 모르는 낱말을 `failed` 로 읽는다. `?discord=` 는 돌아오자마자 주소창에서 지운다.

## 보안 (필수)

1. **`state`** — 서버가 만들고 서버가 저장(사용자 id에 묶음). 수명 10분 · 한 번만 쓰임. 콜백은 `state` 만으로 사용자를 정한다. (공격자가 자기 `code` 를 피해자에게 보내도 **공격자 자신의 `state`** 에 묶여 있어 공격자 계정에 공격자 채널이 저장될 뿐이다.)
2. **리디렉션 주소** — `WEB_ORIGIN` 은 서버 설정이고 요청 값으로 바꿀 수 없다(열린 리디렉션 금지). 콜백 주소는 디스코드 앱 설정(Redirects)에 **같은 값을 등록**해야 한다(안 맞으면 디스코드가 거부).
3. **받은 것 중 저장하는 것은 웹훅 주소 하나뿐** — `access_token` · `refresh_token` 은 **저장하지도 로그에 남기지도 않고** 버린다(웹훅 하나만 필요하다). `webhook.url`/`webhook.token` 은 비밀이다 — 로그·오류 메시지·응답에 싣지 않는다. 저장은 기존 규칙(암호화 · 가린 모양만 응답).
4. **주소 검사** — 디스코드가 준 `webhook.url` 도 기존 `DISCORD_HOSTS` 검사를 통과해야 저장한다(통과 못 하면 `failed`).
5. **한도** — `start` 에 사용자 단위 한도(예: 분당 몇 번). 콜백에는 `state` 가 곧 한도다.
6. 이미 웹훅이 있는 사용자가 다시 연결하면 **새 것으로 바꾼다**(상태는 `untested` 로). 옛 웹훅은 디스코드 쪽 채널에 남는다 — 지우려면 `DELETE https://discord.com/api/webhooks/{id}/{token}` 을 부를 수 있다(선택, 이번 범위 아님).

## 사람이 해야 하는 설정 (서버 코드로 못 한다)

디스코드 개발자 포털에서 **앱 하나**를 만들고(무료) ① **Client ID · Client Secret** 을 서버 설정(git 밖 환경 파일)에 넣고 ② **OAuth2 → Redirects** 에 위 콜백 주소를 등록한다. 개발용(로컬)과 운영용은 리디렉션 주소를 각각 등록한다. ★이미 소셜 로그인용으로 디스코드 앱을 만든다면 **같은 앱**에 리디렉션 주소만 더해도 된다. 따라 하기 안내: [2026-10-05_디스코드_앱_만들기_안내.md](2026-10-05_디스코드_앱_만들기_안내.md). 값은 저장소·문서·커밋 메시지에 적지 않는다. 환경변수 이름은 서버 세션이 정한다.

## 완료 기준 (시험 예)

- 디스코드 mock 서버(토큰 교환 응답에 `webhook.url` 을 싣는 것)로 `start → callback` 한 바퀴: 저장됨 · 응답에는 가린 모양만 · `GET /v1/web/profile` 이 `discord_webhook.set=true`, `status="untested"`.
- 같은 `state` 두 번 → 둘째는 `?discord=expired`. 11분 뒤 → `expired`. 모르는 `state` → `expired`.
- `error=access_denied` → `?discord=cancelled`(저장 안 됨).
- 토큰 교환 실패(4xx/5xx) · 토큰 응답에 `webhook` 없음 · `webhook.url` 이 디스코드 주소가 아님 → `?discord=failed`(저장 안 됨).
- 설정(Client ID)이 없으면 `GET /v1/web/profile` 에 `available` 이 없거나 `false`, `start` 는 404.
- `access_token` · `refresh_token` · `webhook.token` 이 DB · 로그 어디에도 없다(저장 열 목록과 로그로 확인).
- 이미 있던 웹훅이 있어도 연결하면 새 것으로 바뀐다.

## 확인하지 못한 것

- 고객 쪽 조건: 디스코드가 웹훅 만들기를 허락하려면 고객이 고른 채널에서 **웹훅 관리 권한**이 있어야 하는지(디스코드 문서에서 확인하지 못했다. 보통은 그렇다고 알려져 있다). 권한이 없는 서버는 디스코드 창에서 고를 수 없거나 실패할 수 있다 → 웹은 `failed` 문구로 말한다.
- 디스코드 개발자 포털의 화면 이름(안내 문서에 적은 것)은 이 PC에서 로그인해 보지 못하고 적었다 — 달라졌으면 알려 달라.
- 서버가 없는 일반 고객: 이 방식도 **고객에게 서버(길드)가 하나 있어야** 한다. 서버를 안 만든 고객은 먼저 디스코드 앱에서 서버를 만들어야 한다(웹이 안내문으로 말한다). 서버 없이 쓰는 개인 메시지(DM) 방식은 이번 범위가 아니다.
- 공식 참고: Discord OAuth2 문서(`docs.discord.com/developers/topics/oauth2`)의 `webhook.incoming` 항목.
