# Dining 2단계 — 실행 내 결과 재사용 계획

**Goal:** 동일 판정 실행의 동일 도구·동일 인자 조회는 기존 확인 결과와 call_id를 반환한다.

**Spec:** [승인된 설계의 2번](2026-10-23_dining-agent-completeness-reuse-clarification.md). 1단계 변경을 보존하고 3단계 질문 연결은 수정하지 않는다.

**Architecture:** DiningTools의 실제 호출 기록에서 재사용 가능한 결과를 찾는다. 별도 영구 캐시·공유 상태·TTL은 추가하지 않는다. 기존 allowed·off_scope 검사 후 재사용을 확인하고 새 호출에만 max_calls를 적용한다. 재사용은 별도 횟수와 원 call_id로 기록한다.

## 판단 기록

- 확인된 결과만 재사용한다. unknown·found=false·속성 unknown·명시적 오류와 거절은 재사용하지 않는다. 자료 도구의 빈 hits·places·attributes도 재사용하지 않는다. 부정 판정(bad·closed)은 오류가 아니므로 재사용한다.
- key는 도구 이름과 키 순서만 정규화한 JSON 인자다. 식당·시간·날짜·속성 값이 달라지면 별도 조회한다. 속성 배열 순서나 생략 인자의 의미를 임의로 같다고 간주하지 않는다.
- 입력·반환 결과를 깊게 복사해 외부 수정이 원래 근거와 재사용 키를 바꾸지 못하게 한다.
- 기존 좌표 기반의 같은 가게 재검색 방지는 별도 동작이다. 다른 이름·인자를 같다고 간주하는 범위를 이번 단계에서 넓히지 않는다.
- 기존 작업 폴더와 1단계 미커밋 작업을 유지한다. 수정 전 5파일은 `_backup/2026-10-23_dining-result-reuse/`에 보존했다. 커밋·푸시·배포 없음.
