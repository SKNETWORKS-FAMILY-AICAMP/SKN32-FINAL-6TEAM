# 장소를 못 찾았을 때 — 후보 보이고 묻기 + 직접 고르기

## 한 줄 결론

장소를 못 찾은 줄은 묻기 전에 막힌 검색을 한 번 더 하고, 그래도 못 찾으면 **후보를 보이는 질문 카드**로 묻는다. 카드에는 「후보 하나 · 직접 고르기 · 장소 없이」 세 단추가 있고, 「직접 고르기」는 새 화면을 만들지 않고 **이미 있는 수정 화면(등록 전) · 수정 모드나 추가 칸(등록 뒤)**으로 넘긴다.

## 사용자 결정 (2026-10-19)

- 「후보 보이고 묻기」로 간다(세 안 중 ③). 근거 · 비교: [처리 확인 기록](../reports/2026-10-19_계획읽기_종류모름_처리확인.md) 「사용자 결정」 절.
- 「직접 고르기」는 **수정 모드로 전환해 단계를 채팅창에서 수정 화면으로 넘긴다**. **일정 추가 상황이면 추가 모드로** 넘긴다.
- 고객이 대화로 이름 · 시간 · 장소를 고르는 일은 등록 전 확인 화면에 채팅 입구가 없어 D-026 2단계(대화와 계획서를 같은 고리로)에서 연다.

## 왜 (코드에서 확인한 지금 모습 — 원격 `7c255f38`)

| 자리 | 지금 | 문제 |
|---|---|---|
| 계획 읽기 → 먼저 채우기 | 못 찾은 줄은 `check_gaps` 가 `place_not_found` 질문 「정확한 이름을 알려 주세요」 하나로 넘긴다. 질문 기록(`reading.prefill.questions`)에는 **어느 일정인지(id)가 없다** | 화면이 질문과 그 줄 · 후보를 잇지 못한다 |
| 검색이 막혀서 못 찾음 | 근거에 `blocked` 를 남기고 「막혀 있어서 못 찾은 것일 수 있어요」만 붙인다 | 고객에게 물을 일이 아닌데 묻는다 |
| 후보 | 이미 있다 — `GET …/candidates`(같은 이름 다른 지점 → 앞뒤 일정 근처 같은 종류, 최대 3) · `GET …/place-search` | 질문에서 쓰이지 않는다 |
| 채팅 「○○로 바꿔 줘 / ○○ 넣어 줘」 | 이름을 못 찾으면 「장소 이름을 조금 더 정확히 알려 주세요」 거절 문장 | 고객이 고를 길이 채팅에 없다 |

## 무엇을 바꾸나

### 1. 계획 읽기 — 먼저 채우기(`intake/prefill.py`)

1. **막힌 검색 다시 하기** — `place_not_found` 빈칸 중 그 일정의 장소 근거에 `blocked`(조회 막힘 — 한도 · 시간 초과 · 연결 실패)가 있는 것은 담당에게 보내기 전에 **한 번** 같은 말로 다시 찾는다(`pipeline.edit(via="autofix", learn_aliases=False)` — 고객이 고친 길과 같다). 찾으면 「우리가 채움 · 장소 조회가 막혀 못 찾았던 곳을 다시 찾아 채웠어요」로 기록하고 질문에서 뺀다. 또 못 찾으면 질문으로 남기고 `blocked: true` 를 붙인다.
   - 횟수 1회는 우리가 고른 값이다 — 읽기 직후 같은 분 안이라 한도 소진은 다시 해도 대개 막힌다. 시간 초과 · 일시 실패를 건지는 몫이다.
2. **질문 모양** — `place_not_found` 질문에 그 일정을 가리키는 칸과 단추를 싣는다:
   `{kind: "place_not_found", question, quote, item, source_id, index, mode: "change", actions: ["pick_candidate", "pick_myself", "no_place"], blocked}`.
   - 질문 문장: 「「{제목}」을 지도에서 찾지 못했어요 — 후보에서 고르거나 직접 골라 주세요」(막혔으면 「장소 조회가 막혀 다시 찾아봤지만 찾지 못했어요 — …」).
   - **후보는 질문에 싣지 않는다** — 화면이 이미 있는 `GET …/candidates?source_id=&index=` 로 받는다(같은 검사 · 같은 순서. 먼저 채우기에서 미리 계산하면 읽기가 길어지고 판이 바뀌면 낡는다).
3. 다른 질문(첫날 · 숙소 이름 · 범위)과 같은 목록(`prefill.questions`)에 모은다 — 한 번에 보인다.

### 2. 채팅 — 못 찾음 카드(`conversation/chat_edit.py` · `trip_desk.py` · `trip_messages.py`)

1. **막힌 검색 다시 하기** — 넣기(`add`)의 종류를 정하려고 이름을 찾을 때(`chat_edit.run`) 결과가 막힘이면 한 번 더 찾는다.
2. 그래도 `place_not_found` 로 거절되면 답에 **`pick` 카드**를 싣는다(거절 문장은 그대로):
   `pick = {mode: "change" | "add", item_id, query, prefill: {title, date, starts_at, ends_at, kind}, blocked, actions: ["pick_myself"]}`
   - `mode: "change"` — 있는 일정의 장소를 바꾸려다 못 찾음(「○○로 바꿔 줘」). `item_id` = 그 일정. 화면은 「일정 수정」과 같은 전환으로 **수정 모드를 그 일정이 골라진 채** 연다.
   - `mode: "add"` — 새 일정을 넣으려다 못 찾음(「3일차 저녁 7시에 ○○ 넣어 줘」). `item_id` 없음. 화면은 수정 모드로 넘어가며 **일정 추가 칸**을 열고 `prefill` 값을 미리 채운다.
   - `prefill` 은 **채팅 고치기가 쓰려던 값뿐**이다(날짜 · 시작 · 이름 · 종류 — 날짜를 말하지 않았으면 채팅 고치기가 고른 날). 지어내지 않는다. 끝 시각을 고객이 말하지 않아 기본 머무는 시간(60분)으로 채운 값은 `ends_at` 에 싣지 않는다.
   - 대화 기록(`GET …/chat`)에도 남겨 새로 고쳐도 카드가 보이게 한다(`reply.pick`).
3. 채팅 카드에는 후보를 아직 싣지 않는다 — 수정 모드로 넘어가면 그 일정의 후보 · 검색이 이미 있다. 채팅 안에서 후보를 고르는 일은 D-026 열린 질문과 함께 연다.
4. 「○○로 바꿔 줘」가 못 찾아 **요청한 목적지를 「위치 확인 필요」로 남기는 길**(`requested_destination.apply`)이 먼저 처리하면 그 결과를 그대로 돌려준다(이번에 바꾸지 않는다).
   - `[2026-10-19 덧붙인 사용자 결정 A — 실서버 확인 뒤]` 이 길 때문에 바꾸기에서는 「직접 고르기」가 실제로 나오지 않았다(x600 실서버, 화면 세션 확인). 그래서 **저장은 그대로 하고 같은 답에 `pick: change` 를 싣는다** — `item_id` 는 저장이 만든 **바뀐 일정**(요청한 이름이 든 새 일정), `query` 는 요청한 이름. 고객의 요청이 사라지지 않고(이름은 남는다), 고객은 카드로 수정 모드에서 그 일정의 장소를 고른다. 거절하고 원래 일정을 남기는 안(B)은 고르지 않았다. 구현: `requested_destination.apply` 가 바뀐 일정 id 를 돌려주고, `chat_edit.with_saved_pick` 이 카드를 붙인다(저장이 바꾼 것이 없으면 붙이지 않는다).

### 3. 화면 (화면 담당 세션 — 계약으로 넘긴다)

| 자리 | 할 일 |
|---|---|
| 계획 확인 화면 | `prefill.questions[]` 의 `place_not_found` 를 그 일정 줄에 카드로 붙인다. 후보는 `GET …/candidates` 1~3, 단추: 후보 → `POST …/edits` 의 `items[n].place` 에 고른 장소 그대로 · 직접 고르기 → 그 줄의 장소 바꾸기 · 검색을 연다(단계 전환 없음) · 장소 없이 → `{"none": true}` |
| 여행 화면 채팅 | 답의 `pick` 이 있으면 「직접 고르기」 단추. `change` → 「일정 수정」과 같은 전환 + 그 일정 선택, `add` → 수정 모드 + 일정 추가 칸(미리 채움) |

## 지키는 선

- 장소 이름 · 좌표는 지어내지 않는다 — 후보는 자료(우리 장소 표 · 관광공사 · 요식 원장 · 카카오)에 있는 곳만, 확정은 고객(D-025 · D-026 초안 §5).
- 고객이 적은 이름 · 고정 · 예약 일정은 바꾸지 않는다. 등록한 여행의 변경 규칙(D-020)은 그대로다 — 채팅 고치기는 고객이 시킨 변경이다.
- 새 실행기 · 새 화면 · 새 표를 만들지 않는다.

## 시험

| 시험 | 무엇을 막나 |
|---|---|
| 단위 — 질문 모양 | `place_not_found` 질문에 `item` · `source_id` · `index` · `mode` · `actions` · `blocked` 가 붙는다. 막혔으면 문장이 다르다 |
| 단위 — 다시 찾기 | 막힘 근거가 있는 빈칸만 한 번 다시 찾고, 찾으면 채움 기록 · 질문에서 빠짐, 못 찾으면 질문 + `blocked: true`. 막힘 근거가 없으면 다시 찾지 않는다 |
| 단위 — 채팅 카드 | 바꾸기 → `change` + 그 일정 id, 넣기 → `add` + 고객이 말한 값만, 기본 60분 끝은 빠짐, 다른 거절 코드에는 카드 없음 |
| 단위 — 넣기 다시 찾기 | 첫 찾기가 막힘이면 한 번 더, 막힘이 아니면 한 번만 |

## 확인 안 하는 것

- DB 가 필요한 접수 종단 시험 · 화면 시험 · 실서버(x600 · 오라클 · AWS) 확인 — 이 PC 에 로컬 개발 DB 가 없다. 배포하지 않는다.
- 못 찾은 줄이 실제로 몇 건 남는지 — 재생 시험(⑤ 계획서 칸) 몫.
