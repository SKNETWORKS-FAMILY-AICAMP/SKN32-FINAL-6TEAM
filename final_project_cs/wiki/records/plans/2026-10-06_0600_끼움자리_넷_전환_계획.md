# 2026-10-06 06:00 — 필수 부품이 팀 내부를 부르는 14곳을 끼움 자리 넷으로 바꾼다

## 1. 왜

필수 부품(감시 · 대화 · 계획 · 접수)이 요식 · 이동 · 활동 **팀 내부**를 직접 가져다 쓴다. 그러면
「팀은 꽂고 뺄 수 있다」는 말이 거짓이 된다 — 팀 하나를 빼면 부품이 import 단계에서 깨진다.

[D-CS-013](../../decisions/D-CS-013-domain-folder-layout.md) 의 칸 규칙에서 이 수를 상한 **14** 로 박아 뒀다
([칸 규칙 시험](../../../tests/architecture/test_travel_ops_cells.py)). 이번에 0 으로 내린다.

## 2. 자리 넷 (Codex 2회차 합의 — 「지금 2개로 뭉치지 말고 자리 4개」)

| 끼움 자리 | 부품이 묻는 것 | 꽂는 쪽 | 짝 |
|---|---|---|---|
| `components/mobility/legs.py` | 두 지점 사이 이동 시간 · 노선 · 사고 반영 · 도보 상한 | 이동 팀 | 7 |
| `components/dining/ledger_hook.py` | 근처 식당 들여놓기 · 시간대 영업 판정 · 이름으로 가게 찾기 | 요식 팀 | 5 |
| `components/places/similarity_hook.py` | 활동 비슷한 정도 · 선호 읽기 · 거리 우선 여부 | 활동 팀 | 2 |
| `components/watch/watch_planners.py` | 항목 종류별 감시 판정 함수 | 세 팀 | 3 |

★ 자리를 둘로 뭉치지 않는 이유 — 요식만 빼거나 이동만 바꿔 끼우는 일이 실제로 생긴다(시나리오 모드는
이미 요식 원장을 끈다). 뭉치면 하나를 끄려고 다른 하나까지 꽂아야 한다.

## 3. 미등록일 때의 답 (조용한 축소를 만들지 않는다)

| 자리 | 미등록이면 | 왜 그 값인가 |
|---|---|---|
| 이동 — `leg_planner` | `None` | 지금도 「계산기가 꺼져 있으면 어림값」 길이 코드에 있다(`planner.add_moves(engine=None)`) |
| 이동 — `disruptions_from_events` | `([], [])` | 사고 정보가 없는 것과 같다 |
| 이동 — `walk_limit_m` | `None` | 부르는 쪽이 `0.0`(늘 새 판) 으로 간다 — 지금 `GuardrailMissing` 때와 같다 |
| 요식 — `add_nearby` | 받은 목록 그대로 | 지금 `add_nearby` 실패 때와 같다 |
| 요식 — `states` / `state` / `find_by_name` | `None` | 지금 시나리오 모드(`dining_ledger=False`) 와 같다 |
| 활동 — `score` / `preference_of` / `distance_first` | `None` | 부르는 쪽이 유사도 없이 거리만 본다(`plan_activity_adjustment(similarity=None)` 이 이미 받는다) |
| 감시 — `planner(kind)` | `None` | 지금 모르는 종류일 때와 같다 (`_planner` 가 `None` 을 돌려준다) |

**없는 값을 지어내지 않는다.** 미등록은 「그 기능이 조립에 없다」는 사실이고, 부르는 쪽은 이미 그
사실을 다룰 길을 갖고 있다 — 새 기본값을 만드는 자리가 아니다.

## 4. 순서

1. 자리 넷 파일 작성 (`register` / `clear` / `is_registered` + 묻는 함수)
2. [`app/composition.py`](../../../app/composition.py) `wire_optional_features()` 에 네 등록 추가 — 조립 때 한 번
3. 부품 14 파일의 늦은 import 를 자리 호출로 바꾼다
4. 칸 규칙 시험 CEILING `14 → 0`
5. 시험 — 구조 · 계약 · 단위 · 보안 → 통합 · e2e · 시나리오 (나눠 돌린다)
6. 결정 문서 D-CS-013 에 결과 한 절, 리포트

## 5. 걸릴 수 있는 것

- `trip_watch_batch._planner` 는 **순환 import 때문에** 늦게 불러온다(주석에 적혀 있다). 자리로 바꾸면
  순환이 사라지는지 확인한다 — 사라지면 그 주석도 고친다.
- 시험이 팀 함수를 직접 monkeypatch 하는 곳이 있으면 자리 쪽으로 옮겨야 한다. `clear()` 로 되돌릴 수 있게 둔다.
- 이동 팀의 `wiring.leg_planner` 는 `disruptions=` 를 선택 인자로 받는다 — 자리의 서명이 그걸 그대로 받아야 한다.
