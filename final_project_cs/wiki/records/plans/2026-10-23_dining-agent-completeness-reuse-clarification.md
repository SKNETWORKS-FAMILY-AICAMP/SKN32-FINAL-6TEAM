# Dining 검사 완결성·결과 재사용·추가 질문 설계안

2026-10-23. 사용자 요청: 현재 에이전트 구조를 유지하고 세 항목을 보완한다.
상태: 코드 조사 및 설계 초안. 구현·검증 완료를 뜻하지 않는다.

## 현재 확인한 코드

- `instances/dining/agent.py`: 식사별 found·시각이 있는 open_at 누락을 센다. 검증 실패한 체크도 체크 이름 집합에는 들어가는 부분을 보완해야 한다.
- `instances/dining/customer_requests.py`: 모델이 읽은 조건의 인용·대상·필수 여부를 검증하고 조건별 누락을 센다. 적용 대상이 모호하면 request_scope_unclear로 남긴다.
- `instances/dining/judge.py`: 실제 접수 수명주기에서는 AgentResult.missing과 별개로 필수 검사 누락을 다시 확인한다. 누락은 기록·실패 코드에 반영하나 고객 질문으로 연결하지 않는다.
- `instances/dining/agent_tools.py`: 동일한 도구·인자 반복을 거절한다. 이때 기존 call_id와 결과를 반환하지 않으며 호출 상한 검사도 재사용보다 앞선다.
- `components/intake/dining_review.py`: 진행 중에는 등록을 기다리게 하고, 실패 자체와 unknown은 등록을 막지 않는다. 검증된 필수 bad만 등록을 막는다. 이 정책은 유지한다.

## 채택할 접근

에이전트가 도구와 다음 행동을 선택하는 구조를 유지하고, 코드가 검사 완결성과 근거 연결을 책임진다. 세 기능을 별도 서비스나 영구 캐시로 확장하지 않는다.

### 1. 필수 검사 누락

- 식사마다 found, 시각이 있으면 open_at을 대조한다. 고객 조건은 원문 목록에 기록된 active 조건의 대상 식사·속성마다 대조한다.
- 근거 검증에 실패한 체크는 검사 완료로 세지 않는다. unknown을 정직하게 반환한 검사와 아예 하지 않은 검사를 구분한다.
- 누락을 감사 기록뿐 아니라 현재 접수 결과의 미확인 안내에도 연결한다. 실제로 확인된 기존 bad는 보존한다.
- 문장 의미를 키워드 코드로 다시 분류하지 않는다. 모델이 고객 조건 자체를 원문 목록에서 빠뜨리는 문제까지 결정론적으로 완벽 검출한다고 주장하지 않는다.
- 누락·unknown만으로 새 등록 차단을 만들지 않는다.

### 2. 확인된 결과 재사용

- 같은 DiningTools 인스턴스, 즉 같은 판정 실행 안에서만 동일 도구·동일 인자의 성공 반환 결과를 재사용한다. 다른 날짜 판정·고객·revision 간에는 공유하지 않는다.
- 원래 call_id와 결과를 반환하여 기존 근거 검증을 그대로 쓴다. 호출 기록과 외부 조회를 늘리지 않는다.
- 인자의 키 순서는 무시하지만 장소·시작·종료·조회 속성 등 값이 달라지면 별도 조회한다.
- 거절·예외는 재사용하지 않는다. 호출 상한에 도달해도 기존 결과 조회는 허용하되 새 호출은 막는다.
- 반환 객체를 수정해도 보관한 근거가 바뀌지 않게 복사한다. 재사용은 호출 기록에 캐시 적중으로 구분할 수 있게 한다.
- 지속 캐시·유효기간·원장 갱신 무효화는 이번 범위가 아니다. 현재 실행 단위 경계가 수명과 격리를 정한다.

### 3. 모호한 요청의 질문·답변 연결

- request_scope_unclear를 일반 실행 실패 문구로만 숨기지 않고 원문 인용과 함께 구체적인 질문으로 보여 준다. 예: 「그 식당은 할랄이어야 해요」는 어느 날짜·어느 식사에 적용할지 묻는다.
- 후보는 현재 접수의 식사만 사용한다. 활동·이동 항목이나 다른 고객 식사를 섞지 않는다.
- 답변은 원래 조건과 고객이 정한 적용 식사를 함께 보존하고 현재 접수 판의 재검증으로 연결한다. 화면에 질문만 표시하고 답변을 버리는 구현으로 끝내지 않는다.
- 접수 판이 바뀌면 오래된 질문 응답을 그대로 적용하지 않는다. 고객 정정·조건 취소도 새 판정에 반영한다.
- 기존 로딩 중 설문(고정 문항)과 동적인 식사 조건 질문을 혼합하지 않는다. 실제 입력·화면 연결 위치는 구현 전 호출 경로를 추가 추적한다.

## 검증 계획

1. 검증 실패 체크·빈 체크·누락 속성·한 식사만 누락한 경우를 먼저 실패 시험으로 재현한다.
2. 동일 조회의 외부 호출 1회·원래 call_id 재사용·호출 상한 이후 재사용·다른 인자 재조회·실패 미재사용·반환값 변조 방지를 검증한다.
3. 모호한 조건 질문 생성→대상 식사 선택→원문과 답 저장→현재 판 재검증을 검증한다. 오래된 판·다른 항목 접근을 거절하는 시험을 포함한다.
4. 기존 요식 agent·customer_requests·judge·접수 등록 회귀 시험과 ruff F·E9를 실행한다. 화면이 바뀌면 화면 확인을 수행하고 확인하지 못한 환경은 보고한다.

## 작업·기록 경계

- 현재 작업 트리에 기존 수정·미추적 파일이 많다. 변경 전 해당 파일 사본을 별도 백업하고 이번 변경만 구분한다. 기존 작업을 되돌리지 않는다.
- 공유 응답·답변 필드가 필요하면 현재 wiki 계약을 코드보다 먼저 보완한다. 독립 검토·운영 반영으로 보고하지 않는다.
- 커밋·푸시는 이번 요청에 포함되지 않는다.
