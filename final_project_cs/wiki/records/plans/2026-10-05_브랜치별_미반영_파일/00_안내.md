# 브랜치별 미반영 파일 — 담당 세션 점검 안내 (2026-10-05)

`[2026-10-05 사용자 지시]` 아래 브랜치들의 내용 중 **더 잘 만들어진 것만** 각 담당 세션이 확인해 로컬에 반영한다. 모두 끝나면 우리 로컬이 가장 최신이다.

## 위층 — 한 번 읽고 알 수 있게

**결론.** 팀 저장소의 다른 작업자 브랜치 일곱 개 중 로컬이 한 번도 가져 본 적 없는 파일이 합쳐서 308개 있다. 영역별로 나눠 담당 세션이 하나씩 읽고 「반영 · 일부 반영 · 제외」를 적는다.

**달라지는 것.** 다른 작업자가 만든 더 나은 부분이 우리 로컬에 들어온다. 우리 설계를 다른 쪽 구현으로 바꾸지는 않는다.

**끝나는 모양.** 모든 줄에 판정이 적히고, commit 세션이 같은 비교를 다시 돌려 「남은 것 = 전부 판정이 적힌 제외 항목」임을 확인한다.

## 규칙

- **develop · 팀 저장소의 다른 브랜치는 읽기만 한다** — 푸시 · 머지 · 리베이스 · 되돌리기 없음(2026-10-05 사용자 지시).
- **기준은 우리가 이미 구현한 설계다.** 같은 일을 이미 하고 있으면 「제외」다. 더 나은 것만 우리 모양에 맞춰 옮긴다(파일째 덮어쓰지 않는다).
- **DB 마이그레이션 번호가 겹친다** — develop 의 `014` · `016` · `017` 활동 파일이 우리의 `014_itinerary` · `016_trip_request_key` · `017_supplier_tier` 와 앞 번호가 같고, `220` 은 develop 이 `dining_runtime_link`, 우리는 `dining_notice_scope` 이며 우리만 `221`~`223` 이 있다. **번호는 05 코어 담당이 한 번에 정한다 — 영역 세션은 마이그레이션 파일을 직접 옮기지 않고 05 에 알린다.**
- 반영한 변경은 평소대로 commit 세션에 경로를 직접 지정해 커밋을 요청한다(개인 저장소까지 자동 · 팀 저장소는 사용자 지시 때).
- 시험을 돌려 확인하고, 비밀(키 · IP · 웹훅)이 든 파일은 옮기지 않는다.

## 방법과 한계

- 로컬 `HEAD` · 작업 폴더의 파일 내용과 각 브랜치 머리의 파일 내용을 비교했다(이력이 서로 달라 커밋 단위 비교는 못 했다). 「본 적 없는 내용」 = 로컬 이력 · 작업 폴더 어디에도 그 내용이 없던 파일.
- 파일 내용을 하나씩 읽은 것은 아니다. 어떤 줄은 우리가 이미 같은 일을 다른 모양으로 하고 있을 것이다 — 그것이 「제외」다.
- 다른 작업자가 계속 올리므로 「최신」은 비교한 시각 기준이다. 끝난 뒤 commit 세션이 비교를 다시 돌려 본다.
