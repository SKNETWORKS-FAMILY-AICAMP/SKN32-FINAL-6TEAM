### B. 올리는 순서와 이유

1. **새 코드 → 팀 저장소.** commit 세션이 올린다(AI 세션은 저장소 푸시를 직접 하지 않는다). ★묶음에 무엇이 들어가는지 확인: 이동 세션 코드(`21163726` 이전·이후) 외에 계획 확인 화면 개편(`e64af84f`) · 디스코드 단추 웹(`2b944fc1`) · 디스코드 서버 쪽(`97bc0bef`)이 같이 가면 서버·웹이 한꺼번에 바뀐다. 서버 쪽만 먼저 올리면 서버는 반영되지만 웹 단추는 없는 상태가 된다(디스코드 앱 값이 없으면 어차피 단추가 안 보인다).
2. **서버가 5분 주기로 자동 반영.** 반영 기록: 서버의 반영 상태 파일(`deployed_sha` · `bad_sha`)과 반영 기록 파일. 새 코드는 키 이름 `seoul_metro_api_key` 를 받는 자리가 있어 키가 환경 파일에 이미 있어도 뜬다 — 단 **옛 코드가 도는 동안 컨테이너가 다시 시작되면** 키가 있을 때 뜨지 못한다(그래서 키는 반영 뒤에).
3. **반영 뒤 점검 셋**(이동 세션이 요청한 것 그대로):
   - ① **api 가 뜨는지** — 컨테이너 4개 정상 · 다시 시작 0회 · 로그 오류 0 · 설정 적재 성공(기동 로그의 이동 계산기 켜짐 줄).
   - ② **읽기 전용 스모크**(실행 중인 서버와 따로 띄운 일회용 컨테이너, DB 쓰기 없음) — 따릉이 거치 대수(서울 키로 대여소 하나 조회) · 지하철 무정차 감시 소스(`SubwayRouteEvents.affecting` 에 `2호선:이대` 같은 대상을 넣는다 — 공통 키 사용. **지금은 알림이 없어 빈 결과가 정상**이다).
   - ③ **공통 키 형태** — 환경 파일 값이 Encoding 형태(`%` 포함)인데 앱 코드의 `settings.public_data_key` 가 `unquote` 해서 쓰므로 앱 경로는 맞다. **임시 스크립트로 직접 부를 때만** 이중 인코딩이 되니 그 함수로 키를 얻어 쓴다.
   - 점검 스크립트는 **개수·이름·상태만 출력**한다(키 값·응답 본문 원문을 찍지 않는다).
4. **키 넣기(사용자).** 서버 환경 파일에 `ACOP_SEOUL_METRO_API_KEY` 를 직접 넣고 api · worker 를 다시 시작. 서울 「실시간 지하철 인증키」는 일반 키와 **별개**이고 하루 1,000건이며 제공처가 http 만 받는다(평문) — 이 키 전용으로 쓴다.
5. **키가 들어간 뒤 한 번 확인** — 실시간 도착 소스가 열차 정보를 읽는지(하루 한도 500 안에서 1~2회). 판정에 안 쓰이므로 실패해도 서비스 영향은 없다(`misses` 로만 센다).

### C. 되돌리기와 실패 모양

| 일이 틀어졌을 때 | 증상 | 대응 |
|---|---|---|
| 키가 새 코드 반영 **전에** 환경 파일에 들어갔고 컨테이너가 옛 코드로 다시 시작됨 | api 가 설정 오류(모르는 이름)로 못 뜸 | 환경 파일에서 그 줄만 주석 처리 후 재시작 — **사용자 승인 필요**(서버 설정 변경). 새 코드 반영 뒤 다시 켠다 |

| 공통 키 점검에서 401·형식 오류 | 이중 인코딩 의심 | 점검 ③ 방법으로 다시. 앱 경로 문제와 점검 스크립트 문제를 가른다 |

- **develop 푸시**: 이동 세션 · commit 세션 모두 보류. 방식(추천 ③: role-manager 에 두고 팀 합치기 때 같이)은 사용자 답이 없다.
- **이동 점검 보고서가 남긴 후속**(서버 반영과 별개): 도로 사건 2차 소스(ITS)가 **월 호출 한도 초과로 지금 못 읽는다** — 사용자가 국가교통정보센터 포털에서 한도를 늘려야 산다 · 지하철 알림의 서울 열린데이터광장 쪽 2차 소스는 **서비스 이름을 찾아야** 붙일 수 있다(로그인 후 「Open API」 탭) · GraphHopper 정리 여부(추천: 그대로 둔다) — 보고서 §5·§6.

- ★UTIC 후속(02:22, 사용자 지시로 이동 세션이 처리): 서버 `.env.apikeys` 에 `ACOP_UTIC_API_KEY_1` · `_2` 두 줄을 더했다(원래 줄이 없었다 · 백업 · 권한 유지). **실행 중인 컨테이너는 아직 안 읽는다** — 다음에 컨테이너가 새로 만들어질 때(다음 코드 반영 또는 수동 재생성) 읽힌다. 그런데 x600 에서 키별로 직접 불러 보니 **둘 다 `허용된 IP가 아닙니다`(resultCode 03)** — 키는 등록한 IP 에서만 통하고 x600 의 나가는 IP 는 등록돼 있지 않다. 그래서 키를 읽어도 UTIC 는 못 읽고, ITS 월 한도도 소진이라 **도로 사건 감시는 여전히 둘 다 못 읽는다**(지금과 같은 상태 — 퇴보 아님). 해결 길 둘: ① UTIC 에 x600 의 나가는 IP 를 등록(사용자 몫) ② 고정 IP 경유 터널 — x600 에 터널(1080 포트 수신)과 `ACOP_OUTBOUND_PROXY_URL` · `ACOP_OUTBOUND_PROXY_SOURCES` 두 줄이 필요하고(컨테이너 안 `socksio` 1.0.0 은 이미 있다) **인프라 변경이라 사용자 승인 대기**. 승인되면 환경 줄 추가 → 컨테이너 새로 만들기(`TRIPILOT_TAG` 지정) → UTIC 직접 호출 확인 순서.
