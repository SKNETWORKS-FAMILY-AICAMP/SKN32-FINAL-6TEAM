# 약관 동의 기록 · 사용 조건 · 위치 수집과 「멈춘 지점」 확인 — 백엔드 요청

작성: ui 세션(웹) · 2026-10-05 · 대상: cs 백엔드 세션 · ★이 문서는 **계획서**다. 서버 코드는 고치지 않았다. 사용자 지시(2026-10-05): ① 「약관 동의를 DB에 기록하고, 동의해야 우리 앱을 쓸 수 있게」 ② 「웹앱에서 지도가 나올 때 고객 위치를 바로 지도에 표시」 ③ 「서버에서 고객이 정확히 어느 지점에서 멈춘 건지 체크」 ④ 「지금 기능들에 필요한 동의 약관을 다 넣고 법적 효력 있게」.

## 위층 — 한 번 읽고 알 수 있게

**결론.** 서버에 세 가지가 필요하다. ① **동의 기록**: 누가 어떤 약관 버전의 어떤 항목에 언제 동의했는지(철회 포함)를 DB에 남기고, 필수 동의가 없으면 앱 호출을 막는다. ② **위치 받기**: 고객이 위치 동의를 했을 때만, 웹이 보낸 위치 점들을 받아 저장한다. ③ **멈춘 지점 찾기**: 받은 위치 점들에서 「고객이 한곳에 머문 곳」을 서버가 계산해 일정의 장소와 맞춰 본다.

**고객 입장.** 처음에 약관 화면에서 **필수 2개**(서비스 이용약관 · 개인정보 수집·이용)에 동의해야 앱을 쓴다. **선택 3개**(민감정보 · 위치 · 알림 채널)는 거부해도 앱을 쓸 수 있고, 마이페이지에서 언제든 켜고 끌 수 있다. 위치에 동의하면 지도에 내 위치가 바로 보이고, 서버는 여행 중 머문 곳을 알아 일정을 지켜본다.

**왜 선택 동의는 앱을 막지 않나(법무 확인 필요).** 개인정보 보호법은 서비스에 꼭 필요한 최소한을 넘는 정보에 동의하지 않는다는 이유로 서비스를 거부하는 것을 금한다(제16조 제3항 — 조문 번호는 법무 확인 전). 그래서 **「동의해야 앱을 쓴다」는 필수 항목에만** 건다. 위치를 필수로 하면 지도에 내 위치가 안 보이는 것이 아니라 앱 전체를 못 쓰게 되어 이 규정에 걸릴 수 있다.

**정할 것(사용자) — 아래 「정할 것」.**

## 1. 동의 기록과 사용 조건

### 항목과 버전

| 코드 | 항목 | 필수 |
|---|---|---|
| `service_terms` | 서비스 이용약관 | 필수 |
| `privacy` | 개인정보 수집·이용 | 필수 |
| `sensitive` | 민감정보(종교·식사 제한 등) 수집·이용 | 선택 |
| `location` | 개인위치정보 수집·이용(위치기반서비스 약관 포함) | 선택 |
| `alert_channel` | 알림 수신 채널 정보(디스코드 웹훅·텔레그램 대화 번호) 수집·이용 | 선택 |

약관은 **버전**을 갖는다(`TERMS_VERSION`, 예 `2026-10-05`). 서버는 지금 버전과 필수 코드 목록을 설정으로 들고 있고, 버전이 오르면 사용자는 **다시 동의**해야 한다. 웹은 약관 전문을 번들에 싣고(`src/features/consent/terms-content.ts`), 동의할 때 보여 준 한국어 전문의 `sha256` 을 함께 보낸다 — 서버는 그 값을 **증빙으로 저장**한다(정본 텍스트는 저장소의 해당 버전 파일).

### 호출

| 호출 | 인증 | 하는 일 |
|---|---|---|
| `GET /v1/web/consents` | 세션 | `{"current_version", "required": ["service_terms","privacy"], "items": [{"code","agreed","version","agreed_at"}], "ok": true\|false}` — `ok` = 필수가 모두 **지금 버전으로** 동의됨. 철회한 선택 항목은 `agreed:false` |
| `POST /v1/web/consents` | 세션 + CSRF | 본문 `{"version": "2026-10-05", "items": [{"code","agreed","text_sha256"}]}`. 보낸 항목만 바꾼다. 버전이 지금 버전이 아니면 409 `terms_version_changed`(응답에 지금 버전). 알 수 없는 코드 422. **필수 항목을 `agreed:false` 로 보내면** 기록하고 `ok:false`(앱 사용 중지). → 200 `{…GET 과 같은 모양}` |

### 기록 (DB)

- **추가만 하는 사건 표**(`consent_events`): `tenant_id · user_id · session_kind(guest/member) · code · agreed · terms_version · text_sha256 · at(서버 시각) · ip_hash · user_agent`. 지우지도 고치지도 않는다 — 철회도 새 줄이다. 동의의 증빙이기 때문이다.
- **현재 상태 표 또는 뷰**: 사용자·코드별 가장 최근 줄. `ok` 계산에 쓴다.
- `ip_hash` 는 원문 IP 가 아니라 **서버 비밀로 만든 해시**(증빙은 되고 IP 자체는 안 남긴다 — 법무 확인).
- 보관 기간: 동의 기록은 서비스 이용 종료 뒤에도 일정 기간 남기는 것이 일반적이다(분쟁 대비). **기간은 정할 것**.

### 사용 조건 (게이트)

- 필수 동의가 없으면 `/v1/web/*` 호출은 **403** `{"error": {"code": "consent_required", "message": "약관에 동의해야 쓸 수 있어요", "current_version": "…", "required": [...]}}`.
- **게이트를 면제하는 호출**: 약관·동의 호출(`/v1/web/consents`) · 세션을 만드는 호출(`/v1/web/auth/*` — 소셜 로그인 포함) · 건강 확인 · 공개 여행계획서 링크(여행별 토큰, 로그인 없음 — 고객이 아니라 링크 소유자가 읽는 것이라 다른 근거로 다룬다, 법무 확인) · 텔레그램/디스코드가 부르는 웹훅.
- 에이전트 키(`acop_a_…`)·MCP 로 오는 호출: **키를 만든 사용자의 동의 상태**를 따른다(그 사용자가 동의를 철회하면 키도 막힘).
- 게스트도 같다: 게스트 세션이 만들어진 뒤 **첫 호출로 동의를 기록**하고, 그 전에는 위 면제 호출만 된다.
- 철회 효과: `location` 철회 → 이 사용자의 **위치 점·멈춘 지점을 지체 없이 삭제** · `sensitive` 철회 → 종교·식사 관련 취향 답을 서버에서 삭제 · `alert_channel` 철회 → 디스코드 웹훅·텔레그램 연결 삭제.

## 2. 위치 받기

| 호출 | 인증 | 하는 일 |
|---|---|---|
| `POST /v1/web/trips/{trip_id}/location` | 세션 + CSRF + `location` 동의 | 본문 `{"fixes": [{"lat","lng","accuracy_m"?,"at"}]}` — 한 번에 최대 20개, `at` 은 브라우저가 위치를 잰 시각(ISO). 같은 `(trip_id, at)` 은 한 번만 저장(다시 보내도 안전). 동의가 없으면 403 `consent_required`(`code":"location"`). 한도: 사용자당 분당 6번. 점이 한국 밖이거나 정확도가 너무 나쁘면(예: 반경 500 m 초과) 저장하지 않고 `skipped` 개수만 돌려준다. → 200 `{"saved": n, "skipped": m}` |
| `DELETE /v1/web/trips/{trip_id}/location` | 세션 + CSRF | 이 여행의 위치 점과 멈춘 지점을 모두 지운다 → 200 `{"deleted": n}` |

- **저장은 최소로**: 위도·경도·정확도·시각·여행 번호·사용자 번호뿐. 기기 이름·IP 원문은 저장하지 않는다.
- **웹은 페이지가 열려 있을 때만 위치를 읽는다**(웹앱은 백그라운드 추적이 안 된다). 그래서 서버가 받는 점은 「화면을 켜 둔 동안」의 점이다 — 멈춘 지점 계산은 이 한계를 안고 한다.
- 보관 기간: 여행이 끝난 뒤 **N일**(정할 것) 또는 사용자가 지울 때. **지켜볼 필요가 끝나면(여행 종료) 파기**가 기본이다.
- 위치정보법상 **이용·제공 사실 확인자료**를 자동 기록해 일정 기간 보관해야 하는지(제16조 — 법무 확인): 필요하면 위치 점 자체가 아니라 「누가 언제 이 정보를 수집·이용했나」 기록을 따로 남긴다.

## 3. 「멈춘 지점」 확인

★**사용자 말의 해석(확인 필요)**: 「서버에서 고객이 정확히 어느 지점에서 멈춘 건지 체크」를 **「위치 점들에서 고객이 한곳에 머문 지점을 서버가 찾는 것」** 으로 읽었다. 다른 뜻이면(예: 화면에서 어느 단계에서 멈췄는지) 알려 달라.

**규칙(제안, 값은 정할 것)**
- **머문 지점(stop)** = 시간순 위치 점들이 **반경 50 m 안에 5분 이상** 머문 구간. 점이 드문 경우(웹이 꺼진 사이)는 앞뒤 점이 같은 반경 안이고 간격이 15분 이하일 때만 이어서 본다 — 점이 없는 시간을 머문 것으로 지어내지 않는다.
- 머문 지점의 값: 중심 좌표(구간 점들의 중앙값) · 시작 시각 · 끝 시각(진행 중이면 `null`) · 반경 · 점 개수 · 정확도 평균.
- **일정과 맞춰 보기**: 중심이 **일정의 장소에서 100 m 안**이면 `matched_item_id` 에 그 일정, 아니면 `null`(계획에 없는 곳에서 멈춤). 가까운 일정이 둘이면 더 가까운 쪽.
- **쓰임**: 일정 시작 시각이 지났는데 그 장소에 도착하지 않았거나(`late`), 계획에 없는 곳에서 오래 머무는 경우를 감시 루프가 알아 **Case 로 만들기만** 한다(알림 정책은 기존 규칙 — 알림은 승인 요청이 아니다).

| 호출 | 인증 | 하는 일 |
|---|---|---|
| `GET /v1/web/trips/{trip_id}/location/stops` | 세션 + `location` 동의 | `{"stops": [{"stop_id","lat","lng","started_at","ended_at","radius_m","points","matched_item_id"}], "last_fix": {"lat","lng","at","accuracy_m"}\|null, "computed_at"}` — 위치 동의가 없으면 403, 점이 없으면 `stops:[]` 와 `last_fix:null`(지어낸 값 없음). 웹이 마이페이지·여행 화면에서 「지금 어디에서 멈췄나」를 보일 때 읽는다 |

## 법무 확인이 필요한 것(서버·웹이 함께 지켜야 해서 여기에 적는다)

- **위치기반서비스사업 신고** 대상인지, 개인위치정보 수집·이용·제공에 필요한 약관·동의 형식 — 위치정보법(제9조 신고, 제15·18·19조 동의, 제16조 확인자료). 이번에 조문을 읽고 확인하지 않았다.
- **민감정보**(종교 등) 별도 동의(개인정보 보호법 제23조) · 국외 이전·위탁(지도·장소 조회·언어 모델·메신저 업체) 고지(제26조·제28조의8) · 동의 기록 보관 기간 · 만 14세 미만 가입.
- 위 모두 **변호사 검토 전**이다. 약관 초안은 웹 `terms-content.ts` 와 `wiki/records/plans/2026-10-05_약관_초안/` 에 둔다(초안 표시 `TERMS_STATUS="draft"`).

## 완료 기준 (시험 예)

- 동의 없는 세션: 일반 호출 403 `consent_required` · 면제 호출은 통과 · 필수 둘을 `POST` 한 뒤 통과.
- 버전이 오르면 `ok:false` 로 돌아가 다시 동의. 오래된 버전으로 `POST` 하면 409.
- 동의 기록은 추가만: 같은 항목을 동의→철회→동의하면 사건 3줄, 현재 상태는 마지막 줄. `text_sha256` 이 저장됨. IP 원문이 DB·로그에 없음.
- `location` 동의 없이 `POST …/location` 403 · 철회하면 점과 머문 지점이 지워짐 · 같은 `at` 두 번 → 한 번만 저장.
- 머문 지점: 합성 점 열(한곳에 6분 머문 점 → stop 1개 · 신호 대기 2분 → stop 없음 · 점이 20분 비면 이어 보지 않음) · 일정 장소 100 m 안이면 `matched_item_id`.
- 게스트·회원·에이전트 키 호출 모두 게이트가 같은 규칙으로 막고 푼다.

- 머문 지점 반경·시간의 적정값(실제 이동 자료로 재 보지 않았다 `[예상]`).
