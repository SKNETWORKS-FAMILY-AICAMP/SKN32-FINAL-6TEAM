# 디스코드 앱 만들기 — 「디스코드로 연결」 버튼을 쓰려면 한 번만 하는 설정

작성: ui 세션(웹) · 2026-10-05 · 읽는 사람: 프로젝트 담당자(디스코드 계정이 있는 사람)

## 먼저 답부터

| 궁금한 것 | 답 |
|---|---|
| 돈이 드나요? | **무료**입니다. |
| 몇 개를 만드나요? | **앱 1개**. 이미 소셜 로그인용으로 디스코드 앱을 만들었다면 그것을 그대로 씁니다. |
| 얼마나 걸리나요? | 5분 안팎. |
| 무엇을 얻나요? | **Client ID**(공개 번호)와 **Client Secret**(비밀 값) 두 개. Secret 은 채팅·문서·커밋에 적지 말고 서버의 `.env` 같은 git 밖 파일에만 넣습니다. |
| 무엇을 등록하나요? | **Redirects(돌아올 주소)** 에 서버의 콜백 주소 — 개발용 1개, 운영용 1개. |

★이 문서는 **디스코드 화면을 직접 보지 않고** 적었습니다(개발자 포털은 로그인해야 열립니다). 화면 이름이 다르면 알려 주세요, 고치겠습니다.

## 그림으로 보는 순서

```
디스코드 개발자 포털 ──▶ 앱 만들기 ──▶ OAuth2 메뉴 ──▶ ① Client ID 확인 / ② Secret 만들기 ──▶ ③ Redirects 에 주소 등록
                                                              │                                    │
                                                              ▼                                    ▼
                                                 서버 .env 에 넣기 (서버 세션)         서버의 콜백 주소와 한 글자도 다르면 안 됨
```

## 따라 하기

| 단계 | 어디서 | 무엇을 | 끝나면 보이는 것 |
|---|---|---|---|
| 1 | 브라우저에서 `discord.com/developers/applications` 열기 → 디스코드 계정으로 로그인 | 화면 오른쪽 위 **New Application** 누르기 | 이름을 묻는 창 |
| 2 | 이름 칸 | `triPilot` 처럼 고객이 알아볼 이름 입력 → 약관 체크 → **Create** | 앱 설정 화면(왼쪽에 메뉴 목록) |
| 3 | 왼쪽 메뉴 **OAuth2** | 누르기 | **Client information** 칸에 CLIENT ID 와 CLIENT SECRET |
| 4 | CLIENT ID | 오른쪽 **Copy** → 메모해 두기 | 클립보드에 숫자 복사됨 (공개해도 되는 값) |
| 5 | CLIENT SECRET | **Reset Secret** → 확인 → 나온 값을 바로 **Copy** | ★이 값은 **지금 한 번만** 보입니다. 놓치면 다시 Reset 해야 합니다 |
| 6 | 같은 화면 아래 **Redirects** | **Add Redirect** 누르고 칸에 콜백 주소 붙여넣기 (아래 표) → **Save Changes** | 목록에 주소가 한 줄 생기고 저장됨 알림 |
| 7 | 서버의 환경 파일(git 밖, `.env` 계열) | **채팅이 아니라 파일에 직접** 두 줄 넣기: `ACOP_DISCORD_CLIENT_ID=<4단계 값>` · `ACOP_DISCORD_CLIENT_SECRET=<5단계 값>` (변수 이름은 서버 세션이 정했습니다) | 서버를 다시 켜면 마이페이지에 「디스코드로 연결」 단추가 생김 |

### Redirects 에 넣을 값

| 용도 | 넣을 주소 | 비고 |
|---|---|---|
| 개발용(내 PC) | `http://127.0.0.1:8042/v1/web/profile/discord/connect/callback` | 포트는 서버를 띄우는 포트와 같게 |
| 운영용 | `https://<우리 서버 주소>/v1/web/profile/discord/connect/callback` | 배포 주소가 정해진 뒤에 추가. 이 문서에는 주소를 적지 않았습니다 |

### 건드리지 않는 것

- **Bot** 메뉴: 만들지 않습니다(이 방식은 봇이 필요 없습니다).
- **Installation / Scopes**: 따로 고를 것이 없습니다. 권한(`webhook.incoming`)은 서버가 로그인 주소에 담아 보냅니다.

## 막혔을 때

| 보이는 문구 | 원인 | 고치는 법 |
|---|---|---|
| 디스코드 창에 「Invalid OAuth2 redirect_uri」 | 서버가 보낸 콜백 주소와 Redirects 에 등록한 주소가 다름 | 6단계의 주소를 서버 설정의 콜백 주소와 **글자 하나까지** 같게(끝의 `/` 포함) |
| 디스코드 창에 서버 목록이 비어 있음 | 이 계정에 서버가 없음 | 디스코드 앱에서 **+(서버 추가) → 직접 만들기**로 내 서버를 만든 뒤 다시 |
| 목록에서 서버를 골랐는데 채널이 안 나오거나 실패 | 그 서버에서 웹훅을 만들 권한이 없음 | 내가 만든 서버를 쓰거나, 서버 관리자에게 권한 요청 |
| 마이페이지에 「디스코드로 연결」 단추가 안 보임 | 서버에 Client ID/Secret 이 아직 없음 | 7단계 확인 후 서버 재시작 |
| 연결 뒤 「디스코드 연결에 실패했어요」 | Secret 이 틀렸거나 바뀜 | 5단계로 Secret 을 다시 만들어 서버 설정을 갱신 |

## 끝난 뒤 확인

마이페이지 → **디스코드로 연결** → 디스코드 창에서 서버와 채널 고르기 → **승인** → 마이페이지로 돌아와 「디스코드 채널이 연결됐어요」 → **시험 메시지 보내기** → 고른 채널에 메시지가 오면 끝입니다.
