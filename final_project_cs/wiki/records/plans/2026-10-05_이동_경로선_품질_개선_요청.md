# 지도 경로선이 비현실적으로 보이는 문제 — 이동 세션 요청 (2026-10-05)

> 작성: cs 프로젝트 개발 세션 → 이동 세션 · 출처: 사용자가 지도 화면을 보고 「경로가 사람이 다닐 수 있는 길로 안 보인다 · 최대한 확대해도 똑같다」고 지적(2026-10-05). 상태: **요청(미착수)**

## 위층 — 한 번 읽고 알 수 있게

**결론.** 이 선은 오류로 틀리게 그린 것이 아니라 **지하철·버스 구간을 점 두세 개만 잇는 방식**이라 그렇게 보인다. 확대해도 같은 것은 선 자체가 두 점 사이 직선이기 때문이다(확대용 상세 선 옵션은 도로 그래프로 그리는 걸음·택시·자전거에만 효과가 있다).

**그런데 더 좋게 그릴 재료는 이미 있다.** 이동 계산기가 지하철 호선별 역 순서(`LineOrder.path`)와 버스 노선별 정류장 순서·좌표(정류장 4만 1천여 행)를 갖고 있는데, 경로선을 그리는 쪽이 쓰지 않는다. 쓰면 직선 한 줄이 역·정류장 하나하나를 지나는 꺾은선이 된다.

**이동 세션이 할 일.** 지하철은 탄 역과 내린 역 **사이의 모든 역**을, 버스는 탄·내린 정류장 **사이의 모든 정류장**을 잇는다. 단, 이것도 선로·차도의 실제 곡선은 아니다(곡선 자료는 없다) — 그래서 화면이 「역을 이은 선」임을 알 수 있게 응답의 표시용 칸(`source` · `grade` · `note`)은 계속 정확히 채운다.

## 현상 (사용자 말, 화면 이미지는 이 세션에 전달되지 않았다)

- 지하철 이동이 지도에 **긴 직선**으로 찍혀 사람이 다닐 길로 안 보인다. 최대한 확대해도 모양이 같다.
- 사용자 짐작: 「지하철 경로를 그대로 지도에 찍은 것 같다」 — 코드를 읽으니 **맞다**.

## 원인 (코드를 읽어 확인한 것 · 실서버 응답은 안 봤다)

[`route_shape.py`](../../../app/domains/travel_ops/instances/mobility/route_shape.py) 의 `build_shape`:

| 수단 | 지금 그리는 방식 | 줄 |
|---|---|---|
| 걸음 · 자전거 · 택시 | 도로 그래프 경로(`source=local_road_graph`). 길찾기가 꺼졌거나 못 구하면 직선(`근거없음`) | 166~171 |
| 지하철 · 지하철+버스 | **일정에 담긴 `uses` 의 역 좌표를 순서대로** 잇는다 — 탄 역 · 갈아탄 역 · 내린 역뿐이다. 양 끝 걸음만 도로 그래프. 버스 구간은 직선 | 172~187 |
| 버스 | **출발 장소 → 도착 장소 직선** (노선 번호만 있고 정류장 목록이 일정에 없다고 적혀 있다) | 190~191 |
| 그 밖 | 직선 | 192~193 |

- 파일 머리 설명(15~16행)에도 「역 사이는 실제 선로 곡선이 아니다 · 버스는 직선」이라고 적혀 있다 — 알고 한 한계다.
- `detail=true`(c02dea3a)는 `_fit` 의 점 줄이기 오차만 바꾼다(2 m → 0.5 m). 원래 점이 두 개인 선은 확대해도 두 개다.

## 재료가 이미 있다 (읽어서 확인)

- 지하철: [`engine/line_order.py`](../../../app/domains/travel_ops/instances/mobility/engine/line_order.py) 의 `LineOrder.path(line, a, b)` — 한 호선에서 a→b 사이 **역 이름 목록**. 역 좌표는 `route_shape._stations` 가 이미 쓰는 `sc.get(호선, 역명)` 으로 얻는다.
- 버스: `datasets/mobility/processed/mobility/bus_stops_v1.jsonl` — 노선별 `seq` · `lat` · `lng` · 정류장 이름 (41,820 행, 2026-09-10 판). 계산기(`engine/bus.py`)는 이미 `a_seq`~`b_seq` 로 탄 구간을 안다.

## 요청

1. **지하철**: 탄 역→내린 역(갈아타면 구간마다) 사이의 모든 역 좌표를 이어 그린다. 순환선은 `path` 가 짧은 쪽을 주므로 실제 운행 방향과 다를 수 있다 — 그 경우 `note` 에 적는다.
2. **버스**: 탄 정류장→내린 정류장 사이의 정류장 좌표를 이어 그린다. ★일정에 **탄·내린 정류장 식별자가 저장돼 있어야** 한다(지금 `uses` 는 노선 번호뿐이라고 적혀 있다) — 계획 때 계산기가 이미 아는 값을 `route_def` 에 같이 저장하는 일이 먼저다. `[미확인]` 저장 위치를 이동 세션이 가장 잘 안다.
3. 그려도 **실제 곡선이 아님**은 그대로 `note` 로 밝힌다(`source=stations` · `grade=추정`). 새 칸이 필요하면(예: 중간 역 이름 목록) 웹 표시용으로 응답에 더하고 계약(`wiki/external/rest-endpoints.md` 접수 경로선)에 적는다 — uiux 세션이 「지하철 4호선 · 역 사이는 직선」처럼 화면에 밝힐 수 있게.
4. 시험: 같은 경로를 점 두 개 방식과 중간 역 방식으로 그려 점 수·길이를 비교하고(실제 지하철 거리와 어긋나는지), 역 좌표가 빠진 역이 있어도 선이 끊기지 않는지.

## 하지 않는 것 · 확인 못 한 것

- 선로·차도의 실제 곡선 자료를 새로 구하는 일은 이 요청에 없다(곡선 자료가 있는지는 안 찾았다 — `rail_edge_track_v1` 에 선로 길이는 있으나 곡선 좌표가 있는지는 안 열어 봤다).
- 사용자 화면이 어느 수단(지하철·버스·혼합)이었는지는 이미지를 못 봐서 모른다 — 위 원인은 수단별로 적었다.
- 실서버 응답의 `source` · `note` 값은 안 봤다.
- 웹이 확대할 때 `?detail=true` 를 실제로 쓰는지는 uiux 세션 몫이다(이동 쪽 커밋 설명은 「이미 반영했다」).
