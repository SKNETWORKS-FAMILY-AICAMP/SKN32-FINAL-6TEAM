# 계획 확인 화면 — 이동수단 고르기 (화면 계획서)

작성: ui 세션(웹) · 2026-10-05 · 상태: **계획서 — 구현 전.** 코드는 한 줄도 고치지 않았다. 이동 세션이 「사용자 지시: 구현 전에 화면 기획서부터」라고 전해 와서 쓴다(전달 경로: 세션 간 메시지). 읽는 곳: 이동 세션(서버 계약 확정), 사용자(결정 확인).

## 위층 — 한 번 읽고 알 수 있게

**결론.** 확인 화면의 이동 한 칸(앞 장소 → 다음 장소)을 눌러 펼치면 맨 위에 **「이동 수단」 선택박스**가 있다. 박스를 열면 이 구간을 **지하철 · 버스 · 택시 · (있으면) 걸음 중 하나로** 가는 경우가 한 줄씩 나오고, 줄마다 걸리는 시간·요금·「여유 ○분」이 적혀 있다. **다음 일정 시작 안에 닿는 수단만 고를 수 있고**, 안 닿는 수단은 숨기지 않고 「늦어요 ○분」과 함께 회색으로 둔다. 고르면 그 구간의 시간·요금·지도 선만 바뀐다.

**고객 입장에서 달라지는 것.** 계산기가 고른 수단이 마음에 안 들어도(예: 택시는 싫다, 지하철이 갈아타기 번거롭다) 지금은 바꿀 방법이 없다. 이 기능이 있으면 **여유 시간 안에서** 고객이 직접 수단을 고르고, 왜 다른 수단은 못 고르는지 바로 볼 수 있다.

**예.** 올리브영(12:00 끝) → 광장시장(12:30 시작) 구간은 30분 안에 닿아야 한다. 지하철 16분(추천, 여유 14분) · 택시 12분(여유 18분) 은 고를 수 있고, 버스 38분은 「늦어요 8분」이라 회색이다.

**정할 것(사용자)**: 아래 「정한 것」 표의 추천을 그대로 쓸지. 특히 ② 후보를 **누를 때 한 구간씩** 부르는 것(권장)과 ④ **고정(잠금)한 일정 사이의 구간도 수단을 바꿀 수 있게** 하는 것.
**서버(이동 세션)에 필요한 것**: 구간별 수단 후보를 주는 읽기 경로와, 고른 수단을 반영하는 쓰기 경로 — 아래 「서버에 필요한 것」.

## 정한 것 (요청 ①~⑧에 대한 답)

| # | 물음 | 정한 것 | 이유 |
|---|---|---|---|
| ① | 선택박스 자리·열리는 방식 | **이동 카드 안**. 이동 줄을 눌러 펼친 칸 맨 위에 「이동 수단」 박스. 박스를 누르면 **그 자리에서 아래로 펼쳐지는 목록**(떠 있는 창·시트 아님). 접힌 줄은 지금처럼 시간·거리만 | 사용자가 이동 줄을 조용하게 만들라고 했다(2026-10-04). 떠 있는 창은 시트 안에서 잘리고 320px에서 겹친다. 안 닿는 수단의 **이유 문장**은 브라우저 기본 `select` 에 넣을 수 없다 |
| ② | 후보를 언제 부르나 | **선택박스를 여는 순간, 그 구간 하나만.** 화면이 열릴 때 전부 부르지 않는다. 한 번 받으면 그 판(revision)이 바뀔 때까지 기억(다시 열면 바로 보임). **v1 은 일반 응답**, 서버가 단계별 진행(SSE)을 내놓으면 줄이 하나씩 채워지게 이어 붙인다 | 계산이 구간마다 0.2~10초 걸린다. 전부 부르면 일정 하나에 수십 건이다 — Route Matrix 는 1,000요소 5달러(루트 `CLAUDE.md` 가격 행)이고 팀당 기계 비용 상한이 10,000원이라 쓸데없는 호출은 상한을 먹는다 |
| ③ | 기본 선택 표시 | 지금 쓰는 수단 줄에 **채움 표시(●)**, 계산기 추천 수단에 **「추천」 꼬리표**. 고객이 바꾼 뒤에도 추천 꼬리표는 남아 한 번에 돌아갈 수 있다. 바꾼 수단에는 「내가 고름」 | 되돌리기가 곧 「추천 줄 고르기」가 된다 |
| ④ | 고르면 무엇이 바뀌나 | **그 구간만**: 걸리는 시간 · 요금 · 도착 · 「여유」 문장과 간격 · 지도의 경로선. **앞뒤 일정의 시간은 안 움직인다**(닿는 수단만 고를 수 있으므로 뒤 일정의 여유가 줄지 않는다). **고정(잠금)한 일정 사이 구간도 바꿀 수 있다** — 잠금은 장소·시간을 지키는 것이지 가는 길을 지키는 게 아니고, 이 기능이 가장 필요한 때가 「고정한 두 일정 사이가 늦을 때」이기 때문 | 닿는 후보만 고르게 하는 것이 이 기능의 핵심 안전장치 |
| ⑤ | 택시 요금·근거 등급 | 택시는 **「약 9,000원~」** 로 쓰고 「추정」 꼬리표. 눌러 보는 설명: 「택시 요금은 기본요금 기준 하한값이에요. 실제는 더 나올 수 있어요.」 시간표가 아니라 거리로 어림한 구간(`basis=estimate`)에는 지금처럼 「추정」 표시 | 하한값을 정확한 값처럼 보이면 안 된다(근거 없는 문장 금지) |
| ⑥ | 후보가 없을 때 | ⓐ **하나도 안 닿음**: 줄은 모두 회색으로 두고 아래에 「여유 안에 닿는 수단이 없어요. 다음 일정 시작을 늦추면 고를 수 있어요.」 + **「시간 고치기」** 단추(다음 일정의 시간 편집기를 연다). ⓑ **서버가 후보를 못 줌**: 「이 구간의 이동 수단을 찾지 못했어요」 + 서버가 준 이유(`why_not`). ⓒ **오류**: 서버 문장 + 「다시 불러오기」. ⓓ **서버에 이 기능이 없음(404)**: 선택박스를 **아예 두지 않는다**(지금 화면 그대로) | 가짜 단추를 두지 않는 이 화면의 원칙. 안 닿는 이유를 보여 주는 것이 사용자의 요청이다 |
| ⑦ | 선택 되돌리기 | 고르면 알림줄에 「지하철로 바꿨어요 · 되돌리기」(기존 알림줄의 되돌리기 단추 방식). 박스 목록에서 「추천」 줄을 다시 고르는 것도 같은 효과 | 장소 바꾸기·시간 고치기와 같은 모양 |
| ⑧ | 시험 | 아래 「시험」. mock 서버 시험(화면 반응)과 실서버 확인(서버 응답)을 **두 줄로 나눠** 적는다 | 전역 규칙 |

**걸음**: 서버가 후보에 걸음을 주면 목록에 넣는다(맨 아래, 고정 순서). 안 주면 줄 자체가 없다. **혼합(갈아타는) 경로**는 고를 수 없다 — 계산기가 고른 `transit` 이 지금 수단이면 그 줄은 「현재」로 보이고, 단일 수단을 고르면 그것으로 바뀐다. **목록 순서는 고정**(지하철 · 버스 · 택시 · 걸음)이고, 회색 줄도 제자리에 둔다(고르는 사이 줄이 뛰지 않게).

## 화면 상태

| 상태 | 보이는 것 |
|---|---|
| 닫힘 | 지금과 같은 이동 줄(시간·거리·수단 아이콘). 펼친 칸에 「이동 수단 [현재 수단 ▾]」 |
| 여는 중 | 네 줄 자리에 「찾는 중…」 줄 네 개(줄 수가 안 바뀌게). 8초가 넘으면 「아직 찾고 있어요」 |
| 목록 | 줄마다 수단 · 시간 · 요금 · 「여유 ○분」 또는 「늦어요 ○분」 · 꼬리표(추천·추정·내가 고름) |
| 고르는 중 | 박스 잠김, 고른 줄에 돌리는 표시. 끝나면 알림줄 + 목록 닫힘 |
| 못 고름 | 회색 줄. 누르면 이유를 말한다(「버스로는 8분 늦어요 · 다음 일정이 12:30에 시작해요」) — 다른 단추들과 같은 「이유를 말하는 단추」 |
| 쓸 수 없는 때 | 확인 중·재검증 중·삭제 예정 일정 옆 구간·등록 뒤: 박스는 보이되 잠기고 이유를 말한다(기존 `frozen`/`removedWhy` 문장 재사용) |

접근성: 박스는 `aria-haspopup="listbox"` + `aria-expanded`, 목록은 `role="listbox"`, 줄은 `role="option"` + `aria-selected` · `aria-disabled`(이유는 `aria-describedby`). 화살표 위/아래로 이동, Enter 로 선택(못 고르는 줄은 이유를 말함), Esc 로 닫기. 320px 에서 줄이 두 줄로 접혀도 가로로 넘치지 않는다.

## 서버에 필요한 것 (화면이 요구하는 모양 — 경로·이름은 이동 세션이 확정)

1. **구간별 후보 읽기** — 제안 그대로 `GET /v1/web/trip-intakes/{id}/moves/{from}~{to}/options`: `{"revision", "recommended_mode", "current_mode", "options":[{"mode":"subway|bus|taxi|walk","label","minutes","km"?,"fare_krw","fare_is_floor"?,"depart","arrive","slack_min","fits","basis","grade","why_not"?}]}`. 화면이 쓰는 것: 모양이 모르는 `mode` 는 버린다 · `fits` 가 없으면 `slack_min ≥ 0` 으로 정한다 · `slack_min` 이 음수면 「늦어요 ○분」 · 택시는 `fare_is_floor` 로 「~」.
2. **고른 수단 반영** — 한 번의 호출로 `{from, to, mode}` 를 보내고 **그 구간이 다시 계산된 확인 결과(review)** 를 돌려받는다(화면이 한 번에 갱신). 기존 `POST …/edits` 에 이동 항목을 더하든 별도 경로든 상관없다. 닿지 않는 수단을 보내면 거절(422)하고 이유를 돌려준다.
3. **경로선** — 고른 뒤 `GET …/route-shapes` 를 다시 받는다(이미 있는 것).

**서버가 정해 준 것** `[2026-10-05 이동 세션 계약안]` ([서버계약안](2026-10-05_이동수단_선택_서버계약안.md), 사용자 확인 대기): ⓐ 고른 뒤 **다시 제출이 필요 없다**(서버가 다시 계산해 확인함, 응답의 `review` 전체로 화면을 갱신) ⓑ 앞뒤 일정이 바뀌면 고른 수단을 **다시 시도해 닿으면 유지, 안 닿으면 추천으로 복귀**(`mode_choice.state` = `kept`/`dropped` + 이유 — 화면은 `dropped` 에 「바뀜 · 이전 ○○」) ⓒ 전체 자동 추천도 고른 수단을 유지 ⓓ `grade` = 확정·추정·근거없음 ⓔ 걸음 `fare_krw=0`, 지하철 요금을 못 내면 `null`. 위 ⓑ 는 이 계획서가 권한 「무조건 추천으로 복귀」보다 고객의 선택을 덜 잃는 쪽으로 서버가 정했고, 화면은 그것을 따른다.

## 시험

- **단위 시험**: 후보 읽기(모르는 수단 버림 · `fits` 없을 때 · 택시 하한값 표기 · 늦어요 문장) · 고정 순서 · 판이 바뀌면 기억 버리기.
- **mock 서버 시험(화면 반응)**: 박스는 서버가 못 한다고 하면 안 나온다(404) · 박스를 열 때 **그 구간 한 건만** 부른다(다른 구간은 부르지 않음) · 목록 네 줄의 꼬리표·회색·이유 · 닿는 수단을 고르면 한 번의 쓰기 요청과 줄·지도 선·알림줄 갱신 · 되돌리기 · 다시 열면 요청 없음 · 아무것도 안 닿을 때 문구와 「시간 고치기」 단추 · 오류와 다시 불러오기 · 잠근 일정 사이 구간은 바꿀 수 있음 · 삭제 예정 일정 옆은 잠김 · 320px 가로 넘침 없음 · 키보드.
- **실서버 확인(서버 응답)**: 이동 세션이 경로를 내놓은 뒤, 사용자 허락을 받고 여행 하나를 등록해 구간 하나에서 후보를 열어 본다. mock 서버 통과를 실서버 확인처럼 쓰지 않는다.

## 확인하지 못한 것

- 서버가 후보를 줄 수 있는 수단·요금 근거(`grade` 값)와 걸림 시간. 위 모양은 이동 세션의 제안 그대로이며 서버 실물로 확인하지 않았다.
- 한 번에 얼마나 걸리는지(0.2~10초는 이동 세션이 알려 준 값 `[전달받음 — 미실측]`). 8초 안내 문구의 기준은 이 값에 맞춰 다시 정한다.
- 이 설계는 **한 구간씩 고르기**만 다룬다. 여행 전체의 이동수단 일괄 변경·교통비 합계는 이번 범위가 아니다.

| 줄 순서·못 만든 수단은 줄 없음 | 서버 순서(지하철·버스·택시·걸음) 그대로, 줄이 없는 수단은 그리지 않는다. 줄 이름은 서버 `label`(예: 「지하철 2호선」)을 쓰고 없으면 수단 이름 |
| `fits:false` + `why_not` | 회색 줄 + 서버가 완성한 이유 문장 그대로(「버스로는 8분 늦어요 …」). 줄 오른쪽 「고를 수 없어요」 |
| **`fits:null`** (계산이 오래 걸려 못 끝냄) | 「늦어요」가 아니라 **「확인 못 함」** 으로 따로 보인다 — 회색 + `why_not`(「계산이 오래 걸려 확인하지 못했어요」). 지어낸 시간·요금은 쓰지 않는다. 박스를 닫았다 다시 열면 다시 불러볼 수 있다 |
| `fare_krw: null` | 「요금 미상」 |
| `grade` | `확정` 은 꼬리표 없음, `추정`·`근거없음` 은 꼬리표(택시의 「약 ~원~」 하한값 표기는 `fare_is_floor` 로) |
| 404 `not_available` | 박스를 두지 않는다(옛 서버의 404 와 같은 처리) |
| 쓰기 409 `stale_revision` | 화면이 판을 다시 읽고 「그 사이 일정이 바뀌었어요. 다시 골라 주세요」 |
| 쓰기 422 `mode_not_fit` + `why` | 알림줄에 서버 `why` 를 그대로, 목록은 그대로 둔다 |
| 못 닿는 구간 3~11초 | 「아직 찾고 있어요」 안내를 **8초**에 띄우고, 20초가 넘으면 「오래 걸려요 — 다시 불러오기」 (값은 구현 때 실측해 다시 정한다 `[미실측]`) |
| 쓰기 200 `review` 전체 | 장소 바꾸기와 같은 길로 화면을 갈아 끼운다. 다시 제출은 켜지 않는다(ⓐ). 고른 구간은 「변경 완료」 파란 강조와 「✎」 개수에는 센다 |

## 사용자 확인 대기 (구현 시작 조건)

이 계획서와 [서버계약안](2026-10-05_이동수단_선택_서버계약안.md) **둘 다** 사용자가 확인하면 구현을 시작한다. 확인 항목: ① 후보는 박스를 여는 순간 한 구간씩(②) ② 고정한 일정 사이 구간도 변경 가능(④) ③ 앞뒤 일정이 바뀌면 닿을 때 유지·안 닿으면 추천 복귀(서버 ⓑ) ④ 고른 뒤 다시 제출 불필요(서버 ⓐ).
