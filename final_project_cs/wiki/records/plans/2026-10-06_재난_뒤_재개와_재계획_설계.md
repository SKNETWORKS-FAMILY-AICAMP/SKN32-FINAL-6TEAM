# 재난 뒤 다시 시작과 재계획 설계

`[결정 2026-10-06 사용자]` 재난이 해제돼도 사용자가 다시 시작하기 전까지 정지로 둔다(설계 `2026-10-06_재난_일정정지와_피난안내_설계.md`). 이 문서는 **다시 시작을 누른 뒤** 일정을 어떻게 이어가거나 다시 짜는지를 정한다. 근거 조사: `wiki/records/reports/2026-10-06_2330_재난_뒤_여행자_행동_조사.md`.

## 사용자가 정한 것
- 구현 순서는 ① 상황 꾸러미와 재개 때의 세 가지 선택 → ② 영향받은 항목의 대체 후보 → ③ 에이전트에게 넘기는 읽기 도구와 제약. 웹 검색 대안은 마지막.
- 방금 재난을 겪은 사용자에게는 **제안만 보여 주고 자동 적용하지 않는다**(누르면 적용, 안 누르면 그대로).
- **사용자의 선택을 기록한다**(`user_activity_events`). 「사용자가 활동한 모든 데이터는 운영을 위해 기록해야 한다」.
- 구현 후 커밋 · 푸시.

## 원칙 (조사에서)
| 근거 | 원칙 |
|---|---|
| 출발 전 사람은 취소 · 연기가 크고, 여행 중인 사람은 갈린다 | 여행 전 / 여행 중을 따로 다룬다 |
| 「피해 지역만 빼고 계속」이 사례로 많다 | 「영향받은 것만 바꾸기」를 추천, 나머지 둘도 항상 둔다 |
| 피해 없는 주변도 위축 · 여진에 마음을 바꾼다 | 범위가 불확실하면 불명으로 두고, 새 사건이면 다시 멈춘다 |
| 정보 · 위험 인식 · 동행이 결정을 가른다 | 우리가 결정하지 않고 판단을 돕는다 |
| 우리 사용자 행동 자료가 없다 | 보수적으로 시작하고 선택을 기록한다 |

## 구현 (1차)
1. **상황 꾸러미**(`components/watch/safety_recovery.py` · `GET /v1/web/trips/{id}/safety/recovery` · 다시 시작 응답의 `recovery`) — 사실(출처) · 모르는 것 · 항목별 영향 판정(확정 / 불명 / 없음) · 선택지 · 제약.
   - 영향 판정: 재난문자가 **서울 구를 지정**하면 그 구 안 = 확정, 구 밖 = 없음(공식 문자 기준), 항목의 구를 모르면 불명. **문자에 구가 없거나 지진이면 전부 불명**. 다른 도시의 같은 이름 구는 서울로 읽지 않는다.
2. **선택과 기록**(`POST …/safety/recovery`) — `keep` · `replace_affected` · `replan_all` + `lighter_day` + 숙소 · 동행 답. 기록 칸은 비식별 값만. 실패하면 `recorded: false` 와 경고(조용히 넘기지 않음).
3. **대체 후보**(`replace_affected`) — 영향 **확정** 항목마다 기존 「후보만 알아봐 줘」 길(`TripDesk.propose_alternatives`)로 **제안**한다. 후보에서 피해 구의 곳을 거르고(`keep` 함수), 구를 모르는 후보는 표시를 붙여 남긴다. 고르면 바뀌고 안 고르면 그대로.
4. **에이전트에게**(`tripilot_get_recovery_brief`, MCP 읽기) — 같은 꾸러미를 개인 AI 가 읽는다. 다시 짠 일정은 기존 `tripilot_submit_itinerary` 검증을 통과해야 등록된다. `plan_trip`(서버가 일정 짜기)에는 아직 제약을 직접 넘기지 않는다.

## 정하지 않은 값 · 한계
- 꾸러미 유효 기간 72시간, 영향 판정 규칙, 질문 두 개는 **우리가 고른 값**이다(측정하지 않았다).
- **밀도를 낮추는 것은 기본이 아니다** — 낮추는 근거 연구가 없다(밀도 값 0.40 만 연구에서 직접 관찰, 0.55 · 0.70 · 0.80 은 운영점 — D-019). 「오늘은 가볍게」는 사용자가 고르는 선택이고 기록 · 제약 전달만 한다.
- 지진은 범위를 단정하지 않는다 — 항목이 전부 불명이라 `replace_affected` 가 제안을 만들 곳이 없다(채팅으로 바꾸고 싶은 곳을 말하게 안내).
- 재난별 거름 규칙(홍수면 저지대 · 야외 등)은 **아직 없다**. 근거 없이 넣지 않는다.
- 우리는 일정(시간표)만 조정한다. 날짜 연기 · 취소 · 업체 예약은 범위 밖이라 `scope_note` 로 안내한다.
- 실서버(x600 서버의 cs 프로젝트 서버) 확인은 아직 안 했다. 시험은 로컬 개발 DB 기준이다.

## 남은 일
- 웹 화면(화면 담당): 다시 시작 직후 꾸러미 표시와 세 선택지 · `lighter_day` 체크 · 질문 두 개.
- `plan_trip` 에 제약(`avoid_districts` · `lighter_day`) 직접 전달.
- 웹 검색 대안(비용 · 출처 확인 방식을 정한 뒤).
- **사용자 결정 대기: 여행 · 계정을 지운 뒤 채팅 · 활동 기록을 비식별로 남길지.** 지금은 여행을 지우면 같이 지운다(개인정보 기본값). 「우리 데이터로 삼는다」와 부딪히므로, 남긴다면 약관 동의와 비식별 처리를 먼저 정해야 한다.
