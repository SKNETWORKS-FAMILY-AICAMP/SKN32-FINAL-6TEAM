# Dining 필수 검사 누락 보완 실행 계획

**Goal:** 사용자가 승인한 세 보완 중 1번만 구현한다. 검사 실패를 완료로 세지 않고, 누락을 현재 접수 화면에 미확인으로 표시한다.

**Architecture:** 모델이 검사·도구를 선택하는 구조는 유지한다. 에이전트의 완료 집계와 접수 합치기에서 누락을 확인하며, 별도 unknown 안내 행을 사용해 기존 검증 결과와 분리한다.

**Spec:** [승인된 설계의 1번](2026-10-23_dining-agent-completeness-reuse-clarification.md)

**Tech Stack:** Python·pytest, TypeScript·Vitest.

## 판단 기록

- 사용자: 「1번부터 차근차근 진행」. 결과 재사용·모호한 요청의 질문 연결은 이번 단계에 포함하지 않는다.
- 현재 role-dining의 작업 트리와 미커밋 구현을 기준으로 보완한다. 새 worktree는 미커밋 접수 수명주기를 복사하지 않으므로 현재 폴더를 유지하고 `_backup/2026-10-23_dining-required-checks/`에 수정 전 사본을 둔다.
- 실패·unknown 자체로 등록을 차단하지 않는 기존 정책 유지. 별도 `dining_check` unknown 행으로 고객 안내를 제공하며 기존 bad·ok 행을 덮지 않는다.
- 원문에서 모델이 아예 누락한 의미까지 코드가 검출한다고 주장하지 않는다. 모델이 제출한 조건 목록·실제 검사·근거 검증 결과를 대조한다.

## 실행

- [x] 검증 실패한 found/open_at, 정직한 unknown, 식사별·조건별 누락에 대한 실패 시험 작성·재현.
- [x] 에이전트 완료 집계 수정, 접수 누락 안내 연결, 현재 판·등록 경계 회귀 시험.
- [x] `dining_check` 응답 계약·웹 표시 타입과 라벨 연결 및 시험.
- [x] 관련 Python·웹 시험, ruff F·E9, 변경 검토와 한계·인계 기록.

결과: [1단계 보고서](../reports/2026-10-23_dining-required-checks.md). 기존 실패 2건과 기존 웹 타입 오류 15건은 분리 확인했으며 전체 검사 통과를 뜻하지 않는다.

## 검증 범위

실제 DB·유료 모델 호출을 요구하지 않는 단위·접수 저장 경계 시험을 먼저 실행한다. 실행하지 못한 실서버·화면 검증은 별도로 남긴다. 커밋·푸시·배포는 하지 않는다.
