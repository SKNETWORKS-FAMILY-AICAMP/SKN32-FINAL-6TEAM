# 숙소 카드 · 「○○에서 출발」 띠 — 화면 확인과 다듬기 (UI/UX 인계)

**한 줄 요약**: 숙소 카드와 「○○에서 출발」 띠는 **코드도 자동 시험도 이미 있다.** 빠진 것은 **사람이 화면을 눈으로 보고 다듬는 일**이다. 아래 3가지를 해 주면 된다.

- 무료 / 유료: **무료** — 이 PC 의 mock 서버(시험용 대역)와 브라우저만 쓴다. 외부 유료 API 를 부르지 않는다.
- 만들 것: 캡처 4장(일정 화면 하루 1장) · 계획 확인 화면 시험 1개 · 확인 결과 보고 1개.
- 걸리는 시간: 1~2번 합쳐 반나절 정도 `[추정 — 잰 값 아님]`. 3번은 서버 쪽 고침을 기다려야 한다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 1. 일정 화면(등록 뒤) 캡처해서 눈으로 확인 · 다듬기 | 해 주실 것 | 0/1 = 0% |
| 2. 계획 확인 화면(등록 전) mock 서버 장면 · 시험 추가 | 해 주실 것 | 0/1 = 0% |
| 3. x600 서버(실제 운영 환경)에서 확인 | 막힘 — 서버 결함(아래 「3.」) 고친 뒤 | 0/1 = 0% |
| (참고) 화면 코드 구현 | 끝 | 2/2 화면 = 100% |
| (참고) 일정 화면 자동 시험(mock 서버) | 끝 | 38/38 = 100% (10-13, 숙소 장면 + 여행 화면) |

---

## 0. 무엇을 그리는 화면인가

**숙소는 일정에서 「한 항목」이다** — 체크인 날 시작해서 체크아웃 날 끝난다(10-13 사용자 결정, 「숙소 B안」). 서버에는 숙소 항목이 하나만 있고, **둘째 날부터의 띠와 체크아웃 줄은 화면이 그 한 항목을 보고 그려 내는 표시**다(서버에 따로 저장된 줄이 아니다).

예: 롯데호텔 서울에 10/1 15:00 체크인, 10/4 11:00 체크아웃(3박). 날마다 이렇게 보여야 한다.

```
 1일차 10/1                         2일차 10/2
 ┌───────────────────────────┐      ┌───────────────────────────┐
 │ 10:00  경복궁               │      │ 🛏 롯데호텔 서울에서 출발  2박째 │ ← 띠(점선 초록 테두리, 맨 위)
 │ 12:30  토속촌 삼계탕        │      │ 09:35  호텔 → 남산서울타워  │ ← 아침 이동(서버가 만든 이동)
 │        (이동)               │      │ 10:00  남산서울타워         │
 │ 15:00  🛏 롯데호텔 서울 체크인│      └───────────────────────────┘
 │ ~10/4 11:00  [3박 · 10/1~10/4]│ ← 숙소 카드(침대 아이콘 · 박 수 알약)
 │        (이동)               │      3일차 10/3 (다른 일정 없음)
 │ 18:00  명동교자             │      ┌───────────────────────────┐
 └───────────────────────────┘      │ 🛏 롯데호텔 서울에서 출발  3박째 │ ← 일정이 없어도 띠는 나온다
                                    └───────────────────────────┘
 4일차 10/4
 ┌───────────────────────────┐
 │ 🛏 롯데호텔 서울에서 출발  마지막 날 │
 │ 09:10  호텔 → 광장시장       │
 │ 09:30  광장시장             │
 │ 11:00  🛏 롯데호텔 서울 체크아웃 │ ← 체크아웃 줄 「퇴실 마감」 — 시각 순서 자리에 끼운다
 │ 13:00  창덕궁               │
 └───────────────────────────┘
```

띠나 체크아웃 줄을 누르면 그 숙소 항목(체크인 카드)을 보여 준다 — 숙소는 하나이기 때문이다.

## 1. 일정 화면(등록 뒤) — 캡처해서 눈으로 확인 · 다듬기

자동 시험은 「글자가 있다 · 순서가 맞다」만 본다. **색 · 간격 · 잘림 · 테마 · 좁은 폭에서의 모양은 아무도 보지 않았다.** 이걸 봐 달라는 것이다.

### 1-1. 캡처 뽑기

시험에 캡처 스위치가 이미 들어 있다 — 환경변수 `STAY_SHOTS_DIR` 에 폴더를 주면 날마다 한 장씩(430×932, 휴대폰 크기) 저장한다.

Git Bash:

```bash
cd final_project_cs/frontend/apps/web
mkdir -p ../../../../scratch/stay-shots
PLAYWRIGHT_CHANNEL=chrome STAY_SHOTS_DIR=../../../../scratch/stay-shots npm run test:live -- tests/live/stay-b-20261013.spec.ts
```

PowerShell:

```powershell
cd final_project_cs/frontend/apps/web
$env:PLAYWRIGHT_CHANNEL = "chrome"; $env:STAY_SHOTS_DIR = "$PWD/../../../../scratch/stay-shots"
npm run test:live -- tests/live/stay-b-20261013.spec.ts
```

**끝나면 보이는 것**: 시험 1개 통과(`1 passed`), `scratch/stay-shots/` 에 `stay-2026-10-01.png` ~ `stay-2026-10-04.png` 4장.

- `npm run test:live` 는 mock 서버(`tests/live/stub-server.mjs`)를 띄우고 웹을 빌드해서 돈다. 실제 서버(cs 프로젝트 서버)에는 접속하지 않는다.
- 이 시험이 쓰는 mock 서버 장면은 `tripItems: "stay"` 다 — [stub-server.mjs 의 `stayItems()`](../../../frontend/apps/web/tests/live/stub-server.mjs)(4일 여행, 위 그림과 같은 일정).
- 직접 띄워 놓고 손으로 눌러 보고 싶으면 같은 장면을 mock 서버에 걸고 `/trips/<시험 여행 id>` 를 열면 된다(시험 [stay-b-20261013.spec.ts](../../../frontend/apps/web/tests/live/stay-b-20261013.spec.ts) 의 `beforeEach` 와 `start()` 가 그 순서다).

### 1-3. 다듬어도 되는 것 · 건드리지 말 것

- **다듬어도 되는 것**: 색 · 테두리 · 간격 · 아이콘 크기 · 글자 크기 · 말줄임 · 체크아웃 줄을 일반 카드보다 얇게 할지 같은 **모양**. 지금 모양은 디자이너 검토 없이 팀장이 기존 색 토큰으로 맞춘 첫 판이다.
- **건드리지 말 것**: 숙소가 「한 항목」이라는 점(띠 · 체크아웃 줄을 서버에 따로 저장하거나 서버에 보내지 않는다), 서버가 주는 값(`kind: "lodging"`, 시작 = 체크인, 끝 `ends_at` = 체크아웃 날 시각), 아침 이동은 서버가 만든 것만 그린다는 점(화면이 이동을 지어내지 않는다).
- 모양을 바꾸면 위 시험의 글자 확인(「3박 · 10/1~10/4」 · 「2박째」 · 「마지막 날」 · 버튼 이름 「… 에서 출발 — 숙소 보기」)이 깨질 수 있다. 문구를 바꿀 때는 시험도 같이 고친다.

## 2. 계획 확인 화면(등록 전) — mock 서버 장면 · 시험 추가

계획 확인 화면(일정을 등록하기 전에 검토하는 화면)에도 같은 띠와 아침 이동이 들어가 있다(10-13 `0185e24c`). 그런데 **이 화면에는 숙소가 든 mock 서버 장면이 없어서 브라우저 시험이 하나도 없다** — 단위 시험(순서 계산) 3개뿐이다.

| 할 일 | 어디 | 끝나면 |
|---|---|---|
| 접수 확인 응답에 숙소 항목을 싣는 장면 추가 | [stub-server.mjs](../../../frontend/apps/web/tests/live/stub-server.mjs) — 계획 확인 장면(`review: "on"` 쪽)에 숙소 행 하나(`kind: "lodging"`, `end_date`, 체크인 15:00 · 체크아웃 11:00)와 `from_stay: true` 아침 이동 | 계획 확인 화면에 숙소 카드 제목 「… 체크인」 · 알약 「n박 · 날짜」, 묵는 날 맨 위 띠가 보인다 |
| 시험 추가 | `tests/live/` 에 새 spec(일정 화면 시험 [stay-b-20261013.spec.ts](../../../frontend/apps/web/tests/live/stay-b-20261013.spec.ts) 를 본떠서) | 1번과 같은 점검을 계획 확인 화면에서 자동으로 본다. 캡처 스위치도 같은 방식으로 |

- 서버가 계획 확인 화면에 주는 모양은 계약 문서 `final_project_cs/wiki/external/rest-endpoints/web-intakes.md` 와 서버 시험 `tests/unit/travel/test_intake_stay_morning.py` 를 본다(숙소 행의 `end_date`, 아침 이동의 `from_stay`).
- 화면 코드: `features/plan-check/plan-rows.tsx`(카드 제목 · 알약 · 띠) · `features/plan-check/plan-check.module.css` 의 `.stayBand`.
- 계획 확인 화면의 띠는 지금 **누를 수 없다**(일정 화면 띠는 누르면 숙소로 간다). 같게 맞출지는 보고 판단해 주세요 — 추천: 맞춘다(같은 모양이 다르게 동작하면 헷갈린다).

## 3. x600 서버에서 확인 — 지금은 막혀 있다

**지금 x600 서버의 웹에서는 숙소가 든 여행을 만들 수 없다.** 일정 등록 때 「○○호텔 체크인」 줄이 장소로 풀리지 않는다(서버 결함 LB-01, [숙박 · 예약 동작 점검](2026-10-15_0100_숙박예약_동작점검_결과와_인계.md)). 화면 문제가 아니라 서버 문제라 UI/UX 쪽에서 고칠 일은 아니다. 10-15 기준 원격 role-manager 에 고친 커밋은 아직 없다(커밋 메시지에서 「LB-01」 검색, 0건).

서버가 고쳐지면 이 순서로 확인한다:

1. x600 서버의 웹 「일정 등록」 화면 → 「테스트 계획」 선택상자에서 `test16`(숙소가 있는 서울 2일) 고르기 → 입력칸에 계획 원문이 채워진다.
2. 「계획 확인하기」 → 호텔 줄의 장소가 풀렸는지, 계획 확인 화면에 숙소 카드 · 띠가 보이는지(2번 점검).
3. 등록 → 일정 화면에서 1-2 점검표를 실제 데이터로 한 번 더.
