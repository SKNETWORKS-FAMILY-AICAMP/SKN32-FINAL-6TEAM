# 이동 모듈 — 외부 API 를 쓰는 지점 · 오픈소스로 바꿀 수 있나 · 멈추면 어떻게 하나 (2026-10-05 점검)

> 요청(사용자): 「이동 모듈에서 api 부분 지금 쓰이고 있는 부분이 정확히 어느 지점들이고, 오픈소스 프로젝트들로 대체할 수는 없는지, 해당 api 가 멈출 때 대응은 지금 어떻게 하기로 잡혀 있는지」.
> 방법: 코드에서 네트워크 호출(`urllib` · `httpx` · 소스 어댑터)과 실패 처리를 직접 읽었다. 확인하지 못한 것은 `[미확인]` 으로 적었다.

## 결론 (먼저)

1. **이동 계산기 본체가 런타임에 부르는 외부 API 는 둘뿐이다** — 따릉이 실시간 거치 대수(`bike.py`), 그리고 **선택 사항**인 GraphHopper 서버(`car.py` · 기본은 꺼짐). 시간표 · 요금 · 환승 · 길찾기는 **저장소 안 자료와 우리 파이썬 코드**로 돈다.
2. 이동 **둘레**(감시 · 출발 알림)에서 부르는 외부 소스는 셋이다 — 도로 돌발(UTIC), 지하철 무정차(서울교통공사 지하철알림정보), 그리고 판정에 안 넣는 실시간 도착정보.
3. **오픈소스로 바꿀 수 있는 것은 이미 바꿨다**(길찾기 = OSM + 우리 A\*). 남은 외부 API 는 전부 **알고리즘이 아니라 「지금의 사실」 자체**(열차가 지금 서는가 · 자전거가 몇 대 있는가 · 도로가 지금 막혔는가)라 오픈소스 코드로는 대체할 수 없다. 공휴일만 오픈소스 보조(검증용)가 가능하다.
4. 멈췄을 때: **모르는 값을 지어내지 않는다.** 따릉이는 「근거없음」으로 후보를 유지하고, 사건 소스(UTIC · 지하철알림)는 **못 읽으면 치명**(결정 15)으로 그 이동의 감시·알림을 보내지 않고 사람에게 넘긴다. 단 **사건 소스에는 대체 소스가 없다** — 결정 15 의 「1차 실패 시 대체」가 이 자리에는 아직 구현돼 있지 않다.

## 1. 정확히 어느 지점인가

### 1-1. 이동 계산기 본체 (런타임)

| 무엇 | 어디서 | 호출 형태 | 켜짐 조건 |
|---|---|---|---|
| **따릉이 실시간 거치 대수** | [bike.py:62](../../../app/modules/travel_ops/mobility/engine/bike.py#L62) `URL` · [bike.py:97](../../../app/modules/travel_ops/mobility/engine/bike.py#L97) `urlopen` | 서울 열린데이터광장 `bikeList`(http) · 대여소 하나당 1회 · 키 `ACOP_SEOUL_OPENAPI_KEY` | 키가 있을 때(없으면 꺼짐) |
| **GraphHopper 서버**(자전거·걸음·택시 길찾기) | [car.py:208](../../../app/modules/travel_ops/mobility/engine/car.py#L208) `GraphHopperClient` | 자체 서버 주소(`mobility_gh_url`) | **기본 꺼짐**(주소 `""`). 켜면 시작 때 `info()` 로 닿는지 보고 고른다([runtime.py:191-204](../../../app/modules/travel_ops/mobility/engine/runtime.py#L191)) |

그 밖의 이동 코드(`plan.py` · `verify_time.py` · `options.py` · `graph_router.py` · `route_shape.py` · `wiring.py`)에는 **네트워크 호출이 없다**(`urllib` · `httpx` · `requests` 검색 결과 위 두 곳뿐).

| 무엇 | 어디서 | 하는 일 | 키 |

### 1-3. 이동 입력을 만드는 곳 (모듈 밖이지만 걸려 있다)

장소 좌표·이름을 정하는 **관광공사 TourAPI · 카카오 로컬**(`intake/places.py` 쪽)이 이동 계산기의 입력(좌표)을 만든다. 이동 계산기는 좌표만 받으므로 이 둘이 멈추면 **이동 계산 이전에 장소가 안 정해진다**(「모름」으로 남는다). 이번 점검 범위 밖이라 세부는 보지 않았다.

### 1-3b. 화면의 지도 타일 — 이동 모듈은 아니지만 **외부 서비스에 걸려 있다** (처음 점검에서 빠뜨렸다)

웹 화면의 기본 지도는 **Leaflet + OpenStreetMap 공개 타일 서버**(`tile.openstreetmap.org` · [config.ts](../../../frontend/apps/web/src/features/map/config.ts) · [osm.ts](../../../frontend/apps/web/src/features/map/providers/osm.ts))다. 지도 **그림 자체**는 OSM 재단의 서버에서 오고(우리가 내장한 것은 그리는 라이브러리뿐), 그 정책상 SLA 가 없고 막거나 느리게 할 수 있다 — 코드 주석도 「개발 기본값이지 고객에게 한 약속이 아니다」라고 적고 있다. 구글·네이버 지도는 키가 있을 때의 선택지다.
- 멈추면: 타일이 3번 연속 안 오면 화면이 「무료 지도 타일을 불러오지 못했어요」라고 알린다(핀과 경로선 데이터는 그대로). 지도가 빈 회색 상자로 보이지 않게 막아 두었다.
- **우리 길찾기 데이터(OSM 추출 파일)와는 별개다** — 길찾기는 디스크의 파일을 읽을 뿐 타일 서버를 안 부른다.
- 완전히 「내장」하려면 같은 지도 원본(Geofabrik 추출)으로 타일을 직접 만들어 우리 서버에서 내리는 길(벡터 타일 파일 + MapLibre 류)이 있다 — 필요 용량·작업량은 `[미확인]`(만들어 보지 않았다).

### 1-4. 오프라인 — 자료를 **만들 때만** 부르는 곳 (서비스 런타임은 안 부른다)

[datasets/mobility/scripts/](../../../../datasets/mobility/scripts/) 가 시간표 · 노선 · 역 좌표를 모은다: 국토부 **TAGO**(`apis.data.go.kr/1613000`) · 서울 열린데이터광장(`openapi.seoul.go.kr`) · 서울 버스(`ws.bus.go.kr`) · 한국천문연구원 특일(`B090041`) · 지도 원본 **Geofabrik**(OSM). 결과는 파일(`processed/`)이라 **API 가 멈춰도 서비스는 마지막으로 받은 자료로 돈다.** 새 자료만 못 받는다.

## 2. 오픈소스로 대체할 수 있나

| 지점 | 대체 가능? | 이유 |
|---|---|---|
| 길찾기(자전거·걸음·택시) | **이미 대체했다** | 지도 원본 OSM(ODbL) 위에서 우리 파이썬 A\*(`graph_router.py`)가 직접 찾는다. GraphHopper 는 선택 사항으로만 남았다. OSRM · Valhalla · GraphHopper 서버를 띄우는 길도 있으나 서버·메모리 부담이 크다 |
| 대중교통 경로·소요·요금 | **이미 대체했다**(자체 구현) | 시간표 판정기 + 운임거리(공표 + OSM 선로 길이 추정). OpenTripPlanner 같은 오픈소스는 GTFS 가 있어야 하고 서버가 무겁다 — 한국 지하철 GTFS 공급처는 `[미확인]` |
| 따릉이 실시간 거치 대수 | **불가** | 서울시가 지금 가진 **사실**이다. 오픈소스 코드로 만들 수 없다. 공개 표준 포맷(GBFS) 공급 여부는 `[미확인]`. 정적 통계로 「있을 것 같다」를 채우면 근거 없는 문장이라 금지 |
| 지하철 무정차·지연 | **불가** | 서울교통공사만 아는 운영 정보. 오픈소스 대체 없음(공지 페이지 긁기는 대체가 아니라 같은 정보의 다른 통로이고 약관 `[미확인]`) |
| 도로 돌발(UTIC) | **불가** | 경찰청 정보. 같은 종류의 다른 **API**(ITS · 서울 TOPIS)는 있으나 오픈소스는 아님 — 이것은 대체가 아니라 **이중화 후보** |
| 실시간 도착 | **불가** | 위와 같음(지금 값) |
| 공휴일 | **보조만 가능** | 이동은 이미 **파일**(`holidays_2026_2027.json`)을 쓴다. API 는 요식·활동 쪽(KASI). 파이썬 `holidays`(KR) 같은 오픈소스로 **검증용 대조**는 가능하나 임시공휴일 반영이 늦을 수 있다 `[미확인]` |
| 시간표 수집(TAGO · 서울) | 부분 | 수집 도구는 우리가 이미 쓴다. 공급 자체(데이터)는 오픈소스가 아니다 |

한 줄로: **「코드」로 풀 일은 이미 오픈소스 데이터(OSM)로 풀었고, 남은 API 는 「데이터」라 코드로 바꿀 수 없다.** 줄일 수 있는 것은 의존의 **강도**(멈춰도 덜 아프게)이지 의존 자체가 아니다.

## 3. 멈추면 어떻게 하나 — 지금 코드가 하는 것

원칙은 [D-018](../../../../wiki/decisions/D-018-decision15-stop-paths.md)(초안)과 결정 15다: **모르는 값을 지어내거나 「사건 없음」으로 넘기지 않는다.** 멈추는 단위는 프로세스가 아니라 그 판정이고, 층마다 다르다(기동 조립 = 기동 거부 · Case 실행 = 사람 인계 · 배치 = exit 1).

| 지점 | 멈춤의 모양 | 지금의 대응 | 대체(2차) 소스 |
|---|---|---|---|
| **따릉이 실시간** | 키 없음 · 네트워크 · http 오류 · 응답 이상 · 대여소 없음(`last_error.kind`) | `BikeLive.get` → `None`. 판정기는 그 대여소를 **「거치 대수 근거없음」으로 두고 후보는 유지**한다([verify_time.py:1060](../../../app/modules/travel_ops/mobility/engine/verify_time.py#L1060) 일대 — 확인된 0대만 「빌릴 수 없음」으로 건너뜀). 키가 든 주소는 오류에 안 싣는다 | **없음** |
| **GraphHopper**(켠 경우) | 서버 안 닿음 | 시작 때 안 닿으면 **로컬 도로 그래프로 대체**(`runtime.py:199`). ★이 선택은 **시작 때 한 번**이다 — 도는 중에 GraphHopper 가 죽으면 호출이 `RouterDown` 이 되어 그 구간 소요가 「근거없음」이 된다(자동으로 로컬로 갈아타지 않는다). 기본 설정은 GraphHopper 가 꺼져 있어 로컬이 1차다 | 로컬 도로 그래프 |
| **로컬 도로 그래프** | 자료 없음 · 지도 밖 · 경로 없음(`RouterDown`) | 장소↔장소 걸음: 직선×우회계수로 대체(길 **없음**은 후보에서 제외, 못 닿음은 길이 없다는 근거가 못 됨). 택시: `taxi_unavailable` + 이유 | 직선 어림(걸음만) |
| **UTIC**(도로 사건) | 못 읽음(IP 거절 · 형식 이상 · 한도) | `affecting()` → `None` → **치명**(결정 15). 감시 루프는 그 이동을 `fatal` 로 기록하고 일정을 안 바꾼다([trip_watch.py:149](../../../app/modules/travel_ops/trip_watch.py#L149)). 출발 알림은 **보내지 않고** `fatal` 로 센다([trip_reminders.py:297](../../../app/modules/travel_ops/trip_reminders.py#L297)). 배치(`run_sweepers --once`)는 `fatal` 이 하나라도 있으면 **exit 1** | **없음**(사건 쪽). ※ 장소 반경 점검(`check`)에는 ITS + UTIC 가 있지만 경로 사건은 UTIC 하나다 |
| **지하철알림정보** | 못 읽음 | 위와 같은 치명 경로. 단 이 소스는 **1~8호선 대상이 있을 때만** 부른다(대상이 없으면 호출 안 함). 키가 없으면 그 소스만 빠지고 그 대상은 「확인 못 한 대상」(`unsupported`) | **없음** |
| **실시간 도착** | 못 읽음 | 판정에 안 들어가 영향 없음. 실패는 `misses` 로만 센다 | — |
| **키 없음**(전반) | 조립 때 | 그 소스만 빠지고 기동은 된다. 이름과 이유가 `unavailable` 에 남고 `/ui/admin` 이 보여 준다 | — |
| **한도 초과**(전반) | `RateLimited` | 호출 안 하고 `None`(「모름」) — 위 치명 경로와 같다. 한도 값은 [settings.py](../../../app/core/settings.py) `rate_*` · 템플릿에 기록 | — |
| **시간표 · 자료 파일 낡음** | 수집 API 가 오래 멈춰 갱신 못 함 | 서비스는 마지막 자료로 돈다. 수집일이 기준(`mobility.staleness.timetable_warn_days`)을 넘으면 `timetable_stale` 경고, **날짜를 못 읽으면 낡은 것으로 본다**([runtime.py:231-253](../../../app/modules/travel_ops/mobility/engine/runtime.py#L231)) | 마지막 자료 |
| **입력 날짜가 자료 범위 밖**(공휴일 파일) | `CalendarOutOfRange` | 입력 오류로 올린다(지어내지 않음) | — |

## 4. 구멍 — 「잡혀 있다」고 하기 어려운 곳

- **사건 소스에 대체가 없다.** 결정 15 는 「1차가 안 되면 대체로」인데, 경로 사건(도로 · 지하철)은 한 소스씩이라 그 소스가 멈추면 곧바로 치명(= 그 이동은 감시·알림 없이 사람 인계)이다. 이중화 후보: 도로 = ITS(이미 `check` 에 있음) · 서울 TOPIS 돌발(OA-13315, 서울 키) / 지하철 = 같은 정보의 다른 통로뿐이라 **현실적 후보가 약하다** `[미확인]`.
- **GraphHopper 를 켜는 순간 도는 중 전환이 없다**(위). 지금은 꺼져 있어 해당 없다 — 켤 거면 런타임 전환(요청 단위 try → 로컬)이 필요하다.
- **UTIC 키는 IP 에 묶여** 서버 이전·고정 IP 서버 장애 시 전부 거절된다(`utic.py` 머리말) — 그때 모든 도로 사건이 치명으로 쏟아진다.
- **지하철알림정보는 제목 글자를 읽는다** — 「사건 없음」은 「알림에서 못 찾음」이다(위 12-7). 멈춤이 아니라도 **놓침**이 있는 소스다.
- D-018 은 **초안**이다(`status: draft`) — 층별 정지 경로가 합의된 사양인지는 아직이다.

## 5. 정하실 것 (없으면 이대로 둔다)

1. 도로 사건에 **ITS 를 2차 소스로 붙일지**(UTIC 가 멈추면 ITS 로 답) — 결정 15 의 대체를 이 자리에 구현하는 일. 추천: 붙인다 — ITS 어댑터가 이미 있으나(`its_traffic.py`), 응답에 **도로 이름 칸**이 있어 `도로:이름` 대상과 맞출 수 있는지는 아직 안 봤다 `[미확인]`(실호출로 먼저 확인).
2. GraphHopper 를 쓸 계획이 없으면 **코드·설정에서 정리할지**(지금은 선택 사항으로만 남음). 추천: 그대로 둔다(켜지 않으면 비용 0).

## 6. 구멍 두 가지 처리 · 미확인 조사 결과 (2026-10-05 새벽 추가)

### 6-1. 구멍 ① 사건 소스에 대체가 없다 → **도로는 ITS 를 2차로 붙였다**

- [ItsRouteEvents](../../../app/infrastructure/travel/its_traffic.py) 를 만들고, 도로 사건은 [AlternateRouteEvents](../../../app/infrastructure/travel/subway_notice.py)(UTIC 1차 + ITS 2차)로 **둘 다 물어 합친다**(합집합 · 겹치면 1차 값). 둘은 서로 다른 사건을 가진다(UTIC = 시내 사고·집회 · ITS = 도시고속도로·국도).
- **한쪽만 못 읽으면 읽은 쪽으로 답하고 `degraded` 에 남긴다. 둘 다 못 읽을 때만 치명**(결정 15). UTIC 키가 없어도 ITS 만으로 도로 사건에 답한다. 조립은 [base.py](../../../app/infrastructure/travel/base.py), 시험 6개([test_its_route_events_alternate.py](../../../tests/unit/travel/test_its_route_events_alternate.py)).
- ITS 응답에 **도로 이름 칸이 있다**(`roadName` + 메시지 `<종류>::도로::…`) — 기존 어댑터가 이미 쓰는 칸이라 `도로:이름` 대상과 맞춘다. (이번 실호출은 아래 한도로 못 했다.)
- ★**ITS 키가 지금 월간 호출 한도 초과로 거절된다** — `HTTP 401 · resultCode 4001 「월간 API 호출 한도를 초과하였습니다. 국가교통정보센터 로그인 후 인증키 상세정보에서 월 호출 한도를 증설한 후 이용해 주시기 바랍니다」`(2026-10-05 실호출). 월간 한도의 크기는 `[미확인]`(포털 로그인 화면에 있다). 그래서 **지금은 ITS 가 2차로서 못 읽는 상태**이고 위 규칙대로 UTIC 단독 + `degraded` 로 돈다. 사용자가 포털에서 한도를 늘려야 2차가 산다. 설정의 `rate_its_per_day=1000` 은 **하루** 기준 추정이라 월 한도를 막지 못한다.
- **지하철 쪽 2차**: 같은 알림이 **서울 열린데이터광장에도** 올라와 있다(OA-22718 「서울시 교통공사 지하철 알림정보 현황」 · 일반 인증키 사용 · 우리가 이미 가진 키). 그러나 **서비스 이름(요청 주소의 `…/json/<서비스명>/1/5/`)을 정적 페이지·검색으로 못 찾았다** — 그 화면은 로그인한 뒤 「Open API」 탭에서 샘플 URL 이 보인다. 그것을 받으면 같은 해석 코드로 2차 소스를 붙일 수 있다(두 소스가 같은 데이터라 **통로의 이중화**이지 사건의 이중화는 아니다 — 서울교통공사가 알림을 안 올리면 둘 다 없다).

### 6-2. 구멍 ② UTIC 키가 고정 IP 에 묶여 장애 때 치명이 쏟아진다 → ① 로 **치명이 되지 않는다**

UTIC 가 IP 거절(`resultCode 03`)을 내면 이전에는 도로 사건이 전부 치명이었다. 이제 ITS 가 받는다(ITS 한도가 풀려 있을 때). 거절 이유는 `misses` 에 「bad_xml(…허용된 IP가 아닙니다)」로 남고 `degraded` 가 `utic_route_events` 를 알린다. 두 소스가 같은 날 같이 막히면(지금처럼 ITS 한도 + UTIC 장애) 그때는 치명이다 — **ITS 월 한도를 올려 두는 것이 이 구멍의 실제 방지책**이다.

### 6-3. 미확인 조사 결과

| 질문 | 찾은 것 | 판정 |
|---|---|---|
| 따릉이를 GBFS 같은 공개 표준으로 받을 수 있나 | 공식 데이터는 서울 열린데이터광장 OA-15493 의 인증키 API 뿐이다. GBFS 피드(`gbfs.json`) 공급 흔적을 **검색에서 못 찾았다**(검색 범위: 한·영 검색 한 번 + 서울 데이터광장 목록) | 없을 가능성이 높다 `[못 찾음 — 존재하지 않는다는 증명은 아님]` |
