# 버스 실시간 공유 저장과 거리자료 명세

승인된 버스 정보를 실제로 받아 숫자 시간과 상태 메시지를 구분했고, 서로 다른 객체가 로컬 개발 DB 응답을 공유함을 확인했습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 버스 최신 응답 1회 | 완료 | 1/1 = 100% |
| 신규·기존 버스 시험 | 통과 | 18/18 = 100% |
| 거리 데이터 문서·등록표 | 완료 | 3/3 = 100% |
| 현재 자료 해시 검사 | 통과 | 1/1 = 100% |

## 결과와 적용 조건

버스 원문은 정류소 104개, 도착정보 208개였습니다. 175/208 = 84.1%에 분·초가 명시됐고,
33개 상태 메시지는 출발대기 15·곧 도착 14·회차대기 4였습니다.
숫자가 없는 상태를 0초로 바꾸지 않았습니다. 공급시각은 정류소 104개 모두 조회 시점보다 8초 전이었습니다.
이는 한 노선의 한 시점 실측입니다.

동일 노선의 원문과 정적 자료를 노선ID·정류소 순번·정류소ID로 비교한 결과 104/104개가 일치했습니다.
실제 도착 원문의 방향 이름은 104/104개가 빈 값이며, 정적 자료에는 방향이 104/104개 있습니다.
운영 연결부는 이름만으로 방향을 고르지 않고 세 식별자를 대조한 뒤 정적 방향의 출처를 함께 써야 합니다.

새 시험은 실제 로컬 개발 DB를 사용하며 mock 전송은 첫 객체 1회, 둘째 0회입니다.
다른 순번의 정류소 선택·도착시간·최초 확인 순간·공급시각 보존·버스 30초 만료·키 원문 미저장을 확인했습니다.

거리 입력은 선로 v2의 777행 중 726개에 값이 있고, 공표 거리 대응표가 214간선을 보강합니다.
전체 등록 자료는 23개입니다. 선로는 **추정**, 대응표는 **공표값·대응방향 추정**으로 기록했습니다.
대응 방향이 미확정인 묶음 13/56개와 거리 수치 충돌 9간선은 보강에서 제외합니다.
현재 명세에 대한 파일 이름·크기·SHA-256 검사는 누락과 불일치 없이 통과했습니다.
검사 분모는 실제 런타임 데이터 입력 12개이며, 명세 대응·존재 확인 모두 12/12개였습니다.
