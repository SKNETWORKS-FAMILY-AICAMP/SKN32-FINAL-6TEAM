# 여행 밀도 관측 경고 구현

> 수치 근거 보강 후속판은 [2026-09-22_2300_여행밀도_근거자료.md](2026-09-22_2300_여행밀도_근거자료.md)와 해당 코드의 `research_calibrated` 정책을 기준으로 읽는다.

2026-09-22 사용자 요청과 [D-019](../../../../wiki/decisions/D-019-travel-density.md)에 따라 입력 시간으로 밀도를 계산하고 등록·조회 API에 경고를 추가했다. 실제 실행한 관련 테스트는 43/43(100%) 통과했다. 실측 데이터로 비율을 검증한 결과는 아니다.

## 변경

- `app/modules/travel_ops/density.py`: 선택 입력 검증, 서울 날짜/야간 창, 항목·별도 이동·완충시간 합산, 초과/미측정 판정.
- `app/modules/travel_ops/trip_api.py`: 현재 저장 버전으로 계산한 `density`, `warnings` 응답 추가. 기존 위반 반환 계약 유지.
- `config/guardrails.yaml`: `travel.density.targets`에 [추정] 정책값 집중.
- `tests/unit/travel/test_density.py`, `tests/e2e/test_trip_api.py`: 누락·중복 시간·정확한 상한·완충·이동·날짜 경계와 실제 DB 등록/중복/조회 검증.
- [API 계약](../../external/travel-density.md), D-019, 문서 인덱스 갱신.

계약 문서를 먼저 작성하고 구현했다. `_trip_view`가 저장된 현재 항목으로 다시 계산하기 때문에 변경 후 조회에도 적용된다. 밀도 기능은 일정 생성/거절/자동 삭제를 수행하지 않는다. UI 변경과 배포는 포함하지 않았다.

## 근거

[The Vacation Planning Problem](https://www.sciencedirect.com/science/article/pii/S0305054822003136)의 방문·이동 시간과 하루 시간 예산 모델, [FHWA](https://ops.fhwa.dot.gov/publications/tt_reliability/ttr_report.htm)의 완충시간 개념을 참고했다. 어느 자료도 네 단계 임계값이나 서울 관광의 고정 버퍼를 검증하지 않는다. 그래서 정책값을 추정으로 명시하고, 실제 필요 버퍼는 입력으로 받는다.

## 검증 및 한계

[실행 기록](../evidence/2026-09-22_density-tests.md). 최초 실행 중 DB 메모리 부족 1건은 수정 없이 재실행해 해소됐으며 원인 분석/운영 안정성 검증까지 완료한 것은 아니다.

외부 경로 API 검증 없이 제출된 시간·경로를 측정한다. 명시 창 밖 숙소 왕복, 누락 식사 등 제출하지 않은 활동을 추론하지 않는다. 이동 정보를 모르면 밀도 숫자를 내지 않는다. 동행자 보정 및 임계값 기반 재조정은 실측과 정책 확정 후 연결할 후속 작업이다. 별도 모델의 교차검수는 수행하지 않았다.

작업 중 다른 변경도 감지됐다(`trip_api.py`의 `_create_trip` 분리 등). 해당 변경을 수정하거나 되돌리지 않았다. 이 리포트의 구현 목록은 밀도 변경만 설명하며 테스트 결과는 실행 시점 작업 트리 기준이다.
