# 출발 재검증의 사건 소스 분리와 도보 안내 검증

사건 소스가 없으면 현재 이동시간 계산까지 건너뛰던 문제를 고쳤습니다. 현재 관측 기능이 켜진 직접 도보는 사건 조회와 별개로 다시 계산하며, 단절은 안내를 보류합니다. 노선 확인이 필요한 이동의 소스 누락과 경로 정의 누락도 저장 시각 문구로 우회하지 않습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 수정 전 문제 조건 재현 | 재현 | 5/5 = 100% |
| 관련 시험 | 통과 | 37/37 = 100% |
| 확대 회귀 시험 | 통과 | 704/704 = 100% |
| 로컬 개발 DB 도보 | 통과 | 2/2 = 100% |

## 목표·원인·변경

v11 §6-B의 출발 시각 조회를 현재 이동 모델과 연결하는 최소 수정입니다. `build_departure`는 경로 정의 또는 경로 사건 소스가 없으면 현재 관측 콜백보다 앞에서 반환했습니다. 사건 대상이 없는 도보도 현재 보행망·계단 시간·단절을 다시 검사하지 않았습니다. 소스가 있지만 조회 결과를 못 내는 경우에도 불필요한 사건 조회가 재검증을 막았습니다.

변경 파일은 [안내 입구](../../../app/domains/travel_ops/components/watch/trip_reminders.py:327), [새 단위 시험](../../../tests/unit/travel/test_departure_source_gate_v1.py), [새 DB 시험](../../../tests/scenario/test_departure_source_gate_db_v1.py), [새 시각화 생성기](../../../scripts/mobility/build_readiness_visual_v16.py)입니다. 공개 Core/Team 계약과 요금·속도 상수는 바꾸지 않았습니다. 선택 경로의 사건 대상이 비어 있으면 사건을 확인했다는 표시 없이 현재 모델을 재검증합니다. 등록된 관측이 없는 기존 안내 계약은 유지했습니다.

| 조건 | 수정 전 | 수정 후 |
|---|---|---|
| 사건 대상 없는 도보·사건 소스 없음 | 저장 시각 문구 | 현재 모델 재계산 |
| 사건 대상 없는 도보·사건 소스 조회 불가 | 재계산 실패 또는 치명 상태 | 불필요한 조회 생략·현재 모델 재계산 |
| 도보 단절·사건 소스 없음 | 저장 시각 문구 | 보류 |
| 노선 확인 필요·사건 소스 없음 | 저장 시각 문구 | 치명 상태·발행 안 함 |
| 관측 등록·경로 정의 없음 | 저장 시각 문구 | 보류 |

[비교 흐름도와 전체21개 판단](assets/2026-10-09_mobility_readiness_v16/mobility-readiness.html)에 두 실행 흐름을 담았습니다. 사건 없음과 사건 조회 대상 없음은 다릅니다. 이번 변경이 보행 중 위험·재난까지 모두 확인한다는 뜻은 아닙니다.

## 검증 범위·분모

수정 전 새 단위 시험7개 중 문제 조건5개가 실패하고 기존 콜백 미등록 계약2개가 통과했습니다. [수정 전 XML](../evidence/2026-10-09_0358_출발재검증_사건소스_분리/departure-gate-before-v1.xml)과 전체 콘솔 로그를 보존했습니다. 최초 콘솔의 일부 한글은 출력 디코딩으로 깨졌으며 XML 및 최종 UTF-8 로그를 근거로 사용합니다. Python 종료 정리에서 pyreadline 오류도 표시됐지만 pytest 판정과 구분했습니다.

수정 후 목표35개가 통과했고 새 DB2개도 통과했습니다. 관련37개는 최종 확대704개의 시험 ID에서 확인한 부분집합이며 합산해741개로 세지 않습니다. 확대 실행은 네 프로세스를 순차 실행했습니다. 실제 도로 그래프를 적재하는 시험은 별도 프로세스이며 단일 프로세스 상주 메모리 검증으로 부르지 않습니다. [최종 명령·종료 코드](../evidence/2026-10-09_0358_출발재검증_사건소스_분리/departure-gate-regression-v1-commands.json)·[분모·해시](../evidence/2026-10-09_0358_출발재검증_사건소스_분리/verification-proof-v1.json).

DB 시험은 기존 도보 저장·관측·안내·중복 방지 시나리오를 사건 소스 없는 조건에서 실행했습니다. 통제된 도보 계산을 주입했고, 가능 조건은 현재 예상5분 안내 및 반복9회 중복 차단, 단절 조건은 보류·출발 발행0건을 확인했습니다. 실제 보행 측정이나 고객 GPS가 아닙니다. 외부 고객 채널에 메시지를 보내지 않았습니다.

mock 서버 시험(화면 반응): 안 했음. 통제된 경로 입력을 사용하는 단위·DB 시험 포함.
실서버 확인(로컬 개발 DB 연동): 했음. 배포된 cs 프로젝트 서버 응답 및 실제 보행·탑승·결제: 안 했음.

## 오늘 확인한 문서·논문과 적용 전제

[GTFS 공식 Trip Updates 문서](https://gtfs.org/documentation/realtime/feed-entities/trip-updates/)는 실시간 갱신 부재를 정시 운행으로 해석하지 말라고 명시합니다. 이번에는 사건 소스와 이동시간 재검증의 역할을 구분하는 참고로 사용했습니다. 서울 API를 GTFS라고 간주하거나 사건·보행 정확도 보장으로 적용하지 않았습니다.

[T-REX 논문 초록](https://arxiv.org/abs/2605.18778)은 대규모 시간표·환승 전처리와 실시간 일정 갱신을 다룹니다. 초록만 검토했으며 해당 알고리즘이나 논문의 속도 수치를 우리 계산에 이식하지 않았습니다. 이번 결함은 이미 등록된 계산이 실행되지 않는 입구 문제여서 그 분기를 먼저 수정했습니다. [조회 범위·참고 판단](../evidence/2026-10-09_0358_출발재검증_사건소스_분리/web-research-v1.json). 이번 지도 웹 경로 신규 관측0건·지도 API 직접 호출0회입니다.
