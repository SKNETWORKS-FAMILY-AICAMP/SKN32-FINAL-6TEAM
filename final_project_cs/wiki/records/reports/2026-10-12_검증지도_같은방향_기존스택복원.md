# 검증 지도에서 같은 방향 이전 일정의 기존 스택 복원

사용자가 v4 목업의 같은 서쪽 일정 두 개를 각각 표시한 부분을 정정했다. 같은 방향의 화면 밖 이전 일정은 기존 거리 스택 하나로 묶으며, 서로 반대 방향이면 따로 표시한다. 현재 지도 안 일정과 새로 확인 중인 일정은 이전 스택에 합치지 않는다. 공개 배포 전이다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 지도 단위 시험 | 통과 | 108/108 = 100% |
| mock 서버 시험 (화면 반응) | 재실행 포함 고유 사례 통과 | 12/12 = 100% |
| 목업 이미지·영상·가로 넘침 | 두 화면 폭 통과 | 2/2 = 100% |
| 원본·검사 사본 해시 | 일치 | 4/4 = 100% |

실서버 확인 (cs 프로젝트 서버 응답): 안 했음. 좌표를 배치한 mock 서버 응답으로 제품의 SSE·순차 지도 이동을 실행했다. 실제 접수·여행 등록 요청과 공개 배포는 하지 않았다.

## 변경

`map-geometry.ts`가 검증 중 모든 먼 일정의 묶음을 무조건 해제하던 조건을 고쳤다. 현재 지도 사각형의 비율과 마커 방향으로 왼쪽·오른쪽·위·아래를 구분하고, 같은 가장자리를 향하는 이전 일정만 묶는다. 새 현재 일정은 카메라가 도착하기 전에도 별도로 남는다. 일반 완료 화면의 기존 근접 묶음·최대 개수·거리 표시·클릭 동작과 스택 UI는 그대로 사용한다. API·권한·DB 계약은 바뀌지 않는다.

기존 강제 개별 표시 시험을 이번 사용자 정정에 맞춰 변경했다. 작은 지도에서 같은 방향 2·3·4·5·20개 일정이 빠짐없이 스택에 남는지, 동서남북이 분리되는지, 지도 안 일정과 새 현재 일정이 스택에서 제외되는지, 지도 도구를 피하는지 검사한다. Chrome에서는 375px·1280px의 같은 서쪽과 반대 방향을 실제 SSE 좌표로 실행하며, 이전 마커 요소 유지·현재 마커 중심·이동 중 소실과 잘못된 합침·가로 넘침을 관찰한다. 기존 일반/동작 줄이기 및 전체 접힌 목록 검사도 포함한다. 밀집 스택 누름 검사는 기존 제품 CSS를 재사용한 DOM 진단이며 실제 SSE 검사를 대체하지 않는다.

## 실행과 한계

2026-10-12 로컬 실행. 격리 사본에서 production webpack 빌드·TypeScript 검사를 실행했고 종료 코드0이다([빌드 상태](../evidence/2026-10-12_map-stack-direction-v5/build-status.json), [전체 빌드 로그](../evidence/2026-10-12_map-stack-direction-v5/build.log)). 변경한 네 파일의 ESLint 종료 코드0을 확인했다([로그](../evidence/2026-10-12_map-stack-direction-v5/lint.log)). 실제 제품 원본과 검증 사본 네 파일의 해시가 일치한다([해시](../evidence/2026-10-12_map-stack-direction-v5/source-match.json)). 이를 현재 공유 작업 폴더의 모든 변경 검증 완료로 확대하지 않는다.

단위 시험 최종 실행은 `vitest run src/features/map --maxWorkers=1`로 108/108 통과·실패0이다([결과](../evidence/2026-10-12_map-stack-direction-v5/map-unit-final.json)). 초기 전체 단위 실행은 권한·디스크 제약으로 일부 시험 파일을 실행하지 못했으며 그 집계는 최종 통과 수에 포함하지 않는다([초기 결과](../evidence/2026-10-12_map-stack-direction-v5/map-unit-results.json)). 초기 빌드는 격리 실행 환경의 경로 접근 거부로 실패했으며 필요한 실행 권한으로 다시 빌드했다.

Chrome 첫 실행은 11개 통과·1개 실패·생략0이다([원본 결과](../evidence/2026-10-12_map-stack-direction-v5/browser-results.json), [전체 로그](../evidence/2026-10-12_map-stack-direction-v5/browser.log)). 실패한 1280px 동작 줄이기 사례는 디스크 여유0 시점의 Chrome page/context 준비 시간 초과였으며 GPU 버퍼 초기화 실패도 기록됐다. 화면 동작의 assertion 실패는 아니었다. 공간 확보 후 **같은 코드**로 그 한 사례만 재실행해 1/1 통과했다([재실행 결과](../evidence/2026-10-12_map-stack-direction-v5/retry-results.json), [로그](../evidence/2026-10-12_map-stack-direction-v5/retry.log)). 따라서 12개 고유 사례 모두 통과했으나 한 번의 중단 없는 12/12 실행이라고 보고하지 않는다.

공간 확보에는 Codex·Claude 기록과 기존 Next 빌드 캐시의 NTFS 압축만 사용했다. 파일 내용·원본 자료를 삭제하지 않았다. 여유 공간 변화 전체를 이 작업만의 확보량이라고 계산하지 않는다.

- [촬영 자료 해시](../../../frontend/apps/web/mockups/map-reveal-continuity-2026-10-12-v5/capture-manifest.json): 새 HTML·PNG·영상 해시.

- [변경 직전 백업](../evidence/2026-10-12_map-stack-direction-v5/_backup/): 배치 계산·단위 시험·Chrome 시험 두 파일·wiki 흐름 계약 원본. 원래 보관 위치는 작업용 임시 폴더였으며 이 증거 폴더에 복사했다.

실제 촬영 화면을 직접 보고 왼쪽 기존 스택과 가운데 현재 마커, 넓은 화면의 동일 배치를 확인했다. 이 수정은 Codex가 수행했으며 Claude의 새 구현·독립 검토 결과로 표시하지 않는다. 커밋·푸시 담당 채팅에는 앞선 전부 개별 표시 판을 대체하는 후속 변경으로 인계한다.
