# 요식 판정 — 원장 밖 가게도 구글로 영업 확인 (2026-10-21)

사용자 지시: 「원장에 없는 가게는 인허가 · 카카오로 찾고, 찾으면 구글로 영업 확인을 한 번 더」 → 「순서대로 진행하자」.

## 문제

`find_place` 는 원장 → 인허가 → 카카오 순으로 찾는다. 인허가 · 카카오로 찾은 가게는 원장 번호(`place_uid`)가 없는데,
영업 도구는 모두 원장 번호를 받았다 — 구글 실시간 확인(`live_open_check`)도 원장 표에서 이름 · 좌표를 꺼냈다.
그래서 원장 밖 가게는 구글을 부를 길이 없었고 영업 줄이 늘 「확인 필요」였다(사람 정답 평가 33번 「판정 없음」).
「원장에 없으면 구글」이라는 결정이 판정 에이전트 경로에서는 작동하지 않고 있었다.

## 고친 것

| 파일 | 변경 |
|---|---|
| `instances/dining/agent_tools.py` | `live_open_check` 가 `place_uid`(원장 가게) 또는 `find_call_id`(원장 밖 가게를 찾은 `find_place` 의 call_id) 중 하나를 받는다. 이름 · 좌표는 **그 호출 기록에서** 꺼낸다(모델이 적어 넘기지 않는다). 원장 가게 · 없는 호출 · 좌표 없음 · 둘 다/둘 다 없음은 거절. 결과에 `place_source`(ledger · license · map). 찾기 결과 안내문도 「영업은 live_open_check(find_call_id)로」로 |
| `instances/dining/agent.py` | 근거 검증이 원장 밖 가게를 그 찾기 결과(`find_call_id`)로 가린다 — 다른 찾기 결과의 구글 확인 · 항목의 찾기를 모르는 경우 · 원장 가게 항목에 붙은 경우는 `evidence_other_place`. 인용하지 않은 같은 가게의 구글 「닫힘」도 「영업 가능」을 막는다. 지시문 규칙 3에 원장 밖 가게의 확인 방법 3줄 |
| `instances/dining/judge.py` | `outside_ledger()` — 판정 기록(`dn_agent_judge` 의 `_run` 줄 `detail.outside_ledger`)에 원장 추가 후보를 남긴다. 인허가는 이름 · 주소 · 좌표 · 분류, 카카오는 **고객이 쓴 이름만**(카카오 결과 비저장). 자동 적재하지 않는다 |

화면 문장은 바꾸지 않았다 — 구글이 근거인 영업 줄은 이미 「구글 정보로는 …」으로 나온다(`judge._text`).
Google 같은 가게 판정 반경은 어댑터 기본값 300m 그대로다.

후보 보기(마이그레이션 없음):

```sql
SELECT created_at, detail->'outside_ledger' FROM dining.dn_agent_judge
WHERE check_code = '_run' AND jsonb_array_length(coalesce(detail->'outside_ledger', '[]')) > 0;
```

### 실측에서 찾아 고친 결함

`judge.run` 의 후보 기록을 처음에 `result.tool_calls` 로 셌는데, 이 목록은 도구 **결과를 싣지 않는다**(id · tool · args 만) — 운영에서 후보가 늘 빈 목록이었다.
도구 기록(`tools.calls`)에서 세게 고치고 `judge.run` 경로 시험을 더했다(고치기 전 실패 확인).
한 번은 `tools.calls` 를 바로 읽어 기록이 없는 가짜 도구를 쓰는 시험 9건이 「판정 실패」로 바뀌었다 — 후보 기록은 부가 정보라 기록이 없으면 빈 목록으로 둔다.

- 원장 밖 식사 7항목 모두 모델이 `find_call_id` 로 구글을 불렀다(7/7 = 100%). 근거 검증 실패 0 · 빠진 필수 체크 0 · 실행 실패 0.
- 원장 가게(O5 금돼지식당)는 예전처럼 원장 규칙 도구로만 판정했다 — 원장 경로는 바뀌지 않았다.
- 구글 호출 7회(Text Search 7 · Details 7). 구글 판정이 실제와 맞는지는 대조하지 않았다 — 이번에 본 것은 「길이 생겼고 모델이 그 길을 쓰는가」다.
- O6 에서 모델이 못 찾은 이름을 세 번 찾았다(지시는 「다른 말로 한 번」). 세 번째는 `lat: None` 을 붙여 같은 인자 반복 거절을 비켜 갔다 — 별도 과제.

## 한계

- 6건 · 1회라 정확도 수치로 일반화하지 않는다. 구글 판정의 정답 대조는 하지 않았다.
