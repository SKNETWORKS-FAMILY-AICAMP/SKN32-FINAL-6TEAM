# 웹 API 협업 규칙과 화면별 연동 문서 정리

- 날짜: 2026-09-29 · 작업: Codex.
- 티켓: ST4F-172 (`issue-1790660286474`).
- 기준: `develop` `fc1ac0a`, 문서 작업 브랜치 `codex/wiki-docs`.
- 사용자 확정 범위: 기존 역할표를 변경하지 않고 이름으로 문서 갱신 책임을 정한다. 프론트 연결은 최연우·최상욱 공동이다. 기존 API 명세를 유지·갱신하고 화면별 연동 문서를 추가한다.

## 수행 내용

- [RULE.md](../../../RULE.md) §3.5.1에 최연우(API 명세·백엔드 구현 상태), 최상욱(화면 설명·요구), 공동(프론트 연결·통합 검증) 책임과 에이전트 갱신 절차를 기록했다. 양측 합의·검토를 추정하지 않으며 실제 수행자와 근거를 남긴다.
- [화면별 연동 문서](../../external/web-screen-api.md)에 화면의 동작·필요 데이터, 사용 API, 구현/연결/검증 상태와 협의 항목을 정리했다. 실제 통합 검증을 수행하지 않았으므로 초기 검증 상태는 미검증이다.
- [API 명세](../../external/rest-endpoints.md)에 예열 API를 추가하고 웹 응답·CORS·실제 상담 경로·설문 소비 범위·미연결 기능을 코드와 맞췄다. 새 기능의 계약을 임의로 만들지 않았다.
- [REST 개요](../../external/rest-api.md)의 오래된 Case 전용 전체 API 설명을 현재 진입점 안내로 갱신하고, [인증 경계](../../external/auth-boundary.md)에 고객 웹의 사용자 키 인증을 구분했다.
- [영역 색인](../../external/index.md)과 [CS 색인](../../index.md)에서 새 문서를 찾도록 연결했다.
- 프론트 원본 안내 8개(`frontend/README.md`, `UI_EVAL_WORKSPACE.md`, 웹 `README.md`·`DEVELOPMENT.md`·`IMPLEMENTATION_SUMMARY.md`·`MAP_INTEGRATION.md`·`PREFERENCES_CONTRACT.md`·`PROFILE_CONTRACT.md`)의 현재 기준을 `fc1ac0a`로 맞추고 공유 문서를 링크했다. 과거 검증 기록은 보존했다.
- 예열 라우트가 OpenAPI 검사 목록에 없는 점은 [결함 기록](debugs/2026-09-29_1436_예열API_검사목록_누락.md)에 남겼다. 테스트 코드는 변경하지 않았다.

## 범위와 남은 일

- 루트 README의 팀 소개·`wiki/delivery/roles.md`·공통 리뷰 정책은 변경하지 않았다.
- 애플리케이션 코드·API 동작·테스트·환경 설정은 변경하지 않았다. 최신 develop 반영은 기존 커밋의 fast-forward이며 이번 문서 변경과 구분한다.
- Python 계약 검사는 로컬 환경 문제로 실행하지 못했다. 실제 서버·브라우저 검증과 Q-01~Q-04의 양측 합의가 남아 있다.
- 이 문서 작업은 ST4F-170의 원본 최신화 다음 단계다. 앞선 기록은 당시 `0e27dfc` 기준의 결과로 보존한다.
- 이번 작업에서 개인 문서를 팀 저장소로 옮기거나 Jira 상태 전환 정책을 바꾸지 않았다.
- 커밋·푸시·PR은 수행하지 않았다.

## 2026-09-29 커밋 전 재확인

위 결과는 최초 문서 작성 시점의 기록이다. 이후 사용자가 두 저장소의 확인·커밋·푸시를 승인했다. 원격 develop의 `4f6297e`(데이터셋 안내·루트 README 변경)를 fast-forward로 반영했으며 이 문서가 대조한 웹/API 소스는 `fc1ac0a`와 같다. 웹 README에 Turnstile의 과거 시험 기록과 현재 develop의 서버 검증 미적용 상태를 구분하는 문구를 보충했다. 역할표와 팀 공통 문서 배치·티켓 운영 규칙은 추가로 수정하지 않았다.

API 15/15개·프론트 호출 14/14개·화면 경로 10/10개(모두 100%) 정적 대조를 다시 확인했다. 실행 테스트의 기존 환경 제약은 위 기록과 같으며 실서버 시험은 새로 수행하지 않았다. 이 기록은 커밋 전 검토이며, 게시 결과와 최종 커밋은 Git 이력에서 확인한다.

## 2026-09-29 role-eval-ui 통합 및 PR 준비

사용자 승인으로 문서 커밋 `21d7663`을 `role-eval-ui`에 병합·푸시했고, 최신 develop `6dedd87`도 충돌 없이 병합했다(`e786d10`). develop 대비 변경은 Markdown 23/23개(100%)이며 애플리케이션 코드 차이는 없다. 새 develop 커밋의 모델 서버 표기·시험용 주소 변경은 그대로 보존했다.

- PR 기준 정적 대조: API 15/15개·프론트 호출 14/14개·화면 경로 10/10개(모두 100%). 로컬 링크 264/265개(99.6%) 유효. 앞서 기록한 기존 CS 색인 누락 링크 외 새 오류는 없다.
- `git diff --check origin/develop..HEAD` 통과. 팀 역할표·리뷰 정책 변경 없음. `.env.teamflow`는 Git 제외·미추적 상태다.
- `python -m pytest tests/security -q`는 `psycopg` 부재로 수집 오류 2건이 발생했다. 보안 테스트 통과로 표시하지 않는다.
- `python -m scripts.verify_dod`는 종료 코드 1이다. 이 명령은 소스에서 과거 v8 기록용으로 명시되어 있으며 현재 기준은 `verify_dod_v11`이다. 기존 evidence의 부분 통과 항목과 로컬 테스트 수집 실패가 있고, 출력 중 `cp949` 인코딩 오류도 발생했다. 현재 DoD 달성률이나 실행 테스트 결과로 재해석하지 않는다.
- 로컬 Python 실행의 제약은 기존 기록과 구분해 유지한다. PR의 develop·web CI 결과와 병합 결과는 해당 PR에서 확인한다. 실제 서버·브라우저 통합 검증은 이번 문서 통합 범위에 포함하지 않았다.
