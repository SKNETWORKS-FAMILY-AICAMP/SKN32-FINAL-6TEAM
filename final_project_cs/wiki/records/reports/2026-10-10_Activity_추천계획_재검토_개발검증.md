# Activity 추천 계획 재검토와 개발 검증

계획은 그대로 채택하기에 부족했습니다. 기존 문제에 후보 ID와 정답의 강한 상관관계가 있어 품질 결론을 좁혔고, 추가 비용 없이 재계산·경계 시험·사람 검수 준비를 완료했습니다. 운영 채택은 아직 판단하지 않았습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 기존 결과 지표·비용 재계산 | 완료 | 432/432 = 100% |
| 새 단위 시험 루트 재실행 | 통과 | 76/76 = 100% |
| 개발 경계·규모 문제 재실행 | 통과 | 8/8 = 100% |
| 사람 정답 검수 | 대기 | 0/48 = 0% |

지금 달라진 것은 연구 근거와 검증 도구입니다. 실제 고객의 추천을 변경한 결과가 아닙니다. 다음 품질 판단에는 사람이 검수한 새 문제와 모델별 설정을 고정한 비교가 필요합니다. [후속 실행 기준](../../../../program/research/activity_recommendation_20261009/followup-plan-20261010.md)에 제안 표본·통과 기준·실패 처리·비용 보호를 적었습니다.

## 가장 중요한 정정

기존24개 문제 중23개의 최고 정답은 후보 ID가 `c01`로 끝납니다. 방문 조건을 통과한 ID를 단순 오름차순 정렬해도 1위23/24 = **95.83%**, nDCG@3 **0.99824**입니다. 기존 Luna 직접 경로(24문제×3회)의 1위62/72 = **86.1%**를 고객 취향 이해 성능이라고 해석할 수 없습니다. 모델이 실제로 ID 단서를 사용했는지까지 확인한 것은 아닙니다. 기존 합성 자료에 대한 응답과 자동 점수는 보존하되 실제 추천 품질의 채택 근거로 사용하지 않습니다.

Jev API(유료)의 기존 Noul 확률 가중합은 **보정하지 않은 확률 가중합 휴리스틱**입니다. 취향 강도나 잘 정의된 기대 효용으로 표현하면 부정확합니다. 참·거짓 성격 판정과 등급별 취향 적합도를 나누고, 등급·계수·확률의 의미를 사람 검수로 확인해야 합니다. TypeSafe 공식 문서도 Noul의 중간 확률을 중간 강도로 해석하지 않도록 구분합니다. [TypeSafe 질문 유형](https://docs.typesafe.ai/primitives).

기존 원문 판정 시험을 전부 무가치하다고 단정하는 것도 맞지 않습니다. 비정형 공지의 예외·휴무·영향 해석과 오류 유형을 확인하는 가치는 있습니다. 다만 원문 판정154/156의 허용 기준 점수를 고객 취향 추천의 성능으로 옮길 수 없고, 자동 채점·미확인 허용과 실제 정답 정확도도 구분해야 합니다. 원문 해석과 추천은 서로 다른 시험입니다. [이전 코드·실행 기록 검토](2026-10-09_Activity_추천구조_모델비교_실측.md).

## 비용에 관한 결론과 범위

저장된 사용량과 단계별 비용을 다시 계산한432개 행은 기존 기록과 일치했습니다. nano와 Luna의 기존 요청은 같은 `low` 설정·출력 한도에서 측정했으므로 모델별 최적 설정 비교로 확대하지 않습니다.

| 경로 | 관측 사용량의 평균 예상 비용/요청 | 같은 토큰 수·캐시 없음 가정 |
|---|---:|---:|
| GPT-5.4 nano 직접 | $0.00209200 | $0.00209200 |
| GPT-6 Luna 직접 | $0.00039659 | $0.00042356 |
| Jev API(유료)+코드 | $0.00042281 | $0.00042281 |
| Jev API(유료) 선별+Luna | $0.00072087 | $0.00073250 |

캐시 없음 가정에서도 Luna 직접의 비용은 nano 직접보다 약**79.75%** 낮습니다. 분모는 같은 저장 사용량으로 재계산한 nano 직접72회 평균 비용입니다. 이는 새 cold 호출 실측이 아니라 토큰 수를 고정한 가정 계산입니다. 해당 프롬프트에서 비용 차이가 관측됐다는 결론은 유지되지만, 실제 서비스에서도 같은 비율이라는 뜻은 아닙니다. 선별을 더하면 무조건 싸진다는 근거도 없습니다. [재계산 원본](../../../../datasets/travel/activity_recommendation_bench_20261009/audit-20261010-v1/audit.json).

이번 후속의 신규 유료 시험 호출은 **0회**입니다. 누적380/380회, 사용량 기반 예상액 **$0.349834632**, 금액 상한$0.50을 유지했습니다. 결제 명세서를 확인한 금액은 아닙니다. 금액 잔여분이 있어도 호출 수 상한은 소진됐습니다. 기존 실행기의 메모리 기반 비용 확인은 여러 프로세스가 동시에 시작할 때 안전한 공유 예약이 아니므로 차기 유료 비교 전에 잠금·원자적 예약을 검증해야 합니다. 지난 순차 실행이 상한을 초과했다는 증거는 아닙니다.

## 실제 실행한 무료 검증

새 개발 모듈은 필요한 사실의 값·관측 시각·근거 ID와 방문 조건을 확인합니다. 사실이 누락·오래됨·미래 시각이면 정상 추천을 반환하지 않습니다. 가능한 후보가0개면0개, 1·2개면 그 수만 요청합니다. 이 상태 정의는 연구 계약이며 운영의 정보원 대체·고객 안내 정책을 대체하지 않습니다.

단위 시험76개는 계약72개와 기존 기록 재계산 도구4개입니다. 후보 수 경계, 필수 제약, 음수·NaN·큰 정수·중복, 동점 복수 정답, 출력 ID·개수·근거, 후보 순서·ID 변경, 이동시간 증가·예산 축소·선호 중요도 반전을 검사했습니다. 설명의 근거 ID가 존재하더라도 설명문 의미의 진실성은 검사하지 않았습니다. 실제로 허위 설명을 넣어도 `semantic_factuality_verified: false`임을 확인하는 시험을 포함합니다.

별도 개발8개는 후보16·64·256개와 누락·오래됨·미래·음수·가능 후보 없음입니다. 속성과 ID는 별도 난수 흐름에서 생성합니다. 모두 자체 합성 숫자 자료로, 의미 이해 모델 성능이나 실제 장소 사실을 검증한 문제는 아닙니다.

| 후보 수 | 루트 측정 반복 | 코드 시간 p50 | 코드 시간 p95 |
|---|---:|---:|---:|
| 16 | 11회 | 0.5005ms | 0.7564ms |
| 64 | 11회 | 2.5006ms | 3.2478ms |
| 256 | 11회 | 7.9329ms | 9.6700ms |

시간 범위는 이 PC의 사실 확인·필터·정렬·ID·근거 검사 코드입니다. 모델·검색·네트워크·서비스 전체 지연이 아닙니다. 작성자 실행과 루트 실행은 각각 보존했고 두 실행을 모델 간 교대 비교처럼 해석하지 않습니다.

루트 단위 실행은 종료 코드0과 `76 passed`를 반환했습니다. 종료 뒤 `pyreadline3`의 Windows 콘솔 핸들 정리 오류가 표시됐으며 시험 실패로 집계하지 않았습니다. 재계산 도구 개발 중 자체 경로 비용과 선별 포함 총비용을 비교한 검증식 오류를 고쳐 각각 비교했고, 원본 시험 비용을 바꾼 것은 아닙니다.

Windows 줄바꿈 변환으로 개발v1의 기록 해시가 저장 전 LF 문자열을 가리키던 오류도 최종 검증에서 발견했습니다. 새v2는 저장하는 UTF-8·LF 바이트를 그대로 해시하며 회귀 시험을 추가했습니다. v1 결과를 덮어쓰지 않았고 v2 실제 파일 해시와 기록 해시의 일치를 루트가 확인했습니다. 기존 모델 입력·응답·비용에는 영향이 없습니다. ## 아직 필요한 검증과 실행 순서

기존24개의 ID·시설 이름·제시 순서를 바꾸고 정답과 모델 답을 뺀 검수 패킷을 준비했습니다. 두 사람×24개 = 48판정이며 현재 실제 사람 판정은0건입니다. 이미 모델에 사용한 문제이므로 개발 검수에만 씁니다. [검수 안내와 양식](../../../../program/research/activity_recommendation_20261009/human-review-20261010.md).

후속 계획에는 새 조정80개·새 미사용80개를 제안했고 고객·장소·서술 틀 분리를 명시했습니다. 아직 수집·검수하지 않았습니다. 같은 입력 조건의 통제 비교와 같은 조정 예산의 모델별 최적 설정 비교, 후보16/64/256개에서의 실제 모델 평가, 원시 선별과 보호 규칙 적용 후 회수율, 설명의 의미 근거를 분리합니다. 통과 기준은 연구 제안이며 확정된 제품 SLA가 아닙니다. 80개에서 위반이0개여도 실제 위반률0이나1% 미만을 증명하지 못합니다.

현재 공식 문서에서 Luna의 Decisions API도 추가 비교 후보로 확인했습니다. 조건 확률·고정 선택·등급을 다루는 별도 API이며 이번에 실행하지 않았습니다. 공급자 속도 주장을 우리 실측으로 쓰지 않습니다. [OpenAI Decisions 공식 문서](https://developers.openai.com/api/docs/guides/decisions).

독립 Codex CLI 판단과 루트 판단은 **1회차에 합의**했습니다. 합의한 내용은 기존 결과 보존과 무료 개발 검증·사람 검수 준비 우선입니다. 독립 AI 검토는 사람 정답 검수가 아닙니다. [독립 판단 기록](../../../../.tmp/consensus/20261010_activity_followup/decision.md).

[시작·분기·대기·종료를 구분한 연구 흐름](../../../../program/research/activity_recommendation_20261009/followup-flow-20261010.html)을 새로 작성했습니다. 기존 보고서는 당시 관측 기록으로 보존하고, 현재 연구 문서에는 이번 정정 링크를 붙였습니다. 수정 전 문서·코드는 각 폴더의 날짜별 `_backup/`에 보관했습니다.

최종 독립 재검토에서 사람이 설명을 모두 읽었다는 조건만으로 설명 정확성을 보장하지 못하는 빈틈도 보완했습니다. 후속 채택 기준은 응답 검수 누락0/N과 별도로 근거 없는·근거와 모순된 사실 주장0/M을 요구합니다. M은 실제 검수한 개별 사실 주장 수이며, 확인 불가나 빈 설명을 통과로 세지 않습니다. 아직 실제 설명 검수는 수행하지 않았습니다.
