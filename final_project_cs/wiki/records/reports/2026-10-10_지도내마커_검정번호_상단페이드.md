# 지도 안 마커·검정 번호·목록 상단 페이드

지도 안의 장소는 메뉴나 가장자리 가까이 있어도 개별 마커로 표시한다. 겹침을 피한 마커는 실제 좌표와 점선으로 연결하고, 화면 밖에만 검정 번호/여러 일정 칩을 표시한다. 목록 상단에서는 스크롤한 내용이 서서히 사라진다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 지도 계산 시험 | 통과 | 32/32 = 100% |
| mock 서버 화면 시험 | 통과 | 45/45 = 100% |
| 정적 검사·생산 빌드 | 통과 | 3/3 = 100% |
| 화면 촬영 | 완료 | 8/8 = 100% |

기존 화면 밖 판정은 상단·하단 여유와 좌우14px를 지도 영역에서 제외했다. 이제 실제 좌표의0..width/0..height만 판정에 사용한다. 메뉴와 목록 여유는 몸통 배치에만 사용하여 개별 마커를 숨기지 않는다. 공급자 공통 마커 연결선은 stroke-dasharray 2 4로 바꿨다. 좌표·방문 순서·경로선은 유지한다. 물리적으로 빈 자리가 전부 찬 극단적 밀집에서의 기존 개수 표시 규칙은 유지했다.

화면 밖 칩 번호의 배경은 검정(#202020), 글자는 흰색이다. 좌우 순서와 조작 중 거리 숨김,3개 이상 여러 일정 아이콘은 유지했다. 떠 있는 날짜 줄 아래 sheetBody에만 상단32px의 투명→불투명 마스크를 적용한다. 손잡이·날짜·좌표 안내·보내기 버튼에는 적용하지 않으며 추가 시간 애니메이션이나 스크롤 지연을 만들지 않는다.

mock 서버 시험45/45 (화면 반응). 분모는 새 지도·페이드4, 기존 날짜4·좌표 안내2·목록/계획 화면25·최소 접힘4·좌우/날짜/미선택 안내6의 고유 시험이다. 초기 전체 회귀35개 중4개는 옛 날짜 숨김·위치 미정 우선 기대값으로 실패했다. 최신 계약의 날짜 표시·확인 필요 우선으로 수정하고 재실행했다. 다시 드러난 공용 picked CSS 선택자 문제는 실제 data-map-summary를 검사하도록 보정했다. 실패와 재검증 근거를 모두 보존했으며 최종 고유45개는 전부 통과했다.

지도 계산32/32는 실제 경계 네 모서리, 안/밖 혼합 그룹, 메뉴·목록·좌우 가장자리의 개별 몸통 배치를 포함한다. Chrome은375px/1280px에서 실제 지도 드래그로 상단 메뉴 근처·바깥·안쪽 복원을 검사하고 점선·겹침 없음·검정 채움·스크롤 페이드·키보드 접힘을 확인했다. 표준 생산 빌드 후 실행했으며 시험 코드 수정 뒤 해당 시험을 다시 확인했다.
