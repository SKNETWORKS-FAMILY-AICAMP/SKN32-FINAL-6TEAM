# 출발 보류를 감시·현재 경로 재조정으로 연결

안내가 보류된 이동이 재조정 단계에 도달하지 못하던 두 지점을 고쳤습니다. 출발 안내가 아직 발행되지 않은 이동은 다음 방문 시작 전까지 감시하고, 이동 담당이 현재 시각·최신 인원·조건으로 경로를 다시 만듭니다.

## 원인과 변경

기존 감시는 앞으로 시작하는 항목만 읽었습니다. 출발 시각이 지난 이동에서 안내가 현재 경로 단절/옛 문맥/지각을 발견해 보류해도 감시가 읽지 못했습니다. 이동 담당도 운행 사건이 없으면 기존 경로를 그대로 두어, 시간상 불가능한 저장 후보가 재탐색으로 연결되지 않았습니다.

현재는 최신 여행 범위·재난 정지 조건을 유지하면서, 예정 출발~다음 방문 시작 전의 안내 미발행 이동을 별도로 선택합니다. 현재 관측을 동일 안내 계산으로 확인하고 보류만 이동 Case로 전달합니다. 소스 실패는 치명 기록으로 구분하며 안내가 직접 Case를 만들거나 일정을 수정하지 않습니다.

단일·묶음 감시 모두 출발 재검증 항목임을 이동 담당이 읽습니다. 처리 시각이 감지 시각보다 늦으면 처리 시각을 사용합니다. 여행의 최신 인원·조건과 앞뒤 장소로 새 구간을 계산하고 옛 저장 후보나 소요를 대체로 재사용하지 않습니다. 새 출발 문맥의 판·시간 단위, 현재 이후 출발 및 다음 방문 전 도착을 검사합니다. 계산 자료 실패·옛 시각 반환·문맥 누락은 성공으로 처리하지 않습니다. 새 안은 기존 전체 일정 재판정·동의·버전 충돌·멱등 적용 경로를 통과합니다.

## 재현과 시험

첫 신규 감시 시험8건은 미구현 입구 때문에 모두 실패했고 수정 후 통과했습니다. 이후 DB 시험의 두 실패는 시험 입력에서 `schema`를 실제 필드 `schema_version`으로 잘못 적은 것과, 일정 적용 외 응답 작업까지 함께 센 것에서 발생했습니다. 실제 필드와 `itinerary.apply` 작업 종류로 바로잡고 로그를 모두 보존했습니다. 제품 결함8건이나 정확도 개선8건으로 세지 않습니다.

로컬 개발 DB에서 옛 도착 시각이 지난 미발행 이동의 문맥 판을0으로 넣었습니다. 실제 감시→Controller→이동 Team→일정 적용을 실행해 판2→3, 새 이동 항목·문맥 판1을 확인했습니다. 같은 상황10회에서 Case1·일정 적용1·변경 통지1이고, 새 출발 시각에 현재 모델을 재검증한 출발 안내1이 발행됐습니다. 비교 조건인 이미 안내 발행한 이동은 판2를 유지했습니다. 보행망 응답300m를 주입한 통제 시험입니다. 실제 보행거리/시간·탑승·외부 메시지 전달 측정이 아닙니다.

## 연구 대조와 적용 전제

[Dynamic Replanning for Improved Public Transport Routing](https://arxiv.org/html/2505.14193v1)의 §2–4는 현재 시각·현재 정류장과 갱신된 연결에서 다시 탐색하는 구조를 다룹니다. §5.1은 서울 밖 네 도시와 합성 지연을 사용합니다. 현재 시각을 옛 감지 시각으로 대신하지 않고 탑승 상태를 추정하지 않는 범위 설정에 참고했습니다. CSA·envelope는 이 변경으로 구현하지 않았고 논문의 속도·시간 절감 값을 우리 성능으로 옮기지 않았습니다.

[GTFS 실시간 권고](https://gtfs.org/documentation/realtime/realtime-best-practices/)의 자료별 신선도·시각 검사를 확인했습니다. 서울 도착정보가 GTFS 형식이라는 전제는 두지 않았습니다. 이번에는 새 네이버·카카오·구글 경로 관측0건, 실제 탑승·결제0건이며 지도 개발자 API 직접 호출은 하지 않았습니다.

## 아직 해결되지 않은 범위

- 현재 위치·탑승·하차 확인이 없어 안내 발행 이후 이동의 재출발을 추정하지 않습니다. 안내 조회와 Case 처리/적용 사이 발행 경합은 아직 별도 동시성 검증이 필요합니다.
- 현재 관측은 저장된 동행 문맥을 읽습니다. 인원/조건만 바뀐 정상 경로를 자동으로 재탐색하는 대조와 다음 방문 시작 이후 지각은 남았습니다.
- 새 후보의 모든 사건 소스 확인, 장소 좌표 누락의 치명/미해결 구분, 실제 도보·대중교통 오차·혼합 운임·합법 차량 진입·복잡한 회전은 다음 개선 대상으로 남깁니다.
- 전체21개 판단은 조건부4·개선9·추가검증8을 유지했습니다. 코드 회귀 통과만으로 사용 가능으로 승격하지 않았습니다. 시각화는 브라우저 file: 보안 차단으로 렌더 검증하지 못했고 정적 구조만 검사했습니다.
