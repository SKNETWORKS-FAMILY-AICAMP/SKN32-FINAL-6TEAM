## 실패 시험을 정정한 기준

최초 54개 실패를 모두 제품 결함으로 세지 않았습니다. 현행 wiki 계약과 실제 UI를 대조해 제품 오류, 낡은 선택자·기대값, 시험 준비 조건, 실행 증거 부족으로 구분했습니다.

- 출발 시각 시험은 현재 기호·미정 표시로 선택자만 정정하고 시간과 기하 검사를 유지했습니다.
- 일정 0개 접수는 이전 입력 화면 자동 복귀가 현재 계약입니다. 원문·오류 안내 보존, 중복 제출·여행 생성 없음 검사는 유지했습니다. 입력 화면에도 있는 `첫날` 라벨 대신 읽기 단계 종료를 정확하게 검사합니다.
- 정상 일정 상태 배지 제거는 기존 승인된 표시 규칙과 대조했습니다.
- 시각 고정 시험은 그림자 여백을 포함한 날짜줄 상자가 아니라 실제 날짜 버튼 하단을 기준으로 준비합니다. 기존 4px 허용치를 넓히지 않았습니다.
- 지도 선택 후 이전 마커가 화면 밖으로 이동하면 실제 사용자와 같이 먼 마커 버튼으로 돌아갑니다. 숨겨진 마커 강제 클릭과 정렬 기대값 완화는 하지 않았습니다.
- 머리 영역 드래그 시험은 배경으로 포인터가 통과하는 헤더 빈 테두리 대신 날짜 버튼 사이 간격을 누릅니다. 해당 좌표의 실제 요소를 검사한 뒤 드래그합니다.

## Claude 검토와 미확정 항목

실제 `claude-sonnet-5-5` 모델로 UI 소스와 지도 소스를 각각 한 번 검토했습니다. 두 응답의 `modelUsage`와 종료 상태를 [UI 검토 원본](../evidence/2026-10-12_uiux-audit-final/claude-ui-review.json), [지도 검토 원본](../evidence/2026-10-12_uiux-audit-final/claude-map-review.json)에 보존했습니다. 코드 제공 승인을 받은 뒤 진행한 코드 정적 검토이며, Claude가 화면을 열거나 Chrome 시험을 실행한 결과가 아닙니다. 후보는 실제 호출부·계약·재현으로 다시 확인했습니다.

## 최종 추가 확인과 새 목업

변경관리 팝업의 화면 밖 넘침은 최종 관련 Chrome 검사에서 해소를 확인했습니다. 일정 0개 등록 여행의 렌더 오류도 제품 수정과 회귀시험에 포함했습니다.

새 [로딩 중 접힌 전체 목록 계약](../../external/web-flow-2026-10-09.md)을 구현했습니다. 읽어 온 전체 일정의 제목·시간은 먼저 표시하고 현재 검증 중인 카드만 펼칩니다. 다음 카드의 판정·결과·좌표는 미리 공개하지 않습니다. 지도 마커는 기존 검증 순서대로 공개하고, 목록은 현재 검증 중인 행을 따라갑니다. 완료 후 기존 원형 + 일정 추가도 유지합니다. API 입력·출력, DB, 권한 계약은 변경하지 않았습니다.
