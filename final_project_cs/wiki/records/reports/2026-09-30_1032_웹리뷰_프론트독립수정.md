# 웹 리뷰 프론트 독립 수정과 백엔드 전달

사용자가 요청한 수정안을 먼저 공유 연동 문서에 작성하고, 기존 API로 독립 수정할 수 있는 F-01·F-03·F-04를 구현했다. 완료 항목의 상세 수정안과 도입 이력은 이 리포트에 보존한다. 채팅 재시도(F-02/Q-05)와 일정 자동 갱신(F-05/Q-06)의 백엔드 확인 질문·담당 범위·공동 검증 시나리오는 [공유 연동 문서의 후속 협의](../../external/web-screen-api.md#코드-리뷰-후속-협의)에 남겼다.

- 수행: 2026-09-30 · Codex(최상욱 작업).
- 저장소·기준: SKN32-FINAL-6TEAM / `role-eval-ui` / `5202ef5a22baffdec909c925ddce3cce4a97537b` 위 로컬 변경. 착수 시 작업 트리 깨끗함.
- 티켓: **ST4F-179**, `issue-1790731231065`. 사용자 승인 후 생성·재조회 확인. 최종 구현·검증·남은 협의 내용을 기록하고 **review** 상태를 재조회해 확인했다.
- 상태: 프론트 독립 수정 **3/3 = 100% 구현·회귀 검증 완료**. 나머지 2항목의 협의·수정 및 실제 서버 검증·백엔드 합의는 미완료.

## 완료 항목의 도입 이력과 검증 기준

아래는 완료된 수정안의 문제·도입 이력·검증 기준이다. 수정안에 따른 최종 동작과 코드 근거는 위 수행 내용에 기록했다. P1은 우선 수정, P2는 후속 수정 우선순위다. 커밋은 현재 팀 저장소에 반영된 시점이며, 여러 원본 커밋을 합친 기록이므로 특정 개인의 최초 작성 이력으로 단정하지 않는다.

| 항목 | 수정 전 문제 | 도입 커밋 | 검증 기준 |
|---|---|---|---|
| F-01 · P1 | 키 저장 실패 후 다음 요청에서 새 사용자 키를 발급 | `571d7d2`(2026-09-28) | 저장소 차단 시 연속 요청의 키 일치·발급 1회, 저장 실패 안내·키 표시·거절된 키 제거 |
| F-03 · P2 | 입력란의 이전 날짜·시각이 최신 수정 판과 함께 다시 전송됨 | `571d7d2`(2026-09-28) | 서버 갱신 후 다른 칸 저장 시 이전 값 미전송, 성공 시 초안 정리·서버 보정값 반영, 실패·409 충돌 후 사용자 입력 보존 |
| F-04 · P2 | 다른 키로 전환해도 이전 사용자의 조회 캐시가 남음 | `9f6388d`(2026-09-28) | A→B 전환 뒤 B 조회가 느리거나 실패해도 A 자료 미표시, 이전 키의 늦은 응답 차단, 잘못된 키 가져오기는 기존 상태 유지 |

도입 근거: `571d7d2`는 `role-manager`의 계획 접수·서버 연결 작업과 UI 전환을 함께 반영한 커밋, `9f6388d`는 내 여행·키 관리·실서버 연결 등 22개 작업을 묶어 반영한 커밋이다.

## 검증

`[실측]` Windows / Node.js 22.22.3 / 설치된 Chrome / live 데이터 모드 / 가짜 웹 API(`tests/live/stub-server.mjs`). 명령과 출력은 [검증 근거](../evidence/2026-09-30_1032_웹리뷰_검증.md)에 있다.

| 확인 | 결과 |
|---|---|
| `npm run check` | 린트·타입 검사·프로덕션 빌드 통과, 단위 109/109 = **100%**(12/12 파일) |
| 추가 키 회귀 검사 | 5/5 = **100%**. 저장소 전체 차단·쓰기/삭제 차단·읽기 차단·이전 키의 늦은 200/401 |
| live 가짜 서버 브라우저 전체 | 재검증 **36/36 = 100%**, 추가 회귀 시나리오 4/4 포함 |
| 실제 서버·브라우저 통합 / 백엔드 계약 테스트 | 이번 실행 없음. 위 가짜 서버 결과로 대신 완료 처리하지 않음 |

첫 타입 확인에서 새 시험의 Storage 메서드 호출 타입 오류를 발견해 `Reflect.apply`로 고쳤다. 첫 브라우저 실행은 35/36 = **97.2%**였으며, 실패는 `getByRole('alert')`가 앱 오류와 Next.js의 화면 이동 안내 두 요소를 동시에 선택한 시험 오류였다. 검사 범위를 `main` 안으로 좁혔으며 앱 오류 안내와 이전 캐시 제거는 첫 실행에서도 확인됐다. 수정 후 전체 36건을 다시 실행해 모두 통과했다.

## 남은 확인과 전달

- Q-05·Q-06의 구체적인 질문과 검증 목록은 [후속 협의 원본](../../external/web-screen-api.md#코드-리뷰-후속-협의)에만 유지한다. 채팅 전송/조회 분리와 갱신 정책의 구현은 이번에 적용하지 않았다.
- 독립 수정 세 항목도 실제 백엔드에서 키 소유권·접수 수정 판·저장소 제한 브라우저를 최종 확인해야 한다. 프론트 회귀 시험과 실제 통합 검증은 별개다.
- 문서는 로컬 작성 상태다. 백엔드 담당자에게 메시지를 보내거나 합의를 대신 완료 처리하지 않았다. 커밋·푸시는 하지 않았다.

## 문서 정리 후속 (2026-09-30)

사용자 요청에 따라 완료된 세 항목의 상세 수정안을 공유 연동 문서에서 정리하고, 도입 커밋·수정 전 문제·검증 기준을 이 리포트에 보존했다. 연동 문서에는 현재 동작·검증 요약·보고서 링크와 Q-05·Q-06의 협의·공동 검증 사항을 남겼다. 웹 README와 검증 근거의 이동 링크도 새 제목에 맞췄다.

문서 4개를 점검해 상대 링크 **96/96 = 100%**, Markdown 제목·명시적 앵커 참조 **26/26 = 100%**가 유효함을 확인했다. `git diff --check`도 통과했다. 이 후속 정리는 문서만 변경했으므로 코드 시험은 재실행하지 않았으며 위 구현 검증 기록을 유지한다.
