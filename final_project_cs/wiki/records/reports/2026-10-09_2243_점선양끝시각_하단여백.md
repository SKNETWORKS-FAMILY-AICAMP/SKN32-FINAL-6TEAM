# 이동 점선 양끝 시각·하단 여백 수정

일정 시작 시각은 크게, 앞 일정 끝 시각과 이동 도착 시각은 점선 양끝에 작게 표시하도록 바꿨다. 이동 설명 아래의 도착·머무름 줄은 제거했다. 세로 지도 단추 배치, 목록 조작 중 제출 숨김, 추가 취소 후 하단 여백도 수정했다. 로컬 구현·검증 완료이며 공개 배포하지 않았다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 시간·지도·하단 동작 | 완료 | 3/3 = 100% |
| mock 서버 화면 시험 | 통과 | 28/28 = 100% |
| 두 너비 화면 촬영 | 완료 | 8/8 = 100% |

## 확인할 화면

[최신 목업](../../../frontend/apps/web/mockups/timeline-endpoints-2026-10-09-v1/index.html)은 375px/1280px를 전환하며 4개 상태를 보여 준다. 점선 양끝 시각, 추가 취소 복귀, 목록 끝, 조작 중 제출 숨김이다. 실제 프론트를 Chrome으로 촬영했고 지도는 OSM 타일을 사용했다. 이전 목업은 보존했다.

시작 시각은 16px이며 누를 수 있는 영역은 44px 높이다. 작은 끝·도착 시각은 11px이고 점선 위·아래에 놓인다. 끝 시각이 없으면 실제 이동 출발 시각을 쓰며, 도착 시각이 없으면 대시로 표시한다. 출발 편집·끌기·되돌리기는 유지한다.

세로 지도 단추는 거리 숫자 아래에 화살표를 놓고 기존 40px 높이와 메뉴보다 좁은 40px 너비를 유지한다. 배경은 떠 있는 머리말과 같은 92% 불투명도다. 낮은 지도에서는 기존 가로 배치를 유지한다.

제출 단추는 목록의 스크롤·휠·포인터 조작 중 숨고 마지막 조작 후 800ms에 복원한다. 포인터를 누르고 있는 동안은 계속 숨는다. 숨김은 150ms ease-in, 복원은 200ms ease-out이며 투명도와 4px 이동만 쓴다. 동작 줄이기 설정에서는 이동 없이 즉시 바뀐다. 숨긴 단추는 초점·클릭을 받지 않는다. 키보드로 제출 단추에 초점을 둔 상태는 보호한다.

추가 취소 시 바깥 화면이 115px 위로 스크롤돼 마지막 카드가 잘리고 아래가 비는 문제를 재현했다. 복원을 목록 안으로 제한하고 바깥 화면은 스크롤되지 않게 했다. [재현·측정](../debugs/2026-10-09_2235_추가취소_하단여백.md).

## 검증과 한계

mock 서버 시험 **28/28 = 100% (화면 반응)**. 새 시험 7개와 기존 회귀 21개를 파일·이름별 최신 결과로 셌다. 마지막 터치 범위 보완 후 새 시험 7개를 모두 다시 실행하고 기존 정렬 시험 2개도 다시 통과했다. [고유 시험 집계](../evidence/2026-10-09_timeline-endpoints/summary.json), [원본 실행 기록](../evidence/2026-10-09_timeline-endpoints/).

TypeScript 검사, 변경 파일 ESLint 검사, Next 빌드 모두 통과했다. 새 시험은 점선 양끝 좌표·시각 원값·시작 글자 크기·44px 터치 범위·지도 단추 크기/순서/투명도·누락 시각·외부 화면 스크롤 방지·마지막 카드 노출·제출 숨김/복원·동작 줄이기를 확인한다. 기존 회귀는 시간 편집/끌기, 취소/스와이프, 저장 중 취소 차단, 지도 도구, 카드 하단 상태를 포함한다. [정적 검사 기록](../evidence/2026-10-09_timeline-endpoints/checks.txt).

초기 시험에서 시각의 세로 정렬을 14px 보정했다. 제출 전환 시간 기대값은 Chrome의 단일 값 표현과 전역 동작 줄이기 설정의 0.01ms를 반영했다. 도착 시각 누락 시험의 응답 경로도 실제 review.moves 계약에 맞췄다. 최종 시험은 모두 통과했다.

실서버 확인 **(서버 응답): 안 했음**. 실제 cs 프로젝트 서버의 응답과 공개 배포 화면은 이번 검증에 포함하지 않았다. 커밋·푸시·배포는 이 작업에서 하지 않았다.
