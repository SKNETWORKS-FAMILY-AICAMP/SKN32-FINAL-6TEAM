# Oracle ARM 일정 읽기의 장소 검색 설정 누락 진단

`[실측]` 보고된 일정은 10항목 모두 PostgreSQL에 저장됐지만 좌표는 0/10입니다. 장소 검색 키와 공용 장소 표가 비어 있어 명확한 관광지 이름도 찾지 못했습니다. PostgreSQL 자체의 연결 장애나 모델 연결 단절을 이 증상의 주원인으로 볼 근거는 없습니다. **복구 적용은 아직 하지 않았습니다.**

| 확인 | 상태 | 분자/분모 |
|---|---|---|
| 일정 항목 추출·저장 | 정상 | 10/10 = 100% |
| 장소 좌표 확정 | 실패 | 0/10 = 0% |
| 관광공사·카카오 검색 키 | 누락 | 0/2 = 0% |
| 앱·DB·웹·상주 모델·모델 연결기 건강 상태 | 정상 | 5/5 = 100% |

분모 10은 해당 일정의 항목 수이며 다른 일정 전체의 정확도를 뜻하지 않습니다. 건강 상태 5개는 HTTP 건강 응답과 Docker 상태 검사이며 답변 정확도 시험이 아닙니다. `[실측]` 최종 건강 재확인 시각은 2026-10-10 04:41:21 KST입니다. [자격 증명을 제외한 관측](../evidence/2026-10-10_0441_arm-intake-place-diagnosis.json).

## 원인과 확인 범위

해당 접수는 review 단계, 첫 판이며 fatal 오류가 없습니다. 날짜·시각·장소 제목이 저장되어 있습니다. 공용 `places`와 `place_catalog` 표는 각각 0행입니다. 관광공사 개별 키·공공데이터 공통 키·카카오 검색 키가 모두 비어 있습니다. 일정 읽기의 실제 경로는 `pipeline._our_places`가 읽는 `places` → 관광공사 → 카카오이며, `place_catalog` 0행만으로 원인을 확정하지 않았습니다. 원본 장소 claim의 시도 내역과 조립 코드, 실제 환경을 함께 확인했습니다.

10항목 중 8개는 구체적인 관광지 이름이며 나머지 2개는 일반명 「호텔」입니다. 검색 연결 복구 후에도 일반명만으로 임의의 숙소를 확정하지 않습니다. 사용자의 실제 숙소 또는 선택한 후보가 필요합니다. 좌표 복구가 영업시간·이동·예약 검사의 전체 합격을 뜻하지도 않습니다.

`[실측]` 별도로 모델 분류 답변 형식 오류가 로그에 있으며 최종 확인 직전 20분에 해당 경고 2행입니다. 상주 모델 건강 응답과 연결기의 모델 목록 응답은 정상입니다. HTTP 연결 성공을 모델 답변 형식·품질 합격으로 해석하지 않습니다. 장소명이 명확한 항목도 좌표가 없는 현상은 장소 검색 설정 누락으로 별도 설명됩니다.

## 복구 준비와 승인 차단

기존 로컬 관광공사·카카오 키만 기계 내부 비공개 환경 파일에 추가하는 설정을 준비했습니다. 새 키 발급·새 비용·권한 확대는 포함하지 않습니다. 기존 관광공사 호출 상한과 카카오 호출 예산을 유지합니다. 자동 승인 심사가 **해당 목적지로 API 비밀키를 전송하는 명시적 사용자 승인이 부족하다**는 이유로 전송·적용 명령을 거절했습니다. 키는 전송하지 않았고 같은 전송을 우회하거나 반복하지 않았습니다. 사용자에게 정확한 전송 대상과 비공개 보관·무료 상한을 제시해 승인을 요청했습니다.

승인 후에는 기존 질의 회차가 공유 배포 잠금을 놓을 때 환경 파일을 먼저 백업하고 API·상시 작업자에만 설정을 적용합니다. 실패하면 원래 환경으로 되돌립니다. DB·상주 모델·추론 시험은 이 조치로 재시작하지 않습니다. 이후 실제 조회에서 8개 관광지를 확인하고, 기존 접수의 원본과 수정 이력을 보존한 뒤 장소 재확인 경로를 적용합니다. 새 여행을 만들거나 고객 입력을 임의로 바꾸지 않습니다. 승인 자체를 복구 완료로 표시하지 않습니다.

## 검증·보존

실서버 확인(Oracle ARM의 cs 프로젝트 서버 응답): 했음. 실제 DB의 해당 접수·장소 표·환경값 존재 여부와 실제 모델 건강 응답·컨테이너·로그를 확인했습니다. 화면 조작 및 복구 후 재평가는 아직 안 했습니다.

기존 앱·DB·일정 산출물은 수정하지 않았으므로 해당 원본의 덮어쓰기는 없습니다. 문서 연결 수정 전 백업은 [운영 문서](../../operations/_backup/2026-10-10_0443_place_diagnosis/) · [문서 로그](../../_backup/2026-10-10_0443_place_diagnosis/)에 보관합니다. 비밀키와 개인 접속 정보는 공용 기록에 싣지 않습니다.
