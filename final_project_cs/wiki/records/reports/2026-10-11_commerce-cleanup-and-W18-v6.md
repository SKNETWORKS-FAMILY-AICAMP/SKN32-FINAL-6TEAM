# 2026-10-11 이커머스 잔재 정리와 W18 개정

현재 실행 중 수집되는 시험·권한·옛 MCP·새 DB 생성 경로·학습 보스의 과거 자료 사용을 수정했습니다. 원문과 과거 수치는 기록·legacy·백업에 보존했고, W18은 공식 근거와 실제 배포 코드를 대조해 운영 절차와 환경별 관측으로 다시 썼습니다.

## 실제 변경

- 옛 주문·배송·반품 대조군, 구독·청구 분류 fixture, read.order 도구 예산 예시를 여행 정책·활동 취소·예약·장소 조회로 교체했습니다. 성공·거부·금액·인원 상한·미선언 필드·정책 변경에 따른 판정 차이를 유지했습니다. 실제 레일패스 기능이나 모든 산업의 범용성을 증명한다고 쓰지 않습니다.
- 연결되지 않는 옛 Case MCP3종·보조 함수·전용 시험을 legacy로 분리했습니다. 현재 여행 MCP는 웹 사용자 키·본인 여행 소유·쓰기 스위치 계약을 따릅니다. 공유 작업에서 현대 조립 방식에 맞춘 시험 helper 변경도 확인했고 과거 구현으로 덮어쓰지 않았습니다.
- SQL runner가 적용 이력 장부 없이 전체 파일을 매번 읽어 옛5표를 재생성하는 문제를 수정했습니다. 4개 역사 SQL의 이름·바이트는 그대로 두고 명시적 migration-plan에서 제외합니다. 누락·중복·경로 이탈을 거부하고 임시 새DB·데이터가 있는 임시DB 재실행을 확인했습니다. 기존 업무DB DROP·공개 배포는 수행하지 않았습니다. 이력 장부 개선은 별도 검토 대상입니다.
- 자동으로 읽히는 cs 작업 규칙·현재 wiki·개발자 진단 웹 시험·학습 도장을 정리했습니다. 옛 쇼핑몰 보스는 현재 실행에서 빼고 여행 정책 보스v2로 연결했습니다. 이전 학습 성공 기록은 archived로 옮겨 현재 성과와 합산하지 않습니다. 기존 개인 학습 진행 파일을 직접 덮어쓰지 않았습니다.

Docker 빌드 맥락에서 중첩 `_backup/`도 제외하도록 보완했습니다. 앱 아래 보존한 과거 Python 파일이 배포 이미지에 복사되지 않도록 하며 재유입 검사에서 이 설정 누락도 확인합니다. 실제 Docker 이미지 빌드·공개 배포는 수행하지 않았습니다.

여행지 백화점·시장·쇼핑 활동, 여행 예약 환급, 재유입 방지 금지 목록·부정 대조 입력은 유지합니다. 단어가 등장한다는 이유로 여행 기능을 지우지 않았습니다. 과거 발표 계획·가격·성능·수집 기록은 현재 완료 증거로 쓰지 않도록 현재 입구와 보존본을 분리했습니다.

## W18 근거와 적용

‘PC 콘솔’ 대신 **터미널 창**, **개발자용 진단 웹 화면**, **고객 여행 웹 화면**을 사용합니다. 당시 문제는2026년9월 로컬 개발 환경의 수동 실행 장애입니다. 이를 현재 공개 배포 전체 상태로 일반화한 문장을 제거했습니다.

[운영 현황](../../operations/current-state.md)은 로컬 개발·x600 공개 배포·Oracle ARM 앱 실험·ARM 모델 시험·GPU 연구의 구성 근거·관측 시각·범위·미해결·이번 미확인을 구분합니다. [상시 운영 절차](../../operations/always-on.md)는 대상 선택→구성·기동·준비·기능·자동작업 확인→실패 보존·복구→같은 검사 재확인을 안내합니다.

Docker 공식 운영·시작 순서·재시작 정책과Google SRE 모니터링 원문4개를 확인·다운로드했습니다. [근거 대조](../../../../program/research/wiki_review_2026-10-11/w18-evidence-v6.md)에 원문 URL·적용 판단·로컬 코드 근거를 구분했습니다. 원문·회수 시각·SHA256은 [다운로드 목록](../../../../program/research/wiki_review_2026-10-11/references/w18/sources.json)에 있습니다.

현재 API `/health`는 정적 응답입니다. 공개 worker는 원 스크립트 직접 호출 뒤60초 대기이고 로컬tick heartbeat·guard 경로와 다릅니다. worker healthcheck도 비활성입니다. 따라서 준비 검사·회차 계측·지연 경보의 추가 구현·배포는 완료로 표시하지 않았습니다. Compose의 종료 복구와 unhealthy 표시·응답 불능 복구도 구분했습니다. 고객 알림과 개발자·QA 장애 알림은 별도입니다.

Claude Sonnet5.5에는 비밀값 없는 설계 요약을 두 차례 보내 검토했습니다. [1차](../../../../program/research/wiki_review_2026-10-11/claude-review/commerce-response-v5.md)·[후속](../../../../program/research/wiki_review_2026-10-11/claude-review/commerce-w18-response-v6.md). 원격 코드 검토가 아니라 요약 설계 검토입니다. 실제 코드·시험으로 뒷받침되지 않는 확대 추정은 채택하지 않았습니다.

## 백업·남은 범위

[변경 목록](../../../../program/research/wiki_review_2026-10-11/commerce-change-manifest-v5.json)에 파일별 수정 전 SHA256·백업·수정 후 SHA256을 남겼습니다. [과거 문서 목록](../../../../program/research/wiki_review_2026-10-11/commerce-doc-archives-v5.json)은74개 원문 보존본을 연결합니다. 원문 바이트는 각 파일 옆 `_backup/<시각>_travel-commerce-cleanup/`에 있습니다. 역사 MCP·시험 원본은 [legacy](../../../legacy/commerce_cleanup_2026-10-11/)에 있습니다.

같은 초에 같은 파일을 두 번 고쳐 중간 백업2개가 덮인 것을 해시 검사에서 발견했습니다. 보존 원본과 기록된 수정식으로 중간판을 재구성했고 **수정 전 기대SHA256과 정확히 일치**함을 확인했습니다. 복구 경로·방식은 변경 목록의recovery에 명시했습니다. 이후 산출물 백업 경로는 충돌하지 않게 구분합니다.

문서 작성 표준·링크·생성물 일치 검사는 별도 결과에 기록합니다. W13은 현재 실행 자료 전환과 관련 회귀, W18은 운영 문서 개정의 요청 범위에서 완료입니다. 현재read 도구 선언과실제 호출 경계의 후속 검토, 전체25개 검토 항목의 미확정 계약, 공개 배포의 실질 준비·회차 계측과 전체 제품 출시 검증은 별도입니다. 운영 자동화 공백을 문서 수정만으로 해결했다고 하지 않습니다.
