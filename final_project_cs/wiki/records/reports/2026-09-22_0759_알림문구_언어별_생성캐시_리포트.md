# 알림 문구의 언어별 생성 캐시 — 틀만 담고 값은 알림마다 채운다

- 날짜: 2026-09-22 07:59
- 담당: Claude
- 계획 근거: v11 §6-B · 결정 14 · wiki [`architecture/notifications.md`](../../../../wiki/architecture/notifications.md) 「언어」 절
- 상태: **완료** (시험 통과 · 일부러 깨뜨려 재확인)

## 1. 무엇을 했나 — 결론 먼저

안내 알림(②·③)을 **보낼 때마다 통째로 번역하던 것**을, **문구틀만 언어마다 한 번 번역해
담아 두고 값은 알림마다 채우는 것**으로 바꿨다. 같은 언어의 다음 안내는 모델을 부르지 않는다.

★**캐시에 담기는 것은 「틀」이다.** `{leave} 출발 — {title} ({leave}–{ends}).` 처럼 값 자리만
남은 문장이고, 시각·장소 이름·소요 분·일정 버전·계획서 링크는 **캐시 밖에서** 그 알림의 원값으로
채운다. 값이 채워진 완성 문장을 담았다면 값이 다른 두 알림이 같은 항목을 써서 **10:50 출발
안내에 11:50 이 나간다** — 그것을 구조로 막았고, 일부러 그렇게 고쳐 시험이 잡는지 확인했다(§4).

## 3. 어떻게 값이 섞이지 않나

통지 payload 가 세 칸을 같이 싣는다 — `text`(한국어 완성 문장, 화면·기록용) · `template`(틀) ·
`values`(원값). 셋은 같은 `Phrase` 에서 나와 어긋날 수 없다.

```
안내(②·③)   template + values 있음 → 틀만 번역 → (틀, 언어) 로 담음 → 값은 지금 알림의 것으로 채움
변경 통지(①) text 만 있음          → 매번 번역, 담지 않음   ← 매번 새로 생성되는 문장이라 재사용할 것이 없다
```

덧붙는 줄(다른 안·일정 버전·계획서 링크)도 안내에서는 **값 자리**로 뺐다. 틀에 박으면 알림마다
캐시 열쇠가 달라져 재사용이 0이 되고, 무엇보다 값이 틀에 섞인다. ①은 전처럼 그대로 박는다 —
문구가 한 글자도 안 바뀐다(기존 시험이 그것을 본다).

★**번역이 자리를 잃으면 버린다.** 이름별 **개수까지** 대조해 다르면 `PhraseSlotsLost` 를 올리고
캐시에 넣지 않는다. 그 뒤는 전과 같다 — 한국어 원문에 `[번역 실패 — 한국어 원문]` 을 붙여 보내고
`translation_failures` 를 센다(조용한 스킵 금지).

★**채우기는 한 번만 훑는다**(`re.sub` 한 번). 값마다 `str.replace` 를 돌리면 앞 값이 넣은 글자가
뒤 값의 자리로 읽힌다 — 시험 `test_a_value_that_looks_like_a_slot_is_not_substituted_again` 이 본다.

### 4.2 ★일부러 깨뜨려 본 결과 (요청 사항)

`phrase.py` 의 `localize()` 한 줄씩을 고쳐 두 가지로 깨뜨렸다. **둘 다 원복했고**
(`grep -n "일부러" app/infrastructure/notify/phrase.py` 0건), 원복 뒤 308/308 재통과했다.

| 깨뜨림 | 고친 것 | 결과 |
|---|---|---|
| **A — 캐시를 끈다** | `cached = None` 고정 | **6/15 실패.** 모델 호출이 4건 알림에 4회(기대 1회), 언어별 1회 기대가 3→5회, 파일 이어쓰기 실패 |
| **B — 완성 문장을 담는다** | 담을 때 `filled` 를 넣고 적중 때 그대로 반환 | **4/15 실패.** ★`test_two_notices_that_share_a_cached_template_keep_their_own_time_and_place` 가 잡은 실제 출력 — 15:00 출발 알림 자리에 `[zh-TW] 10:50 出發 — 2호선 잠실→성수 (10:50–11:15) … (일정 버전 2)` 가 나갔다. **틀린 시각·틀린 장소·틀린 버전이 한꺼번에 나간 판**이다 |

B 가 이 작업에서 막으려던 바로 그 사고이고, 시험이 그것을 잡는다.

### 4.3 배선 확인

`get_settings().notice_phrasebook_path` → `var/notice_phrasebook.json` 로 풀리고, 파일이 없을 때
`load()` 가 0 을 돌려준다. 안내 payload 의 칸이 `['template', 'text', 'values']` 로 나오고 틀에
값이 없는 것(`{stops}` 만)을 실행으로 확인했다. ★**실제 디스코드 발송은 하지 않았다** — 바깥함을
건드리지 않으려 발행자 구성까지만 확인했다.

## 6. 안 한 것 · 남은 것

- **캐시 파일은 저장소 하나에 하나다**(`var/notice_phrasebook.json`). 테넌트를 나누지 않았다 —
  담기는 것이 테넌트와 무관한 문구틀뿐이라 나눌 이유를 못 찾았다. 고객 값이 들어가면 그때는 나눠야 한다.
- **`load()` 는 깨진 파일에서 예외를 올린다**(조용히 넘기지 않는다). 그 경우 배달 루프가 선다 —
  파일은 우리가 쓰는 것이고 저장은 임시 파일 교체라 깨질 여지를 줄였지만, **「캐시 때문에 알림이
  안 나가는」 경우가 원리상 가능하다**. 운영에서 한 번이라도 나면 「읽기 실패는 빈 캐시로 시작하고
  세어 보고」로 바꿀 만하다 — 지금은 안 정했다.
- ③의 「어떻게 가나」 문구는 경로 수단 이름(`2호선 잠실→성수`)을 **값**으로 둔다. 고유명사라 옮기지
  않는 것이 규칙인데, 고객 언어로 읽을 수 있게 괄호 번역을 붙이는 것은 **안 했다**(그러려면 장소
  이름 번역을 따로 담아야 한다).
- DoD 와의 관계: 이 변경은 DoD 항목을 새로 통과시키지 않는다 — 안내 중복 0(DoD-26)·링크 최신
  (DoD-25)의 동작은 바뀌지 않았고, 시험으로 그대로임을 확인했다(tests/scenario 28건).
