# 최초 숙소 채움 뒤 같은 호텔 안 식사 후보 보존

2026-10-17 18:35 한국 시각. 매니저 통합의 추가 DB 검사 277건 중 3건이 실패했다. 두 체크인 시험은 최초 채움 뒤에도 미정 상태를 기대해 실패했고, 이름 없는 일반 호텔 항목의 후보 시험 한 건은 자동 채움 뒤 같은 호텔 안 식사 후보가 사라져 실패했다. 후자는 2026-10-07 사용자 결정의 기존 선택 기능이므로 기대값을 제거해 통과시키지 않는다.

`candidates.alternatives()`는 숙소·식사 후보 짝을 미정 상태 또는 식사 항목일 때만 붙였다. 일반 호텔 항목은 자동 채움으로 장소가 정해진 상태가 되면서 이 조건을 벗어났다. 원문의 일반 숙소 표현도 조건에 유지하고, 체크인~체크아웃 숙박 항목을 제외하는 기존 경계는 보존한다. 원문 일반 호텔의 최초 자동 채움 상태를 같은 HTTP 회귀 시험에서 명시한다. 실제 호텔 식당 존재를 생성하지 않으며 같은 호텔 이름의 선택 항목과 기존 미확인 안내를 유지한다.

공유 API 계약에 기존 선택 기능의 보존을 먼저 명시했다. 관련 소스·시험·문서는 수정 전에 격리 작업 폴더의 `_backup/2026-10-17_1835_lodging-meal-pair/`에 보존했다. 예약 값 보존과 두 체크인 시험의 새 초기 상태 검증은 커밋푸시 세션에서 별도로 통합 중이다. 최종 배포·모바일 화면 확인은 아직 남아 있다.
