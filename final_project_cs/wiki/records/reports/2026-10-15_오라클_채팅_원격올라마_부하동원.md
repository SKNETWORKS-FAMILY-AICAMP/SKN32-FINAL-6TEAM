# 오라클 서버 채팅 응답 개선 — 원격 올라마 연결과 부하 시 API 동시 동원

`[2026-10-15 사용자 지시]` ① 오라클 서버 모델 응답속도 개선 ② 오라클 서버가 ssh 로 등록된 서버의 올라마 모델로 돌게 ③ 올라마가 부하로 느려지면 API 를 같이 동원.

## 원인 (읽기 전용 확인, 2026-10-15)

- 오라클 서버는 2코어 CPU 에서 모델(`e4b_qat_q40.gguf`)을 직접 돌린다. 같은 해석 지시문을 GPU(x600 서버)는 5~7초에 처리한다(기존 실측, [채팅 모델 자리](../../operations/current-state.md) 참고). 오라클 CPU 는 기존 측정에서 분 단위였다.
- 오라클 서버 환경 파일에는 서버용 OpenAI 키가 없고(`ACOP_LLM_FAILOVER_ENABLED=false`) 채팅은 전부 오라클 CPU 모델이다. 루나를 쓰는 곳은 x600 서버다.
- 오라클 → x600 서버는 사설망이라 직접 못 닿는다. 모델용 GPU 서버(공인 주소)는 오라클에서 직접 닿는다.

## 바꾼 것 (로컬 작업 폴더, 커밋 안 함)

| 영역 | 파일 | 내용 |
|---|---|---|
| 부하 동원 | [llm_failover.py](../../../app/infrastructure/llm_failover.py) | 한 올라마에 진행 중 호출이 `llm_overflow_max_inflight` 이상이면 줄 서지 않고 바로 다음 경로(API)로. 올라마가 `llm_overflow_hedge_seconds` 안에 못 답하면 API 를 병렬로 같이 호출해 먼저 온 쓸 만한 답을 쓴다. 호출 상한·서킷은 그대로. 둘 다 0(꺼짐)이 기본 |
| 설정 | [settings.py](../../../app/core/settings.py) | `ACOP_LLM_OVERFLOW_MAX_INFLIGHT` · `ACOP_LLM_OVERFLOW_HEDGE_SECONDS` |
| 채팅만 원격 | [ollama_adapter.py](../../../deploy/arm/ollama_adapter.py) · [compose.yml](../../../deploy/arm/compose.yml) | `REMOTE_CHAT_URL` 이 있으면 `/api/chat` 만 원격 올라마로 보낸다. 임베딩은 오라클 로컬 유지. 모델 이름 변환, `keep_alive` 미전달, 응답 검사(빈 답·잘린 답·깨진 JSON → 502)는 로컬 경로와 같고 원격 실패 시 느린 CPU 모델로 몰래 바꾸지 않는다 |
| 설치 | [setup_oracle_model_gpu.sh](../../../deploy/arm/setup_oracle_model_gpu.sh) · [connect_gpu_ollama_tunnel.sh](../../../deploy/arm/connect_gpu_ollama_tunnel.sh) | 새 모델용 GPU 서버에 올라마·학습 E4B 설치, 오라클 → 그 서버 터널(길 하나만 허용하는 전용 열쇠 + 자동 재연결 서비스) |

## 시험

- mock 서버 시험(가짜 올라마·가짜 API): `test_llm_failover.py` 63/63, 인프라·구조 단위 254/254, 어댑터 18/18. 계약 시험 1건(`test_active_prompts_are_the_deployed_set`)은 이번 변경과 무관한 기존 실패(DB 에 프롬프트 미등록).
- 실서버 확인: **안 했음.** 터널·올라마 설치·오라클 설정 변경 모두 미실행.

## 남은 일 (승인·실행 대기)

1. 사용자가 PC 에서 `setup_oracle_model_gpu.sh` → `connect_gpu_ollama_tunnel.sh` 실행. 자동 권한 검사가 열쇠 등록(`authorized_keys` 추가)과 서버 간 파일 복사를 막았다.
2. 오라클 서버 설정: 어댑터·compose 교체, `REMOTE_CHAT_URL`(터널 주소)·`REMOTE_CHAT_MODEL`, `ACOP_LLM_FAILOVER_ENABLED=true`, 서버용 키(사용자 승인: x600 서버 키 복사), 오라클 몫 일·월 호출 상한, 동시 동원 설정. 코드는 develop 반영 전이라 오라클 서버가 새 판을 받으려면 commit 세션 경유가 필요하다.
3. 적용 뒤 실제 응답 시간을 전·후로 잰다(같은 질문 · 교대 측정).

## 한계

- 모델용 GPU 서버는 RunPod 컨테이너라 다시 시작되면 올라마가 꺼진다(`/root/start_ollama.sh` 로 재기동). 그 사이는 API 가 대신한다.
- 오라클 서버의 무료 서버 유휴 회수 기준(CPU·메모리·네트워크)은 모델을 밖으로 옮기면 CPU 사용이 줄 수 있다. 기존 반복 시험 작업이 이를 채우는지는 적용 뒤 확인한다([arm-serving-queue.md](../../operations/arm-serving-queue.md)).
