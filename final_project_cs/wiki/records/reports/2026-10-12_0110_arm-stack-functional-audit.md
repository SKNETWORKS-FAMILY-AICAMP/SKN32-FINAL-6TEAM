# Oracle ARM 구성과 실제 기능 점검

[실측] DB·FastAPI·웹·작업자·앱 전용 모델·임베딩 구성은 가동 중입니다. 관광지·식당 검색과 후보 반환도 동작합니다. 다만 일정 접수의 장소 오연결, 검색 자료 미구축, 일부 외부 연결 미설정과 긴 채팅 지연이 확인되어 기능 전체 정상으로 판정하지 않습니다.

관측 창은 **2026-10-12 00:58~01:09 KST**입니다. 이 시각 밖의 지속 가동을 보장하는 결과가 아닙니다. 실제 Oracle ARM 구성 조회·DB 읽기·인증된 HTTP 요청과 기존 합성 여행 반복 시험의 원본을 사용했습니다. mock 서버 시험은 수행하지 않았습니다. 실서버 확인은 수행했으며 아래 범위로 제한합니다.

| 항목 | 판정 | 확인한 분자/분모 |
|---|---|---|
| 핵심 구성 실행 | 가동 | 6/6 = 100% |
| 관광지·식당 검색 및 대체 후보 반환 | 통과 | 4/4 = 100% |
| 이동 계산·접수 지도 경로 | 통과 | 2/2 = 100% |
| 새 합성 일정의 장소 종류 연결 | 오연결 발견 | 2/3 = 66.7% |
| 최근 완료 반복 시험의 채팅 | 응답·지연 미해결 | 4/4 = 100%, 50.98~59.50초 |
| 외부 알림 | 설정 누락·실패 누적 | 관측된 82건 모두 dead_letter |

분모는 이번에 확인한 구성·요청·합성 일정 항목 수입니다. 전 제품 기능 수나 독립 정확도 평가 문항 수가 아닙니다. 실패한 장소 연결 1건도 3건의 분모에 포함했습니다. 반복 시험은 같은 합성 여행과 대화 이력을 재사용하므로 독립 정확도 표본으로 합산하지 않습니다.

## 실행 구성

[실측] API와 작업자 이미지는 `tripilot-arm-api:c4f5c3cb2944`, 웹은 `tripilot-arm-web:c4f5c3cb2944`, DB는 `pgvector/pgvector:pg17`입니다. DB는 PostgreSQL 17.11 ARM64이며 연결 준비와 실제 조회가 성공했습니다. API·웹·모델 연결기의 준비 검사도 성공했고 작업자는 감시 회차를 완료했습니다. 앱 전용 모델·임베딩 프로세스와 작업 대기열도 실행 중입니다.

현재 앱 모델은 Gemma-4-E4B QAT Q4_0 배포 원본이며 **우리 자료 추가 학습 없음, 개발사 학습·QAT 있음**입니다. 실행기는 llama.cpp와 Ollama 호환 연결기입니다. 모델 계보와 이전 지연 계측은 [직전 원인 진단](2026-10-12_0038_arm-latency-root-cause.md)을 따릅니다. 이번 점검은 모델 채택 평가가 아닙니다.

[실측] CD 타이머는 실행 중이고 최근 실행 결과가 성공입니다. 일회성 CD 서비스의 `inactive`는 완료 후 상태입니다. 과거에 종료된 유한 시험 컨테이너와 옛 실패 작업을 현재 핵심 구성 장애로 합치지 않았습니다. 실제 브라우저의 새 루트 페이지 진입도 렌더링되었습니다. Oracle ARM 내부의 단순 HTTP 요청은 Cloudflare 403/1010을 받아, 이를 전체 웹 접속 장애로 판정하지 않았습니다.

## 실제 기능과 결함

### DB와 검색

[실측] 장소 목록 7,996건 모두 좌표가 있습니다. 별도 요식 자료 `dn_place`는 1,228건, 공통 장소 표의 dining은 1,226건으로 서로 다른 표의 집계입니다. `dn_place` 상태는 active 86·closed 46·unknown 1,096건이며, unknown을 실제 폐업이나 현재 영업으로 단정하지 않습니다.

[실측] `place_embeddings`, `knowledge_chunks`, `safety_shelters`는 각 0건입니다. 임베딩 프로세스 준비 검사 성공을 벡터 검색 자료 구축 완료로 표현하지 않습니다. 영업시간 관련 자료는 `catalog_hours` 1,248건, `dining_hours_rule` 8,540건입니다.

[실측] 관광지 검색 8개·대체 후보 3개, 식당 검색 8개·대체 후보 3개가 반환됐습니다. 식당 검색은 Kakao, 식당 대체 후보는 연결된 장소 자료를 사용했습니다. 후보의 설명은 문구틀로 반환되어 이 결과를 LLM의 추천 문장 품질 증거로 쓰지 않습니다. 최초 검색 4회는 검사 도구가 화면 표시 ID를 전송해 422였고, 계약상의 UUID로 수정한 4회가 모두 성공했습니다. 최초 실패 기록도 보존하며 제품 검색 실패율로 계산하지 않습니다.

### 일정 접수의 장소 오연결

[실측] 별도 합성 접수 1건에 경복궁 관람·광화문 근처 한식 점심·국립민속박물관 관람 3항목을 넣었습니다. 두 관광 항목은 연결됐지만 **식사 항목을 관광지 광화문에 연결하고 유지 가능한 상태로 판정**했습니다. 식사 항목의 `kind=dining`과 연결 장소의 `kind=activity`가 다릅니다. “가게 이름이 없어 광화문으로 잡았어요”라는 설명도 반환됐습니다.

이 재현으로 확인한 결함 지점은 처음 일정을 읽고 장소를 연결하는 단계입니다. DB 전체 비어 있음이나 모델 연결 단절로 설명할 수 없습니다. 현재 로컬 장소 연결 파일과 실행 중 파일의 해시가 달라, 로컬 코드 검토만으로 실행 중 세부 원인을 확정하지 않았습니다. 고객 여행을 수정하지 않았고, 합성 접수를 여행으로 등록하거나 후보를 적용하지 않았습니다.

### 이동·채팅·알림

[실측] 이동 계산 1회가 경복궁에서 광화문광장까지 도보 약 990m·16분을 반환했습니다. 이는 추정 경로이며 실제 교통 상황 검증이 아닙니다. 합성 접수 지도는 경로 2개를 반환했습니다. 위험 조회는 HTTP 성공이지만 검사 대상 0개여서 실제 위험 탐지 성공으로 세지 않았습니다. 변경 적용·되돌림·실제 예약은 이번 범위에서 검증하지 않았습니다.

[실측] 최신 완료 반복 회차는 01:02:42 KST에 계약·합성 답변 11/11을 통과했습니다. 채팅 4개의 지연은 59.50·50.98·59.46·53.57초입니다. 같은 여행·이력 재사용 결과이며, 첫 질문 지연이나 독립 보류 정확도를 대표하지 않습니다. 모델 응답은 확인됐지만 속도 문제는 남아 있습니다.

[실측] Oracle 실험 환경에서 Google 연결값이 빠져 작업자가 새벽 요식 확인을 건너뛰고 있습니다. Discord 웹훅도 설정되지 않아 `trip.notice` 82건이 각각 3회 시도 후 실패 상태입니다. 최근 실패 시각은 **2026-10-11 22:06:31 KST**이며, 이번 점검 중 새로 생긴 82건이라는 뜻이 아닙니다. 다른 환경의 키를 복사하거나 외부 알림을 재전송하지 않았습니다.

## 남은 작업과 판정 경계

1. 식사·활동 종류가 다른 장소를 확정하지 않도록 실행 중 장소 연결 경로를 대조하고 회귀 시험 후 반영합니다.
2. 장소 벡터·지식·안전 자료의 필요한 범위와 적재·조회 경로를 점검합니다. 현재 DB 규칙 검색 성공과 전체 RAG 준비를 구분합니다.
3. Oracle 실험 환경의 새벽 확인·외부 알림 설정과 실패 회수 절차를 정합니다. 공유 API 사용량과 외부 발송 영향을 확인한 뒤 변경합니다.
4. 상주 모델의 입력 처리·생성·경쟁 시간을 계속 분리하고, 최소 수정이 다음 CD 이미지에도 보존되도록 검증합니다. 10초 응답은 아직 달성하지 않았습니다.

이 문서는 구성·기능 점검 결과입니다. 제품 전체 통과·상용화·실서비스 배포 완료 판정이 아닙니다.
