# 차량 회전 제한 파일의 내용 교체를 놓치던 결함을 수정했습니다

차량 경로 계산이 갱신된 회전 제한을 다음 요청부터 다시 검사합니다. 파일 크기와 수정시각이 같아도 새 내용이면 반영하고, 손상되거나 도로자료와 맞지 않으면 오류를 냅니다. 내용이 같은 파일 교체는 기존 결과를 유지합니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 신규 결함 검사 | 통과 | 5/5건 = 100% |
| 관련 회귀 검사 | 통과 | 41/41건 = 100% |
| 보유 서울 경로 교대 재생 | 일치 | 8/8회 = 100% |
| 다른 기존 파일 보존 | 일치 | 409/409개 = 100% |

## 원인과 수정

기존 [회전자료 적재 코드](../../../app/domains/travel_ops/instances/mobility/engine/turn_restrictions.py)는 크기·수정시각만 비교했습니다. 원자적 파일 교체 후 원래 시각을 보존한 개발 재현에서 정상 규칙 변경을 놓쳤고, 손상 JSON·다른 그래프 해시·잘못된 방향 관계도 옛 캐시로 통과시켰습니다. 수정 전 신규 5건 중 4실패·1통과였습니다. [수정 전 JUnit 원문](../evidence/2026-10-10_0311_차량회전자료_내용갱신/before-v1.xml)·[재현 명령](../evidence/2026-10-10_0311_차량회전자료_내용갱신/before-v1-run.json).

이제 차량 요청마다 회전 파일의 바이트를 한 번 읽고 SHA256으로 내용을 비교합니다. 변경 시 비교했던 그 바이트를 파싱하고 기존 그래프 결합·회전 관계 검사를 거칩니다. 내용이 같으면 기존 테이블을 재사용합니다. 약 21만 바이트(211,626바이트)의 파일 읽기·해시 비용이 요청마다 추가되며 실제 요청 지연은 측정하지 않았습니다. 큰 도로 그래프는 같은 회전 내용에서 재해시하지 않습니다.

[Python 공식 hashlib 문서](https://docs.python.org/3/library/hashlib.html)의 바이트 입력 SHA256을 사용했습니다. [OSM 회전 관계 문서](https://wiki.openstreetmap.org/wiki/Relation:restriction)의 금지·강제 회전 의미와 보행자·조건부 범위는 유지합니다. 새 탐색·예측 논문 알고리즘이나 미지원 복합 제약을 추가한 변경은 아닙니다.

## 검증과 제품 경로

실제 차량 경로는 GraphRouter.route → 회전자료 load → 들어온 유향 간선을 구분하는 기존 탐색으로 이어집니다. CarService는 이 경로의 거리·시간·회전 적용 근거를 기존대로 소비합니다. 공개 고객 JSON이나 운영 정책 수치는 바꾸지 않았습니다.

신규 5/5와 기존 36/36을 합친 관련 41/41 통과입니다. 신규 5건은 정상 규칙 변경, 손상 JSON, 그래프 해시 불일치, 잘못된 방향 관계, 동일 내용 교체입니다. 기존 시험은 유향 회전 탐색과 별도 구현의 최단거리 대조, 부분 출발·도착, 도보·자전거 분리, 파일 삭제·손상 등을 포함합니다. [새 시험 코드](../../../tests/unit/travel/mobility/test_turn_policy_content_reload_v1.py)·[명령](../evidence/2026-10-10_0311_차량회전자료_내용갱신/after-v1-run.json)·[로그](../evidence/2026-10-10_0311_차량회전자료_내용갱신/after-v1.log). Ruff는 변경 코드와 새 시험 2개 파일에서 통과했습니다.

보유 서울 도로자료의 좌표 2쌍을 고정하고 백업 코드 A·수정 코드 B·B·A로 8회 재생했습니다. 거리·시간·좌표열·간선·붙임 선택 근거를 포함한 응답 전체가 조건별로 같았습니다. 경로 거리는 각각 10,184.1m와 1,468.71m이며 적용 관계는 기존 2,487개입니다. 이 재생은 자료가 바뀌지 않은 경우의 결과 보존 검사이며 독립 웹 정확도나 실제 통행 검증이 아닙니다. [좌표·해시·재생 원문](../evidence/2026-10-10_0311_차량회전자료_내용갱신/real-data-replay-v1.json). 그래프 폴더의 기존 파일 6/6개 해시도 유지했습니다.

## 보존과 남은 작업

직전 완료본 해시 411개 중 403개는 같고, 다른 작업의 코드·설정 8개 변경을 이번 시작 기준으로 보존했습니다. 이번에는 회전자료 적재 코드 1개와 wiki를 수정하고 시험·기록을 새로 만들었습니다. 허용한 두 파일을 제외한 409/409개 시작 해시가 동일합니다. [보존 검사](../evidence/2026-10-10_0311_차량회전자료_내용갱신/preservation-v1.json)·[코드 수정 전 백업](../evidence/2026-10-10_0311_차량회전자료_내용갱신/backup-manifest-v1.json)·[결과 기록 전 백업](../evidence/2026-10-10_0311_차량회전자료_내용갱신/publication-backups-v1.json)·[결함 상태](debugs/2026-10-10_0311_차량회전자료_내용갱신.md).

실시간 대체 정보는 [AREX 공식 페이지](https://www.airportrailroad.com/train/normal/live)의 정적 본문을 열었지만 브라우저 초기화와 공개 HTML 추가 조회가 실패해 열차ID·생성시각·목록의 역 귀속을 추가 확인하지 못했습니다. [GTFS 공식 운행 갱신 문서](https://gtfs.org/documentation/realtime/feed-entities/trip-updates/)의 정보 부재를 정시로 추정하지 않는 원칙을 다시 확인했습니다. AREX가 GTFS라는 뜻은 아닙니다. 그래서 근거 없이 자동 대체 연결을 추가하지 않고 다음 우선순위의 재현된 회전 결함을 수정했습니다.

제한 있는 API 호출·재시도는 각각 0회입니다. 공급자 공유 누적 사용량·잔여량·갱신 시각은 미확인으로 두고 호출하지 않았습니다. 일일 예비율 20%·운영 서비스 한도·예약 주기·알림 정책은 유지했습니다. [출처·실패·예산 기록](../evidence/2026-10-10_0311_차량회전자료_내용갱신/source-assessment-v1.json).

전체 21개 기능 분류는 조건부 사용 3개·개선 필요 9개·추가 검증 9개이며 완료율이 아닙니다. [시각화 v51](assets/2026-10-10_mobility_readiness_v51/mobility-readiness.html)·[기능별 기존 근거](assets/2026-10-10_mobility_readiness_v51/readiness-catalog.json). 브라우저 렌더링은 도구 오류로 미확인이고 HTML 구조·로컬 연결 대상은 검사했습니다.

회전 파일을 읽은 뒤 탐색 중 교체하는 경우, 도로 그래프 자체를 같은 크기·수정시각으로 바꾸는 경우, 복잡한 유턴·시간/차종 예외는 이번 해결 범위 밖입니다. 실시간 대체 소스의 식별·출발 연결, 1.2km 정책 안 새 웹 대조, 혼합 운임·누락 경로와 실운행 검증도 계속 남습니다. 커밋·푸시·배포·외부 메시지는 하지 않았습니다.
