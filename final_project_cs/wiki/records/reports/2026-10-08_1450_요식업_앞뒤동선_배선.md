# 요식업 앞뒤 동선 검사 배선

## 해결됨 (2026-10-08) — 누락 배선

요식업 낮 감시·다른 식당 추천·완화 후보에 기존 앞뒤 일정 계산을 연결했고, 현재 위치 추천은 걷는 시간을 실제 입장 시각에 반영한다. 코어 TeamTask/TeamResult 계약과 동선 계산기의 기존 판정 규칙은 바꾸지 않았다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 계산 배선 | 완료 | 4/4 = 100% |
| 관련 실행 검증 | 통과 | 43/43 = 100% |
| 실시간 교통·배포 확인 | 안 했음 | 0/1 = 0% |

## 수행

사용자 2026-10-08 지시의 「구현된 요식업 앞뒤 동선 검사를 연결」 범위다. D-CS-013의 컴포넌트→팀 직접 import 금지를 유지했다. 이동 계산기는 `components/team_hooks/legs.py`로 주입받는다.

- `app/domains/travel_ops/components/itinerary/itinerary_changes.py`: `plan_dining_disrupted`, `plan_fresh_alternate`, `relaxed_options`에 `meal_route(items, meal, leg=_leg_engine(trip))` 연결. 현재 위치 `plan_nearby`는 `items`를 받아 다음 예정 장소를 선택하고, 현재 좌표에서 후보까지 걷는 시간을 입장 시각에 더한다. 식사 후 다음 일정까지 기존 MealRoute로 검사한다.
- `tests/unit/travel/test_dining_route_connections.py`: 신규 9건. 주입 함수만 사용해 API 자원·키·DB 없이 검증했다.
- 호출부 `trip_messages.py`에서 `items=items`를 전달하는 한 줄은 통합 담당자가 변경한다. 이 전용 작업에서는 해당 파일을 쓰지 않았다.

## 백업과 기존 변경 보존

수정 전 원본은 [같은 폴더 백업](../../../app/domains/travel_ops/components/itinerary/_backup/2026-10-08_요식업동선연결/itinerary_changes.py)에 보존했다. SHA256는 `EC4B9D2677F1D9B82DF5EB6F06DE84A63E59A73E57A0A052CBF8C46DC64237CB`.
원본에 이미 있었던 TYPE_CHECKING·늦음/가게 앞 신고/새벽 동선 배선은 그대로 유지했다. 이 전용 작업의 diff는 백업 파일과 새 파일의 비교로 분리할 수 있다.

## 검증

관련 시험 43/43 = 100%, 변경 코드·시험 린트 2/2 파일 통과. [재현과 실제 출력](../evidence/2026-10-08_1450_요식업동선연결.md).
전체 제품 검사·고객 화면·x600 서버 응답은 이 작업에서 확인하지 않았다. 커밋·푸시·배포도 실행하지 않았다.

## 그대로 남은 판정 범위

- 기존 MealRoute는 앞 일정 이동 시간을 **순위**에 반영하고 앞 일정 출발→식당 도착 지각으로 탈락시키지는 않는다.
- 다음 일정은 원래 식당 대비 **추가 지각**을 막는다. 현재 위치 추천은 식사 없이 현재 위치에서 곧바로 다음 일정으로 갔을 경우를 기준으로 쓴다(`planned_end=at`).
- 먼 다음 일정의 대중교통은 원래 기준점과 상위 3개 후보만 기존 이동 계산기로 재측정한다. 계산기 미등록/실패/측정 불가 시 기존 도보 어림을 유지한다. 이 배선만으로 모든 후보의 실시간 교통 검증을 보장한다고 말할 수 없다.
- 현재 위치→식당 구간은 도보 거리의 어림값이다. 현재 위치의 원 좌표는 저장하지 않는다. 외부 영업 데이터의 신선도·SNS·감시 주기는 별도 정책이며 이번 작업에서는 변경하지 않았다.
