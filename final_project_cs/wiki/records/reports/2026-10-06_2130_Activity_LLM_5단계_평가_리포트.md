# Activity LLM 5단계 — 골든셋 평가 리포트

## 결론

원문을 해석하는 네 판정에서 **LLM 정확도는 0.987(154/156 관측, 95% CI [0.962, 1.000])이고, 규칙은 0.462(24/52 항목, CI [0.327, 0.596])다.** 차이는 +0.526(CI [0.391, 0.654], 짝지은 52항목)이다. 위험한 오답(확정 값인데 틀림)은 LLM 2/156, 규칙 13/52다.
다만 **라벨은 작성자(Claude)가 달았고 사람이 검토하지 않았다.** 프롬프트를 쓴 사람이 골든셋도 만들었으므로 이 수치는 낙관 쪽으로 기울었을 수 있다. 전환 판단에 쓰기 전에 사람 검토가 필요하다.
웹 판정(실시간 운영 상태)은 정확도를 재지 않았다(라벨 없음). 회차 간 일관성이 3/8 항목으로 낮고, 분당 한도(429)에 자주 걸렸다.
평가 중에 **운영 중인 규칙의 결함**도 찾았다. 정기휴무 정규식이 실제 원문 「매주 X」 309건 중 307건을 놓친다(결함 리포트 별도).

실행 조건: gpt-5.4-nano · effort low · temperature/seed 없음 · 프롬프트 `activity_judge.*.v1` · 골든셋 sha256 `5a0c98e5…` · 반복 3회 · 항목 단위 군집 부트스트랩(n=10000, seed=7). 원문은 [evidence](../evidence/2026-10-06_액티비티_LLM_5단계_평가_실측.md)에 있다.

- 규칙은 결정적이라 항목당 한 번만 센다(분모 = 항목 수). LLM 은 관측마다 센다(분모 = 항목 × 3).
- 정확도 1.000 의 CI 는 부트스트랩 특성상 [1.000, 1.000] 으로 나온다. 표본이 작아(10~14항목) 실제 불확실성을 반영하지 못한다. 그래서 표에 적지 않았다.
- 실패 지표: LLM 호출 실패 0/156, 근거 검증 탈락(`llm_uncited`) 0/156.
- 지연(원문 해석 판정, 웹 없음): p50 1,708ms · p95 3,065ms. 비용은 호출당 평균 $0.000294(추정).

### LLM 이 틀린 곳

- **closure-06** (「매주 토요일~일요일 / 법정공휴일」, 10/9 한글날): 3회 중 2회 `not_closed`(위험한 오답), 1회 `unknown`. 「법정공휴일」 조건을 무시했다. 입력의 `is_public_holiday` 가 `null`(모름)이라 프롬프트는 `unknown` 을 요구한다.
  - 원인 후보: 요청에 공휴일 여부를 넣지 않는다(`judge/requests.py`). 설정에 특일 API 키 칸(`holiday_api_key`)이 이미 있으니, 공휴일 여부를 채워 넣으면 이 유형이 줄어들 것으로 본다. 실측은 안 했다.
- 회차마다 답이 갈린 항목(일관성 4/52 불일치): closure-05 · closure-06 · closure-10 · disaster-06. closure-06 을 빼면 모두 허용 집합 안에서 「확정 값」과 「모름」 사이를 오갔다.

### 규칙이 틀린 곳 (지금 운영 동작)

- 휴무 위험한 오답 9/16. 「매주 월요일」(휴무 낱말 없음), 「토요일~일요일」(범위), 「매월 둘째 주」, 날짜 명시(1월 1일), 「점포별 상이함」을 모두 `not_closed` 로 확정했다.
  - 실제 CSV 에서 같은 결함을 셌다: [정기휴무 규칙이 「매주 X」 원문 307건을 놓친다](debugs/2026-10-06_1610_정기휴무_규칙이_매주X_원문_307건을_놓친다.md) (미해결).
- 재난문자 위험한 오답 4/12. 다른 지역의 위급재난은 막고, 같은 장소의 긴급재난 통제는 놓쳤다(등급만 본다).

## 실시간 운영 상태 (실행 B, 라벨 없음, 8항목 × 3회)

| 지표 | 값 |
|---|---|
| 호출 성공 | 16/24. 8건은 `RateLimitError`(429) |
| 성공한 16건의 판정 | open 8 · closed 1 · unknown 7 |
| 회차 간 일관성 | 3/8 항목. 429 로 「모름」이 된 회차도 불일치에 들어간다 |
| 지연(성공 건) | p50 15.7초 · p95 40.7초. 가드레일 45초에 가깝다 |
| 검색 횟수 | 성공 건 평균 약 2.8회 |
| 남은 출처 | 20건. 그중 게시일 없음 13건 |
| 비용 | 실행 B 합계 $0.517(추정). 성공 건당 약 $0.032 |

관찰한 것
- 근거 검증 탈락은 0건이었다. 출처는 모두 검색 목록과 일치했다.
- 부분 휴관을 다루기 어렵다. 서울식물원은 월요일에 온실만 휴관하는데, 3회 중 1회는 `closed`, 2회는 `unknown` 이었다. 서울대공원도 일부 시설의 임시휴관을 언급하며 판정이 갈렸다. 프롬프트에 「전면 통제만 closed」 기준을 더 분명히 할 여지가 있다.
- 정기휴무일(덕수궁 월요일)은 프롬프트대로 `unknown` 이었다. 정기휴무는 휴무 판정의 몫이다.

## 429 (분당 한도)

- 실행 A(동시 6): 실시간 24/24 실패. 실행 B(동시 1, 직후): 8/24 실패. 그 뒤 단건 점검 3회는 정상.
- 웹 검색을 끼면 호출 1건이 17k~30k 토큰이다. **운영 섀도(백그라운드 동시 2)에서도 몰리면 429 가 난다**고 봐야 한다. 지금은 `llm_error` + `RateLimitError` 로 기록되고 고객 응답에는 영향이 없다.

## 제안 (결정 필요)

1. **라벨 사람 검토**: `eval/activity_judge/build.py` 의 52개 라벨. 특히 허용 집합에 `unknown` 을 넣은 9항목.
2. **공휴일 여부를 요청에 채운다**(특일 API) — closure-06 유형의 위험한 오답을 줄인다.
3. **웹 판정 속도 조절**: 실시간 판정은 동시 1, 429 는 별도 코드(`llm_rate_limited`)로 센다, 재시도 간격을 둔다.
4. **정기휴무 규칙 결함 처리**: 결함 리포트 §5의 세 안 가운데 하나.
5. **전환 기준(계획서 §8)**: 아래 초안을 검토해 확정한다.

### 전환 기준 초안 (판정 종류별)

- 라벨을 사람이 검토했다.
- 골든셋에서 LLM 의 위험한 오답이 규칙보다 적고, 정확도 차이(LLM − 규칙) CI 하한이 0보다 크다.
- 운영 섀도에서 그 종류의 비교 가능 관측이 100건 이상이고, 불일치 표본을 사람이 검토해 LLM 이 맞은 비율이 규칙보다 높다.
- 웹 판정(`live_status`)은 라벨 셋과 429 대책이 생길 때까지 대상이 아니다.

이번 수치로만 보면 운영시간 · 실내외 · 재난문자가 첫 조건(골든셋)을 넘는다. 휴무는 closure-06 유형을 먼저 해결해야 한다.
