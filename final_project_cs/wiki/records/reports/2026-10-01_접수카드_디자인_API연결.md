# 접수 카드 디자인 및 API 연결

담당: Codex · 2026-10-01 · 기준 `role-manager` `878e709` + 미커밋 프론트 변경. 사용자 지시의 접수 확인 화면 디자인·기존 API 연결 범위다. 백엔드·개인 PC 설정은 변경하지 않는다.

## 발견 및 정정

- 저장 충돌 뒤 접수 재조회까지 실패하면 `query.error` 분기로 편집기가 사라져 초안이 소실될 수 있었다. 기존 조회값이 있을 때 편집기를 보존하고 최신 조회 실패를 별도로 표시하도록 수정. 새 회귀 시험 통과.
- 지도 창에서 React `autoFocus`만으로는 `showModal()` 이후 검색창 초점을 보장하지 못했다. 최초 추가 시험에서 **47/48 = 97.9%**, 실패 1건은 검색창이 아닌 다른 요소에 초점이 있는 문제였다. 창을 연 뒤 입력 요소로 초점을 옮기도록 수정했다. 재실행 중 시험이 지도 미설정 안내와 장소 검색 실패 안내를 모두 선택해 실패한 것은 선택자를 좁혀 정정했다. 최종 접수 시험 **6/6 = 100%** 통과.
- 이전 수동 확인에서 취소 클릭의 처리 여부가 불확실했으나 재개 후 실제 화면 및 자동 시험에서 초안 취소·다시 열기 정상 확인. 제품 결함으로 확정하지 않는다.

- 카드별 오류로 재배치하면서 날짜 누락 항목만 있는 경우 기존 여행 첫날 일괄 입력이 숨겨질 수 있었다. 기본정보 영역 표시 조건을 보완하고 요청 본문 회귀 시험을 추가했다.

## 변경 범위

- `frontend/apps/web/src/features/intake-review/`: 카드 편집기·모델·모델 시험 분리, 일차·상태 요약·실제 지도·편집 초안과 충돌 처리, CSS 적용. 기존 편집기 제거로 사용하지 않는 CSS만 정리.
- `frontend/apps/web/mockups/`: 사용자 지정 장소 카드 2차본과 인덱스.
- `frontend/apps/web/tests/mock-api/`: 기존 흐름의 버튼명·카드 펼치기 반영 및 접수 회귀 시험 6개 추가.
- `frontend/apps/web/tests/real/real-server.spec.ts`: 등록 버튼명 반영. 전체 실서버 자동 시험은 실행하지 않았으며 별도 수동 브라우저 흐름으로 확인.
- 앱 README, [연동 상태](../../external/web-screen-api.md), 이 기록과 [검증 근거](../evidence/2026-10-01_접수카드_검증.md).

## 검증 결론

[실측] `npm run check` 통과: 린트·타입 검사, 단위 시험 **134/134 = 100%**, 실제 연결 설정 프로덕션 빌드 성공. 개발 서버와 별도 빌드 디렉터리를 사용했고 Next가 자동 추가한 tsconfig 변경은 되돌렸다. 이후 날짜 누락 표시 보완도 모방 서버 프로덕션 빌드·추가 시험에서 확인했다.

[실측] 모방 서버 기존 브라우저 시험 **43/43 = 100%**, 최종 추가 접수 시험 **6/6 = 100%**. 전체 시험 후 실패 부분을 수정하고 관련 6개를 다시 실행한 결과이며 최종 소스로 49개를 한 번에 다시 돌렸다는 뜻은 아니다. 320·390px 편집기/지도 창 가로 넘침, Esc 초안 보존, 시간 역전, 취소, 422, 409 뒤 재조회 실패, 원본 ID와 판 보존을 포함한다.

[실측] 실제 로컬 서버의 새 테스트 계획에서 접수 → 제목·시간 저장 → 창덕궁 검색·저장 → 장소 없음 → 경복궁 복구 → 항목 제외 → 최종 등록 → 여행 관리 화면 도착 확인. API 로그는 이 테스트 접수에 GET 200 6건, edits 200 7건, confirm 200 1건을 기록했다. 등록된 일정은 2개다. 기존 사용자 계획은 조회와 화면 전환만 했고 저장하지 않았다. 지도는 실제 OSM 타일을 확인했다.

## 남은 범위

- 여러 장소 후보·주변 추천·별도 재검사 API는 [협의 항목](../../external/web-screen-api.md)에 남았다. 미지원 기능을 완료로 표시하지 않는다.
- 실제 휴대폰, Naver/Google 지도 인증, 실제 외부 API의 한도 초과는 이번 검증 범위 밖이다. 실패 화면은 모방 응답으로 검증했다.
- 이전 개발 문서에 적힌 `tests/contract/test_web_client_contract.py`는 이 기준 브랜치에 없어 실행 시 `file or directory not found / no tests ran`이었다. 해당 계약 시험 통과를 주장하지 않는다. 백엔드 파일은 변경하지 않았다.
- 현재 로컬 변경이며 커밋·푸시·병합 전이다. 검증된 프론트 변경과 개인 실행 환경 설정은 구분한다.
