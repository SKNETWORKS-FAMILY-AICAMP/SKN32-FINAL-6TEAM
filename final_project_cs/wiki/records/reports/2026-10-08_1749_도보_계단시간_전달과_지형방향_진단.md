# 도보 시간은 계단 전달과 지형 방향을 함께 고쳐야 한다

계단 시간 전달이 끊기는 결함을 확인했습니다. 그러나 기존 30쌍에서 계단 시간만 보존한 가상 계산은 ±5분 이내 구간을 늘리지 못했습니다. 지도 원본의 고도와 오르내림을 확보해 방향별 시간을 계산하는 후속 작업이 필요합니다. 이번 구현 변경은 **실제 도로 그래프의 판·출처 표시**에 한정했습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 기존 도보 구간 재계산 | 끝 | 30/30 = 100% |
| 지도 자료 판·출처 표시 수정 시험 | 통과 | 23/23 = 100% |
| 지형을 반영한 시간 구현 | 후속 작업 | 0/1 = 0% |

## 관측과 원인

기존 서울 도보 개발 표본 30쌍을 같은 좌표로 다시 계산했습니다. 기본 라우터는 실제로 `road_graph_v2`를 선택했고, 파일 전체를 읽어 421,482개 노드와 583,486개 간선을 확인했습니다. 간선 534,864개는 보행 가능, 5,911개는 계단 표시를 가집니다. 노드와 간선 전체에서 `ele`, `elevation`, `incline`, `slope`, `gradient` 칸을 가진 행은 각각 0/421,482 및 0/583,486입니다. 이는 **현재 그래프 파일에 고도·경사를 싣지 않았다**는 확인입니다. 원본 OSM 전체에 해당 정보가 없다는 뜻은 아닙니다.

[계산 흐름 그림](assets/2026-10-08_walk_diagnosis_v1/walk-time-flow.html)은 거리와 계단 시간이 어느 단계에서 분리되는지 보여 줍니다.

1. `GraphRouter._response`는 계단 구간을 평지 속도의 60%로 계산해 응답 시간을 만듭니다. 경로 선택은 계단 거리에 1.5배 비용을 주지만, 시간은 같은 거리를 약 1.667배로 계산합니다. 선택 비용과 안내 시간의 목적도 완전히 같지 않습니다.
2. `BikeRouter.route`는 거리와 시간을 함께 보존합니다.
3. `Planner._walk_net`은 거리만 반환합니다. 직접 도보와 가장 이른 도착 계산은 그 거리를 설정 속도 1.04m/s로 다시 나눕니다. 역·정류장 접근 계산 `_eff`도 거리만 전달합니다.

따라서 라우터의 기본 5km/h 시간을 그대로 붙이면 기존 1.04m/s 보행 기준까지 바뀝니다. 먼저 평지 시간·계단 시간·경사 시간·횡단 대기를 나눠 전달하는 계약을 정해야 합니다. 본 작업은 이 시간 계약을 수정하지 않았습니다.

## 기존 30쌍 결과

분모는 기존 새 100쌍 개발 자료 중 웹 도보 비교 값이 있는 짧은 구간 30쌍입니다. 정답은 웹에서 읽은 카카오 최단거리 안내 시간이며, 현장 보행 실측이 아닙니다. 기존 40쌍을 교체하지 않았습니다.

| 측정 | 현재 계산 | 계단 시간만 보존한 가상 계산 |
|---|---:|---:|
| 웹 시간과 ±5분 이내 | 15/30 = 50% | 15/30 = 50% |
| 평균 절대 차이 | 7.0375분 | 6.7817분 |
| 중앙 차이(우리−웹) | +0.2873분 | +0.7830분 |
| 중앙 차이 bootstrap 95% 구간 | −1.4734~+5.6163분 | −0.3610~+5.7810분 |

계단 구간이 있는 경로는 12/30 = 40%입니다. 가상 계산은 **미구현 진단**이며 `계단 거리 / 설정 보행 속도 × (1/0.6−1)`을 기존 시간에 더했습니다. 새 보정 계수를 학습하거나 장소별 시간을 맞춰 넣지 않았습니다. Bootstrap은 동일 30쌍, seed 20261008, 2,000회 재표집입니다. 중앙 차이 구간이 겹치므로 가상 계산이 일반적으로 우수하다고 확정하지 않습니다.

기존 저장 시간과 이번 같은 경로의 평지 시간 차이는 최대 0.000642분입니다(거리 소수점 반올림 차이). 계단 거리와 잔차의 Pearson 상관은 −0.4233이나, 30쌍의 탐색적 상관으로 인과나 보정 계수를 정하지 않습니다. 큰 잔차 중에는 계단이 없는 구간도 있어 경로·접근 연결 문제가 별도로 남습니다.

## 추가 웹 대조: 광화문 기념물↔N서울타워

아래는 주 세션이 네이버·카카오 브라우저에서 직접 조회해 기록한 값입니다. 각 제공자의 같은 장소 검색을 역순으로 바꿨습니다. 역방향을 독립 표본으로 추가하지 않았고, 기존 N063의 광화문역 근처 좌표와도 합산하지 않았습니다. 두 방향의 경로 형상이 완전히 같은지는 아직 입증하지 않았습니다.

| 웹 제공자·경로 | 기념물→타워 | 타워→기념물 | 시간 차이 |
|---|---|---|---:|
| 네이버 큰길우선 | 4.1km·82분 | 4.1km·76분 | 6분 |
| 네이버 계단회피 | 4.7km·92분 | 4.7km·78분 | 14분 |
| 네이버 추천 | 4.0km·101분 | 3.8km·97분 | 4분·거리도 다름 |
| 카카오 큰길우선 | 3.8km·82분 | 3.8km·71분 | 11분 |
| 카카오 최단거리 | 3.7km·83분 | 3.7km·71분 | 12분 |

원문은 로컬 자료의 [네이버 정방향](../../../../datasets/mobility/raw/kakao_golden/additional_web_2026-10-08_v1/naver-W01-walk.json), [네이버 역방향](../../../../datasets/mobility/raw/kakao_golden/additional_web_2026-10-08_v1/naver-W01R-walk.json), [카카오 정방향](../../../../datasets/mobility/raw/kakao_golden/additional_web_2026-10-08_v1/kakao-W01-walk.json), [카카오 역방향](../../../../datasets/mobility/raw/kakao_golden/additional_web_2026-10-08_v1/kakao-W01R-walk.json)에 있습니다. 원문 파일은 git 밖에 두었습니다.

Google 화면 URL의 공개 Plus Code 중심을 공식 [Open Location Code 알고리즘](https://github.com/google/open-location-code/blob/main/python/openlocationcode/openlocationcode.py)으로 풀어 별도로 로컬 경로를 계산했습니다. 출발은 (경도 126.976859375, 위도 37.5760125), 도착은 (126.988234375, 37.5511625)입니다. 네이버·카카오 출입구 좌표와 정확히 같다고 검증한 값은 아닙니다.

이 좌표에서 로컬 그래프는 양방향 모두 3,488.1m, 평지 계산 55.899분, 계단 442.296m, 계단 가산 4.725분을 냈습니다. 계단만 보존해도 약 60.624분이고 **방향 차이는 0분**입니다. 웹의 방향 차이를 지형만의 효과라고 단정할 수는 없지만, 현재 거리와 양방향 동일 비용만으로 그 차이를 재현할 수 없습니다.

## 실제 수정과 검증

`GraphRouter.info()`가 실제 v2 자료를 읽어도 v1과 2026-09-18 출처를 고정 표시했습니다. MANIFEST 버전과 `source_id`를 사용하도록 고쳐 실제 파일에서 `local:road_graph_v2` 및 `osm_road_graph_v2@2026-10-03`를 반환합니다. 그래프를 적재하지 않고 확인할 수 있습니다. 문서 주석도 v2 보행 전용 길 포함 여부와 남은 지형 한계를 구분하도록 고쳤습니다.

변경 파일은 [길찾기 본체](../../../app/domains/travel_ops/instances/mobility/engine/graph_router.py:173)와 [출처 표시 시험](../../../tests/unit/travel/mobility/test_graph_router_metadata.py)입니다. 원본 [백업](../../../app/domains/travel_ops/instances/mobility/engine/_backup/2026-10-08_1745_그래프출처표시/graph_router.py)을 먼저 만들었습니다. 그림 표기 정정 전 판도 [백업](assets/2026-10-08_walk_diagnosis_v1/_backup/2026-10-08_표기정정/walk-time-flow.html)으로 남겼습니다.

[검증 기록](../evidence/2026-10-08_1749_도보_계단시간_진단_검증.md)에 재현 방법과 실제 출력을 기록했습니다. 로컬 계산 시험 23/23 통과, 실그래프 장시간 회귀 2개는 이번 실행에서 선택하지 않았습니다. 외부 지도 경로 API 호출은 0회입니다. cs 프로젝트 서버 배포 확인은 하지 않았습니다.

## 후속 구현 순서

- 보행 시간 구성 항목을 전달하고, 직접 도보·접근 도보·가장 이른 도착이 같은 값을 쓰게 합니다. 경로 선택 비용과 안내 시간도 같은 목적에 맞춥니다.
- 고도 자료를 받아 경로를 따라 높이를 표본화하고, 방향별 상승·하강과 계단을 중복 가산하지 않도록 계산합니다. 후보 자료는 [USGS SRTM 안내](https://www.usgs.gov/centers/eros/science/usgs-eros-archive-digital-elevation-shuttle-radar-topography-mission-srtm)의 1 arc-second global이며, 검색 결과에서 내려받기 제공을 확인했으나 직접 원문 열기는 시간 초과, 실제 자료 내려받기는 아직 하지 않았습니다. 국내 고해상도 DEM은 국토지리정보원 공개 소개에 제시되지만 현재 다운로드 화면·서울 파일·이용 조건은 추가 확인해야 합니다.
- 같은 출입구·경로 종류를 고정한 평지·산지·하천·지하 연결 구간을 더 모으고, 방향을 교대로 조회해 검증합니다. 시간 보정으로 거리 오차를 덮지 않습니다.

정본 Mobility wiki 갱신과 종합 시각화 반영은 공유 파일 충돌을 피하도록 주 세션에 인계했습니다. 커밋·푸시는 하지 않았습니다.
