# 여행 초안 원문·전체 관문

2026-10-18 사용자 승인: DB 연결로 미완료였던 19건과 전체 DoD를 끝까지 실행하고 실패를 고친다. 여행 상세에 고객이 입력한 초안 원문을 추가하고 양쪽 매니저 반영·운영 배포·실제 화면 확인까지 수행한다.

## 착수·시험 DB

시작점은 양쪽 매니저 `cd21caa3823d00f4319ac6fe6b4d93a3ddbb7b84`다. 기존 격리 사본에서 새 작업 브랜치를 사용하며 공유 원본의 소스·데이터·Git 상태를 동기화하지 않는다. 별도 PostgreSQL 컨테이너·새 볼륨·시험용 계정·시험 DB를 만들었다. 고객 DB나 고객 행을 복제하지 않고 현행 SQL·프롬프트·합성 여행 자료만 넣었다. 연결 시 DB·계정이 시험용 이름인지 확인하는 실행기를 사용한다.

## 1차 결과

미완료 19건을 같은 시험 ID 그대로 실행해 **19/19 통과**했다. 계약·보안 전체와 전체 DoD는 진행 중이다. 이전 날짜 기록의 DB 제한을 지우거나 오늘의 통과로 덮어쓰지 않는다.

## 초안 계약·구현 계획

현재 `trip_intakes`와 `intake_sources.transcript`에 입력 원문과 여행 연결이 저장돼 있다. 기존 1판 계획은 등록된 구조화 계획이므로 원문과 별도 탭으로 보인다. 최초 등록 접수만 고르며 수정 접수를 원본으로 섞지 않는다. 관련 [관리자 계약](../../external/admin-screen-api.md)을 구현 전에 추가했다. 구현·공유 계약 검토는 이번 작업자가 맡으며 독립 검토 완료로 쓰지 않는다.

## 1차 원문 구현·계약·보안 시험

미완료 19/19에 이어 계약·보안 전체 **455/455 통과**했다. 초안 원문 API는 최초 접수·수정 접수 제외·장문/줄바꿈·파일명·원문 미보관·개인정보 가림·고객/테넌트 격리·운영자 권한을 포함해 **24/24 통과**했다. 원문 표시는 저장된 글을 그대로 읽는 별도 탭이며 1판 계획을 원문처럼 다시 만들지 않는다. 현재 관리자 운영 빌드와 전체 DoD는 진행 중이다.

실제 자료의 읽기 전용 집계에서 지정 여행 중 「내 여행」과 식사 여행의 원문이 각각 1개 보관돼 있음을 확인했다. 나머지 검증용 여행은 원문 접수가 보관되지 않은 경로다. 실제 원문 내용은 공용 문서에 싣지 않았으며 운영 화면 대조는 새 배포 뒤 수행한다.

## 화면·계층 검증 완료

관리자 운영 빌드·TypeScript·변경 파일 ESLint·기존 단위 **22/22**, 실제 Chrome mock 서버 **9/9**, 전체 아키텍처 **159/159**를 통과했다. 상세 화면 패턴을 유지하고 원문 탭을 추가했다. 375px·1280px 화면에서 4개 탭·초점·키보드 이동·오류 재시도·원문/받아쓴 글의 구분·HTML 비실행·긴 글과 줄바꿈을 확인했다.

전체 DoD는 로컬 실행에서 계속 진행 중이다. 시험 DB 조회 왕복이 실측 평균 158ms라 긴 DB 통합 시나리오가 느려, 현재 코드 사본과 별도 합성 시험 DB를 DB와 같은 기계의 운영 Python 3.12 환경에서도 실행했다. 두 실행 모두 운영 고객 DB·고객 행과 분리한다. 전체 DoD의 결과는 아직 판정 전이다.

## 전체 DoD 완주

현재 검증 소스 사본·고객 데이터 없는 별도 DB·배포 이미지의 Python 3.12 환경에서 `python -m scripts.verify_dod_v11`을 완주했다. **전체 26/26 = 100%, 미통과 0·미측정 0·시험 없음 0**, MVP 부분도 **18/18**이다. 검사 항목을 빼거나 성공으로 간주하는 변경 없이 원래 명령을 실행했다. 소스 사본의 압축 SHA-256은 `91c1cf013c39cc73c4b71d0fa544e03e22d9f3280750e190e83a12dba20edc21`이다. 계약·보안 455건에는 앞서 따로 재실행한 19건이 포함되므로 독립된 시험 수로 합산하지 않는다.

이전 DB 미완료 19건과 전체 DoD에 이제 미확인 항목이 남지 않는다. 제품 코드를 고치거나 시험 기준을 완화해서 통과한 것이 아니라, 독립된 정상 시험 DB와 필수 초기 자료를 준비해 실행했다. 원문 기능·관련 회귀 검증 후 양쪽 반영과 실제 화면 검증으로 이어간다.
