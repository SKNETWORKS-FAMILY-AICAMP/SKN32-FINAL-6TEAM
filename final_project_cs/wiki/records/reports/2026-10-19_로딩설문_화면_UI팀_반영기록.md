# 로딩 설문 · 활동 세부 코드 — UI 팀 브랜치에 반영할 화면 변경 (2026-10-19)

**한 줄**: cs 프로젝트 서버가 로딩 중 질문을 「계획서에서 못 얻은 것만, 상한 없이」 보내도록 바뀌었고, 활동 우선순위 세부 값이 관광 분류 일곱 코드가 됐으며, 빈 글 · 무관한 글은 모델 읽기 전에 돌려보낸다(빠른 거름). 화면은 이 저장소에서 고치지 않았다 — `[2026-10-19 사용자 지시]` **UI 팀이 자기 저장소 브랜치에서 작업**하므로, 그 작업이 올라오면 아래 목록을 그 브랜치에 반영한다.

- 계약(정본): [web-intakes.md 「설문 질문」](../../external/rest-endpoints/web-intakes.md) · 설계 [2026-10-19_로딩설문_읽은칸빼고_빈칸만묻기.md](../plans/2026-10-19_로딩설문_읽은칸빼고_빈칸만묻기.md) · 서버 구현 기록 [2026-10-19_로딩설문_빈칸만묻기.md](2026-10-19_로딩설문_빈칸만묻기.md)
- 서버가 바뀐 판: 원격 role-manager 반영 해시는 구현 기록 「반영」 줄에 적는다.
- ★서버는 이미 새 모양을 보낸다. 지금 화면은 `kind: single` 만 그리므로 **새 서버 + 옛 화면** 조합에서는 누구와 · 여유 두 문항만 보이고, 우선순위 · 실내외는 화면이 그릴 때까지 안 보인다(계약대로 그 문항만 건너뛴다 — 오류는 없다).

## 하지 않는 것(서버 결정 그대로)

- 「일정이 꼬이면」(`on_disruption`)은 로딩 질문에 다시 넣지 않는다 — 항로 지킴이 카드가 그대로 받는다.
- 덜 걷게 · 하루 시작/끝 시각 · 식사 제한 · 접근성 · 내국인 여부는 로딩에서 묻지 않는다.
- 로딩이 끝날 때까지 못 물은 문항을 확인 화면 「나중에 답하기」 카드로 잇는 일은 만들지 않는다(10-05 범위 변경 1).

## 확인 상태

- 서버: mock 서버 없이 시험 DB 로 단위 · e2e 시험을 돌렸다(구현 기록 「시험」). **실서버 확인(x600 서버의 cs 프로젝트 서버) · 배포는 하지 않았다.**
- 화면: 이 기록을 쓴 세션은 웹 코드를 고치지 않았다. 웹 시험(chrome 채널)도 돌리지 않았다 — 고칠 웹 코드가 없다.
