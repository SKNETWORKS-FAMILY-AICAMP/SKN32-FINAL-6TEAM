# 설문 여행자 구성 인원(`party_size`) — B안 (2026-10-20, ST4F-581)

**한 줄**: 시작 설문 여행자 구성 카드의 인원을 설문 계약 `TripSurvey.party_size`(1~4)로 서버에 보내고, 웹 접수 등록에서 여행 인원이 비었을 때만 쓴다(계획 확인에서 고친 값 > 계획서에서 읽은 값 > 설문). 로컬 시험 · 로컬 실서버 확인까지 했고 배포 · 독립 검토는 아직이다.

## 결정 · 담당

- `[2026-10-20 사용자 결정]` B안(서버 계약에 인원 칸) — A안(웹이 `trip.party_size` 를 고침)은 하지 않는다. 서버 쪽도 이번에는 UI · 검증 담당(이 작업)이 고친다(사용자 지시 「우리가 수정할꺼야」).
- 변경 담당: UI · 검증 담당(Claude 세션, 사용자 지시). 검토: **작업자 자체 검토만 — 매니저 · 설문을 쓰는 기능 담당의 독립 검토 대기**([개발 역할](../../../../wiki/delivery/roles.md) 「공유 계약을 변경하는 순서」 2).
- 영향: 설문 계약(`TripSurvey`, `extra=forbid`) — 판 `2026-09-24.v1` 은 올리지 않았다(선택 칸 추가). **이 칸을 모르는 옛 서버는 422 로 거절하므로 웹 · 서버를 같이 배포한다.** 직접 등록(`POST /v1/trips` · `/plan`)은 요청의 `party_size` 가 정본이라 설문 인원은 기록으로만 남는다.
