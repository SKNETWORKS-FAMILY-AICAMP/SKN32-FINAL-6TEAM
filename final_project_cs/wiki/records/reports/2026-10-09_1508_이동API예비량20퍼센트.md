# 이동 개선 예약 작업 API 예비량 20% 적용

이동 모듈 개선·재검증 예약 작업은 일일 제한이 있는 API마다 하루 한도의 최소 20%를 남기도록 지시를 저장했습니다. 호출 전 같은 키·프로젝트의 전체 사용량을 확인하고, 잔여량이 불명확하면 새 호출을 하지 않습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 기존 호출 제한 확인 | 끝 | 1/1 = 100% |
| 예약 작업 지시 갱신 | 끝 | 1/1 = 100% |
| 저장 결과 재조회 | 통과 | 5/5 = 100% |

분모 5는 저장된 지시·주기·대상 대화·활성 상태·이름의 대조 항목입니다. 제품 동작이나 API 사용률을 뜻하지 않습니다.

## 적용 기준

예비율 20%는 구체 비율을 지정하지 않은 사용자 요청에 따라 이번에 정한 작업 기준입니다. 예를 들어 실제 하루 한도가 1,000회라면 전체 누적 사용량 800회에서 이 예약 작업의 추가 호출을 멈추고 200회 이상 남깁니다. 매 6시간 실행마다 800회를 새로 주는 방식이 아닙니다.

실제 제한 단위·갱신 시간대와 다른 작업의 공유 사용량을 먼저 확인합니다. 실패·재시도·페이지·행렬 요소 등 공급자가 차감하는 단위도 예산에 포함합니다. 기존 제한이 더 엄격하면 더 작은 한도를 따르고 월 무료 한도·비용 상한도 유지합니다. 호출 직전에 공유 예산을 확보할 수 없거나 사용량 기록이 불완전하면 해당 API를 호출하지 않습니다.

80%에 닿으면 다음 공급자 일일 갱신까지 이 예약 작업의 추가 호출을 중단하며 키 교체나 자동 재시도로 우회하지 않습니다. 그동안 공식 웹, 허용된 보관 자료 재사용, 오프라인 검증으로 작업을 이어갑니다. 조회 전후 사용량과 잔여량은 비밀값 없이 근거에 남깁니다.

## 범위와 확인

기존 [카카오 수집 도구](../../../scripts/mobility/collect_kakao_car_golden.py)의 `DAY_SHARE = 0.8`과 호출 전 예산 확보, [공유 예산 도구](../../../app/domains/travel_ops/ports/data_sources/call_budget.py)의 일·월 공유 기록과 `share` 조건을 읽었습니다. 이번 변경은 automation-2의 작업 지시이며 운영 제품 코드·한도·6시간 주기·대상 대화·알림 정책은 수정하지 않았습니다. 모든 기존 API 호출 경로를 전역으로 차단했다는 뜻은 아닙니다.

저장 후 지시·주기·대상 대화·활성 상태·이름 5/5를 재조회 대조했습니다. [저장 확인 원문](../evidence/2026-10-09_1508_이동API예비량20퍼센트/saved-automation-v1.json)에 검증 범위를 보존합니다. 다음 실제 호출 때는 공급자별 사용량을 확인해야 합니다.

mock 서버 시험 0건 (화면 반응): 이번 설정 변경에서는 실행하지 않았습니다.

실서버 확인 (서버 응답): cs 프로젝트 서버 HTTP 확인 안 했음. 제한 있는 외부 API 호출은 0회이며 실제 잔여량은 이번에 측정하지 않았습니다.
