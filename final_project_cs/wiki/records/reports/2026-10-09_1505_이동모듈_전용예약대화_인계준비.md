# 이동 모듈 전용 예약 대화 인계 준비

김포공항 공식 승차시간 확대는 자료 반영 후 검증 전에 멈춰 있습니다. 전용 대화의 6시간 예약 연결과 변경 상태를 확인했으며, 다음 실행은 기존 백업을 비교 기준으로 삼아 검증부터 이어갑니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 작업 규칙과 인계 자료 확인 | 끝 | 3/3 = 100% |
| 자료·명세·기존 백업 점검 | 끝 | 3/3 = 100% |
| 다음 실행용 인계 기록 | 끝 | 1/1 = 100% |

분모는 이번 준비 작업의 확인 단위이며 이동 기능 완료율이 아닙니다. 목표는 계획서 v11의 서울 이동 검증 작업을 다음 예약 실행으로 넘기는 것이고, 이번 실행에서는 제품 계산·회귀 검사·외부 자료 조회를 진행하지 않았습니다.

## 확인한 상태

공표 대조 자료는 이미 12그룹·2,044분입니다. 백업의 기존 8그룹은 내용이 같고 새 김포공항 4그룹은 보관 공식 사실값과 4/4 일치합니다. 명세의 해당 자료 해시와 크기도 일치합니다. 이는 파일 상태 확인이며 제품 적재·출발 선택 검증 완료가 아닙니다.

이전 완료 해시 명세의 310개 파일을 다시 대조한 결과 307/310 = 99%가 같고, 달라진 3개는 공표 대조 자료·자료 명세·이동 wiki입니다. 모두 중단된 김포공항 작업의 변경 대상입니다. 변경 전 백업 4/4 = 100%는 기록된 해시와 일치합니다. [점검 원문](../evidence/2026-10-09_1426_김포공항_공표승차_대조/dedicated-handoff-inspection-v1.json)과 [백업 명세](../evidence/2026-10-09_1426_김포공항_공표승차_대조/backup-manifest-v1.json)에 경로와 해시를 보존했습니다.

김포공항 근거 폴더에는 변경 전 제품 재생이 있고, 변경 후 제품 재생·관련 회귀 로그/XML·최종 해시 명세는 아직 기록되지 않았습니다. 지정한 두 스크립트 이름을 명령줄에 포함하는 Python 프로세스는 2026-10-09 15:03:51 한국 시각 조회에서 0개였습니다. 최초 제한 환경의 CIM 조회는 접근 오류였으며 읽기 전용 권한 확장 조회로 다시 확인했습니다. 다른 이름의 작업과 미래 실행까지 부정하는 결과는 아닙니다.

기존 예약 automation-2는 활성 상태이며 이 전용 대화를 대상으로 6시간 간격입니다. 기존 설정을 읽어 확인했고 이번 실행에서 수정하지 않았습니다. 원래 대화에 메시지를 보내지 않았습니다.

## 다음 예약 실행의 시작점

1. [이동 wiki](../../teams/mobility.md), [상태 파일](../../../../.tmp/mobility_complete_20261008/gimpo-published-state-v1.json), 이번 점검 원문과 현재 파일 해시·프로세스를 다시 확인합니다. 새 작업자 변경이 있으면 먼저 구분합니다.
2. 적용 스크립트를 그대로 재실행하지 않습니다. 현재 자료는 12그룹이고 기존 실행은 변경 전 기록을 새 파일로 쓰려 하므로 재실행 전제가 맞지 않습니다. 변경 전 백업의 공표 자료·명세로 격리한 A 입력을 구성하고, 현재 자료를 B로 읽어 원자료와 운영 입력을 덮어쓰지 않고 비교합니다.
3. 평일·휴일×양방향을 A·B·B·A로 재생합니다. 서울방향 준비 13:18에서 기존 13:19→공식 13:24, 공항방향 준비 13:05에서 기존 13:06→공식 평일 13:09·휴일 13:10을 확인합니다. 합계 12그룹·2,044분, 적재 제외 312행, 다른 1,746그룹 보존, 입력 판 변경은 다음 실행에서 실측할 기대값입니다. 계양 목적지는 계산기 내부 검사이며 서울 상품 범위 확대 근거가 아닙니다.
4. [관련 검사 스크립트](../../../../.tmp/mobility_complete_20261008/verify_gimpo_boarding_v1.py)를 읽고 출력 충돌 여부를 확인한 뒤 실행합니다. 새 보고서·정적 시각화 v50·백업 기록·최종 무결성 명세를 남기고 이동 wiki와 데이터 보고서, 미해결 결함 상태를 검증 결과에 맞춰 갱신해야 이 단위가 완료됩니다.

그 다음 우선순위는 실시간 도착정보의 실제 출발 안내·탑승·환승 재계산 연결, OSM 회전 제약, 1.2km 정책 안 도보 웹 표본, 혼합 운임·누락 경로입니다. 공덕 공식 본문 미확보를 공급자 전체 불가로 단정하지 않습니다. 전체 21개 분류는 조건부 3·개선 9·추가 검증 9로 인계받았으며 완료율이 아닙니다.
