- 로컬·팀 저장소 이력에는 `git merge-base HEAD team/role-eval-ui`로 공통 조상이 나오지 않는다. 팀 배포 이력이 snapshot 방식으로 옮겨졌기 때문이다.
- 대응 기준은 팀 `8fd211fb`와 로컬 `bc750713`. 사용자 웹 경로에 대해 `git diff --name-only 8fd211fb bc750713 -- final_project_cs/frontend/apps/web` 결과가 비어 파일 내용이 같음을 확인했다.
- `git diff --name-only 8fd211fb team/role-eval-ui -- final_project_cs/frontend/apps/web`로 최신 변경 61개 경로를 얻었다.
- 각 경로를 기준 파일·현재 작업 사본·담당 브랜치 파일로 나눠 임시 폴더에서 `git merge-file -p`로 계산했다. CRLF/LF 차이를 정규화했다. 실제 소스 파일에는 쓰지 않았다.
- 관리자 앱·개발자 콘솔은 이번 사용자 웹 61개 경로 분석의 대상이 아니다. 통합 후 빌드·화면 시험은 아직 하지 않았다.

## 우리가 최근 고친 화면 보존 여부

담당 브랜치 변경 목록에는 `src/features/plan-check/`, `src/features/consent/`, 공통 알림 카드(`toast-view`), `styles/tokens.css`, mock 서버 구현 파일이 포함되지 않는다. 따라서 이번 61개 경로를 기준에서 현재 사본으로 결합하면 사진 읽기 값 선택·후보 종류 및 숙소 꼬리표·가운데 일정 수정/삭제·확인 필요 지도 필터·날짜 줄·오류 알림·약관 실시간 버전 작업은 직접 덮어쓰지 않는다. 단, 공통 메뉴와 화면 틀은 위 표처럼 수동 결합해야 한다.

등록 뒤 여행 화면에는 새 지도 위 시트·일정/채팅·알림 센터·재난 표시·제목 펼침/공유·상세 보기가 추가된다. `trip-home` 두 파일을 제거하고 전용 `trip-screen`으로 교체한다. 이름 바꾸기·사진·카카오톡 공유 등의 준비 중 상태와 등록 여행 경로선 응답 부족은 담당 리포트의 미해결 항목이며, 충돌 해결로 완료되는 기능이 아니다.
