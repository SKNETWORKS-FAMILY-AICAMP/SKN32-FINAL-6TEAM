# 계획서 읽기 — 장소는 종류 먼저 (2026-10-19)

## 한 줄 결론

장소를 찾기 **전에** 종류(숙소 · 이동 · 대표 장소 · 구역)를 원문 글자와 읽기 에이전트의 분류로 정하고, 종류가 다른 후보는 버리게 고쳤다.
진단 사례로 만든 회귀 시험 37개는 고치기 전 코드에서 26개가 실패했고 고친 뒤 37개 모두 통과했다. 실서버 확인은 하지 않았다.

## 무엇이 문제였나 (진단 근거)

[세 환경 계획서 진단](../../../../wiki/records/reports/2026-10-19_chat-intake-secretary-review.md) 「2. 장소를 엉뚱한 곳·엉뚱한 종류로 붙인다」의 사례를 코드에서 따라가 원인을 찾았다(확인 시각 2026-10-19 오전, 원격 role-manager `e538a13e` 기준 격리 사본. 작업 중 원격이 `88defd2b` 로 움직여 겹친 세 파일 — `pipeline.py` · `places.py` · `guardrails.yaml` — 을 3방향으로 합쳤고 충돌은 없었다. 아래 시험은 두 판 모두에서 돌렸다).

| 사례 | 코드에서 찾은 원인 |
|---|---|
| 경복궁스테이 · 노스텔지어 더블재 · 트레블로지가 「식사」 | 장소 찾기(`places.resolve`)는 종류 단서가 식사 · 활동뿐이었다. 관광공사 자리(활동 목록)에 없으면 요식 원장(인허가 자료 포함)의 **같은 이름 식당**을 받아 종류가 식사가 됐고, 숙소 묶기(`assemble._stays`)는 식사 항목을 빼므로 체크인 줄이 숙소가 되지 못했다 |
| 읽기 에이전트가 숙소라고 읽은 항목 | 에이전트 답의 `kind: lodging` 을 `pipeline._agent_rows` 가 버리고 식사만 넘겼다 |
| 「택시로 이동」 · 「공항철도 타고 인천공항」 | 규칙 읽기가 시각 줄 · 사이 줄을 일정 항목으로 만들고, 장소 찾기가 그 글을 그대로 이름으로 찾았다 |
| 「명동 롯데호텔 서울」 → 「명동」 | 뒤 단어를 떼어 가며 찾는 규칙(`narrowings`)이 「명동」에서 관광지를 받았다 |
| 창덕궁 → 운현궁 · 국립중앙박물관 → 축제 · 국립민속박물관 → 오촌댁 | 받은 이름이 원문이 가리킨 곳과 같은지 확인하는 단계가 없었다(원장 앞부분 맞추기 · 카카오 결과). 세 서버는 손 수정 코드라 정확히 어느 단계였는지는 이 사본에서 재현하지 않았다 |
| 광장시장 → 삼모녀꼬마김밥 | 시장 끼니(`_meal_near`) · 시장 + 음식 말(`_dish_inside`)이 시장 근처 원장 식당 하나를 골랐다(확인 필요 표시는 붙었다) |
| 268km 광주 호텔 | 숙소 팀 숙소 비교 검색이 이름만으로 찾으면 다른 도시를 낸다(10-15 기록). 확인 화면 길은 반경으로 거르지만 팀 답을 받는 입구(`_team_lodging_places`)에는 서울 · 반경 확인이 없었다 |
| 운영시간 「모름」 상위 | 관광공사 운영시간 표가 비면 대체가 없었다 |

## 고친 것

| 무엇 | 어떻게 | 파일 |
|---|---|---|
| 종류 먼저 | 고객 별칭 다음, 이름 찾기 앞에서 ① 숙소(에이전트 `lodging` · 원문 제목의 숙소 말 · 「○○스테이」 · 숙소 상표) ② 대표 장소 정답표 ③ 구역을 본다. 숙소는 우리 장소 표 숙소 행 → 관광공사 숙박(32) → 카카오 숙박(AD5)에서만, 못 정하면 정하지 않는다 | `intake/landmarks.py`(새) · `intake/places.py` · `intake/pipeline.py` `_place_kind_hint` · `_agent_rows` |
| 이동 말 | 「수단 + (로 · 타고) + 이동」 또는 끝점이 공항 · 역 · 터미널이면 장소를 찾지 않는다(장소 값 비움, 근거 `move_phrase`, 확인 화면 「장소 없이 둔 줄」). 「따릉이 타고 한강」은 「한강」만 찾는다. 「차 마시고 인사동」 · 「버스킹」은 이동이 아니다 | `intake/landmarks.py` `read_move` · `pipeline._move_rows` · `review.place_state` · `_place_line` |
| 대표 장소 정답표 | 별칭 → 정답 이름 하나로 찾고 자료가 낸 이름이 정답(또는 받는 이름)과 같을 때만 받는다. 좌표 · 번호는 표에 적지 않는다(자료 값만) | `config/seoul_landmarks.yaml`(새) |
| 구역 | 시장(관광공사 38 중 「시장」 · 카카오 분류 「시장」)과 표의 거리 · 동네는 구역 그대로. 식사면 항목 종류만 식사, 구역 밖 말(「빈대떡」)은 확인 필요 | `intake/places.py` `_zone` |
| 숙소 후보 반경 | 숙소 팀 답에서 서울 사각 밖과 기준점 15km 밖을 버린다. 남는 것이 없으면 자체 고르기 | `intake/candidates.py` `_team_lodging_places` · 가드레일 `travel.candidates.lodging_team_radius_m` |
| 대표 장소 운영시간 | 다른 자료가 모두 비면 표의 값(`source: landmark_table`, `hours_read` 에 출처 · 확인 날짜). 광장시장은 「점포마다 다름」을 이유로 보이고 값을 만들지 않는다 | `intake/hours.py` `_apply_landmark` |
| 계약 | 계획 읽기 계약에 ①~⑤ 와 숙소 반경을 적었다 | `wiki/external/rest-endpoints/web-intakes.md` · 루트 `wiki/decisions/D-025` 구현 상태 3-A |

## 남은 일 · 한계

- 커밋 · 푸시: commit 세션에 경로 목록과 시험 결과를 넘긴다(이 세션은 커밋하지 않는다).
- 실제 자료 확인: 정답표의 정답 이름(「창덕궁과 후원」 · 「N서울타워」 · 「롯데호텔 서울」 …)이 관광공사 · 카카오가 실제로 내는 이름과 같은지 실서버에서 확인해야 한다. 다르면 표의 `accept` 에 더한다 — 다를 때는 「찾지 못했다」로 남는다(엉뚱한 곳은 붙지 않는다).
- 이동 줄은 지금 「장소 없이 둔 일정」이다 — 앞뒤 일정 사이 이동 수단으로 옮기는 일은 하지 않았다.
- 정답표는 11곳이다(진단이 말한 200곳 규모는 아니다). 경복궁 · 국립중앙박물관 운영시간은 넣지 않았다.
- 시장 끼니는 이제 시장 자체가 장소다. 시장 안 가게를 고르는 일은 고객 몫(확인 화면 후보 · 검색)이다 — 전체 자동 추천(빈칸 채우기)이 시장 끼니를 다시 가게로 채우는지는 DB 가 필요한 e2e 라 확인하지 못했다.
- 숙소 판정은 원문 제목의 낱말로 한다 — 「스테이크 하우스」처럼 숙소 말과 겹치지 않는 이름은 시험했지만, 이름에 「호텔」이 든 식당(「호텔 ○○ 레스토랑」)은 숙소 쪽으로 찾는다(그 곳이 숙소 안이면 장소는 맞다).
