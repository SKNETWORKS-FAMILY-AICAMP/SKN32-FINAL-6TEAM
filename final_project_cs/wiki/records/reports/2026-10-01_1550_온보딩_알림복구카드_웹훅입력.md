# 웹 온보딩 알림·복구 카드와 디스코드 웹훅 입력

온보딩 `/start`의 선택 카드 「복구용 이메일」을 **「알림·복구」**로 바꾸고, 복구용 이메일 칸은 그대로 둔 채 여행 알림을 받을 **디스코드 웹훅 URL** 칸을 추가했다. 서버에는 사용자별 웹훅을 받는 API가 없어 두 값 모두 페이지 메모리에만 두고 **서버로 보내지 않는다.** 사용자별 알림 연결은 공유 연동 문서에 [Q-07](../../external/web-screen-api.md#협의가-필요한-항목)로 협의를 요청했다.

- 수행: 2026-10-01 · Claude(최상욱 작업). 사용자 요청 — 복구용 이메일 카드를 연락 수단 카드로 바꾸고 웹훅 칸 추가, 더 나은 카드 이름 제안.
- 저장소·기준: SKN32-FINAL-6TEAM / `role-eval-ui` / `13ae5d1` 위 로컬 변경. 착수 시 작업 트리에 다른 작업의 미커밋 변경이 있었고, 작업 중 다른 세션이 `src/features/intro/intro.tsx`·`tests/live/keys.spec.ts`를 수정했다. 둘 다 이 리포트의 범위가 아니다.
- 티켓: **ST4F-189**, `issue-1790835894981`. 사용자 승인 후 생성하고 재조회로 확인했다.
- 카드 이름: 후보(연락처·알림·복구·연락 채널·알림 받을 곳) 중 사용자가 **알림·복구**(영문 Alerts & recovery)를 골랐다.
- 상태: 화면 입력·형식 검사 구현과 데모·가짜 서버 브라우저 검증 완료. 서버 저장·전송은 미구현(Q-07 협의 필요). 이 화면은 서버로 보내는 요청이 없어 실서버 통합 검증 대상이 아니며, 실행 중인 live 개발 서버에서 화면만 확인했다.

## 수행 내용

현재 알림은 서버 설정 `ACOP_DISCORD_WEBHOOK_URL` 한 곳으로 운영 테넌트 것만 나간다([discord.py](../../../app/infrastructure/notify/discord.py), [배달 일꾼](../../../scripts/run_outbox_worker.py)). 그래서 이번 변경은 화면의 입력·검사까지로 한정하고, 데모 응답이나 로컬 저장으로 등록된 것처럼 보이지 않게 했다.

| 변경 | 동작 | 코드 |
|---|---|---|
| 카드 이름·아이콘 | 「알림·복구」+「선택」 배지, 종 아이콘. 접힌 부제는 한 줄 「토큰 복구 이메일과 디스코드 알림.」. 메일 아이콘은 쓰는 곳이 없어져 지웠다 | [onboarding.tsx](../../../frontend/apps/web/src/features/onboarding/onboarding.tsx), [icons.tsx](../../../frontend/apps/web/src/features/onboarding/icons.tsx) |
| 카드 본문 | 복구용 이메일(기존 그대로) 아래에 디스코드 웹훅 URL 칸 — `type=url`·`inputMode=url`·자동완성 끔. 안내·오류 문구와 「서버에 저장하지 않아요 · 인증 메일과 디스코드 알림도 아직 보내지 않아요」 안내 | [contact.tsx](../../../frontend/apps/web/src/features/onboarding/contact.tsx) (`recovery-email.tsx`에서 이름 변경, 사용자 승인) |
| 형식 검사 | `discordWebhookProblem` — 앞뒤 공백만 지우고, 비면 미입력, 그 밖에는 `https://` + `discord.com`·`discordapp.com`·`ptb.`·`canary.` + `/api[/vN]/webhooks/{숫자}/{토큰}`만 받는다. 다른 호스트·포트·`http`는 거절. 웹훅이 실제로 있는지는 확인하지 않는다 | [model.ts](../../../frontend/apps/web/src/features/onboarding/model.ts) |
| 진행 막기·포커스 | 기존 이메일 규칙과 같다. 입력 중에는 오류를 보이지 않고, 약관·취향으로 넘어갈 때 검사한다. 둘 다 틀리면 두 오류를 함께 보이고 이메일부터 포커스한다. 각 오류는 제 칸을 고치거나 지우면 사라진다 | [onboarding.tsx](../../../frontend/apps/web/src/features/onboarding/onboarding.tsx) `contactPasses` |
| 상태 | `OnboardingState.webhook` — 페이지 메모리. 저장소·서버로 보내지 않는다. 카드 머리에는 입력 여부만 보이고 주소(토큰 포함)는 보이지 않는다 | [onboarding-state.tsx](../../../frontend/apps/web/src/features/onboarding/onboarding-state.tsx) |

시험은 단위(웹훅 규칙 3건), 데모 브라우저(웹훅 3건 추가·기존 8건 갱신), live 가짜 서버(「등록까지 가도 이메일·웹훅이 어떤 요청에도 실리지 않는다」 1건과 이를 위한 `finishOnboarding`의 선택 인자)를 더했다. 문서는 [웹 README](../../../frontend/apps/web/README.md)의 화면 표·남은 연결 제약과 [공유 연동 문서](../../external/web-screen-api.md)의 온보딩 행·Q-07·갱신 근거를 고쳤다.

## 남은 문제

1. **Q-07 협의**: 웹훅을 받을 요청·필드, 저장 방식(웹훅 URL은 토큰이 든 비밀값 — 응답·로그·화면에서 가림), 서버 쪽 호스트 검사(디스코드 주소만 허용해 임의 주소 호출 방지), 지금의 팀 채널 통지와의 관계, 무효 웹훅·전송 실패 처리, 변경·삭제 경로와 마이페이지 표시. 합의 전에는 웹이 보내지 않는다.
2. **재방문자 경로와의 관계**: 다른 세션이 진행 중인 변경(토큰이 있는 live 사용자는 첫 화면에서 `/start`를 건너뜀)이 들어오면 이 카드는 주로 첫 방문자에게 보인다. 나중에 웹훅을 넣거나 바꿀 자리(마이페이지 등)를 Q-07에서 함께 정해야 한다.
3. **로컬 린트 환경**: 위 빌드 폴더 두 개. 정리하거나 제외 목록에 넣을지는 별도 결정.
4. 커밋·푸시는 하지 않았다.
