# 수정 화면 「바꾸기」 빠른 길 — 2026-10-19

> ★**취소된 1차안 — 지금 동작이 아니다**(같은 날 사용자가 방향을 바꿨다) — 지금 기록은 [접수 대안 미리 준비](2026-10-19_접수대안_미리준비.md). 이 문서는 그때 잰 값의 기록으로만 둔다.

## 결론

계획 확인 화면에서 일정 하나의 「바꾸기」(`GET /v1/web/trip-intakes/{id}/candidates`)가 자동 추천과 같은 빠른 길로 답한다. 로컬 시험 DB · 실제 이동 자료로 같은 입력을 교대로 5번 잰 값은 중앙값 **12.6초 → 0.011초**다. 화면이 읽는 응답 모양은 그대로다. 커밋 · 배포 전이고, x600 서버의 cs 프로젝트 서버에서는 확인하지 않았다.

## 왜 늦었나 (원인 — 2026-10-19 부른 세션 조사, 이 세션이 코드로 다시 확인)

- 누를 때마다 후보 5곳(`LIMIT` 3 + `POOL_EXTRA` 2)을 이동 계산기로 다시 쟀다(상한 `ENGINE_BUDGET_S` 12초).
- 그 뒤 이유 문장 모델을 `travel.candidate_reason.budget_seconds`(6초)까지 기다렸다.
- 같은 함수를 쓰는 전체 자동 추천(`autofix`)은 `use_engine=False, rank_only=True` 에 모델 없이 불러 바로 됐다.

## 바꾼 것

| 파일 | 바뀐 것 |
|---|---|
| `app/domains/travel_ops/entry/trip_api.py` | `web_intake_candidates` 가 `use_engine=False, rank_only=True, lodging_team=True, reason_wait=0` 으로 부른다 |
| `app/domains/travel_ops/components/intake/candidates.py` | `alternatives` 에 `reason_wait`(모델 문장 기다리는 초) · `lodging_team`(숙소 팀을 부를지, 기본은 종전대로 `rank_only` 가 아닐 때만) 인자 |
| `app/domains/travel_ops/components/intake/reasons.py` | `polish(wait_seconds=…)` — 0 이면 저장된 문장만 쓰고 바로 돌아오며 모델은 뒤에서 써 저장. 쓰는 중인 같은 사실 열쇠는 다시 맡기지 않는다(`_inflight`) |
| `tests/e2e/test_intake_candidates_fast_path.py` | 새 시험 3개 |
| `wiki/external/rest-endpoints/web-intakes.md` | 대체 후보 · 이유 문장 절에 새 동작 |

- 이동은 직선 어림값이 되어 앞뒤 일정이 있는 후보는 `estimated: true` 로 나간다. 이동 시간표 판정은 고객이 고른 뒤 확인 화면 검사가 다시 한다.
- 숙소 팀은 「바꾸기」에서 **지금처럼** 부른다(바꾸지 않았다). 전체 자동 추천에서 숙소 팀을 부르는 것은 아래 「남은 일」.

## 잰 시간 (실측 — 로컬)

조건: 이 PC(playdata2), 이 세션이 만든 시험 DB(포트 5441 · 마이그레이션 + 프롬프트 + 데모 데이터), 이동 자료는 로컬 작업 폴더 `datasets/mobility/processed`(해시 확인 끔 — 원격 최신과 같은 판인지 확인 안 함), 관광공사 목록은 시험용 고궁 · 마을 8곳, 카카오는 메모리 대역, 일정 「2026-10-13 09:30 남산타워 / 11시 경복궁 / 13:30 광장시장」의 경복궁 줄. `candidates.alternatives` 함수만 잰 값이다(HTTP 왕복 · 확인 화면 읽기는 빠짐). 옛 · 새 호출을 한 번씩 번갈아 5회.

| 호출 | 5회 (초) | 중앙값 |
|---|---|---|
| 옛 호출(이동 계산기, 모델 없음) | 27.989 · 19.463 · 12.273 · 12.578 · 12.318 | 12.578 |
| 새 호출(빠른 길) | 0.009 · 0.011 · 0.015 · 0.012 · 0.011 | 0.011 |

- 고른 후보 셋은 같았다(종묘 · 창경궁 · 창덕궁). 옛 호출은 계산기 시간 상한에 닿아 `engine_budget_exhausted` 였고 셋 중 둘은 이미 어림값이었다.
- 모델 대기: 3초 걸리는 모델 대역으로 옛 방식(기다림) 3.094초, 새 방식(`reason_wait=0`) 0.014초. 실제 모델(x600 서버의 채팅 모델) 시간은 재지 않았다 — 옛 방식에서 그 대기의 상한은 설정값 6초다(예상 아님, 설정값).

## 시험

- mock 서버 시험(메모리 대역 · 화면 반응 아님 — 서버 응답 모양): 관련 시험 18파일 212/212 = 100%, 새 시험 3/3 = 100%. 새 시험 셋 중 화면 경로 시험 2개는 옛 `trip_api.py` 로 돌리면 실패했다(막는 힘 확인).
- 실서버 확인: 안 했다(x600 서버 배포 전).
