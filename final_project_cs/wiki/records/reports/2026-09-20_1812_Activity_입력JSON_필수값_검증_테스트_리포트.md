# Activity — 장소·일정 JSON 필수값 검증 테스트 추가

## 1. 작업 목표

사용자가 "장소와 일정 JSON을 넣었을 때 제대로 검증하는지"를 테스트하고 싶다고 요청. 후속 질문으로 범위를 확정 — **장소·일정 JSON 전체 형태 검증(스키마·필수값)**. `test_activity_tour_operating.py`는 TourAPI 운영 원문 처리에 좁게 스코프돼 있어 관심사가 다르므로 새 파일로 분리.

## 2. 실제 수행 내용

신규 파일: `tests/unit/travel/test_activity_input_validation.py` (8건, `FakeTools`로 API 키·DB·네트워크 없이 검증)

**필수값 — 없으면 확정 답을 안 만든다:**
- `test_missing_booking_json_escalates_instead_of_guessing` — `booking=None` → `unknown_예약 내역`
- `test_booking_json_missing_starts_at_escalates` — `starts_at` 키 자체 누락 → `unknown_예약 시각`
- `test_booking_json_with_unparseable_starts_at_escalates` — `starts_at`이 문자열("모름") → 같은 갈래(타입 오류도 "모름"으로 처리됨을 확인)
- `test_missing_policy_json_escalates_instead_of_guessing` — `policy=[]` → `unknown_취소·환급 규정`

**있으면 좋지만 없어도 판정은 계속되는 값:**
- `test_missing_place_json_does_not_block_the_judgement` — `place=None` → escalate 안 함, `feasible: True` 유지, `place_confirmed: False`
- `test_empty_place_json_counts_as_confirmed_but_carries_nothing` — ★경계 케이스. `place={}`(빈 dict)는 `None`과 다르게 `place_confirmed: True`로 찍힌다. 옳고 그름을 판정하지 않고 현재 동작을 그대로 고정
- `test_missing_party_and_capacity_skips_the_capacity_check_safely` — 정원 필드 둘 다 없어도 안 죽고 정원 초과 검사만 건너뜀
- `test_booking_without_place_id_asks_read_place_for_none` — `place_id` 누락 시 `read.place`가 실제로 `{"place_id": None}`으로 불림을 `tools.calls`로 직접 확인(조용한 대체값 없음)

`wiki/teams/activity.md` "① 검증 규칙" 절에 결과 표와 빈 dict 경계 케이스를 반영.

## 4. 미해결 이슈·다음 작업 제안

- `place={}` 를 `None`과 다르게 취급하는 게 의도인지 결함인지는 판단하지 않았다 — 필요하면 스키마 검증(필수 필드 존재 확인)을 `read.place`나 `_check_feasible` 앞단에 추가하는 결정이 별도로 필요하다.
- `booking`이 dict가 아닌 다른 타입(list 등)으로 오는 경우는 다루지 않았다 — `read.booking` 계약(dict|None)을 신뢰하는 전제이고, 계약 위반은 이 Team 책임 밖이라 판단.
