# 매니저 실행·재개 복구와 되돌리기 버튼 반영

복구 코드를 최신 매니저·디벨롭 변경과 보존 병합하고 공개 서비스에 반영했습니다. 공개 화면과 내려오는 버튼 스타일, API·worker·web 실행 상태를 확인했습니다. 전체 제품의 완전성이나 이동 알고리즘의 상용 정확도를 뜻하지 않습니다.

## 문제와 원인

고객 업무 변경과 되묻기 응답이 담당 Team 실행·대기·재개 흐름을 일관되게 거치지 않았습니다. 후속 매니저 배포에 누락된 복구 작업과 새 메뉴·화면 확대 변경을 함께 보존해야 했습니다. 공개 화면 중단에는 배포 기계의 호스트 디스크 고갈과 WSL I/O 오류가 확인됐습니다. 공간 확보 후 공개 첫 화면은 실제 Chrome에서 HTTP 200·화면 표시·오류 0건을 확인했습니다.

## 수정

- 업무 변경은 Controller → Team.execute → ActionProposal → 코어 적용으로 연결했습니다. 담당이 꺼졌거나 설치되지 않았으면 해당 업무를 HTTP 503으로 거절하고 독립 읽기는 계속합니다. 요청·SSE·worker 회차는 한 조립 판을 고정합니다.
- 되묻기는 waiting_input으로 보존하고 답변 본문을 같은 Case의 resume으로 넘깁니다. 재전송·동시 재개는 중복 적용하지 않습니다. 교정된 읽기 decision과 스냅샷은 ROUTED.state_patch에 함께 저장합니다. SHA256은 내용 일치 검사이며 서명이 아닙니다.
- 장소·시각 되돌리기는 확인 필요 배지와 높이·글꼴·안쪽 여백을 맞췄습니다. 아이콘·문자 때문에 너비는 다릅니다. 시각 크기는 약 25.8px이고 클릭 영역은 44px입니다.
- 빈 공공 버스 키 기본값·템플릿, 은퇴한 커머스 MCP 도구·scope, 배포 이미지 SQL 검사 의존성을 정리했습니다. 현재 SQL 계획을 검증하고 기존 DB 볼륨을 보존합니다.
- 깨끗한 CI에서 git 밖 자료 생성기를 import하던 버스 시간 정규화 함수를 추적 가능한 순수 모듈로 옮겼습니다. 함수 내용은 동일하며 데이터 재생성·지도 API 호출은 하지 않았습니다.
- 감시 묶음은 Activity 활성 여부에 다른 담당이 종속되지 않게 했습니다. 각 항목은 자기 담당의 도구·지식 범위·예산으로 계산합니다. 미실행 항목의 재시도 표지를 보존하며 독립 항목의 실패·안내 결과를 버리지 않습니다.

## Claude 독립 검토

실제 Claude Code CLI의 claude-sonnet-5-5, effort high로 최소 변경 코드를 검토했습니다. 후속 검토에서 확인된 두 P2는 미실행 항목의 재시도 누락, 독립 미해결 결과 폐기이며 회귀를 추가했습니다. 정적 검토는 제공한 코드 범위에 한정하고 실행 검증을 대신하지 않습니다. 계정 잔여 사용량은 확인 불가입니다.

실제 이미지 사전 검사에서 후보의 안전 실행기 연결 누락을 추가 발견해 교체 전에 중단했습니다. [원인·복구 기록](debugs/2026-10-12_native_migration_contract.md)의 검토된 실행기를 복구한 뒤 DB 검사까지 포함해 최종 검사를 다시 실행했습니다. 초기 3974 통과만으로 배포 계약 확인을 완료한 것이 아닙니다.

Claude 검토 8회 합계: 입력 16·출력 118192·캐시 생성 163091·캐시 재사용 10804 토큰. 마지막 SQL 안전·묶음 재시도 검토는 확정 P1/P2 미발견이며 정적 검토 한계는 그대로입니다.

## 공개 반영과 Git

공개 실행 코드 커밋은 `0b33deb816d56ca2507e741673cb5931b43a8eea`입니다. API·worker 이미지는 `sha256:9360e69d7cbd11fc91680e7ea61f6f69ed191eb9a3770388e74eca9ad2eb2afa`, web 이미지는 `sha256:392d95d5d304122675b14ab98d425b654cc04ed37bfdb87f76b036fdba117551`입니다. 이 보고서를 마감하는 후속 커밋은 문서·증거만 바꾸며 실행 코드와 구분합니다.

실서버 확인(서버 응답): 했음 — 실제 Chrome의 공개 첫 화면 HTTP 200·화면 표시·스크립트 오류 0·실패 요청 0, 공개 CSS HTTP 200·실행 이미지와 SHA256 일치, 공개 API `/health` Chrome 2회·별도 요청 3회 모두 HTTP 200, API/web healthy·worker running·세 프로세스 재시작 0. worker 초기 감시 4회·배달 4회에서 보고된 오류는 0건입니다. worker에는 별도 Docker 건강 검사가 없으므로 running 관찰과 실제 회차를 함께 확인했습니다.

장소·시각 되돌리기의 공개 CSS는 12px 글꼴·2px 8px 여백·최소 높이 해제로 적용됐습니다. 44px 누름 영역도 유지합니다. 실제 고객 일정에 쓰기·되돌리기 시험을 하지는 않았으며, 버튼 동작은 mock 서버 12/12와 공개 스타일 일치로 구분합니다.

공개 API 후속 확인 중 단발 502 한 건을 관측했습니다. 이후 Chrome 2회와 별도 요청 3회는 모두 200, 프록시 내부 API 연결도 정상, 컨테이너 재시작 0회였습니다. 이 기록은 장기 무중단 보장을 뜻하지 않으며 단발 응답의 원인을 단정하지 않습니다.

DB 컨테이너·볼륨과 기존 앱 환경·자료 연결을 보존했고 복원용 이미지에 별도 태그를 남겼습니다. 실제 이미지 검사 → 현재 SQL 계획 적용 → 정확한 이미지 ID로 교체 → 30초 추가 관찰을 통과했습니다. 복구 이미지 삭제·공용 WSL 재시작·SDK 이동은 하지 않았습니다.

origin과 team의 `role-manager`·`develop`은 기존 네 이력을 모두 조상으로 포함하는 최종 문서 커밋까지 일반 푸시로 반영했습니다. 강제 푸시는 사용하지 않습니다. 실제 원격별 최종 해시는 별도 로컬 푸시 확인 영수증과 최종 사용자 보고에서 확인합니다. 공개 실행 코드와 후속 문서 커밋은 서로 다른 해시입니다.

## 보존과 한계

변경 전 파일·이전 시험 결과·Claude 원문·고객 자료 조회 로그는 Git 밖 작업 백업에 보존했습니다. 공개 증거에는 자격 증명·운영 환경 파일·고객 식별자를 포함하지 않습니다. 실제 고객 DB·지도 데이터·모델·복원 이미지의 삭제는 수행하지 않습니다.

호텔 자동 대체의 단일 카드 계산은 현재 시간 구간에 맞는 후보만 고릅니다. 수동으로 장소와 시각을 함께 바꾼 사례를 단일 자동 대체와 동일 조건으로 볼 수 없습니다. 전체 일정의 공동 시간 재계산과 LLM 추천 품질은 이번 실행 경로·버튼 회귀 통과로 완료 판정하지 않습니다.
