## 목표·기존 문서 대조

사용자는 Team 인스턴스가 없으면 그 업무만 실행되지 않고 독립 서비스는 유지되는 마이크로커널 플러그인 구조를 요청했습니다. 기존 [구성 단위 계약](../../teams/composition.md), [등록표 문서](../../teams/team-registry.md), [D-CS-013](../../decisions/D-CS-013-domain-folder-layout.md)는 의존 역전·계산 hook을 설명하지만, 비활성 우회 차단·수명 관리·Controller와 전역 계산 서비스의 같은 판 교체를 구현 완료로 입증하지 않습니다.

현재 wiki·구성 계약·코드와 관련 키워드를 확인한 범위의 결론입니다. 저장소 밖 개인 문서나 모든 동결 기록에서 같은 계획이 존재하지 않는다고 단정하지 않습니다.

상위 v11 계획서와 동결된 records/plans·handoff는 수정하지 않았습니다. 실행 계획은 현재 지식인 [Team 플러그인 수명 관리](../../teams/team-plugin-lifecycle.md)에 새로 작성했습니다. 문서는 제안·현재 결함·미정 계약을 구분하며 제품 구현 완료를 주장하지 않습니다.

## 설계 결과

1. 비활성 구현은 import하지 않고, 선언 검증과 로딩을 분리합니다. 필수 코어와 선택 팀의 실패 범위를 구분합니다.
2. 자동·직접 지정·재개·계산 서비스는 같은 활성 집합과 동기화된 실행 참조 획득을 사용합니다.
3. 전역 hooks의 조립 중 변경을 없애고 Controller·Registry·계산 서비스를 같은 조립 판으로 준비·교체합니다.
4. 신규 실행 차단·진행 작업 종료 대기·대기 Case/답변/토큰 보존·멱등 적용을 포함합니다. API의 구성 장애를 고객 입력 오류로 안내하지 않습니다.

의도적 비활성화와 결정 15의 활성 팀 필수 데이터 장애를 구분합니다. 기존 정책 전체를 자동 폐기하지 않습니다. 같은 프로세스의 논리적 격리를 프로세스 전체 크래시 격리로 주장하지 않습니다.

## Claude CLI 호출·차단

- 로컬 설치 확인: Claude Code `2.1.287`.
- 요청 모델: `claude-opus-5-5`를 명시했습니다. 실제 모델 실행 성공은 확인하지 못했습니다.
- 첫 호출: `--safe-mode --strict-mcp-config --tools Read,Glob,Grep --permission-mode plan --no-session-persistence -p --output-format json`.
- [첫 응답 원문](../evidence/2026-10-11_1826_team_plugin_review/attempt-1.json): exit 1, `ENOTFOUND`, 입력·출력 토큰 0, `modelUsage={}`, `total_cost_usd=0`. 이 수치는 해당 CLI 반환값이며 별도 청구 검증은 아닙니다.
- 같은 모델의 제한 밖 재시도는 자동 승인 심사에서 거절했습니다. 사유: 관련 내부 코드·설계 문서의 외부 전송에 대한 명시적 사용자 승인이 부족하다는 판단. 제한 밖 실행은 시작되지 않았습니다.
- 사용자에게 비밀정보·개인정보 제외 관련 코드·문서 전달 또는 설계 요약만 전달의 범위를 질문했습니다. 응답 전 해당 재시도를 수행하지 않습니다.
- [준비된 검토 프롬프트](../evidence/2026-10-11_1826_team_plugin_review/review-prompt.txt). 동의·반박·합의 결과는 아직 없습니다.

## 검증·코드 상태

[최소 재현 출력](../evidence/2026-10-11_1826_team_plugin_review/registry-observations.json)의 현재 동작 관측 4/4가 일치했습니다. inactive execute 호출을 확인했으며 개선 인수 시험 통과가 아닙니다. 관련 소스 8개 SHA-256을 함께 보존했습니다.

신규 문서 3개에서 로컬 링크 21/21의 대상 존재와 코드 울타리 짝을 확인했습니다. [문서 검사 결과](../evidence/2026-10-11_1826_team_plugin_review/document-check.json). `git diff --check`의 대상 추적 문서에서는 공백 오류 없이 통과했으며 LF/CRLF 안내만 있었습니다. Mermaid 렌더링·제품 인수 시험을 실행한 결과는 아닙니다.

관측 기준 HEAD는 `38f9e08cb08cafba6ce2f66ff7b08c19788cf1d1`이며 실제 코드는 기존 미커밋 변경이 있는 작업 트리입니다. 코드 수정·커밋·푸시·배포는 하지 않았습니다. CLI 검토와 재현은 고객 데이터·실제 업무 적용을 수행하지 않습니다.
