# Activity — 휴무 요일 대조(유일한 자동 판정 예외) 구현

## 1. 작업 목표

사용자가 "2026-09-22(화)면 feasible이 false가 나와야 한다"고 요청 — 이는 직전에 확정한 "자동 판정 금지" 원칙과 정면으로 부딪히는 요청이었다. 재확인 결과, **원칙을 완전히 뒤집는 대신 가장 좁은 예외 하나(요일 대조, 예외 조건 미반영을 안내문에 필수 표기)** 로 범위를 좁혀 구현하기로 사용자가 결정했다.

## 2. 실제 수행 내용

### `app/modules/travel_ops/activity.py`

- `_weekday_closure_match(restdate_text, at)` classmethod 신설 — `"<요일> in restdate_text and "휴무" in restdate_text"` 하나만 본다. 예외 조건("단 공휴일과 겹치면 개방")은 절대 안 본다.
- `_check_feasible()` 수정:
  - `weekday_match` 계산 후 `decisions["feasible"] = not weekday_match`로 초기화(기존엔 무조건 `True`였다)
  - answer의 **첫 문장**이 `weekday_match` 값에 따라 달라지도록 수정 — "성립합니다"로 시작해놓고 뒤에서 뒤집는 모순을 피했다(초안에서 직접 발견해 수정)
  - `weekday_match is True`일 때만 캐비앗 문장("단, 이 판단은 요일만 비교한 것이고 공휴일과 겹치는 경우 같은 예외 조건은 반영하지 않았습니다...")을 answer에 강제로 붙이고, 전용 warning 추가
  - `decisions["operating"]["weekday_match"]`에 결과(`True`/`False`/`None`) 노출

### `tests/unit/travel/test_activity_tour_operating.py`

- **flaky 버그를 구현 중 직접 발견해 수정**: 기존 `_values()`가 `starts_at`에 `in_hours(30)`(상대 시각)을 쓰고 있었는데, 기본 `_operating()`의 `restdate_text`에 실제 "화요일" 텍스트가 있어 — 요일 대조 로직이 생긴 뒤로는 **테스트 실행일이 우연히 화요일 근처면 무관한 기존 테스트들이 이유 없이 깨지는 상태**가 됐다. `DEFAULT_STARTS_AT`을 고정 시각(2026-10-03, `date` 명령으로 실측한 토요일)으로 바꿔 해결.
- `test_operating_text_never_flips_feasibility` → `test_free_text_closure_without_a_weekday_pattern_does_not_flip_feasibility`로 이름·문서화 변경(더 이상 "절대 안 바뀐다"가 사실이 아니므로 범위를 정확히 적음). `weekday_match is False`(패턴은 매치 시도됐지만 요일이 다름) 단언 추가 — 처음엔 `is None`으로 잘못 썼다가 실행 결과 보고 직접 고쳤다.
- `test_operating_present_but_empty_does_not_claim_it_was_checked`에 `weekday_match is None`(restdate_text 자체가 없을 때) 단언 추가.
- 기존 "실사용값" 테스트 1개를 2개로 분리 — 경복궁·2026-10-03(토, 실측)은 `feasible: True`/`weekday_match: False`, 경복궁·2026-09-22(화, 실측)는 `feasible: False`/`weekday_match: True`+캐비앗 문구·경고 필수.

## 4. 미해결 이슈·다음 작업 제안

- `_weekday_closure_match`는 `"<요일> in text and "휴무" in text"`라는 아주 단순한 substring 매칭이다 — "화요일과 목요일은 정상 운영, 수요일 휴무"처럼 요일명이 다른 문맥에 섞여 있으면 오탐할 수 있다. 지금은 의도적으로 받아들인 단순화다(사용자가 선택한 "생각 바꿀 — 간단한 요일 대조만 구현" 옵션의 범위).
- `usetime_text`는 여전히 전혀 안 본다 — "화요일에도 열지만 단축 운영" 같은 케이스는 다루지 않는다.
