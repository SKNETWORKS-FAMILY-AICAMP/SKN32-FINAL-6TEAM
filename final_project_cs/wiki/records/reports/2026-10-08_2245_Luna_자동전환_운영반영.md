# GPT-6 Luna 자동 전환 운영 반영

Ollama 연결 실패 시 별도의 cs 프로젝트 서버용 키로 GPT-6 Luna를 부르도록 실제 운영 설정과 호출 코드를 반영했다. API·상시 일꾼 모두 전환 스위치가 켜져 있으며 개인 키는 비어 있다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 자동 전환 시험 | 통과 | 57/57 = 100% |
| 보안 시험 | 통과 | 12/12 = 100% |
| 실제 자동 전환 | 성공 | 3/3 = 100% |
| 운영 컨테이너 | 실행 중 | 5/5 = 100% |

## 변경

- 서버용 키만 `ACOP_OPENAI_API_KEY_SERVER`로 운영 환경 파일에 넣고 `ACOP_LLM_FAILOVER_ENABLED=true`, `ACOP_LLM_FAILOVER_MODEL=gpt-6-luna`를 설정했다. 환경 파일은 변경 전에 백업했고 키는 Git·이미지·시험·리포트에 넣지 않았다.
- GPT-6는 `max_completion_tokens`를 쓰고 샘플링 옵션을 보내지 않는다. Luna는 짧은 JSON·문장 추출 예산을 추론 토큰이 먼저 소진하지 않도록 `reasoning_effort=none`을 명시한다. 다른 모델과 로컬 기본 꺼짐 설정은 유지했다.
- 기존 호출 상한(일 2,000회·월 30,000회), 개인정보 마스킹, 장애 경로 기록, 복구 후 재시도 기능을 유지했다.

## 배포와 확인 범위

현재 배포본 기준의 격리 브랜치에 이번 수정 3개 파일만 넣었다. 운영 배포 브랜치에 fast-forward 반영 후 기존 자동 배포 절차의 건강·안정성 검사를 통과했다. 배포 커밋은 `bd0239b09bb5891d39d3aaf78fdc3f6b189e79b1`이다. 공동 작업 폴더의 다른 변경은 이 커밋에 들어가지 않았다.

mock 서버 시험 57/57 (응답 모양·전환 분기). 최초 제한 환경 실행에서는 loopback 통신 3건이 실패했고, 통신 허용 환경에서 동일 57건이 통과했다. 배포 기준 격리본에서도 57/57을 확인했다. 보안 시험은 별도 12/12이다.

실서버 확인 (서버 응답): 했음. 직접 API 연결 1/1은 GPT-6 Luna가 응답했다. 운영 호출 코드로 Ollama 연결 실패를 실제로 거친 JSON·채팅 질문 해석·문장 응답 3/3이 API로 전환됐다. 경복궁의 시간 질문이 올바른 일정과 시간 질문으로 해석됐다. 응답 시간은 각각 6.51초·5.67초·4.09초이며 단회 표본이라 평소 속도·품질을 일반화하지 않는다. 고객 일정·Case·채팅을 수정하지 않았고 브라우저에서 새 고객 메시지를 제출하지 않았다.

API·상시 일꾼 2/2에서 서버용 키 일치와 개인 키 비어 있음을 값 노출 없이 확인했다. 운영 컨테이너 5/5 실행 중이며 건강 검사 적용 4/4 정상이다. 이 확인으로 GPU 서버의 Ollama 프로세스가 종료됐다고 단정하지 않는다. 관찰된 원인은 Ollama 연결 실패다.

## 제한 및 기록

`codex-consensus` 교차 검토는 자동 승인 검토가 내부 배포 정보를 외부 Codex로 보내는 전송을 차단하여 수행하지 않았다. 전송은 중단했고 실제 배포 저장소·기준선·차이·시험·실호출을 직접 확인하여 진행했다. 기계 교차 검토 합의가 있었다고 기록하지 않는다.
