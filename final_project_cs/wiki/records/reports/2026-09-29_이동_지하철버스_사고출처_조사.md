# 지하철·버스 사고 출처 조사 (2026-09-29)

> 이동 계산기 문제목록 #36 — 「사고 감시가 도로 통제만 본다. 지하철 무정차·버스 사고를 못 본다」.
> 실행계획 1단계의 완료 기준: 후보 출처와 무료 여부, 호출 한도를 표로 정리하고, 없으면 「없음」이 아니라 찾은 범위를 적는다.

## 결론

- **지하철 1~8호선(서울교통공사 구간)은 무료 공개 API 가 있다** — 「서울교통공사_지하철알림정보」. 지연·사고·**무정차**·시간표 변경 공지를 1분마다 갱신한다.
  다만 **노선·역이 칸으로 나오지 않고 공지 글(제목·내용)** 로 나온다. 우리 대상 표기(`2호선:잠실`)로 옮기려면 글에서 노선·역을 뽑아야 한다.
- **버스 우회·통제는 TOPIS 공지사항 API** 에 들어 있다고 소개돼 있다. 응답 칸은 이 조사에서 확인하지 못했다. 공지 글이라 노선 번호를 글에서 뽑아야 할 가능성이 크다.
- **코레일 구간(1호선 일부·경의중앙선 등)·9호선·공항철도의 실시간 사고 공지 API 는 이 조사 범위에서 못 찾았다.** 이 대상은 지금처럼 「확인 못 한 대상」으로 센다.
- 붙이려면 **공공데이터포털 활용신청(사람이 계정으로 한다)** 이 먼저다. 이 조사에서는 호출을 하지 않았다.

## 확인 범위 — 이 조사가 놓칠 수 있는 것

- 웹 검색 3회(열린데이터광장 지하철 지연·무정차 / 공공데이터포털 서울교통공사 장애·지연 / TOPIS 버스 우회·결행)와 설명 페이지 4곳 읽기로 찾았다. **API 를 실제로 부르지 않았다** — 응답 칸 이름·노선 범위는 설명문 기준이다.
- 레일포털 개방데이터 목록 전체는 열어 보지 않았다 — 코레일·9호선·공항철도 사고 항목이 거기 있을 수 있다.
- 9호선 운영사(서울시메트로9호선)·공항철도 자체 공지 API 는 찾지 않았다.

## 다음에 할 것

1. 공공데이터포털에서 「서울교통공사_지하철알림정보」·「TOPIS 공지사항」 활용신청 — **사람이 계정으로 한다**.
2. 받은 키로 한 번 불러 응답 칸을 확인하고 공지 표본을 모은다(무정차·지연·운행 중단 문장 모양).
3. 경로 사건 소스(`UticRouteEvents` 와 같은 모양)에 지하철 소스를 더한다. 글에서 노선·역을 뽑지 못한 공지는 「확인 못 한 공지」로 세어 드러낸다(조용히 버리지 않는다).
4. 레일포털 목록을 열어 코레일 구간 사고 항목을 찾는다.
