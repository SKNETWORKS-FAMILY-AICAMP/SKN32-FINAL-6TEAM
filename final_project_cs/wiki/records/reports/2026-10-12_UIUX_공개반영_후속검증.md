## 원인과 보완

자동 배포의 표시 태그 차이·Compose 서비스별 해시 문제를 수정한 뒤 첫 구성 보관 검사는 통과했습니다. 이어지는 내장/연결 파일 검사에서는 기존 읽기 전용 연결이 새 이미지의 실행기를 덮어 `safety_manifest`를 불러오지 못했습니다. 이는 DB 변경 전에 의도대로 중단한 결과입니다.

운영 파일을 먼저 지우거나 검사를 생략하지 않았습니다. 실제 실행 중 이미지·설정·연결 파일을 비공개 복구 자료로 보존하고, API/worker의 DB 실행 파일 연결만 제거한 별도 후보를 만들었습니다. API/worker/웹의 새 이미지 ID와 표시 태그 외의 설정은 유지했습니다. 두 서비스의 세 파일씩 연결, 합계 6개를 후보에서 제거했습니다. 기존 연결 파일 원본은 보존했습니다.

새 이미지의 내장 manifest와 후보 Compose manifest가 같고 SQL 89개 해시가 검토한 Git 소스와 일치함을 확인했습니다. PostgreSQL 17 독립 시험 11개를 실행했습니다. 처음 두 시도는 비밀 없는 시험 필수 설정 누락으로 각각 11개를 건너뛰었으며 성공으로 세지 않았습니다. 필수 설정을 채운 최종 실행은 11 통과·실패/오류/건너뜀 0입니다. 시험은 외부 연결과 호스트 포트를 열지 않은 전용 네트워크·임시 DB에서 진행했고 정리도 확인했습니다.

업무 DB는 같은 기계의 비공개 파일에 읽기 전용으로 백업했습니다. 별도 PostgreSQL 17에 복원한 사본에 후보 SQL을 적용했고 주요 여행 표 8개의 행 수가 유지됐습니다. 과거 도메인 표의 정확한 이름 5개는 재생성되지 않았습니다. 이 검사는 모든 행의 모든 값이 같다는 증명은 아닙니다. 고객 행·백업 본문은 외부로 보내거나 Git에 넣지 않았습니다.

## 실제 전환

기존 자동 배포와 같은 잠금을 잡고 실제 이미지·컨테이너·설정이 준비 시점과 같은지 다시 확인했습니다. 안전 검사 후 시간 제한을 둔 SQL 작업·앱 교체·건강 및 재시작 관찰을 실행했습니다. 성공한 후보의 파일 연결 변경만 기본 추가 설정에 승격한 뒤 엄격한 구성 보관 검사를 다시 통과했습니다. 이후 배포 상태를 갱신했습니다. 앱 전환·검사에는 약 128초가 걸렸습니다. DB 컨테이너와 볼륨은 삭제·재생성하지 않았습니다.

API·웹은 건강 검사 통과, API·worker·웹 모두 재시작 0을 확인했습니다. worker는 건강 검사가 없는 구성이라 실행 상태·이미지·재시작 관찰을 확인했습니다. 관리자 웹앱은 실행 태그가 다르지만 Git의 관리자 앱 디렉터리 내용이 이번 기준과 같음을 대조했습니다. 이것만으로 모든 고객 업무 흐름을 확인했다고 주장하지 않습니다.

공개 새 여행 화면을 새로고침해 분류별 준비 계획 선택, 문제 없는 세 계획, 유형별 색상이 실제 보임을 UIUX 채팅에서 확인했습니다. 그 밖의 공개 화면 회귀 확인과 전체 웹 CI는 진행 중입니다. 추가 준비 안내 지연 수정도 검증 완료 후 별도 반영합니다.
