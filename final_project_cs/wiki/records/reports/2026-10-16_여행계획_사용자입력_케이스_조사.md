# 여행계획 — 사용자 입력 케이스 조사 (2026-10-16)

사용자 요청: 「여행계획에 대해서 사용자 인풋 케이스 조사」.

범위: 고객이 여행계획을 **넣는** 경로와 그 입력 모양. 코드는 2026-10-16 작업 트리(`role-dining`, 미커밋 변경 포함)를 읽었고, 입력 모양 22가지는 **규칙 읽기 층(`rules.read_plan`)과 파일 종류 판별(`sources.sniff`)에만** 직접 넣어 봤다. 그 뒤 단계(모델 인용 · 장소 찾기 · 조립 검사)는 돌리지 않았다 — 아래 「틀림」 가운데 일부는 뒤 단계가 고칠 수 있으며 확인 안 함.

## 2. 평가 자료가 덮는 입력 — `eval/intake/`

합성 60건 = 형식 6 × 10: `paste` · `text_pdf` · `photo` · `scan_pdf` · `xlsx` · `mixed`(채팅 글 + 사진). 결함은 형식마다 3건(`relative_date`「내일」 · `no_time` · `typo`). 줄 모양은 3가지(`N일차 · M월 D일` / `DAY N YYYY-MM-DD` / `N일차 YYYY-MM-DD`) + `HH:MM 제목`, 하루 3항목, 1~3일, 1~4명, 서울 안 장소만(`build.py:70-133`).

→ 실제 고객이 낼 만한 모양(대화체 · 화살표 · AI 답변 마크다운 · 카톡 대화 · 외국어 · 서울 밖 · 범위 밖 · 링크)은 평가 자료에 **없다**.

## 3. 입력 모양 22가지 — 규칙 읽기 층 실측

| 판정 | 수 | 케이스 |
|---|---|---|
| 바로 읽음 | 6/22 = 27% | 표준 일차 머리줄 · 시간 범위(`10:00~12:00`) · 「오후 1시 반」 · 이동 항목(공항 · 공항철도) · 숙소 체크인/아웃 · 인원 6명(읽고 뒤에서 `party_size_out_of_range`) |
| 모델 · 확인으로 넘김(의도대로) | 8/22 = 36% | 대화체 한 문장 · 시각 없는 목록 · 링크만 · 취향만(→ 짜기) · 일본어 · 중국어 머리줄 날짜(못 읽은 줄 → 모델) · 「토요일」 · 「모레」(날짜 없음 → 확인 필요) |
| **틀린 값 · 조용한 누락** | 8/22 = 36% | 아래 표 |

| # | 입력 | 실측 결과 | 왜 문제인가 |
|---|---|---|---|
| C1 | `10:00 도산공원` · `은평한옥마을` · `에버랜드` · `은행나무길` | 제목 `산공원` · `평한옥마을` · `버랜드` · `행나무길` | **이름 첫 글자가 「에·는·은·도」면 잘린다.** `rules.py:64` `_LEAD = ^[\s,.:·\|/\-~에는은도]+` 가 조사를 떼려다 이름 첫 글자를 먹는다. 인계의 「은평구 → 평구」(배포 판)와 같은 뿌리로 보인다 |
| C2 | `첫째 날: 경복궁 → 북촌 → 인사동` | 항목 0건 · 못 읽은 줄 0 | **머리줄과 화살표 나열이 한 줄이면 통째로 사라진다.** 머리줄 처리 뒤 `continue`(`rules.py` `read_plan`)로 화살표 규칙에 안 가고, 줄은 「읽음」이라 모델에게도 안 간다. 머리줄을 따로 쓴 줄은 3건 읽음 |
| C3 | 카톡 내보내기 `[민지] [오후 3:12] 우리 20일에 경복궁 10시 어때` | 15:12 「] 우리 20일에 경복궁」 · 10:00 「어때」 | 메시지 보낸 시각을 일정 시각으로 읽는다 |
| C4 | ChatGPT 식 `- **오전 9:30** 경복궁 🏯` | 제목 `** 경복궁 🏯` | 굵게 기호 · 이모지가 제목에 남는다(장소 찾기가 견디는지 미확인) |
| C5 | 블로그 서술 「2시쯤 이촌역 근처에서 점심」 | 02:00 · 제목 `쯤 이촌역 근처` | 오전/오후 없는 「2시」를 새벽으로 · 「쯤」이 제목에 |
| C6 | `23:30 동대문 야시장` → `01:00 숙소 복귀` | 01:00 이 같은 날 | 자정 넘김(조립 단계가 고치는지 미확인) |

## 4. 평가 자료에 넣음 — `edge-01`~`edge-08` (같은 날 추가)

C1~C8 을 `eval/intake/edge.py`(`python -m eval.intake.edge`)로 손글 정답 8건 · 항목 25개로 넣었다. 정답은 사람이 읽은 값이고, `expect_problems` 로 조립 문제 코드도 정답에 둔다(C8 의 `days_out_of_range` 는 **아직 코드에 없는 이름**). 기존 60건 파일 해시는 그대로다(`manifest.json` 에 edge 8줄과 `edge_cases` 만 늘었다 — 생성기가 바뀐 해시가 있으면 멈춘다). 기본 실행(`python -m eval.intake.run`)은 원래 60건만, edge 는 `--only edge`.

채점기(`run.py`)에 지표 셋을 더했다 — **남는 항목**(짝 없는 뽑은 항목, 재현율이 못 보는 헛항목) · **제목 그대로**(포함 짝짓기가 「산공원」을 찾은 것으로 세던 구멍) · **나와야 할 문제**. 관광공사 키가 없으면 멈추던 것을 관광공사 없이 돌고 요약에 `tour_api: unavailable` 을 남기게 했다.

기준선 실행 `intake_eval_3ad93f24`(모델 gemma4:e4b · 카카오 24회 · **관광공사 키 없음** · DB `acop_ci_local` — 로컬 `acop_cs` 는 마이그레이션 038 전이라 `place_aliases.customer_id` 가 없어 실패):

| 지표 | edge 8건 |
|---|---|
| 항목 재현율 | 17/25 = 68.0% |
| 제목 그대로 | 7/17 = 41.2% |
| 시각 정확도 | 13/16 = 81.2% |
| 남는 항목 | 3/20 = 15.0% |
| 나와야 할 문제 | 0/1 = 0% |
| 값 변조 · 근거 없는 값 | 0/20 · 0/118 |
| 장소 1위 | 8/17 = 47.1% — 관광공사 없이 잰 값이라 이전 실행과 견주지 않는다 |

C1~C8 은 전체 흐름(모델 인용 · 장소 찾기 · 조립)을 거친 뒤에도 **8/8 = 100% 재현**됐다: 「산공원 산책」 · 「평한옥마을」 · 「봉산 등산」(장소 0/3) · 화살표 항목 0/3 · 카톡 15:12 · 헛항목 2 · `** 경복궁 🏯` · 02:00 · 05:30 · 01:00 이 같은 날 · 영어 날짜 0/4(`no_date`) · 8일 일정에 문제 없음.

회귀 확인 `intake_eval_c87a3931`(`--only paste` 10건, 같은 환경): 재현 54/54 · 시각 53/53 · 제목 그대로 54/54 · 남는 항목 0/54 · 변조 0/58. 사진 · PDF · 표 · 섞임 50건은 이번에 돌리지 않았다(받아쓰기 모델 시간).

## 4-1. C1 · C2 고침 (같은 날)

시험을 먼저 쓰고(`tests/unit/travel/test_intake_rules.py` 끝 13건 — 고치기 전 12 실패) `rules.py` 를 고쳤다. 백업 `_backup/2026-10-16_intake-c1-c2/`.

- **C1** `_LEAD` — 조사 글자(에·는·은·도)를 **뒤에 띄어쓰기·구두점이 올 때만** 뗀다. 「9시 반에 도산공원」의 「에」는 그대로 떼고 「도산공원」은 남는다. 대가: 붙여 쓴 「10시에경복궁」의 「에」는 이제 이름에 남는다.
- **C2** 머리줄 · 날짜 줄(시각 없음)의 나머지에 화살표 나열이 있으면 순서 항목으로 읽는다(`_arrow_items(..., begin=)`). 표 행 `DAY 1 | 경복궁 -> …` 도 같다.

## 5. 더 넣을 후보

파일 2종(HEIC · HWP)은 아직 평가 자료에 없다. 그 밖에 아직 넣어 보지 않은 모양(분모 밖):

- 네이버 · 구글 지도 「저장 목록」 공유 링크, 여행 앱(트리플 · 마이리얼트립) 일정 공유 글
- 손글씨 메모 사진 · 지도 앱 화면 캡처
- 한 도시 안 여러 날을 한 표에 가로로 쓴 xlsx(열 = 날짜)
- 「점심은 아무 데나」 같은 빈 자리 · 「비 오면 박물관」 같은 조건 일정
- 예약 확인 메일 붙여 넣기(예약번호 · 시각이 섞인 긴 글)
