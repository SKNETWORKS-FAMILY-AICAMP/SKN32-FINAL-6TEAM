# 고객 알림의 개발용 디스코드 우회 제거

고객이 외부 알림을 연결하지 않았거나 외부 발송이 꺼져 있으면 외부 요청을 하지 않고 앱 알림을 유지하도록 로컬 코드를 수정했다. 운영 중인 cs 프로젝트 서버에는 배포하지 않았다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 고객 알림의 공용 디스코드 우회 제거 | 로컬 수정 완료 | 1/1 = 100% |
| 알림 발송·건너뛰기·앱 조회 검증 | 통과 | 52/52 = 100% |
| 주변 웹 신호·고객 구분·재시도 검증 | 첫 실행 1건 실패 | 22/23 = 96% |
| 실패한 웹 신호 시험 단독 재확인 | 수정 없이 통과 | 1/1 = 100% |
| 운영 중인 cs 프로젝트 서버 배포 | 미실행 | 0/1 = 0% |

## 바뀐 동작

- 외부 발송 꺼짐: 고객 알림은 `NoticeSuppressed` → `skipped`로 남긴다. 운영 디스코드·고객 채널·번역을 호출하지 않는다.
- 외부 발송 켜짐 + 고객 미연결: 기존 연결 확인 경로에서 `skipped`로 남기고 운영 디스코드로 우회하지 않는다.
- 외부 발송 켜짐 + 고객 연결: 기존 고객별 텔레그램·디스코드 발송을 유지한다.
- 앱 화면 위쪽 알림 API는 배달 상태로 목록을 거르지 않는다. 발송을 건너뛴 뒤 본인 키로 알림을 읽으면 본문이 그대로 보인다. 개발용 디스코드의 운영 리포트는 별도 `ops_alert.send_ops_alert` 경로이며 이번 수정으로 바꾸지 않았다.

앞선 「디스코드 발송 실패 20건」은 잘못된 공용 디스코드 경로의 실패 기록이었다. 고객이 연결한 채널의 실패나 앱 알림 유실 20건으로 해석하면 안 된다. 원인·정정은 [결함 기록](debugs/2026-10-09_2012_고객미연결_운영디스코드_오발송.md)에 남겼다. 기존 운영 DB 이력은 변경·재발송하지 않았다.

## 검증 범위와 재현

기준 HEAD: `38f9e08cb08cafba6ce2f66ff7b08c19788cf1d1` + 작업 폴더 변경. 실행일: 2026-10-09, Windows Python 3.12, 로컬 개발 DB. 저장소에 다른 작업의 변경이 있어 해당 파일을 되돌리지 않고 대상 부분만 수정했다.

```powershell
python -m pytest tests/e2e/test_notice_routing.py -q -k 'never_fall_back or without_external_delivery'
python -m pytest tests/e2e/test_notice_routing.py -q
python -m pytest tests/e2e/test_trip_events.py tests/integration/messaging/test_outbox_tenant_guard.py tests/unit/core/test_outbox_retry_after.py tests/unit/travel/test_notice_tenant_guard.py -q
python -m pytest tests/e2e/test_trip_events.py::test_a_proposal_that_is_decided_or_expires_also_sends_a_signal -q
```

- 수정 전 회귀 시험: [원문](../evidence/2026-10-09_2012_notice_channel_split/before.txt) — 4 failed, 1 passed. 꺼짐 조건에서 억제되지 않고 운영 채널로 위임되는 것을 재현했다. 이 로그의 한국어 일부는 콘솔 인코딩으로 깨져 있으나 시험 이름·판정은 보존됐다.
- 수정 후 알림 시험: [원문](../evidence/2026-10-09_2012_notice_channel_split/after.txt) — 52 passed in 43.56s. 꺼짐/미연결, 외부 요청 0회, 운영 발행자 호출 0회, 재시도 없음, 웹 알림 API 본문 보존 포함.
- 주변 기능: [첫 실행 원문](../evidence/2026-10-09_2012_notice_channel_split/adjacent.txt) — 22 passed, 1 failed in 15.10s. 웹 제안 생성·만료 신호 시험에서 2개 기대 중 1개만 관측했다. [같은 시험 단독 재실행](../evidence/2026-10-09_2012_notice_channel_split/events_recheck.txt)은 코드 변경 없이 1 passed in 4.46s. 첫 실패 원인을 확정하지 않았으며 시간에 의존하는 시험의 불안정 가능성이 남는다.
- 처음 제한 환경 실행은 로컬 개발 DB 연결 권한 오류로 5 errors였으며, 연결 권한을 허용한 실행에서 위 결과를 확인했다.
- 대상 변경 파일의 `git diff --check` 통과. 커밋·push·배포는 하지 않았다.

mock 서버 시험 52/52 = 100% (화면 반응: 외부 알림 응답은 `httpx.MockTransport`, 앱 알림 API는 TestClient로 검증했으며 브라우저 화면은 미확인).

실서버 확인 (서버 응답): 실제 디스코드·텔레그램 발송 안 했음. 로컬 개발 DB를 통한 앱 알림 API 응답은 확인했음. 운영 중인 cs 프로젝트 서버의 수정 후 동작은 배포 전이라 확인하지 않았음.
