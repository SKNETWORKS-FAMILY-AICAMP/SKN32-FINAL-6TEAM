# 경보 원본 예약 수집 — 2026-10-10 09:05

원본 5종을 새 회차에 보관했다. ITS는 기존과 같은 제공처 월간 한도 초과라 추가 사용자 알림을 생략한다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 예산 설정 확인·수집 실행 | 끝 | 1/1 = 100% |
| 경보 소스 읽기 | 일부 성공 | 5/6 = 83% |
| 기존 실패 원인 대조 | 끝 | 1/1 = 100% |

## 실행과 근거

여행 검증·지속관리 중 원본 수집만 수행했다. [운영 기준](../../operations/alert-snapshots.md)과 개인 설정의 공용 중단선 0.2·소스별 하루 시도 2회·월 시도 62회를 확인했다. 실행기 해시는 직전 검증판과 같았다.

```powershell
python -B -m scripts.capture_alert_scenarios --archive-only
```

실제 출력:

```json
{"run_id": "2026-10-10_090529_7b078f86", "status": "archived_partial", "snapshots": 0, "should_notify": true}
```

종료 코드는 1이다. [이번 원본·실행 결과](../../../var/alert-snapshots/real/2026-10-10_090529_7b078f86/)에 공급자 본문·원래 확인 시각·캐시 여부·적용 제한을 보관했다. 기상특보·지진·UTIC·지하철 공지는 새 HTTP 응답 각 1개, 재난문자는 캐시다. ITS의 당일 첫 시도는 HTTP 401이며 본문 `resultCode=4001`, 「월간 API 호출 한도를 초과하였습니다」였다. 실패를 경보 없음으로 해석하지 않았다.

실행기의 `should_notify=true`는 표면 실패 표기가 `budget_exhausted`에서 `http_401`로 바뀐 것을 감지한 결과다. 공급자 원문을 확인하면 [직전 회차](../../../var/alert-snapshots/real/2026-10-09_111600_e183aeb5/)와 같은 제공처 월간 한도 초과다. 따라서 새 실패 원인·새 사용자 조치에 해당하지 않아 [예약 알림 판단](../../../var/alert-snapshots/real/2026-10-10_090529_7b078f86/heartbeat-decision.json)에 알림 생략을 별도로 기록했다. 원래 실행 결과를 바꾸지 않았다.

## 보존·다음 회차

이전 상태 파일은 [교체 전 백업](../../../var/alert-snapshots/real/_backup/2026-10-10_090540_59e0d64c/)에 보존됐다. 원본은 새 폴더라 이전 회차를 덮지 않았다. 다른 코드·설정·한도·카운터를 초기화하거나 변경하지 않았다. 새 수집용 시도 기록은 기존 제한기가 관리한다.

고객 API·계정·접수·여행·브라우저·대체안 검사·채팅·고객 알림·관리자 설정·배포는 실행하지 않았다. 다음 예약에도 같은 제한과 원본 수집 범위를 유지한다. 조회 사이에 생겼다가 해제된 모든 사건을 확보했다고 주장하지 않는다.
