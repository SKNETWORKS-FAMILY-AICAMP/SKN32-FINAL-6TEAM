# 로딩 설문 · 빠른 거름 시험 — 다시 돌리는 법과 결과 (2026-10-19)

이 문서는 [작업 기록](2026-10-19_로딩설문_빈칸만묻기.md)의 시험을 **나중에 같은 방식으로 다시 돌릴 수 있게** 남긴다. 시험에 쓴 임시 사본 · 시험용 DB 는 이 문서를 반영한 뒤 지운다(아래 「뒷정리」).
확인 범위: 서버 코드를 이 PC 의 시험용 DB 로 시험했다. mock 서버 시험은 해당 없음. **실서버 확인**은 x600 서버의 반영 기록(아래 「x600 서버 반영」)만 읽었고 화면 · 고객 경로 동작은 보지 않았다.

## 1. 환경 (도커가 없는 PC)

- 이 PC 에는 도커가 없어 conda 환경의 PostgreSQL 16(pgvector 포함)을 임시 폴더에 새로 만들어 썼다. CI(깃허브)는 `pgvector/pgvector:pg16` 컨테이너 — 같은 버전 계열이다.
- 격리 사본: 원격 role-manager 의 커밋을 `git archive` 로 폴더에 풀었다(git 저장소가 아니다 → 아래 「알려진 실패」의 일부 원인). 시험에 필요한 폴더: `final_project_cs/` · `final_project_sample/`(`acop_composer` 가 여기에 있다 — `PYTHONPATH`) · `ruff.toml`. 비교용으로 같은 방식으로 풀은 「원격 판 사본」을 따로 두었다.
- 파이썬 3.12, `requirements.txt` 설치된 환경.

## 2. 시험용 DB 만들기 · 띄우기

```bash
# 한 번만 — 데이터 폴더 만들기 (<PGBIN> = conda 환경의 Library/bin, <DATA> = 임시 폴더)
<PGBIN>/initdb -D <DATA> -U postgres --auth=trust -E UTF8 --locale=C

# 띄우기 — 포트 5470, 시간대 서울(CI 가 시간대를 서울로 확인한다), 연결 여유 200
<PGBIN>/postgres -D <DATA> -p 5470 -c timezone=Asia/Seoul -c max_connections=200

# 한 번만 — 시험 DB
<PGBIN>/psql -h 127.0.0.1 -p 5470 -U postgres -c "CREATE DATABASE acop_ci"
```

- ★도구 안에서 `pg_ctl` 로 직접 띄우면 도구와 같이 죽는다 — 앱 관리 실행 설정(`.claude/launch.json` 에 위 `postgres` 명령을 등록해 `preview_start`)으로 띄웠다.
- ★이 PC 는 가상 메모리가 빠듯해(1~3GB) 시험 도중 DB 서버가 한 번 죽었다(`the database system is in recovery mode`) — 그 회차의 오류 93건은 전부 연결 실패였다. **같은 DB 에 시험을 동시에 돌리지 않는다**(전체 시험 중에 대조 시험을 겹쳐 돌린 것이 원인으로 의심된다). 병렬(`-n`)도 쓰지 않는다.
