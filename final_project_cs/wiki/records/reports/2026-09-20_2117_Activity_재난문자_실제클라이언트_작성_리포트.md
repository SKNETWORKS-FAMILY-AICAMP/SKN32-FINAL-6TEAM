# Activity — 재난문자API 실제 클라이언트(disaster_msg.py) 작성

## 1. 작업 목표

사용자가 "재난문자 클라이언트도 실제로 만들어줘"를 요청. `tour_api.py`(313줄, 실 키로 검증됨)에 준하는 실제 HTTP 클라이언트를 재난문자API에도 만든다. API 키가 없어 실제 호출 테스트는 못 하지만, 지어낸 스펙으로 만들지 않기 위해 웹 조사로 실제 근거를 먼저 확보했다.

## 2. 조사

WebSearch·WebFetch로 확인:
- 데이터셋: data.go.kr 15134001 "행정안전부_긴급재난문자", 실제 호출은 재난안전데이터 공유플랫폼(safetydata.go.kr)의 V2 API
- 엔드포인트: `https://www.safetydata.go.kr/V2/api/DSSP-IF-00247`(자매 API인 대피소 DSSP-IF-00195의 실제 코드 예제로 URL 패턴·파라미터 확인)
- 공통 파라미터: `serviceKey`·`returnType=json`·`pageNo`·`numOfRows`·`rgnNm`(지역 필터, 검색으로 확인)
- 응답 모양: 최상위 `body` 키 아래 배열(자매 API 예제로 확인)
- 필드명: `SN`·`CRT_DT`·`MSG_CN`·`RCPTN_RGN_NM`·`DST_SE_NM`·`EMRG_STEP_NM` — 검색으로 확인, 013·016 마이그레이션 설계와 일치함을 대조
- **확인 못 한 것**: 날짜 범위 필터 파라미터 이름, 오류 봉투 정확한 모양, `CRT_DT` 정확한 포맷, 키가 공통 키(`data_go_kr_key`)로 되는지

## 3. 실제 수행 내용

### `app/infrastructure/travel/disaster_msg.py` (신규)
- `DisasterMsgSource(TravelSource)` — `tour_api.py`와 같은 규율(①~④, `base.py`)을 따름
- `recent(since_hours, region_name)`: `rgnNm`으로 지역 필터(확인된 파라미터), 날짜는 **서버에 안 맡기고 클라이언트 쪽에서 `CRT_DT` 기준으로 자름**(`_recent_only`) — 서버 날짜 파라미터 이름을 확신 못 해서
- `near(lat, lng, at)`: `read_tools.disaster()`가 기대하는 인터페이스에 맞춘 래퍼. **위도·경도를 실제로 안 쓴다** — 이 API가 좌표가 아니라 지역명으로 걸러서다. 이게 `_disaster_blocks()`의 "지역 관련성 미확인" 캐비앗이 판단이 아니라 API의 구조적 한계임을 보여주는 발견
- `_body_error` 오버라이드: `header.resultCode≠00` 류를 방어적으로만 봄(확신 없음을 코드 주석에 명시)
- 시각 파싱 실패 시 "오래됨"으로 단정하지 않고 포함시킴(모름을 모름으로)
- 모듈 docstring에 "확인됨" vs "추정(미검증)" 표를 명시적으로 분리 — `tour_api.py`의 "실측" 수준에 못 미침을 숨기지 않음

### 조립
- `app/core/settings.py`: `disaster_api_key` 필드, `rate_disaster_msg_per_day`(확인: 플랫폼 공통 일일 1,000건) 추가
- `app/infrastructure/travel/base.py`: `build_travel_sources()`가 키 있으면 `DisasterMsgSource` 조립, 없으면 `unavailable["disaster"]`에 발급 안내
- `.env.apikeys.example`: `ACOP_DISASTER_API_KEY` 항목 추가, 공통 키 적용 여부 미확보를 주석으로 명시

## 5. 미해결 이슈·다음 작업 제안

- **실 키로 첫 호출을 아직 못 했다** — 이게 가장 큰 리스크다. 키가 생기면 가장 먼저 `disaster_msg.py` 모듈 docstring의 "확인/추정" 표를 검증하고 갱신해야 한다.
- 위도·경도 → 지역명 역지오코딩이 없어서 `near()`가 사실상 전국을 반환한다 — `_disaster_blocks()`의 지역 관련성 미확인 문제의 근본 원인.
- 페이지네이션 루프가 없다 — `numOfRows=100`을 넘는 발령이 있으면 놓친다.
- 재난문자 키가 공통 키로 되는지, safetydata.go.kr 별도 가입이 필요한지 미확보.
