## 아래층

### 1. 무엇을 어떻게 합쳤나 (방침)

- 정본은 요식 원장(`dining` 스키마). 대체 후보 = 장소 목록 + 근처 원장 가게를 **그 여행 전용 장소**로 들인 것([nearby.py](../../../app/modules/travel_ops/dining/nearby.py)), 판정 = 방문 시간대 원장 판정(`dining.ledger.dining_states`).
- 우리 쪽 옛 방식(원장이 후보를 직접 냄: `ledger_pool` · `DbLedgerView` · `ToolLedgerView` · `read.dining_alternatives` · `ledger_place_for` · `link_trip`)은 걷었다.
- 남긴 것: 마지막 주문 20분 탈락·60분 경고(원장 판정에도 `order_ok` 로 적용), 낮 감시 재점검 한도, 조건 풀기·그 자리 찾기·지금 위치 근처, 일정 전체 재판정(`_fit`), 롤백 다시 적용, 시나리오 모드의 원장 격리, 여행별 알림 기록(마이그레이션 220).
- **싣지 않은 것**: 활동팀의 CSV 임시 우회(`csv_places` · `_CsvFallbackTour` · 카카오 근처 힌트). 관광공사 호출 제한을 피하려는 활동팀의 임시 방편이고 자료 파일이 우리 쪽에 없다. 카카오 근처 힌트는 우리 시험용 카카오 대역과 인자가 안 맞아 접수 7건을 깨뜨렸다.
- 마이그레이션: 우리 `220_dining_notice_scope` 는 그대로 두고(이미 적용된 이름은 바꾸지 않는다 — wiki/data/migrations.md 규칙 1·3) 팀의 `220_dining_runtime_link` 는 새 번호 `224_dining_runtime_link.sql` 로 들였다.

### 2. 코덱스 점검에서 나온 팀 코드의 문제 (1차 — 팀 코드 자체)

모두 [추정]이 아니라 코드를 읽어 확인한 것이다(코덱스 · 제가 대조).

| 순위 | 문제 | 조치 |
|---|---|---|
| 1 | 등록할 때 원장을 못 읽으면 닫힌 식당이 그대로 등록된다(경고는 서버 로그에만) | 병합 중 `with_ledger` 에 경고 로그와 「원장 못 읽음」 표시를 더했다. 등록 응답에 사용자 경고를 싣는 것은 **미해결**(아래) |
| 2 | 원장 후보·판정 SQL에 `tenant_id` 조건이 없다 | **오류 아님으로 판정** — `dn_place` 에는 테넌트 열이 없고 원장은 운영 한 곳의 공용 자료다. 다른 테넌트 노출 경로는 없음. 테넌트 격리가 필요해지면 설계를 바꿔야 한다 |
| 3 | 구글 가격 조회가 한도 없이 호출된다(팀 사용자 결정 9/30) | 우리 결정(9/28: 식당은 가격으로 순위 매기지 않음)과 맞춰 **가드레일 스위치 뒤 기본 꺼짐**으로 감쌌다. 켤 때는 호출 수를 세고 무료 한도 초과 시 운영 알림 1회 |
| 4 | 이름이 같은 식당 둘이면 여행 전용 장소를 하나로 합쳐 잘못 잇는다(`adopt_places`) | 이름 충돌 후 실제 저장된 행의 번호로만 잇도록 이미 걸러 있음 — 동명이인 둘 다 후보로 못 들어오는 한계는 **남음** |
| 5 | 조용히 삼키는 곳 4곳(원장 읽기 실패) | 4곳 모두 경고 로그(예외 종류만, 원문·키 없음) 추가 |

### 3. 코덱스 점검 (2차 — 병합 결과)

| 순위 | 문제 | 조치 |
|---|---|---|
| P1 | 시나리오 모드의 완화 제안(`watch_relaxed`)이 실제 원장을 읽고 장소를 저장한다 | **병합 전 코드에도 있던 문제.** 미해결 — 시나리오 감시 경로에 `use_ledger=False` 를 흘려야 한다 |

| P2 | 시간대 없는 시각을 DB 세션 시간대로 읽는다 | **고침** — 원장은 서울 시각으로 읽는다 |

### 4. 병합 중 시험으로 잡은 결함

- 원장 파일(`dining/ledger.py`)이 코어(`replan`)를 import 하면 시험이 단독으로 읽지 못한다 — 기본 20분 값을 파일 안에 두고 [시험](../../../tests/unit/travel/test_dining_order_margin_same.py)이 코어 값과 같은지 지킨다.
- 대체 항목 기록에서 카드 결제 값이 빠졌다(`applied_record`) — 되살렸다.
- 「확인 필요」 문구에 서울 변환이 빠져 있었다 — 서울 시각 시험이 잡았다.
- 호출 한도 세기 표(`external_call_budget`)에 팀이 더한 표시 줄(`:over_free`, 상한 0)이 사용량 보고에서 「소진」으로 보일 뻔했다 — 보고에서 뺐다.

### 5. 시험 결과 (두 줄로 나눠 적는다)

- **자동 시험(실제 DB 복사본 위)**: 단위·계약·보안·구조 2,525 통과 · 통합(RAG 제외)·시나리오 496 통과 · e2e 일정 생성 40 · 접수 20 통과.
  - e2e 일정 생성·요식 시험은 **식당 원장이 비어 있는 DB**(CI 조건) 기준이다. 개발 DB처럼 원장에 1,800곳이 들어 있으면 일정 초안에 식당이 섞여 팀 시험 12건이 깨진다(팀 시험이 스스로 밝힌 전제 — `test_trip_dining_ledger.py`).
- **병합 전 코드에서도 똑같이 실패하는 것**(병합이 만든 문제 아님): 완화 제안 2건 · 일정 생성 SSE 1건 · RAG 검색 15건(로컬 임베딩 서비스 꺼짐).
- **실서버 확인**: 안 했다(x600 서버·cs 프로젝트 서버 모두 안 건드렸다).
