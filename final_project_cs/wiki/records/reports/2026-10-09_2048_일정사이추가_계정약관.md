# 일정 사이 추가·계정 버튼·약관 관리 반영

스크롤한 목록 가운데에 가까운 경계에서 바로 일정을 추가하고 장소를 검색할 수 있게 했다. 계정 버튼 형식을 통일하고 필수 약관은 전문 확인으로, 선택 동의만 관리 목록으로 나눴다. 로컬 구현과 검증을 마쳤으며 공개 배포는 하지 않았다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 요청한 네 가지 동작 | 완료 | 4/4 = 100% |
| mock 서버 화면 시험 | 통과 | 81/81 = 100% |
| 관련 단위시험 | 통과 | 44/44 = 100% |
| 두 크기 화면 촬영 | 완료 | 14/14 = 100% |

## 바뀐 동작

- 목록의 이동→일정, 일정→이동 경계 중 현재 보이는 중심과 가장 가까운 곳 하나에 +를 표시한다. 화면 크기·목록 높이·스크롤이 바뀌면 다시 고른다. 시간축 높이는 늘리지 않고 44px 누름 영역과 초점·포인터 설명을 제공한다. 일차 시작/끝도 같은 일차 안에서 처리한다. 검증 완료 전·등록 후·미리 보기·필터·시간 편집·삭제 대기 중에는 신규 위치를 제시하지 않는다.
- 누른 경계 바로 아래에 일정 추가 양식을 연다. 날짜와 앞뒤 출발/도착 시각을 바탕으로 시작·끝의 초깃값을 넣고 사용자가 수정할 수 있다. 기존 장소 검색 API의 결과에서 좌표·출처·식별값을 고른다. 추가는 기존 수정 API에 여섯 필드를 한 번에 보내며, cs 프로젝트 서버가 앞뒤 이동과 제약을 다시 검사한다. 실패하면 선택·입력을 유지하고 취소하면 원래 +가 보이도록 돌아온다.
- Google·Kakao 등 활성화된 계정 방법은 공식 아이콘과 `회사 계정으로 계속`이라는 같은 형식, 높이 48px·같은 정렬을 사용한다. 연결/해제와 게스트 일정 보관 동작은 유지한다.
- 마이페이지 관리 목록에는 선택 동의 세 항목만 둔다. 필수 약관 둘은 `약관 전문 확인`에서 읽고 전환할 수 있다. 철회·동의 변경 단추는 전문 창에 두지 않는다. Tab/Shift+Tab은 창 안에서 순환하고 Escape/닫기는 원래 버튼으로 초점을 돌린다. 최초 이용의 필수 동의는 유지한다.

빈 계획에는 검색 기준 일정이 없으므로 기존 이름 직접 입력을 유지한다. 같은 시작 시각 또는 앞뒤 이동을 넣을 여유가 없는 경우 최종 삽입 가능 여부는 cs 프로젝트 서버의 재배치·보호 규칙이 판단한다. 검색 결과를 신규 방문 시각의 검증 결과처럼 표시하지 않는다.

## 검증 범위와 결과

mock 서버 시험 81/81 (화면 반응): 계정·약관 36, 일정 추가·설문·이동 표시 7, 기존 카드·지도·목록 회귀 38의 고유 시험 합계다. 첫 회귀 실행 77/79에서 추가 시험의 동적인 선택자 두 건이 실패했고, 고정된 위치 선택자와 실제 가시 범위 확인으로 보완한 뒤 추가 4/4·통합 로그인 2/2가 통과했다. 마지막 제품 빌드에서는 일정 추가·기존 흐름 7/7와 촬영 2/2가 다시 통과했다. 촬영은 기능 시험 81개에 합산하지 않는다.

단위시험 44/44: 삽입 시각·일차 경계 4, 신규 일정 요청 8, 되돌리기 연결 6, 약관 모델·본문·동기화 26. 타입 검사와 변경 코드 ESLint, 공백 검사가 통과했다. Chrome 375×812와 1280×812에서 가로 넘침을 검사하고 실제 렌더링 7장씩 촬영했다. 넓은 화면에서도 기존 휴대폰 틀은 유지한다.

실서버 확인 (서버 응답): 안 했음. 실제 장소 검색·외부 OAuth·x600 서버의 cs 프로젝트 서버 검증 및 배포는 이번 작업에서 하지 않았다. 지도 배경 타일만 공개 OpenStreetMap을 사용했다. 일정과 계정 응답은 mock 서버 데이터다. mock 응답의 항목 정렬은 실제 `assemble.collect`의 날짜·시작시각 순서와 맞췄지만 실제 이동시간 재계산 결과를 증명하지는 않는다.
