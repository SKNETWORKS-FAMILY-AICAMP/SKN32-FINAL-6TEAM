## 작업 중 바로잡은 것

- **스냅숏을 받는 방식에 따라 그리는 순서가 달랐다.** 여러 번 나눠 받으면 날짜 목록을 「확인 시작」보다 먼저 정했고, 한꺼번에 받으면 나중에 정했다. 단위 시험이 찾았다. 날짜는 읽기 끝에 정하도록 맞췄다.
- **목록 머리 개수의 분모가 틀렸다.** 「장소 1/1」처럼 지금까지 나타난 장소만 셌다. 목업처럼 「장소 1/4」가 되도록 읽은 줄에서 전체를 세게 바꿨다.
- **카드가 흐리게 남은 듯 보인 현상은 결함이 아니었다.** 앱 내장 브라우저에서 확인할 때였는데, 창이 화면을 초당 2장만 그리고 있어 나타나는 애니메이션이 시작되지 못한 것이었다(`requestAnimationFrame` 1초에 2번). 애니메이션이 끝난 뒤에는 정상으로 보였다.
- **공통 지도의 최소 높이가 이 화면의 지도 칸보다 크다.** 그래서 지도 아래 「좌표가 없는 일정」 안내가 잘린다. 화면이 「위치 미정 · ○○」을 지도 위에 직접 보이게 했다. 지도 크기 맞춤은 CSS 마감 몫으로 인계했다.

실제 서버 연결 시험은 하지 않았다. 이번 범위가 아니고, 연결은 백엔드 몫이다. 실제 휴대폰과 다른 브라우저도 확인하지 않았다.

## 남은 문제·다음 작업

1. **2단계 결과 보기**(시나리오 2) — 카드 펼침, 카드↔지도 핀 선택, 일차 전환, 목록 높이(손잡이).
2. **3~5단계** — 카드 동작(자동 추천·잠금·삭제·되돌리기), 하단 버튼 줄(전체 자동 추천 → 재검증 → 여행 등록), 수정 화면(검색·후보·사진). 대부분 서버 API가 없어 「협의 필요」다. 인계 문서 §4에 정리했다.
3. **백엔드 연결** — 확인 단계(checking), 장소별 검사 결과, 이동, 진행 이벤트가 협의 필요다(인계 문서 §4).
4. **CSS 마감(Codex)** — 지도 칸 크기, 지도 위에 올리는 시트, 핀 상태색·경로 선(지도 어댑터 구조 변경 필요), 그림자·모션, 뉴트럴 테마.
5. **로컬 빌드 폴더** — `.next-mock/`은 앞서 시험할 때 생긴 빌드 폴더다. 시험 폴더 이름이 바뀌면서 Git 제외에서 빠져 미추적으로 보인다. 커밋하지 않았다.
