# 실제 SQL 구조 감사와 wiki 추가 댓글 반영

로컬 개발 DB와 x600 서버의 cs 프로젝트 DB 모두 옛 이커머스 표 5개가 남아 있습니다. 로컬 SQL 제외 규칙도 실제 배포 코드에는 없습니다. 기존 업무 DB의 삭제·DDL 적용·배포는 하지 않았습니다.

## 확인 근거와 한계

[SQL 현황·그림·전체 구조 검색](../../../../program/research/sql_review_2026-10-11/index.html)은 실제 읽기 전용 조회를 사용했습니다. 화면 캡처로 표시하지 않았습니다. 고객 행·JSON 값·함수 본문·접속 정보는 저장하지 않았습니다. 각 환경의 원본 JSON에 확인 시각·열·제약·인덱스가 있습니다.

과거 5표의 내부 외래키 4개와 customers로 나가는 외래키 3개가 남았습니다. 다른 표가 과거 5표를 참조하는 외래키는 전체 조회에서 0개입니다. DB 뷰·사용자 함수의 이름 후보·검사한 Python SQL 문자열의 참조도 0개였으나 동적 SQL·ORM·수동 작업·다른 이름의 구조·업무 값까지 부재를 보증하지 않습니다.

place_aliases_customer_scope는 NOT VALID이고 place_aliases는 PK 대신 고객별 유일 인덱스를 사용합니다. 038 SQL에서 의도한 방식이므로 즉시 결함으로 단정하지 않았고 기존 행의 충족 여부는 미검증으로 남겼습니다. INVALID 인덱스는 0개이며 case_events·outbox의 핵심 UNIQUE는 확인했습니다.

## 댓글별 반영

- 공통·여행 시험은 C로 분리했습니다. 여행 사례로 공통 불변식을 확인하는 A와 C를 대안으로 제시한 설명을 정정했습니다. 미분류·중복은 실행 오류입니다.
- DB의 실제 환경별 표·뷰·열·제약·인덱스와 관계도를 만들었습니다. 파일 수와 적용 수를 구분했습니다.
- 현재 평가 절차·판본표·실험별 독립 보고서 52개를 연결했습니다. 새 중앙 모델 등록 서비스는 도입하지 않았습니다.
- 디렉토리 작업 경계는 유지하고 기능 책임표를 설계안으로 정정했습니다. NASA 책임 배정과 GitHub 경로별 검토의 차이를 근거로 적었습니다. 최초 발명자·산업 표준 인증을 주장하지 않습니다.
- 실제 결정 문서 2개에 결정·구현·검증 머리말과 환경 표를 넣었습니다. 구현 증거를 추정하지 않고 unverified로 표시했습니다. 모든 페이지의 전환이나 새 필드의 자동 의미 검증을 주장하지 않습니다.
- 실제 기존 wiki 검사 프로그램·대상·명령·결과를 보여 줍니다. 중복 검사 프로그램은 만들지 않았습니다.

## 검증

[실행 결과 요약](../../../../program/research/sql_review_2026-10-11/audit-summary.json): 공통 관련 35개·여행 관련 17개·임시 DB 재실행 4개·배송 예문을 여행 안내로 교체한 기존 시험 1개가 통과했습니다. DB 시험은 자신이 만든 임시 DB에서만 쓰기를 수행했고 기존 업무 DB는 읽기 전용으로 조사했습니다.

분리 수집은 공통 775개·여행 6,004개, 교집합·미분류 0개였습니다. 전체 공통 실행은 완료하지 않았습니다. 처음 수집의 임시 경로 권한 오류는 워크스페이스 임시 경로로 보완했고 동시 추가된 시험 2개를 분류한 뒤 재수집했습니다. 실패·중단 로그도 보존합니다. 기본 live 제외 244개는 실행하지 않았습니다. Windows 콘솔 종료 시 pyreadline3 예외 출력이 있었으나 선택 회귀의 pytest 종료 코드는 0입니다.

정적 HTML·자료·링크·백업·이미지 검사 29/29, 모의 DOM JavaScript 8/8을 확인했습니다. 실제 브라우저 렌더링은 로컬 파일 접근 도구 정책상 확인하지 못했고 우회하지 않았습니다. 최종 wiki 300문서 검사에서 위반 0개·기존 길이 경고 2개입니다. 과거 records 전체의 정상 여부를 뜻하지 않습니다.
