# SFT 학습·서빙 템플릿/토크나이저 동일성 + 근거 판별 일반화 가능성 (2026-10-31)

작성: Claude Opus 5.5 하위 작업자, 2026-10-31 04:40~05:30 KST. **모델 적재·추론 0 · GPU 0 · 유료 0 · x600 접속 0 · 고객 자료 0 · 운영 변경 0 · 커밋 0.** 로컬 Ollama 는 `/api/version`·`/api/tags`·`/api/ps`·`/api/show`(메타데이터, 적재 없음)만 불렀고 `/api/ps` 는 비어 있었습니다. 이전 검토물은 읽기만 했습니다(해시 19/19 동일).

## 0. 결론

1. **배포 서빙과 HF 학습 쪽의 어휘는 같습니다.** 토큰 262,144개·병합 514,906개·특수 토큰 24개가 배포 blob(로컬 Ollama `/api/show`, parent `sha256-4c27e0f5…`)과 HF `google/gemma-4-E4B-it@ee0ef602` tokenizer.json, 검사기 어휘 파일 `ggml-vocab-gemma-4.gguf` 사이에서 모두 일치했습니다.
2. **템플릿이 같습니다(조건부).** 배포 호출(`[system, user]`, `think=false`, 도구 없음)의 서빙 prompt 는 Ollama v0.31.1 `gemma4` small renderer 를 옮긴 포트로 만들었습니다. 이 문자열은 HF 현재 템플릿(sha `0a2c8073…`)과 Ollama 기준 E2B 템플릿으로 렌더한 결과와 **10/10 = 100%** 같았습니다(픽스처 7 + 규모 3). 학습 문자열은 「서빙 prompt + 정답 JSON + `<turn|>\n`」과 7/7 = 100% 같았습니다.
3. **토큰이 같습니다(이 표본 한정).** 서빙 prompt 토큰은 Ollama BPE 포트와 llama-tokenize(stdin, BOS 없음)에서 10/10 = 100% 같았습니다. 학습 문자열을 한 번에 토큰화해도 서빙 prompt 토큰이 접두사로 보존되고, 이어지는 토큰은 「정답 토큰 + `<turn|>` + `\n`」과 7/7 = 100% 일치했습니다(경계 `\n` | `{"` 병합 없음).
4. **남은 차이 3건**이 실제 장애 후보입니다(§2).
   - (a) 어휘 GGUF 에 내장된 템플릿은 생성 프롬프트 끝에 빈 생각 블록 `<|channel>thought\n<channel|>` 을 붙입니다. 서빙은 붙이지 않습니다.
   - (b) Ollama BPE 는 같은 순위의 병합을 heap 순서로 처리합니다. 포트로 예측한 결과, 반복 문자(ㅋㅋㅋㅋㅋ·ㅎㅎㅎ·ㅠㅠㅠ 등)에서 HF 와 토큰이 달라집니다.
   - (c) 검사기 `token_budget.count` 는 Windows 텍스트 모드 임시 파일을 써서 줄바꿈마다 `\r` 을 셉니다. 그래서 토큰 수를 **208–255개 과대** 추정합니다. 실제 system 은 7,605가 아니라 **7,439토큰**입니다.
5. **근거 판별:** 어휘 목록 없이 일반적으로 잡히는 것은 두 부류뿐입니다(이 합성 표본 기준, §3).
   - **구조 결함**: 정답 JSON 전체 비교(M1)로 잡힙니다.
   - **일정 개체 언급**: 사례 자료에서 뽑은 개체로 잡히고, 거부 대상 7/26, 오표시 0/17이었습니다.
   - 나머지 **19/26**(외부 세계 주장·기억 약속·거절·다른 대상 추천·날씨)은 표면 신규성으로 가를 수 없습니다(AUC 0.409). 의미 판단(사람 rubric 또는 승인된 판정 모델)이 필요합니다.

## 4. 다음 순서 (진행 0/5)

1. 라우팅·채팅 구현 담당이 후보 0.2 를 반영할 때 T3 를 고칩니다. 방법은 렌더된 서빙 prompt 전체를 stdin 과 `--no-bos` 로 세는 것입니다. 이어서 T1 렌더 동일성 검사와 M1 정답 전체 비교를 fail-closed 로 넣습니다.
2. 학습 도구를 정할 때(G5) 다음 셋을 고정합니다.
   - HF 템플릿 sha `0a2c8073…`
   - BOS 를 문자열로 1개만 둠(토크나이저 자동 BOS 금지)
   - 완성부 `\n` 손실 제외 여부
   그다음 서빙과 같은 토크나이저로 `input_ids` 를 만들지 정합니다(T2).
3. T2 를 실제 코드로 확인합니다. Go 도구가 있는 곳에서 Ollama `tokenizer` 패키지로 `좋아요ㅋㅋㅋㅋㅋ`를 토큰화하면 됩니다. 또는 승인된 서빙 호출이 있을 때 `prompt_eval_count`를 대조합니다.
4. M3 를 검수 표시 코드(`R_ENTITY_IN_FREE_TEXT`)로 넣고, 남은 의미 부류는 사람 rubric 으로 보냅니다. 판정 모델은 승인 뒤 사람 라벨로 교정합니다.
5. 별도 작성자가 새 보류 탐침을 쓰고 한 번만 실행합니다(이 보고의 79행은 맹검이 아님).
