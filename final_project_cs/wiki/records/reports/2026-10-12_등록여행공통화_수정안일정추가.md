## 변경

- 수정안에서 추가 위치 계산과 `+` 렌더링을 다시 켰습니다. `+`를 누르면 기존 직접 수정과 같은 절차로 수정안을 먼저 저장하고 추가 입력을 엽니다. 실패하면 입력 화면으로 넘어가지 않습니다. 취소 후 목록에 `+`가 다시 표시됩니다.
- 수정안 전환 시 목록을 맨 위로 초기화하고 이전의 부드러운 스크롤을 취소합니다. 이어지는 휠·터치 입력을 차단하고 새로 시작한 스크롤은 허용합니다. 추가 입력도 맨 위에서 엽니다. 변경 전으로 돌아갈 때는 저장한 위치를 복구합니다.
- 등록 여행도 검증 화면의 날짜 표시 재측정, 스크롤 중 날짜 숨김과 최상단 복귀, 목록 확대 설정·두 손가락 전환, 선택 시각과 따라오는 시각의 여백 계산을 공유합니다. 정상 접힌 카드의 테두리를 숨기고 예약 정보가 있는 일정만 예약 표시를 둡니다. 일정/채팅 전환은 날짜 아래 줄로 옮겼습니다.
- 새 등록은 저장된 같은 판의 검증 이동을 일정 사이에 보관합니다. 기존 여행은 본인의 연결된 접수에서 현재 인접 일정과 이름·종류·날짜·시각·좌표가 일치하는 이동만 읽기용으로 복구합니다. 이동 시각과 경로선에서 같은 항목을 사용하고 실제 DB 일정은 다시 쓰지 않습니다. 이미 저장된 이동을 우선합니다. 바뀐 장소에 예전 경로를 붙이지 않습니다.
- 채팅에서 이전 내용을 읽는 동안 위치를 유지하고 최신 대화 이동 단추와 새 메시지 표시를 제공합니다. 직접 보낸 메시지는 최신 위치로 이동합니다. 단추를 키보드로 실행하면 대화 영역으로 초점을 돌립니다. 예약 보호·SSE·입력 초안·기존 알림은 유지합니다.

## 확인 범위와 실행 결과

mock 서버 시험 23/23 (화면 반응): 실제 설치 Chrome, 375px/1280px 및 기존 320px/1440px 배치 시험, 움직임 줄이기 포함. 수정안 전환의 남은 휠 차단·새 휠 허용·추가 입력·취소 후 `+`, 날짜 표시 복구, 확대·전체 날짜 전환, 예약·시각·경로, 채팅 최신 이동·새 답변·직접 전송·키보드 초점과 가로 넘침을 확인했습니다. 실제 휴대폰의 가상 키보드는 확인하지 않았습니다.

실서버 확인 (서버 응답): 로컬 개발 DB를 사용하는 cs 프로젝트 API 시험 24/24. 새 등록·반복 등록·기존 여행 이동 복구·기존 DB 비변경·변경 좌표의 과거 경로 제외·다른 고객 접근 차단·예약 번호 없는 예약 선언을 확인했습니다. x600 서버의 cs 프로젝트 서버 응답과 공개 서비스 배포는 확인하지 않았습니다. 외부 이동 공급자의 실시간 품질을 검증한 결과는 아닙니다.

최종 화면 고유 23개는 다음 실행에서 중복 없이 합쳤습니다. 등록·예약·채팅·배치 11개는 `chrome-release.log`, 수정안 전환 2개는 `chrome-corrective.log`, 날짜 선택 회귀 10개는 `chrome-marker-final.log`입니다. corrective 실행에는 이미 통과한 날짜 2개·등록 2개도 포함되어 있어 합산에서 제외했습니다. 경로선 6개와 마커 안내 제거 3개는 앞선 `chrome-shared.log`에서 통과했으며 최종 23개의 분모에 넣지 않았습니다.

API 고유 24개는 최종 전체 실행에서 기존 21개와 새 2개가 통과했고, 새 시험 1개가 응답 봉투를 잘못 읽어 실패했습니다. 시험을 고쳐 새 3개를 재실행해 3/3 통과했습니다. 이 합계는 한 번의 24/24 실행이 아닙니다. 단위 시험 88개와 정적 검사 ESLint·TypeScript 2개는 각각 별도 실행입니다.

중간 실패도 보존했습니다. 초기 화면 13/16·공통 화면 28/32의 시험 기대값/입력 속성 오류, 최종 실행 전 TypeScript의 정규식 인자 오류, 수정안 시험이 텍스트 없는 단추를 `textContent`로 읽던 오류를 바로잡았습니다. 최종 Chrome 13개 실행의 11통과·2실패도 그대로 보존하며 corrective 재시험으로 마무리했습니다. 단위 시험 종료 후 pyreadline 콘솔 정리 경고가 있었고 88개 판정은 통과했습니다.

시험 명령은 `pytest tests/unit/travel/test_registered_moves.py tests/unit/travel/test_route_shape.py tests/unit/travel/test_trip_intake.py tests/unit/travel/test_intake_rules.py -q`, `pytest tests/e2e/test_trip_intake_api.py tests/e2e/test_registered_trip_routes.py -q` 및 `playwright test --config playwright.location.config.ts`의 관련 파일 선택입니다. Chrome은 독립 작업 사본의 production 빌드로 실행했습니다. [시험 대상 원본/사본 해시 15/15](../evidence/2026-10-11_registered-trip-parity/source-hashes.json)로 변경 파일 일치를 확인했습니다.
