# 하루 요약 응답 지연 수정 — 2026-10-12

## 결론

[실측] Oracle ARM의 하루 요약 버튼 요청을 기존 일정에서 직접 읽도록 수정하고 실제 앱에 반영했다. 같은 시험 여행·날짜·문장으로 측정한 응답은 수정 전 175.075초, 수정 후 0.320초였다. 일반 자유 질의와 모델의 전체 품질 문제가 해결됐다는 뜻은 아니다.

## 원인과 변경

- 수정 전 모델은 이미 메모리에 올라가 있었다. 실제 추론 엔진은 llama.cpp이며, 개발사 배포 Gemma E4B QAT Q4_0 원본을 사용했다. 우리 추가 학습 어댑터는 연결되지 않았다.
- 하루 요약 요청에도 모델 판단을 기다렸고, 한 번 측정한 175.075초는 화면의 90초 작업 제한을 넘었다. 모델 연결 단절이나 PostgreSQL 장애로 단정할 근거는 없었다.
- 웹 버튼은 `summary_day`로 날짜를 전달한다. 본인 여행·날짜·정해진 요약 문장을 확인한 뒤 기존 일정 정보로 응답한다. 자유 문장이나 변경 요청을 무조건 이 경로로 보내지 않는다.
- 기존 Case·감사·중복 처리와 일정 읽기 전용 동작을 유지했다. DB 구조와 모델 프로세스는 변경하지 않았다.
