# basement 네 폴더 점검 — 2026-10-07

`[사용자 요청]` 도메인 폴더를 칸으로 나눈 것(D-CS-013)에 이어 「코어 쪽 폴더도 다시 점검」. 업무 도메인 폴더(`app/domains/`)는 2026-10-06 에 정리했고, 이 네 폴더는 그때 손대지 않았다.

## 한 줄 결론
**코어는 다른 폴더를 하나도 안 부른다(0).** 층끼리 부르는 방향에서 어긋난 곳은 **하나의 원인**이었다 — 코어의 가림 함수(`masked` · `mask_json`)를 표현 층 파일(`presentation/security.py`)이 다시 내보낸 것을 응용 · 인프라 · 도메인이 거쳐 쓰던 것. 고쳤고 방향을 고정하는 시험을 더했다.

## 어떻게 쟀나
`app/` 아래 모든 `.py` 의 `import` / `from … import` 를 AST 로 읽어, 폴더 → 폴더 **서로 다른 (파일, 대상 모듈) 짝의 수**를 셌다(함수 안의 늦은 import 포함).
**놓칠 수 있는 것:** 문자열로 부르는 동적 import(`importlib` · 설정 파일의 경로) · 상대 import(이 저장소는 절대 import 만 쓴다) · 시험 · 스크립트의 import(이 점검은 `app/` 안만 본다).

## 고친 것
- 응용(`classification.py`) · 인프라(`db/repository.py`) · 도메인(`core_hooks/feedback.py`) · 조립 루트(`composition.py`) · 표현(`ui/routes.py` · `api/cases.py`)의 가림 함수 import 를 **`app.core.redaction` 직접**으로 바꿨다. `presentation/security.py` 의 다시 내보내기는 다른 프로젝트가 쓸 수 있어 **남기되** 「이 저장소 안에서는 쓰지 않는다」고 적었다.
- **시험을 더했다:** `tests/architecture/test_basement_layers.py` — 코어는 다른 폴더를 못 부르고(0), basement 는 도메인을 import 로도 못 알고(0), 인프라는 응용 · 표현을 못 부르고(0), 응용은 표현을 못 부르고(0), 표현은 도메인을 못 부르며(0), 알고 있는 예외 셋은 **그날 수를 상한으로** 박았다(늘면 실패 · 줄이면 상한을 내리게 실패). 이유는 시험 안에 적었다.
- **빈 폴더 20개를 지웠다**(`core/access_action/**` · `core/shared/**` · `infrastructure/{auth,graph_projection,integrations,vectorstore}` · `presentation/{mcp,schemas,web}`). 파일이 하나도 없고 git 에도 없던 **로컬 찌꺼기**라 저장소와 x600 서버에는 처음부터 없었다.

## 발견했지만 이번에 안 고친 것 (사용자 결정 또는 후속)
1. **쇼핑몰 시절 자산 하나 — `infrastructure/messaging/mock_payment_publisher.py`.** 「결제 제공자 대역」이고 `tests/integration/messaging/test_payment_timeout_unknown.py` 하나만 쓴다. 시험 내용은 「시간 초과는 **모름**으로 남기고 자동 재시도하지 않는다」는 **일반적인 발송 규칙**이다. D-023(쇼핑몰 자산을 쓰지 않는다)에 따라 **기록(`legacy/`)으로 옮기고 시험을 여행 말로 다시 쓰는 것**이 맞아 보이지만 지우는 일이라 사용자 결정으로 둔다(D-023 「정하실 것」).
2. **`core/composer_stores.py`** — 작성기가 쓰는 **파일 저장소 구현**이다(「이 제품의 구현」). 구현이므로 코어보다 인프라 자리가 어울린다. 쓰는 곳이 적어(`composer_host.py` 등) 옮기기 쉽지만, 다른 세션 작업과 겹치는지 보고 옮긴다.
3. **인프라 바로 아래 흩어진 파일** — `ollama_chat.py`(10개 파일이 씀) · `turnstile.py`(3) · `oauth_providers.py`. 같은 종류 폴더(`llm/` · `auth/`)로 모으는 게 정돈되지만 import 가 퍼져 있어 **다른 세션의 미커밋 작업과 부딪힐 수 있어** 남겼다.
4. **큰 파일** — `presentation/ui/routes.py` 971줄(운영 화면 HTML 이 길다) · `application/controller.py` 734줄 · `presentation/ui/theme.py` 477줄 · `core/settings.py` 472줄. 나누는 게 이득인지 이번엔 판단하지 않았다.
5. **쓰이지 않는 작은 모듈 둘** — `core/graph_retrieval/port.py`(7줄 · `GraphStorePort`) · `infrastructure/messaging/ports.py`(9줄 · `MessageBrokerPort`). 규격만 선언한 `Protocol` 이다. 지우지 않았다(규격 문서 역할).
6. **`wiki/index.md` 12행**이 「`access_action/` 은 `__init__.py` 만 남은 빈 패키지」라고 적는다 — 이번에 폴더가 지워져 낡은 문장이 됐다(문서 수정은 이번 범위 밖, 기록으로 남김).
7. `app/presentation/a2a/travel_remote_agent.py` 는 이름에 도메인(`travel`)이 들어 있다. 기존 낱말 시험이 「원격 Agent 데모 — 왕복 검증용 상대역」으로 예외 처리한 파일이다.
