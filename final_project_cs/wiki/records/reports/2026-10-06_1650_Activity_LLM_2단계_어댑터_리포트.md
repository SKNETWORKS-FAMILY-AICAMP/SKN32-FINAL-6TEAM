# Activity LLM 2단계 — Responses API 어댑터 · 배선 리포트

## 결론

활동 판정용 Responses API 어댑터(`OpenAIResponsesJudgeLLM`)를 만들어 Activity Team까지 배선했다. 실호출로 실제 SDK 응답을 읽을 수 있는 것도 확인했다.
Team은 아직 이 어댑터를 부르지 않는다. 판정 계층은 3단계에서 붙인다. 그래서 고객 답변은 바뀌지 않는다.
시험 결과는 1917 passed, 73 skipped다. 기준선 1896 passed에 새 시험 21건이 더해진 수이고 실패는 0건이다. 실호출 시험 1건도 통과했다.

## 바꾼 것

| 파일 | 내용 |
|---|---|
| `app/infrastructure/llm/openai_responses.py` (새 파일) | `judge(prompt_key, payload, schema=…, schema_name=…, web_search=…)` → `JudgeCall`(판정, 출처 목록, 검색 횟수·동작, 토큰, 지연). `temperature`·`seed` 는 넘기지 않는다. 읽을 수 없는 응답은 `JudgeResponseError` 를 낸다 |

| `app/modules/travel_ops/activity/team.py` | `judge_llm: Any \| None = None` 자리만 추가했다 |

## 정한 것

- **섀도 판정은 백그라운드로 돌린다** (계획서 §5.6 (가)). Controller 는 Case 하나에 Team 을 한 번 실행하고 그 결과로 답한다. 그래서 동기 시간 제한(나)을 쓰면 고객 응답이 그만큼 늦어진다.
- **프롬프트 폴더는 `prompts/activity_judge/`** 로 한다(계획서 §5.5). `prompts/judge/` 는 평가 프롬프트가 쓰고 있고, 프롬프트 키가 폴더 이름에서 만들어지기 때문이다.

- `ActivityJudge` 계층: `RuleJudge` · `LLMJudge` · `ShadowJudge`(백그라운드), 인용·출처 검증기
- `prompts/activity_judge/*.v1.md` 를 만들고 `ALLOWED_PROMPT_KEYS` 에 등록
- 실패 코드 `llm_timeout` · `llm_schema_invalid` · `llm_uncited` · `llm_fallback_rule`
