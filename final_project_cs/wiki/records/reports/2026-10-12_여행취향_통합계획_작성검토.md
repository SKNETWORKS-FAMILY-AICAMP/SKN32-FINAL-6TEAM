# 여행 취향 통합 계획 작성과 검토

여행 잡담과 다섯 입력 경로를 고객별 취향으로 모으는 구현 계획 초안을 작성했습니다. 취향 기억과 일정 변경 허가를 분리하고, 현재 설문 상속 기능을 재사용하도록 설계했습니다. 기능 구현·SQL 적용·커밋·푸시·배포는 하지 않았습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 다섯 입력 경로 조사 | 문서·코드 확인 | 5/5 = 100% |
| 계획·그림 작성 | 초안 완료 | 2/2 파일 = 100% |
| 문서 링크 검사 | 통과 | 39/39 = 100% |
| 그림 화면 확인 | 확인 | 2/2 화면 폭 = 100% |

작성·자체 검토 담당은 이 채팅의 Codex입니다. 독립 검토는 하지 않았습니다. 2026-10-12 KST에 작업했으며 검토 증거를 아래에 남깁니다.

## 결과물

- [통합 구현 계획](../plans/2026-10-12_여행대화와_고객취향_통합_구현계획.md): 대화 예시, 현재/누락 기능, 다섯 입력, 의미 추출, 데이터·API·화면·추천 소비, 단계별 구현, 수용 시나리오 24개, 결정 안건 세 가지와 출처입니다. 24개는 향후 실행할 수용 시나리오 수이며 기능 시험 통과 수가 아닙니다.
- [취향 수집과 추천 흐름](../plans/2026-10-12_여행취향_수집과추천_흐름.html): 수집 한 회차와 추천 한 회차를 각각 7개 노드로 나눈 정적 흐름도입니다. 시작·끝·판단 조건을 표시했습니다. 작은 화면에서는 그림 영역을 좌우로 스크롤해 오른쪽 분기를 봅니다.
- [wiki 입구](../../index.md): 기존 내용을 보존하고 계획 초안 링크 한 문단만 추가했습니다. 기존 사양 계약을 확정 내용으로 바꾸지 않았습니다.

## 조사에서 바로잡은 점

처음 전달된 조사만으로는 이전 답 재사용을 충분히 드러내지 못했습니다. 현재 코드를 추가 추적해 `survey_answers.inherit`가 같은 고객의 이전 로딩 설문 답을 새 접수에 기록하고, `pipeline`에서 호출하며, 등록 때 `merged_survey`로 여행 설문에 합친다는 것을 확인했습니다. 따라서 “고객별 재사용 기능이 전혀 없다”로 적지 않았습니다.

활동 기록 표도 존재합니다. 현재 조사한 호출부는 재난 뒤 재개 선택에 연결돼 있으며, 고객의 모든 일정 편집을 취향으로 바꾸는 기능이 있다고 일반화하지 않았습니다. 마이페이지의 취향 표시가 브라우저 설문 상태를 쓰는 것도 고객별 장기 기억과 구분했습니다.

조사 범위는 로컬 코드·SQL 파일·현재 wiki와 고객 웹 소스입니다. 과거 기록·백업은 현재 구현 검색에서 제외하고 관련 운영 관측 기록은 별도로 읽었습니다. 실행 중 DB 구조·직접 모델 응답·실제 배포 파일은 이번에 조회하지 않았습니다. 다른 이름의 동적 연결이나 다른 채팅의 후속 변경은 구현 착수 전에 다시 확인해야 합니다.

## 문서·그림 검증

검증 도구는 [검토 스크립트](../../../../scratch/taste-plan-review-20261012/check.cjs)이며, 원본 결과는 [검토 결과 JSON](../../../../scratch/taste-plan-review-20261012/result.json)에 있습니다.

| 검사 | 방법·결과 | 한계 |
|---|---|---|
| 로컬 링크 | Markdown 링크의 파일·폴더 존재 39/39 확인 | 외부 링크 가용성·내용 전체를 자동 검사한 수가 아닙니다 |
| 수용 기준 | A01~A24 총 24개 행 확인 | 실행하지 않았습니다 |
| SVG 구조·안전 | diagram-design `scripts/self_check.py` 통과 | 의미·화살표 해석은 자체 시각 검토입니다 |
| 데스크톱 | 설치된 Chrome headless, 1120×960에서 전체 캡처 확인 | 앱의 모든 파일 미리보기 환경을 포괄하지 않습니다 |
| 작은 화면 | 390×844에서 전체 캡처 확인, 페이지 전체 가로 넘침 없음 | 도식은 가로 스크롤이며 오른쪽 분기는 이동해 봅니다 |
| 텍스트 경계 | SVG 두 개에서 텍스트가 viewBox 밖으로 나간 항목 0개 | 노드 안 의미 밀도는 시각 검토로 보완했습니다 |
| 공백·패치 | wiki 입구 대상 `git diff --check` 통과 | 공유 작업 폴더 전체의 다른 변경을 검증하지 않았습니다 |

초기 자동 캡처는 Playwright 기본 브라우저 실행 파일을 해당 실행 환경에서 찾지 못해 실패했습니다. 설치가 확인된 Chrome 실행 파일을 지정한 뒤 캡처를 완료했습니다. 첫 작은 화면에서 과도한 왼쪽 여백을 확인해 viewBox와 최소 너비를 조정하고 재검사했습니다. Google Fonts 연결과 한국어 글꼴 대체 경로를 사용하므로 인터넷이 없는 환경에서는 로컬 글꼴로 보입니다.

신규 계획·그림 두 파일의 접속 정보 패턴 검색에서는 Google Fonts의 글꼴 굵기 표기 `@400`이 한 줄 검출됐습니다. 해당 줄은 공개 글꼴 URL이며 접속 계정·키·IP가 아닙니다. 이 확인을 저장소 전체 검사 결과로 일반화하지 않습니다. 커밋을 하지 않았으므로 커밋 직전 저장소 전체 검사는 이번 작업에 포함하지 않았습니다.

검토 시점 식별자:

```text
계획서 SHA-256: b03a3492c68d8dd2f35397964c7cdc5bae8fee9c60d4d3c1d286acf88891aef2
흐름도 SHA-256: f29a33f8b6b1c75592c0f623be58693d53d7ed569af043d61e1439ed446267d1
```

실서버 확인(서버 응답): 안 했음. x600 서버의 cs 프로젝트 서버와 로컬 개발 서버에 요청하지 않았습니다.

남은 제품 결정은 장기 기억·과거 자료 사용 허용 방식, 보존·삭제 범위, 추천 적용 범위와 활성화 순서입니다. 권장안을 계획서에 적었으며 확정 계약으로 표시하지 않았습니다. 구현을 시작할 때 최신 공유 변경과 계약을 다시 대조하고 담당 검토 후 단계별 구현·실행 검증을 진행합니다.
