# 2026-10-06 00:30 — 업무 도메인 폴더 정리 0단계 (옛 app/domain 이동 · 잔재 정리)

## 1. 목표

[D-CS-013](../../decisions/D-CS-013-domain-folder-layout.md) 의 0단계. 업무 도메인 울타리 이름을 `domains` 로 하려면 `app` 안에 이미 있는 `app/domain/` 과 한 글자 차이로 겹친다(사용자 거부). 그래서 옛 `app/domain/` 을 내용에 맞는 이름으로 먼저 옮긴다.

## 2. 수행

- `app/domain/`(파일 2 · 235줄: 이벤트를 Case 상태로 접는 리듀서 `case.py`, 이벤트 종류와 허용 전이표 `events.py`) → **`app/core/case_lifecycle/`** (`git mv`, 이력 보존).
- 이를 가져다 쓰던 30개 파일의 주소를 `app.domain` → `app.core.case_lifecycle` 로 바꿨다(app 12 · tests 16 · scripts 2). `scripts/map_commits_to_phase.py` 의 `app/domain/` 은 **옛 커밋을 단계에 대응시키는 기록 표**라 그대로 뒀다.
- 경계 시험 `tests/architecture/test_basement_is_domain_free.py` 의 코어 목록에서 `domain` 을 뺐다 — `core` 가 그 자리를 덮는다.
- 상태 그림 문서 `wiki/runtime/case-state-machine.generated.md` 를 `python -m scripts.make_state_diagram` 으로 다시 만들었다(출처 줄 1줄 변경).
- 지금 쓰이는 문서 5개의 경로를 고쳤다: `wiki/operations/unknown-state.md` · `wiki/runtime/case-lifecycle.md` · `wiki/runtime/shared-state.md` · `wiki/teams/composition.md` · 허브 `wiki/delivery/roles.md`. `records/` 아래 기록은 고치지 않았다.
- 잔재 정리(둘 다 git 추적 파일 0, `.pyc` 캐시뿐이라 소스는 없다): `app/modules/customer_ops/`(옛 쇼핑몰 팀 캐시 10개) · `app/core/case_runtime/`(빈 폴더).
- **옛 주소 안내 파일은 남기지 않았다.** 가져다 쓰던 곳 26개(작업 트리 기준, 미커밋 파일 포함)를 전부 고쳤고, 새로 옛 주소를 쓰면 시험이 곧바로 ImportError 로 잡는다. 안내 파일을 두면 `app/domain` 폴더가 남아 이번 목적(이름 겹침 없애기)에 어긋난다.

## 4. 함께 찾은 것 — 경계 시험의 사각지대

`app/infrastructure/travel/`(파일 28: 관광공사 · 기상청 · 재난문자 · 교통 · 구글 장소 …)이 **코어 층에 있는데 경계 시험이 울지 않는다.** 시험의 업무 단어 목록이 booking · itinerary · lodging 등이라 날씨 · 교통 · 관광 소스 이름이 걸리지 않는다. 부르는 곳은 `app/composition.py` · 여행 코드 3곳 · `app/tools` 1곳뿐이라 `domains/travel_ops/ports/` 로 옮길 수 있다 — D-CS-013 「울타리 밖에서 들어올 후보」에 올렸다.
