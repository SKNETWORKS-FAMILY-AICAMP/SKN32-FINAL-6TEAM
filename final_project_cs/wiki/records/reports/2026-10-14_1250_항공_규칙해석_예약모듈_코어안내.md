## 한 줄 요약

**숙소는 에이전트(모델 해석) 그대로, 항공은 규칙 기반 예약 모듈**이 됐다. 항공 `flight.assist` 가 고객 문장을 읽을 때 모델을 **0번** 부른다(`interpret_rules`).
코어가 **고쳐야 할 것은 없다** — 팀 id · 능력 · 도구 · 결과 모양 · 항목 계약이 전부 그대로다. 아래는 「달라진 동작」과 「원하면 치워도 되는 것」이다.
**13:2x 추가 — 모듈 이름을 `booking` 으로 바꿨다(6절)**: 폴더 `instances/booking/` · 클래스 `BookingTeam` · 등록 문자열. 식별자(`team_id` · `flight.*` · `kind`)는 그대로 — 바꾸려면 `booking.*` 겹침부터 결정이 필요하다(6절).

팀장이 받기만 하면 되게 우리 쪽에서 바꿨다. **코어 동작은 그대로** — 등록 문자열만 달라졌다.

| 무엇 | 전 | 후 |
|---|---|---|
| 폴더 | `app/domains/travel_ops/instances/flight/` | `instances/booking/`(`git mv`, 이력 유지) |
| 클래스 | `FlightTeam` | `BookingTeam`(`FlightTeam = BookingTeam` 별칭 남김) |
| 표시 이름 | Flight Team | Booking Module (항공) |
| 등록 문자열 | `instances.flight:FlightTeam` | `instances.booking:BookingTeam` — `config/project.yaml` · `app/composer_host.py`(`team.flight_search`) · `app/core/project_config.py`(`KNOWN_IMPLEMENTATION_REFS`) |
| `travel_ops/__init__` 내보내기 | `FlightTeam` | `BookingTeam` + `FlightTeam`(별칭) |
| 우리 시험 · 스크립트 import | `instances.flight` | `instances.booking`(시험 2 · 스크립트 3) |

**그대로인 식별자**: `team_id="flight"` · 능력 `flight.assist / status / itinerary / itinerary_question` · case type `flight` · 항목 `kind:"flight"` · 프롬프트 키 이름.

**왜 식별자는 안 바꿨나(팀장 결정 필요)**: 코어에 `booking` 이 이미 쓰인다 — `booking_handoff` 팀 능력 `booking.verify · booking.prepare_change · booking.prepare_cancel · booking.prepare_revert`, 항목 `detail.booking`(잠긴 예약), `components/booking/`(재확인 부품), `REGISTERED_TEAMS` 의 `"booking"`. 능력을 `booking.assist` 로 하면 `booking_handoff` 와 같은 이름 공간에 들어간다. 항목 `kind` 는 기차 · 버스가 생기면 `train` · `bus` 로 따로 가므로 `flight` 가 맞다. 선택지: ① 능력 이름만 `booking.*` 로(겹침 감수, `booking_handoff` 와 구분 규칙 필요) ② `reservation.*` 같은 다른 접두어 ③ 식별자는 `flight` 유지하고 이름만 `booking`(지금 상태). 바꾸면 접수 라우팅 · 검증 정책 · `select_capability` · 웹 · 시험이 같이 움직이므로 코어와 날 잡아 한 번에.
