# 재난 수신 기록 기간 조회·모의 실제 구분·검사 대상 표시

수신 기록 화면을 모의/실제/둘 다, 한국 시각 달력 기간, 50건 페이지 번호로 조회하도록 구현했다. 기본 기간은 오늘을 포함한 최근 7일이다. 실제 수신 문자와 6종 API 점검, 감사 이력에 저장한 mock API 입력을 한 목록에 표시한다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 격리 DB·HTTP 시험 | 통과 | 21/21 = 100% |
| mock 서버 시험(화면 반응) | 통과 | 2/2 = 100% |
| 실서버 확인(실제 DB 읽기) | 했음 | 1/1 = 100% |
| 매니저 반영·관리자 화면 배포 | 인계 | 0/2 = 0% |

## 원인과 수정

10월 24일 창덕궁 일정은 10월 17일의 실제 90분 검사 대상이 아니었다. 해당 일정의 관리자 날씨 예보 시험이 14:57:34~15:12:34 켜져 있었고, 기존 감시 함수는 유효한 시험 항목을 시간 범위 밖에서도 처리하도록 설계되어 있었다. 기존 운영 화면은 시험 대상과 실제 대상을 구분하지 않은 채 모두 ‘90분 안’이라고 설명했다.

감시 정책은 유지하고 화면용 대상을 실제 방문·90분 안 방문과 모의 시험 대상으로 나눴다. 모의 대상은 명시적으로 표시한다. 모의 여행 점검에서 선택하지 않은 실제 API 응답은 실제 API 기록으로 분류하며, 샘플 제공자의 입력은 실제로 표시하지 않는다.

현재 수신 상태·검사 대상과 기간별 과거 기록은 구분한다. 기록의 날짜 기준은 수신·점검 시각이며 발표 시각은 문자에 따로 표시한다. 다음 페이지는 첫 조회 기준 시각을 유지한다. 조회는 외부 API를 다시 호출하지 않고, 운영자 권한·테넌트 격리와 읽기 전용 트랜잭션을 유지한다.

## 검증 범위

- Python ruff F·E9, 관리자 ESLint·TypeScript·Next production build 통과.
- 격리 PostgreSQL DB에서 21개 시험 통과: 6종 API·문자·모의 입력 혼합, 구분 필터, 한국 시간 날짜 양 끝, 최근 7일, 50/50/23 페이지, 새 기록이 들어오는 동안 기준 시각 보존, 타 테넌트 제외, 입력 오류, 비밀값 가림, 미래 시험 대상 분리, 실제 API 수신 상태 이력 보존, HTTP 입력·권한·읽기 전용 거래.
- mock 서버 시험 2/2 (화면 반응): 1280px·375px, 기본 7일, 달력 기간, 모의/실제/둘 다, 번호 페이지, 대상 구분, 입력 보존, 키보드 이동, 가로 넘침 없음. 실제 고객 알림·재난 입력 쓰기는 실행하지 않았다.
- 실서버 확인 (서버 응답): 실제 cs 프로젝트 DB에서 후보 조회 함수를 읽기 전용으로 실행했다. 최근 7일 actual 13,080건·simulation 213건·all 13,293건, 페이지당 50건 및 같은 기준 시각의 1·2페이지 중복 없음 확인. 이 숫자는 조회 시점의 기록 수이며 전체 API 호출 횟수가 아니다. 배포된 HTTP 경로와 새 관리자 화면은 아직 확인하지 않았다.
- 비차단 경고: 시험 도구 Starlette/anyio의 deprecated alias 1건.

## 보존·한계

로컬 원본과 Git 색인·sparse 설정은 수정하지 않았다. 현재 실행 소스를 격리 사본에 캡처하고, 수정 직전 파일 8개를 별도 백업했다. 이전 탭 분리 백업도 유지했다. 시험 DB·컨테이너는 실행 후 종료하고 자료는 보존했다.

기존에 보관하지 않은 과거 API 응답값은 재구성하지 않는다. 이번 반영 이후 실제 재난문자 API 수신 상태도 새 이력으로 쌓고, 6종 점검에서 판정에 사용한 허용 필드를 보존한다. 공급자 원문·접속 비밀값을 통째로 보관하는 기능이 아니다.

현재 원격 브랜치와 실행 소스에 차이가 있으므로 통합 담당은 최신 기능을 보존하며 좁은 변경분을 통합해야 한다. 구현·자체 검증 담당은 현재 UI·API 작업 세션이며, 매니저의 독립 검토·푸시·배포 확인은 인계 단계다. 정본 계약은 [수신 기록 조회](../../operations/receipt-history.md)다.
