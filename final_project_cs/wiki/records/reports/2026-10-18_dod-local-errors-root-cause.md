# 로컬 DoD 오류 원인 확인

## 착수 — 2026-10-18T02:17:53

사용자 지시: 이전 로컬 전체 실행의 오류 2건을 재실행 통과로 끝내지 말고 원인을 확인해 전체 DoD 26/26을 단일 실행으로 통과시킨다. 수정의 커밋·양쪽 매니저 푸시·운영 배포는 지정한 커밋푸시 세션이 수행한다.

이전 오류는 변경 링크 상세 시험과 승인 후 철회 시험의 ERROR 2건이다. 앞선 관문 실행기는 해당 traceback을 보존하지 않아 원인이 확인되지 않았다. 기존 후속 2/2는 오류 해결의 확정 근거로 삼지 않는다.

현재 격리 소스 `748e25c6`에서 원래 전체 시험 순서·판정 기준을 유지하고, pytest 원문·JUnit·Windows 메모리 할당 한도·가용 메모리·시험 프로세스의 스레드/핸들 수를 별도 보존하며 진단 실행 중이다. 고객 DB와 분리된 기존 시험 DB와 이번 전용 터널만 사용한다. 자동 재실행·실패 제외는 하지 않는다. 시작 계측에서 할당 한도 23,292MB 중 22,768MB 사용, 여유 524MB였으나 원인 확정 전이다.

남은 일: 오류 원인 재현·수정·회귀, 수정한 전체 DoD 단일 통과, 검토 가능한 패치와 증거를 커밋푸시 세션에 인계하고 반영 결과 확인.


## 진단 도구의 확인된 결함 — 2026-10-18T02:27:41

기존 검증기는 pytest에서 ERROR가 집계돼도 원문 traceback을 출력하지 않았다(존재하지 않는 시험이 있을 때만 마지막 2,000자를 출력). 또 자식 pytest가 Windows 기본 인코딩으로 출력한 글을 UTF-8로 읽어 한글 원인이 깨지는 문제가 실제 오류 주입 시험에서 재현됐다. 부모의 UTF-8 출력 설정만으로 자식 출력은 바뀌지 않았다.

실제 pytest 정리 오류·비정상 종료·매개변수 전체 성공·기존 근거 폴더 보호를 검사하는 4건을 추가했다. 첫 실행은 한글 원문 보존 1건이 실패하고 3건이 통과했다. 자식 출력 인코딩을 명시한 뒤 **4/4 통과**했다. 하위 pytest 종료 코드를 무시하던 경로도 실패로 처리하고, 전체 traceback·원문 로그·JUnit·판정과 선택한 시험 ID를 새 실행 폴더에 보존하도록 수정했다. 공유 CLI 계약을 구현 전에 시험 지도에 추가했다. 판정 기준·시험 순서·재실행 정책은 바꾸지 않았다.

이 결함은 과거 오류 2건의 원인을 잃은 이유이며, 과거 두 ERROR 자체의 발생 원인과 구분한다. 진단용 기존 코드 전체 실행은 두 해당 시험을 통과해 현재까지 동일 ERROR를 재현하지 않았다. 메모리 부족 가설도 아직 확정하지 않는다. 수정한 정식 명령의 단일 전체 실행은 별도로 수행한다.

## 전체 계측 실행의 실제 연결 오류 — 2026-10-18T02:49:43

원래 소스의 전체 단일 실행은 **201/203 통과, 2 실패, DoD 24/26**이었다(874.19초). 실패한 것은 일정 제약 복원 시나리오와 읽을 수 없는 이동 경로를 알리지 않는 시험이며, 둘 다 SQL이나 판정 전에 새 DB 연결을 맺던 `psycopg.connect()`에서 `OperationalError: server closed the connection unexpectedly`가 발생했다. 과거 ERROR 2건과 같은 시험 ID는 아니므로 과거 원문을 복구했다고 주장하지 않는다. 과거 두 시험의 잔존 합성 데이터는 본문 수행 후 정리 단계에 남았고, 이번 원문은 새 연결 장애가 서로 다른 위치의 시험도 깨뜨릴 수 있음을 보여 준다.

DB 자체와 접속 구간을 분리해 검사했다. 같은 시험 DB를 대상으로 WSL 내부 프로토콜 응답은 3,000/3,000, 원격 Windows loopback의 짧은 프로토콜 응답은 3,000/3,000이었다. 로컬 SSH 전달 경유 응답은 2,998/3,000이며 2회 4초 timeout이었다. 이후 원격 Windows에서 동일 psycopg 3.3.4/libpq 18로 실제 인증·SELECT 1·연결 종료를 3,000회 수행하자 2회 `ConnectionTimeout`이 재현됐다. 따라서 SSH 전달만의 문제로 결론내릴 수 없으며 Windows–WSL localhost 전달을 추가 분리한다. 반복은 실패를 통과로 바꾸는 재시도가 아니라 합성 시험 DB의 별도 연결 진단이다.

관측 구간의 PostgreSQL 비정상 종료·강제 종료·교착 카운터는 0이었고 해당 시각 DB 로그에도 대응 SQL 오류가 확인되지 않았다. Windows 가용 메모리와 할당 한도는 낮았으나 메모리 부족을 확정할 직접 증거는 확보하지 못했다. 고객 DB, 운영 설정, 제품 연결 재시도 정책은 바꾸지 않았다.

원문·JUnit·자원 계측은 git 밖 전용 QA 폴더에 보존한다. DB 비밀번호가 포함될 수 있는 raw traceback/JUnit은 공개 패키지에 넣지 않는다. 검증 도구의 새 원문 출력에는 자격정보 가림을 추가했고, 실제 오류 주입 5건과 기존 관문 60건 **65/65 통과**했다.

## 원격 환경 중단과 로컬 전용 DB — 2026-10-18T02:59:45

추가 경로 비교를 준비하던 중 원격 WSL 실행 명령이 배포판 기동 오류로 실패했다. 커밋 담당도 별도로 WSL 중지 상태를 확인했다. WSL 중단의 원인을 이 시험이나 앞선 연결 지연으로 확정하지 않는다. 운영 WSL·Docker·고객 앱을 이 채팅에서 재시작하거나 설정을 바꾸지 않고 추가 원격 부하를 중단했다. 준비하려던 QA 전용 전달기는 WSL 명령부터 실패해 실행됐다는 근거가 없다.

이 PC의 새 격리 폴더에 PostgreSQL **16.15**·pgvector **0.8.6**을 공식 배포 패키지로 준비했다. 원격 시험 DB는 PostgreSQL 17이므로 같은 DB 버전 비교라고 쓰지 않는다. Python 3.12.7·psycopg 3.3.4·libpq 18.3은 앞선 로컬 실행과 같다. 새 DB는 루프백으로만 열고 무작위 자격정보·합성 자료만 사용한다. 정식 마이그레이션·프롬프트 등록·여행 seed **3/3 통과**했다. 새 연결 안정성 검사 후 수정한 정식 DoD 명령을 원래 203개 시험·26항목 그대로 한 번 실행한다. 제품의 연결 재시도·판정·제외 기준은 바꾸지 않는다.

기존 Conda 플러그인 오류로 첫 패키지 설치는 진행하지 못했으며, 기존 Conda 환경 변경 없이 독립 실행 도구로 새 폴더에 패키지를 설치했다. 실패 로그·설치 명세·합성 DB·접속 비밀파일은 git 밖에 보존한다. DB 버전 차이와 실제 고객 화면/배포 미확인은 최종 인계에도 명시한다.

커밋 담당에게는 기준 커밋·8개 파일별 적용 전후 해시·차분·검수 요약을 제공한다. 다른 세션의 관리자 생성 설정 변경과 백업·raw 근거·비밀 설정은 패키지에서 제외한다. 원본 작업 폴더를 동기화하거나 이 채팅에서 커밋·푸시하지 않는다. 양쪽 role-manager 보존 통합·최신 통합판 검증·푸시와 운영 배포는 지정 세션에서 처리한다. 원격 WSL 복구 전에는 운영 배포를 완료했다고 쓰지 않는다.
