# 수정한 경계

- 서버가 기존 설정 비밀키와 tenant·session_hash를 분리 도메인 HMAC한 `privacy_scope`를 내려줍니다. 고객 ID·쿠키·CSRF를 브라우저 저장소나 탭 신호에 넣지 않습니다. 고정 계정 이름·세션 종류·객체 생성 여부·대체 비밀키를 신원으로 만들지 않습니다. 이 값은 인증·CSRF 권한이 아닙니다.
- diff 저장은 `chatDiffs.v2:<인증된 scope>:<trip>`에 귀속합니다. scope 없는 응답에는 저장·복원을 하지 않습니다. 같은 scope의 성공 재조회와 새로고침은 이력을 보존합니다. 새 scope와 확정 종료는 이전 이력을 제거하고 소유자 없는 v1은 귀속을 추정하지 않고 폐기합니다. 일반 환경 설정은 보존합니다. 이는 탭에만 있던 before 값의 보관 정책이며 서버 여행 삭제가 아닙니다.
- 탭 종료 신호에는 비권한 scope와 nonce만 보냅니다. 대상 scope가 같은 탭만 세션을 종료하며, 늦은 A 종료 신호가 B 이력을 지우지 않습니다. 최초 성공 probe는 남은 다른 scope 자료를 제거합니다. 저장소가 차단되거나 신호를 놓친 탭은 focus/pageshow의 서버 재조회로 확인합니다. 모든 브라우저·저장소 차단 환경에서 즉시 전달된다고 주장하지 않습니다.
- logout은 요청 세션을 잡고 완료 시 여전히 그 scope일 때만 종료 snapshot을 반환합니다. 같은 scope를 재조회한 새 객체는 같은 세션으로 취급합니다. 다른 세션으로 바뀌었다면 UI 정리 소유권을 주지 않습니다. SignOut은 이를 확인하고 query 취소 대기 뒤에도 다시 확인하여 B query·동의·설문을 지우지 않습니다.
- 계정 전환 시 query cache를 동기적으로 비우고 여행 등 하위 화면을 새 경계로 다시 만듭니다. 채팅의 메모리 diff도 소유자가 일치할 때만 보입니다. 계정 화면은 로그아웃 응답의 소유권 검사를 유지합니다.
- 실제 서버에서도 늦은 logout `Set-Cookie`가 B 쿠키를 지울 수 있음을 발견했습니다. 서버는 요청에서 인증한 세션만 폐기하고 logout 및 무효 쿠키 401에 삭제 Set-Cookie를 보내지 않습니다. 폐기된 쿠키는 인증되지 않고 새 세션 발급 때 교체됩니다. 계약 후보를 wiki에 먼저 적고 구현·e2e 기대를 함께 바꿨습니다. 이 계약 변경은 아직 운영 승인·반영되지 않았습니다.
