# 공지 실패 띠 — 한 번 실패로 뜨지 않게

| 항목 | 내용 |

| 고친 곳 | `role-manager` `dacca3c2` 위 |

## 1. 무엇이 왜

- 본 것: 첫 화면에서 공지 요청(`GET /v1/web/support/notices`)이 두 번 나갔고, 두 번째가 화면 이동으로 끊겼다(`ERR_ABORTED`). 그 한 번으로 아래쪽에 「서비스 공지를 확인하지 못했어요 · 공지와 점검 상태를 다시 확인해 주세요」 띠가 떠 화면 아래(「동의하고 다음으로」 자리)를 가렸다.
- 원인: 앱 전체 질의 기본값이 「다시 묻지 않음」(`app/providers.tsx` `retry: false`)이라, 공지처럼 배경으로 읽는 정보도 한 번 실패하면 바로 오류가 됐다. 앞서 받은 공지가 있어도 다시 묻다 실패하면 같은 띠가 떴다.

## 2. 고침

`features/support/service-notices.tsx` — 공지 질의만 **두 번 더 묻는다**(1초 · 2초 뒤, `NOTICE_RETRIES`). 묻는 동안은 띠를 띄우지 않고, 세 번 모두 못 받을 때만 「확인하지 못했어요」. 앞서 받은 공지가 있으면 다시 묻다 실패해도 그것을 그대로 둔다. 앱 전체 기본값(`retry: false`)은 그대로다 — 일정 · 동의처럼 바로 알려야 하는 요청은 지금처럼.

## 3. 검증

- mock 서버 시험(화면 반응): 새 `tests/live/notice-retry-20261014.spec.ts` **2/2**(한 번 끊기고 다시 받으면 띠 없음 · 세 번 다 못 받으면 그때 띠와 「다시 확인」) — **고치기 전 코드에서는 둘 다 실패**함을 확인. 기존 `support.spec.ts` · `consent.spec.ts` 와 함께 한 줄씩(재시도 1회) **28/28**
- 단위 시험 `vitest run src/features/support` 8/8 · `tsc` 0 · 바꾼 파일 `eslint` 0
- 실서버 확인(서버 응답 · 화면): **했음** — x600 서버가 `0f3a0f13`(이 고침 `7ef976ee` 포함)을 배포한 뒤 공개 주소 첫 화면을 새로 열어 8초 — 공지 요청 2건 모두 200 · 띠 없음. 이어서 브라우저 안에서 공지 요청만 일부러 실패시키고 60초 자동 새로 읽기를 기다렸다 — 공지 요청 3번(처음 + 두 번 더) 모두 실패했지만 앞서 받은 공지가 있어 띠가 뜨지 않았다(고치기 전 판이면 첫 실패에 바로 떴다). 끝나고 브라우저 요청을 되돌렸다.
