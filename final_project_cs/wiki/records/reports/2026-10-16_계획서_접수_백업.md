# 계획서 접수 백업 — 지우기 전에 담고, 보관 기간은 관리 화면에서

## 결론

고객이 입력한 계획서(원문 · 우리가 읽은 값 · 고객이 고친 값 · 확인 화면 결과 · 설문 답)는 이제 **지워지기 직전에 DB 의 백업 표에 통째로 남는다.**
백업을 얼마나 둘지는 관리자 웹앱 「운영 설정 · 보관 기간 → 웹 이용 · 서비스 설정」의 **「계획서 백업 보관 기간(0 = 지우지 않음)」** 칸에서 정한다. 기본은 0(지우지 않음)이다.
로컬 작업 사본에서 만들고 확인했다. **x600 서버에는 아직 배포하지 않았다.**

## 왜

사용자 지시(2026-10-16): 「7일 뒤 삭제하면 안 되고 우선 DB 에 다 저장을 해놔야 해. 삭제하기 전에 백업해 두는 기능 만들고, 보관 기간은 관리자 웹앱에서 설정」.
x600 서버의 cs 프로젝트 DB 를 읽기 전용으로 센 결과(2026-10-16) 계획서 접수 150건 중 115건이 게스트(로그인 안 한 사용자) 또는 기타 고객 것이었다. 게스트 정리는 마지막 사용 뒤 7일(일정이 남으면 일정 끝 + 3일)에 접수를 지운다.

## 무엇을 바꿨나

| 바꾼 것 | 파일 |
|---|---|
| 백업 표 `intake_backups` (접수 한 건 = 한 행, 자식 표를 `to_jsonb` 로 통째로) | `app/infrastructure/db/migrations/906_intake_backups.sql` |
| 백업 · 만료 정리 함수 | `app/domains/travel_ops/components/intake/backup.py` |
| 여행 삭제가 접수를 지우기 직전에 백업(이유 `trip_delete`) | `app/domains/travel_ops/components/itinerary/trip_delete.py` |
| 회원 정리 · 게스트 정리가 여행 없는 접수까지 백업(이유 `member_cleanup` · `guest_cleanup`) | `modules/web_account/member_cleanup.py` · `guest_cleanup.py` |
| 관리 화면 설정 `retention.intake_backup_days`(0~3650일, 기본 0) | `modules/web_account/web_guard.py` · `config/guardrails.yaml` |
| 정리 작업이 하루 단위로 기간 지난 백업만 지움 | `scripts/run_sweepers.py` |
| 계약 문서 한 단락 | `wiki/external/rest-endpoints/web-auth.md` |

- 백업이 실패하면 예외가 그대로 올라가 **삭제 전체가 되돌려진다**(조용히 지우지 않는다).
- 백업은 고객 · 여행과 외래키로 잇지 않는다 — 고객 행이 지워져도 남는다. 칸 이름을 `source_customer_id` · `source_trip_id` 로 둔 것은 「여행 번호 칸을 가진 표는 여행 삭제 목록에 있어야 한다」는 시험을 일부러 비켜 가려는 것이다(이 표는 남기는 표다).
- 보관 기간은 **지울 때** 읽는다 — 관리자가 기간을 바꾸면 이미 쌓인 백업에도 새 기간이 적용된다.
- 관리자 웹앱은 서버가 주는 설정 목록을 그대로 그리므로 화면 코드는 고치지 않았다.

- 시험 DB 는 로컬 개발 DB(5433) 안에 따로 만든 `acop_backup_test` 에서 돌리고 끝난 뒤 지웠다.
- 화면 확인은 원래 작업 폴더의 관리자 앱(설정 화면 코드가 같다)을 이 작업 사본의 운영 API(127.0.0.1:8070)에 붙여서 했다. 그 관리자 앱은 원격 최신보다 조금 뒤라 「자료 조회 정책」 · 「결함 사후 분석」 칸은 「경로를 찾을 수 없습니다」로 나왔다 — 이번 변경과 무관.
- mock 서버 시험: 해당 없음 / 실서버 확인(x600 서버의 cs 프로젝트 서버): **안 했음**(배포 전).

## 남은 것

1. x600 서버에 배포 — 배포 전까지 x600 서버에서는 게스트 정리가 지금처럼 백업 없이 지운다(10-16 기록상 대상 4명, 일정이 남아 보류 중).
2. 약관 문장과의 관계 — 약관 · 계약은 「여행 삭제 = 즉시 완전 삭제」 · 보관 기간 뒤 파기를 말한다. 백업이 그 문장과 어긋나는지, 약관을 고칠지는 사용자 결정.
3. 대화 기록(`trip_chat_turns`)도 같은 이유로 남길지 — 이번 범위(계획서) 밖.
4. 원본 파일(사진 · PDF)은 DB 에 없어 백업에도 저장 위치만 남는다.
