## 화면에서 달라진 것

- **계획 확인 화면**: `prefill.questions[]` 의 `kind: "place_not_found"` 가 가리키는 일정 카드 안(접혀 있어도 보이는 자리)에 칸이 붙는다 — 서버 문장 그대로 · 후보 1~3(그 일정의 `GET …/candidates`) · 「직접 고르기」 · 「장소 없이 두기」. 후보 0개면 후보 칸 없이 단추 둘.
  - 후보를 누르면 바꾸기 화면과 같은 길(`POST …/edits` 의 `items[n].place` 에 그 후보 그대로)로 보낸다.
  - 「직접 고르기」는 화면을 바꾸지 않고 그 일정의 장소 바꾸기를 열며 위 검색 칸에 바로 쓸 수 있게 한다.
  - 「장소 없이 두기」는 일정 편집기의 「장소 없음」과 같이 `{"none": true}` 로 보낸다.
  - 일정에 장소가 생기거나 「장소 없음」이 되면 칸이 사라진다(서버 기록에 질문이 남아 있어도). 카드에 실린 질문은 목록 위 안내(먼저 채운 것)에 다시 나오지 않는다. 화면에 없는 일정을 가리키는 질문은 예전처럼 안내에 남는다.
- **여행 화면 채팅**: 답에 `pick` 이 있으면 마지막 답 아래에 「직접 고르기」 단추가 붙는다(대화 기록 `turns[].reply.pick` 에서도 다시 나온다).
  - `change` — 「일정 수정」과 같은 전환으로 수정 모드를 열고, 그 일정(여행 일정 id → 수정 접수의 `0-n`, 다시 연 줄의 `evidence.item_id` 로 찾음)의 장소 바꾸기를 검색 칸에 `query` 를 넣은 채 연다. 수정 접수에 없는 일정(지난 일정 등)이면 「바꿀 일정을 찾지 못했어요」라고 알린다.
  - `add` — 수정 모드의 일정 추가 칸을 연다: 이름 · 날짜 · 시작 · 종류는 채팅 값, 검색 칸에 `query`. 끝 시각을 고객이 말하지 않았으면 추가 칸의 기본(시작 + 60분)으로 채운다 — 서버가 지어낸 값이 아니라 화면 칸의 기본값이고 고객이 고칠 수 있다.

## 실서버 확인 (확인 시각 2026-10-19 17:49~18:05, x600 서버의 cs 프로젝트 서버)

- 배포: x600 서버 자동 반영이 다시 돌아 17:04 에 `3a330f0e`(이 화면 + 서버 쪽 `1771d818` 포함)로 api · worker · web 이 다시 떴다(이미지 이름표 `tripilot-api:3a330f0e84` · `tripilot-web:3a330f0e84` 확인).
- 방법: 공개 주소는 Cloudflare 가 파이썬 요청을 봇으로 막아(1010) 우회하지 않고, x600 서버 안 api 컨테이너에서 컨테이너 안 주소로 같은 공개 API 를 불렀다. 시험 손님 1명 · 접수 1건 · 여행 1건을 새로 만들었다(사람 확인 · 약관 게이트는 x600 서버에서 꺼져 있다). 등록 알림은 손님 본인 채널로만 가고 시험 손님은 채널이 없어 밖으로 나간 것은 없다.
- 계획서 「12:00 을지로 순자네 비밀식당 점심」 · 「15:00 망원동 꿀벌네 공방 체험」(지도에 없을 이름) →

| 확인 | 결과 |
|---|---|
| `prefill.questions[]` 의 `place_not_found` | 두 줄 모두(`item` 0-1 · 0-2, `source_id` · `index` · 단추 셋 · `blocked: false`) — 계약 모양 그대로 |
| 그 줄의 후보(`GET …/candidates`) | 줄마다 3곳(식당 줄 「무구옥」 등, 공방 줄 「K-컬처 스크린(대한민국역사박물관)」 등 — 경복궁 둘레 같은 종류) |
| 후보 그대로 보내기(`items[1].place`) | 저장 · 다시 확인됨(`place_state: customer`, 무구옥) |

| 채팅 「10월 25일 저녁 7시에 망원동 꿀벌네 공방 넣어 줘」 | `edit_refused` + `pick: {mode: add, query, prefill: {title, date: 2026-10-25, starts_at: 19:00}}` — 계약 그대로. 대화 기록 `turns[].reply.pick` 에도 있음 |
| 채팅 「12시 점심 일정을 을지로 순자네 비밀식당으로 바꿔 줘」 | **`pick` 없음** — `adjusted`(`decision_replace_named`): 서버가 거절하지 않고 그 이름을 「위치 확인 필요」 목적지로 저장했다(`trip_desk.py` 의 `requested_destination` 길). 계약 문서에 적힌 동작이지만, 이 때문에 바꾸기 쪽 「직접 고르기」는 실제로 거의 나오지 않는다 |

- 작은 어긋남: 넣기 거절 답의 `reason` 이 계약의 `place_not_found` 가 아니라 `decision_add_item` 으로 왔다(`pick` 은 실렸다 — 화면은 `reason` 을 보지 않아 영향 없음).
- 하지 않은 것: 실서버 **화면**(공개 주소를 실제 브라우저로 열어 카드 · 단추를 눈으로 보기) — 새 손님은 약관 동의 화면을 거쳐야 해 이번엔 하지 않았다. 화면 반응은 mock 서버 시험으로만 확인했다.

## 고친 함정 하나

- 카드가 처음 그려질 때 후보를 바로 물으면 「그 일정은 이미 없어요」가 났다 — 화면 연결(`useServerReview`)의 효과가 카드보다 늦게 돌아 화면의 계획을 아직 모를 때였다. 후보 요청을 다음 순간으로 미뤄 고쳤다.
- mock 서버가 못 찾은 줄의 장소 칸을 「고객이 장소 없음으로 정함」(`method: customer`, 값 null)으로 내보내 「장소 없이 두기」가 보낼 것이 없다고 판단됐다 — 실서버처럼 「찾으려던 이름 · 좌표 없음」(`method: lookup`)으로 고쳤다.
