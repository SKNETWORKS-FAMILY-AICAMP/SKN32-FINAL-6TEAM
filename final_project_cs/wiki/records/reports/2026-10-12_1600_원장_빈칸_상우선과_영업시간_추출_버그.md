# 원장 빈칸 상 우선 — 정기휴무 오집계 정정 · 영업시간 추출 버그 수정 · 남은 130곳 검수 시트

## 1. 목표

사용자 지시 「상 247곳부터 채워줘」. 상 우선은 판정에 바로 걸리는 빈칸(빠진 요일 · 요일 모름 · 휴무 모름)이다(`datasets/dining/원장_빈칸_정리_2026-10-11.md`).

## 2. 한 일

**① 247곳은 잘못 센 수였다.** 정기휴무 요일을 빠진 요일로 셌다 — 「매주 일요일 휴무」 가게는 월~토 규칙만 있는 것이 맞다. 정기휴무 요일을 빼면 상은 170곳이었다. 정리 문서 · 작업목록을 고쳤다.

**② 관광공사 영업시간 추출 버그를 찾아 고쳤다.** 170곳 중 원문이 있는 곳 다수가 `[평일]- 11:00~21:00- 준비시간 …` 모양이었고, 추출이 시각 뒤에 붙은 「- 준비시간」을 자기 낱말로 읽어 평일을 통째로 버렸다. 함께 「토,일 12:00~21:30 브레이크타임 15:00~17:30」 · 「상시 영업」 · 휴무 「매주 주말」을 고쳤다. 결함 리포트: [debugs/2026-10-12_영업시간_추출이_평일을_통째로_버린다.md](debugs/2026-10-12_영업시간_추출이_평일을_통째로_버린다.md)

**③ 로컬 원장을 다시 세웠다.** 상 우선 170곳 → 130곳(진짜 빠진 요일 50 → 13).

**④ 남은 130곳을 빈칸 검수 시트에 올렸다.** 사람이 지도로 볼 곳이다. 원장 값을 직접 지도에서 긁어 넣지 않았다 — 구글은 번호만 저장, 카카오는 저장하지 않는 것이 이 프로젝트의 규칙이다(`dining.dn_source.storage_mode`, `kakao_presence.py`). 팀이 쓰던 흐름(초안 → 사람이 확인일 → `make_gap_sql.py`)을 따랐다.

- `datasets/dining/processed/gaps/빈칸_검수_20261012.csv` (341줄) = 이전 시트 264줄 그대로 + 새 77곳.
  - 이전 줄 중 53곳은 영업시간은 확인했지만 정기휴무가 비어 있다 — 「할 일」 칸(적재되지 않는 칸)에만 재확인 표시.
  - 새 77곳은 요일 칸 · 라스트오더를 지금 원장 값으로 미리 채웠다. 「연중무휴」 확정에는 일곱 요일이 다 차 있어야 하고, 비운 요일은 적재되지 않기 때문이다.
- `make_gap_sql.py` 는 가장 최근 시트 하나만 읽는다 — 새 시트로 바꿔도 지금 적재 내용이 같음을 확인했다(아래).

## 4. 확인하지 못한 것 · 다음 작업

- **130곳의 실제 값은 아직 비어 있다** — 사람이 시트에서 지도로 확인하고 확인일을 적어야 들어간다.
- 개발 서버 원장에는 이 수정이 안 들어갔다. 서버 원장은 DB 가 비었을 때만 채워진다(`deploy/README.md`) — 서버 담당이 다시 채울 때 함께 반영된다.
- 「연중무」 · 「연중휴무」(오타로 보이는 휴무 표기)는 추출 규칙에 넣지 않았다 — 「연중휴무」는 글자대로면 「늘 쉰다」라 사람이 본다.
- 「[월요일~금요일/일요일]」 · 「토요일~일요일·법정공휴일」 같은 요일 묶음은 아직 일부 요일을 놓친다(각 1곳) — 시트로 사람이 본다.
- `rebuild.py` 머리말의 기본 DB 설명과 실제 기본값(코어 DB)이 다르다 — 고치려면 요식 담당 판단이 필요하다.
