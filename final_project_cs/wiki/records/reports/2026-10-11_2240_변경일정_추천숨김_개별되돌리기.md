# 변경 일정의 추천 숨김과 개별 되돌리기

변경된 카드의 자동 추천을 숨기고 해당 일정만 원래 값으로 복원하도록 수정했습니다. 로컬 구현·검증 완료이며 x600 서버 공개 배포는 하지 않았습니다.

| 확인 | 결과 | 진행 |
|---|---|---|
| 관련 단위 시험 | 통과 | 83/83 = 100% |
| 로컬 개발 DB API 시험 | 통과 | 15/15 = 100% |
| mock 서버 시험 (화면 반응) | 통과 | 3/3 = 100% |
| 정적 검사 | 오류 없음 | 2/2 = 100% |
| Chrome 촬영 | 완료 | 8/8 = 100% |

실서버 확인 (서버 응답): 안 했음. x600 서버의 cs 프로젝트 서버 응답과 공개 접수는 이번 작업에서 변경·재검증하지 않았습니다. 로컬 API 시험은 실제 로컬 개발 DB를 사용하고 외부 조회는 시험 대역을 사용합니다.

## 원인과 수정

- 추천 아이콘은 이미 변경된 일정인지 확인하지 않았습니다. 변경 표시 또는 개별 복원 기록이 있으면 숨깁니다.
- 기존 카드 되돌리기는 시간 변경에만 연결되어 있었습니다. 선택 일정의 값·근거를 완료된 과거 판으로 복원하는 선택 필드를 기존 복원 API에 추가했습니다. 다른 일정과 여행 정보는 현재 값을 보존합니다.
- 장소·내용 복원은 시간 되돌리기보다 우선합니다. 성공하면 그 카드의 변경 표시를 정리하고 수정 버튼으로 초점을 돌립니다. 실패하면 내용과 복원 기록을 유지합니다.
- 완료된 원판만 사용하고 잠금·예약·본인 소유권·현재 판 충돌·검사 실패 롤백 경계를 그대로 적용합니다. 새로고침 이전 기록은 보관하지 않습니다.

## 검증 근거

- [단위 시험](../evidence/2026-10-11_changed-item-undo/unit.log): 전체 복원, 개별 원판, 시간 복원 관련 7개 파일의 83개 시험.
- [API 시험](../evidence/2026-10-11_changed-item-undo/api.log): 기존 전체 복원 11개와 새 개별 복원 4개. 선택 일정 값·근거 복원, 다른 일정 보존, 잠금·예약, 알 수 없는 대상, 다른 고객 접근을 확인했습니다.
- [Chrome 최종 실행](../evidence/2026-10-11_changed-item-undo/chrome-review.json): 375px·1280px, 다른 일정의 변경 유지, 추천 숨김, 카드 복원, PC 키보드 Enter, 실패 뒤 재시도, 가로 넘침 검증.
- [정적 검사](../evidence/2026-10-11_changed-item-undo/static.json): ESLint·TypeScript 종료 코드 0.
- [촬영 모음](../../../frontend/apps/web/mockups/changed-item-undo-2026-10-11-v1/index.html): 실제 Chrome 목업 지도 화면 4개와 카드 4개입니다.

초회 화면 시험은 2/3 통과였습니다. 실패 시 제목 비교가 innerText와 textContent의 줄바꿈 차이를 혼용해 같은 방식으로 보정했습니다. 검증 사본 복사 때 상대 경로 오류가 한 번 있어 그 실행을 최종 증거로 사용하지 않고 절대 경로로 복사한 뒤 재실행했습니다. 최종 3/3은 수정한 시험과 현재 UI 파일로 실행한 결과입니다.

API 계약과 웹 코드는 같은 작업자가 확인했습니다. 독립 검토로 보고하지 않습니다. 팀 기준 커밋 위 검증 사본에서 UI를 빌드했으며 기존 전체 변경을 합쳐 커밋하지 않았습니다.
