2. **코어 작업이 develop 에 없습니다.** role-manager 가 develop 보다 125커밋 앞서고 59커밋 뒤처져 있습니다(2026-10-13 기준). 활동 팀은 develop 에서 갈라져 나와 코어의 새 연결 자리(원장 판정 · 판정 예산 조립)를 볼 수 없었고, 그래서 `check_live_status.py` 주석에 「조립 코드는 develop 에 없을 수 있어 쓰지 않는다」고 적고 코어 코드를 복사해 우회했습니다. → **고침**: role-manager 와 develop 을 합쳐 develop 에 올렸다(`2e87bc23`). 이제 develop 에 원장 판정 연결 자리 · 판정 예산 조립 · 예약 → 여행 찾기가 있습니다.
3. **팀이 정기 작업을 끼울 자리가 없습니다.** 작업 실행기 `scripts/run_sweepers.py`(1분마다 도는 코어 작업 묶음)는 작업이 전부 코드에 고정돼 있어, 팀 배치를 넣으려면 매번 코어를 고쳐야 합니다. 2번 요청은 이 빈틈 때문에 정당합니다. → **고침**: 팀이 자기 폴더에 `jobs.py` 만 두면 등록되는 자리를 만들었다(아래 2절).

### 활동 쪽 문제 (5가지)

1. **운영 상태가 한 경로에만 들어갑니다.** 새로 만든 읽기 함수(`live_lookup`)는 예약 성립 판정만 씁니다. 확인 화면 · 감시가 부르는 원장 판정(활동 `ledger.py` 의 `state` · `state_by_content`)에는 운영 상태를 읽는 코드가 없어, 고객이 가장 많이 거치는 두 곳은 임시휴무를 보지 못합니다. (예약 판정 경로는 DB 연결이 없어 코어의 한 줄 연결은 필요합니다 — 1번은 받습니다.)
2. **조용히 꺼집니다.** 「연결 안 하면 경고도 없이 꺼진다」는 동작은 활동 `team.py` `_live_status_check` 자체 코드입니다(`live_lookup is None → None`). 프로젝트 규칙 「조용한 대체 금지」에 어긋나니 활동 쪽에서 경고를 남겨 주세요.
3. **확인 대상과 읽는 쪽이 어긋납니다.** 배치는 **여행 일정 항목**만 확인 대상으로 고르고, 저장값을 읽는 쪽은 **예약 성립 판정**입니다. 일정에 연결되지 않은 예약은 계속 「미확인」으로 남습니다.
4. **「코어 파일 두 곳 한 줄씩」이 실제와 다릅니다.** 이번 판에서 새로 바꾼 것만 센 숫자입니다. develop 과 비교하면 활동 브랜치에는 코어 파일 20여 개가 바뀌어 있고(`read_tools.py` +260줄, `composition.py` +47줄, `openai_responses.py` 신규, `disaster_msg.py` +111줄, 마이그레이션 300~305, `guardrails.yaml` +101줄, docker compose 등), 이 사본들은 role-manager 의 같은 파일과도 내용이 다릅니다. 합칠 때 같은 코어 파일이 두 판으로 부딪힙니다.
5. **비용이 요청서에 없습니다.** 섀도 모드(기록만 하고 고객 답에는 안 쓰는 모드)라 웹 호출 비용(하루 최대 50회)은 나가는데, 사람이 라벨로 정확도를 재기 전까지 고객이 얻는 것은 없습니다. 이 기간 · 비용을 요청서에 적어 주세요.

## 1. 저장된 실시간 운영 상태 읽기 연결 — 반영했습니다

예약 성립 판정 경로는 DB 연결 없이 도구로만 읽으므로, 제안하신 대로 조립(`app/composition.py` `build_registry`)에서 읽기 함수를 꽂았습니다. 운영 조립에서만 꽂고, 도구를 주입한 시험 조립에는 꽂지 않습니다.

```python
if production and hasattr(team, "live_lookup"):
    from app.domains.travel_ops.instances.activity import live_store
    team.live_lookup = live_store.build_lookup(get_connection)
```

지금 develop 의 활동 코드에는 `live_lookup` 칸 · `live_store` 가 없어서 **아무 일도 하지 않습니다.** 활동 브랜치가 들어오면 그때부터 꽂힙니다.

다만 이것만으로는 **예약 성립 판정 한 곳만** 임시휴무를 봅니다. 고객이 가장 많이 거치는 두 곳은 이 값을 보지 못합니다.

- **확인 화면**(일정 등록 전 운영시간 판정)과 **감시**는 활동 팀이 등록하는 원장 판정(`activity_ledger.state` · `state_by_content` → 활동 `ledger.py`)을 부릅니다. 이 함수는 DB 연결을 받으니, 여기서 `activity.ac_live_status` 를 같이 읽어 **별도 칸**(예: `live_status: {value, checked_at, citations}`)으로 실어 주세요. 코어 변경은 필요 없습니다.
- 섀도 모드일 때는 그 칸만 싣고 `closed` 등 기존 판정은 바꾸지 말아 주세요(지금 팀 경로와 같은 규칙).
- 원장 판정 연결 자리는 role-manager `97829e58` 에서 만들었고, 이번에 develop 에 들어갔습니다.

**꺼짐 경고**: 요청서에 「연결 안 하면 경고도 없이 꺼진다」고 적으셨는데, 그 동작은 활동 `team.py` `_live_status_check` 의 `self.live_lookup is None → return None` 입니다. 모드가 `rule` 이 아닌데 읽기 함수가 없으면 로그 경고(또는 `unchecked` + 이유)를 남겨 주세요. 프로젝트 규칙의 「조용한 대체 금지」에 해당합니다.

## 2. 웹 확인 배치 — 팀 정기 작업 자리를 만들었습니다(새벽 3시 정기 점검 시간대)

**정정**: 요청서의 「15시 정기 점검 직전」은 **03시 정기 점검**입니다. 코어의 새벽 작업(식당 새벽 확인 · 관광공사 운영시간 새벽 읽기)은 03:00~08:00 사이에만 일하고, 작업 실행기는 1분마다 돕니다.

이 배치 하나만 실행기에 박지 않고, **팀이 코어를 고치지 않고 정기 작업을 더하는 자리**를 만들었습니다.

| 누가 | 무엇을 |
|---|---|
| 활동 팀 | `app/domains/travel_ops/instances/activity/jobs.py` 에 `JOBS = [TeamJob(name="activity_live_status", tick=..., window="dawn")]` |
| 코어 조립 | 활성 팀의 `jobs.py` 를 찾아 등록한다(`components/team_hooks/scheduled_jobs.py`) — 파일이 없으면 건너뛰고, 파일 안 import 가 깨졌으면 기동을 멈춘다 |
| 작업 실행기 | 1분마다 부른다. 시간대(`guardrails.yaml travel.team_jobs.windows.dawn` = 03:00~08:00) 밖이면 부르지 않는다. 결과는 `team:<이름>` 줄에 실린다 |
| 손으로 돌리기 | `python -m scripts.run_sweepers --only team:activity_live_status` — 시간대를 보지 않고 지금 한 번 |

활동 쪽에서 맞춰 주실 것:

1. `check_live_status.py` 의 본문을 **한 회차 함수** `tick(tenant_id: str, now: datetime) -> dict[str, int]`(건수 반환, `now` 는 서울 시각)로 빼서 `TeamJob` 에 넣어 주세요. 스크립트는 그 함수를 부르는 껍데기로 남기면 됩니다.
2. **1분마다 불립니다.** 시간대 밖 막기는 실행기가 하지만, 한 회차에 몇 곳까지(`per_tick`)와 「이미 확인한 곳 건너뛰기」는 `tick` 이 지켜 주세요(지금의 6시간 재확인 · 예산 멈춤 그대로).
3. 예산 계산을 다시 봐 주세요. 72시간 앞까지 보고 6시간 뒤 재확인이라, 매일 새벽 돌면 같은 장소 · 같은 날짜를 **최대 3번**(사흘 전 · 이틀 전 · 하루 전) 부릅니다. 요청서의 「장소 · 날짜당 한 번」과 다릅니다. 의도한 것이면 문서에 「최대 3번」으로 적어 주시고, 하루 50회 상한이 그 기준으로 충분한지 봐 주세요.
4. 확인 대상은 **여행 일정 항목**에서 고르는데, 저장값을 읽는 쪽은 **예약 성립 판정**입니다. 일정에 연결되지 않은 예약은 계속 「미확인」으로 남습니다. 예약도 대상에 넣을지, 아니면 그 경우를 「미확인 — 일정 밖 예약」으로 따로 세어 둘지 정해 주세요.

`refresh_places → read_hours → decide_indoor` 도 같은 방식(한 회차 함수를 `JOBS` 에 더하기)으로 넣으시면 됩니다 — 코어 변경 없이 돕니다. 순서가 필요하면 한 `tick` 안에서 차례로 부르세요.
