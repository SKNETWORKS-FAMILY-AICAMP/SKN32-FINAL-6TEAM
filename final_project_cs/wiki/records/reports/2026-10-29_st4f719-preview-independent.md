2026-10-29 KST. **릴리스 HOLD를 유지합니다.** [수정 후보 인계](../../../../wiki/handoff/2026-10-29_st4f719-preview-privacy-fix.md)를 기존 격리 후보에서 독립 검증했습니다. 실제 PostgreSQL 쿠키 인증을 사용하는 Edge 시험은 21/24 = 87.5%이며, 비인증 전환의 늦은 성공·늦은 실패 재시도·재시도 중 성공 3건이 실패했습니다. A→B와 A→B→A의 보호는 확인됐지만 비인증 경계까지 승인할 수 없습니다. 기존 scanner/XML 보안 HOLD도 남습니다.

## 재현과 판단

`scratch/st4f719-blocker-independent-20261029/repo`를 그대로 재사용했습니다. 이 검증 세션은 제품 수정 작성자가 아니며 제품 수정은 하지 않았습니다. 다른 담당자의 승인이나 최신 통합 tip 검증을 확보했다고 표시하지 않습니다.

실제 PG `/auth/me` 인증으로 합성 계정 A를 확인한 뒤 마운트된 React hook의 `previewRecommendAll`을 호출하고 응답을 보류했습니다. 계정 B, A로의 복귀, 쿠키 제거 후 비인증 확인, 취소, 페이지 unmount를 수행한 다음 응답을 완료했습니다. 쿠키·계정·scope 값은 출력하지 않고 반환 여부·일반 오류 코드·자료 표식 유무·호출 수만 집계했습니다. 새 소유자의 warm-up은 보류·변조 대상에서 제외했습니다.

**P1: query 수명이 비인증 상태의 요청 수명까지 보장하지 않습니다.** `providers.tsx`와 `cache-owner.ts`는 401에서 오류 화면을 유지하기 위해 기존 query를 보존합니다. `intake-review.tsx`의 `isCurrent`는 query 객체 동일성만 검사하고 `use-server-review.ts`의 `active()`는 그것과 mount 생존 여부에 의존합니다. 따라서 query가 남은 비인증 전환은 늦은 응답의 소유권을 끝내지 못합니다.

- 늦은 성공: 응답 해제 전후 인증 없음, 원래 요청 1회, 이전 응답의 `AutoResult` 반환과 hook 미리보기 상태 저장을 확인했습니다.
- 재시도 중 늦은 성공: 두 번째 요청이 시작된 뒤 비인증으로 전환해도 결과 반환과 상태 저장을 확인했습니다.
- 늦은 실패: 비인증 확인 뒤 원래 응답을 실패시키자 추가 autofix와 stub 세션 생성이 일어났습니다. 전체 autofix 3회에는 후속 warm-up도 포함되므로 이를 재시도 3회라고 세지 않습니다. 최종 반환은 `item_gone`으로 거절됐으나, 오래된 작업이 후속 요청·새 세션을 시작하는 결함은 남습니다.
- 같은 비인증 전환에서 보관된 취소 콜백을 먼저 호출하면 늦은 성공은 거절됐습니다.

늦은 응답의 **hook 상태·반환 경계** 재현입니다. 실패한 두 성공 시험은 상태 검사에서 중단됐으므로 DOM에 개인정보가 렌더링됐다는 별도 주장은 하지 않습니다. `auth/me`와 세션 검증은 실제 PG이며 여행 응답·쓰기·새 세션 생성 응답은 로컬 stub입니다. 운영 여행 mutation·실제 고객 자료 유출·실제 소셜 로그인 검증으로 일반화하지 않습니다. 권고는 오류 화면 보존과 별개로 요청 시작 시 인증 수명을 캡처해 세션 소실 이후 응답·재시도를 영구 거절하는 것입니다. 이 검증에서는 제품을 고치지 않았습니다.

첫 실행 16/20, 두 번째 20/24에는 새 소유자의 warm-up까지 보류하거나 동일 계정의 최종 오류 대조군 재시도를 성공으로 돌린 시험 오류가 포함됐습니다. 세 번째는 선택 구문 오류로 시험 0개였으며 통과로 세지 않습니다. 이를 수정한 최종 21/24 결과와 최초 실패·준비 오류를 모두 보존했습니다. 최종 비인증 실패 3건은 시험 오류 수정 후에도 재현됐습니다.

## 조정·재현·인계

루트·후보 규칙, RULE, wiki 정본·역할·코드 경로·웹 인증 계약, 기존 coord snapshot(62개)을 작업 전에 읽었습니다. 현재 `wiki/coord`·`_coord`와 프로젝트 상위의 coord 디렉터리는 없었고 접근 가능한 전용 coord 도구도 없습니다. snapshot은 최신 예약의 보장이 아닙니다. 공유 계약·다른 후보·원격 예약을 변경하지 않았으며 이 세션의 로컬 검증 사용 범위는 반환합니다. 디스크 가드 ledger에 해당 scratch 후보의 lease가 없으므로 등록·release 명령으로 다른 소유권을 바꾸지 않았습니다.

재현은 기존 작업 폴더의 `independent_preview_verify.py`와 추가 시험을 사용합니다. 새 이름으로 실행하도록 phase/output 이름을 바꿔 기존 자료를 보존하십시오. 정상 실행은 최종 `browser4`, 변이는 `mutant`, 관문은 `gates`, 복구 시험은 `unit-restored`에 기록했습니다. 변이·PG·다른 시험을 동시에 실행하지 마십시오. 공개 [집계·시험·보존](../evidence/2026-10-29_st4f719-preview-independent/)에 결과가 있고 원시 로그·계정 fixture·setup 백업은 기존 작업 폴더에만 있습니다.

디스크 inventory와 생성 파일 실측은 evidence의 `disk-inventory.json`·`privacy-receipt.json`에 남깁니다. 기존 PG·Next 캐시의 순증은 사전 측정이 없어 분모 모름입니다. 새 전체 사본 대신 기존 산출물을 재사용했습니다. 공개 파일은 실제 fixture 문자열 대조와 기존 scanner 함수로 검사하며 예외를 추가하지 않습니다. [인계](../../../../wiki/handoff/2026-10-29_st4f719-preview-independent.md).

보존 검사 첫 실행에는 manifest의 해시 객체를 문자열과 비교한 검사기 오류가 있었습니다. 최초 실패 결과를 보존하고 `sha256` 필드를 비교하도록 수정한 뒤 상속 source 11/11 = 100%를 확인했습니다. 제품 파일 변경은 없었습니다. 공개 요약도 최초 생성분을 로컬에 보존한 뒤 최종 해시 결과로 갱신했습니다.
