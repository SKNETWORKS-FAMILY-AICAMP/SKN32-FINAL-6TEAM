## 원인

1. **실행 프로그램이 A4000 용이 아니었다.** 작업큐의 모델 실행 프로그램(llama-server)은 ADA2000 에서 옮겨 온 판(llama.cpp `4ebdf2c`)이었고, A4000(연산 능력 8.6)용 CUDA 커널이 없어 모델을 올리는 순간 `CUDA error: no kernel image is available for execution on the device` 로 죽었습니다. 같은 기계에서 성공한 「현재 제품 판정 1448문항」 작업은 계약 파일로 A4000 에서 직접 빌드한 판(`bed0a85`)을 따로 쓰고 있어 피해 갔습니다. 해당 작업 9개: E2 비교 6개(E4B QAT 원본 · finch · cosine · oos2r · oos3 · Saluki 27B 원본) · 앱 스키마 비교 3개.
2. **메모리 한도를 cgroup v2 경로로만 읽었다.** A4000 컨테이너는 cgroup v1 이라 `/sys/fs/cgroup/memory.max` 가 없어 `FileNotFoundError` 로 끝났습니다. 해당 작업 2개: Winnow 기반 GGUF 준비 · Saluki 시험 학습. 이 둘이 막히면서 뒤에 걸린 Winnow 비교 9개와 Saluki 변환 · 평가 8개가 입력 파일을 기다리며 멈췄습니다.

Winnow 새 학습(`oos2_cosine_s20261019`)은 이 두 원인과 무관하게 끝났습니다(2,613행 · 654단계 · 약 5시간, 어댑터 GGUF 변환 완료).

## 바꾼 것

- **작업큐 실행 프로그램**: `manifest.json` 의 `engine` 을 A4000 빌드로 바꿨습니다. 바꾸기 전 manifest · state 는 작업큐 폴더 `_backup/2026-10-15_1655_retry_engine_switch/`(UTC 시각) 에 있습니다. 바뀐 이유 · 두 판의 해시는 manifest 의 `engine_change_20261016` 에 적었습니다. ★llama.cpp 커밋이 `4ebdf2c` → `bed0a85` 로 다릅니다. 앞서 ADA2000 에서 잰 결과와 견줄 때 실행 프로그램 판이 다르다는 것을 함께 적습니다.
- **메모리 한도 코드 새 판**(원본은 그대로 둠): Winnow `queue_control_v2.py` · Saluki `runner_v2.py` · `saluki_packed_lora_queue_v2_20261016.py`(새 runner 를 부름) · `saluki_lora_convert_v2_20261016.py`(새 학습 폴더를 가리키는 `queue_private_config_r2.json` 을 읽음). 공통 함수 `cgroup_memory()` 가 v2 → v1 순으로 읽습니다.
  - ★**판단 하나를 바꿨습니다**: 「쓰는 메모리」를 `사용량 − 비활성 파일 캐시` 로 셉니다(되찾을 수 있는 캐시는 뺌, /dev/shm 은 그대로 셈). 원래 식(캐시 포함)으로 세면 여유가 8.4GiB 라 Saluki(12GiB 필요) · Winnow 준비(13.5GiB 필요)가 캐시 때문에 계속 막힙니다. 새 식으로는 여유 19.4GiB 입니다.
- **다시 넣을 작업 12개**(`_r2`, 원래 작업의 실패 기록은 그대로 둠): Winnow 기반 준비 1 · 앱 스키마 3 · E2 비교 6 · Saluki 시험 학습 1 · Saluki 변환 1. 순서와 설정은 원래 작업 그대로이고 `retry_of` · `retry_reason` 을 붙였습니다. 목록은 작업큐 폴더 `retry_20261016/staged_jobs.json`.

## 왜 아직 작업큐에 안 넣었나

각 실행기가 시작할 때 「루트 디스크 3GiB 이상」을 확인합니다. 지금 2.0GiB 라 넣는 즉시 실패하고, 작업큐는 실패를 자동 재시도하지 않아 또 새 판을 만들어야 합니다. 그래서 `retry_20261016/open_gate.py` 가 작업마다 조건(루트 3.5GiB · Winnow 준비는 /dev/shm 9.96GiB · Saluki 학습은 메모리 여유 12GiB)을 확인하고 통과한 것만 manifest 에 붙입니다. 기본은 확인만 하고, `--apply` 일 때 manifest 를 백업한 뒤 붙입니다.
