## 배경 — 무엇이 빠져 있었나

앞 단계(0229·0249 리포트)는 서버에 경로가 없는 동작을 화면에서 빼거나 미리보기에만 두었다. 목업과 비교하면 다음이 없었다.

- 지도가 화면을 채우고 위 막대가 떠 있으며 시트가 지도 위로 올라오는 배치
- 수정 화면: 검색창이 된 위 막대, 지금 일정과 후보 A·B·C 카드 넘기기, 지도의 후보 핀, 사진, 검색 결과, 「이 장소로 바꾸기」
- 카드의 「자동 추천」, 잠금, 삭제 뒤 「되돌리기」
- 하단의 「전체 자동 추천」 → 「재검증」 → 「여행 등록」 → 「등록 완료」

사용자 결정(위 지시)에 따라 **화면은 목업대로 모두 두고, 서버가 아직 없는 동작은 함수 자리(`PlanCheckActions`)만 비워 둔다.** 비어 있는 동작의 단추는 보이되 `aria-disabled`이고, 누르면 이유(「…은 준비 중이에요」)를 알린다.

## 수행 내용

### 1. 화면 — [plan-check.tsx](../../../frontend/apps/web/src/features/plan-check/plan-check.tsx)

- **배치**: 지도(`TripMap variant="fill"`)가 칸을 채우고, 위 막대는 떠 있으며, 시트는 손잡이로 반·전체·접힘을 오간다. 핀이 위 막대 밑에 깔리지 않게 지도는 막대 아래에서 시작한다.
- **카드 도구**: 수정·자동 추천·잠금·삭제. 잠그면 수정·자동 추천·삭제가 막히고, 확인 필요 일정은 잠글 수 없다(목업 규칙). 막힌 단추도 누르면 이유를 말한다(`Act`).
- **알림**: 바꾼 내용과 「되돌리기」를 함께 보인다. 되돌리기는 `undo`가 있을 때만 나온다.
- **머리 상태**: 등록 완료 / 재검증 중 i/n / 확인 필요 / 고친 곳이 있어요 · 재검증해 주세요 / 고칠 곳이 없어요.
- **하단**([result-parts.tsx](../../../frontend/apps/web/src/features/plan-check/result-parts.tsx) `ResultFooter`): 「전체 자동 추천」과 남은 개수, 오른쪽 단추는 상태에 따라 재검증 → 여행 등록 → 「✓ 등록 완료」(여행 보기 링크).
- **삭제 확인창**: 「○○ 일정을 삭제하시겠습니까?」. 되돌리기가 없으면 「삭제한 일정은 되돌릴 수 없어요」라고 미리 말한다.

### 2. 수정 화면 — [place-change.tsx](../../../frontend/apps/web/src/features/plan-check/place-change.tsx)

- 위 막대가 장소 검색창이 되고, 시트에 「○○ 바꾸기」와 카드 넘기기(지금 일정 + 후보)가 나온다. 넘긴 카드에 맞춰 지도 핀이 강조된다(회색·바꾸는 일정·후보 A·B·C — `map/model.ts` `PinLook`).
- 후보 카드: 순위·거리(「○○에서 0.9km」)·분류·주소·이 장소의 검사·「이 장소로 바꾸기」.
- 사진: 6칸 격자, 「사진 더 보기」는 시트를 전체로 올린다.
- 검색: 결과를 같은 카드 모양으로 보인다. 검색이 없는 서버에서는 「장소 검색은 준비 중이에요」와 함께 **「「검색어」로 바꾸기」**를 내어, 쓴 이름을 서버가 다시 찾게 한다(지금 서버로 되는 길).
- 「직접 고치기」(이름·날짜·시각·장소 없음)는 접힌 칸으로 남겼다.
- 조사 처리는 `src/lib/josa.ts`(을/를, 으로/로, 과/와).

### 3. 미리보기 — [preview-engine.ts](../../../frontend/apps/web/src/features/plan-check/preview-engine.ts) · [preview.tsx](../../../frontend/apps/web/src/features/plan-check/preview.tsx)

- 목업 스크립트의 규칙을 옮긴 **예시 계산**이다: 같은 분류의 가까운 후보 3곳, 거리, 방문 시각의 운영시간·휴무일 검사, 앞뒤 이동 다시 계산, 전체 자동 추천(잠근 일정 유지), 삭제 뒤 이동 잇기, 일정별 재검증 순서.
- 판정 규칙은 목업과 같다: 검사 중 `bad`가 하나라도 있으면 확인 필요.
- 예시 장소 18곳·사진 이름은 목업 데이터 그대로다(`fixtures.ts`).
- 실제 경로는 이 파일들을 쓰지 않는다. live 빌드에서 `/preview/plan-check`는 404다.

### 4. 실제 경로 — [intake-review.tsx](../../../frontend/apps/web/src/features/intake-review/intake-review.tsx) · [from-intake.ts](../../../frontend/apps/web/src/features/plan-check/from-intake.ts)

## 작업 중 바로잡은 것

- **위 막대 밑 핀이 눌리지 않음**: 지도가 화면 맨 위부터 그려져 막대가 핀을 가렸다. 지도를 막대 아래(60px)에서 시작하게 했다.
- **판정 규칙 차이**: 처음에 `warn`도 확인 필요로 셌다. 목업 규칙(`bad`만)으로 맞췄다.
- **사진 안내가 틀림(live)**: 장소가 아직 없고 넘길 후보도 없는데 「옆으로 넘겨 후보 매장의 사진을 보세요」가 나왔다. 넘길 후보가 있을 때만 그 안내를 보이고, 아니면 「등록된 사진이 없어요 · 장소 사진은 준비 중이에요」를 보인다.
- **꺼진 단추 시험**: Playwright는 `aria-disabled` 단추를 누르지 않는다. 이유 알림을 보는 시험은 `click({ force: true })`로 누른다.
