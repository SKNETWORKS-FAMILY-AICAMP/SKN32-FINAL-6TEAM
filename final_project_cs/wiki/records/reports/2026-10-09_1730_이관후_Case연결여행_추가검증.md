# 이관 후 기존 Case가 있는 여행의 웹 접근

현재 회원은 이관된 여행에 기존 Case가 있어도 제안을 조회·선택할 수 있습니다. Case가 발생한 시점의 기록을 직접 수정할 필요는 없었습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 열린 Case 여행 권한 추가 시험 | 통과 | 1/1 = 100% |
| 이관 시험 전체 | 통과 | 8/8 = 100% |
| 새 브라우저 왕복 시험 작성 | 완료 | 2/2 = 100% |

- `tests/e2e/test_web_auth_guest_transfer.py`에 열린 Case·여행·보류 제안을 만든 뒤 회원의 조회/선택과 다른 고객의 404를 확인하는 시험을 추가했습니다. [실행 근거](../evidence/2026-10-09_1730_이관후_Case연결여행_권한.md).
- `tests/live/unified-account-20261009.spec.ts`에 글 작성→소셜 mock 왕복→복구, 파일 한도 거절→입력 보관→소셜 mock 왕복→첨부·글 복구 2건을 추가했습니다. 실제 브라우저 실행은 루트 종합 시험에서 수행합니다.
- 기존 `tests/live/social-login.spec.ts`의 분리된 연결/로그인 선택과 게스트 자료 소실 경고 기대를 새 사용자 계약에 맞췄습니다. 기존 회원 연결 충돌·nonce·재사용 표 시험은 유지했습니다.

기존 Case의 운영자 화면, 실행 중인 모든 Core 업무와 장기 기록 보관 정책은 이번 단일 권한 시험의 범위가 아닙니다. 기존 게스트 보관 만료로 옛 Case가 정리될 가능성은 루트에 전달했고 삭제 정책은 임의로 바꾸지 않았습니다.

기존 파일 사본은 [수정 전 백업](../../../_backup/2026-10-09_통합인증_수정전/)에 있습니다. `customer_cases` 직접 UPDATE, x600 서버 배포, 실제 외부 소셜 인증은 하지 않았습니다.
