## 요청과 결정

- 2026-10-22 사용자: 채팅 입력창 위 단추와 서버 답 UI 를 바꾸기 전에 트렌드 조사 + 목업 여러 안 → **② 상황 칩 + ⓑ 결과 카드**, 서버 수정 없이 프론트만 먼저.
- 같은 날 결정: ⓑ 서버 글 가운데 카드와 겹친 줄은 **글자까지 같을 때만 · 카드가 그려졌을 때만** 뺀다 · 칩 줄은 옆으로 밀기(채팅 칸 「밀면 일정 칸」과 구분 — `data-no-swipe`) · 서버 선택지(혹시 이런 뜻이었나요? · 다음 중 하나인가요?)는 칩 줄이 아니라 **답 카드 아래에 줄을 바꿔 전부** · 카드 단추 「상세 보기」 → 그 일정의 상세 보기, ← 로 채팅 칸 보던 자리 · 「채팅으로 일정을 바꾸면 …」 안내는 **입력창 아래 짧은 한 줄 + 「자세히」**(펼친 창은 창 밖을 누르거나 Esc 로 닫힘).

### 겹친 줄 빼기 — 실제로 빠지는 것과 남는 것

서버 문장 틀(`trip_facts.py` · `chat_edit.py`, 2026-10-22)을 읽어 화면 값으로 같은 줄을 다시 만든다. 글자가 다르면 남긴다.

| 줄 | 결과 |
|---|---|
| 하루 요약의 일정 줄 「· 09:00~11:00 경복궁 관람(활동)」 | 빠짐(타임라인 카드) |
| 시각 바꾸기 답의 「· 10월 24일(토) 12:00~13:00 광장시장 점심」 | 빠짐(바뀐 일정 카드) |
| 「마음에 안 드시면 「되돌려 줘」라고 말씀해 주세요.」 | 되돌리기 단추가 그려진 동안만 빠짐 |
| 「· 지도: …」 · 「지도에서 보기: …」 | 링크가 그 일정의 `mapUrl` 과 같을 때만 빠짐 |
| 「· 어디: 장소 · 주소」 | 서버가 따로 조회한 주소가 화면 주소와 같을 때만 빠짐(다른 출처라 대개 남음) |
| 「· 그날 영업: …」 · 「영업시간(저장된 값)」 · 이동 줄(「↳ 이동: …」) | 남음 — 서버가 쓰는 값(저장 운영시간 · 이동 수단 · 걸리는 시간)이 여행 조회에 없다 |

### 데이터 · 서버 협의(나중)

- 장소 카드가 뜨는 때: 칩(「선택 일정」 · 「다음 일정」)으로 보낸 답은 바로, 직접 쓴 질문은 대화 기록(`/chat`)의 `reply.focus` 가 실린 뒤.
- 바뀐 일정 비교 · 머리표 · 진행 과정은 이 탭에서 받은 답에만(되돌리기와 같은 기준) — 다른 기기 · 새 탭에서 다시 읽은 대화는 글만.
- 서버 협의 거리: 보내기 응답 · 대화 기록에 `status` · `focus`, 사실 질문의 마지막 단계 이름(지금은 「일정에 반영하는 중이에요」), `answer_web` 의 「되돌려 줘」 꼬리, 카드용 구조화 칸(저장 운영시간 · 이동 수단), 선택지 짧은 이름.
