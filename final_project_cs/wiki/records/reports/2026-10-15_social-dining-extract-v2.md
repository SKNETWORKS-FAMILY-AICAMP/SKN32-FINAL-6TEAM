# SNS 맛집 추출 프롬프트 v2 — 2026-10-15

## 요청과 변경

사용자 지시: v2에서 `null` 예시를 빼고, 지역은 전체 주소 대신 가장 짧은 지명으로, 지역·메뉴의 근거 줄도 함께 인용한다.

`app/domains/travel_ops/components/intake/social_links.py`의 기본 추출 프롬프트를 `social_dining_extract.v2`로 바꿨다. 이름·지역·지점·메뉴를 독립적으로 살피고 원문에 명시된 값만 채운다. 값이 없거나 식당과의 연결이 모호하면 해당 필드는 여전히 `null`이다.

- 값을 모두 채운 합성 예시 2개로 교체했다. 하나는 서로 다른 메타 줄의 이름·지역·복수 메뉴, 하나는 메타와 고객 메모의 분리 인용이다.
- 지역은 원문이 해당 식당에 연결한 짧은 동네·상권·역명을 우선한다. 없으면 명시된 구·도시를 쓴다. 도로명·건물번호·전체 주소를 넣거나 주소에서 동네를 추정하지 않는다.
- 명시적 지점 접미사는 별도 지점 칸에도 넣고, 각 메뉴를 원문 그대로 담는다. 복수 식당의 지역·메뉴를 섞지 않는다.
- 지역·메뉴가 이름과 다른 줄이면 해당 근거 줄도 각각 인용한다. 인용의 실제 출처(`metadata`, `customer_note`)와 원문 부분문자열 검증을 유지한다.
- 응답 모양·메타 수집 경로·일정 변경 절차·모델 설정을 바꾸지 않았다. 저장된 v1 후보를 자동 재추출하지 않는다. 새 추출부터 v2 버전·해시를 기록한다.

## 모델 비교

합성 QA 8건은 별도 검토자가 사전 정답과 함께 작성했다. 프롬프트를 확정한 뒤 같은 입력에 v1·v2를 적용한다. QA 결과로 프롬프트를 다시 조정하지 않는다. 프롬프트 예시·실제 SNS 5건 개발 기록과 구분한다.

최종 비교 **16/16 = 100%** 응답을 확인했다. [평가 JSON](../../../eval/reports/2026-10-15_social_extract_v1_v2_synthetic8.json)에 고정 입력·사전 정답·v1/v2 지시문·모델 원응답·서버 근거 대조 결과를 함께 보관했다. 지역·메뉴의 전체 근거 줄은 [줄별 검증 JSON](../../../eval/reports/2026-10-15_social_extract_v1_v2_support_lines.json)으로 대조했다.

| 고정 합성 평가 기준 | v1 | v2 |
|---|---|---|
| 식당명·지역·지점·메뉴 모두 정답과 일치한 사례 | 4/8 = **50%** | 7/8 = **87.5%** |
| 이름 포함 각 필드의 엄격 일치 | 18/32 = **56.3%** | 28/32 = **87.5%** |
| 실제 명시된 선택 필드(지역·지점·메뉴)의 엄격 일치 | 9/20 = **45%** | 18/20 = **90%** |
| 지역 값과 근거 줄 전체를 함께 확인 | 3/7 = **42.9%** | 6/7 = **85.7%** |
| 각 메뉴 값과 근거 줄 전체를 함께 확인 | 3/10 = **30%** | 9/10 = **90%** |
| 지역·메뉴 합계 | 6/17 = **35.3%** | 15/17 = **88.2%** |

엄격 일치는 사전 정답의 식당명으로 항목을 연결하고, 지점 분리와 복수 메뉴의 개별 배열 출력까지 확인한다. 단일 메뉴 문자열과 1요소 배열은 같게 본다. v1은 일부 지점을 이름에 붙이거나 복수 메뉴를 하나의 문자열로 내보내 점수가 낮아졌다. 이 비율은 **단순히 빈칸을 채운 비율이 아니다.** 식당 자체를 놓친 경우 그 식당의 모든 필드와 기대한 근거 줄을 실패로 센다. 실패 사례를 분모에서 빼지 않았다.

v2의 실패 1건(`synthetic-06`)은 정상 식당 정보와 지시문 주입이 함께 있는 입력이다. 지역·메뉴를 가짜 값으로 바꾸지는 않았으나, 정상 정보까지 버리고 `restaurant_not_found`를 반환했다. 이 건은 v1이 맞혔던 퇴행이다. 검증 표본으로 프롬프트를 조정하지 않고 누락 한계로 남겼다.

응답 시간은 v1 중앙값 18.711초·최대 31.094초, v2 중앙값 13.329초·최대 47.516초였다. 표본이 작고 각 1회이므로 속도 개선을 주장하지 않는다.

평가 스크립트와 고정 입력·프롬프트는 저장소 루트 `tmp/social-dining-v2/`에 있다. 모델에는 합성 메타와 합성 고객 메모만 보내며, SNS나 고객 DB는 호출하지 않는다. 설정된 `gemma4:e4b`, temperature 0, seed 미지정, 문맥 8192, 각 1회로 평가한다. 순서 효과를 줄이기 위해 사례마다 v1·v2 순서를 교대한다.

처음 평가 도구에 쓴 합성 URL이 지원 형식과 맞지 않아 모델 호출 전 거절된 실행은 도구 오류로 제외했다. URL만 고쳤고 프롬프트·입력·정답을 조정하지 않았다. 제한 환경 사전 호출은 0.125초 만에 `OllamaError`로 실패했고, 네트워크 실행에서도 15초의 평가용 제한을 넘어 중지했다. 이 사전 시도 실패 2건은 JSON의 `setup_attempts`에 남겼다. 최종 비교 16건에는 앱의 원래 60초 제한을 그대로 사용했으며 모두 응답했다. 앱 설정은 변경하지 않았다. 현재 실행 환경에는 별도 서버용 API 키가 없어 API 모델을 호출하지 않았다.
