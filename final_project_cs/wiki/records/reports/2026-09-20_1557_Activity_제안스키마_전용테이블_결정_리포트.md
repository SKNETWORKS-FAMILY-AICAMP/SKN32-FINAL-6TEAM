# Activity — 제안 DB 스키마(activities/tour/disaster)를 Activity 전용으로 결정

## 1. 작업 목표

`wiki/teams/activity.md`의 "데이터 저장 — 제안 스키마" 절에 남아 있던 미확보("`activities`/`tour`/`disaster`가 Activity만의 것인지 Dining과 공유할지")를 사용자 결정으로 닫는다.

## 2. 실제 수행 내용

변경 파일: `wiki/teams/activity.md`

1. "실제 `places` 테이블" 서브섹션의 마지막 문장을 "아래 제안 스키마는 Activity 전용이다"로 정정.
2. "제안 테이블" 서브섹션 제목을 "제안 테이블 — Activity 전용"으로 바꾸고 `[결정 2026-09-20]` 태그로 명시 — Dining·Mobility 공유 여부는 다시 묻지 않는다고 못박음. 표에 "소유" 열을 추가해 세 테이블 모두 **Activity 전용**으로 표시.
3. 새 문단 추가 — `activities`(제안)와 기존 `places`(실제, 공유)가 서로 다른 목적임을 명시(범용 장소 vs Activity 전용 부가 정보). 둘의 관계(FK로 묶을지 간접 연결만 할지)는 아직 미확보로 남김.
4. "걸리는 것" 표의 "제안 DB 스키마 vs 실제 마이그레이션" 행을 "부분 닫힘"으로 갱신 — 전용 여부는 결정됐고, 마이그레이션 미반영·`places`와의 관계만 남은 미확보로 재정리.

## 3. 검증 방법과 결과

문서 반영 작업. 코드 실행 검증 해당 없음.

## 4. 미해결 이슈·다음 작업 제안

- `activities.tour_api_content_id`/`disaster_api_content_id`가 `places`의 `source_content_id`와 같은 개념인지, 중복 저장이 되는 건 아닌지 실제 마이그레이션 작성 시 확인 필요.
- `activities`를 실제로 마이그레이션에 넣을 시점과 담당자는 아직 정해지지 않음.
