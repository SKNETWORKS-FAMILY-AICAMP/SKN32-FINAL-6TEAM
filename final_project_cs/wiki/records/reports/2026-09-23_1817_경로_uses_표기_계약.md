# 경로 `uses` 표기를 계약으로 정했다

작성 2026-09-23 18:17 · 문서 작업(코드 변경 없음)

## 1. 왜

일정 등록 몸통 `routes{<키>}.options[].uses` 의 표기를 묻는 질문이 들어왔다 — 지하철 노선을 이름으로 쓰는지,
역명에 「역」을 붙이는지, 버스는 노선번호·정류장·구역 중 무엇인지, 도로는 UTIC 도로명을 그대로 쓰는지.

찾아본 결과 **계약이 어디에도 없었다.**

| 찾은 곳 | 결과 |
|---|---|
| `wiki/external/rest-endpoints.md` 여행 API 절 | `uses` 표기 없음 |
| `wiki/decisions/D-CS-005-odsay-not-used.md` | `uses` 를 외부가 보낸다는 사실만 있고 형식은 없음 |
| 코드 docstring | `replay.py:104` 「노선:역」·「도로:이름」 모양 — 한 줄 |
| 확정 시나리오 JSON | 세 가지 뜻이 섞임 — `2호선:잠실`(역) · `버스:성수동`(구역) · `도보:서울역`(도착지) |

감시가 이 값을 사건과 **문자열로 대조**하므로, 표기가 다르면 사건이 있어도 **오류 없이 놓친다.**
보내는 쪽이 알아서 쓸 수 있는 칸이 아니다.

## 2. 무엇을 정했나

`wiki/external/rest-endpoints.md` 「`routes{<키>}.options[].uses`」 절.

| 수단 | 형식 |
|---|---|
| 지하철 | `<노선명>:<역명>` — 1~9호선은 `N호선`(두 자리 채움 ✗), 역명은 「역」·괄호 병기 뺌, 역 이름 자체가 「서울역」이면 그대로. 탄 역·갈아탄 역(두 노선 각각)·내린 역만 |
| 버스 | `버스:<노선번호>` + 지나는 주요 도로를 `도로:` 로 함께 |
| 도로 | `도로:<UTIC 도로명 전체>` |
| 도보 | `도보:` 쓰지 않음 — 지나는 큰길을 `도로:` 로, 없으면 `[]` |

**바깥 계약이라 사람이 읽는 공식 표기를 쓴다.** 내부 데이터가 다른 표기(예: 두 자리 노선명)로
정규화하더라도 그 변환은 그 모듈의 입구에서 한다 — 외부가 내부 키 규칙을 알게 만들지 않는다.

## 3. 확인한 것

- 대조 지점 네 곳의 줄을 현재 작업 트리에서 확인했다 — `trip_watch_cases.py:126` · `trip_reminders.py:225` ·
  `replan.py:204` · `itinerary_changes.py:152`.
- UTIC 대조는 **포함 여부**다(`app/infrastructure/travel/utic.py:177` — `roadName`·`incidentTitle`).
  그래서 도로명을 줄이지 말라고 적었다.
- 지하철·버스는 우리 코드에 연결된 실시간 소스가 없다 — UTIC 소스가 `unsupported()` 로 「확인 못 한 대상」을 돌려준다
  (`utic.py:161`). 후보로 서울교통공사 지하철알림정보(data.go.kr 15144070)를 `[미연결]` 로 적었다.
  이 후보는 이동 담당 팀원 브랜치(`team/role-mobility`, 미병합)의 소싱 문서가 조사한 것이며 참고로만 인용했다.

**하지 않은 것** — 코드·시나리오 JSON·시험은 고치지 않았다(문서 세션). 역명 표기가 실제 소스 표기와 같은지는
소스를 붙일 때 다시 확인해야 한다.

## 4. 남은 것 (코드 담당)

1. 확정 시나리오 JSON 의 `버스:성수동`·`도보:서울역`, 환승역 한쪽만 적은 구간을 계약에 맞춘다.
2. 등록 시 형식 검사 — 표에 없는 모양을 거절(`422`)할지 경고할지 정한다. 지금은 받는다.
3. 이동 데이터 모듈이 들어오면 입구 어댑터에서 표기를 바꾼다(누가 만들지는 이동 담당과 합의).
