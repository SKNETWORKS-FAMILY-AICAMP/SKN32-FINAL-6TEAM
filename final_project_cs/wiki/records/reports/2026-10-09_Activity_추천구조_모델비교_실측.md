## 선별의 효과와 위험

Jev API(유료)가 낸 특성 확률과 코드 가중합으로 상위 4개만 남기면 최고 정답 보존은 61/72 = 84.7%, 정답 상위3 회수는 87.0%입니다. 이번 연쇄는 규칙 상위 2개를 추가 보호하여 최고 정답 보존 71/72 = 98.6%, 정답 상위3 회수 94.4%였습니다. 따라서 연쇄 결과를 선별 모델 단독 성능이라고 부르지 않습니다. Noul 확률을 이 자료에서 따로 보정하지 않고 기대 취향 점수로 결합했습니다. 이 결합 방식의 성능과 다른 Score·임계값·추가 학습 구성은 구분해야 합니다.

후속 모델은 선별 단계에서 사라진 후보를 회복할 수 없습니다. 선별 비용은 후속 입력 절감보다 작아야 하고, 출력·추론 토큰 감소까지 실제로 확인해야 합니다. 이 시험은 후보 수를 9개로 고정했으므로 더 큰 후보 목록에서의 비용 손익을 직접 측정하지 않았습니다.

## 비용·토큰·실패

## 실제 서비스 연구에 적용할 구조

[추천 흐름 그림](../../../../program/research/activity_recommendation_20261009/recommendation-flow.html)은 연구 제안입니다. 고객 분석 기능이 취향·기피·동행자 요구·중요도·원문 근거를 정리하고, 코어는 공통 계약으로 전달하며, Activity가 후보 회수와 분야별 점수를 적용합니다. 코어에 장소 분류와 취향 계산을 넣으면 도메인 독립 경계가 흐려집니다.

모델에 맡길 부분은 “차분하게 앉아서 만들 수 있는 곳”과 후보의 경험을 연결하는 의미 판단입니다. 이동시간·가격·가중합 계산과 현재 사실 검증은 코드가 합니다. Jev API(유료) 등으로 의미 점수를 얻은 뒤 코드만으로 순위가 충분하면 Luna를 생략할 수 있습니다. 복합 취향 충돌·맥락·다양성에서 추가 효과가 검증된 요청만 재정렬합니다. 최종 고객 적용은 한 안을 고르되 대조용 상위3과 규칙·모델 제안은 기록에 보존할 수 있습니다.

최신 근거 43개는 [연구 보고서](../../../../program/research/activity_recommendation_20261009/research.md), [논문·문서·기술 글 목록](../../../../program/research/activity_recommendation_20261009/source_catalog.md), [핵심 본문 대조](../../../../program/research/activity_recommendation_20261009/key_evidence_audit.md)에 있습니다. 논문17·공식문서15·직접기술글11이며 초록만 확인한 자료의 범위를 표시했습니다. 분야 전체를 망라한 전수 조사라고 주장하지 않습니다.

- [COMPASS v2](https://arxiv.org/html/2510.07043v2): 방문 가능 집합과 효용 최적값을 구분합니다. 이번 고정 후보 시험은 재정렬을 보며 후보 검색의 누락은 따로 시험해야 합니다.
- [2026 순서 편향 연구](https://arxiv.org/html/2608.03091v1): 관련도와 일관성은 다른 축입니다. 동일 입력 변동과 순서만의 효과를 분리하는 후속 시험이 필요합니다.
- [TREK v2](https://arxiv.org/html/2607.26977v2): 정답 자체의 실행 가능성을 먼저 검증합니다. 정답 계획의 사람 검수가 고객 만족 검증을 대신하지 않습니다.
- [LinkedIn 검색](https://www.linkedin.com/blog/engineering/search/reimagining-linkedins-search-stack), [Spotify](https://research.atspotify.com/2026/8/from-models-to-products-llms-for-recommendation-at-spotify-scale), [Netflix GenRec](https://arxiv.org/html/2608.10257v2): 실제 후보 연결·학습과 검수·입력 압축·비용 제어를 함께 사용합니다. 전용 추천 모델의 개선을 범용 API 교체의 예상 이득으로 옮기지 않습니다.

후속 검증은 고객 원문을 사람이 블라인드로 검수한 문제, 후보 검색 규모 16·64·256개, 해법 없음·동점·오래된 사실·여러 일정 연결을 포함해야 합니다. 고객 표현을 만드는 사람과 정답 판단하는 사람을 분리하고, 조정 자료와 최종 미사용 평가 자료를 나눕니다. 선별 보정도 조정 자료에서만 하며 미사용 자료로 다시 확인합니다. 최종 관문은 필수 조건 위반·설명 근거·최고 후보 보존·품질 차이·전체 비용·p95 지연입니다. 이 후속 시험은 이번에 실행한 것과 구분합니다.

- 정답 표기의 의미는 AI 작성·다른 에이전트 검수입니다. 사람 검수가 아니며 같은 설명 틀의 반복은 독립성을 낮춥니다. 후보 ID와 설명 구조의 반복도 일반화 한계입니다. 실제 고객 만족·추천 이유의 모든 사실·운영 코드 적용은 미검증입니다.
- 필수 조건 위반은 코드 선별 이후 제출 ID의 검증입니다. 모델 자체가 방문 가능성을 잘 판단했다는 증거가 아닙니다. 공지 조회나 웹 검색 품질도 이번 추천 시험에서 측정하지 않았습니다.
- 실행·분석 단위 시험 71/71 통과는 모델 응답 대역의 계약 검사입니다. mock 서버의 화면 시험은 하지 않았습니다. 실제 OpenAI API·TypeSafe API 호출 결과는 위의 호출 기록과 별도입니다.
