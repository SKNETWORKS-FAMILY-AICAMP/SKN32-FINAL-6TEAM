## 원인과 수정

공개 탭의 DOM을 읽어 확인했을 때 목록 높이 698px, 보이는 높이 429px, 스크롤 위치 269.600006px로 실제 끝에 도달해 있었습니다. 하단 버튼의 투명도는 1이었으나, 이름표는 `visibility: hidden`, `opacity: 0`이었습니다. 기존 ‘목록 끝 자동 표시’ 처리는 버튼의 숨김만 해제했고, 이름표는 여전히 hover 또는 키보드 초점에만 표시됐습니다. 버튼 전체가 사라진 상태와 구분한 관찰입니다.

- 목록 끝 여부를 하단 구성 요소에 전달하고, 끝에 있는 동안 이름표도 대기 없이 표시합니다. 원형 버튼 모양과 실제 동작은 유지합니다.
- 위로 스크롤하면 기존 숨김·유휴 복귀를 유지합니다. 최소 접힘·지도 이동 중 숨김 조건과 등록 불가 조건은 우회하지 않습니다.
- 스크롤 자체로 등록·재제출 요청을 보내지 않습니다. 등록과 재제출의 기존 API·권한 조건은 변경하지 않았습니다.

## 검증 범위와 증거

mock 서버 시험 10/10 (화면 반응): 실제 Chrome에서 375px·1280px, 일반·동작 줄임, 등록 가능·재제출의 8개 조합을 확인했습니다. 각 조합에서 끝 도착 후 250ms 이내 이름 표시, 끝에서 추가 휠 입력 후 유지, 위로 이동 후 숨김, 가로 넘침 방지, 자동 등록·재제출 요청 0건을 확인했습니다. 나머지 2개는 등록 불가와 최소 접힘·다시 펼친 후 끝으로 이동한 경우입니다.

실서버 확인 (cs 프로젝트 서버 응답): 안 했음. 공개 탭의 현재 DOM 표시만 읽었으며, 실제 여행 등록·재제출 요청을 보내지 않았습니다. 지도는 단색 시험 타일을 사용하는 mock 서버 화면입니다. 실제 지도 타일·GPS·cs 프로젝트 서버의 등록 처리 검증으로 해석하지 않습니다.

최종 실행은 동일 UI 소스를 복사한 격리 폴더의 프로덕션 빌드입니다. 메모리 사용을 줄이기 위해 해당 시험 폴더에서만 작업 스레드 1개와 webpack 캐시 비활성화를 사용했습니다. 원본의 Next.js 실행 설정은 변경하지 않았습니다. 수정한 소스 3개와 시험 파일의 원본·사본 해시가 모두 일치합니다.

## 중간 실패와 실행 환경

최종 집계는 마지막 프로덕션 실행의 고유 시험 10개입니다. 이전 회차의 통과를 더하지 않았습니다.

- 초기 시험 응답에서 항목 상태를 `ok`로 썼던 부분을 실제 계약의 `keep`으로 바로잡고, 아직 확인 중인 항목이 없다는 검사도 추가했습니다. 초기 회차는 최종 통과 집계에서 제외했습니다.
- 최소 접힘 해제 후 기존 동작대로 목록 상단으로 돌아갈 수 있으므로, 다시 끝으로 이동한 뒤 이름표가 표시되는지 확인하도록 시험 기대값을 고쳤습니다. 목록 위치 복원 기능을 새로 변경하지 않았습니다.
- 개발 모드 회차는 디스크 부족(`ENOSPC`), 메모리 할당 실패, 시험 작업 프로세스 종료를 겪었습니다. 정적 검사도 한 차례 메모리 부족으로 종료됐으나 단독 재실행과 최종 빌드의 TypeScript 검사는 통과했습니다. [개발 모드 로그](../evidence/2026-10-12_submit-end-label/thread-browser.log), [중간 실행 로그](../evidence/2026-10-12_submit-end-label/final-verified.log), [정적 검사 재실행](../evidence/2026-10-12_submit-end-label/typecheck-retry-status.json)을 보존했습니다.
- 사용자 허가 범위에서 npm 다운로드 캐시와 Node 컴파일 캐시를 정리했습니다. 대화 로그는 삭제하지 않고 NTFS 압축으로 보존했습니다. 압축 후 C 드라이브 여유 약 608MB를 관찰했고, 최종 화면 시험 후에는 약 508MB였습니다. 다른 작업도 실행 중이므로 이 차이를 정확한 회수량으로 해석하지 않습니다. 모델·문서·원본 소스·대화는 삭제하지 않았습니다. 휴지통 전체 비우기는 자동 승인 검토가 거부하여 실행하지 않았습니다.
