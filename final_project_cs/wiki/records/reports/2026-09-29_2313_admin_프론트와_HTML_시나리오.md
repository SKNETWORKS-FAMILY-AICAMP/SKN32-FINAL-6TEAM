# 운영자 콘솔 프론트와 단일 HTML 시나리오

2026-09-29 · 수행 Codex(구현·독립 QA 분업) · `role-eval-ui` 기준 `38cd59d` + 로컬 변경 · TeamFlow `ST4F-176`.

운영자 콘솔의 프론트 화면 11개와 앱 소스로 생성한 단일 HTML 시나리오를 구현했다. 단위 23/23·브라우저 17/17·미설정 모드 1/1, 합계 **41/41(100%)**이 통과했다. 실제 API·운영자 인증·DB 저장·배포는 이번 작업 범위에 없으며 연결하지 않았다.

## 목표와 기준

사용자는 Claude가 정리한 기획에 따라 운영 앱 구현과 팀원들이 직접 체험할 단일 HTML 목업을 요청했고, 작업 중 현재 범위가 프론트임을 확인했다. [SCREEN_PLAN.md](../../../frontend/apps/admin/SCREEN_PLAN.md) §5의 화면 단계와 와이어프레임 v1.2를 따랐다. 기획서에 남은 미정 정책을 운영 정책으로 확정하지 않았다.

## 결과

- 로그인, 운영 홈, 사용자 목록/상세, 한도/감시, 사용량, 서버 상태, 문의함, 공지/점검, 운영 기록, 임시 승인/위임/발송 확인: **11/11개(100%)**.
- 검색·필터·정렬, 사유가 필요한 변경, 답변 템플릿 관리와 답변, 공지 게시/점검 미리보기, 운영 기록 조회를 연결했다.
- 데모 모드를 명시한 경우에만 데이터 경계가 생성된다. 미설정·빈 값·다른 값에는 「연결 미설정」을 표시한다.
- `AdminGateway`로 데이터를 받고 명령을 실행한다. Zod 검증 실패 시 상태와 기록을 모두 보존한다. 실제 HTTP 요청이나 브라우저 저장소 사용은 없다.
- 차단은 키 폐기와 분리한 데모 상태다. 발송 확인은 `unknown`을 유지하며 확인 결론·확인자·근거만 기록하고 재발송하지 않는다.
- 정상/로딩/빈 목록/실패 상태를 선택할 수 있고 초기화로 전체 데모 변경을 되돌린다.
- [admin-scenario.html](../../../frontend/apps/admin/mockups/admin-scenario.html)은 같은 React·CSS·데모 코드로 생성한 **779,746 bytes** 단일 파일이다. 외부 폰트·CDN·API 없이 `file://` 오프라인에서 실행한다. 안내된 6단계 시나리오와 자유 조작을 지원한다.
- 앱 3300, 브라우저 시험 3301, 미설정 별도 빌드 시험 3302를 사용한다. 앱은 루프백 주소에만 연다.

## 검증과 보완

| 검증 | 결과 |
|---|---|
| `npm run check` | 린트·타입·단위·빌드 4/4(100%), exit 0 |
| 단위 시험 | 23/23(100%), 사유 누락/실패 원자성/기록/발송 중복 처리/일·월 예산/재점검 |
| Chrome 앱 + HTML 브라우저 시험 | 17/17(100%), 8.8초, exit 0 |
| 모드 미설정 별도 빌드·Chrome | 1/1(100%), 2.5초, exit 0 |
| 오프라인 HTML | HTTP 요청 0건, 상태 변경→문의 답변→운영 기록→초기화 확인 |
| 시각 확인 | 홈·문의·사용량 PC 1440px, 홈 모바일 390px 캡처 직접 확인 |
| `git diff --check` | 통과 |

독립 QA가 발견한 모달 Escape 후 포커스 복원 누락을 고치고 원래 버튼 복귀를 재검증했다. 닫힌 모바일 메뉴는 포커스 대상에서도 제외한다. 일/월 예산 중 하나 도달 시 멈춤, 점검 시각 전진과 상한 변경 후 진단 갱신, 문의 필터와 선택 상세의 일관성도 보완했다. API별 집계 대상이 다른 무료 제공량은 전체 그래프 선으로 오해하게 그리지 않는다.

초기 npm 설치는 Vite의 esbuild 조건 충돌과 npm 의존성 해결 오류가 있었다. 기존 콘솔의 검증된 잠금 버전을 기준으로 esbuild 0.28.2를 추가해 설치했다. 처음 Playwright가 요구한 Chromium 버전은 로컬에 없어 설치된 Chrome을 명시했다. 샌드박스에서는 시험용 서버 종료가 멈춰 정상 프로세스 정리가 가능한 실행 권한으로 재검증했다. 최종 시험은 모두 exit 0이다.

첫 Chrome 브라우저 시험 실패에는 select/textarea를 찾는 테스트 탐색 문제와 실제 모달 포커스 문제가 함께 있었다. 전자는 접근성 역할로 탐색하도록 수정했고, 후자는 앱 코드를 수정했다. 모달 격리·Escape 복원 기대는 유지했다. 최종 코드의 실제 출력은 evidence에 보존했다.

## 남은 범위와 공유 상태

실제 운영 API·로그인·권한 검증·서버 중계·영속 저장·추가 계측은 [기획서 §7](../../../frontend/apps/admin/SCREEN_PLAN.md)의 다음 단계다. 데모 성공을 실서버 검증으로 간주하지 않는다. 팀원 검토·CI 추가·배포·커밋·푸시는 수행하지 않았다. 생성 HTML은 로컬 전달 준비 상태다.

개인 규칙 파일의 admin 검증 표는 다른 저장소이므로 이번 작업에서 수정하지 않고, 앱의 실행/검증 정본인 README·DEVELOPMENT에 명령을 정의했다.
