# ODsay 키를 넣으면 감시 소스 조립이 죽는다 — `odsay.py` 가 없다

## 해결됨 (2026-09-18) — 키가 있어도 조립이 죽지 않고, 「어댑터 미구현」을 이름으로 남긴다

- 수정: `app/infrastructure/travel/base.py` `build_travel_sources` 의 키가 있는 갈래가 없는 모듈을 부르지 않고
  `sources.unavailable["transit"] = "ODsay 어댑터 미구현 — …"` 로 남긴다(§6 의 2안). `transit`·`route` 는 키가 빈
  경로와 같이 `None`(「모름」)이다. 조용한 대체가 아니라 이유가 `/ui/admin` 에 보인다.
- 시험: `tests/unit/travel/test_transit_source_assembly.py` 2건 — 키가 있어도 안 죽고 이유를 남기는가 · 키가 비면
  키 문구를 남기는가. **수정 전 코드에서 빨간 것을 확인했다** — HEAD 의 `base.py` 사본으로 같은 호출을 하면
  `ModuleNotFoundError: No module named 'app.infrastructure.travel.odsay'`.
- 확인: `python -m pytest tests/unit -q` → `567 passed` · `python -m pytest tests/unit/core/test_debug_report_status.py -q`
  → `34 passed` (2026-09-18).
- 열린 채 둔 것: **ODsay 어댑터 구현 자체**(1안). 키가 없어 응답 모양을 실측할 수 없고, 대중교통 경로·운행은
  계속 「연동 전」이다.

### 발견 시점 기록 (그때는 미해결)

- 발견: 2026-09-18 15:20 · 수집 데이터 보고서 3차를 쓰며 감시 소스 조립(`build_travel_sources`)을 읽다가
- 상태: 발견 · 수정 전 기록(다른 세션이 같은 저장소를 작업 중이라 `base.py` 를 건드리지 않았다)

## 1. 무엇이 일어나나

`app/infrastructure/travel/base.py:547~555` 는 `ACOP_ODSAY_API_KEY` 가 채워져 있으면
`from .odsay import OdsayTransit` 를 부른다. **그 모듈이 저장소에 없다.** 키가 비어 있는 지금은
「대중교통 소스 없음」으로 정상 처리되지만, **키를 채우는 순간 조립 전체가 `ModuleNotFoundError` 로 죽는다.**

같은 모양의 사고가 한 번 있었다 — 2026-09-14 전에는 `weather_provider=kma` 를 고르면 `kma.py` 가 없어
기동이 안 됐다(`base.py:397` 주석).

## 2. 실측

- 파일: `app/infrastructure/travel/` 에 `odsay.py` 없음(작업 트리). `git log --all -- final_project_cs/app/infrastructure/travel/odsay.py` 출력 0줄 — **한 번도 커밋된 적이 없다.**
- 키: `.env.apikeys` 의 `ACOP_ODSAY_API_KEY=` 비어 있음 → 지금 운영 조립은 안 죽는다.

## 3. 재현

```powershell
python <세션 scratch>\repro_odsay.py
```

실제 설정(`get_settings()`)에 `odsay_api_key` 만 가짜 값으로 바꿔 `build_travel_sources` 를 부른다. 외부 호출 없음.

```
현재 키 비어 있음: True
키 없을 때: transit = None / unavailable 에 transit 있음: True
키 있을 때: ModuleNotFoundError No module named 'app.infrastructure.travel.odsay'
  File ".../app/infrastructure/travel/base.py", line 552, in build_travel_sources
    from .odsay import OdsayTransit
```

## 4. 위험도

- **지금: 없음**(키가 비어 있다).
- **키를 채우는 날: 높음.** 감시 루프(`run_sweepers --only trip` · `trip_cases`)와 여행 API 의 소스 조립이
  한꺼번에 실패한다. 대중교통은 이동 항목 판정의 1차 소스 후보라, 연동하려고 키부터 넣는 순서가 자연스럽다.
- 조용한 실패는 아니다(예외가 크게 난다). 다만 **원인이 「키를 넣었다」라서 키 문제로 오진하기 쉽다.**

## 5. 내가 잘못 보고했던 수치의 정정

없음. 수집 데이터 보고서 3차(`program/산출물양식/w3/데이터수집_여행/`)는 대중교통을 「연동 전」으로 적었다 — 맞다.

## 6. 고치는 길(제안)

1. `odsay.py`(`OdsayTransit`, `TravelSource` 규율 ①~④)를 구현하거나,
2. 구현 전까지는 키가 있어도 `unavailable["transit"] = "ODsay 어댑터 미구현"` 으로 **명시적으로** 비워 둔다
   (폴백이 아니라 「없음」을 이름으로 남기는 것 — `RULE.md` §3.2).

어느 쪽이든 **키를 채운 설정으로 조립을 부르는 시험**을 붙인다. 지금 시험은 키가 빈 경로만 지난다.
