# 테스트 코드가 일반 글로 접수됨
## 해결됨 (2026-10-11)

준비된 코드 인식·원문 확장·본인 범위 저장과 기존 검증 연결을 구현했고, 접수62/62·Chrome21/21 및 정적 검사·새 빌드로 확인했다. 아래 최종 확인과 결과 보고가 원본 검증 근거다.

## 발견 당시 기록
- 상태: 수정 전.
- 위치: app/domains/travel_ops/entry/trip_api.py의 web_intake_start와 components/intake/pipeline.py의 open_intake. 현재 text를 그대로 원본으로 넣고 코드 전환 경로가 없다.
- 재현: 계획 입력란에 test1을 적어 제출한다. 시험 코드 확장 없이 원문 test1이 읽기로 전달된다. 사용자 공개 화면은 일정 0개였다. 같은 공개 접수를 새로 생성해 재현하지 않았다.
- 실측: 관련 접수·등록 제품 코드 검색에서 코드 인식 구현을 찾지 못했다. wiki/external/test-scenarios.md에는 12개 코드 계약만 있고 미추적 초안 상태다.
- 위험: 시험용 단축 입력으로 빈 계획이 만들어져 사용자가 계획을 다시 써야 한다. 일반 여행의 검증 결과를 시험 성공으로 바꾸면 안 된다.
- 정정: 앞선 일정 0개 복귀 수정은 복귀 동작을 고쳤을 뿐, 시험 코드 미연결을 해결한 것이 아니다.

## 수정 범위
준비된 서울 계획 12개·정확한 코드 인식·기존 접수와 검증 연결·시험 표시·관리 설정·입력 안내를 구현한다. 고정 계획 원문을 제공하며 실제 조회값이나 실시간 경보를 만들어 넣지 않는다. rt 실제 경보 생성은 별도 미구현으로 명시적으로 거절한다.

## 최종 확인
코드 인식·원문 확장·본인 범위 저장·기존 검증 연결을 구현했다. 접수62/62, Chrome21/21, 타입·문법·새 빌드3/3 통과. 공개 cs 프로젝트 서버 응답·x600 서버 배포는 미확인이다. [결과 보고](../2026-10-11_0710_준비된_시험계획_연결.md).
