# 위임을 **다시 주면** 「누가 언제 거뒀나」가 사라진다

## 해결됨 (2026-09-22)

마이그레이션 [021](../../../../app/infrastructure/db/migrations/021_delegation_audit_trail.sql)
이 `delegation_events`(append-only)를 만들고, `delegation.grant()`·`revoke()` 가 상태를 바꿀
때마다 거기에 **덧붙인다**. 「지금 상태」는 `delegations` 가, 「어떻게 여기까지 왔나」는 이
표가 답한다.

무엇으로 확인했나 —
`tests/integration/api/test_delegation_api.py::test_regranting_does_not_erase_who_revoked_it`
(주기 → 거두기 → 다시 주기 뒤 이력이 `granted · revoked · granted` 로 남고 행위자가
`op-3 · op-2 · op-1` 로 남는다). **이력 적기를 일부러 끄면 이 시험이 빨개지는 것**까지 확인했다
(근거 문서 §3). 브라우저로도 봤다 — 다시 주기 확인 화면에 철회 기록 줄이 그대로 떴다.

  있었나」를 나중에 확인할 수 없게 된다. 019 가 스스로 지키겠다고 적어 둔 성질이다.

## 무엇이 문제였나

`delegations` 는 `(tenant_id, customer_id)` 한 행에 **지금 상태 한 벌**만 든다.
그런데 다시 주기가 이렇다.

```sql
INSERT INTO delegations (tenant_id, customer_id, granted_by, note) VALUES (…)
ON CONFLICT (tenant_id, customer_id) DO UPDATE
   SET granted_at=now(), revoked_at=NULL, revoked_by=NULL,
       granted_by=EXCLUDED.granted_by, note=EXCLUDED.note
```

`revoked_at`·`revoked_by`·`note` 가 **NULL 로 덮인다.** 즉 **주기 → 거두기 → 다시 주기** 를
하면 누가 언제 왜 거뒀는지가 흔적 없이 사라진다.

019 는 정확히 그 반대를 하겠다고 적어 두고 있었다.

> 철회는 지우는 것이 아니라 `revoked_at` 을 적는 것이다 — 언제 누가 철회했는지가 남아야
> 「그때는 위임 안에 있었다」를 나중에 확인할 수 있다(감사).

**한 번만 주고 거두는 동안은 지켜졌다.** 다시 주는 순간 깨진다. 019 를 쓸 때 다시 주기를
`ON CONFLICT DO UPDATE` 로 둔 것이 그 자리에서 보이지 않았던 것이다.

## 재현 (수정 전 기준)

```powershell
python - <<'EOF'
from app.infrastructure.db.session import get_connection
from app.modules.travel_ops import delegation
# tenant/customer 는 아무 것이나 (seed 의 demo/cust_01 등)
with get_connection() as conn, conn.transaction():
    delegation.grant(conn,  tenant_id=T, customer_id=C, by="op-1", note="처음 맡김")
    delegation.revoke(conn, tenant_id=T, customer_id=C, by="op-2", note="잠시 거둠")
    delegation.grant(conn,  tenant_id=T, customer_id=C, by="op-3", note="다시 맡김")
    with conn.cursor() as cur:
        cur.execute("SELECT revoked_at, revoked_by FROM delegations "
                    "WHERE tenant_id=%s AND customer_id=%s", (T, C))
        print(cur.fetchone())      # 수정 전: (None, None) — op-2 가 거둔 사실이 사라진다
EOF
```

## 실측

- 수정 전: `delegations` 조회 결과 `(None, None)` — **철회 기록 0건**이 남는다.
  다른 어디에도 안 남아 있었다(`case_events` 는 Case 에 붙는 표라 위임과 무관하다).
- 수정 후: `delegation_events` 에 **3행**(`granted`·`revoked`·`granted`), 행위자
  `op-1`·`op-2`·`op-3` 가 그대로 남는다. `delegations` 의 지금 상태는 여전히 덮인다 —
  **그게 그 표의 일이다.**

## 고친 방식과 그 이유

「상태」와 「행위」를 **다른 표에 둔다.** `case_events` 가 Case 에 대해 하는 것과 같다.

- `delegations` — 지금 상태(덮어쓴다). 판정기가 `FOR UPDATE` 로 잠가 읽는 자리다.
- `delegation_events` — 상태를 바꾼 **행위**(덧붙인다. 고치지도 지우지도 않는다).

★**`delegations` 를 이력 표로 바꾸지 않았다.** 판정기가 「지금 살아 있나」를 한 행에서
잠가 읽는 구조라, 이력 표로 바꾸면 판정 경로가 통째로 바뀐다 — 돈이 나가는 경로를
감사 기록 때문에 흔드는 것은 맞바꿈이 나쁘다.

★**순서 칸(`seq`)을 뒀다.** 시각만으로 줄을 세우면 같은 순간에 들어온 둘의 앞뒤가 정해지지
않아 「주기 → 거두기」가 뒤집혀 보일 수 있다. 이력이 거짓말을 하면 없느니만 못하다.
