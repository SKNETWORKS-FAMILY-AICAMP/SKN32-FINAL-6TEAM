# 일정 0개가 확정되어도 질문 화면에 남음

## 해결됨 (2026-10-11)

완료 `review`의 원문 일정0개를 질문 유지·진행 재생보다 먼저 처리하고 입력 화면으로 `replace` 이동한다. 현재 탭의 제출 글·파일을 복원하고 빈 응답 보관분을 비운다. 변경 전 Chrome375px에서 자동 복귀 실패1/1을 재현했다. 첫 수정의15건 중 복귀·복원·기존 접수13건은 통과했고, 같은 접수 번호를 재사용하는 mock 서버 재입력2건은 남은 빈 응답 보관분 때문에 실패했다. 보관분 제거 후 새 빌드에서15/15·단위19/19·정적 검사와 빌드3/3을 통과했다. [시험 근거](../2026-10-11_0643_빈일정_자동복귀.md)를 따른다. 공개 cs 프로젝트 서버 응답·x600 서버 배포 확인은 하지 않았다.

## 발견 당시 기록

- 위치: `frontend/apps/web/src/features/intake-review/intake-review.tsx:180`의 질문 유지 분기가 빈 결과 분기보다 앞선다. 읽기가 완료되어도 질문을 붙잡은 동안 「찾은 일정0개」와 확인 버튼이 남을 수 있다.
- 재현: Chrome mock 서버 시험에서 질문2개·읽는 중0개를 표시한 뒤, 완료 GET의 원문 일정도0개로 응답한다. 질문을 한 번 건드린 상태에서도 입력 화면으로 자동 복귀해야 한다.
- 실측: 코드 순서를 확인했다. 변경 전 브라우저 재현 결과는 별도 증거에 남긴다. 제보한 공개 접수의 완료 응답은 아직 확인하지 않았다.
- 위험도: 빈 계획을 확인하기 위해 불필요한 질문에 답하거나 버튼을 누르게 한다. 결제·예약 변경과는 관계없다.
- 범위: 읽기 완료 `review`에서 원문 일정0개만 자동 복귀한다. 읽는 중 임시0개, 등록된 여행, 읽힌 뒤 사용자가 전부 삭제한 일정, 치명 오류를 빈 결과로 취급하지 않는다. 입력 글·선택 파일은 가능한 현재 탭의 제출본으로 복원한다.
