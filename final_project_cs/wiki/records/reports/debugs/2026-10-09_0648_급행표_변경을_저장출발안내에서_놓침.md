# 급행표가 달라져도 저장된 출발 안내의 입력 판 대조가 통과함

## 해결됨 (2026-10-09, 부분) — 저장 문맥의 급행 내용 판 대조

위치: engine/departure_context.py:23, departure_observer.py:88. 저장하는 입력 판과 출발 관측의 현재 입력 판은 일반 시간표·규칙 두 값뿐입니다. 급행표만 변경된 경우 재계산 관문을 통과해 이전 구간의 안내를 계속 만들 수 있습니다.

재현: 신규 test_departure_express_basis_v1.py에서 내용 판만 바꾼 통제 런타임을 대조합니다. 실제 운행 변경이나 실제 탑승 관측이 아닙니다. 최초 두 조건의 수정 전 로그를 남깁니다.

해결 범위: 계산에 사용한 런타임 급행 입력 스냅샷의 내용 해시·노선·부재 상태를 정렬해 식별자를 만들고 저장 문맥과 현재 관측이 같은 함수를 씁니다. 파일 경로나 사용자 로컬 경로는 저장하지 않습니다. 일반 시간표와 규칙이 같아도 급행 내용 판이 다르거나 기존 문맥에 식별자가 없으면 needs_replan으로 안내를 보류합니다. 내용이 같은 파일 경로·수정 시각 교체는 불필요하게 보류하지 않습니다. 저수준 수동 런타임에서 급행 추적을 아예 전달하지 않은 경우의 기존 두 필드 호환은 유지합니다.

남은 범위: 도착 정보의 운행 정확도·실제 위치와 탑승·조회와 안내 저장 사이 새 입력 교체·이미 배달한 안내의 회수·운영 배포와 새 웹 대조는 별도입니다.
