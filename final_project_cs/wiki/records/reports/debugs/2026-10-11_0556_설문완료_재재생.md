# 완료 계획 확인 시 재재생과 대기 창 중복 동작

## 제보 · 확인 범위

- 질문이 남은 완료 화면에서 「읽어 온 계획 확인하기」를 누르면 장소·운영시간 → 정리 완료가 다시 재생된다는 제보.
- 대기 창의 「계속 답하기」와 「자동으로 넘어가지 않기」가 사실상 같은 역할이라는 지적.
- 로컬 코드 확인: 질문이 표시되는 동안 `useReveal`의 이전 상태는 멈추지만 읽는 화면은 최신 완료 결과를 사용한다. 질문 화면을 닫으면 멈춘 내부 상태에서 재생이 시작된다.
- 기존 단위 시험은 질문을 닫은 뒤 첫 재생을 재개하도록 기대하고 있다. 이 기대를 실제 완료 결과로 바로 이동하는 규칙으로 고친다.
- 대기 창의 계속 답하기는 30초 대기를 다시 시작하고, 별도 중지 버튼만 자동 넘김을 멈춘다. 계속 답하기를 자동 넘김 중지로 통합한다.

## 수정 전 상태

미해결. 완료 후 수동·자동 이동, 계속 답하기·Esc 이후 장시간 대기, 실제 브라우저의 진행 단계 변화를 검사한다. 공개 cs 프로젝트 서버 응답과 배포 상태는 이 기록의 확인 범위 밖이다.

## 해결됨 (2026-10-11)

완료 대기 해제 시 내부 상태를 전체 완료 결과로 동기화했다. 대기 창의 단일 계속 답하기와 Esc는 자동 넘김을 멈춘다. 변경 전 재현2/2, 수정 후 Chrome mock 서버 고유28/28·단위14/14·타입/문법/제품 빌드3/3을 확인했다. 첫 수정 실행의4개 실패는 질문 답변을 저장하도록 시험 데이터를 고쳐 해결했으며 제품 코드는 추가 변경하지 않았다. [수정과 근거](../2026-10-11_0556_설문완료_재재생방지_대기버튼통합.md).
