# Luna 자동 전환이 공개 앱에서 작동하지 않음

## 초기 관찰 — 수정 전

- 사용자 요구: 올라마 장애 시 개인 키가 아닌 cs 프로젝트 서버용 OpenAI 키로 `gpt-6-luna`를 호출한다.
- 실측: 공개 앱의 자동 전환 설정 꺼짐·서버용 키 미설정. 기존 채팅 실패 2/2건, 모델 상태 조회 연결 끊김 2/2건. 로컬에는 별도 서버용 키가 있으며 개인 키와 같지 않음을 값 노출 없이 확인했다.
- 위치: `app/infrastructure/llm_failover.py`의 `wrap_from_settings` 및 `OpenAIChat._complete`. 기존 모델 옵션은 `max_tokens`, GPT-6가 빠진 temperature 제외 목록이다.
- 수정 범위: GPT-6 호출 옵션 호환성, x600 서버 운영 설정의 자동 전환·모델·서버용 키. 기존 호출 상한과 마스킹을 유지한다.
- 위험: 모델이 끊기면 고객 채팅이 상담 실패로 끝난다. API 자동 전환에는 유료 호출이 생기며 기존 상한을 적용한다.
- 근거: [이전 진단](../2026-10-08_2154_채팅모델_연결진단.md), [공식 모델](https://developers.openai.com/api/docs/models/gpt-6-luna), [GPT-6 호출 옵션](https://developers.openai.com/api/docs/guides/latest-model).
- 재현: cs 프로젝트 서버 실행 환경에서 `get_settings()`의 전환 스위치와 키 존재 여부를 읽고, `from_settings` 객체 종류를 확인한다. 키 값·접속 주소는 출력하지 않는다.

## 해결됨 — 2026-10-08

운영 설정·키와 Luna 호환 호출 옵션을 반영했다. 실제 Ollama 연결 실패 → Luna 응답 3/3, API·상시 일꾼 서버용 키 2/2, 운영 컨테이너 실행 5/5를 확인했다. [작업 리포트](../2026-10-08_2245_Luna_자동전환_운영반영.md).
