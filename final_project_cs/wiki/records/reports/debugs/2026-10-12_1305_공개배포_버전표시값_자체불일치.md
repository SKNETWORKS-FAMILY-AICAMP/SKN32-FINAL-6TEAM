# 공개 배포 버전 표시값의 자체 불일치

## 미해결

공개 배포는 이전 이미지 `afeb62460b`를 유지하고 자동 반영은 `role-manager`를 따르지만 실행 중 구성의 일치 검사에서 중단됩니다. 2026-10-12 읽기 전용 점검에서 실행 타이머는 active, 배포 서비스는 failed·종료1이며 `DeployError: tripilot-api: Compose configuration drift; reconcile before deployment`를 확인했습니다.

위치: `deploy/migration_safe_deploy.py`의 `snapshot()`과 배포 후 버전 표시 동기화. 현재 `.env`의 배포 표시 `TRIPILOT_TAG`와 이미 실행된 API·worker가 받은 값이 다릅니다. 이미지 자체는 현재 배포 이미지와 일치합니다. 실제 Docker Compose 해시를 표준 입력만으로 다시 계산했으며, 표시값 하나를 현재 컨테이너 값으로 복원하면 API·worker·web 세 구성 해시가 모두 일치했습니다. 실제 파일·설정·컨테이너는 변경하지 않았습니다. 기능 설정 변경과 구별되는 표시값의 자기 변화가 안전 검사를 막는 원인입니다.

별도 관찰: 현재 운영 Docker Compose에서 기존 `config --hash` 뒤에 서비스 이름 셋을 넣은 호출은 API 해시 하나만 반환했습니다. 서비스별 호출은 세 값을 반환했습니다. 표시값 처리와 함께 실제 CLI의 해시 수집 방식도 회귀 검증이 필요합니다. 이 기록은 관찰한 버전의 동작이며 모든 Compose 버전에 일반화하지 않습니다.

위험: 새 Git 커밋이 공개 고객 화면에 반영되지 않습니다. 설정 불일치 검사를 끄거나 운영 설정을 덮는 방식으로 우회하지 않습니다. 배포 변경은 수행하지 않았으며 해결 전이므로 운영 반영 완료로 표시하지 않습니다. [해시 비교 실행 결과](../../evidence/2026-10-12_uiux-catalog-api/deployment-hash-proof.json).


## 코드 보완·검증 (운영 반영은 미확인)

실행 구성 복원은 `TRIPILOT_TAG` 하나에만 적용하며 후보 구성은 새 표시값을 유지합니다. 실제 기능 환경값 차이는 계속 차단합니다. 서비스별 해시를 각각 수집하고 누락·잘못된 응답을 차단합니다. 새 회귀21/21과 계약·보안·접수416/416이 통과했습니다. 안전 검사 비활성화·수동 무검증 배포·운영 파일 직접 수정은 하지 않았습니다. 공개 실행 버전이 새 커밋으로 바뀌었는지 확인하기 전까지 이 결함을 운영 해결로 닫지 않습니다.
