# 지도 이동 중 보이는 마커가 화면 밖 버튼에 들어가는 문제

## 제보와 조사 범위

로딩 중 가운데로 이동해 보이는 일정이 다른 화면 밖 일정과 묶이는 제보를 받았다. 물리적 지도 경계 안의 좌표를 칩에서 제외하는 계산은 이미 있다. 이 계산 자체뿐 아니라 이동 중 사용되는 지도 위치 정보와 실제 마커의 숨김 시점이 맞는지 조사한다.

- OSM은 이동 이벤트 다음 animation frame에 위치 정보를 전달하며, 공통 지도는 React 상태에 저장한 위치 정보로 거리 칩과 마커 숨김을 계산한다.
- Google·Naver는 idle에서만 위치 정보를 전달해 이동 중 이전 경계가 남는다.
- 제보한 공개 접수 화면을 읽기 전용으로 열었을 때는 이미 완료되어 마커4개가 보였고 화면 밖 버튼은 없었다. 과거 로딩 순간의 재현 증거로 삼지 않는다.

## 상태

미해결. 실제 Leaflet의 매 프레임 마커 좌표와 거리 칩 번호를 동시에 관찰해 이동·자동 맞춤 중의 잘못된 합침을 재현한 뒤 수정한다. 시험은 mock 서버 화면 반응과 공개 cs 프로젝트 서버 응답 확인을 구분한다.

## 해결됨 (2026-10-11)

Chrome 로딩 재현은 375px에서는 통과하고 1280px에서는 실패했다. 첫 맞춤의 `setView`·`fitBounds`가 기본 CSS 확대 전환을 시작해, 마커의 화면상 위치와 계산용 경계가 어긋났다. 이벤트 전달만 앞당긴 첫 수정에서도 같은 1280px 문제가 남았다. 첫 맞춤에 `animate: false`를 명시하고 이후 확대·축소에 프레임마다 경계를 갱신하는 이동을 사용하자 재현이 해소됐다. OSM의 추가 animation frame 대기를 제거하고 Google·Naver의 `bounds_changed` 및 공통 SDK 갱신 시점도 맞췄다.

최종 Chrome mock 서버 시험15/15, 단위28/28, 타입·문법2/2를 통과했다. 변경 전 스택 문구·접힌 지도 도구를 가정하던 기존 시험 네 건은 현재 승인된 규칙에 맞췄다. 실제 마커 좌표·거리 버튼 번호를 매 프레임 함께 검사한 여섯 경우 모두 잘못된 합침0건이었다. [최종 근거와 한계](../2026-10-11_0615_지도이동중_마커분리.md)를 따른다. 공개 cs 프로젝트 서버의 과거 로딩 순간은 재현하지 않았고, Google·Naver 실제 SDK 화면은 확인하지 않았다.
