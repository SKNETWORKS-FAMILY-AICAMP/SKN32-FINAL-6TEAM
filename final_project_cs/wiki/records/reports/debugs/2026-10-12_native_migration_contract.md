# 이미지 자체 SQL 안전 계약 누락

## 해결됨 (2026-10-12) — 구현·합성 DB 검증 완료, 공개 교체는 릴리스 보고서 확인

배포 전 실제 새 이미지에서 `safety_manifest` import가 실패했습니다. 교체·운영 DB SQL 실행 전에 중단됐으며 기존 API·worker·web은 보존됐습니다.

위치: `app/infrastructure/db/migrate.py`. 후보 병합에 과거 실행기가 남았고 배포 도구는 계약 2 함수를 요구했습니다. 또한 SQL 바깥 BEGIN/COMMIT를 제거하는 기존 컴파일러가 실행기에 연결되지 않았습니다. 단위 Docker 대역은 실제 이미지를 대신하므로 이 불일치를 발견하지 못했습니다.

수정 계획: 검토된 `compiled_sql`·`safety_manifest` 구현을 복구하고 DB 없는 빌드 검사에서 실제 함수·계약·전체 파일 해시를 검사합니다. 별도 합성 PostgreSQL의 강제 실패·savepoint·재실행 검증을 실행한 뒤 새 이미지 자체 검사와 공개 반영을 재개합니다. SQL 원문·운영 데이터는 지우지 않습니다.

이전 3974 성공 결과의 범위에는 `tests/integration/db`가 포함되지 않았습니다. 그 결과만으로 새 이미지의 배포 안전 계약과 SQL 전체 원자성 확인을 완료했다고 해석하면 안 됩니다.

검증: 최종 코드·시나리오 4015 성공·실패 0, 그중 `tests/integration/db` 40/40 성공·건너뜀 0. 강제 실패 시 DDL·기존 행 전체 롤백, 호출자 savepoint, 재실행을 확인했습니다. `pglast==7.20`은 운영 requirements에 있으며 새 이미지 빌드 --check가 성공했습니다. Claude 독립 안전 검토는 확정 P1/P2 미발견입니다. 실제 이미지 검사를 다시 수행한 뒤 공개 교체합니다.
