# 계획서 줄 안의 요청(「이 일정만 내일로 미뤄줘」)이 조용히 빠졌다

## 결론

사용자가 x600 서버의 웹에 넣은 계획서(2026-10-16 16:10 접수)에서 `15:00 국립중앙박물관 · 전시 관람 - 이 일정만 내일로 미뤄줘 알아서` 가 1일차 그대로 등록됐다.
그 순간 **계획을 이해하는 모델 읽기가 실패**해(로컬 모델 연결 안 됨 + 유료 대체 시간 초과) 규칙 읽기로 대신 읽었고, **규칙 읽기는 줄 안의 요청을 이해하지 못해 「국립중앙박물관」만 남기고 나머지 글을 아무 표시 없이 버렸다.**

## 근거(x600 서버의 cs 프로젝트 DB, 읽기 전용 조회 2026-10-18)

| 확인 | 값 |
|---|---|
| 접수 | `37350701-…`, 2026-10-16 16:10, 상태 확인 화면 대기 |
| 모델 읽기 기록(`reading.agent`) | `used: false` · `OllamaError: 모든 모델 경로가 실패했다: ollama=connect, openai=timeout` |
| 그 일정의 읽은 값 | 제목 「국립중앙박물관」(규칙) · 날짜 2026-10-23(규칙, 1일차) · 15:00 · 장소 관광공사 |
| 요청 글(「이 일정만 내일로 미뤄줘 알아서」)을 가리키는 값 · 경고 | 없음 |
| 같은 문구가 든 다른 접수 | 없음(`미뤄` 검색 1건) — 모델이 성공했을 때 날짜를 옮기는지는 **확인 안 했음** |
| 16:10 뒤 모델 읽기 | 대부분 성공. 실패는 2026-10-17 01:16 묶음(3건)뿐 |

## 왜 두 겹인가

1. **모델 경로가 그 시각에 막혔다** — 원인(x600 서버 Ollama 연결 실패 시각 · 유료 대체 9초 넘김)은 아직 안 봤다.
2. **대신 읽는 길이 요청을 조용히 버린다** — 규칙 읽기는 「시각 + 장소 · 설명」 모양만 읽는다. 줄 뒤의 글은 남은 줄로도 잡히지 않아(그 줄에서 무엇이든 읽혔으므로) 확인 화면에 「읽지 못한 부분」으로도 안 보인다. 결정 D-025 가 지적한 「한 줄에서 무엇이든 읽히면 그 줄이 모델에 안 간다」와 같은 구멍이 대체 경로에 남아 있다.

## 미해결 (2026-10-20 상태 표시)

이 리포트를 쓴 뒤 고친 기록 · 실서버 확인 기록은 찾지 못했다 — 아래 「남은 일」 세 가지가 그대로 열려 있다. 이 절은 2026-10-20 알려진 시험 실패 고침 세션이 결함 리포트 상태 규칙(`tests/unit/core/test_debug_report_status.py`)에 맞춰 붙였고, 원인 · 고침 여부를 다시 조사하지는 않았다.

## 남은 일

1. 같은 계획서를 다시 넣어 모델 읽기가 성공할 때 박물관이 2일차로 옮겨지는지 확인(x600 서버 실서버 확인 · 사용자 손으로).
2. 대체 경로에서 줄 안에 읽지 못한 요청 글이 남으면 확인 화면에 「이 부분은 읽지 못했어요」로 보이게 할지 — 고칠 곳은 계획 읽기 담당.
3. 모델 경로가 막힌 시각의 원인(Ollama 연결) 확인.
