# 검증 중 일정 추가의 장소 선택 누락
## 해결됨 (2026-10-09, 구현·요청 검증) — 통합 화면 확인은 루트 담당

- 위치: `frontend/apps/web/src/features/plan-check/add-stop.tsx` 장소 이름 입력과 `use-server-review.ts`의 `add`.
- 재현: 검증 완료 화면에서 일정을 추가한다. 장소 이름만 입력할 수 있고 검색 결과의 실제 장소·지점을 고를 수 없다. 저장 시 `{name: draft.place}`만 전송한다.
- 확인 범위: 기존 일정 수정의 검색 API와 `pickedPlace` 변환, 신규 추가의 6개 수정 필드 전송 코드를 대조했다. 고객의 공개 접수는 조작하지 않았다.
- 위험: 같은 이름의 다른 지점을 선택한 것으로 해석할 수 있다. 추가 화면에서도 정확한 검색 결과의 좌표·출처·장소 식별값을 보존해야 한다.
- 계획: 기존 실제 일정 기준 검색 API를 재사용하고, 선택한 장소 원값을 기존 `/edits`에 전달한다. 취소·검색 실패·저장 실패는 계획과 입력을 보존한다. 입력기는 선택 경계 아래에 바로 열 수 있도록 제공한다.
- 변경: 장소 검색 결과 선택·다시 검색·검색 실패 재시도·inline 입력기를 구현했다. 검색 원값의 좌표·출처·관광 장소 식별값을 기존 `pickedPlace` 변환으로 보존하고 신규 6개 항목 필드와 함께 저장한다. 검색 기준 일정이 없는 빈 계획은 기존 직접 이름 입력을 유지하고 제한을 명시한다.
- 검증: 신규 단위시험 8/8 및 기존 전체 되돌리기 6/6, 총 14/14 통과. 타입검사·변경 파일 ESLint·공백 검사 통과. 정확한 선택값 저장, 삭제 이력 번호 보존, 검색의 읽기 전용 동작, 오래된 판 재조회, 접수 전환 후 늦은 응답 거절, 추가 실패 원판 보존을 확인했다.
- 실제 화면: 루트의 최신 통합 빌드·브라우저 시험 담당 범위로 인계했다. 공개 cs 프로젝트 서버나 외부 검색 API 응답을 이번 하위 작업에서 호출하지 않았다.
