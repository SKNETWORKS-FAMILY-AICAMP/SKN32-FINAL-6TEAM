# 남은 시간이 짧을 때 「오늘부터」 계획이 하루 마감을 넘겨 거절된다

## 미해결 (2026-10-23 00:30 KST — 고침 배포됨 · 단위 시험 · DB 포함 시험 통과, 밤 22~24시 실서버 확인 전)

- 닫는 조건: 고침이 x600 서버(cs 프로젝트 서버)에 배포된 뒤, 밤 시간(첫날 남은 창이 짧은 때)에 「서울 2일」을 오늘 시작으로 요청해 `day_overflow` 거절 없이 일정이 나오고(첫날은 창에 들어가는 만큼만, 없으면 비움), 둘째 날이 평소 시각으로 시작하며, 만들어진 시험 여행을 표시 후 삭제해 보관함에 남는 것을 실서버에서 확인할 때.
- 고객 영향: 하루가 거의 끝난 시각에 「오늘부터」 일정을 요청하면 422 로 일정을 못 받는다.

로컬 재현: 같은 모양(후보 12곳 · 식당 10곳, 지금 = 23:43)으로 `plan_trip(start_at=…)` 을 불러 첫날 항목 4개가 10-23 01:15~05:20 으로 밀려 `day_overflow` 로 거절됨. (재현 시험의 후보는 시험용 가공 자료다 — 실서버 후보와 같지 않다.)

## 경위 (값이 된 단계)

- 시계는 정상이었다(이 PC · x600 Windows · WSL · api 컨테이너 · DB 모두 23:44 KST — SSH work 세션 확인).
- 오늘 시작이면 첫날 창이 (지금 5분 올림 ~ 하루 끝)이다. 23:43 이면 창이 23:45~23:59 로 14분인데, 하루를 맞추는 함수(`fit_day`)는 창에 하나도 안 들어가도 **하루 최소 곳 수**로 짜서 돌려준다. 그 항목들이 시작 시각부터 이어 붙어 다음 날 새벽으로 밀렸고, 마감 검사(`_refuse_overflow`)가 거절했다.
- 이 거절은 앞선 「하루가 짧아져 칸이 모자랄 때의 거절은 미확인」(2026-10-21 기록)으로 적어 둔 위험이 실서버에서 나타난 것이다.

## 원인

첫날 창이 짧을 때 최소 곳 수를 지키려고 창 밖으로 항목을 밀어 넣었다. 창에 들어가는 만큼만 두고 나머지를 덜어 내는 단계가 없었다 (`planner._plan_trip` 의 첫날 `fit_day` 뒤).

## 고친 곳

- [planner.py](../../../../../app/domains/travel_ops/components/planning/planner.py)
  - `_trim_to_window`(새 함수): 지금부터 짜는 첫날은 이동을 넣고도 창 안에 끝나게 가장 늦은 항목부터 덜어 낸다. 하나도 안 들어가면 그날은 비운다(둘째 날부터 평소 창).
  - `_plan_trip`: 덜어 낸 항목 수만큼 총량 점검(`plan_short`)을 완화하고, 덜어 냈으면 `planner.first_day = {from, until, dropped_items}` 로 보고한다(조용히 사라지지 않는다).
