# warmup API 계약 시험 목록 누락

## 해결됨 (2026-09-30)

`CONTRACT_V1_PATHS`에 이미 구현·명세가 있는 `/v1/web/warmup`을 추가했다. 수정 전 OpenAPI 검사에서 실패 1건을 재현했고, 수정 후 같은 검사 7개와 웹 클라이언트 계약 검사 4개, 합계 11/11(100%) 통과로 확인했다. [재현 조건과 실제 출력](../../evidence/2026-09-30_0044_warmup_API_계약시험_누락.md). 이 판정은 코드와 로컬 회귀 검증 기준이며 원격 CI 성공과 구분한다.

2026-09-30 · Codex · 기준 `role-eval-ui` / `develop` `2e890a7`. 사용자 요청으로 main CI 실패를 확인하고 계약 목록 누락을 정정한다.

- 상태: 발견 시 계약 목록 미수정. main CI의 기존 실패이며 admin 병합 전 `38cd59d`에서도 같은 오류가 발생했다.
- 위치: `tests/integration/api/test_openapi_surface.py:28`의 `CONTRACT_V1_PATHS`, 같은 파일 `:170`의 경로 차이 단언.
- 근거: 실제 `POST /v1/web/warmup`은 `app/modules/travel_ops/trip_api.py:1027`에 있고, [API 명세](../../../external/rest-endpoints.md#web-warmup)에도 이미 있다. 구현·명세를 추가하는 작업이 아니라 검사 목록을 일치시키는 작업이다.
- 위험도: main CI의 제품 전체 시험을 실패시킨다. 이 오류만으로 실제 API 호출 실패를 뜻하지 않으며, 목록에서 인증 검사를 제외해서는 안 된다.

## 재현

`final_project_cs`에서 mock LLM과 시험용 환경을 사용하고 실행한다. 이 검사는 OpenAPI와 라우트 의존성을 검사하며 실제 DB·API를 호출하지 않는다.

```powershell
python -m pytest tests/integration/api/test_openapi_surface.py -q
```

수정 전 로컬 실측: `1 failed, 6 passed in 0.96s`(6/7, 85.7%). 실패 메시지는 `['/v1/web/warmup']`이다. [메일의 CI 실행](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN32-FINAL-6TEAM/actions/runs/36591176331)에서도 같은 시험 1건이 실패했다.

## 수행한 변경

`tests/integration/api/test_openapi_surface.py:66`에 명세 근거 주석과 `/v1/web/warmup`을 추가했다. 기존 경로 존재·일치 및 인증 의존성 검사를 그대로 실행했다. `OPEN_WRITE_PATHS`와 API 구현·명세는 바꾸지 않았다. 사용자 웹의 기존 `.env.example` 로컬 변경도 이 수정에 포함하지 않는다.

## 함께 확인한 웹 live CI 범위

[CI (web)](../../../../../.github/workflows/ci-web.yml)은 `check`·demo E2E·`test:live`를 실행한다. `test:live`는 `NEXT_PUBLIC_DATA_MODE=live`로 별도 빌드한 웹을 `tests/live/stub-server.mjs`의 모의 API에 연결한다. 키·계획 접수/확인·채팅·warmup 호출과 오류 화면 등을 검증하지만 실제 Python 백엔드·DB·LLM·지도 인증 성공을 입증하지 않는다.

실제 서버 시험 `test:real`은 DB 시험 데이터 생성·외부 호출·팀 채팅 알림 등의 부작용 때문에 자동 CI에서 제외돼 있다. 웹의 호출 경로·메서드·설문 계약은 develop CI의 `tests/contract/test_web_client_contract.py`가 추가로 검사한다. 이번 작업에서는 웹 workflow나 실서버 시험을 변경·실행하지 않았다.
