# 지도 상태와 경로 표시 정리

확인 필요·변경 개수·위치 안내를 하나의 막대로 모으고, 시간 전체 되돌리기는 변경 메뉴에 배치했다. 이동 수단은 확대된 경로선 위에 표시하며 마커 선택의 중복 설명 알림은 제거했다. 로컬 코드와 Chrome 화면 시험 기준이고 이번 최종 수정은 공개 서비스에 배포하지 않았다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 요청 화면 수정 | 완료 | 3/3 = 100% |
| 단위시험 | 통과 | 51/51 = 100% |
| mock 서버 화면 시험 | 통과 | 27/27 = 100% |
| 마지막 경로 여백 재시험 | 통과 | 1/1 = 100% |
| 수정 파일 ESLint·타입 검사 | 통과 | 2/2 = 100% |

## 변경

- 지도 아래 하나의 흰 막대 안에 `! 개수`, `변경 개수`, 선택 장소 또는 위치 미정 안내를 붙인다. 공통 높이와 구분선을 사용하고 긴 장소 이름은 줄인다. 변경 표시와 시간 초기화를 시트 머리에서 분리한 이전 작업을 이어 배치를 통일했다.
- `변경`을 누르면 바뀐 일정만 모아 보고 변경 관리 메뉴가 열린다. `바꾼 시간 모두 되돌리기`의 터치 높이는 44px이며 시간만 복구한다. Enter·Space·Tab·Escape와 초기화 후 초점 복귀를 실제 브라우저에서 확인했다.
- 별도의 지하철 범례를 없애고 확대 수준 15 이상에서 보이는 경로선에 수단 이름을 표시한다. 화면 밖 양 끝을 잇는 선도 화면 안 부분을 계산하며, 마커·다른 이름·상단 도구·하단 가장자리를 피한다. 가운데가 마커와 겹치면 선의 다른 부분을 사용한다. 점선에는 `직선 연결`을 함께 적고 글자는 클릭을 가로채지 않는다. 이름 계산은 지도 제공자 공통 부분이다. 이번 실제 화면 시험은 Leaflet/OSM 경로에 한정한다.
- 마커를 누르면 해당 일정이 열리고 목록 위치가 맞춰진다. 장소 설명 알림을 중복으로 띄우지 않는다. 경로선을 눌렀을 때의 이동 정보 알림은 기존 동작을 유지한다.

## 전체 되돌리기 누락 수정과 원인 정정

키보드 시험을 추가하면서 SSE 기반 수정 직후 전체 시간 초기화가 3곳 중 1곳만 요청에 넣는 문제를 재현했다. 원래 시간을 항목별로 보관하는 수정만으로는 해결되지 않았다. 실제 `/edits` 요청을 기록하니 저장된 변경은 3곳인데 표시용 일정은 첫 한 곳만 갱신되어 있었다. 표시용 재생 상태로 초기화 대상을 계산한 것이 직접 원인이다.

원래 시간과 전체 초기화 대상은 최신 전체 일정에서 계산한다. 완료된 일정의 수정 결과는 즉시 반영하고 내부 재생 상태도 함께 동기화한다. 최초 검증의 순서·설문 대기·고객의 애니메이션 건너뛰기는 유지한다. 재검증은 기존 별도 확인 표시 재생 경로를 유지한다. 독립 원인 검토와 `use-reveal.ts` 및 단위시험 보완은 추가 에이전트가 담당하고 통합과 화면 검증은 주 담당이 수행했다.

최종 키보드 시험은 초기화 요청의 세 일정 시작·끝 총 6개 값, 변경 표시 제거, 옆 확인 버튼으로 초점 복귀까지 검사한다. 실패한 초기 가설과 요청 원문은 지우지 않고 [시간 초기화 결함 기록](debugs/2026-10-08_1735_시간초기화_일부일정만_되돌림.md)에 정정과 함께 남겼다.

## 검증 범위

mock 서버 시험 27/27 (화면 반응): 상태 막대 4, 기존 지도 상세 13, 일차 줄 숨김 4, 일정 위치 2, 제출·설문·재생 연결 3, 다시 제출 회귀 1. 이 숫자는 서로 다른 시험 27개의 합계다. 마지막 경로 이름 여백 수정 뒤 관련 경로 시험 1건을 추가로 다시 실행해 1/1 통과했다.

실서버 확인 (서버 응답): 안 했음. 실제 고객 접수의 수정·등록·초기화 요청을 보내지 않았으며 이번 작업에서 공개 배포하지 않았다.

실제 Next 빌드 성공, 수정 TypeScript 파일 ESLint와 웹 타입 검사 통과. 단위시험은 경로 이름·지도 좌표·경로 정보·재생 상태·계획 모델 5개 파일의 51개다. 재생 상태의 단위시험은 Node에서 상태와 타이머 경계를 확인하고, 실제 React 렌더는 Chrome 화면 시험으로 확인한다. 지도 확대·이동·축소, 이름 위치, 클릭 통과와 카드 연결을 실제 브라우저 입력으로 확인했다.

375×812와 1280×720의 실제 프론트를 촬영했다. 지도 타일과 여행 자료는 mock 서버용이다. 공개 지도 타일의 색·실제 모바일 기기·Google/Naver 실제 SDK를 이번 시험으로 확인했다고 주장하지 않는다. 빌드가 자동 추가한 시험 전용 타입 경로 두 줄은 검사 전 제거했다. 다른 작업의 수정은 되돌리지 않았다.
