# 뚝섬 대체 장소 실패 조사와 내부 후보 기록

## 확인한 결론과 범위

2026-10-17 10:51 한국 시각의 뚝섬 검증 여행 알림은 `no_alternate`였다. 당시 회차 기록에는 실제 교통 소스 ITS·UTIC 모두 조회 실패가 남아 있다. 시험 입력은 원래 장소의 재난문자 통제를 지정했으며, 대체 장소까지 안전하다고 만드는 설정은 아니다.

실패 전에 배포된 보존 이미지의 코드를 추출해 읽었다. 이 판은 대체 후보의 재검증이 `fatal`이어도 `unresolved`로 반환했다. 조건을 넓힌 재검색도 확인 실패와 후보 부재를 구별하지 않았다. 따라서 확인할 수 없는 상황을 고객에게 “대신 갈 곳을 찾지 못했다”로 안내할 수 있는 결함이다. 최신 주 검색에는 이미 `source_failed` 구분이 있었으며 이번에는 검사 한도·확인 불가 판정과 재검색까지 보완했다.

당시 후보별 목록과 재검증 결과는 보관되지 않았다. 과거 목록 전체를 정확하게 복원했다고 주장하지 않는다. 보존된 당시 일정·원래 장소의 시험 입력, 같은 시각의 실제 교통 조회 실패 응답, 현재 조회한 후보 목록으로 분류 오류를 재현했다. 당시 코드에서는 `unresolved`, 최신 코드에서는 `source_failed`였다. 현재 후보 중 4곳은 교통 확인 실패를 넣었을 때 재검증에서 탈락하고 1곳은 영업시간 미확인으로 탈락했다. 이것은 재현 결과이며 당시 5곳이 모두 존재했다는 증거가 아니다. 외부 자료가 모두 정상이라는 반대 조건에서는 변경안을 만들었다. 계절 장소의 현재 주간 영업시간을 실제 영업 보증으로 해석하지 않는다.

조사 시점의 실제 교통 API 한 차례 조회는 UTIC가 응답했고 ITS는 `budget_exhausted`였다. 당시 UTIC의 더 세부적인 실패 원인은 저장된 회차 기록으로 확정할 수 없다. 조회 예산이나 안전 검증을 우회하지 않았다. 고객 일정·알림·시뮬레이션 상태를 변경하는 재현은 수행하지 않았다.

## 수정

- 주 검색: 확인 불가·도구 예산·검사 한도 보류를 후보 부재와 구별한다. 한도 뒤 후보도 사유를 남긴다. 확인된 대안이 있으면 그대로 선택한다.
- 재검색: 소스 확인 실패·실행 오류를 간단한 확인 지연 안내 경로로 전달한다. 확인하지 못한 후보를 추천하거나 후보 부재로 단정하지 않는다.
- 내부 관찰: 계산 계층의 포트가 후보별 선택·탈락·중복·보류·영업 조건·API 확인 상태·실패 종류·조회 공급자를 전달하고 감시 계층이 기존 이력 표에 한 후보씩 저장한다. Team은 DB를 직접 쓰지 않는다.
- 고객 경계: 새 진단 데이터를 고객 결과에 추가하지 않는다. 기존 일정 전체 재판정의 `fit.skipped` 상세 사유와 탈락 장소 설명도 고객 전달물에서 제거한다. 적용한 일정 자체의 밀도 경고는 유지한다.

조회는 기존 운영자 감시 상세 API의 `ops:introspect`와 테넌트 조건을 유지한다. 고객 API·앱·알림·디스코드에 후보별 진단을 추가하지 않는다. 접속 주소·비밀값은 가리고 공급자 원문 응답은 저장하지 않는다. 125개 후보 저장과 100/25개 운영자 페이지를 확인했다.

## 검증

정적 검사: 변경 코드와 신규 시험의 ruff F·E9 통과.

격리 시험 DB에서 새 회귀·보안 시험 21개와 관련 기존 활동 대체·순위·전체 일정 재판정·밀도·도구 예산·식당 대체 시험 170개, 합계 **191/191 = 100%** 통과. 공급자 호출은 시험에서 대역으로 넣었고 시험 컨테이너는 외부 통신이 없는 별도 DB 환경이었다. 기존 시험 중 고객에게 탈락 설명을 기대하던 3개 파일의 단언은 이번 사용자 금지에 맞춰 변경했다. 새 시험은 실패 기록의 비공개 전달·권한 거부·타 테넌트 404·페이지 누락 없음·비밀값 가림을 검증한다. Starlette 시험 클라이언트의 사용 중단 예정 경고 1개가 있었다.

mock 서버 화면 시험: 이번 변경은 화면 변경이 없어 실행하지 않았다.

실서버 확인(응답): 실제 운영 DB의 당시 회차·일정 버전·알림을 읽기 전용으로 확인했고, 기존 예산·캐시 규칙에 따라 현재 교통 API 응답을 한 차례 확인했다. 이번 수정 코드의 운영 배포·운영 DB에 새 후보 기록 저장은 이 보고서 작성 시점에는 미확인이다.

전체 계약·보안·릴리스 관문은 매니저 통합 판에서 추가 확인해야 한다. 이번 191개를 제품 전체 검증으로 일반화하지 않는다.

## 검토와 보존

구현·검증 담당은 현재 결함 수정 채팅이다. 매니저 검토는 `git commit push` 채팅에 요청하며 독립 검토 완료로 표시하지 않는다. API 요청·응답 계약과 DB 스키마는 바꾸지 않는다. 내부 기록 규칙은 [운영 계약](../../operations/candidate-diagnostics.md)에 먼저 작성했다.

원본 작업 폴더는 수정·동기화하지 않았다. 수정 전 코드·시험은 격리 작업 폴더의 `_backup/2026-10-17_candidate_diagnostics/`에 보존했다. 실제 여행 입력·과거 응답·보존 이미지 소스·시험 실행 보조 스크립트는 비공개 작업 자료이며 커밋 대상에서 제외한다. 사용한 격리 시험 컨테이너·DB는 정지 후 보존했다.
