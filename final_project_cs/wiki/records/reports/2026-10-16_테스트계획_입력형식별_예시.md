# 테스트 계획 목록 — 입력 형식별 예시 34개 추가 (2026-10-16)

계획 입력 화면의 「테스트 계획」 목록에 **계획 이해 시험지의 입력 형식 11가지**로 나눈 예시 34개(test17~test50)를 더했다.
형식마다 짧은 것(한두 줄)부터 긴 것(하루 꽉 찬 일정 · 2박 3일 · 4박 5일 · 7일)까지 있다. 기존 test1~test16 은 글자까지 그대로다.

그래서 달라지는 것: 계획 읽기 재설계 **전후를 화면에서 같은 예시로** 견줄 수 있다. 예시마다 「10/16 지금 구조: …」 문장으로
지금 무엇을 읽고 무엇을 못 읽는지를 적어 두었다 — 재설계 뒤 같은 번호를 넣어 보면 차이가 바로 보인다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 지금 구조 파악(서버 목록 → 웹 목록) | 끝 | 1/1 = 100% |
| 예시 34개 쓰기(11형식 × 짧음·보통·김) | 끝 | 34/34 = 100% |
| 지금 구조로 읽혀 보기(x600 과 같은 모델 재현) | 끝 | 34/34 = 100% |
| 서버 쪽 시험(로컬 시험 DB) | 통과 | 110/110 = 100% |
| 웹 mock 서버 시험(화면 반응, Chrome) | 통과 | 14/14 = 100% |
| 실서버(x600) 확인 | 안 함 | 0/1 = 0% |
| 커밋 · 푸시 | commit 세션에 넘김 | 0/1 = 0% |

## 무엇을 넣었나

분류 이름은 시험지 채점표의 형식 이름(`eval/intake_diverse/report.py` 의 `SHAPE_KO`)을 그대로 썼다. 목록은 두 묶음으로 보인다 —
「검사 항목별 · 시각+장소 목록」(test1~16, 기존) 과 「입력 형식별 · 계획 이해 시험지 분류」(test17~50, 새로).

| 형식(시험지 이름) | 번호 | 짧음 | 보통 | 김 | 지금 구조에서(요지) |
|---|---|---|---|---|---|
| 정형 목록+자유 문장 | test17~20 | 4줄 | 10줄 하루 | 2박 3일 · 7일(36줄) | 장소는 거의 읽음. 「택시로 이동」 같은 문장이 일정이 됨, 이동·조건·성향 못 읽음 |

- **실제 접수 모양** 4개는 x600 서버에 들어온 접수 20건의 **모양만** 본떴다(시각 없는 한 줄, 저녁 두 줄, 화면 예시를 고친 목록,
  장소 없이 조건만 있는 요청). 고객 원문은 옮기지 않았다.
- **시험지 문장도 옮기지 않았다.** 시험지(69건)를 화면 예시로 쓰면 재설계 때 그 문장에 맞춰 고치게 되어 시험이 오염된다. 장소는 서울의 실제 장소다.
- **메모식 엑셀**은 시험지에서는 `.xlsx` 파일이지만, 목록은 파일을 붙일 수 없어 「엑셀에서 복사해 붙인 글」로 넣었다(파일 모양은 시험지 `inputs/X0n.xlsx`).
  **나눠 보낸 메시지**는 입력칸이 글 하나라 메시지 사이를 줄바꿈으로 이었다(시험지 실행기와 같다).
- 날짜는 `@d1`(2026-10-23) · `@md1`(10/23) · `@k1`(10월 23일) · `@w1`(금) 같은 표시를 두고 **접수한 날의 7일 뒤**를 첫날로 채운다(기존 test1~16 과 같은 규칙).
  「내일」「담주 토욜」「모레」 같은 상대 날짜는 그대로 둔다. 인원은 모두 4명 이하, 기간은 최대 7일이다.
- 이름은 「분량 · 요지」로 두었다(예: 「김 · 4박 5일, 조건이 많은 문단」). 「못 읽음」은 이름이 아니라 고른 뒤 보이는 안내 문장에 날짜를 붙여 적었다 —
  재설계 뒤에도 같은 이름으로 견주기 위해서다.

## 지금 구조에서 어떻게 읽히나 — 확인한 방법

| 확인 | 무엇으로 | 결과 |
|---|---|---|
| 읽기(모델 포함) | `pipeline.read_source` 를 GPU 서버 B 의 x600 재현 Ollama(0.31.1 · `tripilot-pointer:e4b-ft` · 문맥 8,192)로 | 34/34 오류 없음, 모델 부름 20건 |
| 읽기(규칙만) | 같은 함수를 모델 없이 | 34/34 오류 없음 |
| 접수 → 읽기 → 확인 화면 | e2e 시험(로컬 시험 DB · 실제 접수 API · 관광공사·카카오는 mock 서버 역할의 시험 제공자 · 모델 없음) | 34/34 `review` 상태 |

- 원 결과: [reads_with_model.jsonl](../evidence/2026-10-16_test-plan-forms/reads_with_model.jsonl) · [reads_rules_only.jsonl](../evidence/2026-10-16_test-plan-forms/reads_rules_only.jsonl) ·
  실행 스크립트 [read_forms.py](../evidence/2026-10-16_test-plan-forms/read_forms.py). 「오늘」은 2026-10-16 10:00(KST)로 고정했다.
- 장소 찾기(관광공사 · 카카오)는 넣지 않았다 — 위 표는 **읽기**만 본다. 실제 화면에서 장소 이름 · 운영시간 검사는 실제 조회에 따라 달라진다.
- 걸린 시간: 모델이 불린 건 2.2~11.0초(첫 건이 모델을 올리느라 11초). ★다른 세션이 같은 GPU 를 쓰던 중(사용률 69%)이라 시간은 참고만 한다.
- 이번 확인에서 새로 보인 것(시험지 기준선 보고서에 없던 것): **「1시 · 2시 · 3시」처럼 오후를 안 적은 시각을 새벽으로 읽는다**
  (test21 · 22 · 23 · 34 · 39 · 40). 시험지는 정답에 오전/오후를 사람이 정해 두었지만 이 점을 따로 짚지 않았다 — 재설계에서 볼 것.

**서버 쪽 시험(로컬 시험 DB)**: 110/110 통과

- 시험 DB 는 로컬 개발 DB 서버에 따로 만든 `acop_presets_test`(스키마 · 프롬프트 · 데모 데이터는 CI 순서대로). 파이썬 「전체」(ci-main 순서 전부)는 돌리지 않았다.
- 웹: 타입 검사 통과 · vitest 783/783 · 바뀐 파일 ESLint 통과.

**실서버 확인(서버 응답)**: 안 했음. x600 서버에는 새 목록이 아직 배포되지 않았고, x600 서버에 시험 접수를 만들지 않았다.
대신 위의 「x600 과 같은 모델 재현(GPU 서버 B)」으로 읽기만 확인했다 — 이것은 x600 서버 확인이 아니다.
배포 뒤 할 일: x600 서버 공개 화면에서 목록이 50개 · 18분류로 보이는지, test26(긴 문단) · test20(7일)을 넣어 확인 화면까지 가는지.

## 남은 한계

- 「지금 구조」 문장은 **10/16 재현 모델 결과**다. 모델 답은 실행마다 조금 다를 수 있고(같은 시험지 두 번 실행은 69/69 같았다), 재설계 뒤에는 낡는다 — 그때 문장을 새 결과로 바꾼다.
- x600 서버의 관광공사 · 우리 장소 목록 · 지명 사전 · 식당 원장은 읽기 확인에 넣지 않았다(읽기 칸과는 상관없고, 찾은 장소 이름만 달라진다).
- 형식마다 「보통」 또는 「김」 중 하나가 없는 곳이 있다(말투·오타 · 메모식 엑셀 · 실제 접수). 한 줄 형식은 길게 쓰면 다른 형식이 되기 때문이다.
