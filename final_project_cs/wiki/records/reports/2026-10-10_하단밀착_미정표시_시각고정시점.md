# 하단 안내 밀착·미정 표시·시각 고정 시작점

수정안 안내 아래 빈 공백을 없앴고, 이동 시각이 정해지지 않으면 미정으로 표시한다. 따라오는 일정 시각은 글자가 위로 가려지는 때부터만 고정한다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 요청한 수정 | 완료 | 3/3 = 100% |
| mock 서버 화면 시험 | 통과 | 20/20 = 100% |
| 관련 단위 시험 | 통과 | 26/26 = 100% |
| 정적 검사·표준 생산 빌드 | 통과 | 3/3 = 100% |
| 화면 촬영 | 완료 | 10/10 = 100% |

완료 목록 아래의 최소88px 여백과 선택 일정 정렬 여유를 제거했다. 수정안 안내의 아래 마진은0이며, 보내기 버튼용 공간은 안내 오른쪽 안쪽에 확보했다. 실제 클릭으로 수정안 전환을 확인했고 마지막 일정 펼침·출처·추가 단추·일차 이동·목록 접기는 유지한다.

이동 출발·도착이 모두 없으면 미정 하나만 표시한다. 일부만 없으면 알려진 실제 시각과 미정을 각각 표시한다. 읽어주는 버튼 이름에는 출발·도착을 구분하고, 기존 편집창·시각 드래그와 저장 보호를 유지한다. 시간이나 좌표를 생성하지 않는다.

시각 고정은 기존 펼침·검토 필요·해당 일정 되돌리기 가능 조건을 유지한다. 기존에는 목록 위64px 패딩과 고정 위치64px를 중복으로 더하고 버튼 위17.5px도 포함하여 시각이 날짜 줄보다92.5px 아래에서 멈췄다. 날짜 줄의 실제 아래 경계에서 스크롤 패딩과 기존 시각의 위 여유를 빼서 고정 위치를 계산한다. 목록·날짜 줄 높이가 바뀌면 다시 계산한다. 375px 화면에서 날짜 아래424px일 때 수정 전 시각은516.5px에서 멈췄고, 수정 후에는427px까지 원래 위치와 함께 움직였다. 제목과 정렬 유지, 경계에서 고정, 위로 복귀, 해당 일정 끝에서 함께 사라짐을 두 화면 크기에서 확인했다.

mock 서버 시험 20/20 (화면 반응). 새 요구6개와 기존 조건별 시각·직접 수정·추가 폼8개, 지도 조작1개·펼친 시각1개·시간 드래그1개·추가 취소 후 마지막 카드2개·도착 누락1개를 같은 최종 생산 빌드에서 확인했다. 첫 새 시험은 화면4개 통과, 미정 시험2개가 편집창 이름의 조사 누락 때문에 실패했다. 실제 화면 이름에 맞춘 뒤 전체20개를 다시 통과했다. 실패와 재시험을 근거에 보존했다.

실서버 확인 (서버 응답): 안 했음 — 이번 수정본으로 공개 cs 프로젝트 서버의 저장·스크롤 동작을 확인하지 않았다. 이 작업에서 x600 서버 배포를 실행하지 않았다.
