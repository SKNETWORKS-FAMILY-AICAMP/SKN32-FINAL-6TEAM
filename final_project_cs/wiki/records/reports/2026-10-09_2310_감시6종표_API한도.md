# 감시 6개 항목 표에 API별 한도 표시

관리자 **감시 현황·로그** 화면에 사용자가 제시한 6개 항목 표를 넣고 API별 ENV 한도 열을 붙였다. 예보·도로·대기질은 두 API의 한도를 각각 표시하며 합산하지 않는다. 기존 사용량 화면의 전체 API 목록도 유지한다. x600 서버에는 아직 배포하지 않았다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 감시 항목 연결 | 완료 | 6/6 = 100% |
| 관련 API 한도 표시 | 완료 | 9/9 = 100% |
| 화면 검증 | 통과 | 6/6 = 100% |

## 화면의 동작

`확인하는 것 / 사용하는 정보 / 무엇을 판단하나 / API별 ENV 한도` 네 열을 표시한다. 예보는 강수확률·풍속의 주의사항으로 설명한다. 각 API에는 하루·월 한도를 표시하며 ‘ENV 이름·출처 보기’를 열면 변수 이름과 명시 설정/기본값 여부를 볼 수 있다. 조회 실패나 API 목록 누락은 한도 미확인으로 표시하고 0으로 만들지 않는다.

현재 설정은 기존 `GET /admin/api/api-limits` 응답을 읽는다. 새 외부 제공처 호출이나 DB 쓰기를 추가하지 않았다. ENV 파일 변경은 운영 앱 재시작 후 보인다. 이 표의 API 목록은 감시에 쓰는 1차·대체 소스이며 해당 회차에 실제로 사용된 출처는 기존 회차 로그에서 확인한다. 좁은 화면에서는 항목별로 설명과 한도를 세로로 묶어 같은 화면 폭에 표시한다.

mock 서버 시험 **6/6 (화면 반응)**: 새 감시 한도 2개, 기존 감시 2개, 기존 API 사용량 2개. Edge 1280px·375px에서 확인했다. Next.js 빌드·TypeScript·ESLint도 종료 코드 0이다. 백엔드 조회 구현은 바꾸지 않았으며 이번 턴에는 백엔드 시험을 다시 실행하지 않았다.

실서버 확인 (서버 응답): **안 했음** — x600 서버 배포·응답을 확인하지 않았다. 화면의 숫자는 시험용 목업 응답이며 운영 한도를 증명하지 않는다.
