# 검증 지도 먼 마커의 실제 방향 유지

서쪽 일정은 왼쪽, 동쪽 일정은 오른쪽에 각각 남도록 수정했다. 같은 방향의 두 일정을 충돌 회피 때문에 반대편으로 보내던 문제를 재현했고, 작은 지도에서 번호 단추가 중앙 마커를 밀어내지 않도록 가장자리부터 배치했다. 전체 접힌 목록과 순차 지도 이동은 유지한다. 공개 배포 전이다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 지도 단위 검사 | 통과 | 108/108 = 100% |
| mock 서버 시험 (화면 반응) | Chrome 통과 | 10/10 = 100% |
| 목업 이미지·영상 재생 | Chrome 통과 | 2/2 화면 폭 = 100% |

실서버 확인 (cs 프로젝트 서버 응답): 안 했음. 이 기록은 좌표를 배치한 mock 서버 응답으로 실제 제품 화면을 검사한 결과다. 실기기 GPS·공개 서비스 반영을 확인한 결과가 아니다.

## 원인과 변경

이전 배치 계산은 충돌이 나면 좌우 양쪽의 빈자리를 탐색했고, 좁은 공간에서는 일정 순서대로 화면 전폭에 번호를 펼쳤다. 따라서 실제 서쪽 일정이 오른쪽으로 이동할 수 있었다. 새 계산은 검증 중 좌표 방향의 반쪽만 사용한다. 같은 방향의 번호는 그 가장자리부터 44px 번호 폭과 6px 간격으로 채우며, 공간이 더 부족하면 같은 쪽의 가용 폭 안에서 나눈다. 정북·정남 방향은 기존 가용 공간을 사용한다. 일반 완료 화면의 거리 묶음 정책은 바꾸지 않았다.

새 회귀 검사를 먼저 실행했을 때 기존 계산은 180px 높이의 서쪽 두 일정 검사에서 실패했다([수정 전 실행](../evidence/2026-10-12_map-direction-v4-final/before-unit.log)). 최종 지도 단위 검사 108개에는 기존 밀집 일정·도구 충돌·실제 화면 경계 검사와 새 방향 검사 6개가 포함된다([단위 결과](../evidence/2026-10-12_map-direction-v4-final/unit-results.json)).

## 화면 확인 범위

375px·1280px에서 서쪽 두 일정, 서쪽 1번·동쪽 2번 장면을 각각 검사했다. 실제 SSE 응답과 최종 조회의 좌표를 함께 바꿨으며, 제품의 순차 공개·카메라 이동·마커 요소 재사용을 그대로 실행했다. 매 프레임 이전 번호의 소실·합침·화면 안 마커 숨김을 관찰하고, 카메라가 도착한 프레임의 좌우 방향을 검사했다. 실제 번호 본체가 중앙에서 밀려나지 않는 조건도 별도로 검사했다. 물방울 마커는 좌표가 몸통의 모서리에 닿는 기존 모양이므로 본체 중심과 좌표 중심은 약17px 차이가 난다.

전체 접힌 목록 2개, 순차 지도·동작 줄이기 4개, 실제 방향·현재 마커 본체 4개를 합쳐 최종 10/10이 통과했다. 각 장면의 관찰 결과와 본체 위치는 [프레임 증거](../evidence/2026-10-12_map-direction-v4-final/frame-proofs.json), 전체 결과는 [Chrome 실행 결과](../evidence/2026-10-12_map-direction-v4-final/browser-final-results.json)에 있다. 중간에 추가 검사가 마커의 바깥 상자에서 내부 본체의 속성을 읽으려 해 실패했고, 내부 본체를 읽도록 검사 선택자를 고친 뒤 최종 10개를 다시 실행했다.

새 목업의 6개 이미지가 로드되고 동영상 2개가 재생되며 가로 넘침이 없는지 두 화면 폭에서 확인했다([목업 확인](../evidence/2026-10-12_map-direction-v4-final/mockup-check.json)). 촬영 화면을 직접 살펴 좌우 방향, 같은 쪽 번호 분리, 중앙 마커와의 겹침을 확인했다.

## 구현·빌드 범위와 산출물

이번 변경은 지도 배치 계산·단위 검사·Chrome 검사 세 파일이다. 다른 작업과 섞이지 않도록 앞선 UI 검사 고정 사본에 이 세 파일을 복사해 실행했고, 최종 원본과 검사 사본의 해시 일치 3/3을 확인했다([원본 일치](../evidence/2026-10-12_map-direction-v4-final/source-match.json)). 이를 현재 작업 폴더 전체의 검사 완료로 확대하지 않는다. 최종 타입·린트 종료 코드가 모두0이고([정적 검사](../evidence/2026-10-12_map-direction-v4-final/static-final-status.json)), webpack 생산 빌드가 통과했다([빌드 결과](../evidence/2026-10-12_map-direction-v4-final/build-live-status.json)). 첫 빌드 명령에서 webpack 설정에 기본 Turbopack을 사용해 실패한 기록도 보존했으며, 명시적으로 webpack을 사용한 최종 빌드로 화면 검사를 실행했다.

- [새 목업 v4](../../../frontend/apps/web/mockups/map-reveal-continuity-2026-10-12-v4/index.html): 실제 제품 화면의 이미지·전체 이동 녹화와 같은 서쪽 방향 비교.
- [촬영 자료 해시](../../../frontend/apps/web/mockups/map-reveal-continuity-2026-10-12-v4/capture-manifest.json): PNG 6개·WebM 2개.

- [첫 촬영 백업](../../../frontend/apps/web/mockups/map-reveal-continuity-2026-10-12-v4/_backup/2026-10-12_first-capture/): 중앙 공간 보완 전 v4 촬영 자료. 이전 v1·v2·v3도 보존했다.
