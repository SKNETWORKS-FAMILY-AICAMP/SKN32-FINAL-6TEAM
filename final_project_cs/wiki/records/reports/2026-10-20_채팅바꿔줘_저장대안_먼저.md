# 채팅 「다른 데로 바꿔 줘」 — 저장 대안 먼저 (2026-10-20)

「수정 화면 대안을 자동 수정 방식으로 빠르게」 세션. 지시: 상위 「수정 페이지 대안 속도 문제」 세션이 사용자 지시 「멈춘 하위세션들 이어서 작업 ㄱ 시켜」를 전달하며 맡김 — 사양 마지막 단계 「등록 → 채팅 바꿔 줘 → 저장 대안으로」가 되게, 항로 지킴이 끔(먼저 물어봐)이면 묻되 묻는 안을 저장 대안에서 먼저.

## 결론

해석이 「바꿔 줘」를 **「후보 알아봐 줘」**(`propose_alternatives` — 바꾸지 않고 고르게 하기)로 읽으면, 그 길은 저장된 「다른 안」을 보지 않고 늘 새로 찾았다(`plan_fresh_alternate`). 바로 바꾸는 길(`apply_change`)은 전부터 저장분을 썼다. 묻는 길도 저장분을 먼저 쓰게 고쳤다(로컬 구현 · mock 서버 시험까지, 커밋 · 배포 전).

## 경위 (x600 서버 기록 — 상위 세션 15:36 실서버 확인, role-manager fb840cd1)

| 단계 | 기록 | 값 |
|---|---|---|
| 등록 | `itinerary_items` (여행 `a2d3bcbb…`, 판 1) | 「북촌한옥마을 산책」 `detail.alternates` = 빨래골 · 은평한옥마을 · 서울 관상감 관천대 (`alternates_from` 접수) |
| 설문 | 여행 `constraints.survey.on_disruption` | `ask_first`(항로 지킴이 꺼짐 — 먼저 물어봐) |
| 고객 말 | `trip_chat_turns` 2356 (15:36:01) | 「북촌한옥마을 다른 데로 바꿔 줘」 |
| 해석 | Case `7952b3fa…` `classified` · `routed` | `action: propose_alternatives` → 활동 팀 `activity.propose_change`. 해석 모델은 첫 모델 시간 초과(`ollama:timeout`) 뒤 대체 모델(12.38초) — 17.2초 대부분 |
| 팀 | `conversation_work._propose_alternatives` | `_fresh_plan` → `plan_fresh_alternate` 로 새로 찾음(후보 평가 로그에 저장 대안 「서울 관상감 관천대」도 새 후보로 다시 평가돼 「그 시각 영업을 확인할 수 없다」로 빠짐) |
| 답 | `trip_chat_turns` 2357 | 「다른 안은 1) 북촌전망대 · 2) 그랑핸드 가회점 · 3) 세인트제임스 부티크 삼청 · 4) 14:30으로 늦추면 북촌동양문화박물관」 |

경위 미확인: 해석 모델이 처음부터 `propose_alternatives` 를 냈는지, `apply_change` + 조건 칸(`condition_text`)을 내서 `decision_unit` 의 조건 막이(`condition_guard` → `propose_alternatives`)를 탔는지는 기록에 남지 않아 가르지 못했다(Case 이벤트에는 바뀐 뒤 할 일만 있다). 어느 쪽이든 고친 뒤에는 저장분을 먼저 묻는다.

## 고친 것 (로컬 — 원격 fb840cd1 의 git archive 사본)

- `itinerary_changes.stored_alternates(item, places_by_id, now)` — 들고 있는 「다른 안」 가운데 지금 고를 수 있는 것. 빼는 것(낡음): 지금 곳과 같은 곳 · 이 여행에 장소 행이 없는 곳 · 시작 시각이 이미 지난 안.
- 활동 · 식사 팀 `conversation_work._propose_alternatives` — 저장분이 있으면 그것으로 묻고(고르는 둘째 차례도 같은 저장분에서 찾는다), 없거나 다 낡았을 때만 새로 찾는다.
- `TripDesk.propose_alternatives`(팀을 거치지 않는 채팅 길) — 같은 규칙. 재난 뒤 다시 시작(`keep` — 피해 구 빼기)은 전처럼 새로 찾는다.
- `case_dispatch._prepare_candidates` — 쓸 수 있는 저장분이 있으면 팀 실행 전 후보 넓히기(관광 목록 · 원장 근처)를 건너뛴다(필요 없는 계산을 줄인다).
- D-020 은 그대로다 — 「먼저 물어봐」 여행은 여전히 묻고 바꾸지 않는다. 묻는 안의 출처만 바뀌었다.

## 남은 일

- 커밋(commit 세션) → x600 자동 배포 → 실서버 확인(상위 세션): 등록 대안 있는 활동 「다른 데로 바꿔 줘」가 저장 대안 셋을 묻는지, 「1번」으로 그곳으로 바뀌는지.
- 저장분을 묻기 전에 다시 거르지는 않았다(고를 때 `plan_swap` 이 다시 점검한다). 접수 때 확인한 안이라 그대로 싣는다.
- 해석 17초 — 첫 모델 시간 초과 뒤 대체 모델로 넘어간 탓. 이번 작업 범위 밖.
- 「바꿔 줘」를 「후보 알아봐 줘」로 읽는 해석 자체는 고치지 않았다(경위 미확인 — 위).
