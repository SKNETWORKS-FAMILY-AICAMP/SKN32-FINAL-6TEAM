# 계획 정리 완료와 진행 문구 동기화

계획 정리 완료·100% 뒤 마지막 SSE의 「7/8 · 이동 확인 중」이 남는 결함을 수정했다. 완료 상태에서 큰 단계 막대와 상단 작은 막대의 부가 진행 문구를 숨긴다. 받은 적 없는8/8 값을 만들어 채우지 않는다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 수정 전 불일치 재현 | 확인 | 2/2 = 100% |
| mock 서버 화면 고유 시험 | 통과 | 6/6 = 100% |
| 진행률 단위 시험 | 통과 | 5/5 = 100% |
| 타입·lint | 통과 | 2/2 = 100% |
| 실제 촬영 확인 | 완료 | 2/2 = 100% |

## 원인·변경

결과를 받은 뒤에도 마지막 progress 패킷은 보관된다. 완료 단계·100%는 이미 `view.stage`를 보지만 아래 문구는 마지막 패킷을 항상 「확인 중」으로 출력했다. 질문에 답하기 위해 읽기 화면을 붙잡으면 둘이 함께 보였다. 보존된 패킷이나 API 계약을 바꾸지 않고 두 출력 위치에서 완료 여부를 확인한다. 진행 중 실제 수치·제목은 그대로 보인다. 접근성 `aria-valuetext`에서도 완료와 미완료가 섞이지 않는다. 질문 대기·자동 넘김·카운트다운·다시 연결 정책은 변경하지 않았다.

## 재현·검증 범위

mock 서버의 실제 SSE 마지막 progress만 `moves:7/8`, 「인사동 → 창덕궁」으로 바꿨다. 질문 화면이 보인 뒤 완료 결과 조회를 허용한다. 완료 상태와 SSE 마지막 수치가 어긋나는 조건을 의도적으로 만든 것이며 공개 cs 프로젝트 응답의 원문을 수집한 것은 아니다.

- 변경 전375/1280 각1회 모두 `정리 완료 · 100% · 7/8 · 인사동 → 창덕궁 이동 확인 중`을 기록했다.
- 새 시험2개: 질문 대기 상태에서 완료100%·완료 접근성 문구·이전7/8 없음, 결과 목록으로 이동한 뒤 이전 문구 없음. 결과 화면은 진행 막대 대신 계획 정보를 표시한다.
- 기존4개: SSE 진행 스트림, 실제 진행 알림, 진행 알림 없는 경우, SSE404인 경우 기존 조회 방식.
- 새 production 빌드 후 고유 화면 시험6/6. 같은 제품 빌드로 촬영용 스크롤 위치만 바꿔2개 재실행하여2/2. 단위5/5, 타입·lint2/2 종료0.
- 최초2개 시험 구성 시도는 완료 조회를 열지 않았거나 중복 완료 문구를 단일 선택하여 실패했고 백업에 보존했다. 제품 수정 직후 시험은 완료 상태 검사를 통과했으나 최종 결과 화면에 진행 막대를 기대해2개 실패했다(`after.json`). 최종 결과 목록 확인으로 바로잡았으며 제품 코드는 그대로다. 실패를 통과 수치에 합치지 않는다.
- 화면 점검은 변경된 진행 문구·질문 대기 영역만 대상으로 했다. 기존 스타일 유지, 새 모션 없음,375/1280 가로 넘침 없음. 최종2장 직접 확인.
- mock 서버 시험6/6 (화면 반응).
- 실서버 확인 (서버 응답): 안 했음 — 공개 cs 프로젝트 서비스와 x600 서버 배포 미확인.
