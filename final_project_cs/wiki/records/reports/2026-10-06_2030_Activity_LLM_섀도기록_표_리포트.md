# Activity LLM — 섀도 기록 표 리포트

## 결론

섀도 기록이 이제 DB 표 `activity_judge_shadow` 에 쌓인다(A안, 사용자 결정). 전에는 `INFO` 로그로만 남겼는데, 앱에 로깅 설정이 없어 운영에서는 아무 데도 남지 않았다.
실제 모델로 섀도 실행을 한 번 돌려 표에 5행이 쌓이는 것을 확인했고, 종류별 일치율을 SQL 한 줄로 집계했다. 고객 응답 시간과 내용은 바뀌지 않는다.

## 바꾼 것

| 파일 | 내용 |
|---|---|
| `app/infrastructure/db/migrations/031_activity_judge_shadow.sql` | 새 표. 외래 키 없음. `origin`(`live`·`eval`)과 평가용 칸을 둔다. 인덱스는 (kind, created_at) · case_id · eval_run |
| `app/infrastructure/db/repository.py` | `create_activity_judge_shadow` — 정해진 칸만 쓴다(다른 키는 버린다) |
| `app/composition.py` | `build_activity_judge_shadow_sink()`. 판정 LLM 을 넣을 때 함께 `ActivityTeam.judge_shadow_sink` 에 넣는다 |
| `app/modules/travel_ops/activity/judge/modes.py` | `ShadowJudge(sink=…)` · `build_judge(sink=…)`. 로그와 표에 같은 기록을 남기고, 표 쓰기에 실패하면 `WARNING` 만 남긴다 |
| `judge/types.py` · `feasibility.py` · `team.py` | `JudgeContext.tenant_id`, sink 전달, `judge_shadow_sink` 자리 |
| 시험 | `test_judge_modes.py` 4건, `test_activity_judge_wiring.py` 1건 보강, `tests/integration/db/test_activity_judge_shadow_db.py` 4건(롤백 트랜잭션) |

## 운영 영향

- **다른 환경은 마이그레이션을 돌려야 한다**(`python -m app.infrastructure.db.migrate`). 표가 없으면 쓰기가 실패하지만, 판정은 그대로 가고 `activity_judge_shadow_sink_failed` 경고만 남는다.
- 보존 기간·정리 정책은 아직 없다. 판정 1건당 1행이고, 성립 점검 한 번에 최대 5행이 쌓인다.
