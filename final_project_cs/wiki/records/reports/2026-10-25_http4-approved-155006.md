## 권한 경계·정리

새 scratch runner는 현재 nodeid가 위 네 원본 시험일 때만 다음을 허용합니다.

1. 실제 로드 모듈 `__file__`이 지정 시험 파일이고 원본 함수 code object가 일치하는 호출 stack에서 `AF_INET/SOCK_STREAM`, `127.0.0.1:0` bind만 허용합니다.
2. 해당 node가 방금 확보한 소켓만 listen을 허용하고, 연결은 같은 node가 확보한 정확 `127.0.0.1:port`만 허용합니다. 임의 loopback 전체 허용은 없습니다.
3. 기존 정확 stdlib `_fallback_socketpair.__code__` 예외와 실제 send/recv preflight를 유지했습니다. connect_ex/sendto/psycopg·외부 연결·비소유 loopback은 계속 차단합니다. HTTP4 활성 중에도 비소유 loopback와 외부 주소 connect를 각각 차단하는 8회 의도적 probe를 통과했습니다.
4. 원본 시험이 주입하는 `Api` 대역을 그대로 사용했습니다. 실 OpenAI/LLM/API 전송·실 DB 접속은 허용하지 않았습니다. 합성 unit 설정/비밀 dotenv 차단·standalone_services·mobility reset·conftest 격리도 기존대로입니다.

[허용 감사](../evidence/2026-10-25_http4-approved-155006/runs/20261024T155045_343073Z/http-allow-audit.json)에 bind/listen/connect와 소유 nodeid를 남겼습니다. 통합 run 임시 포트는 55362·55364·55366·55369입니다. 단독 run은 55341·55344·55346·55348입니다. 원본 shutdown 이후 runner teardown에서 소유 소켓만 close하여 모두 fileno=-1, 새 server thread 잔존 0을 확인했습니다. 프로세스 종료 후 [netstat](../evidence/2026-10-25_http4-approved-155006/netstat-after.txt)에서 이 8개 포트의 LISTENING 0을 별도 검산했습니다. 기존 서비스 프로세스/포트를 종료하는 명령은 사용하지 않았습니다.

## 보존한 시행착오·생성물

최초 scratch 실행 `20261024T155010_137928Z`의 4 FAILED를 덮지 않고 보존했습니다. 복사된 pyc의 `co_filename`이 옛 playdata2 경로여서 경로 기반 caller 식별이 원본 시험 bind를 거절했습니다. 제품 결함이 아닙니다. runner만 실제 모듈 `__file__` + 해당 원본 함수 `__code__` identity로 고쳐 정확한 파일·함수 경계를 유지했고 재실행했습니다. 시험/제품/정책 gate를 완화한 것이 아닙니다. 첫 실패 runner의 SHA256은 그 run identity에 남고 최종 runner는 별도 SHA256으로 기록됩니다.

보존 스크립트 최초 netstat decode는 Windows cp949 때문에 실패했고 cp949 명시 후 정상 검산했습니다. pytest 결과를 가정하거나 합산하지 않았습니다. 최종 증거에는 세 실행의 원문 로그·JUnit·전후 hash·단계/node 결과·cleanup, runner/manifest/provenance와 검산을 포함한 36개 파일 및 복사 SHA256 inventory를 보존했습니다. 원래 runner/manifest/evidence는 덮지 않았습니다.

변경은 현재 profile의 고유 scratch, 새 cs 보고서/evidence와 cs wiki 결론 링크뿐입니다. root 현재 상태/인계 연결은 부모 소유로 남깁니다. DB schema/905·실모델·앱서비스·배포·커밋/푸시는 하지 않았으며, 관련 정상 전체 contract/security/DoD 관문도 본 절에서 성공으로 승격하지 않습니다.
