## 연결기 수정과 검증 범위

모델의 빈 문자열·비정상 종료·완성되지 않은 JSON을 HTTP502(모델 응답 실패)로 구분합니다. 고객 요청 오류400과 나눴고 종료 이유·사용 토큰·추론 시간 정보는 보존합니다. JSON 임의 보완·자동 재호출·추가 모델 호출은 하지 않습니다. 전체 스키마와 일정 선택·내용의 정답 검사는 앱이 따로 수행해야 합니다.

[로컬 검사 흐름 그림](2026-10-11_response-guard-flow.html)은 시작·판단·정상/실패 종료를 보여 줍니다. 이 그림은 운영 배포 상태를 나타내지 않습니다.

| 기존 합성 개발 답안의 모델 판 | 완성 응답 보존/전체 | 실패로 구분 | 우리 데이터 추가 학습 |
|---|---|---|---|
| Gemma-4-E4B-it Q4_K_M 배포 원본 | 47/48 = 97.92% | 1/48 | 없음 |
| 같은 기반 + FINCH seed20261014 | 48/48 = 100% | 0/48 | 있음 |

| Gemma-4-E4B-it QAT Q4_0 배포 원본 | 47/48 = 97.92% | 1/48 | 없음 |

배포 원본도 개발사의 학습을 거친 Instruct 판입니다. 위 비율은 **기존 답안의 완성 여부를 재생한 값**이며 신규 추론 정확도나 독립 표본이 아닙니다. 400토큰 조건의 빈 답3개를 확인했고 800토큰 조건은 각 판24/24가 완성됐습니다. 이번240개에서 잘린 JSON 원문 자체는 관측하지 않았고, 잘린 JSON·중복 키·NaN 등은 별도 단위 시험으로 검사했습니다. Oracle ARM 실제 앱에서 확인한 잘린 JSON은 별개 사건으로 유지합니다.

- mock 서버 시험 5/5 = 100% (화면 시험이 아닌 연결기 HTTP 응답 검사): 요청 오류400, 빈 답502, 잘린 JSON502, 정상200, upstream 형식 오류502.
- 로컬 기존 계약11/11와 보호 시험7/7 = 100%. 별도 대기열 조건 시험3/3 = 100%.
- 실서버 확인(서버 응답): 기존 Oracle ARM 실제 HTTP 실패 기록·서비스·대기열·자원 상태를 읽었음. **수정된 연결기로 Oracle ARM 앱 답변 회귀는 안 했음**.

## Oracle ARM 자원과 앱 실패
