# 테스트 계획 목록 — 아이폰에서 골라도 입력칸에 안 채워지던 문제 수정 (2026-10-16)

아이폰 · 아이패드에서 「테스트 계획」 목록을 열고 계획을 탭해도 입력칸에 계획이 채워지지 않던 문제를 고쳤다(사용자 신고).
입력칸에 이미 다른 글이 있는지와는 상관없다 — 고르면 원래 글을 바꿔 넣는다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 원인 찾기 | 끝 | 1/1 = 100% |
| 고치기 | 끝 | 1/1 = 100% |
| WebKit(사파리 엔진) 탭 확인 | 통과 | 4/4 = 100% |
| 크롬 목록 화면 시험(mock 서버) | 통과 | 15/15 = 100% |
| 실서버(x600) · 실제 아이폰 확인 | 안 함 | 0/1 = 0% |

## 원인

목록은 「초점이 목록 밖으로 나가면 닫는다」로 되어 있었다(2026-10-12 `45ab1efa` 부터). 크롬은 단추를 누르면 그 단추로 초점을 옮겨 문제가 없지만,
WebKit(사파리)은 **탭한 단추에 초점을 주지 않고 바탕(`main`)으로 옮긴다**. 그래서 손가락을 떼기 전에 목록이 먼저 닫히고, 누른 계획이 골라지지 않았다.
WebKit 에서 사건 순서를 찍어 확인했다: `mousedown(단추)` → `focusout(summary → MAIN)` → 목록 닫힘 → `click` 은 바탕에 떨어짐.
기존 화면 시험은 모두 크롬으로만 돌아 이 문제를 잡지 못했다.

## 고친 것 — [test-plans.tsx](../../../frontend/apps/web/src/features/trip-registration/test-plans.tsx)

1. 목록 안을 누를 때 초점이 움직이지 않게 했다(목록 칸의 `mousedown` 기본 동작을 막음 — 클릭은 그대로 일어난다).
2. 목록은 **바깥을 누르면** 닫는다(문서 전체 `pointerdown`). 초점 이동으로는 Tab 키로 밖에 나간 경우만 닫는다.
3. 키보드(화살표 · Home · End · Esc · Enter)는 그대로다 — 기존 키보드 시험 통과.

## 시험

**mock 서버 시험(화면 반응)**
- WebKit(Playwright WebKit 26.6 · 아이폰 13 화면 · 손가락 탭): **고치기 전 0/4 → 고친 뒤 4/4**. test38 · test26 · test1 · test50 을 탭해서 입력칸에 채워지고, 바깥을 탭하면 목록이 닫히는지 본다.
  이 확인은 저장소 설정(크롬 전용)에 넣지 않고 한 번 돌린 임시 설정이다.
- 크롬(`PLAYWRIGHT_CHANNEL=chrome`): 목록 관련 4파일 **15/15**. 새 시험 1개를 더했다 — 단추를 누르는 순간 초점을 비워 사파리 조건을 흉내 낸다(고치기 전 코드에서 실패함을 확인).
- 타입 검사 통과 · ESLint(바뀐 파일) 통과 · vitest 787/787.

**실서버 확인(서버 응답)**: 안 했다. x600 서버에 배포된 뒤 실제 아이폰으로 목록에서 하나를 골라 입력칸에 채워지는지 봐야 한다.
