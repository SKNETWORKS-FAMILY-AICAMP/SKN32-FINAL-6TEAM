# 서비스 평가 베이스라인과 개선 전후 (2026-10-06)

## 한눈에

- 서비스가 하는 일(고객 말 분류 · 일정 항목 짚기 · 규정 답 · 계획 읽기 · 알림 번역)마다 **지금 값(베이스라인)** 을 제품 코드를 그대로 불러 쟀고, 개선한 것은 **전과 후를 같은 질문으로** 다시 쟀다. 실제 측정치만 적었고 못 잰 것은 「못 잼 + 이유」로 적었다.
- 가장 잘 나온 곳: 의도 분류 97.5% · 일정 항목 짚기 97.3%(769문제, 연결 시험 기준 — 가르친 모델 단독은 97.5~98.8%) · 규정 문장 인용 정확도 100% · 자동 시험 4,245개 통과 · 결정 단위 재생 167/172 = 97.1%.

- 개선해서 다시 잰 것: 규정 색인 개선(정답을 보인 비율 B 43.8% → 64.6%, 대가 있음) · 규칙+ML 앞단(섞은 흐름 90.8% → 91.9%) · 가르친 모델(688 → 750~760, **시드만 바꿔도 10문제 움직임**) · 학습한 분류기(긴급도 60.9% → 88.4%).
- 정할 것: ① 규정 색인 개선을 운영에 넣을지 ② 일정 항목 짚기의 「빈 답」을 「해당 없음」으로 처리할지(같은 시험에서 계산하면 90.8% → 93.4%) ③ 번역 보호 장치에 금액 단위 대조를 더할지. 세 가지 모두 제품 코드를 안 고치고 측정만 했다.

## 3. 일정 항목 짚기 — 에이전트의 핵심 과제

고객 말 하나 → 일정 항목 번호 하나 또는 「없음」. 모델은 번호만 고르고 답 문장은 DB 값으로 만든다(시각·장소를 지어낼 자리가 없다).

### 3-1. 개선 이력 (769문제 세트, 요청 둘 제외 · 엄격 계수)

| 단계 | 전 → 후 | 읽기 |
|---|---|---|
| 모델을 우리 데이터로 가르침(QLoRA) — Gemma-4 E4B | **688(89.5%) → 750(97.5%)** · 이쪽만 맞음 69 : 7, p=6.4×10⁻¹⁴ — **시드만 바꿔 다시 가르치면 760(98.8%)**(시드 2, 13 : 3, p=0.021) | 가장 큰 개선. 학습 한 번의 차이가 10문제(1.3%p) |
| 같은 방식 — Jev 계열 Winnow-E4B(시드 1개) | 655(85.2%) → **756(98.3%)** | 가르친 E4B 시드 1(750)과 10 : 4(p=0.18), 시드 2(760)와 4 : 8(p=0.39) — **구분되지 않는다. 「Winnow 가 더 낫다」는 근거 없음** |
| 가르친 E2B · Kanana-2-3B | → 739 · 715 | 작을수록 낮음 |
| 프롬프트 자동 최적화(GEPA, E4B) | 사람 세트 직접 +2/264 · 종단 83 → 82 | **효과 없음** (마스터 문서 §46-4) |
| 규칙·ML 앞단을 붙임 | 750 → 745~747 (가르친 E4B) | 호출은 줄지만 점수는 못 올림 — **다만 섞은 대화에서는 다르다(3-2)** |

초기 90문제 세트에서는 현행 코드(질문 속 낱말이 일정 제목에 그대로 있어야 찾음) 33/90 = 37% → LLM 번호 고르기 87/90 = 97% 였다(다른 세트라 위 표와 견주지 않는다). 개선 시도 전체표(파인튜닝 · 프롬프트 · 추론 방식 · 조합)는 [마스터 문서 §46](../../../../program/research/여행일정_질문인식_모델비교_2026-09-29.md).

### 3-2. 실전처럼 섞은 흐름 (2026-10-06, 서버 C에서 문제마다 실제 호출)

재료: 위 769(+요청 둘 66) + **관광지 질문 틀 × 우리 장소 목록**(서울·경기 관광지 QA 의 질문 틀 516개에 우리 장소 DB 8,370곳 이름을 채움 — 일정 안 장소 300 · 일정 밖 장소 300) + AI Hub 일상 대화 1,000 + KoCulture 구어체 300 = **2,735문제**를 일정 5개에 나눠 무작위(seed 20261006)로 섞었다. 정답 = 일정 항목 또는 「없음」(일상 대화·일정 밖 장소·범위 밖 요청). 변형당 1회.

| 구조 | 요청 둘 제외 전체 정답(2,669) | **정답이 「없음」인데 항목을 짚음**(1,786) | 정답 항목이 있는 질문 맞힘(883) | 전문가 모델 호출 | 지연 중앙 / p95 |
|---|---:|---:|---:|---:|---:|
| 가르친 E4B 단독 | 2,424 = 90.8% | **80 = 4.5%** | 786 = 89.0% | 2,735 (100%) | 164 / 205ms |
| 규칙 → 가르친 E4B | 2,419 = 90.6% | 83 = 4.6% | 784 = 88.8% | 2,608 (95%) | 163 / 206ms |
| **규칙 → ML 판별기 → 가르친 E4B** | **2,453 = 91.9%** | **58 = 3.2%** | 784 = 88.8% | **2,117 (77%)** | 189 / 241ms |
| 규칙 → ML → Jev 계열(학습 없는 Winnow-E4B) → 가르친 E4B | 2,385 = 89.4% | **9 = 0.5%** | 639 = 72.4% | 768 (28%) | 506 / 746ms |

- **ML 앞단은 섞은 흐름에서 이득**이다: 단독 대비 37 : 8(이쪽만 맞음 : 단독만 맞음), 정확검정 p=1.5×10⁻⁵. 잡담 새어 나감 4.5% → 3.2%, 전문가 호출 23% 감소, 정답 항목 맞힘은 거의 같다(89.0% → 88.8%). 769 세트(전부 일정 관련 질문)에서는 −3이었던 것과 달리 **일정과 무관한 말이 많이 섞이면 거르는 앞단이 값을 한다.**
- **학습 없는 Jev 계열 모델을 보낼 곳 판정에 넣으면** 새어 나감이 0.5%로 가장 낮지만 **일정 항목을 있는데 「없음」으로 닫는 일이 늘어**(항목이 있는 질문 맞힘 72.4%) 전체는 단독보다 낮다(89.4% vs 90.8%, 114 : 153, p=0.02). 학습 없는 모델이므로 가르친 모델과의 공정한 비교가 아니다 — 가르친 Jev 계열을 보낼 곳 판정에 넣은 시험은 아직 없다 `[미실행]`.
- 출처별 새어 나감(가르친 E4B 단독): 일상 대화 58/1000 = 5.8% · 구어체 16/300 = 5.3% · 일정 밖 장소 관광지 질문 4/300 = 1.3%.

### 3-3. 읽기 실패 — 빈 답 85건(3.1%)

- 2,735문제 중 **85건(3.1%)이 빈 답**(형식 오류)이었다. **두 번 돌려 같은 85건**이 나왔다(결정적 재현). 원인은 확인하지 못했다 `[미확인 — 모델이 첫 토큰에서 바로 끝내는 것으로 보이나 어댑터·템플릿 쪽을 파 보지 않았다]`. 종류: 잡담 33 · 일정 밖 장소 27 · 일정 안 장소 13 · 변경 요청 8 · 요청 둘 4.
- 정답이 「없음」인 질문이 85건 중 **68건**이다. 같은 시험에서 **「빈 답 = 해당 없음」으로 처리하면 정답 +68, 새 오답 0**이라 단독 90.8% → 93.4% 가 된다(사후 계산 — 같은 시험에서 정한 정책이라 다른 자료로 확인해야 한다). 다시 부르는 것은 도움이 안 된다(같은 답이 나온다).

### 3-4. 실패 분석 — 「일정 안 장소」 질문이 71.3% 밖에 안 나온 이유

일정 안 장소 300문제의 엄격 정답은 214(71.3%)지만 **틀린 66건 중 59건은 같은 장소의 다른 일정 항목을 고른 것**이다(정답 장소가 일정에 두 번 이상 나오는 질문이 132/300). 「경복궁은 몇 시에 가요?」처럼 장소만 묻는 질문은 그 장소가 두 번 나오면 정답 항목이 하나로 정해지지 않는다 — **라벨이 모호한 것이지 모델이 못 읽은 것이 아니다.**

| 해석 | 정답 |
|---|---:|
| 엄격(샘플로 뽑은 그 항목이어야 정답) | 214/300 = 71.3% |
| 장소 일치(같은 장소의 항목이면 정답) | 273/300 = 91.0% |
| 정답 장소가 일정에 한 번만 나오는 질문 | 159/168 = 94.6% |

진짜 실패 27건 = 다른 장소를 고른 7 + 「없음」으로 닫은 7 + 읽기 실패 13. 따로 눈에 띄는 것은 추천형 질문(「야경 명소 추천」 같은 틀은 일정 항목으로 답이 정해지지 않아 0/6) — 이 틀의 질문은 시험 설계상 정답이 없다. 한계: 장소 일치로 본 91.0% 는 내가 다시 정한 채점 기준(사후)이고 제품이 이런 질문에 되묻도록 설계됐는지는 별도다.
