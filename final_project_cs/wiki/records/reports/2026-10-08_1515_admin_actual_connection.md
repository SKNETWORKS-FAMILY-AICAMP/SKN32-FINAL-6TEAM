## 실제 변경

- 팀 관리자 앱을 로컬 작업 폴더에 복원했다. 원래 README와 팀 앱 원본을 `_backup/2026-10-08_live_restore`에 보관했다.
- 실제 연결을 기본으로 하고 명시된 demo만 예시 자료를 사용한다. 실패하면 데모로 전환하지 않는다.
- 운영자 서명 쿠키·PBKDF2 비밀번호·로그인 잠금·로그인/쓰기 CSRF와 scope를 기존 인증으로 적용했다.
- 고객 쿠키·키는 운영자 인증이 아니다. 계정 미설정·제거·권한 회수는 접근을 닫는다.
- 변경 행위자는 쿠키의 운영자 id이며 몸통의 actor를 받지 않는다. 운영용 API 키는 설정에서만 읽는다.
- 사용자 차단·기본/예외 채팅 한도·문의 답변·템플릿·공지·점검 모드는 DB에 영속 저장하고 감사 기록을 남긴다.
- 승인·위임·발송 결과 해소는 기존 고객 API 경로를 재사용하며 Case를 직접 UPDATE하지 않는다.
- 기존 서비스 설정·보관 기간과 접수 상태·이벤트·근거를 새 관리자 탭에 연결했다.
- 고객 문의/답변 조회는 본인 테넌트·본인 사용자만, 공개 공지에는 운영자 id를 내보내지 않는다.
- 개인정보 가림을 저장/감사 전에 적용하고 고객 문의·정책·채팅 카운터는 고객 보관 정리와 함께 지워지도록 외래키를 연결했다.
- 안전 감시 주기 편집을 실제 운영에서 끄고 채팅 한도만 저장한다. 자동 유료 영업 조회를 새로 켜지 않았다.

## 계측과 한계

- 사용자 마지막 사용은 기존 키와 쿠키 세션 둘 다 읽는다. 사용자별 DB 반복 조회를 일괄 조회로 바꿨다.
- 외부 호출은 국내 소스 한국 날짜, 구글·카카오는 UTC 기준으로 읽는다. 원래 제공처 보호 상한을 운영자가 높이지 못한다.
- LLM 집계는 현재 테넌트 접수와 연결된 호출만 포함한다. 귀속되지 않은 웹 호출은 합계에 포함하지 않는다.
- HTTP 경로별 지연·CPU·메모리·디스크·재시작·감시 실패 계측은 미연결이고 미계측으로 표시한다.
- 같은 기계의 별도 프로세스·포트 분리다. 다른 기계로 물리 분리됐다고 주장하지 않는다.
- 실제 x600 서버 배포·외부 제공처 재호출은 이 담당 작업에서 수행하지 않았다. 통합·배포 판정은 루트 작업이 확인한다.

- `python -m pytest tests/security/test_admin_json_gateway.py -q`: 11 passed.
- 보안 8개 당시와 기존 계층/운영앱 분리 회귀 묶음: 37 passed, 기존 SyntaxWarning 1개. 이후 새 보안 3개를 추가해 별도로 11 passed 확인.

- mock 서버 시험 3/3 = 100% (운영자 로그인·미설정 차단·실제 설정 저장 화면 반응). 브라우저 테스트의 alert 선택자 1개를 명확히 한 후 통과했다.

- 기존 팀 시연/오프라인 HTML 회귀: 17개 중 16개 처음 통과, 저장 버튼 이름 회귀 1개는 시연 모드 표기를 보존한 뒤 해당 1개 재시험 통과(합계 17/17). 동작을 무시하는 방향으로 시험을 바꾸지 않았다.
