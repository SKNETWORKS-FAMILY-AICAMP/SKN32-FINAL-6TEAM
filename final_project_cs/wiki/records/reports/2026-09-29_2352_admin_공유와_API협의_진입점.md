# 운영 앱 공유와 API 협의 진입점

2026-09-29 · Codex · `role-eval-ui` · 기존 구현 작업 `ST4F-176`의 공유 후속 작업.

사용자는 현재 앱과 문서를 커밋·푸시하여 백엔드 에이전트가 구현 내용을 확인하고 API 계약을 먼저 합의하는 흐름으로 진행하고자 했다. 프론트 구현·화면 기획·목업·백엔드 조사 자료를 함께 공유하고, [운영 앱 API 협의](../../external/admin-screen-api.md)를 다음 작업의 진입점으로 추가했다.

## 이번 결과

- 위키 문서에 읽을 순서, 백엔드가 제시할 계약 초안의 내용, S-01~S-11과 A-01~A-15 대응, 정책 미정 사항과 상태 갱신 기준을 정리했다.
- 합의·백엔드 구현·프론트 연결·실제 통합 검증을 분리했다. 현재 API 합의는 없고 live 연결은 미구현이다.
- External 인덱스, 프론트 공통 README/작업 안내, admin README, 목업 README, 허브 로그에서 협의 문서로 연결했다.
- 기존 앱 소스·HTML·API 계약은 이번 공유 준비에서 바꾸지 않았다. Google 지도 예산 계측 등 기획/데모와 최신 백엔드의 차이는 조사 보고서로 안내한다.
- 독립 검토에서 홈 화면의 요구 ID 누락(A-05·08·13)을 찾아 협의 표에 반영했다.
- stage 점검에서 E2E 시험 파일 2개의 마지막 빈 줄 경고를 정리했다. 테스트 동작과 앱 소스·HTML에는 변화가 없다.

## 공유 범위

이번 커밋 대상은 `frontend/apps/admin/`의 실행 소스·테스트·설정 예시·화면 기획·정적 목업·단일 HTML, 프론트 공통 안내, 위키 협의/조사/검증 기록과 링크다. 앞선 develop 동기화 기록도 로그의 참조 자료로 포함한다.

기존에 남아 있던 `frontend/apps/web/.env.example` 수정은 이 작업과 분리해 미커밋 상태로 보존한다. 실제 `.env`, `.env.teamflow`, node_modules, 빌드·시험 결과 디렉터리는 Git에서 제외된다. 팀 규칙·백엔드 코드·개인 규칙 원본은 변경하지 않았다.

Python 시험의 최초 샌드박스 실행은 가상환경의 원본 Python 프로세스를 만들지 못했다. 실행 권한을 확보해 재시도한 결과 위의 시간 제한에 도달했다. 이번에는 백엔드 코드·기대값을 수정하지 않았다. [이번 점검 기록](../evidence/2026-09-29_2352_admin_공유와_API협의_진입점.md)을 참고한다.

## 공유와 다음 단계

공유 대상은 `origin/role-eval-ui`다. 이 커밋을 push해도 `role-manager`나 `develop`에 자동 반영되는 것은 아니다. 백엔드는 해당 브랜치의 [협의 문서](../../external/admin-screen-api.md)와 연결 자료를 읽고 API 계약 초안·정책 질문을 제시한다. 프론트와 합의한 항목부터 구현/연결하고 실제 통합을 검증한다.

이 문서는 커밋 준비 시점의 범위와 검증 기록이다. 실제 커밋·푸시 완료 여부와 커밋 ID는 Git 작업 결과와 원격 이력으로 확인한다. 백엔드의 자료 수신·검토·합의, 실제 연결·배포는 이번 작업에서 확인하지 않았다.
