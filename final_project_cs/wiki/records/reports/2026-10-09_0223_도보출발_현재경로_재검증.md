# 직접 도보의 출발 안내도 현재 경로로 다시 계산한다

정상 도보가 차량용 저장 구간 검사를 통과하지 못해 안내가 보류되던 문제를 새 도보 문맥에서 해결했습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 직접 도보 식별·현재 계산 | 구현·검증 | 1/1 = 100% |
| 관련 시험 | 통과 | 55/55 = 100% |
| 확대 회귀 | 통과 | 671/671 = 100% |

## 문제와 변경

v11 출발 시점 조회·안내 범위입니다. 직접 도보는 빈 legs와 check=None으로 저장됐지만 관측 함수는 차량 구간만 허용했습니다.
새 내부 옵션은 path_kind=direct_walk로 식별합니다. 빈 차량 구간이나 이름만으로 도보라고 추정하지 않습니다.
계획과 출발 관측은 동일 보행망 거리·계단 시간 함수를 사용합니다. 현재 일정 장소와 저장 동행 조건의 도보 상한을 확인하고,
현재 시각을 분 올림해 출발·도착을 재계산합니다. pre_departure 운영 여유까지 목표시각 안에 들어야 안내합니다.
저장 ETA를 현재 값으로 간주하지 않습니다. 길 단절은 보류하고 계산기 미가용은 기존 거리 환산 모델과 이유·degraded 근거를 남깁니다.
공개 경로 응답과 코어 계약·배포 설정은 변경하지 않았습니다.

## 검증 근거와 범위

- 첫 시험 50/51 통과, 임시 폴더 생성 오류1건. [첫 원문 XML](../evidence/2026-10-09_0213_도보출발_재검증/walk-departure-target-v1.xml)을 보존했습니다.
- 작업 폴더 안 임시 경로를 지정한 관련 시험 55/55. 로컬 DB 도보 시험2/2를 포함합니다.
- 실제 GraphRouter·BikeRouter·Planner의 계단 경로 시간 유지, 현재 경로 변경, 초 단위 올림, 명시적 길 단절,
  거리 환산 대체 근거, 동행 정책 상한, 운영 여유, 비정상 수치 차단을 확인했습니다.
- 로컬 DB 고유 시험 여행에서 문맥 왕복과 현재 ETA5분 안내를 확인했습니다. HTTP·보행 응답은 통제 입력이며 실제 서울 보행 시간 측정은 아닙니다.
  10회 확인에서 안내1회, 길 단절 조건에서는 안내0회였습니다. 관련 시험과 확대 회귀 수는 합산하지 않습니다.
- 확대 671/671, live·mobility_full 제외. 저장소 전체 시험이나 새 독립 웹 오차 검증이 아닙니다.
- Ruff·선택 변경의 diff 검사 통과. 기존 추가 웹 원자료6/6 해시 일치. 이번 새 웹 정확도 표본0건·지도 개발자 API 호출0회.

mock 서버 시험: 이번 단계에서는 사용하지 않았습니다. 실제 계산 코드·로컬 DB와 통제 응답을 사용했습니다.
실서버 확인(서버 응답): 배포된 cs 프로젝트 서버는 이번 단계에서 안 했습니다. 실제 버스·보행·결제 측정도 안 했습니다.

## 연구 확인과 남은 원인

[보행 경로 연구(2015)](https://drops.dagstuhl.de/entities/document/10.4230/OASIcs.ATMOS.2015.1)의 출판사 초록을 다시 확인했습니다.
보도·광장 횡단 정보 부족을 다루는 연구이며, 이번 관측 연결이 보행망 품질을 해결했다는 근거로 쓰지 않습니다.
연구 알고리즘을 새로 적용하지 않았고 오늘까지의 문헌을 전부 조사했다는 주장도 하지 않습니다.

옛 문맥 누락·명시적 종류가 없는 옵션은 여전히 경로 복구가 필요합니다. 현재 여행 동행 조건 변경과 저장 문맥의 대조도 남았습니다.
늦음·단절 보류를 실제 Case 재조정으로 전달하기, 탑승 중 갱신, 회전 제약 적용, 혼합 운임,
출입점 일치 새 웹 표본·실제 보행 오차 검증을 이어갑니다. 전체21개 기능 완료를 선언하지 않습니다.
