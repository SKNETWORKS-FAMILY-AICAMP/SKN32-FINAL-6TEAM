# 재난 후보 내부 기록 매니저 통합 검토 — 2026-10-17

기존 재난 수신 화면 커밋 위에 후보 진단 수정 14개 파일을 보존 병합했다. 자료 확인 실패를 대안 부재와 구별하고, 고객에게 후보별 탈락 이유를 전달하지 않는다. 운영자 조회의 기존 권한과 테넌트 경계는 유지한다.

## 통합 시 보완

매니저에 빠져 있던 확인 실패 구분과 이동 계산 인원·조건 전달을 함께 보존했다. 내부 관찰 모듈은 외부 자료 호출 계층이 아닌 순수 계산 부품에 배치했다. Team의 인프라 직접 호출 금지 계약 검사는 예외를 추가하거나 약화하지 않았다. 실패 코드 시험 두 곳은 기존 공용 처리 코드 itinerary_source_failed에 맞췄으며, 미확인 후보를 추천하지 않는 단언과 고객 비노출 단언을 유지했다.

## 독립 검증

단위·구조·계약: 7,570개 통과, 138개 건너뜀. 추가 예약 시험 221개 통과. 변경 영역·권한·비밀값·수신 기록 DB 시험 189개 통과. 실행분 합계 7,980/7,980, 건너뜀 포함 대상 7,980/8,118. 정적 검사 F·E9와 릴리스 관문 26/26 통과. 격리 DB를 정지 후 보존했으며 운영 DB 스키마 변경은 실행하지 않았다.

첫 검사에서는 검증 사본의 기존 검사 설정·평가 입력 누락을 바로잡았다. 실제로 발견된 구조 경계 위반과 시험 기대값 차이도 수정 후 다시 검증했다. 생산자가 보고한 191개 관련 시험과 이번 전체 통합 검증의 범위는 다르다.

## 반영 범위

팀·개인 role-manager만 대상이다. develop과 main은 대상이 아니다. 현재 운영 API·worker에 있는 최신 자료 재조회와 대안 계산 변경은 별도의 운영판 보존 병합 대상이며, 이 Git 반영만으로 배포 완료라고 선언하지 않는다. 관리자 화면 실제 반영과 운영자 후보 조회·고객 비노출 확인은 배포 후 별도 기록한다.

mock 서버 시험(화면 반응): 화면 변경 없는 추가 진단 범위에서는 실행하지 않았다.

실서버 확인(응답): 실행판 조회만 했다. 이번 추가 진단 코드의 실제 운영 반영과 기록 저장은 아직 확인하지 않았다. 과거 후보 목록은 보관되지 않아 복원했다고 주장하지 않는다.

로컬 원본은 수정·동기화·정리하지 않았다. 시험과 코드 통합은 격리 사본에서 실행했다.
