## 1. 고른 것과 다른 후보 — 회의에서 바꿀 수 있게

비교 목업은 작성자의 개인 저장소에 있다(팀 미공유). 이 절에 후보를 글로 옮긴다.

| 정한 것 | 고른 안 | 다른 후보 |
|---|---|---|
| 마이페이지 구성 | **A — 지금 상태 줄 다섯, 줄을 누르면 항목별 화면** | B: 마이페이지는 보기만, 「수정」 한 화면에 섹션 여섯 · C: 프로필과 ⚙ 설정 목록 분리(설정 → 세부 두 단계) |
| 로그인 자리 | **메뉴 입구 + 마이페이지 「로그인 · 계정」 화면이 로그인 화면을 겸함**(별도 `/login` 없음) | 별도 `/login` 화면 · 메뉴 줄 이름만 바꾸기 · 메뉴 위 시트 |
| 메뉴 입구 모양 | **후보 1 — 프로필 줄 아래 같은 칸에 큰 단추** | 2 프로필 줄 오른쪽 작은 단추 · 3 메뉴 머리 「로그인」 · 4 게스트 안내 카드 · 5 목록 줄 하나 · 6 간편 로그인 아이콘(바로 업체로) |
| 단추 이름 | **「계정으로 계속하기」** | 「로그인 · 가입」 · 「로그인」 |
| 회원 로그아웃 | **메뉴 맨 아래 + 로그인 · 계정 화면** | 계정 화면에만 |
| 게스트 → 기존 계정 로그인 때 옮김 확인 | **묻지 않음(서버 그대로)** | 업체 화면에 가기 전에 한 번 묻기(웹만, 처음 가입하는 사람도 보게 됨) |

참고한 앱 사례는 다음과 같다.

- A안에 가까운 것: Google 계정(홈 카드 → 상세 탭) · Airbnb 계정 설정(섹션 허브). Android 설정 지침도 목록 줄 보조 문구에 현재 상태를 보이라고 한다.
- 소셜 계정 연결 · 해제는 계정 · 보안 쪽에 둔다(Airbnb).
- 로그아웃은 계정 화면 맨 아래에 둔다(Discord · Instagram · 배민).
- 조사 출처 40개와 「요약 · 미확인」 구분은 개인 목업 메모에 있다.

## 2. 바꾼 것

**마이페이지 A안 (`5e17a593`)**

- `/mypage` — 프로필(이미지 · 닉네임) 아래 상태 줄 다섯. 이 화면에는 동작 단추가 없다.
  - 로그인 · 계정: 게스트 / 로그인됨 · 연결 업체
  - 알림 받는 곳: 디스코드 · 시험 결과, 또는 텔레그램
  - 여행 취향: 앞 세 문항 답
  - 약관 · 동의: 필수 동의 여부, 선택 동의 n/3
  - 에이전트 연결: 사용 중인 키 수
- 줄을 누르면 가는 화면. 기존 카드 부품을 옮겨 담기만 했다(`features/profile/profile.tsx`).

  | 화면 | 담긴 것 |
  |---|---|
  | `/mypage/account` | 로그인 상태(회원 로그아웃) · 소셜 계정 |
  | `/mypage/alerts` | 디스코드 웹훅 · 텔레그램 · 웹훅 주소 직접 입력(수정 화면에서 옮김) |
  | `/mypage/consents` | 약관 동의 관리 |
  | `/mypage/agents` | 에이전트 키 |

  여행 취향 줄은 전처럼 시작 화면의 취향 카드를 연다.
- 「수정」 → 「프로필 수정」. 닉네임 · 이미지만 남겼다. 둘 다 서버 저장 API가 없어 지금처럼 「준비 중」이다.
- 서버의 디스코드 연결 콜백은 설정상 `/mypage?discord=…`로 돌아온다. 마이페이지가 그 주소를 받아 `/mypage/alerts?discord=…`로 넘긴다. 서버는 그대로다.
- 알림 화면에서 알림 채널 동의가 없으면 동의 요청이 한 번만 보이게 했다. 주소 입력 칸은 동의 뒤에 나온다.

**메뉴 로그인 입구 (`bae8175b`)**

- 게스트(서버 세션이 회원이 아닌 경우):
  - 메뉴 프로필 줄 아래 같은 칸에 「계정으로 계속하기」를 둔다. 누르면 메뉴를 닫고 `/mypage/account?returnTo=지금 화면`으로 간다.
  - 프로필 줄의 작은 글은 「이 기기에서만 · 마이페이지」로 바꿨다.
  - 마이페이지 프로필 카드에도 같은 단추를 둔다.
  - 로그인 방법이 없는 서버에서도 입구는 보인다. 그 화면이 「설정된 로그인 방법이 아직 없어요」라고 말한다.
- 회원: 메뉴 맨 아래에 「로그아웃」을 둔다. 마이페이지의 로그아웃과 같은 처리로, 읽어 둔 것을 버린 뒤 첫 화면으로 간다.
- 전의 「계정 연결 · 로그인」 줄은 이것으로 대신했다. 그 줄은 로그인 방법이 있을 때만 보였고, 마이페이지 `#accounts`로 갔다.
- 로그인 안내 링크 네 곳도 `/mypage/account?returnTo=…`로 바꿨다:
  - 여행 등록 제한: `trip-registration.tsx`
  - 계획 확인 등록 거절: `intake-review.tsx` · `result-parts.tsx`
  - 여행 목록 빈 화면: `trip-list.tsx`
  - 에이전트 키: `agent-keys.tsx`(A안 커밋에서)

## 3. 백엔드 확인 — 게스트 자료 옮김에 확인 단계가 있나

`[실측 · 코드]` 확인 단계는 **없다.**

- 게스트 세션으로 `login`을 하는 경우(`web_auth.py` `complete`):
  - 이미 가입한 계정이면 결과는 `signed_in`이고, 티켓에 게스트 id를 남긴다.
  - 처음 쓰는 계정이면 그 게스트가 그대로 회원이 된다(`created`).
- 로그인 마무리 호출 `exchange`가 `transfer_guest`를 바로 부른다. 여행 · 접수 · 예약을 옮기고, 게스트 세션 · 키를 거둔다(`b51da6a8`, develop도 같다).
- `exchange` 몸통은 `ticket` · `client_nonce` · `session`뿐이다(`AuthExchangeIn`). 그래서 옮김을 미루거나 거절할 길이 없다.
- 계정이 이미 있는지는 업체 화면을 다녀와야 안다.

사용자 결정으로 서버 그대로 간다. 소셜 카드의 안내 문장(「이 기기의 게스트 여행도 함께 보관돼요」)이 알린다.

★계약 문서 `rest-endpoints.md`의 소셜 로그인 절은 아직 「합치지 않는다 · 게스트 세션은 거둔다」만 적고 있어 게스트 자료 옮김이 빠져 있다. 백엔드 정본 문서라 이 작업에서 고치지 않았다(협의 필요).

## 5. 되돌리는 법

회의에서 다른 안으로 바꾸면 커밋 단위로 되돌린다. 메뉴 입구는 「로그인 · 계정」 화면을 쓰므로 **메뉴 입구를 먼저** 되돌린다.

```bash
git revert bae8175b
```

```bash
git revert 5e17a593
```

`git revert bae8175b`만 하면 마이페이지 A안은 남는다. 이때 로그인 입구는 마이페이지의 「로그인 · 계정」 줄 하나뿐이고, 옛 「계정 연결 · 로그인」 줄과 `#accounts` 링크로 돌아간다.
