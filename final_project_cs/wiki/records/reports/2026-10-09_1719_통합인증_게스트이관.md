# 통합 로그인과 게스트 일정 보관

동일한 소셜 버튼으로 로그인·가입을 처리하며 현재 게스트 여행과 검증 중 접수를 기존 회원 계정에 보관한다. 2026-10-09 사용자 요청 및 [계약](../../external/web-auth-transfer.md)에 따른 변경이다. 배포 완료를 뜻하지 않는다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 인증·게스트 이관 | 구현·회귀 통과 | 51/51 = 100% |
| 웹 요청·복구 helper | 통과 | 16/16 = 100% |
| 실제 소셜 왕복 | 미실시 | 0/1 = 0% |

## 변경

- `web_auth.py`, `web_auth_api.py`: 로그인 시작에서 인증된 게스트 출처를 기록하며 CSRF 확인. 신규 계정이면 같은 게스트 승격, 기존 계정이면 일회용 표 nonce 검증 뒤 여행·접수·예약 소유자를 이관하고 옛 게스트 자격을 폐기한다. 회원끼리는 합치지 않는다.
- `060_web_auth_guest_transfer.sql`: 일회용 표의 게스트 출처 선택 필드. 게스트 보관 만료 정리와 충돌하지 않도록 외래키 삭제 동작은 SET NULL이다.
- 웹 `social-accounts.tsx`, `social-done.tsx`, `auth.ts`: 고객에게 분리된 연결/로그인 선택과 게스트 자료 소실 경고를 없애고 동일 버튼으로 계속한다. 로그인 완료 뒤 원래 작성 경로로 돌아갈 수 있다.
- 웹 `intake-start.ts`, `trip-registration.tsx`, `login-draft.ts`: 한도 거절의 로그인 필요 정보를 보존하고 계정 화면으로 안내한다. 외부 소셜 페이지 이동 전에 글·첨부 파일·계획 조건을 IndexedDB에 보관하고 복귀 시 복구한다.
- 새 HTTP 이관 보안 시험, 웹 복구 helper 시험과 기존 인증 시험의 계약 변경 반영.

## 검증과 남은 범위

[실행 근거](../evidence/2026-10-09_1719_통합인증_게스트이관.md). 웹 타입 검사 및 변경 파일 ESLint 통과. 고유 백엔드 51건, 웹 helper 16건을 통과했다. 처음 실패한 환경 문제와 재실행 결과도 근거에 남겼다.

실제 소셜 업체 인증·외부 페이지 왕복의 첨부 복구와 x600 서버 배포는 실행하지 않았다. 기존 Case 소유권 및 백그라운드 접수 진행 중 이관 경계는 루트 통합 검증에 전달했다. `customer_cases`를 직접 수정하지 않았다.

기존 소스·시험·계약·결함 기록의 수정 전 사본: [백업](../../../_backup/2026-10-09_통합인증_수정전/).
