# 관리자 여행 상세 조회

## 2026-10-17 원인 확인·계약 갱신

- 사용자 요청: 관리자 사용자 상세의 여행을 눌러 실제 대화와 처음·현재 계획을 볼 수 있어야 한다.
- 확인: `UserDetail`의 여행 표는 ID·제목을 텍스트로만 출력한다. 관리자 라우팅·조회 API에는 여행 상세가 없다. `trip_chat_turns`와 append-only `itinerary_versions`·`itinerary_items`에 저장된 자료를 사용할 수 있다. 실제 고객 DB의 해당 여행 기록은 아직 조회하지 않았다.
- 원본 자료 보호: 공유 원본에서 빠진 파일을 복구하거나 덮지 않고 읽기 전용 `tools/safe_git.py ls-tree/cat-file`로 격리 사본 2,245파일을 만들었다. 남은 로컬 파일 147개와 추가 소스 5개를 사본에서 보존했다. Git HEAD 기준과 로컬 파일 출처는 격리 폴더의 `snapshot-manifest.json`에 기록했다.
- 구현 전에 [운영 앱 API 계약](../../external/admin-screen-api.md)에 읽기 전용 여행 상세·대화 페이지·최초/현재 계획 조회와 권한·오류 범위를 추가했다. 작성자 겸 계약 검토자: Codex. 독립 검토는 수행하지 않았다.
- 새 화면 유형: Detail / Record. 기존 관리자 시각 스타일과 반응형·키보드 규칙을 따른다.
- 남은 일: API·화면 구현, 격리 DB·브라우저 시험, 검증 결과와 인계 기록. 운영 배포·실제 고객 경로는 미확인이다.

## 2026-10-17 22:26 KST 구현

- 여행 제목 링크와 상세 버튼 → 사용자·여행 ID를 담은 고유 주소 → 대화/처음/현재 탭을 연결했다. 직접 주소·새로고침·뒤로 가기·키보드 좌우/Home/End 이동을 지원한다.
- 운영 앱에만 읽기 API를 등록했다. 사용자·테넌트·여행을 함께 확인하고 서명 세션·권한이 없으면 거부한다. 대화는 본문을 자르지 않고 작성 시각·역할·접수 연결을 보존하며 커서로 다음 기록을 읽는다.
- 처음 계획은 1판, 현재 계획은 읽기 전용 반복 읽기 트랜잭션의 최신 판을 조회한다. 날짜별 일정·장소·시각·고정 여부·저장된 이동 수단을 표시한다. 기록 미보관과 조회 실패를 구분하고 다시 읽기를 제공한다.
- 기존 7파일은 변경 직전에 `_backup/2026-10-17_admin-trip-detail/`에 보관했다. 코드 변경은 격리 사본 안에서만 수행했다.

### 실패·제외와 후속 수정

- 최초 Python 실행은 격리 사본에 필수 환경변수가 없어 준비 단계에서 실패했다. 시험용 값과 연결 불가 DB 주소로 다시 실행했고, 새 API는 PGlite 연결만 사용했다.
- 기존 보안의 고객 지원 라우터 1건은 고객 식별 과정에서 실제 DB 연결을 기다려 중단했다. 이 한 건은 통과로 세지 않았다. 고객 지원 코드는 수정하지 않았다.
- 첫 Chrome 실행은 4/6 통과했다. 개발 모드의 요청 취소가 실패 목업을 먼저 소비한 문제와 Next.js의 빈 안내용 alert까지 찾은 시험 선택자를 수정했다. 이후 6/6, 마지막 배포 빌드 실행 7/7을 별도로 확인했다. 최초 결과·캡처는 삭제하거나 덮지 않았다.
- 추가로 새로 읽기 실패 시 기존 대화는 남지만 오류가 숨는 경로를 발견해 오류·재시도를 표시했다. 다음 페이지 실패·새로 읽기 실패 후 회복을 추가 시험했다.
- 기존 항목의 이동 수단이 중첩된 저장 값에 있는 것을 확인해 선택된 수단을 읽도록 보완했다. 선택 변경 전/후 격리 DB 2건을 추가했다.
- Windows 경로 접근 제한 때문에 Next.js를 기본 제한 안에서 실행하지 못해 격리 사본의 검증 명령만 승인된 권한으로 실행했다. 원본 소스·운영 기계는 변경하지 않았다.

375px와 1280px의 대화·계획 화면 4장을 직접 확인했다. 화면 넘침 0, 탭 높이 44px 이상, 키보드 포커스, 일정 본문 글자 크기 14px 이상·굵기 600 이하를 브라우저로 확인했다. 별도 UX 프로필 파일은 확인한 프로젝트 트리에 없어서 기존 관리자 스타일과 기본 규칙을 적용했다. 입력·삭제·팝업·새 애니메이션은 이번 변경 범위에 없다.

## 남은 일·인계

검증된 변경만 새 격리 Git 사본의 최신 통합 대상 위에 올려 검토·회귀 시험한 뒤, 명시적인 커밋·푸시 요청 범위에 따라 반영한다. 공유 원본으로 역복사·원본 동기화는 하지 않는다. 운영 배포 뒤 지정 고객 여행의 실제 대화·첫 계획·현재 계획은 읽기 전용으로 확인해야 한다. 기존 보안 시험 제외 1건은 격리 PostgreSQL 환경을 갖춘 통합 세션에서 다시 확인한다.
