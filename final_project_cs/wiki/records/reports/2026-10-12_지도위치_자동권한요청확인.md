## 확인한 동작

- 최초 약관에 개인위치정보 수집·이용과 위치기반서비스 약관의 선택 동의 항목이 있습니다. 기본은 미선택이며, 여기서 동의한 값을 cs 프로젝트 API 동의 기록으로 보냅니다. 이후 지도 진입에서는 같은 서비스 동의 창을 다시 띄우지 않습니다.
- 서비스 위치 동의가 있으면 검증 화면과 등록 여행 모두 지도가 붙을 때 `useMyLocation`이 권한을 확인하고 `watchLocation`으로 위치를 요청합니다. 브라우저 권한이 미결정이면 권한 요청 단계로 이어지고, 허용 상태이면 위치 점을 표시합니다. 이미 차단된 경우에는 다시 요청하지 않고 기존 토스트로 브라우저 설정을 안내합니다.
- 서비스 동의가 없으면 자동 위치 조회·전송을 하지 않습니다. ‘내 위치’ 버튼을 누르면 기존 선택 동의 창을 열고, 동의 후 위치를 표시하고 카메라를 이동합니다. 취소하면 위치를 읽지 않고 버튼으로 초점을 돌립니다. 브라우저에서 허용했더라도 서비스 동의가 없으면 수집하지 않습니다.

[권한 흐름도](../../../frontend/apps/web/mockups/location-permission-flow-2026-10-12-v1/index.html). `diagram-design`과 프로젝트의 `acop` 프로필, flowchart 가이드를 사용했습니다. 설명은 `technical-writing`의 explanation 구조로 정리했습니다.

브라우저 허용은 기기의 위치에 접근할 권한이고 서비스 동의는 위치를 사용하는 범위·기록·철회에 대한 선택입니다. 프로젝트는 등록 여행에서 위치 기록도 처리하므로 브라우저 허용으로 서비스 동의를 대체하지 않습니다. 브라우저는 HTTPS와 명시적 권한을 요구하며, 필요한 경우 위치 API 호출 시 권한을 묻습니다. [MDN 공식 문서](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition). 위치정보법의 이용약관 명시와 동의 조항도 참고했지만 이번 작업에서 제품의 법적 사업자 분류를 새로 판정하거나 약관을 변경하지 않았습니다. [위치정보법 제18조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029559297).

## 검증 범위

mock 서버 시험 11/11 (화면 반응): 설치 Chrome과 현재 코드의 production 빌드, 시험용 위치 좌표를 사용했습니다. 최초 약관에서 위치 동의 저장→등록 여행 지도, 등록·검증 화면의 미결정 권한 자동 요청, 이미 허용한 위치 점, 서비스 미동의의 조회·전송 차단, 이미 차단된 권한 안내와 위치 호출 0회, 버튼 동의·취소·철회, 375px/1280px 누름 영역·초점 복귀를 확인했습니다. 권한 미결정 분기는 Permissions API의 시험 응답으로 재현했고 좌표는 Chrome 시험 공급자가 반환했습니다. 사용자 브라우저의 실제 GPS 값이나 네이티브 권한 팝업을 관찰한 시험이 아닙니다.

실서버 확인 (서버 응답): 안 했음. 공개 웹 조회는 HTTP 403, 브라우저 도구는 초기화 오류로 열리지 않았습니다. 따라서 x600 서버의 공개 배포 코드·현재 브라우저 권한·실제 GPS 수신 상태가 정상이라고 확정하지 않습니다. 공개 환경의 위치 권한 설정을 바꾸거나 배포하지 않았습니다.

처음 11개 실행에서 10개는 통과했고 최초 동의 연결 1개는 시험 빌드 약관이 이전 버전인 상태에서 mock 서버가 새 버전을 요구하여 실패했습니다. 시험 사본의 동의 관련 3개 파일을 현재 제품 코드로 동기화해 다시 빌드한 후 새 시험 3/3, 전체 관련 시험 11/11을 통과했습니다. 기존 제품 결함으로 보고하거나 버전 검사를 끄지 않았습니다.
