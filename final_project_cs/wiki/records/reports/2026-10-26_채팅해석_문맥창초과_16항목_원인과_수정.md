# 채팅 해석 문맥 창 초과(16항목 여행) — 원인과 수정 후보

## 결론

로컬 화면의 「지금 요청을 해석하지 못했어요(해석 모델 응답 오류)」는 모델 오류가 아니라 **입력이 문맥 창(`ollama_num_ctx` 8192)에 들어가지 않은 것**이다. 지시문(system)만 v9 7,291 토큰, role-manager 6,771 토큰으로 창의 83~89%를 쓴다. 답 상한(`travel.decision_unit.num_predict` 1200)을 예약하면 v9 의 `decision_unit.prepare_decision_context` 가 `compact_instructions` 뒤에도 넘쳐 `DecisionFailed: context_capacity_overflow` 를 낸다. role-manager 는 예약 검사가 없어 Ollama 가 창을 채우고, x600 에서는 유료 넘김이 생긴다(부모 보고서 [2026-10-26_x600_채팅해석_유료넘김_원인](2026-10-26_x600_채팅해석_유료넘김_원인.md): 7,842 + 400 > 8,192).

수정은 Codex 와 두 차례 논의해 정했다. 결정은 **프롬프트는 그대로 두고 `ollama_num_ctx` 를 12288 로 올리는 것**이다. 같은 모델을 부르는 호출은 모두 같은 값을 보낸다. v9 에는 용량 초과 답 문구도 따로 둔다. 실제 E4B 확인: 16항목·4턴 여행에서 `done_reason=stop`, 프롬프트 8,522 토큰(native 계수와 provider 계수 일치), 대상 「둘째 날 저녁」을 맞게 골랐다(apply_change), degraded 없음. role-manager 빠른 관문은 9407/9407 = 100% 통과(실패 0, 수집 9580, 기존 skip 173)다.

push·배포·로컬 반영은 하지 않았다: remote 0/2, x600 미배포, 로컬 v9 미반영.

## 1. 토큰 구성 실측

측정 조건은 다음과 같다. 고객 원문은 쓰지 않았다.
- tokenizer: Ollama 0.31.1 Gemma4 native(`native_context_tokenizer`, 해시로 묶인 manifest)
- 여행: 합성 3~4일 16항목
- 스크립트: `measure.py`, `breakdown.py`

| 구성 | v9 | role-manager 3c1af5b7 |
|---|---:|---:|
| 지시문(SYSTEM+EDIT_SYSTEM) | 7,291 | 6,771 |
| 지시문 축약 뒤(`compact_instructions`) | 6,359 | 해당 없음 |
| 일정 한 줄 | 54~59 | 54~59 |
| 16항목 일정 | 943 | 943 |
| 대화 4턴 / 6턴(턴당 160자 상한) | 289 / 434 | 289 / 434 |
| 변경 이력 8줄 | 623 | 343 |
| 출력 예약(num_predict) | 1,200 | (검사 없음) |
| 응답 스키마(`format`) | 0 — 프롬프트 계수에 들어가지 않음 | 0 |

- v9 의 16항목·4턴은 8,630 토큰이고, 축약해도 7,698 + 1,200 = 8,898 > 8,192 다. 빈 여행조차 7,390 + 1,200 > 8,192 이므로 **모든 요청이 축약(degraded)을 거친다.**
- role-manager 의 16항목·4턴은 8,110 토큰이다. 출력에 남는 자리가 82토큰뿐이다.
- 부모의 x600 실측 7,842 는 role-manager 의 16항목·0턴 계산값 6,771 + 99 + 943 = 7,813 과 맞는다. 스키마가 계수에 들어가지 않는다는 근거다.
- 오프라인 재현: `real_probe.py offline 8192 4 16` 을 돌리면 같은 `DecisionFailed: context_capacity_overflow: protected evidence was not truncated` 가 난다(모델 호출 0).

## 3. 계약과 결정(Codex 논의 2회, 읽기 전용, 본문만 전달)

- 지켜야 할 계약은 두 가지다.
  - context-v10(`output-reservation-v10.md`): 고객 문장·일정·이력은 byte 그대로 보내고, 출력 예약은 줄이지 않는다.
  - context-broker: 뺀 것은 반드시 `omissions` 에 남긴다.
  - 따라서 질문과 무관한 일정을 줄이는 안(D)은 계약 위반이다.
- 1차 결정: num_ctx 12288 + v9 답 문구.
  - 16384 대신 12288: x600 은 12GB GPU 에 bge-m3 도 올라가 있어 실측 전에는 보수적으로 둔다.
  - v10 의 「창을 키우지 않는다」는 수치 근거로 예외를 둔다.
- 2차 논의(부모가 「프롬프트 축소 우선」 지시 후):
  - 검토 결과, v10 축약 표 34행은 role-manager 지시문에도 34/34 = 100% 들어맞는다. 지시문을 약 1,036 토큰 줄일 수 있다.
  - 그래도 상시 적용은 **보류**한다. 학습 모델의 모든 요청을 바꾸는데, 정확도 재생(126~434문장)을 이번 모델 예산(4회)으로는 검증할 수 없다.
  - 일정 줄 축약(「실제 진행: planned」 생략 등)도 재생 검증 후속으로 남긴다.
  - num_ctx 는 한 커밋으로 맞춘다. 바꿀 곳은 설정 기본값, 배포 env, `.env.example`, 끼니 고르기·공지 판정 호출이다.
  - **Modelfile `num_ctx` 를 같은 값으로 바꾸는 운영 단계**까지 끝나야 해결로 본다. `num_ctx` 를 보내지 않는 호출(role-manager `OllamaToolChat`)은 Modelfile 기본값을 쓰기 때문이다.
- 기록: `codex-bundle.md` / `codex-answer.md`, `codex-bundle2.md` / `codex-answer2.md`. 고객 원문은 전송하지 않았다.

## 4. 수정 hunk

role-manager(기준 `3c1af5b774659fff7a067d1a04604e5e41ab1c37`)

- `app/core/settings.py`: `ollama_num_ctx` 8192 → 12288, 근거 주석.
- `deploy/make_server_env.py`: `ACOP_OLLAMA_NUM_CTX=12288`.
- `.env.example`: 안내를 12288 로.
- `app/composition.py` `_dining_meal_picker`: ollama 경로가 해석 모델과 같으면 `num_ctx` 를 보낸다(다른 모델이면 0).
- `ports/data_sources/notice_end_model.py`: `NoticeEndModel` · `NoticeImpactModel` 에 `num_ctx` 를 추가했다. `register_from_settings` 는 `ollama_notice_model == ollama_model` 일 때만 이 값을 넘긴다. 방식은 `item_pointer` 와 같다.
- 시험 변경:
  - `tests/unit/test_ollama_default_model.py` 의 기대값을 12288 로.
  - 새 `tests/unit/travel/test_decision_context_window.py`(6건): 설정·배포·안내 일치, 해석 요청의 `num_ctx=12288`·`num_predict=1200`·16항목·4턴 원문 보존, 끼니 고르기 같은/다른 모델, 공지 판정 같은/다른 모델.
  - 이 시험은 토큰 수를 재지 않는다. 저장소에 tokenizer 가 없기 때문이다.

v9 patch(위와 같은 내용, `.env.example` 은 v9 tree 에 없음)

- `trip_messages._decision_failed_answer(failure)`: failure 가 `DecisionFailed: context_capacity_overflow:` 로 시작하면 「이 여행의 일정과 대화가 길어 지금 요청을 한 번에 해석하지 못했어요 — 일정은 바꾸지 않았어요.」로 답한다.
- 그 밖의 해석 실패는 기존 문구 그대로다. 공개 `status=escalated` · `reason=decision_failed` 도 바꾸지 않았다([chat-inquiry-guide](../../external/chat-inquiry-guide.md) 의 decision_failed 그대로).
- v9 시험 추가: 실측 8,522 토큰이 12288 에서 축약 없이 들어가고 8192 에서는 overflow 임을 확인한다. 문구 분기도 확인한다.

겹침:
- `trip_messages.py`(v9 patch): 함수 하나 추가와 답 한 줄 교체. 다른 작업자의 수정과 같은 함수(`handle_trip_message` 의 `decision is None` 분기)에서 충돌할 수 있다.
- `decision_unit.py` · `edit_intent.py`: 손대지 않았다.
