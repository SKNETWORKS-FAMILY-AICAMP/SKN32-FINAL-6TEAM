# 최신 인원·휴식 조건을 출발 재검증과 재경로 계산에 연결

여행 인원이나 휴식 조건이 바뀌었는데도 이전 조건으로 출발 안내를 저장하던 문제를 고쳤습니다. 현재 조건이 저장된 계산 조건과 다르면 안내를 보류하고, 기존 처리 흐름에서 새 경로와 새 안내를 만듭니다.

|---|---|---|
| 최종 이동 회귀 시험 | 통과 | 815/815 = 100% |
| 포함 관련 조건 | 통과 | 34/34 = 100% |
| 신규 로컬 개발 DB 연결 | 통과 | 2/2 = 100% |

생성 시각: 2026-10-09T05:25:41.116427+09:00. 분모는 이 판으로 실행한 시험 조건 수입니다. 관련34건·신규DB2건은 회귀815건의 부분집합이며 합산하지 않습니다. 제품 전체 준비율이나 독립 경로 정확도를 뜻하지 않습니다. 수정 전 소스17개·자료4개가 직전 증거와 일치했고, 최초 출판 시 회귀 시작과 변경대상12개 해시가 일치했습니다. 이후 시각화의 옛 미완료 문구2개만 고쳤으며 제품·시험11개 해시는 그대로입니다.

## 원인과 변경

기존 출발 관측은 장소 좌표와 자료 판을 검사했지만 저장 당시 인원·휴식·첫 방문 조건을 그대로 썼습니다. 안내 생성과 감시에 최신 여행 정보를 전달하고, 이동 팀에서 경로 생성과 같은 party_of로 정규화해 저장 조건과 비교합니다. 인원·mobility_ease='needs_rest'·설문 domestic·first_visit가 지원 입력입니다. foreign은 기존 기록 입력이며 이번에 외국인이라는 이유의 경로 비용을 만들지 않았습니다.

조건이 바뀌면 needs_replan을 반환해 출발 안내를 보류합니다. 현재 버스 도착 콜백보다 먼저 대조하지만, 상위 흐름의 다른 경로 사건 조회까지 전부 생략한다고 주장하지 않습니다. 예산·결제 정보 등 계산과 무관한 값만 바뀌면 불필요한 재탐색을 하지 않습니다. 공개 경로·코어 계약과 거리·시간·요금 상수는 바꾸지 않았습니다.

현재 정보가 잘못된 형태이면 명시적 실패로 전달합니다. 비어 있는 목록을 빈 조건 사전으로 바꿔 숨기지 않도록 정규화 검사를 보강했고 수정 직전 사본을 보존했습니다. 저수준 호환 호출은 trip을 생략할 수 있지만 party_check='current_trip_not_supplied'로 남기며 현재 동행 확인 완료로 부르지 않습니다. 운영 안내·감시는 최신 trip을 항상 전달합니다. 자유문장 '아이/휠체어'를 접근성 플래그로 추정하지 않습니다.

## 재현·검증 범위

수정 전 실제 로컬 개발 DB의 인원 변경/휴식 변경2/2조건에서 안내가 보류되지 않고 이전 조건 안내가 저장돼 시험이 실패했습니다. 수정 후 같은2/2조건에서 안내 보류→사건 처리(Case)1건→최신 조건 경로 계산→일정 판2에서3으로 변경→새 문맥→변경 안내1건과 새 출발 안내1건을 확인했습니다. 각 조건에서 감시를 총10회 호출했고 추가 Case가 열리지 않았습니다. 실제 외부 메시지는 보내지 않았습니다.

이 DB 시험은 격리된 시험 여행의 메타데이터를 SQL로 바꾸고, 보행 경로를 통제된300m 입력으로 공급한 통합 시험입니다. 운영 설정 API나 고객 화면에서 인원을 바꾸는 작업, 실제 보행·탑승·현재 위치를 확인한 시험이 아닙니다. 안내 계산 뒤 조건이 또 바뀌는 동시성은 이2조건의 검증 범위가 아닙니다. 직전 판의 일정 버전 잠금 검증을 조건 쓰기 API 검증으로 대신하지 않습니다.

신규 단위15/15는 버스/도보 각각 정상·인원·휴식·첫 방문·무관한 예산 변경10조건, 잘못된 현재 입력4조건, trip 없는 호환 호출1조건입니다. 변경 조건에서 현재 버스 도착 콜백을 호출하지 않았고 저장 문맥이 바뀌지 않았습니다. 기존 DB/조립 시험4파일의 고정 입력은 현재 여행과 저장 문맥의 첫 방문·인원 기본값을 맞추고 최신 trip 전달을 검사하도록 고쳤습니다. 해당 고정 입력 정리는 실제 운행 성능 개선으로 세지 않습니다.

## 논문 확인과 적용 전제

[IJCAI2025 동적 대중교통 재계획 논문](https://www.ijcai.org/proceedings/2025/937)의 공식 초록은 실시간 지연에 따라 여정을 조정하는 문제를 다룹니다. 현재 위치를 알지 못하면서 실제 출발지로 간주하지 않는 전제는 계속 유지합니다. 이번 변경은 논문의 새 알고리즘을 이식한 것이 아닙니다.

[AGILE2026 보행·환승 제약 연구](https://agile-giss.copernicus.org/articles/7/3/2026/)의 공식 초록을 확인했습니다. 보행·자전거 거리와 환승 횟수 제약이 달라지면 가능한 경로도 달라진다는 점이 최신 입력 대조의 근거입니다. 이는 비엔나의 합성 OD 연구이며 서울 수치, 임상 휴식 기준, 휠체어 접근성 또는 현재 코드 임계값의 적정성을 입증하지 않습니다. 논문 초록 확인과 본문 전체 검토를 구분해 연구 기록에 적었습니다.

외부 Codex CLI 독립 검토는 앞선 자동 승인 검토가 내부 설계 전송의 구체적 승인 부족으로 거절했습니다. 사용자 답이 아직 없어 재시도·우회하지 않았고 로컬 시험을 독립 검토로 부르지 않습니다.
