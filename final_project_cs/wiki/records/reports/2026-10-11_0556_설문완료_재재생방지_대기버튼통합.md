# 완료 계획 확인 재재생 방지와 대기 버튼 통합

완료된 계획에서 질문을 닫을 때 진행 애니메이션이 다시 시작되는 문제를 수정했다. 대기 창은 「계속 답하기」 하나로 합쳐 자동 넘김을 멈추도록 바꿨다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 변경 전 브라우저 재현 | 재현 | 2/2 = 100% |
| 관련 브라우저 고유 시험 | 통과 | 28/28 = 100% |
| 내부 재생 동작 시험 | 통과 | 14/14 = 100% |
| 타입·문법·제품 빌드 | 통과 | 3/3 = 100% |

## 동작과 원인

- 질문 화면은 최신 완료 결과를 표시했으나, 내부 재생 상태는 질문이 시작된 단계에 정지해 있었다. 질문을 닫으면 그 단계부터 다시 시작했다.
- 완료된 결과를 붙잡던 질문 화면을 닫는 렌더에서 전체 완료 결과로 맞춘다. 수동 확인, 5초 자동 이동, 무응답 경고 만료가 같은 동작을 사용한다. 미완료 결과의 진행 표시와 최초 읽기 속도는 유지한다.
- 대기 창의 「계속 답하기」와 Esc는 자동 넘김을 중지한다. 중복된 보조 버튼을 제거했다. 초점 순환·복원, 저장한 답변, 직접 계획 확인 동작을 유지한다.
- 읽기 완료 직후의 별도 5초 안내는 기존 정책대로 유지한다. 이 안내에는 계속 답하기 버튼이 없으므로 「자동으로 넘어가지 않기」를 그대로 둔다.

## 시험 범위와 결과

Chrome 375px·1280px에서 신규10개를 시험했다. 수동 이동, 5초 자동 이동, 무응답 경고 만료, 계속 답하기와 Esc 이후61초 대기·답변 유지·초점 복원이다. 실제 DOM 변경을 관찰하여 질문을 닫은 첫 프레임부터 `data-stage=done`만 나타나는지 검사한다. 최종 결과만 보는 기존 시험의 사각지대를 보완했다.

수정 전 신규 수동 시험2/2에서 `received → reading → done` 재재생을 검출했다. 수정 뒤 첫 실행은 기존18개와 신규6개가 통과했다. 나머지4개는 답변하지 않고 질문만 넘긴 시험 데이터가 완료 시 첫 미답 질문으로 돌아오는 기존 동작을 잘못 기대하여 실패했다. 실제 답변을 저장하는 데이터로 보완한 뒤 같은 제품 빌드에서 신규10/10이 통과했다. 고유 시험 분모28은 기존18 + 신규10이며, 중복 재실행을 합산하지 않는다.

단위 시험은 완료 대기 해제 즉시 결과 표시, 미완료 진행 재개, 일반 진행 속도·수정 결과 유지·애니메이션 건너뛰기 등을 포함한다. 추가 상태 조정으로 생기는 폐기 렌더를 React처럼 처리하도록 시험 장치의 effect 의존성 저장 시점을 커밋 시점으로 고쳤다. 이 보완 전13/14, 보완 뒤14/14이다. 실제 브라우저에서도 동일한 동작을 확인했다.

촬영 재실행의 첫 회는3/4 통과했다. 가상 시계를61초 한 번에 진행하면서 별도 서비스 공지 조회가 실제 mock 응답 도착 전에 시간 초과되어 결과 이동 버튼을 가렸다. 자동 넘김 중지·답변 유지 검사는 이미 통과한 상태였다. 가상 시간을1초씩 진행하고 응답 시간을 확보하도록 시험만 보완했다. [첫 촬영 기록](../evidence/2026-10-11_survey-release/capture-first.json)을 보존했다.
