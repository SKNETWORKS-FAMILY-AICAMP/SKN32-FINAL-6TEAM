# 자료 재생성의 9호선 급행 삭제 재발 방지

줄인 자료를 다시 만들 때 9호선 급행이 기본으로 삭제되던 생성 옵션을 고쳤습니다. 복원한 급행이 다음 재생성에서 다시 사라지는 원인을 막았습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 급행 삭제 기본값 수정 | 완료 | 1/1 = 100% |
| 새 최소 CLI·제품 조회 시험 | 통과 | 5/5 = 100% |
| 확인한 공개자료 해시 불변 | 일치 | 3/3 = 100% |
| 실제 혼잡 일치율 | 이번 미측정 | 분모 미정 |

## 원인과 수정

생성 스크립트는 과거 일반 운행만 읽던 소비자 조건을 그대로 유지해 `drop_express=True`를 기본값으로 사용했습니다. 지금 제품은 9호선 일반·급행을 나눠 조회하므로 해당 기본값이 계속 급행 근거를 없앴습니다.

기본값을 `False`로 바꾸고 스크립트 안내와 도움말을 일반·급행 보존으로 정정했습니다. 기존 `--keep-express`는 같은 보존 동작을 명시하는 호환 옵션입니다. 명시적인 `--drop-express`는 과거 결과 비교용으로 유지하되 제품 자료 생성용이 아님을 도움말에 표시했습니다. 압축과 출발 없는 시간표 행 관련 기본값은 이번에 바꾸지 않았습니다.

## 최소 재생 검증

각 시험은 새 빈 임시 원본·출력 폴더를 만들고 최소 시간표 1행과 같은 역·시각의 일반/급행 혼잡 2행만 넣어 CLI를 실행했습니다. 실제 공개자료를 재생성하거나 `--clean`을 실행하지 않았습니다. 표준 라이브러리만 쓰는 `-S` 실행으로 선택적인 환경 파일 로딩도 하지 않습니다.

| 시험 | 확인한 동작 |
|---|---|
| 기본 CLI | 일반·급행 2행 보존, 명세의 삭제 옵션 false·삭제 0행 |
| 호환 보존 옵션 | 동일 2행, 원본·출력 SHA256과 명세 일치 |
| 명시적 진단 삭제 옵션 | 일반 1행, 삭제 옵션 true·급행 삭제 1행 |
| 생성물→제품 혼잡 조회 | 일반 20%와 급행 120%를 서로 구분; 운행 미지정은 임의 대체하지 않음 |
| 기존 출력이 있는 폴더 | 덮어쓰지 않고 종료 코드 2, 기존 파일 유지 |

혼잡 20%/120%는 소비 경로 구분을 검증하는 통제 입력이며 실제 관측값이 아닙니다. 변경 전은 3개 통과·2개 실패, 변경 후는 5개 모두 통과(1.89초)입니다. 새 시험은 실제 JSONL을 생성해 `Congestion.load`로 읽으며, 생성 함수만 직접 불러 성공으로 끝내지 않았습니다.

실행 전후 실제 공개자료 중 `congestion_line9_v1.jsonl`, `congestion_v1.jsonl`, `timetable_v1.jsonl.gz` 3개 SHA256을 비교해 모두 같았습니다. 그 밖의 모든 파일 불변까지 확대해서 주장하지 않습니다. 임시 원본 입력도 각 CLI 전후 해시가 같은지 시험했습니다.
