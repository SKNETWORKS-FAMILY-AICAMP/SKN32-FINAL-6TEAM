## 실제 화면과 개발 기록

[실제 스크린샷 비교 HTML](../../../frontend/apps/web/mockups/merged-ui-actual-2026-10-08-v1/index.html)은 메뉴 전후·여행 화면 전후·개발 기록 원문·설정과 키보드 및 화면 크기의 4개 탭이다.

앱 이미지는 병합 전 빌드와 병합 후 빌드를 Chrome에서 실행한 실제 스크린샷이다. 같은 여행·한국어·그린 테마·항로 지킴이 켬·로그인 제공자 꺼짐 조건으로 비교했다. 1100×1000 전후 4장과 병합 후 375px·1280px 여행/메뉴 4장, 총 8장이다. 넓은 화면의 휴대폰 틀이 유지되며 375px·1280px에서 페이지 가로 넘침을 검사했다.

지도 바탕의 붉은색은 mock 서버의 시험용 단색 타일이다. 실제 지도 제공자의 지도 이미지는 조회하지 않았다. 앱의 핀·메뉴·일정·채팅은 실제 구현이다. 비교 페이지에서는 바깥 여백만 CSS로 잘라 표시하고, 클릭하면 수정하지 않은 전체 PNG를 연다.

개발 기록은 앱 화면이 아니라 작업 내역 문서다. 충돌은 같은 위치에 우리 쪽의 계획 확인 개선 기록과 UI 담당의 등록 후 여행 개선 기록을 덧붙인 데서 생겼다. 비교 탭에는 양쪽 문서의 실제 충돌 부분(우리 488–544행, UI 담당 488–529행)을 표시했다. 개인 기계 접속 이름만 가렸다. 원문 비교 화면의 브라우저 캡처는 [개발 기록 비교 이미지](../../../frontend/apps/web/mockups/merged-ui-actual-2026-10-08-v1/comparison-records.png)다. 앱 스크린샷과 문서 표시 캡처는 구분했다.

기존 [충돌 비교 목업](../../../frontend/apps/web/mockups/merge-conflicts-2026-10-08-v1/index.html)은 보존했다.

mock 서버 시험은 첫 실행 102통과·1실패였다. 실패 1개는 주요 화면 콘솔 오류 검사에서 `/v1/web/legal/retention`이 404를 반환한 것이었다. 기존 시험은 동의·경로선·신호를 지원하는 mock 조건만 켜고 새 보관 설정 응답은 켜지 않았다. 동일 검사에 `retention: "on"` 조건을 추가한 후 해당 1개를 다시 실행하여 통과했다. 앱 코드를 바꿔 오류를 숨기거나 콘솔 검사를 완화하지 않았다. 최종 103/103은 첫 실행의 통과 102개와 원인 수정 후 재확인 1개의 합이며 전체 103개를 두 번째로 다시 실행했다는 뜻은 아니다.

등록 여행 메뉴의 키보드 시험은 로그인 제공자 꺼짐·항로 지킴이 켬 조건이다. 마이페이지→여행 목록→취향 설문→언어→그린→화이트→애니메이션 건너뛰기→항로 지킴이→닫기의 9개 항목을 지나 처음으로 돌아왔다. 역순 이동, Esc 닫기, 메뉴 단추 초점 복귀도 확인했다. 메뉴 동작은 실제 표시된 요소를 찾아 이동하므로 로그인 연결 줄처럼 조건부 항목을 고정 개수에 억지로 맞추지 않는다. Tab은 초점을 이동시키고 링크 활성화가 화면을 바꾼다.

실서버 확인(서버 응답): **안 했음** — 이번 작업은 로컬 mock 서버 조건으로 확인했다. UI 담당 원문 안의 이전 실서버 확인 기록은 이번 실행 결과에 합치지 않았다.

## 백업

덮어쓰기 직전에 기존 파일을 [병합 전 백업 폴더](../../../frontend/apps/web/_backup/2026-10-08_사용자결정_화면병합전/)에 복사했다. [manifest.json](../../../frontend/apps/web/_backup/2026-10-08_사용자결정_화면병합전/manifest.json)은 가져온 경로와 결합 분류를 기록한다. `.ts`·`.tsx` 백업은 TypeScript가 다시 검사하지 않도록 `.bak` 접미사를 붙였으며 내용은 보존했다. 검사 조건 수정 전 여행 시험과 캡처 뒤 tsconfig도 별도로 보존했다.

이 보고서와 비교 HTML은 새 이름으로 만들었다. 기존 HTML·이미지를 교체하지 않았다.
