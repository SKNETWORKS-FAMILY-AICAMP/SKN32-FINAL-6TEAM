## 2. 「파인튜닝 계획서」라는 말이 맞나 — 정확한 용어

**답: 「파인튜닝 계획서」가 하나의 표준 문서 이름으로 정해져 있지는 않습니다.** 현업에서는 목적별로 서로 다른 문서를 둡니다. 이번 검색에서 「파인튜닝 계획서 표준 양식」은 찾지 못했습니다(검색 도구가 못 찾은 것이지 없다는 뜻은 아닙니다). 아래 이름은 학계 · 현업에서 실제로 쓰는 것을 모은 것입니다.

| 필요한 문서 | 영어 이름 | 무엇을 적나 | 근거 |
|---|---|---|---|
| 학습 계획서 (우리가 말하는 것) | fine-tuning plan / experiment plan / training recipe | 목적, 비교 대상, 성공 기준, 데이터, 학습 설정, 평가, 채택 기준 | 표준 양식 없음. 아래 두 문서 + 평가 계획서의 항목을 합쳐 쓰는 것이 관행 [추정] |
| **데이터 명세서** | Datasheet for Dataset / Data Card | 만든 동기, 구성, 수집 방법, 라벨링, 추천 용도, 배포, 유지 | Gebru 외 「Datasheets for Datasets」 [외부-초록](https://arxiv.org/abs/1803.09010) |
| **모델 카드** | Model Card | 의도한 용도, 조건별 성능, 평가 방법, 한계 | Mitchell 외 FAT* 2019 [외부-초록](https://arxiv.org/abs/1810.03993) |
| **평가 계획서** | Evaluation plan / eval spec | 시험 세트 구성, 지표, 분모, 판정 방식, 통계 | 「평가 세트를 일찍 만들어 두라」: OpenAI 파인튜닝 모범 사례 [외부-공식문서](https://developers.openai.com/api/docs/guides/fine-tuning-best-practices) |
| **라벨링 지침서** | Annotation guideline | 정답을 어떻게 다는지, 애매한 경우 규칙 | 지침 있는 라벨링이 일치도가 높다는 보고는 검색 요약만 봄 [외부-검색요약] |
| **골든셋** | Golden dataset / gold set | 사람이 정답을 단, 학습에 쓰지 않고 지키는 시험 세트 | 업계 용어. 가이드는 벤더 블로그 수준 [외부-검색요약](https://www.getmaxim.ai/articles/building-a-golden-dataset-for-ai-evaluation-a-step-by-step-guide/) |

참고: 데이터 품질 국제 표준으로 **ISO/IEC 5259 시리즈(분석 · 머신러닝용 데이터 품질)** 가 있고, 2부(2024)가 품질 모델과 정확성 · 완전성 · 일관성 · 적시성 · 대표성 같은 측정 항목을 정의한다고 합니다. 벤더 · 재판매 페이지 요약만 봤고 표준 본문은 확인하지 못했습니다. [외부-검색요약](https://www.managementsolutions.com/en/node/4456) 우리 프로젝트에 필요한지는 따로 판단이 필요합니다.

**권장 이름:** 이 프로젝트에서는 문서를 **「학습 계획서」 + 「데이터 명세서」 + 「평가 계획서」(골든셋 구성 포함) + 「모델 카드」** 네 개로 나누는 것을 권합니다. [추정] 한 문서에 다 넣으면 계획서가 길어지고 평가 세트 규칙이 묻힙니다.

## 3. 표준 방법 — 단계별 근거

```mermaid
flowchart TD
 S([시작: 파인튜닝이 필요한가?]) --> A{프롬프트 · 검색(RAG) 으로 안 되나?}
 A -- 해결됨 --> E1([끝: 파인튜닝 안 함])
 A -- 안 됨: 형식 · 판단 행동 문제 --> B[1 과제 정의: 입력 · 출력 · 「없음」 정의]
 B --> C[2 평가 세트 먼저: 사람 정답 골든셋 동결]
 C --> D[3 기준선 측정: 학습 없는 모델 · 프롬프트만]
 D --> F[4 학습 자료: 실제 데이터 우선 · 품질 검수 · 중복 제거]
 F --> G[5 학습: 작게 시작 · 시드 반복]
 G --> H[6 평가: 기준선과 같은 조건 · 구간 · 회귀 확인]
 H --> I{기준 통과?}
 I -- 아니오 --> F
 I -- 예 --> J[7 기록: 데이터 명세서 · 모델 카드]
 J --> K([끝: 채택 판단 — 별도 결정])
```

| 단계 | 표준에 가까운 권고 | 출처 · 확인 범위 |
|---|---|---|
| 0 파인튜닝이 맞는 일인가 | 파인튜닝은 **출력 형식 · 어휘 · 판단 습관**을 가르치는 데 쓰고, **새 사실 지식을 넣는 데는 약하다.** 사실은 검색(RAG)이 낫다. | LIMA(1,000개 정제 자료만으로 형식 학습, 지식은 사전학습에서 옴) [외부-초록](https://arxiv.org/abs/2305.11206) · Ovadia 외: 지식 주입은 RAG 가 일관되게 우세 [외부-초록](https://arxiv.org/abs/2312.05934) |
| 1 과제 정의 · 「범위 밖」 | 「어디에도 해당 없음」 질문이 가장 어렵다. 분류기는 범위 안 분류는 잘하지만 **범위 밖을 못 가린다.** | CLINC150(150개 의도 + 범위 밖 질의, EMNLP 2019) [외부-초록](https://arxiv.org/abs/1909.02027) |
| 2 평가 세트 먼저 | 평가 세트(test)를 **일찍** 따로 만들고 학습에 쓰지 않는다. | OpenAI 파인튜닝 모범 사례 [외부-공식문서](https://developers.openai.com/api/docs/guides/fine-tuning-best-practices) · Tulu 3: 개발용 · 보지 않은 평가용을 나누고 평가 데이터와 겹치는 학습 자료를 제거 [외부-초록](https://arxiv.org/abs/2411.15124) |
| 2′ 정답이 틀리면 시험이 틀린다 | 유명 시험 세트 10개에서도 라벨 오류가 평균 3.3% 이상이고, 오류 때문에 **모델 순위가 바뀔 수 있다.** | Northcutt 외, NeurIPS 2021 [외부-초록](https://arxiv.org/abs/2103.14749) |
| 3 기준선 | 학습 모델은 **학습 없는 모델 · 프롬프트만 쓴 큰 모델**과 같은 시험 · 같은 조건에서 견준다. | 평가 정본에도 같은 취지가 있음 [실측-저장소](C:\Users\playdata2\Documents\final_workspace\final_project_cs\wiki\quality\slm-model-evaluation.md) |
| 4 학습 자료: 품질 > 양 | 적고 정제된 자료가 많고 거친 자료보다 낫다. 품질을 올린 뒤에 양을 늘리고, 효과는 「전체 vs 절반」으로 가늠한다. | LIMA · OpenAI 모범 사례 |
| 4′ 응답 종류 비율 | **학습 자료의 거절 · 「없음」 비율이 실제 사용 분포와 같아야 한다.** 거절을 너무 많이 가르치면 실제로도 거절을 너무 많이 한다. 같은 정답 기준으로 일관되게 라벨링한다. | OpenAI 모범 사례 [외부-공식문서] |
| 4″ AI가 단 라벨의 위험 | AI 라벨로 학습한 분류기는 사람 정답 학습보다 **정확도가 낮고 불안정하며 일찍 정체**한다. 오류가 무작위가 아니라 체계적이라 그대로 전달된다. 필터링 · 앙상블로 일부만 완화. | Lu · Smith 2025 [외부-초록](https://arxiv.org/abs/2504.15432) |
| 4‴ 합성 데이터 | 합성으로 시작하는 것은 괜찮지만 실제 데이터를 **대체하지 않고 보충**한다. 합성 자료는 만든 모델 · 설정을 기록해 문제 묶음을 골라낼 수 있게 한다. | Husain(평가 글: 합성은 실제 로그의 보충) [외부-블로그](https://hamel.dev/blog/posts/evals/) · 출처 기록 권고는 실무자 글 [외부-검색요약](https://tianpan.co/blog/2026/04/09/synthetic-training-data-quality-collapse) |
| 4⁗ 중복 · 오염 | 학습과 시험의 겹침이 시험 점수를 부풀린다. 표준 데이터셋의 검증 세트 4% 이상이 학습과 겹친 사례. 학습 전에 중복 제거. | Lee 외, ACL 2022 [외부-초록](https://arxiv.org/abs/2107.06499) · 오염 개요 [외부-초록](https://arxiv.org/abs/2406.04244) |

## 4. 지금까지 우리가 한 파인튜닝은 어떤 의미인가

(모든 수치는 저장소 보고서의 값이며 [실측-저장소], 제가 다시 잰 것이 아닙니다.)

| 한 일 | 무엇이 확인됐나 | 한계 | 표준에 비춘 의미 |
|---|---|---|---|
| **과제 선택** — 일정 항목 짚기(번호 또는 「없음」) | 형식과 판단 습관을 가르치는 과제 | — | 표준이 파인튜닝에 권하는 종류의 일입니다(0단계). 지식을 넣는 시도가 아님. |
| **Saluki 27B 어댑터** (자료 2,613행, 1회전) | 같은 360문항(D3)에서 잡담 오답 16/240 = 6.7% → 0/240 = 0%, 정상 요청 정답 105/120 = 87.5% → 102/120 = 85.0% | 1회 실행 · 시드 반복 없음 · 독립 보류 세트 없음 · 학습 손실이 0.0006까지 내려가 **자료를 외웠을 가능성**을 보고서도 인정 | 「잡담을 덜 짚는다」는 **방향**은 보였지만 일반화는 증명되지 않았습니다. |
| **학습 E4B · 학습 Winnow-E4B** (Jev 계열 모델 중 Winnow-E4B 를 우리 여행 자료로 가르침) vs 학습 없는 모델 | 판정용 90문제: 학습 E4B 86/90, 학습 Winnow 84/90, **학습 없는 Gemma 26B 87/90**, 학습 없는 12B 83/90. 짝 검정에서 모두 구분 안 됨(p=0.38~1.00) | 질문 90개는 Codex 작성, 일정은 가상 1개, 사람이 쓴 채팅으로는 안 잼 | **정확도 이득은 입증되지 않았습니다.** 입증에 가까운 것은 크기 · 속도(작은 모델이 큰 모델과 구분 안 되는 정확도) — 단, 실행기가 달라 속도는 같은 조건 비교가 아님. |
| **학습 분류기 kf-deberta** | 제품 모델보다 못하거나(72건) 구분 안 됨(24건) → 연결 안 하기로 함 | 학습 자료가 소비자원 민원 제목 6,067 + 합성 875, **라벨은 gemma4:12b 가 붙임**, 한쪽으로 심하게 치우침 | AI 라벨 학습의 위험(Lu · Smith)과 같은 양상입니다. 연결하지 않은 결정은 타당합니다. |

### 계산: 90문제 시험이 구분해 주는 것 [계산]

- 86/90 의 95% 구간(윌슨 방식)은 **89.1~98.3%**, 87/90 은 **90.7~98.9%**입니다. 겹치는 폭이 매우 커서 「86 vs 87」은 사실상 같은 값입니다. 이 시험으로 학습의 효과를 판정할 수는 없습니다.
- 「오지목 ≤ 2%」를 증명하려면: 없음 질문이 n개이고 틀린 것이 0건일 때 95% 상한은 대략 3/n 입니다(rule of three). n=150 이면 2.0%, n=480 이면 0.62%입니다. 계획서의 「없음 480개」 목표는 이 계산과 맞습니다.

### 종합 의미

1. **방향은 맞았습니다.** 좁은 판단 과제를 작은 모델에 가르치는 것은 표준에 맞고, 잡담 오지목을 줄이는 효과의 신호도 있습니다.
2. **하지만 「잘 됐다」고 말할 근거는 아직 없습니다.** 정답도 AI가 달고(라벨 AI), 시험도 AI가 쓰고(Codex), 같은 계열 모델이 채점하는 구조라 AI끼리 닫힌 고리입니다. 사람 정답이 한 번도 들어가지 않았습니다.
3. **학습 자료를 더 쌓는 일은 지금 병목이 아닙니다.** 병목은 **사람 정답이 달린 시험 세트**입니다. 그것이 없으면 자료를 늘려도 좋아졌는지 알 수 없습니다.
