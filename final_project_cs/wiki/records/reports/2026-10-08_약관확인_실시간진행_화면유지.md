# 약관 확인: 기존 화면 유지와 실제 진행 표시

약관 확인 중 앱 전체를 문장 하나로 바꾸던 처리를 수정했다. 기존 동의로 이미 열린 화면은 유지하고 그 위에 진행 카드를 표시한다. 동의 사본이 없는 첫 방문은 같은 휴대폰 화면 틀을 먼저 보여 주며, 동의 확인 전 보호 API를 호출하지 않는다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 화면 유지·실제 단계 표시 | 완료 | 1/1 = 100% |
| mock 서버 화면 시험 | 통과 | 39/39 = 100% |
| 로컬 개발 DB 통합·계약 시험 | 통과 | 33/33 = 100% |
| 약관·SSE 단위 시험 | 통과 | 35/35 = 100% |

## 화면 동작

- 최신 약관 읽기 → 로그인 상태 확인 → 동의 기록 읽기 → 약관 버전 확인 → 필수 항목 확인 → 이 브라우저에 반영. 앞서 실제로 끝난 단계 수만 표시하며 시간이 지났다는 이유로 완료 수를 올리지 않는다.
- 100ms 이내 확인은 카드를 띄우지 않는다. 길어지면 현재 항목, 완료 수, 실제 경과 초를 표시한다. 응답 지연과 연결 끊김은 기존 SSE 상태를 따라간다. 확인이 끝나면 카드가 사라진다.
- 조회 실패를 미동의로 취급하지 않는다. 현재 경로에서 오류 안내와 다시 확인 단추를 제공한다. 새 약관 버전은 같은 자리에 새로 고침을 안내한다.
- 사용자 선택에 따른 UI 담당안의 휴대폰 화면 틀, 새 여행 화면, 항로 지킴이 메뉴는 유지한다.

## API 계약

[GET 동의 기록](../../external/rest-endpoints.md)은 `Accept: text/event-stream`이면 기존 live_progress 실행기를 사용한다. DB 기록 읽기 직전 `consent_records`, 약관 버전 읽기 직전 `consent_version`, 필수 항목 평가 직전 `consent_required`를 내보낸다. 생존 신호, 최종 결과와 안전한 오류 응답을 함께 사용한다. 기존 JSON 응답 형태는 유지한다. 세션 인증은 스트림을 열기 전에 검사한다.

실시간 조회 상한은 기존 공용 상한을 쓰고, 약관 확인의 최대 실행 시간은 가드레일의 60초로 정했다. 시간은 설계값이며 측정된 평균 응답 시간이라는 뜻이 아니다. 순수 읽기이므로 쓰기 기능의 중복 실행은 추가하지 않는다.

## 검증 범위와 근거

mock 서버 시험 39/39 (화면 반응): 동의·메뉴·프로필·세션 화면. 새 시험은 느린 SSE에서 단계 2/6 → 3/6 → 4/6과 화면 유지, 새 창 없이 같은 경로 유지, 동의 확인 전 보호 조회 금지, 조회 오류 후 같은 자리 재시도를 확인한다. 기존 필수 동의 철회·옛 API 호환·메뉴 Tab 이동·로그아웃도 재확인했다.

실서버 확인 (서버 응답): 안 했음. x600 서버의 cs 프로젝트 서버를 직접 호출하거나 배포하지 않았다. 별도로 실제 로컬 개발 DB를 사용하는 TestClient 통합 시험과 웹 계약 시험은 33/33 통과했다. SSE의 단계 순서·JSON과 결과 일치·미인증 거절·동시 조회 제한·응답 지연 생존 신호·오류 내용 보호를 검증했다.

약관 동기화·실시간 연결·약관 내용·약관 해시 단위 시험 35/35. 최종 타입 검사와 수정 파일 ESLint 통과. 실제 화면 빌드 성공. 관련 실행 로그는 작업용 임시 폴더에 보관했다.

추가로 재검사 중 공용 설정에 새 이동 설정의 잘못된 들여쓰기가 생긴 것을 확인했다. 현재 파일을 백업하고 새 설정값을 보존하면서 들여쓰기만 바로잡았으며, 전체 33건을 다시 실행해 통과했다. 공개 공지의 mock 응답은 인증 전에 제공되도록 기존 응답 위치를 옮겨 실제 공개 API의 방식과 맞췄다.
