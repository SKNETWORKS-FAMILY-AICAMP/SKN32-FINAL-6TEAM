# 급행 입력의 출발 안내 저장 전후 판 대조 검증

출발 관측 뒤 급행표가 바뀌면 이전 안내의 저장 거래를 되돌리도록 고쳤습니다. 삽입 전후 두 검사로 늦은 변경과 읽기 실패를 감지했으며 마지막 검사 이후 외부 작성자 변경까지 원자적으로 막았다는 뜻은 아닙니다.

## 원인과 수정

출발 관측은 급행 내용 판을 비교하지만, 안내 저장은 여행 인원·조건·일정 판·현재 이동 항목만 검사했습니다. 실제 임시 gzip 표를 관측 후 바꾸는 조건과 안내 INSERT 후 확정 전에 바꾸는 조건 모두 수정 전에는 이전 안내가 저장되어 두 시험이 실패했습니다. [최초 재현](../evidence/2026-10-09_0704_급행안내_저장대조/express-notice-race-before-v1.log), 같은 이름의 XML. 최초 콘솔 로그의 일부 주석은 기본 문자 인코딩으로 깨졌으므로 UTF-8 XML과 실제 AssertionError 판정을 함께 보존했습니다. 이후 실행은 UTF-8로 고정했습니다.

조립한 관측 함수에 validate_basis 검사를 연결했습니다. 관측의 basis(계산 입력 판)를 별도 복사하고 출발 안내 INSERT 전·후 같은 DB 거래가 확정되기 전에 대조합니다. 내용 판이 다르면 StaleDeparture로 거래를 되돌려 outbox에 안내 행을 남기지 않으며, 다음 감시의 기존 급행 판 불일치 판정과 Case 재계산 흐름에 맡깁니다. 읽기 실패·잘못된 응답은 fatal로 드러내고 저장을 취소합니다. 예외 원문을 안내·결과에 싣지 않습니다.

검사는 급행 파일 내용만 다시 읽습니다. 도착 API를 재조회하거나 거래 안에서 전체 시간표를 적재하지 않습니다. 계산 문맥을 만들 때와 같은 SHA-256 식별 함수를 사용하고 노선·부재 상태를 포함합니다. 같은 바이트의 수정 시각 변경은 불필요하게 취소하지 않습니다. 검사에 넘기는 입력도 매번 복사해 검사 콜백이나 삽입 과정의 payload 변경으로 최초 관측 판이 바뀌지 않게 했습니다.

기다림 문구·하루 안내는 출발 경로 판 검사 대상이 아니며 기존 동작을 유지합니다. 관측 기능이 꺼진 경로·기존 단순 시험 콜백·급행 추적 없는 수동 Runtime은 기존 호환 계약입니다. 제품 조립은 검사 함수를 항상 연결합니다. 이 호환 경로를 현재 급행 자료 검증 성공으로 세지는 않습니다.

## 검사 비용과 남은 경합

기존 두 급행 파일 합계 640,617바이트에서 파일 캐시 준비 후 두 연속 검사30회 평균±표준편차 13.995±1.446ms, 중간값 13.366ms, 최대 20.663ms입니다. [30회 원값](../evidence/2026-10-09_0704_급행안내_저장대조/two-check-cost-v1.json)·[측정 실행기](../evidence/2026-10-09_0704_급행안내_저장대조/cost-runner-v1.txt). 같은 파일의 검사만 잰 값이고 DB 거래·HTTP 지연·최초 적재·혼잡 때의 지연 또는 이전 판과의 A/B 개선율이 아닙니다. 행 잠금을 가진 거래를 파일 읽기 동안 유지하는 비용이 남습니다.

마지막 검사~COMMIT 사이 외부 작성자 변경은 여전히 가능합니다. A→B→A처럼 두 검사 사이 바뀌었다가 원래 내용으로 돌아오면 관측하지 못할 수 있습니다. 확정 뒤 자료 변경·이미 배달한 안내 회수도 이 검사에서 보장하지 않습니다. 이 범위에는 자료 작성과 안내 확정이 공통 세대/게시 절차를 공유하도록 하는 설계가 필요합니다. DB 격리 수준을 바꾸는 것만으로 외부 파일의 변경을 막을 수 있다는 판단은 하지 않습니다. 일반 시간표·다른 모델 입력의 최종 판 대조, 실제 현재 위치·탑승, 실시간 지하철·혼합 환승 운임·누락 경로·1.2km 안의 독립 웹 표본도 남았습니다.

## 공개 논문·공식 문서와 적용 전제

확인일2026-10-09. [Serializable Snapshot Isolation in PostgreSQL, Ports·Grittner, VLDB2012](https://arxiv.org/abs/1208.4179)의 초록과 [PostgreSQL16 거래 격리](https://www.postgresql.org/docs/16/transaction-iso.html)를 읽어 DB 거래의 직렬화 범위를 확인했습니다. [Psycopg 거래 관리](https://www.psycopg.org/psycopg3/docs/basic/transactions.html)는 거래 문맥이 예외로 종료되면 되돌리는 동작을 설명합니다. 우리는 이 동작을 로컬 개발 DB에서 직접 재현해 INSERT 후 예외의 롤백을 확인했습니다. 현재 설치 패키지의 실행 결과를 우선하며 문서의 개발판 표기와 같다고 가정하지 않습니다.

외부 급행 파일은 이 DB 거래의 쓰기 집합에 속하지 않습니다. 따라서 두 검사와 DB 롤백은 관측한 늦은 교체의 저장을 막는 보강이며, DB SSI만 켜면 파일~확정 전체가 원자화된다는 결론은 내리지 않습니다. 이는 자료 범위와 우리 저장 경로를 함께 본 설계 판단입니다. 이번에는 세대 게시 프로토콜이나 거래 격리 설정을 변경하지 않았고, 해당 논문 전체 실험을 재현하거나 오늘까지의 모든 논문을 전량 검토했다고 주장하지 않습니다.
