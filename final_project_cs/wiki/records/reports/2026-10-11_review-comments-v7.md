## 코드·산출물 대조

[실측] 아래 파일의 로컬 원문과 호출 경로를 읽었습니다. 확인 시각·SHA-256은 [대조 데이터](../../../../program/research/wiki_review_2026-10-11/review-comment-status-v7.json)에 있습니다.

- `composition.build_classifier`는 intent·issue_code·sentiment를 전달하며 `classify_case`가 기록합니다.
- `Controller.run_case`는 `TeamRegistry.resolve`로 등록 담당을 찾고 실행 계약으로 호출합니다. 분류 모델 자체가 아닙니다. 실패 시 재배분 모델 경로는 있지만 현재 확인한 출력은 한 담당 재선택입니다.
- `trip_watch_cases._open_batch`는 Activity 라벨을 사용하고 `ItineraryWork.run_itinerary`에서 WatchBatch를 호출합니다. `WatchBatch.ORDER`와 정렬 경로는 활동·식당·이동의 고정 순서입니다.
- 확인한 멀티에이전트 플로우 v11와 구조도 v9는 오케스트레이터의 배정·검증 경계를 설명합니다. 사용자 성향별 다중 팀 실행 계획이 구현됐다는 증거로 일반화하지 않습니다. 원본 산출물을 오늘 사양으로 소급 수정하지 않았습니다.

따라서 “Activity가 다른 팀 전체를 조정하는 구조가 추천·확정”이라는 이전 제안을 철회했습니다. 사용자가 정한 분류 에이전트의 판단 책임을 목표 계약에 반영했고 현재 코드 차이를 남겼습니다. 이 경로 밖의 전체 동적 호출·원격 배포를 확인했다는 뜻은 아닙니다.

## 완료와 미완료

선택·용어·책임의 wiki 및 HTML 반영은 완료했습니다. 개인 AI OAuth의 인가·토큰·실제 클라이언트 연결, 분류 에이전트의 상황·성향 기반 다중 팀 처리 계획, 영업 상태 확인의 운영 설정·조회 연결·인수 검증은 구현 완료로 표시하지 않았습니다. v11은 보존하고 wiki·구현 검토가 끝난 뒤 v12를 새 안내서로 작성합니다.

v2의 브라우저 저장값이 새 확정 선택을 덮지 않게 했습니다. W04=B, W06=A, W07=A, W08=사용자 정정 C, W09=A를 고정하며 되돌리기는 미확정 항목에만 적용합니다. W11은 선택 경쟁에서 빼고 후속 판올림 지시로 표시합니다. 기존 문서 정정 완료 13개는 v6의 실제 결과로 v2 본문을 교체했습니다. 이미 반영한 작업을 미래 수정 계획처럼 다시 읽지 않게 했습니다. 이전 제안은 백업에 보존했습니다.
