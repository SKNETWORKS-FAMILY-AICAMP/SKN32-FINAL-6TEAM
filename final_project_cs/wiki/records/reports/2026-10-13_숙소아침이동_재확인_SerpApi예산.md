## 1. 아침 「숙소 → 첫 일정」 이동

| 무엇 | 어디 |
|---|---|
| 이동 항목에 `detail.from_stay` — 출발지는 「그날 묵는 숙소」(날짜로 찾는다 — 숙소를 바꾸면 항목 id 가 새로 생겨 id 로 가리키면 끊긴다) | `itinerary_checks.FROM_STAY` · `stay_on` · `origin_of` |
| 등록 때 묵는 날(체크인 다음 날 ~ 체크아웃 날)마다 이동 계산기로 「숙소 → 그날 첫 일정」을 만들어 그날 첫 일정 바로 앞에 넣는다. 출발 하한 06:00. 계산기가 없거나 길을 못 찾으면 넣지 않는다(이동 팀이 없어도 등록은 막지 않는다) | `itinerary_changes.with_stay_moves` · `trip_api._insert` |
| 출발지를 읽는 곳이 `from_stay` 를 따른다 — 장소 앞 일정(`place_before` → 경로 다시 짜기 · 감시 재경로) · 경로선 · 출발 재검증 | `itinerary_changes.place_before` · `route_shape.shapes_for_items` · `departure_revalidation` |
| 숙소를 바꾸면 그 숙소에서 출발하는 아침 이동도 새 숙소 기준으로 다시 만든다(순서상 옆이 아니어도) | `itinerary_changes.refresh_moves_around` |
| 웹 — 서버 항목에 `from_stay`, 그 이동의 출발을 그날 숙소로 잡고 「○○에서 출발」 띠 바로 아래 이동 줄로 그린다 | `trip_api._item_view` · 웹 `gateway.ts` · `trip-timeline.ts` |

## 2. 화면 고르기 앞 가격 재확인

- 공용 고르기(`pending.choose`)는 DB 를 잠근 채 돈다 — 바깥 검색은 **잠그기 전에** 부른다(`trip_api._stay_recheck` → `booking/offers/recheck.recheck_stay`).
- 마이리얼트립 후보: 상세 1회(키 없음). 구글 호텔 후보: SerpApi 상세 1회로 판매처 최저가끼리(숙소 팀과 같은 판매처 목록 — 시험이 대조).
- 객실이 없으면 409 `option_gone`(일정 그대로). 바뀌었으면 새 값으로 바꾸고 변경 알림 끝에 한 문장(같음 · 바뀜 · 목록 값과 예약 화면 값의 기준 차이 · 확인 못 함).

## 3. SerpApi 월 250회 예산

- 두 어댑터(`serpapi_hotels` · `serpapi_flights`)가 **같은 칸 이름 `serpapi`** 로 센다 — 전에는 이름이 달라 계정 하나의 한도를 둘이 따로 셀 수 있었다(응답에 찍는 출처 이름은 그대로).
- 설정 `rate_serpapi_per_month = 250` · `rate_serpapi_per_day = 8`(250 / 31). 가드레일 `travel.source_budget_sources` 에 `serpapi` — DB(`external_call_budget`)로 세어 프로세스 · 재시작을 건너 같은 줄. 월 · 일 중 하나라도 차면 부르지 않는다.
- 몰림 허용 `serpapi: 8` — 「바꿔 줘」 한 번이 목록 1 + 상세 최대 3 을 연달아 부른다(하루 합계는 DB 줄이 지킨다).
- SerpApi 의 「Your account has run out of searches」 응답이면 그 달 줄을 멈춘다(문구로 알아본다 — 상태 코드는 확인 안 함).
- `.env.apikeys`(로컬 · x600 서버)에 「무료 월 250회 · 상한 월 250 · 하루 8」 주석. 백업 — 로컬 `final_project_cs/_backup/2026-10-13_serpapi_comment/` · x600 서버 `.env.apikeys.bak_20261013_serpapi_comment`.
- ★하루 8회는 「바꿔 줘」(4) + 고를 때 재확인(1) 으로 대략 하루 한두 번이다. 늘리려면 `ACOP_RATE_SERPAPI_PER_DAY` — 월 250 은 넘지 않는다.
