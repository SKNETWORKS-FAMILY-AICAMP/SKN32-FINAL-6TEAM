# 두 번째 난수 설정의 학습률 대조 실험 예약

[실측] GPU 서버 B에 기존 학습률 대조 실험 뒤 실행할 두 본 학습을 예약했다. 반복 시드·편차 확인은 일일 연구의 기존 합격 조건이며 현재 비교는 한 난수 설정만 있어 한 번의 점수 차이와 안정적인 개선을 구분하기 어렵다. 기존 자료와 기반이 모두 준비된 두 작업을 추가해 준비 대기가 세 개 미만인 상태를 보완했다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 추가 본 학습 예약 | 완료 | 2/2 = 100% |
| 고정 코드·학습 자료 해시 | 통과 | 3/3 = 100% |
| 실행 문법 확인 | 통과 | 1/1 = 100% |
| 같은 예약 재호출의 중복 방지 | 통과 | 1/1 = 100% |
| 추가 본 학습 완료 | 대기 | 0/2 = 0% |

## 조건과 목적

Gemma-4-E4B-it에 우리 여행 자료의 두 번째 보강판으로 추가 학습하는 별도 실험이다. 기존 세 후보에 두 번째 자료를 일괄 적용하는 것이 아니다. 최초 실험은20261012 난수 설정으로 cosine→FINCH였고, 추가 실험은20261013으로 FINCH→cosine 순서를 미리 정했다. 자료 해시·학습 코드·최대 학습률5e-5·FINCH 기준2e-5/계수0.9·LoRA r16·2에폭·누적8을 고정했다. 기존 자료로 반복하므로 독립 보류 자료를 대신하지 못한다.

실행 순서를 바꿔 한 방식이 항상 먼저 실행되는 문제를 줄인다. 두 난수 설정이 남은 평가를 끝낸 뒤 정상 요청·잡담·함정·혼합 문장·학습률 상한 적용 비중과 편차를 함께 비교한다. 반복 두 번이 모든 불확실성을 해소한다고 단정하지 않는다. 현재 학습 완료0/2이며 개선이나 채택을 선언하지 않는다.

## 실제 연결 확인

GPU 서버 B의 현재 Spark 학습 프로세스는 계속 계산하고 있다. 새 대기 프로세스는 선행 학습·변환·기본 평가 완료 표시를 기다리며 새 GPU 학습을 시작하지 않았다. 예약 재호출은 동일 PID를 반환했다. 기반·자료·학습 코드가 존재하고 해시3개와 실행 문법, 여유 공간3GiB 기준을 확인했다. 앞선 일일 실험의 짧은 GPU 연결 검사 완료 표시를 재사용하며 두 번째 시드의 본 실행을 끝냈다고 쓰지 않는다. 새 모델 다운로드·기존 모델 삭제·작업 중단·임대·결제는 추가하지 않았다.

GPU 서버 A는 학습판 D 평가 실행과 D2/H/MX 준비 대기3개다. GPU 서버 B는 Spark 학습 실행, 기존 자료로 준비된 대기 학습4개, 다운로드 준비 후보1개다. 다운로드 후보의 공간은 실행 직전에 다시 확인한다.

## 재개와 한계

10분 자동 확인은 B57 대기 PID·status.log·job.log·finch_DONE·cosine_DONE·ALLDONE 및 각 어댑터 recipe_complete.json을 읽는다. 본 학습·변환·기본 평가 완료 시 HF/GGUF·로그·답안을 로컬로 보관하고 같은 기반에 호환되는 GPU 서버 A 평가를 보충한다. 선행 작업이 완료 표시 없이 종료하면 새 대기열도 실패로 기록하고 원인을 확인한다. 기존 출력 폴더가 있으면 무조건 다시 학습하지 않는다. 3GiB는 예약 시점 기준이며 실행 직전 자원 여유는 다시 확인한다.
