# 경보 원본 예약 수집 — 2026-10-11 08:57

원본 소스 6종 중 5종을 읽어 새 회차에 보관했다. ITS는 전날과 같은 제공처 월간 한도 초과라 추가 사용자 알림을 생략한다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 예산 설정 확인·수집 실행 | 끝 | 1/1 = 100% |
| 경보 소스 읽기 | 일부 성공 | 5/6 = 83% |
| 기존 실패 원인 대조 | 끝 | 1/1 = 100% |

[운영 기준](../../operations/alert-snapshots.md)에 따라 원본 수집만 실행했다. 공용 사용량 중단선 20%, 소스별 한국 시각 하루 2회·월 62회 시도 제한을 확인했다. 실행기 해시는 직전 검증판과 같았다. 다른 기능의 한도나 카운터는 변경하지 않았다.

```powershell
python -B -m scripts.capture_alert_scenarios --archive-only
```

실제 출력:

```json
{"run_id": "2026-10-11_085736_75980cc2", "status": "archived_partial", "snapshots": 0, "should_notify": false}
```

종료 코드 1은 일부 소스 수집 실패를 표시한다. [이번 원본·실행 결과](../../../var/alert-snapshots/real/2026-10-11_085736_75980cc2/)에 출처별 원문·시각·캐시 여부·성공과 실패를 보관했다. 기상특보·지진·UTIC·지하철 공지는 새 HTTP 응답 각 1개, 재난문자는 캐시다. ITS도 HTTP 응답 1개를 보관했으나 요청은 실패했다.

ITS 응답은 HTTP 401, 본문 `resultCode=4001`이며 월간 API 호출 한도 초과를 명시한다. [전날 원본](../../../var/alert-snapshots/real/2026-10-10_090529_7b078f86/its-raw.json)과 같은 원인이다. 이를 경보 없음이나 수집이 하루 설정 한도를 전부 소비한 것으로 해석하지 않았다. 제공처 한도를 늘리거나 우회하지 않았다. 실행기 알림 판단도 false이며 [예약 알림 판단](../../../var/alert-snapshots/real/2026-10-11_085736_75980cc2/heartbeat-decision.json)에 추가 알림 생략을 기록했다.

원본은 새 폴더에 저장했고, 이전 상태 파일은 [교체 전 백업](../../../var/alert-snapshots/real/_backup/2026-10-11_085747_321e71c0/)에 보존됐다. 고객 API·점검 계정·접수·여행·브라우저·대체안 검사·채팅·고객 알림·웹훅·관리자 설정·commit·push·배포는 이번 명령의 실행 범위에 포함하지 않았다.

소스 읽기 성공은 당일 모든 사건 확보를 뜻하지 않는다. 도로는 현재 정보, 지하철은 제공처 최신 공지이며, 조회 사이에 생겼다가 해제된 사건의 전량 확보는 확인하지 않았다. `snapshots=0`은 화면 점검용 산출물을 만들지 않은 원본 수집 모드의 값이며 경보 건수가 아니다.
