# 고른 원장 식당을 원장과 잇고, 3글자 이름을 유일할 때만 찾는다

2026-10-10 · Claude · `role-dining` (`af58453` 위 작업 트리) · 요식(Dining) 팀 몫

## 1. 목표

개발 서버에서 「원장에 있는 가게를 넣어도 없다고 뜬다 · 수정을 눌러도 반영이 잘 안 된다」는 신고를 받아 식당 쪽 문제를 파악했다. 서버는 재구성 중이고(전달사항: 서버 구조조정 · 프론트 버그로 연결 끊김 · 오라클 로컬 모델 미기동으로 추천이 안 나옴) 프론트는 다른 사람이 작업 중이라, **서버 코드 안에서 끝나는 수정만** 했다.

## 2. 한 일

**① 확인 화면에서 고른 원장 식당이 원장과 끊기던 것을 이었다.** 원장 후보는 장소 번호만 싣고 원장 가게 번호를 싣지 않아서, 고객이 고른 식당은 등록 판정과 확인 화면 운영시간이 「모름」이었다. 이제 서버가 고른 식당을 공용 원장 식당 행과 대조해(이름 정확히 같음 · 50m 안 · 한 가게) 원장 가게 번호를 붙인다. 고객이 보낸 번호는 받지 않는다. 결함 리포트: [debugs/2026-10-10_고른_원장식당이_원장과_끊긴다.md](debugs/2026-10-10_고른_원장식당이_원장과_끊긴다.md)

**② 확인 화면 운영시간이 원장 가게 번호를 먼저 본다.** 전에는 관광공사 번호로만 원장을 찾아서, 관광공사 번호가 없는 원장 가게(로컬 전체 원장 1,888곳 중 325곳)는 늘 「모름」이었다. 이름으로 찾은 경우는 정확히 같은 이름 하나일 때만 가게 번호를 쓴다.

**③ 3글자 이름은 앞부분이 맞는 가게가 하나뿐일 때만 잡는다**(사용자 결정). 「편강율」이 「편강 율 플래그십&티하우스」를 못 찾던 것. 4글자 이상은 그대로이고, 3글자로 잡은 것도 확인 필요로 낸다.

**④ 문서 번호 충돌 정정.** 제보 설계 문서가 새 마이그레이션을 `221` 로 적었는데 `221_dining_core_promote.sql` 이 이미 있다 — `228` 로 고쳤다.
