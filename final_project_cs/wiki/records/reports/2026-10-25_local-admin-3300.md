# 2026-10-25 로컬 API·제품 관리자 3300 구성

## 결론·범위

새 격리 사본 `cache/scratch/local_admin_3300_v1/repo`에서 일괄 실행을 수정했습니다. API 8042·운영 API 8070·고객 웹 3100·제품 관리자 3300의 기동 계획을 실제 PowerShell로 실행하되 프로세스/포트/종료 경계는 시험 대역으로 막아 검증했습니다. 관리자 Next 생산 빌드는 새 후보에서 실제 완료했습니다. 실제 서비스 기동·로그인·DB·외부 API·모델·push/배포는 하지 않았습니다. 실환경 예약 OFF는 여전히 미확인입니다.

- 원본 `C:/_proj/final_workspace` HEAD `efeb873a8d065fbd28fe8e92dcc42e5cfb3de3e3`와 `C:/_proj/파이널스페이스` HEAD `a9a6749004ae8d34697a9750d2d6d9b4f114de84`는 서로 다릅니다. 후자의 README 419줄에는 관리자 실행 절이 없으며 운영 API·관리자 package.json이 디스크에 없습니다. sub 규칙 세 파일은 `ls-files -v`에서 `S`이므로 삭제/기능 부재로 단정하지 않고 sparse 상태로 구분합니다. 설정은 변경하지 않았습니다.
- 원본 현재 porcelain 줄 수는 각각 815·1158입니다. 과거 391과 같은 측정 범위·시점임이 입증되지 않았으므로 증감 또는 손실로 해석하지 않습니다. 원본 조회는 변경 없는 `tools/safe_git.py` 정책에 명시 MinGit 실행기를 연결한 scratch 감사 도구로 수행했습니다.

## 원인·최소 수정

1. 최신 README에도 운영 API와 관리자 앱은 별도 명령이었고, 일괄 배치는 개인 `%USERPROFILE%\.acop-ops\start-acop.ps1`을 필수 파일로 검사했습니다. 이 파일이 없는 PC는 네 프로세스 기동 전에 중단됩니다. 개인 스크립트가 있으면 기존 감시·알림 경로를 보존하고, 없으면 README의 고객용 uvicorn으로 명시적으로 기동하도록 수정했습니다. 작업자는 자동 추가하지 않으며 이 차이는 출력/계약에 남깁니다.
2. 운영 API의 설정 포트가 8070이 아닐 수 있는데 배치/관리자 주소는 고정 8070이었습니다. 기동 인자에 `--host 127.0.0.1 --port 8070`을 명시했습니다. 관리자 npm dev/start는 이미 3300으로 올바르므로 수정하지 않았습니다.
3. 배치 bootstrap은 Windows CRLF만 찾아 Git LF checkout에서 PowerShell 본문 대신 배치 문법을 해석했습니다. 줄 시작 marker 정규식으로 LF/CRLF를 모두 처리합니다.
4. Windows PowerShell의 `ConvertFrom-Json` 배열을 바로 `Sort-Object`로 보내던 종료 경로가 상태 배열 전체를 하나의 entry로 다룰 수 있었습니다. JSON을 먼저 변수로 받은 뒤 열거·정렬하도록 수정하고 PID·시작시각 일치, 재사용 PID, 사라진 PID를 회귀로 검증했습니다. 실제 프로세스를 종료하지 않았습니다.
5. README에서 운영 API와 관리자 웹을 서로 다른 터미널로 명시하고 일괄 check/start/stop, 계정·권한·DB 준비와 승인 경계를 보완했습니다. 두 wiki와 인계를 갱신했습니다.

### 실패·해결 기록 (통과 수에 혼합하지 않음)

- `launcher-red.log`: 최초 harness의 `-File` 실행에 process 범위 ExecutionPolicy 인자가 빠져 실제 check 시험 두 건이 환경 실패였습니다. 전역 정책은 바꾸지 않고 기존 배치와 같은 process 인자를 넣었습니다. 이 최초 결과를 제품 RED로 세지 않습니다.
- `launcher-red2.log`: `test_clean_profile_plans_all_four_services_without_private_starter`는 개인 starter 파일 필수 검사로 실패, `test_ops_bind_and_port_cannot_drift_from_admin_gateway`는 운영 포트 명시 누락으로 실패했습니다. 의도한 RED 2건이며 수정 후 통과했습니다.
- `launcher-red3.log`: LF 본문 추출 시험이 배치 `if /I`를 PowerShell로 읽어 ParseException. bootstrap 수정 후 LF/CRLF 모두 통과했습니다.
- `launcher-final.log` 및 `launcher-stop-diagnostic.log`: 새 종료 회귀에서 예상 kill 기록이 없어 실패했습니다. 상태 JSON 배열의 잘못된 열거를 확인해 종료 경로를 최소 수정했고 최종 7/7 통과했습니다.
- 최초 의존성 `copytree`의 WinError3는 Windows 장경로 문제입니다. 한줄 prefix 재시도는 셸 escape SyntaxError였습니다. scratch `copy_dependencies.py`에서 extended prefix를 구성해 partial 대상에 `dirs_exist_ok=True`로 재개했고 native SWC ARM64와 Next/tsc 파일을 확인한 뒤 빌드를 완료했습니다.
- 감사 wrapper의 StringIO.reconfigure 누락은 도구 호환 오류였습니다. scratch capture에 해당 메서드를 추가하여 안전 정책 자체를 바꾸지 않고 재실행 exit 0을 확보했습니다. 번들 Git WinError5 역시 도구 실행 제약이며 제품 오류가 아닙니다.
- 최초 패키징 목록 비교는 Git의 한글 경로 인용(`core.quotepath`) 문자열과 원래 경로를 비교해 실패했습니다. 제품/빌드 오류가 아니며 보고 도구를 `git diff --name-only -z`의 원시 UTF-8 경로 집합으로 교정했습니다. 수동 경로 치환 없이 최종 patch 재구성·tree 일치·hash 검증을 수행합니다.
- 최초 `diff-check.log`는 patch 도구가 혼합 LF/CRLF wiki를 정규화한 삽입 주변 CR을 공백으로 판정했습니다. `preserve_wiki_bytes.py`로 기존 원문 바이트를 그대로 두고 새 문단만 LF로 삽입했습니다. 다음 `diff-check2.log`의 tsconfig 마지막 CR은 격리 Next custom dist typegen 자동 변경이었습니다. 후보의 생성 변경만 원래 바이트로 돌린 뒤 기본 `.next`로 모든 관리자 검증을 새 `admin-final/`에 다시 완료했습니다. 원본 tsconfig는 변경하지 않았습니다.

## 남은 실제 실행 단계·부수효과·승인

[실행 계약](../../operations/local-app-bundle.md)과 README를 따릅니다. 서비스는 아직 켜지지 않았습니다.

1. 원본에 덮어쓰지 말고 독립 검토 후 새 후보의 적용 트리/manifest를 확인합니다. 이번 증분은 예약 OFF v2 staged tree 위에만 적용합니다.
2. 후보에 Python 3.12 가상환경과 의존성, 두 프론트 의존성을 준비합니다. 기존 비공개 설정과 운영자 `ACOP_UI_OPERATORS`·권한키 `ACOP_OPS_API_KEYS`를 별도 승인 범위에서 연결합니다. 계정 생성·암호 출력은 하지 않습니다.
3. 후보 루트 `.\triPilot-실행.bat check`: 서비스 시작 없음. 의존성/실행기 사전 점검만 합니다.
4. 서비스 시작 승인 후 `.\triPilot-실행.bat`: 고객 API 8042, 운영 API 8070, 웹 3100, 관리자 3300 루프백 listener와 `.tmp/local-services` 로그·PID 상태를 만듭니다. API 초기화의 DB/모델/외부 데이터 의존과 개인 starter가 있으면 감시·알림 부수효과를 사전 확인해야 합니다. DB/migration/모델 호출 승인을 포함한다고 추정하지 않습니다.
5. 별도 실데이터 승인 후 `/health`, 관리자 로그인, `/settings` 읽기, 예약 OFF 저장/재읽기/고객 기존 예약 보존을 검증합니다. 시작 포트만 열렸다고 기능 또는 실환경 OFF 완료로 적지 않습니다.
6. `.\triPilot-종료.bat`은 배치 소유 PID+시각 일치 대상만 종료하며 공유 DB·기존 listener를 건드리지 않습니다. push·배포는 별도 승인입니다.
