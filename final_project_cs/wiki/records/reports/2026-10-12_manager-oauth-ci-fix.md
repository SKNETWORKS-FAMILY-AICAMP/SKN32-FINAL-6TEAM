# 개인 AI 연결 관리 CI 보완 — 2026-10-12

개인 AI OAuth·SQL 안전 변경을 매니저에 통합한 뒤 전체 CI에서 같은 시험 두 개가 실패했습니다. 인증을 우회하는 예외를 추가하지 않고 실제 공통 인증 의존성에 연결하고 API 계약 목록을 보완했습니다.

| 실패 | 원인 | 수정 |
|---|---|---|
| 쓰기 경로 인증 의존성 검사 | 연결 폐기 경로가 회원 확인 함수 내부에서 인증했지만 공통 인증 의존성이 라우트 그래프에 드러나지 않았습니다. | `require_member`가 `Depends(web_cookie.require_identity)`로 공통 인증·Origin·CSRF·계정 정책을 받은 뒤 회원 쿠키 조건을 검사합니다. |
| API 경로 계약 검사 | 연결 목록·개별 폐기 두 경로가 공통 API 표면 목록에서 빠졌습니다. | 두 경로를 목록에 등록하고 [OAuth 계약](../../external/personal-ai-oauth.md)에 메서드·인증·오류·소유 범위를 명시했습니다. |

추가한 요청 수준 회귀 시험 9개는 미인증·게스트·기존 사용자 키의 조회 및 폐기 차단과 CSRF 누락·위조·다른 Origin의 폐기 거절을 검사합니다. 거절 후 기존 연결이 살아 있는지도 확인합니다. 본인 폐기 성공·타인 연결 404·토큰 폐기는 기존 시험을 유지합니다.

## 실행과 한계

- 직전 원격 전체 시험은 각 저장소에서 2개 실패, 4678개 통과, 259개 건너뜀, 244개 선택 제외였습니다. 실패 로그는 보존했습니다.
- 수정 후 API·계약·보안·OAuth DB·MCP·기존 키 범위의 첫 로컬 실행은 482개 통과와 준비 오류 6개였습니다. 준비 오류는 새 시험 DB에 기본 데모 조직을 넣지 않아 발생한 외래 키 위반으로 확인했습니다.
- GitHub CI처럼 `scripts.seed_travel`을 새 시험 전용 PostgreSQL에 실행한 뒤 `tests/integration/api tests/security`를 재실행했습니다. **186/186 통과**, 실패·건너뜀 0입니다. 업무 DB와 외부 통신은 차단했고 전용 클러스터는 종료했습니다. 시험 중 소스 변경도 0건입니다.
- ruff 전체와 변경 파일 공백 검사는 통과했습니다. 팀·개인 추적 텍스트 전체 보안 재검사에서 정보 노출 문제는 발견하지 못했습니다. 원문 grep 출력과 JUnit·실패·성공 로그는 비공개 작업 폴더에 보존했습니다.
- 수정 커밋의 원격 전체 CI는 재푸시 후 별도로 확인합니다. 이 기록 자체가 그 최종 성공이나 운영 배포를 주장하지 않습니다.

웹 화면·전체 wiki 개편·v12·운영 정책·분류 조립 기능은 이번 수정 범위에 없습니다. 기존 데이터와 각 원격 이력을 보존합니다. 실제 외부 개인 AI 등록·운영 계정 연결·원격 배포·재시작은 수행하지 않았습니다. 앞선 범위와 제외 이유는 [매니저 통합 기록](2026-10-12_manager-baseline-integration.md)에 있습니다.
