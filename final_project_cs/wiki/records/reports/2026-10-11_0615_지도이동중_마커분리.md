# 로딩·지도 이동 중 보이는 마커를 거리 버튼에서 제외

로딩 중 가운데로 들어온 일정 마커가 화면 밖 일정과 묶여 숨는 문제를 수정했다. 지도 안의 일정은 마커로, 실제 지도 밖의 일정만 거리 버튼으로 표시한다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 지도 화면 고유 시험 | 통과 | 15/15 = 100% |
| 계산·SDK 갱신 단위 시험 | 통과 | 28/28 = 100% |
| 타입·문법 검사 | 통과 | 2/2 = 100% |

## 원인과 수정

화면 안 좌표를 거리 버튼에서 제외하는 기존 계산은 이미 있었다. 그러나 첫 지도 맞춤에서 Leaflet이 기본 CSS 확대 전환을 실행하며 마커와 계산용 지도 경계를 서로 다른 시점에 움직였다. 1280px 재현에서는 지도 경계에서20px 이상 안쪽에 들어온3번 마커가 여러 프레임 동안 거리 버튼에 포함되고 숨겨졌다. 375px의 같은 재현은 통과했다.

첫 위치는 즉시 맞추도록 명시했다. 이후 확대·축소는 마커와 경계를 함께 갱신하는 이동을 사용한다. OSM의 추가 프레임 대기를 없애고 Google·Naver도 이동 완료 전 경계 변경을 전달하도록 했다. 공통 지도는 SDK의 일정 갱신을 화면을 그리기 전에 수행한다. 이동 감소 설정에서는 첫 맞춤·확대·축소를 즉시 처리한다.

화면 안 좌표 제외 계산, 스택 아이콘·개수, 확대 도구와 마커의 겹침 허용, 거리 눈금·접기 버튼 자리 확보 규칙은 유지했다. 확대 도구가 거리 버튼과 겹칠 수 있으므로 해당 시험은 도구를 접고 거리 버튼을 누른다.

## 시험 근거

- [변경 전 로딩 재현](../evidence/2026-10-11_map-moving-visibility/before-loading.json): 2건 중1280px에서1건 실패, 375px에서1건 통과. 공개 접수의 과거 로딩을 재현했다는 의미가 아니다.
- [첫 수정](../evidence/2026-10-11_map-moving-visibility/after.json): 이벤트 갱신만 고친 단계에서도1280px 로딩 문제가 남았다. [다음 확인](../evidence/2026-10-11_map-moving-visibility/final.json)은 새 마커 분리4건 통과, 기존 시험4건 실패였다. 스택 `×3` 문구와 도구 접기 규칙에 맞춰 시험을 갱신했다.
- [최종 Chrome 결과](../evidence/2026-10-11_map-moving-visibility/verified.json): 새 시험6건과 기존 지도 시험9건, 고유15/15. 375px·1280px에서 로딩 자동 맞춤·거리 버튼 선택·확대축소를 각각 검사했다. 각 프레임에서 실제 마커의 화면 좌표와 버튼에 포함된 번호·숨김 여부를 함께 확인했다. [프레임 수](../evidence/2026-10-11_map-moving-visibility/frame-summary.json)에 기록한 여섯 경우 모두 잘못된 합침0건이다. 20px 경계 여유 안쪽을 관찰하므로 지리 경계의 미세한 반올림까지 보장하지 않는다.
- [단위 최종 결과](../evidence/2026-10-11_map-moving-visibility/unit-verified.json): 경계 계산·핀 숨김·버튼·Google/Naver 이동 전 경계 전달과 구독 해제28/28. 초기 실행은 임시 변환 파일 오류, 다음 실행은 Google SDK 대역의 `getCenter` 누락으로 실패했고 이를 보완한 뒤 통과했다. 실패 기록도 함께 보존한다.
- 타입 검사·변경 파일 ESLint 각각 종료0. 제품 코드를 바꾼 후 새 빌드 성공, 동일 빌드에서 최종15건을 실행했다. [빌드·파일 확인값](../evidence/2026-10-11_map-moving-visibility/verification.json)을 보존한다.
