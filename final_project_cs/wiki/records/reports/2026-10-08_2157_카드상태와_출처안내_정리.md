# 카드 상태와 출처 안내 정리

카드의 확인 필요·시간 되돌리기는 오른쪽 아래로 옮겼고, 변경 완료는 제목 옆 체크만 남겼다. 출처는 작은 한 줄로 접고 일정 전환 중에는 잠깐 숨긴다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 카드 표시·마커 위치 | 반영·검증 | 4/4 = 100% |
| 출처 축소·전환 숨김 | 반영·검증 | 2/2 = 100% |
| 화면 시험 | 통과 | 25/25 = 100% |
| 빌드·정적 검사 | 통과 | 3/3 = 100% |

## 최종 동작

- 변경한 일정은 제목 바로 오른쪽에 체크가 보인다. `변경 완료`는 화면에서 글자로 반복하지 않으며 보조 기술을 위한 이름은 유지한다.
- `확인 필요`와 일정별 시간 `되돌리기`는 카드 맨 아래 오른쪽에 있다. 상세 내용을 펼쳐도 하단 위치를 유지한다. 되돌리기는 키보드 Enter로 실행되며 클릭 영역은 높이 44px 이상이다.
- 마커 선택 위치는 이미 반영된 머리줄 높이를 고려하는 방식으로 유지하고 시험을 보강했다. 첫·마지막 일정, 일차 줄 복귀, 긴 제목, 접은 목록을 열 때와 같은 마커를 다시 열 때도 제목이 머리줄에 가리지 않는다. 검증 중 진행 일정의 가운데 정렬도 재확인했다.
- 출처는 목록 끝에서 관광공사·지도 출처 한 줄로 보이고, 누르면 기존 정책 링크와 경로 설명을 펼친다. 일차·수정안 전환, 옆으로 끌기, 목록 끝 당기기 중에는 투명해지고 키보드 접근도 잠깐 막힌다. 종료 후 복귀한다. 애니메이션 줄이기 설정과 종료 이벤트가 빠진 경우의 복귀도 처리한다.

일정 수정·전체 시간 되돌리기·지도 상태 막대·키보드 메뉴·일차 숨김 기능도 함께 시험했다. 공개 앱 응답과 배포 상태를 이 mock 서버 시험 결과로 판정하지 않는다.

## 실행 결과와 제한

mock 서버 시험 25/25 (화면 반응). 서로 다른 시험만 세었으며 `7 + 20 - 중복 2 = 25`다.

실서버 확인 (서버 응답): 안 했음 — 이번 카드·출처 변경의 공개 앱 응답은 확인하지 않았다.

ESLint 선택 파일 7개와 웹 전체 타입 검사가 종료 코드 0이다. 최종 Next 빌드도 통과했고 해당 빌드로 회귀 시험 20개를 실행했다. 별도 백엔드 쓰기 계약을 변경하지 않았으며 이번 작업에서 커밋·푸시·공개 앱 배포는 하지 않았다. 로컬 기준은 `role-manager`, HEAD `38f9e08cb08cafba6ce2f66ff7b08c19788cf1d1` 위 미커밋 변경이다.

최초 빌드는 새 시험 코드의 nullable body 타입 오류로 중단됐다. 추가 시험에서 옛 출처 펼침 기대 1건과 버튼 클릭·시험 자료 동기 문제 2건이 드러나, 접힌 출처를 먼저 펼치고 숨김 종료를 기다리도록 보정했다. GET으로 추가한 둘째 날을 서로 다른 SSE 응답이 덮지 않도록 완료 화면 시험 자료도 맞췄다. 실패·성공 로그를 모두 보존했다.
