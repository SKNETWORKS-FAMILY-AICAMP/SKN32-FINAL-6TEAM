## 1. 간헐 실패 — 무엇이었나

`(\d{3})-(\d{4})-(\d{4})` 전화번호 규칙이 `7da9d588-1234-4253-…` 의 `588-1234-4253` 에 걸렸다. `transition_case` 는 이벤트 payload 를, `create_case` 는 `state_json` 을 통째로 가려 저장한다. 찾은 경로와 반복 수는 디버그 리포트 §3 에 있다. 고친 뒤 같은 조합 30회 실패 0(고치기 전 30회 중 2) — 30 대 30 이라 차이 자체는 강하지 않고, 근거는 원인을 직접 본 것이다.

## 2. 일정 안내(v11 §6-B ②·③)

| | 언제 | 무엇 |
|---|---|---|
| 전날 | 20시 ~ 하루 시작 안내 전 | 다음 날 일정 |
| 하루 시작 | 첫 항목 60분 전 ~ 첫 항목 시작 | 오늘 일정 |
| 출발 | 이동 항목 15분 전 ~ 이동 시작 | 어디로·언제·**어떻게**(보낼 때 경로 사건을 조회해 계획 수단·소요·조회 시각) |

- Case 를 안 만들고 LLM 을 안 부른다. 같은 안내는 `outbox` UNIQUE 로 한 번(DoD-26). 출발 안내 키는 이동 항목 id — 감시가 이동을 바꾸면 새 이동이 새로 안내된다.
- 경로 사건을 못 읽으면 보내지 않고 `fatal`(결정 15), 계획 수단에 사건이 걸려 있으면 낡은 경로를 안내하지 않고 `held`.
- 시각 값(60분·15분·20시)은 **우리가 고른 값**이다 — `config/guardrails.yaml` `travel.reminders.*`.
- 디스코드 발송이 `plan_url` 을 붙인다(안내에 늘 링크). ① 변경 통지는 아직 `plan_url` 을 안 싣는다.
- 시나리오 모드의 안내도 같은 함수를 쓴다(문구가 한 곳).
- `[미구현]` 이동 항목 없이 장소만 이어진 구간의 출발 안내 — 이동 시간 조회가 없다.
- 시험 `tests/scenario/test_trip_reminders.py` 6건. 일부러 깨뜨림 2회: 사건 걸린 경로 보류를 빼면 1건, 중복 차단을 빼면 2건이 실패.

## 3. 승인 뒤 실행 · Booking Handoff 라우팅

- 코어(`controller.py`): 승인 대기로 갈 때 `wait_reason=human_approval` 을 적는다(전에는 안 적어 재개가 `customer_input` 으로 읽혔다). 재개 때 승인된 `pending_approval` 제안을 모아 **적용기가 전부 있으면** 한 savepoint 에서 실행 → `succeeded`·`provider_ref` → `resolved`. 적용기가 하나라도 없으면 예전처럼 Team 재실행. 거부·충돌은 전부 되돌리고 `failed` + `escalated`, 시간 초과·연결 오류는 `unknown` + `escalated`(재실행 없음).
- 승인 제안의 멱등 키: 적용기가 있으면 적용기가 인자에서 꺼낸 대상 id(v11 §4-E). 전에는 Case id 라 한 Case 의 둘째 제안이 합쳐져 사라졌다. 적용기 없는 제안은 아직 Case id.
- 적용기 `booking_actions.py`: 취소 = Mock 공급자 원장·우리 예약 `cancelled`, 변경 = 바꿀 내용이 인자에 없어 **지어내지 않고 인계**(예약 `change_requested` + 바깥함 `booking.handoff`).
- Booking Handoff `select_capability`: `booking_cancel_request` → `prepare_cancel`, `booking_change_request` → `prepare_change`.
- 시험 `tests/integration/controller/test_travel_approval_proposal_reaches_waiting.py` 6건(라우팅 → 승인 대기 → 승인 → 실행 · 변경 인계 · 잠긴 예약 거부 · 적용기 없는 조립은 예전 흐름 · 한 Case 두 대상). 일부러 깨뜨림 2회: 승인 뒤 실행을 끄면 3건, 멱등 키를 Case id 로 되돌리면 1건 실패.

## 5. 함께 본 것 · 남은 것

- **DB 가 종료 기록 없이 꺼진다**(09-15 · 09-17 두 번). 오늘 13:57 에 누가 다시 띄웠다. 셸에서 띄운 프로세스라 그 세션과 같이 죽는다는 가설 — 확인 안 함(디버그 리포트 §5).
- 끝난 Case 에 `run_case` 를 다시 부르면 Team 을 한 번 더 실행한 뒤 상태기계가 막는다(`InvalidTransition`). 부작용은 없지만 쓸데없는 실행이다 — 이번에 고치지 않았다.
- 적용기가 없는 승인 제안의 멱등 키는 여전히 Case id.
- 안내 문구를 언어마다 한 번 생성해 재사용하는 캐시는 없다 — 번역은 발송 때.
