## ① 엉뚱한 대상 변경 — 결정 단위에 「근거 없는 대상은 되묻기」 장치

**한 일.** 모델이 바꾸는 할 일(바꾸기 · 대안 · 되돌리기 · 다시 · 닫힘 알림)에 **근거 없는 대상**을 골랐으면 서버가 바꾸지 않고 「이 중 하나인가요?」로 내린다(`decision_unit.guard_target`). 근거는: 같은 종류가 하나뿐 · 화면에서 고른 일정 · 문장이 짚는 말(「첫 식당」) · 문장과 이름이 겹치는 일정 · 방금 바꾼 일정 · 앞에서 약속한 날. 후보는 모델이 고른 곳을 포함해 최대 셋. 기록된 실패 문장(「저녁 식당 바꿔줘」가 다른 날 식당으로 간 것)을 재생한 시험 19건이 통과한다.

**재생(실제 모델 Gemma 4 12B · 정답은 Claude 표기 · 각 묶음 1회 · 2026-10-07 GPU 서버가 비어 있을 때).**

| 묶음 | 맞음 | 엉뚱한 대상 변경 | 지연 p95 |
|---|---:|---:|---:|
| 실제 대화 | 64/66 = 97.0% | 0 | 5.8초 |
| 화면 조작 | 28/30 = 93.3% | 0 | 5.3초 |
| 긴 대화 | 34/34 = 100% | 0 | 5.3초 |
| 사실 질문 | 41/42 = 97.6% | 0 | 3.6초 |
| **합계** | **167/172 = 97.1%** | **0** | — |

- 실제 대화에서 틀린 두 문장은 기준 실행(2026-09-30)과 **같은 두 문장**이다(「방금 바꾼 … 원래대로」 · 「첫 활동 다른 걸로 바꿔줘」) — 이 장치가 새로 틀리게 만든 문장은 없다.
- 다른 묶음은 기준 실행 대비 화면 조작 29/30 → 28/30, 긴 대화 33/34 → 34/34, 사실 질문 41/42 → 41/42(같은 문장)다. 화면 조작에서 새로 틀린 「둘째 날 두 번째 활동 다른 데로」는 모델이 바꾸기 대신 「대안 제안」을 고른 것으로(서버 장치가 내린 되묻기가 아니다) 같은 모델 · 같은 문장이어도 실행마다 갈릴 수 있는 차이다 `[해석]`.
- ★지연 p95 가 합격선(5초)을 실제 대화(5.8초)와 긴 대화 · 화면 조작(5.3초)에서 넘는다. 기준 실행은 2.5~4.6초였다. GPU 서버를 다른 세션과 나눠 쓰는 영향인지 모델 호출 수가 늘어서인지 가르지 못했다 `[미확인]` — 이 장치는 모델을 더 부르지 않는다(서버가 고른 것을 점검만 한다).
- 한계: 표본이 작고(문장 172) 문장 상당수가 같은 일정 틀이다. 정답은 사람 검수가 아니다. 반복 측정이 아니라 편차를 모른다.

## ② 계획 읽기 값 변조 — 사진 · 스캔을 두 번 다르게 읽은 줄은 「확인 필요」

**한 일.** 사진 · 스캔 받아쓰기에서 전체와 위 · 아래 반쪽을 이미 따로 읽고 있었다(빠진 줄 검사). 그 둘이 **같은 줄을 다르게 읽은 곳**(`sources.differing_lines`)을 저장하고(`intake_sources.differs_json`, 마이그레이션 055), 그 줄에서 읽은 제목 · 예약번호는 값은 그대로 두고 **「확인 필요」 + 두 읽기**를 붙인다. 모델 호출은 늘지 않는다(이미 읽은 반쪽 글을 맞춰 볼 뿐).

**평가 실행(`python -m eval.intake.run`, 합성 60건, 실제 모델 · 관광공사 · 카카오).** 같은 정의의 값 변조(원문에 글자 그대로 없는 제목 · 예약번호)를 셋으로 나눠 센다.

| 지표 | 값 | 분모 |
|---|---:|---|
| 값 변조 전체 | 12 = 3.4% | 뽑은 제목 · 예약번호 350 |
| 그중 받아쓰기 비교로 「확인 필요」 표시 | 10 = 2.9% | 350 |
| 그중 다른 까닭으로 이미 「확인 필요」 | 0 | 350 |
| **표시 없이 새어 나간 변조** | **2 = 0.6%** | 350 |
| 표시한 것 중 실제 변조였던 비율 | 10/14 = 71.4% | 표시한 값 14 |
| 비교가 「다르다」고 한 줄 | 16/211 = 7.6% | 비교한 줄 211 |
| 항목 재현율 | 333/336 = 99.1% (전 97.0%) | 정답 항목 336 |
| 시각 정확도 · 장소 1위 | 327/327 = 100% · 332/333 = 99.7% | 같은 정의 |

- **새어 나간 2건**은 일부러 넣은 오타 「경복굼 관람」을 모델이 두 번 모두 똑같이 「경복궁 관람」으로 고쳐 읽은 경우(사진 1 · 스캔 1)다. 두 읽기가 같아서 이 방식으로는 못 잡는다 — 같은 줄을 같게 오독하면 못 잡는 것이 이 방식의 한계다. 원문의 오타를 모델이 고쳐 적는 것이라 사람이 보면 오히려 맞는 글자일 수 있다 `[해석]`.
- 닮음 기준을 0.4~0.7 로 바꿔도 저장된 받아쓰기 23건에서 결과가 같아(오독 12줄 중 10줄 표시, 표시 16줄) 0.5 를 그대로 두었다.
- 항목 재현율이 97.0 → 99.1% 로 오른 까닭은 가르지 않았다(이 장치는 항목을 더하거나 빼지 않는다 — 다른 세션의 변경이나 모델 응답 차이일 수 있다) `[미확인]`.
- ★받아쓰기 시간이 p50 236초(전 7.9초)로 크게 늘었다 — 이 실행 때 GPU 서버가 다른 세션과 겹쳐 있었다. 이 장치는 모델 호출을 늘리지 않으므로 원인은 환경으로 보이나 확인하지 않았다 `[미확인]`.
- 한계: 합성 60건 · 사람 라벨 아님 · 실제 사진 아님 · 단일 실행(편차 모름). 「표시」는 고객이 값을 확정하기 전에 보게 하는 것이지 값을 고쳐 주는 것이 아니다.
