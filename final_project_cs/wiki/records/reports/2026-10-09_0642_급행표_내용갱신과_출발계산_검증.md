## 발견과 수정

급행표를 노선 이름으로만 기억하고, 계산기 입력 변경 감시에서 급행표를 빠뜨려 새 표로 바꾸어도 옛 출발 시각을 사용했습니다. 통제 자료에서10:00 출발을10:05로 바꾸는 직접 읽기와 런타임 갱신 두 조건 모두 수정 전에 실패했습니다. [최초 재현](../evidence/2026-10-09_0613_급행표_갱신/express-source-before-v1.log).

처음에는 경로·수정 시각·크기·파일 식별자를 비교했습니다. 관련39조건에서 통과했으나 확대 실행과 단독 재실행에서 누락을 확인했습니다. 수정 시각·크기·파일 식별자가 같고 내용만 다른 표를 만드는 추가 두 조건도 모두 실패했습니다. 이전39/39를 최종 완료 근거로 쓰지 않습니다. [같은 파일 정보의 내용 교체 재현](../evidence/2026-10-09_0613_급행표_갱신/express-content-before-v1.log).

최종 판은 파일 정보와 내용의 SHA-256을 함께 대조합니다. 같은 판에서만 읽은 열차를 재사용하고, 부재·삭제·경로 교체도 계산기 입력 상태에 포함합니다. 읽기와 구성 전후가 다르면 섞인 판을 게시하지 않습니다. 구성 실패 때 기존 계산기를 보존하고, 성공한 새 계산기를 이후 요청에 사용합니다. 기존 열차 객체는 수정하지 않습니다. [수정 전 백업과 중간 수정 백업](../evidence/2026-10-09_0613_급행표_갱신/backup-final-v1.json).

## 검증 범위와 결과

새11조건은 같은 표 재사용·변경·새 파일 생성·삭제·경로 교체·없던 표의 런타임 반영·읽기 중 교체·구성 중 교체·손상 후 복구·같은 파일 정보의 직접 읽기·같은 파일 정보의 런타임 교체입니다. 가공한 여행 자료를 사용하는 통제 시험이며 독립 웹 대조나 실제 탑승을 대신하지 않습니다. 표가10:05 첫차로 바뀐 뒤10:00 요청은 기존 정책에 따라 첫차 이전으로 판정하고,10:05 요청은10:05 출발·10:09 도착을 계산합니다.5분 대기를 허용하는 새 정책을 만든 것은 아닙니다.

관련41/41은 새11조건을 포함합니다. 확대 557/557는 관련 조건을 포함한 이동 기본층이며 live·mobility_full 표시는 제외했습니다. 새11·관련41·확대 수치를 더해서 시험 수를 늘리지 않습니다. 확대를 메모리 부담 때문에 기본층 묶음·택시 대체5조건·계산기 연결8조건으로 나누었습니다. 연결8조건은 Windows 비동기 실행의 로컬 통신이 허용되는 환경에서 별도로 확인했습니다. 실패0·오류0·건너뜀0입니다. 전체층·DB 통합·계약/보안 관문을 이번에 모두 재실행한 것은 아닙니다.

[관련 최종 로그](../evidence/2026-10-09_0613_급행표_갱신/express-content-related-v1.log) · [확대1 로그](../evidence/2026-10-09_0613_급행표_갱신/express-source-full-v4-part1.log) · [확대2 로그](../evidence/2026-10-09_0613_급행표_갱신/express-source-full-v4-part2.log) · [연결8조건](../evidence/2026-10-09_0613_급행표_갱신/express-source-wiring-v1.log), 같은 이름의 XML과 [검증 증거](../evidence/2026-10-09_0613_급행표_갱신/verification-proof-v1.json)에 실제 분자·분모를 보존했습니다. 실행 소스·시험·자료 180/180 파일이 최종 확대 시작과 종료에 일치합니다. 연결8조건 직전의 v3 시작 해시와 최종v4 시작 해시도 전량 일치했습니다. 이전 택시 검증76파일 중 변경2개는 이번 작업 소스이며 나머지74개는 일치했습니다. 명시한 파일 집합 밖까지 불변이라고 주장하지 않습니다.

실패 과정도 보존했습니다. 초기 읽기 도중 교체 시험은 Windows가 열려 있는 gzip 파일의 쓰기를 막아 의도한 교체를 하지 못했으므로 읽기 종료 후 열차 구성 중 바꾸도록 수정했습니다. 첫차 이전 요청에 출발이 있다고 기대한 시험도 기존 첫차 정책에 맞게 수정했습니다. 첫 확대는 임시 폴더 접근으로 수집 오류가 났고, 작업 폴더 안 임시 경로로 고쳤습니다. 메타데이터 판의 실패가 나온 확대v2는 끝까지 집계하지 않고 중단했으며 최종v4의 증거로 섞지 않습니다. v3도 Windows asyncio의 로컬 socketpair 생성에서 정지한 실행 위치를 확인하고 중단했습니다. 연결8조건은 로컬 통신이 허용되는 실행에서 통과했고 나머지는 v4로 완료했습니다. pyreadline 종료 정리 오류는 pytest 종료 뒤 출력됐고 pytest 종료 코드와 XML 결과를 함께 확인했습니다. 공개 복사에서 로컬 Python 경로·기기 이름·사용자 경로를 제거했습니다.

## 대가와 한계

내용 확인은 파일 읽기 비용을 추가합니다. 기존 급행표 두 파일 합계 640,617바이트, 파일 캐시 준비 후30회 평균±표준편차 6.730±0.247ms, 중간값 6.628ms, 최대 7.237ms입니다. [30회 원값](../evidence/2026-10-09_0613_급행표_갱신/source-signature-cost-v1.json). 같은 두 파일의 입력 판 확인만 잰 값이며 기존 판과 교대 비교한 개선율도, 최초 적재나 서비스 응답 시간도 아닙니다.

표가 없거나 읽히지 않을 때의 기존 일반 시간표 대체 방식은 유지했습니다. 그 대체 표의 실운행 정확도를 이번에 증명한 것은 아닙니다. 계산기 생성 경로는 급행 판을 추적하지만 수동으로 Runtime을 만들어 급행 입력 상태를 전달하지 않는 저수준 호출은 추적하지 않습니다. 계속 쓰고 되돌리는 외부 작성자에 대한 원자적 최신성까지 보장하지 않습니다.

출발 안내의 저장 문맥은 아직 일반 시간표 판과 규칙 판을 대조하며 급행 판 식별자를 포함하지 않습니다. 이번 수정은 다음 계산의 입력 갱신을 해결한 것이며, 급행 표만 바뀌었을 때 기존 저장 안내·탑승/환승 관측이 반드시 재경로되는 연결까지 완료한 것은 아닙니다. 그 연결과 최초 자료 적재·혼합 운임·누락 경로·1.2km 정책 안의 독립 웹 표본이 다음 확인 대상입니다.
