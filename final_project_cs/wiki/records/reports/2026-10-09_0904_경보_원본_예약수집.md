# 경보 원본 예약 수집 — 2026-10-09 09:04

원본을 새 회차에 보관했다. 수집 성공·실패 상태와 실패 원인은 직전 회차와 같아 추가 알림 대상이 아니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 원본 수집 실행 | 끝 | 1/1 = 100% |
| 경보 소스 읽기 | 일부 성공 | 5/6 = 83% |
| 새 실패 원인 확인 | 끝 | 6/6 = 100% |

## 수행과 근거

목표는 여행 검증·지속관리 범위의 읽기 전용 원본 수집이다. [운영 기준](../../operations/alert-snapshots.md)에 따라 아래 명령만 실행했다.

```powershell
python -m scripts.capture_alert_scenarios --archive-only
```

실제 출력:

```json
{"run_id": "2026-10-09_090445_3bdd3843", "status": "archived_partial", "snapshots": 0, "should_notify": false}
```

종료 코드는 1이다. ITS가 `budget_exhausted`로 읽히지 않아 부분 수집으로 기록했다. 한도를 우회하지 않았다. 기상특보·재난문자·지진·UTIC·지하철 공지 5종은 성공했고, 각 공급자 본문과 확인 시각을 보관했다.

- [이번 원본·실행 결과](../../../var/alert-snapshots/real/2026-10-09_090445_3bdd3843/): `collection.json`, 소스별 원본, `runtime.json`, `report.json`의 새 회차다.
- [직전 비교 회차](../../../var/alert-snapshots/real/2026-10-09_023735_6daf5437/): 소스 6종의 상태·실패 이유를 대조했다. 새 실패 원인 0/6이다. 경보 내용이 같다는 뜻은 아니다.
- [직전 상태 백업](../../../var/alert-snapshots/real/_backup/2026-10-09_090458_be58c243/): 상태 파일 교체 전에 보존했다.

공용 실행 코드·설정은 바꾸지 않았다. 고객 API·브라우저·대체안 검사·접수·여행·고객 알림은 실행하지 않았다. 실제 대체안 화면의 통과 여부를 이 수집 결과로 판단하지 않는다. 수집 실패를 경보 없음으로 해석하지 않으며 조회 사이에 발생·해제된 모든 사건을 확보했다고 보고하지 않는다.

## 남은 범위

ITS의 공유 호출 예산은 기존 정책을 따른다. 새 사용자 조치는 확인되지 않았다. 다음 예약도 원본만 수집한다. 30분 감시·반복 시험 접수는 이번 예약 범위에 포함되지 않는다.
