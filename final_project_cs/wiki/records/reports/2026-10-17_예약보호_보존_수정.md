# 예약 보호 입력 보존 작업

사용자 요청은 숙소 자동 추천·적용, 지도 경로, 예약 보호를 수정해 커밋 채팅을 통해 운영에 반영하고 새 예시부터 실제로 확인하는 것입니다. 다른 채팅이 이미 맡은 작업은 중복하지 않습니다.

## 18:23~18:30 KST — 담당·원인 확인

- 「숙소 추천 위치 로직 수정」 채팅은 최초 숙소 채우기·이동 예산·완료 순서·지도 표시를 담당하고 있습니다. 이 채팅은 예약 정보 누락을 보완합니다.
- 실제 배포 코드에서 모델 결과를 옮기는 `pipeline._agent_rows`가 `booked=None`으로 채우고, 규칙이 이미 읽은 예약번호·예약 여부를 옮기지 않는 것을 확인했습니다.
- 원문의 예약 여부와 예약번호를 보존하는 기존 계약을 복구하는 수정이며 새 승인·업체 거래 권한을 추가하지 않습니다. 모르는 예약 여부는 계속 모르는 값으로 둡니다.
- 공유 원본을 수정하지 않고 별도 격리 사본에 배포 코드 두 파일과 새 회귀 시험을 준비했습니다. 원본 동기화·삭제·복원은 하지 않았습니다.
- 커밋 채팅에 담당 범위와 기존 재현 보고서를 전달했습니다. 양쪽 매니저 반영·배포는 해당 채팅에서 수행하며, 이 채팅은 패치·검증 근거와 배포 후 실제 확인을 맡습니다.

남은 일: 회귀 시험으로 실패 확인 → 예약 값의 원문 대응 보존 → 관련 시험 → 검증 패치 전달 → 배포된 새 예시와 예약 보호 실제 확인.

이 시점에 수정 완료·시험 통과·배포 완료를 선언하지 않습니다.

## 18:30~18:34 KST — 구현·격리 시험

- 모델이 가리킨 장소의 원문 범위와 규칙이 읽은 장소 범위가 하나로 대응할 때에만, 원문 예약 여부·예약번호와 그 근거를 보존했습니다. 항목 순서를 바꿔도 대응한 장소로 옮기며, 같은 줄의 다른 장소나 정정한 새 장소에는 예약 값을 넘기지 않습니다.
- 예약 읽기 회귀 시험 12개를 추가했습니다. 최종 동일 시험은 수정 전 실행판에서 **9개 실패·3개 통과**, 수정 후 **12/12 통과**했습니다.
- 기존 읽기·직접 일정·예약된 숙박 재개 시험과 합쳐 **90/90 통과**했습니다. 변경 파일의 ruff F·E9 검사도 통과했습니다.
- 시험은 당시 실행 중인 API 이미지에 변경 파일만 얹은 별도 컨테이너에서 수행했습니다. 네트워크를 차단하고 시험용 설정만 넣었으며, 운영 DB나 실행 컨테이너는 변경하지 않았습니다.
- 이 시험은 원문 예약 입력 보존과 기존 관련 동작의 회귀 확인입니다. 실제 고객 웹 경로에서 예약 장소의 자동 변경 방지, 새 숙소 추천·지도, 운영 반영 여부는 아직 확인 전입니다.

남은 일: 커밋 채팅에 수정 두 파일과 근거 전달 → 숙소·지도 변경과 통합·양쪽 매니저 반영 → 운영 배포 확인 → 새 예시부터 실제 웹 경로 확인.
