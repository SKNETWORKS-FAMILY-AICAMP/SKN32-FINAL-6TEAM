# 2026-10-26 x600 num_ctx 12288 전환

## 결론

x600 의 `ACOP_OLLAMA_NUM_CTX` 와 Ollama Modelfile `num_ctx` 를 둘 다 8192 → **12288** 로 바꿨다(사용자 승인 「모델 입력 길이는 늘릴수 있으면 늘려」).
api · worker 는 다음 자동 배포의 실행 중 구성 일치 검사(`migration_safe_deploy.snapshot`)가 계산하는 것과 같은 구성으로 다시 만들었다. 같은 검사를 실제로 돌려 **통과**(`Deployment safety snapshot: passed`)했으므로 다음 자동 배포는 `Compose configuration drift; reconcile before deployment` 로 멈추지 않는다.

## 정식 절차를 찾은 근거

- `deploy/auto_deploy.sh` 는 반영 전에 `migration_safe_deploy.py snapshot` 을 돌린다. 이 검사는 `docker compose config`(지금 `.env`)에서 서비스마다 이미지를 실행 중 `Config.Image` 로, `TRIPILOT_TAG` · `ACOP_DEPLOYMENT_VERSION` 을 실행 중 값으로 바꾼 뒤 `compose_json` → `config --hash <서비스>` 를 컨테이너 라벨 `com.docker.compose.config-hash` 와 비교한다.
- 저장소 · wiki 에 별도의 reconcile 명령은 없다. 그래서 「`.env` 를 바꾼 뒤 그 검사와 똑같은 구성으로 api · worker 를 다시 만든다」를 reconcile 로 삼았다(`rollout` 이 `candidate.compose.json` 으로 컨테이너를 만드는 방식과 같다). Codex CLI 검토: 정합성을 맞추는 수동 reconcile 에 가깝다, 사전 · 사후 검사와 실제 snapshot 통과 · 부분 실패 롤백을 갖추라는 조건 — 모두 반영했다.
- `tripilot-web` 은 `.env` 를 `env_file` 로 읽지 않아 다시 만들지 않았다(사후 검사에서 web 도 일치).
