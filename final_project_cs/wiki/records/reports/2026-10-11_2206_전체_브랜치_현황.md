# 전체 브랜치 현황과 통합 대기 변경

[실측] develop에는 10월 11일 매니저 UI 통합이 들어갔지만, 이후 매니저 수정 1커밋과 Activity 실험·숙소/항공 계열은 별도로 남아 있다. 현재 작업 브랜치 role-eval-ui도 develop과 이력이 갈라져 있다. develop → main PR의 웹 검사가 실패했으므로 검사 통과 상태로 보고할 수 없다.

- 확인 시각: 2026-10-11 22:06 KST. Git fetch 성공 후 GitHub 실제 브랜치 목록과 대조했다.
- 조사 범위: 원격 **13/13개 = 100%**, 로컬 **7/7개 = 100%**, 등록 작업 폴더 **4/4개 = 100%**.
- 기준 커밋: develop `180c56ae`, role-manager `d4895eef`, role-eval-ui `875bb41b`.
- 목적: 사용자의 브랜치 조사 요청. 구현·병합·릴리스 완료 판정은 범위 밖이다.
- 근거: [조회 명령과 출력](../evidence/2026-10-11_2206_전체_브랜치_현황_검증.md).
- 10월 8일 조사 기록은 당시 사실로 보존하며, 이후 현황은 이 기록을 따른다.

## UI 브랜치에서 실제로 구분할 것

[실측] role-eval-ui의 독자 커밋 17개 중 일반 커밋은 15개, 병합 커밋은 2개다. `git cherry -v origin/develop origin/role-eval-ui`는 15개 일반 커밋 모두를 `+`로 표시했다. 동일 패치를 찾지 못했다는 뜻이며, 다른 스냅숏·후속 구현으로 기능이 반영되지 않았다는 증명은 아니다.

[실측] 파일 내용으로 확인한 구체적인 차이는 웹 `package.json`의 Next 버전이다. develop과 role-manager는 **16.3.5**, role-eval-ui는 **16.4.0**이다. UI의 버전 갱신 결과가 develop에 반영되지 않은 것은 확인했다. 이번 조사는 해당 버전의 외부 보안 권고를 재검증하지 않았다.

[실측] develop의 웹 CI는 이미 `npm run test:live`를 실행한다. 10월 8일 기록에 있던 ‘없는 test:e2e 실행’ 문제를 현재 실패 원인으로 재사용하지 않는다. develop의 관리자 앱에도 `bf42b659 feat(admin): 실제 운영 연결과 요식업 동선 검사 보완` 커밋이 있으므로, UI 브랜치의 관리자 코드가 전부 미반영이라고 단정하지 않는다.

[미확보] UI의 17개 커밋별 기능 보존 여부 전체, 병합 충돌 여부, 실제 서버 동작은 이번 Git 조사로 검증하지 않았다. 웹 두 tip의 파일 차이는 497개지만 이것도 결함 수는 아니다.

## PR과 CI

[실측] 열린 PR은 [#2 develop → main](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN32-FINAL-6TEAM/pull/2) **1개**다. GitHub의 `mergeable`은 `MERGEABLE`, `mergeStateStatus`는 `UNSTABLE`이다. 자동 병합 계산상 충돌 없음과 검사 통과는 별개다.

- 연결된 Check Run: **9/11개 = 81.8% 성공**, **2/11개 = 18.2% 실패**. push/PR 실행에 따른 중복 검사명을 포함한 집계다.
- 실패한 두 검사 모두 `web (check · e2e · live)`다.
- [PR 웹 실행 38137714908](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN32-FINAL-6TEAM/actions/runs/38137714908)은 mock 서버 브라우저 시험에서 실패했다.
- 해당 실행의 결과: 전체 653개 중 성공 **592/653 = 90.7%**, 실패 **48/653 = 7.4%**, 건너뜀 **13/653 = 2.0%**. 반올림으로 합계가 100%와 다를 수 있다.
- 실패 로그에는 클릭·입력 대기 시간 초과, 예상 URL·텍스트 불일치, 브라우저 404가 나타난다. 개별 원인은 아직 분석하지 않았다.
- 이 결과는 GitHub의 기존 CI 조회이며 이번에 시험을 다시 실행한 것이 아니다. 실제 서버 통합 검증 결과도 아니다.

## 수행 내용과 한계

[실측] 원격 fetch·실제 ref 조회, 로컬 ref·worktree·미커밋 상태 확인, 커밋 도달 관계·patch 비교, PR·기존 CI 로그 조회를 수행했다. GitHub 조회는 읽기만 수행했고 브랜치 전환·병합·삭제·커밋·푸시는 하지 않았다. 애플리케이션 코드 변경과 새 시험 실행도 없다.

[실측] 이번 변경은 이 리포트, [조회 증거](../evidence/2026-10-11_2206_전체_브랜치_현황_검증.md), [wiki 로그](../../log.md)의 항목 추가다. 새 문서 두 개의 로컬 링크 7/7개 = 100%가 존재했고, 줄 끝 공백·코드 블록 짝 검사와 wiki 로그의 git diff --check는 오류 없이 끝났다. 기존 wiki 로그 추가 4줄을 보존하고 이번 항목 4줄을 더했다. 기록은 로컬이며 팀 공유 브랜치에 반영되지 않았다.
