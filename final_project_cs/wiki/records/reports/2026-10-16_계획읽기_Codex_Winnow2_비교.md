## 읽는 법 — 무엇이 공정하고 무엇이 아닌가

- **지시문 2판** = 1판 + 성향 13개 뜻풀이 + 성향 · 조건 · 빠진 값이 든 예 하나. 뜻풀이 · 예 문장은 시험지와 겹치지 않게 썼지만 **어휘는 시험지 정답을 정한 쪽(Claude)이 정했다** — 성향 · 조건 점수는 모든 모델에서 후하게 나왔을 수 있다.
- **Codex 세 모델**은 시험지 출제자(Claude)와 다른 계열이라 출제자 유리함은 없다. 다만 상용 대형 모델이고 **구독 CLI 로 문제마다 한 번** 불렀다(JSON 스키마 강제 · 추론 강도는 CLI 전역 설정값). 시간은 CLI 기준이라 API 를 바로 부르면 다르다. x600 서버에서 돌릴 수 있는 모델이 아니다 — 「작은 모델이 어디까지 따라왔나」를 재는 위쪽 기준선이다.
- **Winnow-E4B 1차 · 2차**는 Winnow-E4B Q8 원본에 우리 데이터 덧붙임(1차 `oos` · 2차 `oos2_cosine_s20261019`)을 얹어 llama.cpp 서버(생각 끔)로 불렀다. 가르친 E4B 는 Ollama 로 불렀다 — 실행기 차이가 섞여 있다. 두 Winnow 모두 이 지시문 · 답 모양으로 가르친 적은 없다.
- **Winnow 시각이 낮은 까닭(1차 원본 답 195개 분류)**: 맞음 45 · **값은 맞았는데 근거 조각(원문 시각 글자)을 비워 「원문에 없는 값은 버림」 규칙에 걸림 74** · 시각을 아예 안 냄 72 · 기타 4. 근거 규칙이 없었다면 119/195 = 61%. 2차 보강과 지시문 2판에서 71% 까지 올랐다.
- **가르친 E4B 2판의 시각 하락(89% → 74%)** 원인은 확인하지 않았다(긴 지시문이 시각 근거 쓰기를 흐린 것으로 추정). 구조 세션의 새 지시문(같은 모델)은 성향 12/18 이었다 — 같은 수준.
- GPU 서버 B 는 다른 세션의 모델 작업과 시간을 나눠 썼다(대기 스크립트로 겹치지 않게 했지만 같은 GPU 의 재현 Ollama 는 다른 세션도 부른다) — 시간 값은 흐려질 수 있다. 각 측정은 한 번씩(온도 0).

## 남은 일

1. 가르친 E4B 의 **시각 하락 없이** 성향 · 빠진 값 묻기를 올리기 — 지시문을 나눠 부르거나(이해 → 시각 근거 다시 쓰기) 이 답 모양으로 학습 자료를 더 만들어 다시 가르치기.

3. 다른 사람이 쓴 시험지로 다시 재기(어휘가 정답과 맞춰져 있는 문제).
