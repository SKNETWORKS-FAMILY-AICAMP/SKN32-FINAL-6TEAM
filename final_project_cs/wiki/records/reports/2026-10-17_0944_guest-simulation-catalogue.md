# 게스트 여행 선택·날짜·페이지 조회 구현

2026-10-17 09:44 한국 시각. 변경 담당과 검토는 이번 Codex 작업자가 겸했으며 독립 검토 완료를 뜻하지 않는다.

게스트 여행을 별도 선택상자에서 찾고, 한국 시각 기준 여행 기간에 겹치는 날짜 범위로 조회하며 10개씩 페이지를 넘기도록 구현했다. 운영 환경에는 배포하지 않았다. 요청 정본은 [여행 선택 계약](../../external/watch-simulation.md#여행-선택--2026-10-17-사용자-요청)이다.

## 변경

- 기존 감시 대상 여행과 게스트 여행의 목록·페이지·선택을 분리했다. 제목·여행 기간·짧은 식별자·조회 가능 상태를 표시한다. 날짜·페이지 변경은 이전 선택을 해제한다. 빈 결과는 날짜 조건 초기화와 목록 새로 읽기로 복구한다.
- 목록은 DB에서 테넌트·소유자 종류·날짜 범위를 거른 뒤 총 건수를 세고 페이지를 조회한다. 한국 날짜의 양 끝을 포함하며 날짜 역전·잘못된 페이지·과도한 페이지 크기를 거절한다. 끝난 게스트 여행도 찾을 수 있지만 시험 적용은 제공하지 않는다.
- 게스트는 명시적으로 켠 재난 시험이 현재 일정 판에서 유효할 때만 감시 예외로 포함한다. 입력 중지·시간 만료·판 변경 시 다시 제외한다. 다른 게스트 여행은 포함하지 않으며 기존 시험 알림의 외부 발송 차단을 유지한다. 재난 정지 중에는 새 시험을 거절하고 중지만 허용한다.

구현 입구: [목록 조회](../../../app/domains/travel_ops/entry/admin_simulation_catalogue.py), [여행 선택 화면](../../../frontend/apps/admin/src/features/operations/simulation-trip-picker.tsx), [회귀 시험](../../../tests/integration/test_simulation_guest_catalogue.py).

실서버 확인 (운영 cs 프로젝트 서버 응답): 안 했음. 신규 기능 배포와 실제 고객 여행에 재난 입력 적용은 수행하지 않았다. DB·API 시험은 새 로컬 격리 PostgreSQL DB와 FastAPI TestClient로 수행했다. 개인 환경 파일·외부 모델 API는 사용하지 않았다.

DB 시험 실행은 작업 폴더의 [격리 실행기](../../../../.tmp/guest-simulation-20261017/run_checks.py)를 사용했다. `test_simulation_guest_catalogue.py`, `test_watch_simulation.py`, `test_travel_ops_cells.py`를 실행했고 91개가 통과했다. anyio가 이미 import되었다는 pytest 경고 1개가 있었다. Python F·E9 린트, 프런트 타입 검사·수정 파일 ESLint, 공백 검사도 통과했다.

검증 도중 현재 체크아웃의 수정하지 않은 파일들이 디스크에서 빠지고 Git에는 `skip-worktree`로 표시된 상태를 확인했다. 원본 체크아웃은 복원하거나 덮어쓰지 않고, Git의 현재 커밋과 디스크에 있는 현재 변경을 별도 사본에 합쳐 전체 관리자 앱을 빌드했다. 원본 설치 라이브러리를 연결해 사용했다. 처음의 작은 화면 시험용 번들은 라이브러리를 이중으로 읽어 실패했으며 최종 근거에는 포함하지 않았다. 전체 앱 첫 화면 시험의 선택상자 탐색 중복은 역할과 정확한 이름으로 고쳐 재실행했고 4/4 통과했다.

화면 증거는 [1280px](../../../../.tmp/guest-simulation-20261017/guest-wide.png)와 [375px](../../../../.tmp/guest-simulation-20261017/guest-narrow.png)다. 화면 안 자료는 시험용 응답이며 실제 고객 건수나 운영 반영의 증거가 아니다.
