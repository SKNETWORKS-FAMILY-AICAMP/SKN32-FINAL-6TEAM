# 오프라인 연결 검증과 택시 대체 재검증

기존 확대 시험의 연결 실패 3건과 택시 대체 건너뜀 4건을 재검증했습니다. 제품 판정 조건을 완화하지 않았습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 이동 팀 연결 시험 | 통과 | 8/8 = 100% |
| 건너뛴 택시 대체 시험 복구 | 통과 | 4/4 = 100% |
| 택시 대체 시험 파일 전체 | 통과 | 5/5 = 100% |
| 오프라인 하네스 정책 시험 | 통과·제품 분모 제외 | 4/4 = 100% |

이 비율은 이번 재검증 범위이며 이동 기능 21개의 실사용 완료율이 아닙니다. 실제 탑승·결제·휴대폰 화면 검증은 수행하지 않았습니다.

## 원인과 변경

- 기존 확대 검증은 모든 socket 연결을 차단하여 Windows asyncio의 표준 내부 `socketpair()` 연결도 막았습니다. 이동 팀의 실행 본문이 시작되기 전에 연결 시험 3개가 실패했습니다.
- 예외를 현재 스레드가 표준 `socketpair()`를 만드는 동안의 숫자 루프백 주소 연결로 제한한 새 하네스를 만들었습니다. 일반 `connect`, `connect_ex`, `create_connection`과 다른 스레드의 연결은 계속 차단합니다.
- 이 PC의 실행 샌드박스에서는 하네스 없이 표준 `socketpair()`만 실행해도 8초 뒤 내부 `accept()`에서 정체했습니다. 같은 표준 IPC 재현은 샌드박스 밖에서 0.34초에 완료됐습니다. 따라서 연결 시험과 하네스 정책 시험은 일반 네트워크 차단을 유지한 채 샌드박스 밖에서 실행했습니다. 정체한 최초 시도는 중단했고 성공 결과로 집계하지 않았습니다.
- 택시 대체 시험은 로컬 도로 그래프를 요청하면서 GraphHopper 기본 주소를 비우지 않아 네트워크 차단 시 초기화 예외를 건너뜀으로 처리했습니다. 시험 초기화에 `gh_url="", seoul_key=""`를 명시했습니다. 기존 판정 조건은 그대로 유지했습니다.
