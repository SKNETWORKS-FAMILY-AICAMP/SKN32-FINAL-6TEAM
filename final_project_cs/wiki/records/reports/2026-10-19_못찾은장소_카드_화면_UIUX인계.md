# 못 찾은 장소 카드 — 화면 인계

**한 줄 요약**: 계획서나 채팅에서 장소를 못 찾으면, 서버가 이제 「후보 · 직접 고르기 · 장소 없이」 카드를 낼 재료를 준다. 화면은 그 카드를 그리고, 「직접 고르기」를 누르면 **새 화면 없이** 이미 있는 장소 검색 · 수정 모드 · 일정 추가 칸으로 넘기면 된다.

- 무료 / 유료: **무료** — 새 외부 API 없음. 후보 · 검색은 이미 있는 경로다.
- 만들 것: 카드 2곳(계획 확인 화면 일정 줄 · 여행 화면 채팅 답) + 수정 모드를 「대상 일정」 · 「추가 칸 미리 채움」으로 여는 입구.
- 서버 상태: 격리 사본 구현 · 단위 시험 통과 · **커밋 전**(commit 세션에 넘김). 배포 · 실서버 확인 0. 정본 계약은 [web-intakes.md 「장소를 못 찾았을 때」](../../external/rest-endpoints/web-intakes.md) 맨 끝 절이다.

## 결정 (2026-10-19 사용자)

- 못 찾은 줄은 **후보를 보이고 묻는다**. 확정은 고객이다(장소를 지어내지 않는다).
- 「직접 고르기」는 **수정 모드로 전환해 단계를 채팅창에서 수정 화면으로 넘긴다**. **일정 추가 상황이면 추가 모드로** 넘긴다.
- 등록 전 확인 화면에서 대화로 고르기는 아직 없다(확인 화면에 채팅 입구가 없다) — D-026 2단계에서 연다.

## 1. 계획 확인 화면 (등록 전)

`GET /v1/web/trip-intakes/{id}` 의 `prefill.questions[]` 중 `kind: "place_not_found"`:

```json
{"kind": "place_not_found", "question": "「을지로 그 집」을 지도에서 찾지 못했어요 — 후보에서 고르거나 직접 골라 주세요",
 "quote": "을지로 그 집", "item": "0-3", "source_id": "…", "index": 3, "mode": "change",
 "actions": ["pick_candidate", "pick_myself", "no_place"], "blocked": false}
```

| 화면 | 할 일 |
|---|---|
| 카드 자리 | `item` 과 같은 `items[].id` 의 일정 줄. 문장은 `question` 그대로(하드코딩하지 않는다) |
| 후보 | `GET …/candidates?source_id=&index=` 1~3 — 이미 쓰는 후보 목록과 같다. 0개면 후보 칸 없이 단추 둘 |
| 「후보」 단추 | `POST …/edits` 의 `items[n].place` 에 고른 후보 그대로(`{name, latitude, longitude, source, kind?, content_id?}`) |
| 「직접 고르기」 | 그 줄의 장소 바꾸기 · 장소 검색(`place-change.tsx` · `place-search.tsx`)을 바로 연다. **화면 전환 없음** — 계획 확인 화면이 곧 수정 화면이다 |
| 「장소 없이」 | `items[n].place = {"none": true}` |
| `blocked: true` | 문장이 「조회가 막혀 다시 찾아봤지만 …」으로 온다. 별도 표시는 선택 |

- 막혔던 조회를 서버가 다시 찾아 채운 줄은 질문 대신 `prefill.filled[]` 에 `owner: "refind"` · `reason` 으로 온다 — 지금 「우리가 채움」 표시와 같은 자리.

## 2. 여행 화면 채팅 (등록 뒤)

`POST /v1/web/trips/{id}/messages` 답(`status: "edit_refused"`, `reason: "place_not_found"`)의 `pick`:

```json
{"mode": "add", "item_id": null, "query": "민수네",
 "prefill": {"title": "민수네", "date": "2026-10-21", "starts_at": "19:00", "kind": "dining"},
 "blocked": false, "actions": ["pick_myself"]}
```

| `mode` | 「직접 고르기」를 누르면 |
|---|---|
| `change` | 「일정 수정」 아이콘과 **같은 전환**(`trip-screen.tsx` `setEditing(true)` → `trip-edit.tsx`)을 하고, `item_id` 일정이 골라진 채 그 일정의 장소 바꾸기 · 검색을 연다. 검색 칸에 `query` |
| `add` | 같은 전환 뒤 **일정 추가 칸**(`add-stop.tsx`)을 열고 `prefill` 을 미리 채운다. `ends_at` 은 고객이 끝 시각을 말했을 때만 온다. 장소 검색 칸에 `query` |

- 지금 수정 모드는 열 때 대상 일정 · 추가 칸 값을 받지 않는다(`TripEdit({trip, onExit})`) — 이 둘을 받는 입구가 필요하다.
- `pick` 은 대화 기록(`GET …/chat` 의 `turns[].reply.pick`)과 같은 요청 되풀이 답에도 실린다 — 새로 고쳐도 카드가 보이게.
- 카드에 후보는 없다(수정 모드에 그 일정의 후보 · 검색이 있다).
