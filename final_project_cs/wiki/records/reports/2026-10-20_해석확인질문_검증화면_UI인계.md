# 검증 화면의 해석 확인 질문 — UI 팀 화면 인계 (2026-10-20)

서버는 준비했다(아래 계약). 화면 구현은 UI 팀 몫이다. 서버 계약 정본: [web-intakes.md 「해석 확인 질문」](../../external/rest-endpoints/web-intakes.md). 경위 · 결정: [작업 기록](2026-10-19_사또갈비_다른안_지역말.md).

## 화면 흐름 (사용자 결정 2026-10-20)

전에는 로딩 화면 · 검증 애니메이션 화면이 있고 검증 화면과 수정 화면이 하나였다. 이제는:

1. 계획서 제출 → **검증 화면**: 애니메이션이 서버 진행 이벤트를 받아 그린다.
2. 질문이 오면 **그 자리에서 멈추고 질문 카드**를 띄운다 — 맨 위가 추천 1안(읽기 AI 의 해석), 그 아래 다른 해석, 맨 아래 「직접 선택」.
3. 고객이 고른다(= 안건 넘기기). 서버는 그동안 1안으로 계속 계산하고, 다른 안을 고르면 그 지점부터 다시 계산한다 — 그 사이도 애니메이션으로 채운다.
4. 질문을 다 넘기면 **수정 화면**으로 간다. 「직접 선택」은 곧바로 수정 화면으로 가서 그 일정의 장소 검색을 연다.

예: 계획서의 「오후 1시~4시 정도」 — 1안 「13:00~16:00 빈 시간」(추천) · 「「정돈 대학로본점」 13:00 일정(「정도」을 오타로 볼 때)」 · 「「정도」 이름 그대로 찾기」 · 직접 선택.

## 서버가 주는 것 · 부를 곳

| 하는 일 | 부를 곳 | 쓰는 값 |
|---|---|---|
| 애니메이션 · 질문 받기 | `GET /v1/web/trip-intakes/{id}/events`(SSE) | 이벤트 `interpretation` — 질문 한 건(키 `id`). 같은 키가 다시 오면 덮는다 |
| 지금 질문 다시 읽기 | `GET /v1/web/trip-intakes/{id}` | `interpretations[]`(없으면 `[]`) |
| 고른 안 보내기 | `POST /v1/web/trip-intakes/{id}/interpretations` `{revision, answers: {질문 id: 선택지 id}}` | 응답 = 조회와 같은 모양 + `interpretation: {applied, pending, revision}`. `Accept: text/event-stream` 이면 `accepted` → `stage{applying}` → `result` |
| 직접 선택 | 수정 화면의 장소 검색 `GET …/place-search?q=` | 선택지의 `action: "pick_myself"` · `query`(검색 칸에 넣을 말) |

- 질문 한 건: `{id, question(화면 문장), quote(계획서 원문), item(일정 id), options[{id, label, recommended, reason, effect, action, query}], answer, applied}`. **`options[0]` 이 추천 1안**이다(`recommended: true`). `reason` 은 1안에만 있다(「읽기 AI 가 「…」를 빈 시간으로 읽었어요」). `effect` 는 고르면 어떻게 되는지 한 줄.
- 고객이 아직 안 골랐으면 `answer: null` — 화면은 `applied`(지금 들어가 있는 안, 처음에는 1안)를 미리 고른 채 보이면 된다.
- 로딩 중에 보내면 `pending: true` 로 곧바로 답한다(저장만, 서버가 검사 끝나기 전에 반영). 로딩이 끝난 뒤에 보내면 그 자리에서 다시 계산한 결과가 온다.
- 오류: 낡은 판 409 `stale_revision`(조회해서 `revision` 을 새로 받는다) · 모르는 선택지 422 `invalid_answers` · 남의 접수 404.

## 정할 것 (UI 팀)

- 질문이 여럿일 때 차례로(1/3 · 2/3) 보일지, 「나머지는 추천대로」 단추를 둘지.
- 「못 찾은 장소」 질문(조회 `prefill.questions[]`, `kind: place_not_found`)도 같은 검증 화면 카드로 보일지 — 서버 값은 이미 조회에 있다.
- 「말로 알려 주기」는 서버에 아직 없다(확인 화면 채팅 입구 — D-026 다음 단계).
