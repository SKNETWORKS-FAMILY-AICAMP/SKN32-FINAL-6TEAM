## 미해결 — 기준 develop의 웹·서버 계약 검사

[실측] [PR #11의 CI](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN32-FINAL-6TEAM/actions/runs/36507145161)는 `tests/contract/test_web_client_contract.py:86`에서 실패했다. [기준 develop `882a19b`의 CI](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN32-FINAL-6TEAM/actions/runs/36459717414)도 같은 항목과 두 경로로 실패했다. 두 실행 모두 1,680개 중 통과 1,615개(96.13%), 실패 1개(0.06%), 건너뜀 64개(3.81%)다. 이번 PR에서 백엔드·웹 소스·계약 검사는 변경하지 않았다.

- `GET /v1/web/session`: 검사기가 `frontend/apps/web/src/lib/live/client.ts:79`의 별도 `init` 변수에 지정된 POST를 읽지 못하고 GET으로 센다. 실제 POST 라우트는 `app/modules/travel_ops/trip_api.py:911`에 있다.
- `POST /v1/web/warmup`: `frontend/apps/web/src/lib/live/extras.ts:94`에 호출이 있지만, 기준 커밋의 `app/`에서 대응 경로를 찾지 못했다. 실제 API의 채팅 모델 사전 준비 호출이 실패할 가능성이 있으며, 운영 실행은 확인하지 않았다.

재현은 CI 환경에서 `python -m pytest tests/contract/test_web_client_contract.py -q`다. 전체 명령·출력·실행 조건은 검증 기록에 남겼다. 목업 이동과 무관한 기존 결함이므로 이 PR에서 계약 검사나 API 구현을 바꾸지 않는다. 웹 검사 통과를 전체 서버 계약 통과로 해석하면 안 된다.
