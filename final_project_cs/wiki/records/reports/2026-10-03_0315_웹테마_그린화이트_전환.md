## 수행 내용

### 1. 메뉴의 테마 카드

- 메뉴의 언어 카드와 플로팅 버튼 스위치 사이에 테마 카드를 두었다([theme-picker.tsx](../../../frontend/apps/web/src/components/ui/theme-picker.tsx)).
- 「그린」(기본)과 「화이트」 두 단추가 나란히 있다.
  - 고른 쪽은 `aria-pressed`와 선택색으로 보인다.
  - 각 단추의 작은 견본은 자기 테마 색으로 그린다. 견본 요소에 `data-theme`을 따로 주었다.
- 고르면 바로 모든 화면에 적용된다. 언어·내비게이션과 같은 설정 저장소(`tripilot.web.settings.v1`)의 `theme`에 남는다.

### 2. 첫 화면 전 적용

- `<html data-theme>`이 테마를 정한다.
- 새로고침 때는 `<head>`의 짧은 스크립트([theme.ts](../../../frontend/apps/web/src/lib/theme.ts))가 본문을 읽기 전에 저장된 테마를 건다.
  - 그래서 화이트를 고른 사람에게 그린이 잠깐 보이지 않는다.
  - 방식은 Next.js 16 안내서 「Preventing flash before hydration」의 테마 예를 따랐다.
- 그 뒤의 변경은 `Providers`가 반영한다.

### 3. 색 역할 변수

- [tokens.css](../../../frontend/apps/web/src/styles/tokens.css)에 화이트 블록(`[data-theme="neutral"]`)을 더했다.
  - 그린과 같은 33개 역할을 모두 정의한다. 값은 사용자가 확인한 표 그대로다.
- 버튼(`primary`)·선택(`selected`)·성공(`success`)·조정(`adjusted`)·확인 필요(`warning`)·오류(`error`)는 따로 둔다.
  - 그린에서는 선택색이 버튼색과 같다.
  - 화이트에서는 선택색이 파랑(#2457d6)이다.

### 4. 직접 적은 색 바꾸기

- 화면 CSS 18개 파일의 직접 적은 색을 역할 변수로 바꿨다(작업 전 약 110곳).
- 반투명 색은 `color-mix(in srgb, var(--color-…) N%, transparent)`로 같은 투명도를 지킨다. 예: `#24392f33` → 글자색 20%.
- 그린과 값이 조금 다른 색은 가장 가까운 역할이나 섞은 값으로 옮겼다. 예: 페이지 바탕 `#f4f6f0` → `--color-background` `#f3f5f3`.
- 선택 상태는 선택 역할로 옮겼다(그린에서는 겉보기가 같다).
  - 언어 선택지, 취향 칩, 여행 화면의 선택한 일정, 지도 개념도의 선택한 점
- CSS 밖의 색:
  - 지도 핀([pin.ts](../../../frontend/apps/web/src/features/map/providers/pin.ts)): 선택 = 선택색, 보통 = `soft`
  - 취향 카드 누름 효과([preferences.tsx](../../../frontend/apps/web/src/features/onboarding/preferences.tsx))
- 기본 프로필 이미지(`Avatar`)
  - SVG 파일(`<img>`)은 페이지의 변수를 읽지 못한다.
  - 그래서 같은 모양을 화면에서 직접 그리고 `soft`·`primary` 역할을 쓴다.
  - `public/images/tripilot-avatar-default.svg`는 이제 쓰이지 않지만 지우지 않았다(삭제는 승인 대상).

### 5. 장식 배경

- 풍경 그림(`Scene`)과 소개 화면 배경 그림은 그린에만 있다.
- 화이트에서는 바탕색만 남긴다.
- 풍경 위의 막·빛 색(`scene.module.css`)은 그림에 딸린 색이라 그대로 두었다. 직접 적은 색이 남은 유일한 화면 CSS다.

### 6. 재발 방지 시험

[tokens.test.ts](../../../frontend/apps/web/src/styles/tokens.test.ts)는 세 가지를 본다.
- 두 테마의 역할 목록이 같은지
- 테마 이름과 첫 화면 전 스크립트가 맞는지
- 화면 CSS에 직접 적은 색이 없는지(`tokens.css`·`scene.module.css` 제외)

## 작업 중 바로잡은 것

- **demo 1개 실패(`profile.spec.ts`)**
  - 원인: 시험이 마이페이지의 프로필 이미지를 `#main-content img`로 찾았는데, 이미지를 `<svg>`로 바꿔 찾지 못했다.
  - 조치: 선택자를 `svg[class*="avatar"]`로 고쳤고, 그 파일 6/6이 통과했다.
- **live 2개 실패(`flow.spec.ts` 119·148행)**
  - 원인: live 전체 시험이 도는 중에 profile 시험을 따로 돌렸다. 그 실행이 같은 `test-results` 폴더를 비우면서 live 실행의 기록 파일이 사라졌다(`ENOENT … .trace`). 화면 검사의 실패가 아니다.
  - 조치: 두 시험을 다시 돌렸다(결과는 아래 검증 표).
- **`next/script`를 쓰지 않은 이유**: 처음에는 그것으로 스크립트를 넣으려 했다. 하지만 안내서의 `beforeInteractive`는 「페이지가 읽히는 것을 막지 않는다」고 적혀 있어, 그린이 잠깐 보일 수 있다. 그래서 안내서의 깜빡임 방지 예처럼 `<head>`에 직접 넣었다.
- **설정 키를 클라이언트 파일에서 가져오지 않은 이유**: `"use client"` 파일(`settings.ts`)의 상수를 서버 레이아웃에서 가져오면 값이 아니라 참조가 된다. 그래서 테마 이름·저장 키·스크립트를 클라이언트 표시가 없는 `lib/theme.ts`로 뺐다.

## 남은 문제·다음 작업

1. **쓰지 않게 된 파일**: `public/images/tripilot-avatar-default.svg`. 지울지 대상을 보이고 승인받는다.
2. **CSS 마감(Codex)**: 남은 과제는 [인계 문서 §5](../../../frontend/apps/web/PLAN_CHECK_SCREEN.md#5-codex-css-인계)에 있다(지도 칸 크기, 지도 위 시트, 경로 선, 320px 목록 길이, 미리보기 조작 막대).
3. **화이트 테마 세부 모양**: 이번에는 같은 역할의 값만 바꿨다. 목업의 모서리·그림자·간격 같은 화면별 모양 차이는 맞추지 않았다.
4. **PC 화면**: 화이트에서 폭을 제한해 가운데 두는 배치는 기존 틀(기기 틀·여정 틀)을 그대로 쓴다.
