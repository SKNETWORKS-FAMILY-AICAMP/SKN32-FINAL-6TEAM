# 사용자 웹에 남은 「마이페이지」 문구 — 안내 문구 반영, 약관 쪽은 보류

| 항목 | 내용 |
|---|---|
| 수행 | 2026-10-13 · Claude(최상욱 작업) · TeamFlow ST4F-205 |
| 저장소 · 브랜치 | SKN32-FINAL-6TEAM / `role-eval-ui`(작업 시작 = develop `e0e124c3`, PR #48 병합 직후) · 보류분은 `feat/terms-mypage-wording` |
| 커밋 | 안내 문구 = 이 리포트와 같은 커밋 · 약관 쪽 = `feat/terms-mypage-wording` 브랜치(PR 은 열지 않았다) |
| 서버 변경 | 반영분 없음. 보류분에 설정 값 하나(`config/guardrails.yaml` `consent.terms_version`) |

PR #48(메뉴 = 마이페이지 · `/mypage` 는 설정 화면)로 「마이페이지」라는 화면이 없어졌는데, 그 이름을 가리키는 문장이 앱 안내 하나와 약관 본문 여섯 곳(한국어 · 영어)에 남아 있었다([앞 리포트](2026-10-13_1655_웹_브라우저시험맞춤_메뉴이름_develop병합.md) 5절). `[2026-10-13 사용자 지시]` 「지금 작업하는 사람이 없으니 우리가 작업을 하고 이 사항 때문에 변경했다고 남기자」로 둘 다 고쳤고, 반영 시점을 다시 보고 `[2026-10-13 사용자 결정]` **안내 문구는 지금, 약관 쪽은 나중**으로 나눴다.

## 1. 결론

- **반영(develop PR)**: 여행을 못 찾을 때의 안내 「계정에 보관한 여행이라면 마이페이지에서 로그인하면 다시 열려요」 → 「… **메뉴의 「로그인 · 가입」으로** 로그인하면 …」(영어도). 글자만 바뀌고 다른 영향이 없다.
- **보류(브랜치에 보관)**: 약관 본문 여섯 곳의 「마이페이지」 → 설정 › 「약관 · 동의」 / 「알림 받는 곳」, 그리고 약관 글이 바뀌므로 **웹 `TERMS_VERSION` · 서버 `consent.terms_version` · 시험 모방 서버를 함께 `2026-10-13.1`** 로 올리는 변경. 배포되면 모든 이용자가 약관에 다시 동의한다.

## 2. 약관 쪽을 보류한 까닭

1. **다시 동의가 두 번 생긴다** — 서버에 「서비스 개선」 선택 동의(`service_improvement`)가 아직 없어(develop 의 `consents.py` `CODES` 다섯, `wiki/external/web-screen-api.md` 협의 표) 그것을 넣을 때 약관 버전을 어차피 다시 올린다. 지금 올리면 이용자는 두 번 다시 동의한다. 함께 올리면 한 번이다.
2. **급하지 않다** — 약관이 말하는 것(어디서 철회 · 변경하는가)은 그대로이고 가는 길의 이름만 옛것이다.
3. **브랜치 충돌을 한 번만 푼다** — `role-manager` 는 이 줄이 이미 `2026-10-10.1` 이다. 지금 develop 에서 바꾸면 매니저가 develop 을 받을 때 맞춰야 한다.
4. 최종 발표(10-26) 앞의 시연 중에 다시 동의 화면이 뜨지 않게 한다.

## 4. 알아 둘 것

- **약관 버전은 서버가 정한다.** 웹은 서버의 `GET /v1/web/legal/retention` 이 주는 `terms_version` 으로 동의를 기록하고(`features/consent/terms-live.ts`), `TERMS_VERSION` 은 서버가 값을 주지 않을 때의 기본값이다. develop 에서는 서버 `2026-10-07.1` · 웹 `2026-10-10.1` 로 어긋나 있다 — 동의 저장을 막지는 않지만, 웹의 글이 바뀌면 같은 버전 이름에 다른 글이 기록될 수 있다. 그래서 약관 글을 고칠 때는 서버 값도 함께 올려야 한다.
- **배포**: 서버의 자동 반영은 서버에만 있는 `autodeploy.conf` 의 브랜치를 따른다(`deploy/README.md`). 2026-10-12 기록은 「자동 반영은 `role-manager` 를 따른다」(`records/reports/debugs/2026-10-12_1305_공개배포_버전표시값_자체불일치.md`) — 그대로라면 develop 에 올린 것은 `role-manager` 가 develop 을 받을 때 공개 서버에 간다. 지금 설정은 서버에서만 볼 수 있어 확인하지 못했다.
- 이용약관 제3조는 약관을 바꿀 때 내용과 시행일을 미리 알리게 적고 있다 — 보류분을 반영할 때 고지 여부도 함께 정한다.
