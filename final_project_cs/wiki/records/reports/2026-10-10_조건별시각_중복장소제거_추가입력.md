# 조건별 시각 고정·중복 장소 제거·추가 입력 우선

일반 접힌 일정의 시각은 원래 위치와 함께 스크롤한다. 펼침·검토 필요·해당 일정 되돌리기 가능 상태에만 따라오게 했다. 직접 수정의 중복 장소 입력은 제거했고 일정 추가는 입력 폼부터 시작한다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 요청한 수정 | 완료 | 3/3 = 100% |
| mock 서버 화면 시험 | 통과 | 18/18 = 100% |
| 관련 단위 시험 | 통과 | 23/23 = 100% |
| 정적 검사·생산 빌드 | 통과 | 3/3 = 100% |
| 화면 촬영 | 완료 | 12/12 = 100% |

시각 조건은 카드 펼침, 검토 필요, 시간 되돌리기, 삭제 대기 복원, 현재 화면에서 저장한 변경의 전체 복원 가능 여부를 해당 일정별로 검사한다. 이전 조회 응답의 변경 표시만 있는 일반 접힌 일정에는 적용하지 않는다. 초점 일정의 시작/끝 두 줄과 굵기·진입 애니메이션은 유지한다.

직접 수정은 상단 장소 검색만 제공하고 기존 장소 값을 내부 초안에 보존한다. 일정 이름·날짜·시작·끝 및 장소 없음 선택은 유지한다. 날짜는 한 줄, 시작·끝은 다음 줄로 나누어 휴대폰의 시각 글자 잘림을 줄였다. 저장 거절 문장과 입력은 유지한다.

일정 추가는 입력 폼(Pattern 3)으로 연다. 빈 검색어에서는 요청을 보내거나 검색창을 자동으로 펼치지 않는다. 입력한 검색어가 있으면 결과로 바꾸고 검색어 지우기·장소 선택 뒤에는 초안을 보존한 폼을 표시한다. 선택한 실제 장소 좌표와 이름을 기존 /edits로 저장한다. 장소 미선택 제출은 상단 검색으로 초점을 옮기며 오류 문장과 검색창을 연결한다. 지우기 단추를 누를 때 검색창이 먼저 줄어 클릭이 빗나가던 문제는 포인터 누름에서 초점을 유지해 해결했다. 기존 저장 중 보호·스와이프 취소·취소 후 초점 복귀·앞뒤 이동 재검사를 보존했다.

mock 서버 시험 18/18 (화면 반응). 새 동작8개와 기존 상단 검색/선택2·배경 취소1·저장 중 보호1·펼친 시각1·직접 수정 거절/검증2·수정 상단 검색1·장소 없음1·시간 드래그1을 최종 빌드에서 한 번에 확인했다. 초기 새 시험은 검색어 지우기 클릭 문제로2개 실패했고 실제 코드를 수정했다. 이후 기존 시험2개는 새 폼의 실제 빈 배경 및 카드 끝 이전의 고정 구간을 검사하도록 조정했다. 첫 단위 실행은 Windows sandbox 임시 SSR 파일 읽기 때문에 두 suite를 읽지 못했고 정상 실행 환경에서23/23을 확인했다. 실패와 재검증 집계를 근거에 보존했다.
