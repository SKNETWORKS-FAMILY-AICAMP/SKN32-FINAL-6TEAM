# 목록 끝 제출 버튼 자동 표시

완료 목록의 맨 아래에서는 스크롤 중에도 제출 버튼을 바로 표시하도록 로컬 수정했습니다. 스크롤만으로 제출 요청을 보내지 않으며, 다시 위로 움직이면 기존 숨김·유휴 복귀를 유지합니다.

| 확인 | 결과 | 진행 |
|---|---|---|
| mock 서버 시험 (화면 반응) | 관련 최종 시험 통과 | 11/11 = 100% |
| 정적 검사 | ESLint·TypeScript 통과 | 2/2 = 100% |
| Chrome 촬영 | 휴대폰·PC, 일반·동작 줄임 | 4/4 = 100% |

실서버 확인 (서버 응답): 안 했음. x600 서버의 cs 프로젝트 서버 공개 배포와 실제 접수 응답 확인은 하지 않았습니다. 이번 변경은 웹의 표시 조건이며 API·권한·제출 요청 내용은 바꾸지 않았습니다.

## 원인과 수정

- 제출 버튼은 목록의 스크롤 활동이 끝난 뒤 800ms를 기다려 복귀했습니다. 목록 끝 여부를 구분하지 않아 끝에 도달한 동안에도 숨었습니다.
- 목록 끝의 남은 높이가 2px 이하면 유휴 숨김만 해제합니다. 소수점 스크롤 위치를 허용하며, 스크롤·목록 크기·내용 변경 때 다시 측정합니다. 최소 접힘과 지도 이동 중 숨김은 우선합니다.
- 접었다 펼칠 때 기존 유휴 타이머가 정리되면서 새 타이머를 잡지 않아 숨김이 남는 경우도 발견했습니다. 다시 펼칠 때 유휴 복귀를 재개하도록 수정했습니다. 날짜 줄의 기존 숨김·초점·지도 드래그 동작은 유지했습니다.

## 검증과 실패 기록

[최종 Chrome 결과](../evidence/2026-10-11_submit-at-list-end/chrome-final.json)는 실제 설치된 Chrome과 mock 서버, production 빌드로 실행한 11개 시험입니다. 375px·1280px에서 일반/동작 줄이기 각각 확인했습니다. 800ms 유휴 복귀보다 빠른 250ms 안에 끝의 숨김 상태가 해제되는지, 계속 끝으로 스크롤해도 유지되는지, 위로 스크롤하면 숨는지, 키보드 초점을 받을 수 있는지, 스크롤 자체로 재검증·등록 요청이 나가지 않는지 검사했습니다. 접힘 우선·다시 펼친 뒤 복귀·날짜 줄·지도 드래그 중 숨김도 확인했습니다.

초회 확장 실행은 [13/16 통과](../evidence/2026-10-11_submit-at-list-end/chrome.json)였습니다. 새 접힘 복귀 시험 1개가 유휴 타이머 문제를 찾아 수정했습니다. 나머지 2개는 기존 지도 도구 높이를 40px로 기대했으나 현재 코드가 44px인 시험입니다. 지도 도구 44px는 이전 내 위치 버튼 작업에서 이미 적용된 크기이며 이번 수정은 지도 CSS를 바꾸지 않았습니다. 이 2개를 고쳐 통과했다고 보고하지 않습니다. 관련 날짜·제출 동작 11개를 선택해 수정 후 모두 재검증했습니다. 제품 전체 시험 통과로 일반화하지 않습니다.

[정적 검사](../evidence/2026-10-11_submit-at-list-end/static-final.json) 종료 코드는 모두 0입니다. [촬영 모음](../../../frontend/apps/web/mockups/submit-at-list-end-2026-10-11-v1/index.html)은 목업 지도와 실제 화면 4장을 담습니다. 새 애니메이션은 추가하지 않았으며 기존 동작 줄이기 설정에서 위치 이동 효과가 없는 것을 확인했습니다.
