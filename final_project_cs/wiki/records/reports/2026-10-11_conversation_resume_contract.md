# 웹 업무 실행과 추가 답변 계약

사용자 요청: 웹 채팅의 팀 실행 우회, 질문 후 완료 처리, 추가 메시지 누락을 수정한다. 기존 변경을 보존하며 배포·커밋·푸시는 하지 않는다.

## 인터페이스와 경계

- `Controller.resume`은 `message: str | None`, `expected_version: int | None`을 추가로 받는다. 고객 입력 대기는 공백 답변으로 토큰을 소모하지 않는다. 답변은 마스킹 후 상태와 이벤트에 저장하고, 팀 입력에는 원래 요청과 답변을 함께 전달한다. `current_state.customer_input`에는 최신 답변, `customer_input_history`에는 순서가 보존된 답변 목록을 전달한다.
- 같은 재개 요청은 한 번만 실행한다. 다른 답변으로 같은 요청 식별자를 재사용하면 충돌로 처리한다. 잘못된 토큰은 다른 고객의 대기 상태를 파괴하지 않는다. 만료 토큰만 기존 만료 정책으로 처리한다.
- 대기 결과의 질문·근거·필수 입력 스키마는 저장한다. 토큰 원문은 DB에 저장하지 않는다. 재개 토큰은 해당 실행의 반환값으로 전달하며 공유 Controller 객체의 전역 임시값에 의존하지 않는다.
- 웹 메시지에 선택적인 `case_id`, `resume_token`, `expected_version`을 추가한다. 대기 답변은 같은 여행·고객의 Case에 연결한다. 명시적 연결이 없으면 해당 여행의 단일 입력 대기 업무만 자동 연결하고, 여러 업무가 대기하면 명시적인 선택을 요구한다.
- 토큰을 잃은 로그인 고객의 웹 재개는 내부 `resume_customer_input`으로 처리한다. 이 입구는 고객·여행 소유권과 고객 입력 대기 상태를 확인하고, 만료·일회성·중복 제한을 그대로 적용한다. 공개 Case API에는 별도 우회 입구를 만들지 않고 기존 메시지 요청의 인증을 사용한다.
- 웹의 일정 변경·신고·되돌림은 실제 등록 Team의 `execute`를 거쳐 `ActionProposal`을 만들고 Controller의 공통 적용 경로에서 한 번만 적용한다. 대안 조회는 Team이 후보를 보여 주며 입력 대기로 남기고, 선택 답변에서 같은 업무를 재개한다. 사실 조회는 읽기 경로로 유지한다. 팀 내부에서는 일정 저장·알림 발송을 하지 않는다.
- 부족한 고객 정보는 `waiting_input`으로 저장한다. 답변으로 부족한 정보가 채워지지 않으면 질문을 유지한다. 모호한 대상은 임의 선택하지 않는다.
- 질문 스키마의 `x-conversation`에는 서버가 확인한 업무·대상을 보존해 연속 질문에서도 앞서 채운 입력을 유지한다. 고객의 대상 선택으로 담당 팀이 달라지면 인증·토큰·버전 검증 뒤 `resuming` 상태에서 `ROUTED`를 기록하고 실제 등록 팀으로 재개한다. 내부 `resume_route`는 도메인이 제공하고 공개 HTTP 요청에서는 받지 않는다.
- 공개 Case 메시지에서 토큰을 잃은 경우에도 `case:write` 권한으로 같은 테넌트 Case의 소유권 조회를 통과한 고객 입력 대기 업무만 인증된 재개로 연결한다. 승인·외부 콜백 대기는 이 방식으로 넘기지 않는다.
- 내부 `resume_route`는 팀 이름 또는 `{owner_team_id, state_patch}`를 반환할 수 있다. patch는 업무·입력 스키마 등 허용 필드만 저장하며 토큰·고객 답변·재개 이력을 덮어쓰지 못한다. 자유 답변은 기존 신고 추출기로 한 번 읽고 해석 결과와 실제 담당을 같은 감사 이벤트로 보존한다.
- `AppliedAction.answer`는 실제 적용 결과의 안내를 선택적으로 반환한다. 보호 조건 때문에 일정 변경 대신 제안만 열린 경우 Team 초안의 ‘바꿨다’는 문장을 실제 질문으로 바꿔 저장하며, 중복 요청에도 같은 안내를 사용한다.
- 웹은 입력 대기 업무 식별자·토큰·버전을 JSON과 SSE 모두에서 다음 답변에 연결한다. 토큰은 브라우저 메모리에만 보관하고 대화 기록이나 영구 저장소에는 넣지 않는다. 새로 고침 뒤에는 인증된 소유권 확인으로 재개한다.

## 검증 기준

여행 사례로 답변 본문 전달, 같은 Case의 대기→재개, 잘못된 답변·토큰, 중복 요청, 팀 실행 호출, 일정·알림의 단일 적용을 검증한다. 기존 웹 응답·사실 조회·되돌림 회귀 시험을 함께 실행한다.

## 작업 경계

공통 재개 스트림: `app/application/controller.py`, `app/application/case_service.py`, `app/presentation/api/cases.py`와 해당 공통 재개 시험. 웹 스트림: `app/domains/travel_ops/`, 조립부, 웹 메시지 클라이언트와 웹 시험. 스트림 간 파일 변경을 겹치지 않는다.
