# 여행 API — 확정 시나리오를 제품 입구로 통과시켰다 (2026-09-14)

지시: `team_branch/jh/확정_시나리오_액티비티_수정_버전.md` 의 시나리오가 동작 확인될 때까지 개발.
앞 단계(`e2abe6c`)는 도메인 함수를 직접 불러 여섯 장면을 재생했다. 이번엔 **HTTP 입구**와
**감시 스위퍼**를 붙였다.

## 만든 것

| 무엇 | 어디 |
|---|---|
| 여행 API 다섯 + 계획서 링크 | `app/modules/travel_ops/trip_api.py` — 계약은 `wiki/external/rest-endpoints.md` 「여행 API」 |
| 재요청 ① 다른 안 교체 · ② 되돌림 | `TripDesk.swap_alternate` · `TripDesk.rollback` |
| 다른 안을 **적용 가능한 값으로** 보관 | `replan.alternate_record` → 항목 `detail.alternates` (전엔 이름만 있어 재요청 때 다시 계산해야 했다) |
| 이동 항목이 경로 정의를 들고 다님 | 등록 시 `detail.route_def` — 스위퍼가 바깥 `routes` 없이 돈다 |
| 감시 스위퍼 | `python -m scripts.run_sweepers --only trip` — 실제 소스, `fatal` 이면 stderr + exit 1(결정 15) |
| 등록 멱등 | 마이그레이션 `016_trip_request_key.sql`(부분 UNIQUE). 015 는 보류 중인 DROP 몫이라 건너뜀 |
| scope | `trip:read` · `trip:write` (`config/guardrails.yaml`) |

★라우터가 `app/modules/` 에 있는 이유 — presentation 은 도메인을 import 하지 못한다
(INV-CS-ARCH-001). `composition.build_domain_routers()` 가 만들어 `create_app()` 에 넣는다.

## 브라우저로 열어서 찾은 결함 둘

1. **두 번째 여행이 기존 장소를 적으면 500.** `places` 는 테넌트 안 `(name, kind)` UNIQUE 인데
   등록이 무조건 INSERT 했다. 시험은 여행마다 테넌트를 새로 만들어 못 잡았다.
   → 있으면 그 장소를 쓰고, 보낸 속성은 **빈 칸만 채운다**(`EXCLUDED || places`).
   회귀 시험 `test_a_second_trip_reuses_known_places_without_overwriting_them`.
2. **계획서 기록에 내부 이름**(`customer_report · delay`)이 그대로 보였다 → 한국어 표기.

☆개발 서버가 `--reload` 인데도 옛 코드로 돌았다(추적 줄 번호가 새 파일의 주석을 가리킴).
  재기동으로 해결. 원인은 안 캤다.
