# 숙소 · 항공(확장 에이전트) 원장 — 연결 안내

- 날짜: 2026-10-12 · 작성: 서유현(숙소 · 항공 담당) · 브랜치 `role-lodging`(→ `role-booking`). develop · role-manager 에는 넣지 않았다.
- 대상: 팀장(공용 부품 · 조립 · 마이그레이션 번호 담당)

## 한 줄 요약

숙소 · 항공 팀은 MCP(마이리얼트립 · Ignav · 구글)에서 후보를 받아 DB 가 없다. 요식 팀의 원장(`dining.*` · `instances/dining/nearby.py`)과 같은 모양으로 **우리 원장**을 만들고 조립에 꽂았다. **부르는 줄**(공용 부품 안)은 넣지 않았다 — 아래 「부르는 곳」에 적은 자리에 넣으면 붙는다. 넣기 전까지는 지금 길 그대로 돈다.

## 왜 필요한가

1. **보여 준 후보 기억** — 「바꿔 줘」마다 새 후보 3개를 내고 앞서 보여 준 것은 뺀다. 지금은 일정 항목 상세(`detail.shown`)에 남기려고 `itinerary.apply`(상세만 변경)를 내서 **후보를 보여 줄 때마다 일정 판이 하나 오른다.**
2. **고른 숙소의 장소** — 고객이 고른 숙소는 장소 표(`places`)에 없다. 적용기(`components/actions/itinerary_actions.py`)는 장소 표에 없는 `place_id` 를 거부하므로 지금은 `place_id` 를 비우고 이름 · 좌표 · 링크를 `detail.chosen` 에 둔다 → 지도 핀처럼 장소 표를 읽는 화면에 안 나올 수 있다(확인 안 함).

요식 팀은 원장 가게를 **그 여행 전용 장소**로 들여놓아(`TripStore.adopt_places`) 후보가 진짜 `place_id` 를 갖는다. 같은 방식을 쓴다.

## 부르는 곳 (공용 부품 — 넣지 않았다, 팀장 판단)

Case 경로의 팀은 DB 에 쓰지 않는다. 요식 팀도 들여놓기는 대화 부품(`TripDesk._add_nearby`)이 꽂힌 자리를 부른다. 같은 자리 두 곳이 필요하다.

1. **고를 때 들여놓기** — 고객이 숙소 후보를 고르는 처리에서, 적용 직전에:
   ```python
   from app.domains.travel_ops.components.team_hooks import lodging_ledger
   place = lodging_ledger.adopt_option(conn, store, trip_id, picked)   # 미등록 · 좌표 없음이면 None
   if place is not None:
       picked = {**picked, "place_id": place["place_id"]}             # 이후 plan_swap / 적용기가 그 장소를 본다
   ```
   후보 자리: `components/planning/pending.py` `choose()` 의 `catalog_place` 처리 바로 옆(관광공사 후보를 같은 자리에서 등록한다), 또는 숙소 팀 결과의 `itinerary.apply` 를 적용하는 적용기 앞.
2. **보여 줄 때 기억하기** — 숙소 · 항공 팀 결과(`decisions[0].itinerary == "customer_request"` 이고 알림 `reason == "requested_options"`)가 완료될 때:
   ```python
   key = lodging_ledger.item_key(kind, item_detail["query"])
   lodging_ledger.remember_shown(conn, tenant_id, trip_id, key, notice["options"] 또는 item_detail["alternates"], case_id=case_id)
   ```
   이 줄이 들어오면 숙소 · 항공 팀이 「보여 준 것」을 원장에서 읽도록(도구 하나 — 예 `read.lodging_shown`) 바꾸고, 항목 상세를 바꾸는 `itinerary.apply` 를 빼서 **일정 판이 오르지 않게** 할 수 있다(우리 쪽 후속).

## 지금 상태로 동작하는 것

- 조립에 등록만 되어 있고 부르는 곳이 없으므로 **동작은 바뀌지 않았다** — 숙소 · 항공 팀은 전처럼 `detail.shown` · `detail.alternates` 를 쓰고, 고른 숙소는 `place_id` 를 비운다.
- 시험: 가짜 연결 · 저장소로만. 마이그레이션은 로컬 DB(127.0.0.1:5433)가 꺼져 있어 **적용해 보지 않았다.**
