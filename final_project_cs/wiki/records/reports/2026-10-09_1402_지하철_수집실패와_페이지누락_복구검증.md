# 지하철 수집 오류·페이지 누락 복구 검증

수집 실패가 정상 빈 시간표로 남는 원인을 두 수집 진입점에서 수정했습니다. 현재 경로 정확도가 좋아졌다는 결과는 아니며 기존 시간표를 보존했습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| API 오류 재현 | 두 진입점 확인 | 2/2 = 100% |
| 새 수집 계약 검사 | 통과 | 38/38 = 100% |
| 기존 포함 관련 검사 | 통과 | 505/505 = 100% |
| 공덕 완전 공식 표 확보 | 조회 장애 | 0/4 = 0% |

## 문제와 원인

기본 수집은 HTTP200 body의 결과코드를 확인하지 않고, 실패도 빈 dict로 돌려준 뒤 완료 목록에 넣었습니다. 재조회도 오류 body를 ok 빈 자료로 처리했습니다. 인증 오류 코드30을 넣은 동일 통제 입력에서 두 함수 모두 잘못 수용한 것을 [수정 전 재현](../evidence/2026-10-09_1357_지하철_수집실패_완료오인_수정/before-reproduction-v1.json)에 보존했습니다. 단일 첫 페이지(요청1000행)만 읽던 것도 전체 건수와 대조하지 않았습니다. 실제 보유 자료의 오류/누락 규모는 아직 미계측입니다.

## 해결한 범위

공통 응답 검사는 정상 코드(00/0000)·구조·전체 건수·페이지 번호와 크기·행수·반복 페이지를 검사합니다. 모든 페이지가 맞아야 성공을 반환하며, 오류와 빈 정상 자료를 구분합니다. 일시 오류만 제한 재시도하고 인증/일일 한도 오류는 반복하지 않습니다. 오류 메시지에는 인증값·요청 URL·제공처 본문을 넣지 않습니다.

원문 행은 raw_item에 보존하고 수집시각을 적습니다. 없는 열차 종류/번호/정차 여부는 만들지 않습니다. 기존 출력은 첫 쓰기 전 백업합니다. 검증 성공 조합은 행 flush/fsync 뒤 완료 JSON을 임시 파일 교체로 저장하므로 다음 API 오류 때 앞 성공 항목이 사라지지 않습니다. 두 파일 전체를 한 거래로 기록하는 것은 아니므로 전원 장애 사이 중복·동시 수집은 미해결입니다.

수정 파일: [공통 검사](../../../../datasets/mobility/scripts/_tago_checked.py) · [기본 수집](../../../../datasets/mobility/scripts/tago_subway_collect.py) · [빈 조합 재조회](../../../../datasets/mobility/scripts/tago_retry_empty.py) · [신규 시험](../../../tests/unit/travel/mobility/test_tago_collection_integrity_v1.py). 기존 가공 시간표·공표 승차 대조 파일과 제품 계산은 바꾸지 않았습니다.

## 검증과 근거

[명령·원문](../evidence/2026-10-09_1357_지하철_수집실패_완료오인_수정/related-v2-run.json) · [로그](../evidence/2026-10-09_1357_지하철_수집실패_완료오인_수정/related-v2.log) · [Ruff2파일](../evidence/2026-10-09_1357_지하철_수집실패_완료오인_수정/ruff-v2.log) · [수집 관련3파일 구문 검사](../evidence/2026-10-09_1357_지하철_수집실패_완료오인_수정/syntax-v1.json). 첫 실행37/37 통과 후 미사용 import의 Ruff 실패1건을 수정했고, 성공 조합 뒤 오류를 다루는 검사1건을 추가했습니다. 기존 정규식 SyntaxWarning1개는 남았습니다. 통제 HTTP 응답 주입 시험이며 독립 운행 검증이 아닙니다.

mock 서버 시험(화면 반응): 안 했음, 0건.

실서버 확인(서버 응답): cs 프로젝트 서버 HTTP 확인 안 했음, 이번 실제 TAGO/지도 개발자 API 호출0회. 전체 수집이나 기존 원자료 가공을 실행하지 않았습니다.

공덕 공식4그룹은 웹 직접 조회 오류, 공식 도메인 검색에서 다른 역 결과만 표시, 기존 브라우저 탭 본문 미표시로 이번 확보0/4입니다. 공급자 전체 불가로 결론 내리지 않았습니다. [조회 범위와 한계](../evidence/2026-10-09_1357_지하철_수집실패_완료오인_수정/source-assessment-v1.json).

공공데이터포털 [TAGO 공식 안내](https://www.data.go.kr/data/15098554/openapi.do)는 역별 시간표의 페이지 분할과 인증/한도/형식 오류를 구분합니다(수정일2026-03-05). 안내 페이지를 확인했으며 이번 정상 실응답과 docx 가이드의 상세 필드는 재확보하지 않았습니다.
