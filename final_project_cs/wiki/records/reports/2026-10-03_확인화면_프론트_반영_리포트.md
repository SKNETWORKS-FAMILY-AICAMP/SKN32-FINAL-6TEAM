## 같이 고친 결함 (실제 서버 확인 중 발견)

1. 완료된 계획을 다시 열면 읽기 연출이 **다시 재생**되던 것 → 스트림은 「아직 읽는 중」일 때만 연다.
2. 카드를 누르면 틀이 **옆으로 밀리던** 것(`scrollIntoView`) → 시트 안쪽만 세로로 움직이게, 틀은 `overflow: clip`.
3. **서버**: 사진 조회가 후보가 주는 `place:<uuid>`(42자)를 길이 제한(40자)으로 422 거절 → 80자로 늘림(시험 추가).
4. 자동 추천 안내가 `[object Object]` 로 나오던 것(응답의 장소는 객체) → 타입과 문구 수정, 시험 추가.
5. 지도 화면에서 연결이 끊겨도 안내가 없던 것 → 시트 맨 위에 안내.
6. 서버가 줄을 이벤트로 알렸지만 접수 조회에는 아직 없는 경우 화면에 줄이 비던 것 → 스트림의 줄도 보충.
7. **새 키 안내가 새 화면에서 빠져 있던 것**(자동 시험이 잡음) → 휴대폰 틀 안에도 「내 여행 열쇠를 따로 보관해 주세요」를 한 번 띄운다.

## 한계 · 알려 둘 것

- **코덱스 아스트라를 못 썼다**(주 계정 사용 한도 소진, 보조 계정에는 모델 없음). 디자인은 목업이 정해 둔 것이라 직접 옮겼다.
- **디스크 가득 참 사고**(C: 100%): 파일 하나(`stub-server.mjs`)가 0바이트로 잘려 커밋본에서 복구했고, npm 캐시(1.5GB, 재생성됨)를 지워 1GB 남짓 확보했다. 앞서 개발 DB가 반복해서 죽은 것과 빌드·시험 실패의 원인일 수 있다. 큰 용량 정리는 사용자 몫(`Documents` · `AppData` · `.codex` 등).
- **개발 DB**: 두 번 죽어 문서 절차로 다시 띄웠다. 도구 안에서 `pg_ctl` 로 띄우면 도구 작업이 끝날 때 같이 죽는 것도 확인(메모리에 기록).
- 백엔드 단위 시험 **전체 재실행은 끝내지 못했다**(메모리·디스크 부족으로 중간에 죽음) — 백엔드 리포트 참고.
- 자동 추천의 대체 후보가 어색한 경우가 있다(남산타워 → 기념품 가게). **서버 후보 순위** 문제로 이 화면의 몫이 아니다.
- 서버 문장 중복: 직접 고른 곳의 「장소」 줄이 「직접 고른 곳이에요 · 직접 고른 곳」 으로 겹쳐 나온다(서버 문구).
- 알림 칸(문제 목록 · 일정 짜기 패널)은 목업에 자리가 없어 시트 맨 위에 평범한 카드로 둔다 — 디자인 검토 필요.
