# 발견 사항

1. **P1 — 다른 탭과 새 회원 세션에서 이전 계정 diff 잔존.** `src/lib/live/client.ts:55`의 정리는 이 탭의 `sessionStorage`만 순회하며 null 세션일 때만 실행됩니다. 실제 Next 앱·Edge의 같은 browser context에 탭 둘을 열고 A 탭 로그아웃 UI 성공 후 다른 탭의 A 비공개 장소 문자열을 조회했으며 그대로였습니다. 그 탭을 새 회원 세션 B를 모사한 성공 `/auth/me` 응답으로 새로고침해도 그대로 남았습니다. 별도 단위 시험에서도 A→B 성공 probe 후 A diff가 남습니다. 이전부터 있던 경계이며 이번 현재 탭 수정으로 해결되지 않았습니다. 탭 간 종료 전달과 인증된 소유자/세션 경계에 맞는 메모리·저장소 정리를 검토해야 합니다. 같은 member 종류나 새 객체 여부만으로 고객 동일성을 판정하지 마세요.

2. **P2 — A의 늦은 로그아웃이 B의 diff를 지움.** `src/lib/live/client.ts:364`의 logout은 요청 때 세션을 잡아 완료 때 비교하지 않고 무조건 null snapshot을 씁니다. A logout fetch를 대기시킨 뒤 B를 `takeSession`하고 B diff를 저장한 다음 A 응답을 성공시켰습니다. B 세션은 null이 되고 B diff도 삭제됐습니다. HEAD의 원래 client로 같은 시험을 실행하면 B 세션 덮어쓰기는 동일하지만 B diff는 남습니다. 따라서 세션 race는 기존 문제이고 **새 정리 분기의 B diff 삭제는 추가 영향**입니다. 로그아웃의 응답 소유권 검증과 UI의 후속 query clear까지 함께 검토해야 합니다. 이 race는 결정적 단위 시험으로 재현했으며 실제 OAuth 서버에서의 동시 로그인 수락까지 증명한 것은 아닙니다.

두 항목은 서버 여행 DB 삭제를 의미하지 않습니다. diff는 탭에만 있던 이전 장소/시간이므로 삭제되면 서버에서 before 값을 재구성할 수 없습니다. 개인정보 시험을 유지하면서 현재 계정 이력의 무조건 삭제로 해결하지 않아야 합니다.
