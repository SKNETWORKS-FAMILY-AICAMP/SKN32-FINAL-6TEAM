## 수정과 재현

네 경로를 격리 사본에서 수정했습니다: `IntakeReview.edit`, `TripEdit.reopen`, `TripScreen.resumed`, `useServerReview`의 응답 적용입니다. 요청 당시 query 객체를 보관하고 현재 캐시의 객체와 동일할 때만 결과를 반영합니다. 같은 id가 다시 생겨도 다른 query 객체이면 거부합니다. reopen은 결과 접수의 키가 아직 없으므로 출발점인 trip query를 기준으로 합니다. 재개 요청은 `SafetyPanel`의 onMutate/onSuccess/onSettled도 검사해 렌더 중 콜백 교체를 보호합니다. edit·reopen의 늦은 오류 처리도 동일한 경계를 따릅니다.

`useServerReview`는 두 호출자가 제공하는 `isCurrent`와 기존 마운트 생명주기를 함께 검사합니다. 늦은 결과로 캐시뿐 아니라 undo·preview·dirty 상태가 갱신되지 않게 했습니다. API·DB 스키마·서버의 소유권 계약은 바꾸지 않았습니다. 기존 순수 hook 시험 네 파일은 명시적인 소유권 조건을 전달하도록 연결했습니다.

실제 마운트된 React mutation/콜백을 Edge에서 실행했습니다. edit·reopen·review는 응답을 보류한 채 캐시를 전환하고 나중에 응답을 풉니다. resumed는 두 화면에 전달되는 실제 완료 콜백을 보관해 전환 뒤 호출합니다. 캐시 이벤트를 구독해 잠깐 들어왔다가 덮이는 결과도 검사합니다. 응답에만 있는 합성 표식으로 mutation 응답과 stub의 후속 재조회를 구분했습니다. 초기 시험의 한국어 셸 인코딩·게스트/알림 접근·stub 재조회 오탐은 장치 문제로 보존했고 결함 수에 더하지 않았습니다.

가드를 없애는 변이에서 네 경로 모두 표식이 캐시에 들어갔습니다. **검출 4/4 = 100%**이며, finally에서 가드를 복구하고 SHA-256 일치를 확인했습니다.
