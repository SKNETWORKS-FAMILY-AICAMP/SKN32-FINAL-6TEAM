- 합치는 기준을 **「내가 마지막으로 develop 에 올린 시점」**으로 잡았다. 처음에 develop@38cd59d4 를 기준으로 했더니 이동 담당의 앞선 수정이
  도로 지워졌다(`verify_time.py` 가 develop 과 584줄 어긋났다). 지금 `verify_time.py`·규칙·시험은 develop 판과 같고 내 것은 `paths`(14줄)·

- 시험 폴더 구조: 점검 스크립트 13개가 시험 폴더 안으로 들어왔고, 시험 폴더 conftest 가 기본 = 게이트, 전체층 = `-m "mobility_full and not live"`.

## 새로 찾아 고친 것

1. **운행일 경계** — 「도착 마감 1분 전」 기준으로 바꿨던 것을 물렸다. 이동 담당·팀장 결정(`test_0400_two_sides`: 03:59:59 는 잇고 04:00:00 은 안 잇는다)과 반대였다.
2. **저장소 맨 위 찾기** — 이 기기의 `final_project_cs/.git`(8월에 생긴 `info/` 만 든 빈 폴더)에 속아 `datasets/` 를 못 찾았다. 진짜 git 저장소만 센다.
3. **상대 경로** — `ACOP_MOBILITY_DATA_DIR=datasets/mobility/processed` 를 서버를 띄운 폴더 기준으로 읽어 자료를 못 찾을 수 있었다. 저장소 맨 위 기준으로 푼다.
4. **공휴일표 밖 날짜(2028~)** — 계산기가 멈추는 오류(`CalendarOutOfRange`)가 장소 교체·일정 짜기 전체를 터뜨렸다. 「계산기가 못 채움」으로 돌려 어림값으로 간다.
5. **밀도 어긋남** — 하루를 맞추는 반복은 이동을 어림값으로 넣는데 최종 이동은 계산기가 채워, 계획이 말한 밀도와 등록이 재는 밀도가 달랐다(0.487 ≠ 0.501). 최종 일정으로 다시 재고 어림값은 `estimated_density` 로 남긴다.
6. **채팅 근거 문구** — 장소를 바꾼 뒤 이동의 산출 근거가 옛 「시간표 판정」으로 남아 어림값 경로를 시간표로 판정했다고 답했다. 세 갈래(다시 판정 · 옛 경로 유지 · 어림값)와 사고 뒤 재경로 모두 근거를 새 상태로 쓴다.
7. **자료 확인 명세** — 이동 담당이 자료와 함께 올린 `MANIFEST_git_v1.json` 으로 서버 기동 때 크기·sha256 을 확인한다.

- 새 e2e 시험 `tests/e2e/test_mobility_engine_flow.py`(4): 기동 절차 그대로 계산기를 켜고 → 계획 짜기(노선 실림 · 근거 「시간표 판정」) → 등록(출발 시각·길찾기 링크) → 밀도 일치 → 공휴일표 밖 날짜 → 등록된 식당 교체(앞뒤 이동 다시 판정).

## 남은 것 · 사용자가 정할 것

- **서버를 다시 띄워야 계산기가 켜진다.** `.env` 에 자료 폴더를 넣었고(로컬), 켜면 기동 때 자료를 확인·적재한다(없거나 명세와 다르면 서버가 안 뜬다 — 결정 15).
- 루트 이동 폴더 4개(`mobility_scripts`·`docs`·`config`·`sql`)는 이동 담당 보고서(9/30) 확인 뒤 사용자 지시로 뺐다(119개 파일). 컴파일 캐시 5개가 든 빈 껍데기 폴더가 로컬에 남아 있다(git 무시 대상).
- 식당 자료(`final_project_cs/data/dining`, git 추적 18개)를 루트 `datasets/dining/` 으로 옮길지 — 복사만 하면 원본이 바뀔 때 낡은 자료를 읽게 되고, 옮기면 추적 파일이 이동으로 잡혀 식당 담당과 시점을 맞춰야 한다.
- 활동 자료는 `datasets/activity/` 로 복사했다(원본 유지). 활동 스크립트 2개는 옛 위치 계산(`parents[5]`)이라 담당이 손봐야 한다.
- 개인 저장소 push · develop 반영은 하지 않았다.
