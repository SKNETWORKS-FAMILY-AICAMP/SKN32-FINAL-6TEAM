# 등록 여행 마커 안내 토스트 제거

등록된 여행에서 마커를 누르거나 목록의 ‘지도에서 보기’를 눌러도 장소 설명 토스트가 나오지 않도록 로컬 수정했습니다. 마커 강조와 목록 상세 열기는 유지합니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| mock 서버 시험 (화면 반응) | 실제 Chrome 통과 | 8/8 = 100% |
| 정적 검사 | ESLint·TypeScript 통과 | 2/2 = 100% |
| 화면 촬영 | 375px·1280px | 2/2 = 100% |

실서버 확인 (서버 응답): 안 했음. x600 서버의 cs 프로젝트 서버 공개 배포와 해당 여행의 실제 응답 확인은 하지 않았습니다. 커밋·푸시·다른 채팅 전송도 하지 않았습니다.

## 원인과 변경

등록 여행 화면의 마커 선택 함수에 장소 제목·시간·주소와 ‘목록에서 보기’ 버튼을 띄우는 호출이 남아 있었습니다. 그 호출을 제거했습니다. 같은 마커를 다시 눌러 선택을 해제할 때 실제 알림까지 닫던 호출도 제거했습니다. 경로선 상세 안내와 실제 변경·선택 요청·재난·실패 알림 코드는 유지했습니다.

기존 제품 파일 2개는 수정 직전에 [백업](../../../_backup/2026-10-11_여행마커토스트제거전/)했습니다. [화면 코드](../../../frontend/apps/web/src/features/trip/trip-screen.tsx)의 변경은 마커 선택 함수와 주석에 한정됩니다.

## 확인 범위와 실행 기록

[최종 Chrome 결과](../evidence/2026-10-11_trip-marker-no-toast/chrome-release.json)는 production 빌드·실제 설치된 Chrome·mock 서버로 실행한 관련 시험 8개입니다. 새 시험 3개와 기존 알림 센터 시험 5개입니다. 375px·1280px에서 실제 마커 본체 클릭·다시 클릭·목록의 지도 보기로 선택과 펼침 상태, 안내 토스트 미표시를 확인했습니다. 실제 선택 요청 알림이 떠 있을 때는 마커 본체 클릭으로 선택하고, 마커의 click 이벤트로 해제하여 알림이 유지되는지 확인했습니다. 해제 후 펼침 상태가 false인지도 검사했습니다.

초회 실행은 5/8 통과였습니다. 새 시험이 보이는 마커 본체 대신 넓은 바깥 컨테이너를 눌렀고, 알림이 겹치는 위치를 누르려 기다리다가 알림이 만료됐습니다. 클릭 대상을 본체로 바꾸고 알림이 가리지 않는 마커를 선택했습니다. 중간 실행은 8/8이었으나 해제 상태를 명시적으로 추가한 검증에서 Enter 입력으로 해제가 발생하지 않아 7/8이었습니다. 최종 시험은 해제 click 이벤트와 상태를 함께 검증해 8/8 통과했습니다. 이 결과를 마커 키보드 조작 검증으로 보고하지 않습니다. 이전 실행 결과도 같은 evidence 폴더에 보존했습니다.

첫 production 빌드는 시험 사본에 기존 Trip.simulation 타입 선언이 빠져 타입 검사에서 멈췄습니다. 원본에 이미 있는 선언만 시험 사본에 맞춘 뒤 빌드했습니다. 제품 모델은 이번 작업에서 바꾸지 않았습니다. [정적 검사 종료 코드](../evidence/2026-10-11_trip-marker-no-toast/static-release.json)는 0이며 [원본과 시험 파일 해시](../evidence/2026-10-11_trip-marker-no-toast/source-hashes.json) 2개가 일치합니다.

[촬영 모음](../../../frontend/apps/web/mockups/trip-marker-no-toast-2026-10-11-v1/index.html)은 실제 화면 2장입니다. 붉은 지도 배경은 mock 서버의 시험 타일입니다. 같은 작업자가 구현과 화면 검증을 수행했으며 독립 검토 완료로 표시하지 않습니다.
