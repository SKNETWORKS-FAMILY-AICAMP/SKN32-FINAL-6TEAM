# 브라우저 세션 쿠키 · 게스트 정리 · 여행 삭제 — 서버 쪽 구현 리포트 (2026-10-04)

## 1. 목표

사용자 결정(2026-10-04) — 「로그인하면 다시 인증하면 되니 토큰을 오래 들고 있을 필요 없다 · 비로그인 게스트는 세션을 잃어도 받아들인다 · 쿠키보다 나은 방식이 오늘 기준으로 없으면 쿠키로 개발 · 로그인 안 한 세션은 삭제하되 관리 콘솔에서 시점 조절 · 초기값은 조사한 최적값과 공식으로 · 나머지는 네 제한대로」.
계획서 단계 없음(사용자 지시 작업). 결정 기록 [D-CS-011](../../decisions/D-CS-011-browser-session-cookie.md), 계약 [rest-endpoints.md](../../external/rest-endpoints.md) 「브라우저 세션 쿠키」 · 「게스트 · 여행 삭제 · 게스트 정리」 — 계약을 코드보다 먼저 고쳤다(RULE §3.5).
같이 처리한 요청: uiux 세션의 「여행 삭제」(요청서 [2026-10-03_1920_웹_실서버_전환_백엔드_요청](../plans/2026-10-03_1920_웹_실서버_전환_백엔드_요청.md) 구현 지침 8항) — 게스트 자동 삭제가 같은 함수를 쓰므로 한 묶음.

## 2. 조사 (오늘 2026-10-04 기준 — 코덱스 웹 검색 + 검토 에이전트 둘이 따로)

- **쿠키보다 나은 방식은 없다** — 서버 저장형 불투명 세션 + HttpOnly 쿠키가 최선(OWASP · RFC 10017 BFF). DBSC 는 Chrome 146 **Windows 만** 정식(2026-04-10)이고 Safari 미발표 · Firefox 부정적이라 **나중에 얹는 보강**. 둘이 같은 결론. claude.ai · ChatGPT 웹도 쿠키(localStorage 장기 키 자료는 못 찾음). 쿠키의 정확한 속성은 공식 자료에 없어 `[미확보]`.
- **게스트 보존 시간** — 코덱스 **24시간**(페이지 재방문 25명 연구 · 목표 포착률 80% 가정 — 스스로 「입증된 최적값 아님」), 에이전트 **14일**(공식 `T*=11.3일`에서 올림). **이 세션에서 공식을 직접 다시 계산**해 일치를 확인했다: `t0=30분 · α=1.2` → 포착률 24시간 54% · 7일 69% · 14일 73% · 30일 77%, 한계 포착률 9.2 · 0.89 · 0.39 · 0.16 %/일. 24시간이 최적이려면 `ρ=9.2%/일`(하루 저장 비용이 손실의 9%)이어야 해 비현실적. → **초기값 7일(168시간)**(`ρ≈1%/일` → 6.4일 올림, 곡선이 꺾이는 자리). 확신도 낮음 — 여행 게스트의 실제 재방문 간격을 못 찾았고 `ρ` 는 정책값이다.

**이번에 새로 찾은 것**
- 요청서의 삭제 대상 표 목록에 **`places.trip_scope`(이 여행 전용 장소 행, 외래키 없음)가 빠져** 있었다 — 서버 DB 조회로 찾아 더했다. 여행 번호 칸을 가진 표 전부를 훑는 시험이 있다(새 표가 생기면 걸린다).
- 열린 Case 를 닫는 길을 전이표에서 찾으면 **`running → completed → resolved → cancelled`** 가 먼저 나온다 — 안 한 일을 「끝냈다」고 기록한다. `resolved` 를 거치지 않는 길(`guardrail_escalated → escalated → cancelled_by_user`)만 쓰게 막고 시험으로 고정했다.
- 사용자 행을 가리키는 외래키 14개 중 13개가 「가리키면 거부」(서버 DB) — Case 가 가리키는 게스트는 사용자 행 한 줄(이메일 · 이름 없는 무작위 번호)만 남는다.
- 「여행 만들기 하루 1건」은 **사용자 단위**라 새 게스트를 만들면 우회된다(코덱스 지적을 코드로 확인) — 「게스트 총 1개」를 별도 행 잠금으로 막았다.
- 게스트의 여행은 이제 감시 · 안내를 받지 않아, 「감시를 받는 웹 사용자」를 가정한 옛 시험 둘(`test_web_api` · `test_web_guard`)은 회원(소셜 계정이 붙은 사용자)으로 고쳤다.

## 5. 한계 · 다음

- **켜진 채 배포된다** — `web.guest_cleanup_enabled` 기본 켬. 서버의 옛 시험 사용자(키만 있는 게스트)는 마지막 사용 7일 뒤 지워지고, 게스트의 여행은 감시 · 안내를 받지 않는다. 관리 콘솔에서 끌 수 있다.
- 7일은 **초기값**이다(위 2절) — 실측 지표(재방문 간격 · 삭제 뒤 복귀)는 만들지 않았다.
- 만들지 않은 것은 [open-items](../../../../wiki/delivery/open-items.md) 「[2026-10-04] 브라우저 세션 쿠키 · 게스트」 표에 올렸다 — 웹 화면 · 에이전트 키 분리(2단계) · 「만료됨」 링크 안내 · 바깥함 보내기 직전 확인 · MCP 삭제 도구 · `case_events` 마스킹 점검 · Safari 서버 쿠키 실기기 확인.
- `[미확보]` 조사에서 못 찾은 것 — 여행 게스트의 재방문 간격 분포 · 쿠키 속성의 공식 문서(claude.ai · ChatGPT) · Edge 의 DBSC 정확한 상태 · 「일정 시작일까지 자동 삭제 유예」를 명시한 서비스 정책.
