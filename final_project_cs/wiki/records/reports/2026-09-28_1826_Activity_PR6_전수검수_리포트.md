# 활동 팀 작업 전수검수 리포트 (2026-09-28)

## 결론

활동 팀이 팀 공용 브랜치에 올린 파일 75개를 모두 검수했습니다. 자동 시험은 전부 통과합니다. 하지만 **「이 시각에 이 활동을 해도 되는지」 판단하는 부분이 우리 코드보다 나빠져서**, 우리 작업 폴더에는 아직 합치지 않았습니다.

그대로 합치면 날씨·재난 정보를 하나도 못 받았거나 호우경보가 내려져 있어도 고객에게 「활동해도 됩니다」라고 답하게 됩니다.

다음 할 것: 판단 부분은 우리 코드를 두고, 쓸 만한 부분만 골라 합치는 안을 권합니다(결정 대기).

| 할 일 | 상태 | 진행 |
|---|---|---|
| 활동 팀 작업 받아오기 | 끝 (참고용으로만) | 1/1 = 100% |
| 파일 하나씩 검수 | 끝 | 75/75 파일 = 100% |
| 자동 시험 | 실패 0 | 통과 1,612/1,676 = 96% (나머지 64건은 데이터가 없어 건너뜀) |
| 변경 전후를 같은 조건으로 비교 | 끝 | 3/3 상황 = 100% |
| 우리 작업 폴더에 합치기 | 결정 대기 | 0/1 = 0% |

## 1. 무엇이 나빠졌나 — 가장 큰 세 가지

**모르는데 「괜찮다」고 답합니다.** 팀 규칙은 「값을 모르면 다른 곳에서 찾고, 거기서도 못 찾으면 오류로 멈춘다」입니다. 새 코드는 날씨·재난 조회가 실패하면 그 항목을 건너뛰고 「성립합니다」라고 답합니다. 이 규칙을 지키던 시험 2개는 지워졌고, 1개는 이름은 그대로인데 확인 내용이 반대로 바뀌었습니다. 시험이 다 통과하는 이유가 이것입니다.

**호우경보·미세먼지·도로 통제를 더는 보지 않습니다.** 우리 코드는 날씨 예보, 기상특보, 재난문자, 대기질, 구 단위 도로 통제를 한 번에 확인했습니다. 새 코드는 이 확인을 걷어 내고 날씨 예보와 재난문자만 따로 봅니다. 예를 들어 호우경보가 내려진 날의 한강공원 일정에, 전에는 일정 변경을 제안했지만 이제는 「성립합니다」라고 답합니다.

**재난문자가 와도 판단에는 「없음」으로 전달됩니다.** 재난문자 조회가 돌려주는 자료와 판단 코드가 읽는 자료의 칸 이름이 다릅니다. 위급재난 문자 한 건을 넣어 돌려 보니, 판단 코드는 빈 목록을 받았습니다. 시험은 가짜 자료를 판단 코드가 기대하는 모양으로 넣어 줘서 이 문제를 잡지 못합니다.

고칠 것은 이 밖에 13가지가 더 있습니다. 5장 표에 쉬운 말로 적었습니다.

## 2. 같은 조건에서 변경 전후의 답

여의도 한강공원(야외)·화요일 예약으로, 같은 입력을 변경 전 코드와 변경 뒤 코드에 넣어 답을 비교했습니다.

| 같은 상황 | 변경 전 | 변경 뒤 |
|---|---|---|
| 날씨·재난 조회가 전부 실패 | 오류로 멈춤 | 「성립합니다」 |
| 다른 곳에서도 값을 못 찾음 | 오류로 멈춤 | 「성립합니다」 |
| 호우경보 발효 | 일정 변경 제안 | 「성립합니다」 |

아래 세 상황은 변경 뒤 코드에만 넣어 봤습니다. 변경 전 코드는 이 입력을 받기 전 단계에서 오류로 멈춰서, 변경 전 답이 맞는지는 이 시험으로 확인하지 못했습니다.

| 상황 | 변경 뒤 |
|---|---|
| 「매주 월요일, 화요일 휴무」인 곳을 화요일에 방문 | 「성립합니다」 |
| 「오늘은 임시휴무입니다」 | 「성립합니다」 |
| 경주 지진 재난문자가 온 상태의 서울 일정 | 「성립합니다… 성립하지 않습니다」를 한 답 안에 같이 말함 |

## 3. 쓸 만한 것

- **대체 장소 고르기.** 닫힌 곳을 빼고, 비슷한 종류·가까운 곳 순으로 1~3위를 뽑습니다. 닫혔는지 모르는 곳은 빼지 않고 「모름」 표시를 붙여 남깁니다. 계산만 하는 코드라 옮기기 쉽습니다.
- **후보 장소 불러오기.** 대체 장소 후보를 데이터베이스(DB)에서 읽습니다. 고객(테넌트)마다 자기 것만 읽고, 기준이 되는 장소를 모르면 「모름」을 돌려줍니다. 조회에 값을 안전하게 끼워 넣어(바인딩) 조작된 입력으로 DB를 건드릴 위험이 없습니다(읽음).
- **쇼핑 장소 자료 보강.** 올리브영·다이소 등 서울 매장 목록을 관광공사 자료와 짝지었고, 장소 목록에 대분류 칸을 더했습니다.

이 셋은 아직 서비스에서 불리지 않습니다(코드 검색으로 확인). 골라 합칠 때 우리 흐름에 연결하면 됩니다.

작지만 살릴 것이 둘 더 있습니다.
- **장소 이름으로 찾기.** 검색 결과가 정확히 한 곳일 때만 그 장소로 정합니다.
- **운영시간 원문 싣기.** 관광공사 운영시간 원문을 근거로 싣습니다. 원문을 해석하는 일은 우리 쪽 영업시간 해석 코드에 맡기면 됩니다.

## 4. 정할 것

1. **합치는 방식.** 권하는 안은 **골라 합치기**입니다. 판단 부분은 우리 코드를 유지하고, 3장의 쓸 만한 것만 가져와 연결합니다. 다른 길은 둘입니다. 그대로 다 받거나(2장처럼 판단이 나빠집니다), 활동 팀원에게 5장 목록으로 먼저 고쳐 달라고 하는 것입니다.
2. **배포용 브랜치 합치기 보류.** 팀 공용 브랜치에서 배포용 브랜치로 가는 합치기 요청이 열려 있고, 이 변경도 거기 실렸습니다. 고치기 전에는 합치지 않기를 권합니다.
3. **휴대전화 번호.** 공개 저장소에 올라간 자료 파일 2개에서 휴대전화 형식 번호 3건을 확인했습니다. 관광공사 공개 자료의 행사 연락처로 보이지만 확인하지는 않았습니다. 저장소 기록에서까지 지우려면 기록을 강제로 덮어쓰는 푸시가 필요합니다.

| 「바꿀까요?」 → 「바꿔 줘」 → 그때 계산 | 끝 (두 감시 경로 모두) | 2/2 = 100% |
| 확실한 분류로 채우기 · 기존 행 다시 채우기 | 끝 (백업 두 번) | 2/2 = 100% |
| 웹 「바꿔 줘」 버튼 | 끝 (화면 세션이 보완) | 1/1 = 100% |
| 시험 | 통과 | 구조·계약·단위 1,786 · 여행 통합·e2e·시나리오 240 |
| 브라우저 확인 | 끝 | 5/5 장면 = 100% |
| 커밋 | 끝 (push 안 함) | 3/3 = 100% |

### 7-2. 정한 것과 이유

- 모르면 묻는다 — 코덱스와 1회차 합의. 분류만으로 「야외」라고 정하면 실내인 곳의 일정까지 자동으로 바뀔 수 있다.
- **묻는 순간에는 대체안을 계산하지 않는다** — 사용자 결정. 대체안 계산은 후보마다 날씨·특보를 다시 조회해 비용이 든다. 동의한 경우에만 계산한다.
- 안전 사건(지진·재난문자·기상 「경보」)과 교통 통제는 이 길을 타지 않는다 — 지금 규칙이 먼저다.
- 확실한 분류만 채운다: 자연 전체·동상·공원·둘레길 = 야외, 공연장·전시관·문화원 = 실내. 처음엔 「문화시설 = 실내」로 넓게 잡았다가, 관광공사가 **낙산공원을 문화시설(공원 중분류)로 분류**해 「야외 아님」이 된 것을 브라우저 시험에서 찾아 중분류로 좁혔다.
- 데모 공간 활동 장소 146곳: 야외 17 · 실내 19 · 모름 110(비 올 때 먼저 묻는 대상).

### 7-4. 새로 찾은 약점 (고치지 않음 — 결정 필요)

- **비 올 때 대체 활동 후보가 「등록된 장소」에서만 나온다.** 경복궁 600m 안에 등록된 활동 장소는 경복궁 자신뿐이라 후보가 0이었다. 관광공사 장소 목록(7,996곳)에는 근처 박물관이 여럿 있지만 쓰이지 않는다. 고치려면 목록의 장소를 대체안으로 고를 때 그 여행 전용 장소로 등록하는 단계가 필요하다(일정 짜기가 이미 그렇게 한다).
- **식당 일정이 「활동」 담당으로 분류되는 요청**이 있다(무구옥·순대국). 답은 일정 종류로 내서 결과는 맞지만 담당 통계가 틀어진다.
