- **왜 초안이 시제품보다 시각 · 요청이 높나** — 시제품 가르친 E4B 는 실제 접수 하나(R19)에서 둘째 날 다섯 줄을 통째로 빠뜨렸다. 초안은 에이전트가 빠뜨린 **시각 있는 줄**을 규칙 값으로 채운다
  (그 줄이 에이전트가 이동 · 조건으로 읽은 줄이거나 고객이 메시지 안에서 고친 경우는 채우지 않는다). 요청 「일정 등록」은 항목이 하나라도 있으면 붙는다(채점 어댑터 규칙 — 지금 구조와 같다).
- **왜 가르친 Winnow-E4B(Jev 계열, 우리 데이터 1차 보강)가 아니라 가르친 E4B 인가** — Winnow 는 항목 · 종류는 더 잘 찾았지만 시각의 근거 조각을 비워 두는 일이 많아
  「근거가 원문에 없으면 버린다」는 선에 걸려 시각이 23% 였고, 요청 종류를 거의 내지 않았다(6%). 이 지시문 · 출력 틀로 가르친 적이 없는 모델이라 공정한 실력 비교는 아니다.
  또 x600 서버에는 Winnow 가 없다(12GB GPU 를 jikimi 와 나눠 쓰는 가르친 E4B 한 모델만 올라가 있다) — 바꾸려면 모델 배치부터 다시 정해야 한다.
- **아직 못 읽는 것** — 성향(「걷기 싫어」 「애들 데리고」) 0/18, 조건 4개 중 하나 꼴로 놓침, 중간 정정 4건 중 2건, 「고객만 아는 빠진 값」 44%. 성향 · 조건은 확인 화면에 칸이 없어
  지금은 `reading.agent` 값 줄에 기록만 한다(화면 · 일정 짜기에 쓰는 것은 다음 일).

## 초안 구조(제품 반영 전)

1. 접수 원본마다 규칙 읽기(빠름)를 먼저 하고, 같은 원문을 **읽기 에이전트**에 한 번 보낸다 — 채팅과 같은 Ollama · 같은 모델(x600 `tripilot-pointer:e4b-ft`) · 같은 문맥 길이(8,192).
   ★채팅 경로는 9초가 넘으면 유료 모델로 넘어가는데, 읽기는 9~17초 걸려 늘 넘어간다 — 그래서 같은 Ollama 를 **긴 대기(90초)로 따로** 부르고 유료로 넘기지 않는다.
2. 모델 답은 JSON 틀(Ollama `format` 스키마)로 받고 **원문에 글자 그대로 없는 조각은 버린다**(장소 · 시각/날짜 근거 · 이동 출발/도착 · 이동/조건/성향 근거).
   시각 값은 모델이 문맥으로 정하되(「1시쯤 점심」→ 13:00) 원문의 시와 다르면 「확인 필요」, 상대 날짜(「낼」)로 정한 날짜도 「확인 필요」.
3. 에이전트 항목이 먼저, 빠진 시각 줄은 규칙 항목, 날짜는 에이전트 값 → 없으면 규칙 날짜 해석. 이동 수단은 확인 화면의 구간 수단 값 줄(`moves[앞~뒤].mode`)로 — 고객이 고르는 칸과 같은 칸이라
   그 구간을 그 수단으로 다시 계산해 닿는지 보고, 안 닿으면 지금처럼 추천 수단으로 돌아가며 이유를 보인다.
4. 에이전트가 실패하거나(연결 · 시간 초과 · 모양 오류), 아무것도 못 읽었는데 규칙은 읽었으면 **규칙 결과를 그대로 쓴다**. 실패 사유는 `reading.agent` 값 줄에 남는다.

| 설정 | 값 | 어디 |
|---|---|---|
| 켜기 · 끄기 | `on` · `shadow`(규칙 결과를 쓰고 에이전트는 기록만) · `off`(옛 경로) | 초안의 가드레일 `travel.intake_reader.mode`, 운영 설정 같은 이름이 먼저(재기동 없이) |
| 대기 · 답 길이 | 90초 · 3,072 토큰 | `travel.intake_reader.timeout_seconds` · `num_predict` |

하지 않았다 — 제품 반영을 멈췄다(2026-10-16 사용자 결정). x600 서버에는 시험 부하도 걸지 않았다(접수 원문 내보내기 SELECT 1회는 기준선 측정 때).

## 이 측정의 범위와 한계

- 시험지는 이 세션(Claude)이 쓰고 정답도 달았다(합성 49). 실제 20건은 x600 서버 cs 프로젝트 DB 의 접수 원문 그대로 — 절반 이상이 웹 화면 예시를 고친 정형 줄이다.
- 에이전트 지시문의 성향 · 조건 · 요청 말 목록은 시험지 정답과 **같은 사람이 정한 같은 어휘**다 — 어휘가 맞춰져 있어 유리할 수 있다. 지시문의 예는 시험지에 없는 장소(낙성대공원 · 샤로수길)로 썼다.
- 모델은 GPU 서버 B 의 x600 재현 Ollama(같은 모델 파일 · 0.31.1 · 문맥 8,192)로 쟀다. x600 서버의 GPU 는 다르다 — 절대 시간은 x600 서버에서 다시 본다.
- 가르친 Winnow-E4B 는 llama.cpp 서버(Winnow-E4B Q8 원본 + 1차 보강 덧붙임, 생각 끔)로, 가르친 E4B 는 Ollama 로 불렀다 — 실행기 차이가 점수에 섞여 있다. 측정 때 GPU 를 다른 세션도 쓰고 있어 시간은 흐려질 수 있다.
- 장소 찾기는 카카오만(관광공사 · 우리 장소 목록 · 식당 원장 없이) — 「찾은 장소 이름」은 x600 서버에서 더 높을 수 있다.
- 한 번씩 쟀다(온도 0). 69건이라 형식별 칸은 3~8건짜리가 많다.
