# 지도 순차 등장과 이전 마커 거리 표시 유지

2026-10-12 로컬 검증. 새 일정으로 카메라를 이동할 때 앞서 등장한 일정은 지도 마커 또는 화면 밖 번호·거리 표시로 유지한다. 새 마커는 이동 도중에도 이전 거리 표시와 합치지 않는다. 공개 배포는 하지 않았다.

## 변경과 원인

- 기존 코드의 매번 전체 일정 범위 맞춤을 최초 확인 중에는 최신 좌표로 이동하는 동작으로 바꿨다. 최초 확인 중 날짜가 바뀌어도 이미 등장한 일정을 지도 입력에서 빼지 않고, 완료 후에는 기존 날짜별 전체 보기로 돌아간다.
- Leaflet의 기존 마커 요소를 재사용한다. 새 일정 때문에 이전 마커를 전부 다시 만들지 않는다. 카메라 이동은650ms로 기존 새 카드 대기800ms 안에 마치고, 새 마커는 튀어 오르는 효과 없이300ms에 걸쳐 나타난다. 지리적 카메라 이동650ms는 일반 UI 전환 시간의 예외다.
- 화면 안 좌표는 거리 표시 대상에서 제외하는 기존 규칙을 유지한다. 새 마커가 아직 화면 밖인 이동 초반에도 그 마커의 거리 표시를 이전 묶음에 합치지 않는다. 완료 후 기존 화면 밖 묶음·스택 개수 규칙은 유지한다.
- 추가 프레임 시험에서 동작 줄이기 모드의 순간 불일치를 재현했다. 전역 `.01ms` 전환 시간이 지도 SDK의 좌표 변경까지 전환으로 만들어, 실제 위치와 거리 표시의 시점이 한 프레임 어긋났다. 지도 영역의 CSS 전환을 완전히 끄고 SDK 자체 전환도 끈다. 지도 경계 전달은 렌더 완료 후 그리기 전에 반영하며, 이전 경계에 대한 거리 표시가 현재 지도 안 좌표를 숨기지 못하도록 보호한다.

실서버 확인 (cs 프로젝트 서버 응답): 안 했음. 실제 접수 데이터·공개 배포·실제 Google/Naver SDK 이동은 이번 시험에 포함하지 않았다. Google/Naver 코드에도 최신 좌표를 카메라 대상으로 전달하지만 실측 완료로 간주하지 않는다.

최종 소스와 격리 촬영 폴더의 변경 파일10개는 줄바꿈을 정규화해10/10 동일함을 확인했다([비교 결과](../evidence/2026-10-12_map-reveal-continuity/source-normalized.json)). Playwright 실행에서 생산 빌드를 다시 생성했다. 앞선 실패 기록은 보존하며 최종 집계에서 성공으로 바꾸지 않았다([증거 폴더](../evidence/2026-10-12_map-reveal-continuity/)).
