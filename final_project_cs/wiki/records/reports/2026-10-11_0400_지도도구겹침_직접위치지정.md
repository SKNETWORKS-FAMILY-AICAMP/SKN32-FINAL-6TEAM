# 지도 도구 겹침 허용·직접 위치 지정

확장 지도 도구와 마커는 겹칠 수 있게 하고 거리·화살표 버튼 하나만 피하도록 변경했다. 일정 추가에서 원하는 검색 결과가 없으면 지도를 직접 눌러 좌표를 지정할 수 있다.

| Chrome 화면 촬영·확인 | 완료 | 8/8 = 100% |

## 동작

- LiveMap의 거리 칩 배치와 세 지도 제공자의 공통 pinArea 모두 data-map-obstacle로 표시한 거리·화살표 버튼만 장애물로 쓴다. 기존 거리 칩끼리·마커끼리 배치와 지도 밖 판정·점선 연결은 유지한다. 경로 수단 라벨은 도구 전체를 피하는 기존 규칙을 유지한다.
- 직접 위치 지정은 기존 일정 추가의 한시적인 좌표 편집이다. 검색어·선택 장소·이름·날짜·시각을 보존하고 취소 시 복귀한다. 화면 클릭 위치를 기존 MapView의 Web Mercator 화면 좌표에서 역변환하며 같은 변환으로 미리보기 핀을 놓는다. 8px 이상 움직인 드래그와 지도 도구 클릭은 새 좌표를 만들지 않는다. 지도 중심 선택은 키보드 대체 입력이고 지도 단추에 초점이 있어도 Esc로 취소한다.
- 장소 이름 1~80자, cs 프로젝트 서버가 이미 허용하는 서울 좌표 범위만 확인 가능하다. 확인으로 초안만 바꾸고 기존 일정에 추가 버튼에서 source=map·name·latitude·longitude를 보낸다. 관광공사 번호·외부 장소 식별값을 생성하지 않는다. cs 프로젝트 서버 코드·API 모양은 변경하지 않았다.
- 위치 선택 제목과 선택한 장소 행이 손잡이 아래 페이드에 처음부터 잘리지 않게 36px 시작 여백을 확보했다.

## 확인 범위

375px·1280px 실제 Chrome/OSM로 검색 결과 없음→지도 클릭→초안 복귀→POST /edits 좌표 원값 전송, 저장 전 쓰기 0건, 검색어·날짜·시각 보존, 취소 초점 복귀, 지도 드래그·도구 클릭 무선택, 키보드 중심 선택/Esc 취소, 서울 밖 확인 금지, 화살표 예약 영역 하나를 검증했다. 최종 빌드 12개와 직전 지도 코드가 동일한 빌드의 마커·페이드 4개를 합한 서로 다른 시험 16개다. 구글·네이버의 실제 서비스 SDK 접속은 확인하지 않았다. 두 제공자도 같은 LiveMap/MapView 변환과 pinArea를 사용하며 코드 경로는 타입 검사했다.

최초 12개는 11통과·1실패했다. 시험이 클릭 좌표의 소수점까지 기대했지만 Chrome 이벤트는 정수 좌표를 전달해 0.9px 차이가 났다. 시험의 클릭 위치를 정수로 맞춰 다시 실행했고 16/16 통과했다. 이후 Esc 취소·선택 행 여백을 추가한 최종 생산 빌드의 관련 12/12도 통과했다. 최초 촬영에서 위치 지정 제목이 손잡이 페이드와 겹친 것을 발견해 제목 시작 여백을 보정했다. 두 시도의 JSON·화면·관련 소스는 백업에 보존했다.
