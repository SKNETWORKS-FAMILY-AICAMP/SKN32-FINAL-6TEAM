# 관리자 재난 6종 시뮬레이션 구현

관리자가 여행과 방문 일정을 고른 뒤 6개 스위치 중 N개를 켜면, 다음 감시 회차부터 선택한 N종의 재난 입력으로 기존 판정·알림·안전정지를 시험할 수 있게 구현했다. 로컬 코드와 DB에서 검증했으며 운영 환경에는 배포하지 않았다. 범위는 2026-10-09 사용자 요청에 따른 여행 지속관리 기능의 관리자 시험 옵션이다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 6종 입력·감시 연결 | 완료 | 6/6 = 100% |
| 핵심 백엔드 시험 | 통과 | 195/195 = 100% |
| 안전정지·복구 시험 | 86개 통과·1개 건너뜀 | 86/87 = 99% |
| 관리자 화면 시험 | 통과 | 2/2 = 100% |

각 행의 분모는 해당 실행에서 수집한 시험 수다. 실행 사이에 같은 시험이 포함되므로 합산하지 않는다. 전체 제품의 DoD 완료율을 뜻하지 않는다.

## 사용하는 순서

관리자웹앱의 **재난 시뮬레이션** 메뉴에서 사용한다. 관리자 기능 자체에는 별도 유료 서비스가 필요하지 않으며 미선택 소스의 기존 실제 조회는 유지된다.

| 순서 | 화면에서 하는 일 | 끝나면 보이는 것 |
|---|---|---|
| 1 | `대상 여행`에서 진행 중인 여행을 고른다 | 현재 일정 판과 선택 가능한 방문 일정 |
| 2 | `대상 일정`에서 진행 중이거나 다가오는 항목을 고른다 | 방문 장소와 시작 시각 |
| 3 | 날씨 예보·기상 특보·재난문자·교통 통제·대기질·지진 중 원하는 스위치를 켠다 | `선택 N/6`과 `선택한 N종 적용` 버튼 |
| 4 | `자동 종료 시간`을 고르고 `적용·중지 사유`를 적어 적용한다 | `시뮬레이션 입력 N종 활성`과 종료 시각 |
| 5 | 다음 감시 회차의 처리를 기다린다 | 실제 감시 점검 결과와 이번 시험의 앱 알림; 화면은 5초마다 다시 조회 |
| 6 | 사유를 적고 `시뮬레이션 중지`를 누른다 | 입력 꺼짐; 이전에 열린 시험 제안은 닫힘 |

화면의 자동 종료 시간은 5·15·30·60분이다. API는 1~60분을 허용한다. 적용은 설정 저장이며 즉시 감시 실행을 호출하는 버튼은 아니다. 이미 변경된 일정이나 안전정지는 중지해도 자동으로 되돌아가지 않는다. 고객 화면의 기존 되돌림·다시 시작 경로를 이용한다.

## 판정과 표시

- 예보 입력은 주의사항 안내와 일정 변경 버튼으로 이어진다. 기상특보·교통통제·대기질은 기존 일정 변경 정책, 재난문자·지진은 기존 안전정지 정책을 통과한다. 안전정지가 우선이어도 6종 전체 점검 결과를 별도로 남긴다.
- N종을 켰다는 것은 N개의 입력을 넣었다는 뜻이다. 실내 일정에 해당하지 않는 날씨·대기질, 중복 방지, 안전정지 우선 정책 때문에 일정 변경이나 알림 N개를 보장하지 않는다. 관리자 화면은 저장 성공과 감시 처리 결과를 구분한다.
- 고객 앱 화면과 시험 알림에는 `[시뮬레이션]`을 붙인다. 시험 알림은 외부 고객 채널과 개발용 디스코드로 보내지 않는다. 시험 종료 후 안전정지 재안내·해제 안내도 시험 출처를 유지한다.
- 여행·항목 하나에만 입력을 붙인다. 공용 장소나 공유 응답 캐시는 바꾸지 않고, 선택하지 않은 소스와 대체 장소는 실제 조회한다. 자동 종료 시각 경과·일정 판 변경·운영자 중지 이후에는 새 입력 주입을 끝낸다.

권한 검사·CSRF(다른 사이트에서 관리자 동작을 대신 실행하는 요청 차단)·테넌트 구분·낡은 설정 거부·수행자와 사유 감사 기록을 적용했다. 고객 API 앱에는 관리자 재난 시험 경로를 등록하지 않는다. 여행 맥락은 모델이 말한 여행 ID 대신 확인된 접수의 대상과 고객 소유권에서 얻는다.

## 백업과 배포 전 남은 일

기존 수정 파일은 각 파일과 같은 폴더 아래 `_backup/2026-10-09_재난6종_시뮬레이션/`에 `.bak` 확장자로 보관했다. 대표 위치는 [일정 처리 백업](../../../app/domains/travel_ops/components/itinerary/_backup/2026-10-09_재난6종_시뮬레이션/), [알림 백업](../../../app/domains/travel_ops/components/watch/_backup/2026-10-09_재난6종_시뮬레이션/), [관리자 메뉴 백업](../../../frontend/apps/admin/src/components/_backup/2026-10-09_재난6종_시뮬레이션/), [고객 화면 백업](../../../frontend/apps/web/src/features/trip/_backup/2026-10-09_재난6종_시뮬레이션/), [계약 백업](../../external/_backup/2026-10-09_재난6종_시뮬레이션/), [생성 설정 백업](../../../frontend/apps/admin/_backup/2026-10-09_재난6종_시뮬레이션/)이다. 새 기능 파일은 신규 생성했다. 화면 이미지는 새 이름으로 저장해 이전 그림을 보존했다.

운영에서 쓰려면 마이그레이션 226·227과 cs 프로젝트 서버의 운영 API·고객 API·worker, 관리자웹앱·고객웹앱에 같은 변경을 배포해야 한다. 커밋·push·운영 배포와 실제 고객 여행에 대한 재난 주입은 수행하지 않았다.
