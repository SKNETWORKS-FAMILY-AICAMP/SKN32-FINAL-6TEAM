## 해결하지 않은 형태도 원문에 남겼다

관계의 태그·회원 순서·OSM id·원문 갱신 시각을 보존했다. 추출 당시 값이 없는 칸을 만들어 채우지 않았다.

| 종류·문제 | 관계 개수 | 후속 처리 |
|---|---:|---|
| node를 거치는 단순 회원 형태 | 5,329 | incoming/outgoing 방향 검사 |
| way를 거치는 형태 | 178 | 연속 경로 상태가 필요 |
| 기타 회원 형태 | 751 | 누락·복수·다른 역할을 그대로 보존 |
| 같은 way로 들어오고 나감 | 2,475 | 유턴과 같은 way의 직진을 구별 |
| 시간 조건 태그 | 3 | 시간·차종 조건 해석 필요 |
| except 태그 | 3 | 적용 제외 차종 해석 필요 |
| way 일부 미대응 | 55 | 69개 회원 참조가 그래프에 없음 |
| via node 미대응 | 19 | 분할 노드 보강 또는 원문 연결 확인 |
| 차량 incoming 없음 | 342 | 일방통행·차량 접근·회원 의미 대조 |
| 차량 outgoing 없음 | 376 | 위와 같음 |

이 표의 문제 개수는 중복될 수 있다. 합산해서 미지원 관계 수로 쓰지 않는다. 현재 원문에서 from 회원이 없는 관계 400개, to가 없는 관계 409개, via가 없는 관계 264개를 확인했다. **이것을 곧바로 실제 도로의 지도 오류라고 단정하지 않는다.** 로컬 지역 추출본의 회원 구성만 검사했으며, 원래 전 세계 관계의 회원이 지역 추출 과정에서 줄었는지는 이번 범위에서 확인하지 않았다.

차종별 restriction 키는 실제 관련 관계에서 0개였다. 하지만 추출기는 이 키를 보존하고, 독립 계약 검사에서는 자전거 전용·차량 예외·시간 조건을 일반 차량 제약으로 바꾸지 않는지 확인했다.

모호한 단순 후보 id는 `6545411`, `6948998`, `6949000`, `8065325`, `12475694`, `12480505`다. 해당 12쌍을 모두 금지하면 반대 방향까지 막을 수 있다. 후보로 남기되 초기 적용 대상에서는 제외하거나 형상과 회원 방향으로 해소해야 한다. 정적 후보의 only/no 모순은 incoming arc별로 검사해 0건이었다. 이는 후보 집합 안의 검사이며 제외 관계까지 모순이 없다는 뜻은 아니다.

## 근본 원인과 구현 계약

현재 [지도 생성기](<C:/Users/playdata2/Documents/final_workspace/datasets/mobility/scripts/build_road_graph_v2.py:89>)는 highway way를 읽으며, [출력 설정](<C:/Users/playdata2/Documents/final_workspace/datasets/mobility/scripts/build_road_graph_v2.py:203>)에 `turn_restrictions: 생략`을 기록한다. [길찾기](<C:/Users/playdata2/Documents/final_workspace/final_project_cs/app/domains/travel_ops/instances/mobility/engine/graph_router.py:465>)는 `dist[node]`와 `closed(node)`를 쓴다. 한 교차로에 다른 도로로 도착한 두 상태를 합치므로, 제약 파일만 읽게 해서는 해결되지 않는다.

```mermaid
flowchart LR
 A[원문 관계·도로 그래프] --> B[차종·시간·방향 해석]
 B --> C[교차로와 들어온 간선별 상태]
 C --> D[금지·허용 회전 검사]
 D --> E[제약을 지키는 차량 경로]
```

1. **탐색 상태를 `(node, incoming_arc)`로 분리한다.** predecessor, best cost, closed도 같은 상태 단위로 유지한다. via way 제약은 접두 경로 상태를 추가한다. 단순히 교차로를 전부 차단하지 않는다.
2. **no는 해당 방향쌍, only는 허용되는 나가는 방향을 검사한다.** 같은 way 유턴은 정확히 역방향인 arc를 구별한다. 같은 way의 앞으로 이어지는 조각을 유턴으로 막지 않는다. 여러 only 또는 no/only가 충돌하면 검사 결과를 남긴다.
3. **출발·도착의 부분 간선에도 상태를 전달한다.** [끝점 1m 예외](<C:/Users/playdata2/Documents/final_workspace/final_project_cs/app/domains/travel_ops/instances/mobility/engine/graph_router.py:417>)와 목적지의 마지막 부분 간선 연결이 제약을 우회하지 않게 한다. 출발 위치가 교차로 자체인 경우의 incoming 없음은 별도 계약으로 정한다.
4. **기동 시 그래프·제약 파일 해시를 함께 검사한다.** 태그·회원이 미지원인 경우 적용했다고 표시하지 않는다. OSM 자료에서 확보한 제약만의 준수율과 실제 도로의 완전성을 구별한다. 도보·자전거에는 일반 자동차 제약을 자동 적용하지 않는다.

예를 들어 A도로에서 교차로로 들어와 B도로로 좌회전이 금지된 경우, C도로에서 같은 교차로로 들어와 B도로로 가는 상태는 별도로 탐색해야 한다. 이 차이를 살리는 것이 들어온 간선을 상태에 포함하는 이유다.

다음 관문은 실제 그래프 후보의 금지쌍을 경로가 통과하지 않는지, 금지 없는 경로가 보존되는지, 우회 거리·시간이 어떻게 달라지는지를 재실행하는 것이다. A*와 Dijkstra를 같은 제약 상태에서 대조하고, node 단위 탐색이 틀리는 작은 반례·only·같은 way 유턴·부분 간선·via way·조건/차종 예외를 각각 확인한다. 웹 대조의 경로 거리 차이가 줄었다고 말하려면 기존 차량 표본과 신규 웹 경로를 같은 조건으로 다시 계산해야 한다.
