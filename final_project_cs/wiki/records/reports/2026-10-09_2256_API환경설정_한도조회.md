# 관리자웹앱 API 환경설정 한도 조회

관리자 사용량 화면에서 외부 API 25종과 OpenAI 장애 대체 호출 1종의 현재 설정 상한을 볼 수 있게 했다. 호출 이력이 없어도 표시하며 ENV 이름·명시 설정/기본값·일/월 한도·DB 사용 기록·운영자 지정 상한을 구분한다. x600 서버에는 아직 배포하지 않았다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 설정 목록과 조회 구현 | 완료 | 26/26 = 100% |
| 선택한 백엔드·경계 검증 | 통과 | 127/127 = 100% |
| 화면·중계·기존 기능 시험 | 통과 | 7/7 = 100% |

## 사용자가 보는 결과

관리자 로그인 → 사용량 → **API 환경설정 한도**에서 API 또는 ENV 이름으로 찾고 ‘한도 다시 읽기’로 재조회한다. 이 버튼은 현재 프로세스의 값을 읽으며 ENV 파일을 새로 읽거나 수정하지 않는다. ENV 파일 변경은 운영 앱 재시작 뒤 보인다.

ITS 월 한도 0은 미설정·세기만, 일반 소스 하루 0은 간격 제한 안 함, OpenAI 장애 대체 상한 0은 호출 차단으로 표시한다. 값 자체와 뜻을 함께 보여 주므로 0을 공급자 무료 무제한으로 오인하지 않는다.

DB 사용량이 없으면 미계측으로 표시한다. DB 마지막 기록 상한은 마지막 호출 때의 값이며 지금 읽은 설정값·운영자 설정값과 다를 수 있다. 공공 소스는 한국 시각, OpenAI 장애 대체 호출은 UTC 계측을 읽는다. Google·카카오 과금 단위별 예산은 기존 현황에서 본다. 이 화면은 해당 운영 프로세스의 설정이며 별도 프로세스의 ENV 일치나 다른 DB 사용량 합산을 증명하지 않는다.

## 발견한 결함과 남은 범위

조회 초안의 UTC 기간 오류와 DB 구현체 직접 의존은 검증 중 고쳤다. 관리자 중계를 실제로 읽으며 기존 감시·시뮬레이션 경로 허용 누락과 검색 조건 전달 누락도 발견해 수정했다. 경로를 무제한 개방하지 않고 기존 UUID 검사와 운영 API 인증·CSRF 검증을 유지했다.

- [기간 경계 결함](debugs/2026-10-09_2256_API한도_계측시간대.md)
- [DB 의존성 결함](debugs/2026-10-09_2256_API한도_DB의존성.md)
- [관리자 중계 결함](debugs/2026-10-09_2256_관리자_중계경로_누락.md)

DB 표 추가나 ENV 값 변경은 필요하지 않다. 커밋·push·x600 서버 배포는 하지 않았다. 환경파일 자체의 출처(.env인지 프로세스 ENV인지)는 추정하지 않고 명시 설정과 기본값만 구분한다.

추가로 실행한 **전체 결함 문서 상태 검사**는 105/116 = 약 91% 통과, 11건 실패였다. 실패는 이번에 수정하지 않은 문서의 상태 표기 문제다. 해당 문서의 실제 해결 여부를 확인하지 않고 고치지 않았다. 이번에 작성한 결함 문서 4개만 선택한 검사는 4/4 통과했다. 로컬 Python 콘솔 종료 시 pyreadline3 핸들 경고가 있었으며 선택 검사의 종료 코드는 0이었다.
