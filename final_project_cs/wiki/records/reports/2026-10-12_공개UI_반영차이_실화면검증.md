## 환경과 증거

2026-10-12, Codex in-app browser에서 소개·새 계획·새 접수·기존 등록 여행을 확인했다. 사용자가 열어 둔 여행 탭은 변경하지 않고 별도 fresh 탭을 사용했다. `test1`과 `test2`라는 합성 시험 입력을 실제 공개 cs 프로젝트 서버에 접수했다. 최종 여행 등록, 기존 여행 일정 변경, GPS 권한 허용, 약관의 새 동의는 수행하지 않았다.

[실제 화면 증거](../evidence/2026-10-12_public-ui-audit-1220/)에 스크린샷 31장을 보존했다. 처음 촬영한 01은 선택 목록이 화면 아래에 있어 목록 증거로 쓰지 않는다. 24·25가 목록 표시 증거다. 09·11·16은 마커 외곽 누름으로 선택되지 않은 시도이며, **18이 실제 마커 몸체 선택과 토스트 재현 증거**다. 26~29 파일 이름에 모바일 표현이 있으나 실제 폭은 1280이었으므로 모바일 증거로 쓰지 않는다. **25·30·31은 실제 `innerWidth=375`, `scrollWidth=375`를 확인한 세 화면**이다. 기존 파일을 덮거나 삭제하지 않았다. 새 산출물이므로 수정 전 백업 대상은 없었다.

## 아직 판정하지 않은 5항목

- 관성 있는 휠·터치로 수정안 진입 뒤 계속 바닥으로 내려가는 현상: 이번 공개 확인은 버튼 전환만 수행했다.
- 지도 이동의 연속 프레임 부드러움·같은 방향 스택과 반대 방향 분리: 14의 잘못된 현재 마커 합침은 재현했지만 연속 녹화와 의도한 방향별 좌표 사례는 최신 배포 후 재검사해야 한다.
- 최종 파싱 일정0개일 때 이전 입력 화면 복귀: 접수 시작 순간의 0은 완료0과 다르므로 그 표시를 실패로 판정하지 않았다.
- 브라우저 GPS 권한·실제 위치 및 서비스 동의 재사용: 지도 도구 버튼 누락은 확인했지만 민감한 위치 권한을 새로 허용하지 않았다.
- 설문 대기 알림 단추 중복·순간 설문 로딩 깜빡임: 이미 답한 설정이 재사용되어 해당 조건을 강제로 초기화하지 않았다.

## Git·공개 실행 차이와 후속

커밋·푸시 담당 채팅이 팀·개인 role-manager·develop 네 대상의 기존 화면 코드 반영을 보고했다. 이후 준비된 test13~15와 분류를 반환하는 API 변경 누락을 발견해 보완 중이라고 보고했다. 전체 웹 CI도 진행 중이므로 최신 변경 전체 통과로 기록하지 않는다.

읽기 전용 배포 기록에서 role-manager를 따라가는 자동 반영이 `Compose configuration drift; reconcile before deployment`로 **컨테이너 변경 전에 중단**됨을 확인했다. 반복된 중단 때문에 공개 실행 이미지가 이전 버전에 남아 있다. 안전 검사를 끄거나 DB를 재생성하지 않았다. 후속 읽기 전용 대조에서 API·worker의 배포 버전 표시 환경값만 현재 실행값으로 복원해 계산하면 API·worker·web 구성 해시가 3/3 일치했다. 담당 채팅은 그 차이를 확인했으며 자동 반영을 안전하게 잇는 최소 코드 보완·시험·후속 푸시를 요청받았다. 이 기록에는 접속 별칭·접속 주소·환경 파일의 비밀값을 넣지 않는다. 원인 추가 전 보고서는 [백업](../evidence/2026-10-12_public-ui-audit-1220/_backup/report-before-deployment-cause/)에 보존했다.

[소스 대조](../evidence/2026-10-12_public-ui-audit-1220/source-branch-parity.json)는 최초 통합 목록의 src 파일 76개와 당시 팀 매니저 blob을 비교한 결과다. 56개 동일·20개 차이지만 기존 develop 보존과 공유 작업 폴더의 후속 수정이 섞여 있으므로 차이20개를 누락20개로 판정하지 않는다. 검증된 사용자 수정의 누락 여부는 담당 채팅에 의미 단위로 대조하도록 전달했다. 이 목록은 전체 저장소 동일성을 주장하지 않는다.

공개 미반영 항목과 스크린샷 위치는 사용자가 지정한 `git commit push` 채팅에 전달했다. 최신 코드 반영 뒤 위 미충족·미확인 항목을 다시 확인하기 전에는 공개 수정 완료로 닫지 않는다.

보고서 원인 추가 직전 백업 명령은 디스크 여유0으로 실행되지 않았는데 편집이 먼저 진행됐다. [직전 판](../evidence/2026-10-12_public-ui-audit-1220/_backup/report-before-deployment-cause/)은 도구 변경 기록에서 복원했으며, 변경 전 디스크 복사본이라고 주장하지 않는다. 이번 설명을 추가하기 전에는 [현재 판을 먼저 복사](../evidence/2026-10-12_public-ui-audit-1220/_backup/report-before-clarification/)했다. 이후 실행 복구를 위해 확인된 Next 빌드의 임시 cache 폴더9개만 정리했고 소스·실행 산출물·촬영·백업은 보존했다. [정리 기록](../evidence/2026-10-12_public-ui-audit-1220/cache-cleanup.json)에 대상과 파일 크기를 남겼으며 직후 C 드라이브 여유583,626,752바이트를 확인했다.

mock 서버 시험: 이번 공개 검사에서는 실행 안 함. 앞선 로컬 검증을 이 검사 통과 수에 합치지 않음.

실서버 확인 (cs 프로젝트 서버 응답): 했음 — 공개 test1·test2 실제 접수, 검증 결과·수정안 읽기, 기존 여행 새 탭 조회. 실제 거래·여행 등록은 수행하지 않음.

[브라우저 오류 기록](../evidence/2026-10-12_public-ui-audit-1220/runtime-errors.json): 관찰한 4개 탭에서 도구가 반환한 최근 error 기록은 빈 목록이다. UI 결함이 없다는 뜻이 아니다.
