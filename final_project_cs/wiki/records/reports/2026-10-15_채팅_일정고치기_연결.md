# 채팅으로 일정 고치기 — 웹 「일정 수정」과 같은 길로 연결 — 2026-10-15 (Claude, 사용자 지시 「이미 있는 기능 그냥 써서 처리해서 답 주면 되는 건데」 · 「전수검사하고 다시는 이딴 문제 없게」)

## 왜

10-14 x600 실서버 재시험(질문 433개, [시간 질문 기록](2026-10-14_시간질문_기준칸_v4.md)과 같은 날)에서 일정 관리 요청이 **「아직 채팅에서 못 해요」로 막혀** 있었다.
막은 것은 10-14 새벽(커밋 `49dd6cb4`) 내가 한 일이다 — 엉뚱한 「다른 곳으로 바꿔 줘」 되묻기를 정직한 안내문으로 바꿨을 뿐 **기능은 잇지 않았다.**
웹 「일정 수정」(등록한 여행 다시 열기 → 고치기 → 완료, `[2026-10-13 사용자 결정]`)은 같은 일을 이미 하고 있었다.

| 고객 요청 | 10-14 실서버 재시험 결과 | 막은 곳 |
|---|---|---|
| 시각 · 날짜 옮기기 | 51건 중 40 「아직 채팅에서 하지 못해요」 · 실제로 바뀐 것 1 | `UNSUPPORTED["change_time"]` · `scope_guard` |
| 일정 넣기 | 8/8 안내문 | `UNSUPPORTED["add_item"]` (활동 회신 10번 「최종발표 뒤로」) |

| 이름 말한 곳으로 바꾸기(「경복궁 대신 창덕궁 가자」) | 「바로 바꾸는 기능은 아직 없어요」 + 창덕궁이 빠진 다른 안 | `named_destination` → 다른 안만 |

## 바꾼 것 — 새 실행기를 만들지 않고 웹 「일정 수정」과 같은 서버 기능을 부른다

```
채팅 문장 → 해석(학습 E4B) → 고칠 것(`chat_edit.ops_for`) → 다시 열기 → 고치기(이름 찾기 포함) → 검사 → 완료(`reopen_commit.commit`) → 새 판 + 변경 이력 + 알림 1개
```

- `components/intake/reopen_commit.py`(새) — 웹 「완료」(`trip_api._confirm_reopened`)의 새 판 쓰기를 공용 함수로 뗐다. 웹은 이 함수를 부른다(동작 같음 — `test_trip_reopen` 14/14).
  장소 저장 규칙(`store_place`)과 `EXTERNAL_PLACE_SOURCES` 도 여기로(웹 경로가 같은 이름을 다시 내보낸다).
- `components/conversation/chat_edit.py`(새) — 해석 → 고칠 것 → 위 길. 시각 옮기기(분 · 새 시각 · 날 · 「지금」 · 범위 전체 한꺼번에) · 넣기(이름 + 시각 또는 다른 일정 앞뒤) · 빼기 · 이름 말한 곳으로 바꾸기 · 순서 바꾸기 · 고정/풀기.
  - 값은 해석이 낸 칸만 쓴다. 모르면 **되묻는다**(`need_*`) — 서버가 짐작으로 채우지 않는다.
  - 옮기는 크기는 모델이 아니라 **문장에 적힌 시간 · 분**에서 센다(`spoken_minutes`), 방향(늦춤 +/당김 −)은 문장의 낱말(`spoken_direction`)이 먼저.
  - 고정 · 예약 · 지난 일정 · 판정 위반은 웹과 같이 막고 까닭을 그대로 답한다. 한 여행의 채팅 고치기는 한 번에 하나(여행 단위 잠금). 못 끝낸 수정 접수는 항상 닫는다.
- `decision_unit.py` — `UNSUPPORTED` 를 비웠다. 할 일 추가: `swap_order` · `lock_item` · `unlock_item` · 서버 전용 `replace_named`. 시간만 바꾸라는 말을 장소 교체로 읽었으면 막지 않고 시각 옮기기로 보낸다. 조건 말(「비 오면」)이 붙은 고치기는 지금 바꾸지 않는다.
- 이름 말한 곳(`replace_named`)은 **먼저 이름으로 장소를 찾는다**(`TripDesk.find_place` — 웹 고치기와 같은 찾기: 우리 장소 표 → 관광공사 → 요식 원장 → 카카오). 한 곳이면 바꾸고, 못 찾으면(모르는 이름 · 「비건 식당」 같은 설명) 바꾸지 않고 「한 곳으로 찾지 못해」 라고 먼저 밝힌 뒤 다른 안을 보인다.
- `schedule_query.matching` — 조회 범위 계산을 떼어 「오후 일정 전부 한 시간씩」도 같은 범위를 쓴다.
- `[2026-10-14 활동 회신 10번]` 의 「채팅으로 넣기는 최종발표(10-26) 뒤」는 사용자 지시(10-15)로 앞당겼다.
- 숙소: 담당 선택 · 숙박 팀 후보 길은 같은 날 다른 세션(LB-02, `4df63ff5`)이 먼저 올려 **내 중복 변경은 뺐다.** 내 쪽은 시험만 남겼다(아래).

파일: `app/domains/travel_ops/components/conversation/{chat_edit,decision_unit,schedule_query,trip_desk,trip_messages,case_dispatch}.py` · `components/intake/reopen_commit.py`(새) · `entry/trip_api.py`.

## Codex 검토 — 내 변경을 독립으로 읽게 했다(읽기 전용, 실행 시험은 안 함)

5건 지적, 모두 고쳤다.

| 지적 | 고침 |
|---|---|
| 「비 오면 북촌 30분 늦춰」가 조건을 무시하고 바로 실행(높음) | 고치는 할 일에도 조건 말이 있으면 지금 바꾸지 않는다(`_CONDITIONAL`) |
| 예상 밖 오류 때 수정 접수가 열린 채 남아 웹 「일정 수정」을 막음(높음) | `finally` 에서 이 요청이 연 접수를 닫는다 |
| 웹이 열어만 둔 빈 접수를 채팅이 같이 씀(높음) | 빈 접수는 닫고 채팅 몫을 새로 연다. 고친 값이 있으면 채팅이 거절한다 |
| 두 요청이 같은 접수를 나눠 쓰다 한쪽 실패가 다른 쪽을 닫음(중간) | 여행 단위 잠금(`pg_try_advisory_lock`) |
| 「30분 앞당겨」를 모델이 0 으로 내면 늦춤(중간) | 방향은 문장 낱말이 먼저, 방향을 모르면 되묻는다 |

## 남은 한계 — 숨기지 않는다

- 「어제 일정 바꿔줘」 · 「오늘 일정이랑 내일 일정 통째로 바꿔줘」 같은 하루 통째 요청은 해석이 실패한다(`DecisionFailed`) — 범위가 너무 넓은 요청이라 되묻는 길이 아직 없다.
- 순서 바꾸기는 같은 날 · 겹치지 않는 경우만 맞춘다. 앞 일정의 이동 시간이 길면 판정이 막을 수 있다(그때는 막은 까닭을 그대로 답한다).
- 여행 이름 · 인원 · 여행 전체 날짜 옮기기는 이번 범위가 아니다(웹 수정 모드도 잠겨 있다).
- 넣기는 「카페」처럼 종류만 말하면 이름을 되묻는다(후보를 먼저 보여 고르게 하지는 않는다).
- 이 재생 · 시험은 학습 E4B 가 새 칸(기준 · 할 일 이름)을 지시문으로만 배운 상태다 — 틀리는 문장은 모델 쪽이다. 다음 단계는 정답표로 모델에 가르치는 것.
- 응답 시간은 x600 에서 재지 않았다. 고치기는 해석 1회 + 서버 처리라 모델 시간은 그대로이고 서버 쪽 처리(이름 찾기 · 검사)가 더해진다.
- 숙소: 실제 마이리얼트립 · 구글 호텔 호출은 이번에 하지 않았다(횟수 제한). mock 자료로 경로만 확인했다.

## 앞으로 이런 일이 없게

- 「못 해요」 안내문을 넣을 때는 **같은 일을 하는 기존 기능이 있는지 먼저 찾는다** — 기능이 있으면 막지 말고 잇는다(이 기록의 원인).
- 채팅 고치기가 거절하는 문구는 `chat_edit._refusal` 한 곳이다. 새 「못 해요」를 늘리면 이 표와 `test_chat_edit_web.py` 에 같이 적는다.
