# 2026-09-22 16:30 — 상시 실행을 서버 쪽으로 옮기는 준비

## 1. 목표

지금 이 제품의 상시 실행이 **전부 개발자 PC 의 콘솔 창**에 매달려 있고,
「안 돌고 있었다」를 알아차릴 방법이 없다. 사용자 지시로 **옮기는 준비**를 했다 —
문서·사용자가 실행할 스크립트·점검까지. ★**시스템 설정은 하나도 바꾸지 않았다**
(서비스 등록·스케줄러 생성·레지스트리·방화벽 없음, DB 정지·재기동 없음).

## 3. 검증 — 돌린 것과 나온 것

```powershell
python -m scripts.ops.install_services              # 미리보기 4개 (sweepers·outbox·daily_feedback·app)
python -m scripts.ops.install_services --only postgres
python -m scripts.ops.install_services --status     # 걸려 있는 것 0/4개
python -m scripts.ops.tick sweepers --show          # 명령만 출력
python -m scripts.ops.tick outbox                   # ★실제로 한 회차 돌렸다 (아래)
python -m scripts.ops.healthcheck                   # OK 6/12 · 경고 2/12 · 실패 1/12 · 못확인 3/12
```

`--apply` 는 **한 번도 주지 않았다.** `--status` 가 `0/4` 로 그것을 확인한다.

### ★이 작업 중 실제로 밖으로 나간 것 — 통지 8건

`python -m scripts.ops.tick outbox` 한 회차가 `handled=237` 을 냈고, 그중
`trip.notice` **8건이 디스코드 웹훅으로 나갔다**(나머지 229건은 시험 잔재라
바깥으로 안 간다 — 디스코드로 가는 topic 은 `trip.notice` 뿐이다,
`app/infrastructure/notify/discord.py:123`).

- 8건은 시나리오 테넌트 4곳의 여행 안내(하루 시작·일정 변경)다. **`attempts=1`**,
  즉 **그때까지 한 번도 시도된 적이 없다.** 만들어진 시각 08:24~08:29, 나간 시각 16:22 —
  **약 8시간** 바깥함에서 잤다.
- ★**바깥으로 메시지가 나가는 것은 먼저 물었어야 했다.** 점검이 설정 테넌트(`demo`)만
  보고 「pending 0건」이라고 했기에 보낼 것이 없다고 보고 돌렸다. 그 판단이 틀렸다.
- 되돌릴 수 없다(보낸 메시지는 못 지운다). 기록으로 남긴다.

### 그 사고가 드러낸 결함 — 점검이 테넌트 하나만 봤다

배달 일꾼은 `--tenant` 없이 돌면 **전체 테넌트**를 집는데, 점검은 설정 테넌트만 세고
있었다. 같은 실수를 사람도 한다. **전체를 세고 설정 테넌트의 몫을 따로 적도록 고쳤다**
(`scripts/ops/healthcheck.py`). 멈춘 Case 도 같은 방식으로 고쳤다 — 되잡기는 설정
테넌트만 훑으므로 **다른 테넌트의 멈춘 Case 는 아무도 안 본다**는 사실을 세어서 알린다
(`[실측]` 지금 1건 있다).

### 점검이 찾은 것 둘 (안 고쳤다 — 이 작업의 범위 밖)

1. **앱은 8043 에서 도는데 `ACOP_PUBLIC_BASE_URL` 은 8042 다.** 이 값이 **고객에게
   나가는 여행계획서 링크에 박히는 주소**라, 앱이 살아 있어도 링크는 죽은 주소를 가리킨다.
2. **DB 가 서비스가 아니다.** 부모가 셸/콘솔이라 그 셸이 사라지면 종료 기록 없이 함께 꺼진다
   (조사는 `wiki/records/manuals/운영_로컬DB_기동과_비정상종료.md`).
