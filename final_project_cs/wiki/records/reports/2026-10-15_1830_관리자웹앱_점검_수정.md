## 찾은 것과 고친 것

1. **채팅 하루 한도가 실제로 안 걸렸다.** 스냅숏의 `chatLimit` 50 은 저장값이 아니라 가드레일 기본값이었고(운영 기록에 `save-limits` 0건), 고객 쪽 검사(`admin_service.access_policy`)는 저장값이 없으면 `None` = 한도 없음으로 처리했다. 웹 횟수 한도(`web.limits_enabled`)도 꺼져 있어, 오늘 한 사용자가 76번 채팅해도 막히지 않았다(스냅숏 실측).
   - 고침: 저장값이 없으면 화면과 같은 기본값(`default_chat_limit()`)을 적용. **0 = 한도 없음**(모든 사용자 기본값 · 사용자별 예외 모두). 웹 횟수 한도가 켜져 있을 때도 사용자 한 명 칸은 이 값을 따른다(0 이면 그 칸은 막지 않음). 입력 범위 1 이상 → 0 이상(서버 `ChatQuota` · 화면 zod · 입력 칸). 화면은 0 을 「한도 없음」으로 표시하고 한도 도달 집계에서 뺀다.
2. **API 환경설정 한도 화면에 조정 기능이 없었고**, 다른 화면의 「운영 상한 조정」은 한 번이라도 불린(DB 예산 줄이 있는) API 만 받았다.
   - 고침: 화면의 각 줄에 「조정」 — 운영자 상한 저장(`api-cap`) · 지정 해제(`api-cap-clear`, 새 명령). 호출 기록이 없어도 DB 예산 소스면 정할 수 있다. ENV 보다 낮게만(높이면 422 — 기존 「낮추기만」 규칙 유지). DB 예산을 거치지 않는 소스(Open-Meteo 날씨 · 대기질 · ODsay 등)는 운영자 상한이 실제 호출에 걸리지 않으므로 단추 대신 이유를 보인다.
3. **「자료 조회 정책」 · 「결함 사후 분석」 화면이 열리지 않았다** — 관리자웹앱 중계가 `source-policy` · `diagnostics` 경로를 허용 목록에 넣지 않아 404.
   - 고침: 중계 허용 목록에 두 경로(진단은 목록 · `/{지문 64자}/customers|events|resolution`)를 더했다.
4. **「웹 제한값」 · 「보관 기간」 화면이 503** — 운영 앱이 이 화면용 API 를 부를 열쇠(`ACOP_OPS_API_KEYS`)에 `limits:read` · `limits:write` 가 없다. 오라클 서버 열쇠 생성기 `deploy/arm/admin_env.py` 의 `OPS_SCOPES` 에 두 scope 가 빠져 있었다.
   - 고침: 저장소의 `OPS_SCOPES` 에 두 scope 를 더함(기준은 origin/role-manager 의 c6f656863 판). **오라클 서버에 적용은 아직** — 서버의 `control/admin_env.py` 를 같은 내용으로 고치고 `sudo ./admin_env.sh keys` 를 돌려야 한다. 이 세션의 실행은 자동 권한 심사(비밀 저장소 쓰기)가 막았다.
