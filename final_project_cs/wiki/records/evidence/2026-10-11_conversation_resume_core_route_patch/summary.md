# 공통 답변 재개와 해석 입력 보존 최종 검증

같은 담당·다른 담당으로 재개할 때 해석된 업무 입력을 보존하는 변경까지 검증했습니다.

| 할 일 | 상태 | 진행 |
|---|---|---|
| 로컬 개발 DB 연결 통합시험 | 통과 | 30/30 = 100% |
| DB 없는 적용기 계약시험 | 통과 | 2/2 = 100% |
| 수정 파일 린트 | 통과 | 7/7 = 100% |
| 시험 전후 해시 비교 | 동일 | 8/8 = 100% |

전체 시험은 32/32 = 100% 통과했고, 실패·준비 단계 오류·건너뜀은 각각 0개입니다. 실행 시간은 23.33초, 종료 코드는 0입니다. 통합시험의 분모는 신규 고객 재개 19개와 기존 여행 승인 11개입니다. 별도 계약시험 2개는 DB를 사용하지 않습니다.

내부 `resume_route`는 기존 팀 식별자 반환뿐 아니라 `{owner_team_id, state_patch}`도 반환할 수 있습니다. 담당이 같더라도 해석 입력이 있으면 등록된 담당을 검증하고 같은 트랜잭션의 `ROUTED` 이벤트로 보존합니다. 팀에 제공할 상태만 허용하고 토큰·고객 답변·재개 기록의 덮어쓰기는 거부합니다. 공개 HTTP 입력은 추가하지 않았습니다.

같은 담당과 다른 담당 각각에서 `subject_ref`·`required_input_schema`가 실제 팀 입력과 감사 이벤트에 보존되는 시험 2개를 추가했습니다. 실제 적용 안내 우선·중복 재생, 입력 대기·토큰·중복·권한·버전·팀 변경, 기존 여행 승인 회귀도 함께 통과했습니다.

실행 환경: Python 3.12.7, `PYTHONPATH=.tmp/conversation-python`의 tiktoken 0.12.0, `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`, `-p no:cacheprovider`. 로컬 개발 PostgreSQL과 애플리케이션 내부 API를 사용했으며 운영 배포된 cs 프로젝트 서버 응답은 확인하지 않았습니다.

전체 출력은 `core-pytest.log`, 기계 판독 결과는 `core-results.xml`, 린트 출력은 `core-ruff.log`, 코드·시험 해시는 `hashes-before.json`과 `hashes-after.json`, 수치 정본은 `summary.json`에 보존했습니다. 이 기록은 직전 30개 검증 이후의 추가 변경까지 포함한 최신 검증입니다. 커밋·푸시·배포는 하지 않았습니다.
