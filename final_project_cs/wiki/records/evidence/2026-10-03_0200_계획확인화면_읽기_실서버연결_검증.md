## 2. live 빌드 전체 (테스트용 모방 서버, 실서버 아님)

```bash
PLAYWRIGHT_CHANNEL=chrome npx playwright test -c playwright.live.config.ts
```

첫 실행에서 새 시험 1개가 실패했다(나머지 57개 통과).
- 실패 내용: `getByRole('listitem').filter({ hasText: '10/1 09:00 경복궁 관람' })`에서 「→ 1일차 09:00 · 경복궁 관람」을 기다리다 `element(s) not found`.
- 원인: 마지막 줄을 그리자마자 확인 화면으로 넘어가 줄 목록이 사라졌다.
- 조치: 다 그린 뒤 0.8초 머물게 하고, 순간적인 「읽음」 표시 확인은 단위 시험으로 옮겼다.

고친 뒤:

```text
  ok  6 tests\live\flow.spec.ts:46:1 › 서버가 읽는 동안 새 계획 확인 화면이 서버의 원문 줄을 읽는 중으로 보이고, 읽기가 끝나면 확인 화면으로 넘어간다 (6.3s)
```

## 4. 로컬 실서버

| 항목 | 내용 |
|---|---|
| API | `final_project_cs`에서 `PGTZ=Asia/Seoul TZ=Asia/Seoul ./.venv/Scripts/python.exe -m uvicorn app.presentation.api.app:app --host 127.0.0.1 --port 8042`(작업 트리 `.env`의 DB `acop_cs_manager`, 팀 채널 알림 주소 비어 있음) |
| 웹 | `NEXT_PUBLIC_DATA_MODE=live NEXT_PUBLIC_API_BASE=http://127.0.0.1:8042 NEXT_PUBLIC_MAP_PROVIDER=osm NEXT_PUBLIC_TURNSTILE_SITE_KEY= npm run dev` |
| 조작 | 앱 내장 브라우저에서 `/trips/new`에 아래 계획을 넣고 「계획 확인하기」를 눌렀다 |

```text
1일차 · 2026-10-20
09:00 경복궁 관람
12:00 광장시장 점심
15:00 북촌한옥마을 산책
```

1초 뒤 화면 글(발췌):

```text
계획을 확인하고 있어요
받았어요 / 일정 읽기 / 장소·운영시간 / 정리 완료
올린 계획
1일차 · 2026-10-20  읽는 중
09:00 경복궁 관람  기다리는 중

15:00 북촌한옥마을 산책  기다리는 중
찾은 일정 0개
```

4초 뒤에는 기존 접수 확인 화면으로 바뀌었다. 화면 글(발췌):

```text
내 여행
여행 계획 살펴보기 · 3개 일정 · 1일차 10.20
09:00–10:30 경복궁 관람 · 12:00–13:00 광장시장 · 15:00–16:30 북촌한옥마을 산책
여행 등록
```

API 서버 로그(이 접수만, 사전 확인 `OPTIONS` 제외, 접수 ID 가림):

```text
"POST /v1/web/session HTTP/1.1" 201 Created
"POST /v1/web/trip-intakes HTTP/1.1" 202 Accepted
"GET /v1/web/trip-intakes/{id} HTTP/1.1" 200 OK   ×3
```

여행 등록은 누르지 않았다. 앱 내장 브라우저가 초당 2장만 그리는 상태라, 줄이 차례로 「읽음」이 되는 움직임은 눈으로 확인하지 못했다.
