# 일정 생성기 — **살아 있는 앱에 실제 HTTP** 로 확인 (2026-09-22)

시험(`pytest`)은 `TestClient` 로 같은 프로세스 안에서 앱을 부른다. 이 기록은 **따로 뜬
uvicorn 에 네트워크로 요청을 보내** 같은 결과가 나오는지 본 것이다 —
`CLAUDE.md` §4 「백엔드·테스트 통과만으로 구현 완료라 하지 않는다」.

대상 `POST /v1/trips/plan` · 앱 `127.0.0.1:8042` · 모델 `gemma4:12b`(Ollama, 터널 경유) ·
테넌트 `demo` · 후보 출처 `place_catalog` 2,063행.

## ★먼저 걸린 것 — 살아 있는 앱이 **옛 코드였다**

첫 요청이 **405 Method Not Allowed** 였다. `POST /v1/trips/plan` 이 없으니
`GET /v1/trips/{trip_id}` 에 `trip_id="plan"` 으로 걸린 것이다.

그 앱은 **`--reload` 로 떠 있었는데 새 파일을 안 읽고 있었다.**

| | |
|---|---|
| 앱 프로세스 시작 | 16:28 |
| 일꾼(자식) 마지막 재기동 | **17:00** |
| 새 파일이 쓰인 시각 | 21:30 ~ 22:16 |
| `app.py` 시각만 갱신하고 2분 대기 | **안 읽었다** |
| 살아 있는 앱의 경로 수 | 42 (새 것 **없음**) |

즉 **17:00 이후의 코드 변경이 살아 있는 앱에 한 번도 닿지 않았다.** 그동안 `/health` 는
계속 200 이었고 어디에도 오류가 없었다 — 조용한 성공 위장이다(`RULE.md` §3.2).

`[추정 — 확인 못 했다]` 그 무렵 저장소 안에 시험이 만든 `.pytest-basetemp*` 폴더들이
생겼고 이것들은 **읽기 권한이 없다**(`grep` 이 `Permission denied` 를 낸다). 감시기가
cwd 를 훑다가 죽었을 수 있다. **확인한 것은 「안 읽는다」까지이고 원인은 못 가렸다.**

조치 — 앱을 **`--reload` 없이** 다시 띄웠다(상시 목록 `scripts/ops/jobs.py` 의 `app` 인자와
같은 형태). 경로 수 42 → **43**, `/v1/trips/plan` 이 목록에 들어왔다.

## 이 기록이 **말하지 않는 것**

- 「영업시간 0/12」는 카탈로그가 영업시간을 모른다는 뜻이다. **그 시각에 연다는 보장이 아니다.**
- 이동 항목이 없다 — 항목 사이 여유는 직선거리 ÷ 도보 80m/분 `[추정]`이고 경로를 조회하지 않는다.
- 두 번씩만 불렀다. 같은 요청을 반복했을 때의 편차는 **재지 않았다.**
