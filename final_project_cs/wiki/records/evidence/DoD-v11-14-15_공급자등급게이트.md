## 1. 등급 칸이 DB 에 생겼다 — 기본값은 실제 공급자 쪽

재현:

```powershell
python -m app.infrastructure.db.migrate
python -c "from app.infrastructure.db.session import get_connection; ..."   # 아래 출력의 질의
```

실제 출력(`information_schema.columns` · `pg_constraint` 직접 조회):

```
('tier', 'text', 'NO', "'real'::text")
('supplier_bookings_tier_chk', "CHECK ((tier = ANY (ARRAY['real'::text, 'simulated'::text])))")
rows by tier: [('demo', 'simulated', 4)]
```

- 기본값이 `real` 이다 — **등급을 잊은 행은 자동 실행 대상이 아니다.** 반대로 두면 잊음의 대가가 돈이다.
- 값은 DB 가 둘로 묶는다(CHECK). 오타가 조용히 「막힘」으로 흘러가지 않는다.
- 시연 tenant `demo` 의 4행은 `scripts/seed_travel.py` 재실행으로 `simulated` 가 됐다(시연용 Mock).

## 2. 게이트가 실제로 막는다 (행동)

재현:

```powershell
python -m pytest tests/integration/controller/test_travel_approval_proposal_reaches_waiting.py -v
```

출력 요약 — **11 passed**(기존 8 + 신규 3). 신규 3건:

```
test_an_approved_cancel_on_a_real_supplier_never_touches_the_ledger PASSED
test_a_supplier_row_without_a_tier_is_treated_as_real              PASSED
test_the_ledger_only_moves_for_the_simulated_tier                  PASSED
```

세 번째가 **같은 조립·같은 승인에서 등급만 바꿔** 두 결과를 나란히 잰다:

| tier | Case | 우리 예약 | 공급자 원장 | action |
|---|---|---|---|---|
| `real` | `escalated` (`action_rejected`) | `confirmed` | `confirmed` | `failed` |
| `simulated` | `resolved` | `cancelled` | `cancelled` | `succeeded` |

★등급은 **승인 뒤**에도 선다 — 첫 시험은 승인한 **다음에** 등급을 `real` 로 바꾸고 실행한다.

## 3. 게이트를 지우면 빨갛게 나는가 (★검사기 검사)

## 남은 것 (이 evidence 가 말하지 않는 것)

- **공급자 원장은 아직 우리 DB 안이다**(`supplier_bookings`). 실제 공급자 **API** 로 나가는 경로는 없다 —
  이 게이트는 그 경로가 생길 때 「등급을 보지 않고 나가는 코드」를 막으려고 미리 세운 문이다.
- 검사 범위는 `app/**` · `scripts/**` 의 **Python 문자열 리터럴 안의 SQL** 이다. 런타임에 조립되는
  SQL(문자열을 쪼개 이어 붙이거나 테이블명을 변수로 받는 코드)은 이 방법으로 못 잡는다.
  ORM·마이그레이션 SQL 파일도 범위 밖이다.
- DoD-16~21(변경 링크 · 위임 범위 N·M·K · 되돌림)은 여전히 **미측정**이다. 이 작업은 14·15 만 닫았다.
