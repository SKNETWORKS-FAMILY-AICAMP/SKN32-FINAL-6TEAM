## 데모 빌드와 브라우저 시험

```bash
NEXT_PUBLIC_DATA_MODE=demo NEXT_PUBLIC_MAP_PROVIDER=demo NEXT_PUBLIC_TURNSTILE_SITE_KEY= npx next build   # 성공, 경로 11개
PLAYWRIGHT_CHANNEL=chrome npx playwright test tests/e2e/onboarding-email.spec.ts
```

첫 실행은 2/11 실패였다. 둘 다 **시험 코드의 실수**였고 화면 동작은 설계대로였다.

1. 잘못된 주소를 여러 개 차례로 넣는 시험이 다음 값을 넣기 전에 칸을 비우지 않았다. 화면은 한 번 보인 오류를 고치거나 지울 때까지 유지한다(이메일 칸과 같은 규칙). 이메일 시험처럼 먼저 비우도록 고쳤다.
2. 영어 시험에서 두 칸을 모두 틀리게 넣어 「To leave it out, clear the field and continue.」가 두 번 보이는데, 한 개를 찾는 검사를 썼다. 2개를 세도록 고쳤다.

```text
  11 passed (38.7s)
```

## live 가짜 서버 시험

```bash

```

`tests/live/serve.mjs`가 `.next-live`에 live 모드로 빌드하고 가짜 서버(8043)에 붙인다. 새 시험은 카드에 이메일·웹훅을 넣고 설문을 마친 뒤 계획 접수→확인 등록까지 간 다음, 가짜 서버가 받은 모든 요청에 두 값과 웹훅 id가 없는지, 확인 요청 본문이 `{revision, survey}`뿐인지 본다.
