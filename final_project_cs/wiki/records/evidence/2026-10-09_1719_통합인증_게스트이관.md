## 확인한 경계

- 신규 계정은 현재 게스트 승격, 기존 회원 로그인은 게스트 여행·접수 보관.
- 콜백만으로 여행 소유자를 옮기지 않는다. 잘못된 nonce·재사용 표는 거절한다.
- 로그인 시작 CSRF 누락 거절. 다른 게스트와 기존 회원 여행 보존.
- 기존 회원끼리 소셜 연결 충돌은 거절하며 회원 계정 전환에서도 기존 여행을 이관하지 않는다.
- 표 발행 뒤 게스트가 회원으로 바뀌면 409로 거절하고 원래 여행을 유지한다.
- 게스트 상한 오류와 현재 첨부·계획조건을 함께 보존하고 로그인 안내를 구분한다.

## 환경과 한계

- 로컬 개발 DB 복구 전 시도는 연결 시간 초과와 미적용 선택 필드로 실패했다. DB 복구와 migration 060 적용 후 위 결과를 얻었다.
- Vitest 한 번은 sandbox 임시 파일 ENOENT로 실행을 못 마쳤다. 동일 2파일을 sandbox 밖에서 재실행하여 16/16 통과했다.
- migration 060 로컬 적용 및 외래키 보완 재적용 완료. x600 서버의 cs 프로젝트 서버에는 적용하지 않았다.
- IndexedDB 파일 보관은 구현과 타입·정적 검사까지만 확인했다. 실제 외부 OAuth 왕복과 브라우저 파일 복구 화면 시험은 별도 확인이 필요하다.
- 기존 여행의 Case 소유권과 진행 중 백그라운드 접수 이관 경계는 루트 통합 작업에서 확인한다.
