## 2. 웹훅 규칙 대조 (웹 ↔ 서버)

같은 입력 38개를 JSON 파일로 두고 두 쪽에서 판정했다. 입력은 정상 9개와 거절 대상 29개다. 거절 대상에는 호스트 6종, 길이 경계, 포트·버전·끝 슬래시·쿼리·조각·`%`·`;`·전각 숫자·대문자 등이 들어 있다.
- 웹: `model.ts`의 `DISCORD_WEBHOOK` 정규식을 읽어 node로 판정
- 서버: 작업 트리의 `customer_profile.parse_webhook`을 venv python으로 판정

웹 정규식은 rebase 뒤에도 바뀌지 않았다.

```text
agree 36/38 = 94%
web stricter than server: ['https://discord.com/api/webhooks/123456789012345678/AbC-def_123456789012345?', 'HTTPS://DISCORD.COM/api/webhooks/123456789012345678/AbC-def_123456789012345']
web LOOSER than server (bad): []
```

## 3. 모방 서버 브라우저 시험 (실서버 아님)

```bash
PLAYWRIGHT_CHANNEL=chrome npx playwright test -c playwright.live.config.ts
```

첫 실행: `55 passed / 1 failed`.
- 실패한 시험: 백엔드 담당이 넣은 「설문을 마친 뒤 새로고침해도 답이 남아…」
- 원인: 이 시험은 옛 버튼 이름 「등록하고 관리 시작」을 찾는다(`waiting for getByRole('button', { name: '등록하고 관리 시작' })`). 같은 커밋의 접수 화면 개편이 버튼을 「여행 등록」으로 바꿨다.

시험의 버튼 이름을 「여행 등록」으로 맞춘 뒤:


실패 내용: `getByLabel('나의 여행 계획')`의 기대값이 `""`, 받은 값이 예시 계획 전문이다(`trip-home.spec.ts:62`). 기대값은 `tests/e2e/helpers/app.ts`의 `registerExampleTrip`이 「예시 불러오기」를 누른 직후 읽은 값이다. 같은 시험을 `--repeat-each=3`으로 다시 돌린 결과 3번 모두 실패했다.

### 기존 결함 확인 — 변경 없는 `1c48943`

스크래치 폴더에 `1c48943`을 그대로 꺼낸 임시 작업 트리를 만들었다(`git worktree add --detach`). 그 안에서 `npm ci`를 하고 demo 빌드를 한 뒤 같은 시험을 돌렸다. 확인 뒤 임시 작업 트리는 지웠다.

## 실행하지 않은 것

- 최종 상태의 실서버 시험. 이메일 저장은 백엔드 담당 구현이고, 웹훅은 서버로 가지 않는다.
- `npm run check`의 빌드 단계를 `.env.local` 기준으로는 실행하지 않았다. 위 demo·live 빌드 두 번이 컴파일을 대신 확인한다.
- 실제 휴대폰, 다른 브라우저.
