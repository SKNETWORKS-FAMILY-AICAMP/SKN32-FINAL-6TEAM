## 관리자앱

실행 위치: `final_project_cs/frontend/apps/dev-console`.

```powershell
$env:NEXT_PUBLIC_CONSOLE_DATA_MODE='demo'
npm run check
$env:PLAYWRIGHT_CHANNEL='chrome'
npm run test:e2e
```

최종 출력 발췌:

```text
> @tripilot/dev-console@0.1.0 check
> npm run lint && npm run typecheck && npm test && npm run build
Tests  55 passed (55)
Running 12 tests using 2 workers
12 passed (28.5s)
```

린트·타입 검사·빌드 성공. 단위 55/55 = 100%, 브라우저 12/12 = 100%, 합계 67/67 = 100%. 두 앱의 최종 자동 시험 합계는 112/112 = 100%다.

기존 시험 도구의 브라우저 시나리오 7개를 보존하고 새 관리 화면 5개를 추가했다. 부분 참조번호/trace 검색에서 해당 발생을 열기, 상태·심각도·출처 조합, 서버 묶음 안의 상시 작업 발생 찾기, 새로고침과 조건 보존 복귀, 미제출 검색어 초기화, 잘못된 묶음/발생 ID, 0명과 상세 예시 없음, 320px/390px 표시를 검증했다. 명시적 demo 외 모드에서 관리 gateway가 샘플을 반환하지 않는 것은 단위 검사로 확인했다. 미설정 모드의 별도 브라우저 빌드는 이번에 실행하지 않았다.

첫 실행에서는 신규 필터의 label 문자열에 option 텍스트가 포함돼 정확한 이름의 선택상자를 찾지 못한 2건이 실패했다. label과 select를 분리하고 브라우저 검사도 `combobox` 접근성 이름을 사용하도록 보완했다. 링크의 접근성 이름도 명확히 했다. 시험 서버 종료가 지연된 초회는 정리 후 다시 실행했다. 이후 부모가 발견한 미제출 검색어 초기화 경로를 보완하고 위 최종 실행을 완료했다.

원문 로그는 로컬 임시 폴더의 `tripilot-dev-management-check-final.log`, `tripilot-dev-management-e2e-final.log`이며 초회 실패는 `tripilot-dev-management-e2e.log`에 남아 있다. 부모가 관리 홈·오류 목록·상세의 PC 캡처와 390px 상세 캡처를 직접 확인했다. 필터 label 보완 후 목록 캡처도 다시 확인했다.

## 문서·범위 확인

앱 안내·화면 기획·API 협의·External 인덱스·리포트·evidence·결함 기록 12문서의 최종 로컬 링크 존재 확인 결과: `Local document links: 102/102 exist` (102/102 = 100%). 변경 범위의 `git diff --check`를 통과했고, 현재 브랜치가 `role-eval-ui`임을 확인했다.

부모가 로컬 확인용 서버를 실행했다. 운영앱 `http://127.0.0.1:3300/users`, 관리자앱 `http://127.0.0.1:3200/` 모두 HTTP 200을 확인했다. 이는 배포가 아니라 이 PC의 확인용 실행이다.

실제 운영 연결·백엔드 변경·공용 배포·클로드의 사용자 웹 작업은 이번 검증 대상이 아니다. TeamFlow 조회는 네트워크 실패 및 자동 승인 검토 거절 뒤 사용자 지시로 생략했으며 후속 호출·티켓 발행을 하지 않았다.
