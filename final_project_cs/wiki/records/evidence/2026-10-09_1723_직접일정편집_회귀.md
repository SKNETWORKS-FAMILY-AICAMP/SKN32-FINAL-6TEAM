# 직접 일정 편집 회귀시험 실행 근거

- 날짜: 2026-10-09, 로컬 개발 DB, 실제 PostgreSQL 트랜잭션과 HTTP 요청을 사용했다.
- 공공 관광정보와 이동 계산은 mock 응답이다. 공개 배포 또는 실제 교통 시간표를 확인한 결과가 아니다.
- 변경 파일: `intake/pipeline.py`, 새 `intake/direct_schedule.py`, 새 단위·HTTP 회귀시험 각 1개.
- 실행 시점 코드: 기존 작업 트리 위 변경분이며 별도 커밋·배포하지 않았다.

검증한 경계: 11분 도보 후 즉시 시간 재배치, 연쇄 재배치, 예약·잠금 기준점 앞당김, 불가능한 보호 일정, 자정 앞 여유 활용 및 다음 날 보존, 운영시간 보호, 선택 이동수단 유지, 계산 실패 보존, 신규 추가·필수값·7일 범위, 고객/tenant 격리, 검사 실패의 claim·revision 롤백.

초기 실행은 샌드박스의 로컬 개발 DB 포트 접근 거절, 이후 로컬 개발 DB 복구 진행 중 setup 오류였다. 로컬 개발 DB 준비 확인 뒤 위 명령을 실행했다. 개발 DB를 별도로 기동하거나 재시작하지 않았다. 선택수단 단위시험 기대값 1개는 기존의 5분 탐색 및 올림 여유를 빼고 예상한 탓에 한 번 실패했고, 실제 기존 규칙의 10:10으로 기대값을 정정한 뒤 합본을 다시 실행했다.

추가 정적 확인: 변경 Python 파일 `compileall` 성공, 추적 변경의 `git diff --check` 성공.

mock 서버 시험: 이 하위 작업에서 웹 화면 반응 시험은 실행하지 않았다. HTTP 시험의 외부 관광·이동 응답은 mock이며 실제 DB를 사용했다.
