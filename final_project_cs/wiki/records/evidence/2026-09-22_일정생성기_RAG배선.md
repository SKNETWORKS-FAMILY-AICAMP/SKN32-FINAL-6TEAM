# 일정 생성기가 요청을 **우리 규정에 붙인다** (2026-09-22)

`POST /v1/trips/plan` 이 고객의 말로 **여행 코퍼스**를 검색해, 찾은 조각을
①모델이 순서를 짤 때 바탕으로 보이고 ②응답에 `evidence` 로 싣는다.

구현 [`planner.py::ground_request`](../../app/modules/travel_ops/planner.py) ·
코퍼스 [`knowledge/travel/`](../../knowledge/travel/) 12문서·130청크.

## ★★이것이 바꾸는 것은 「근거」이지 「후보 고르기」가 아니다

규정 문서는 **장소를 담지 않는다.** 무엇이 열려 있고 얼마인지는 `places`·`place_catalog`
가 안다. 그래서 규정으로 후보를 거르려면 **규정 문장과 장소 속성을 기계로 맞출 방법**이
있어야 하는데 지금 그것이 없다 — 카탈로그는 영업시간도 가격도 모른다(`coverage` 가
0/12 라고 적는 그 값이다).

**「RAG 를 붙였으니 초안이 규정을 지킨다」고 읽으면 안 된다.** 지금 보장하는 것은
「이 요청에 걸리는 규정이 무엇인지 함께 나온다」까지다.

| 하는 것 | 안 하는 것 |
|---|---|
| 고객의 말로 여행 코퍼스를 검색한다 | 규정으로 후보를 **거르지 않는다** |
| 찾은 조각을 모델에게 **바탕**으로 보인다 | 규정에서 시각·가격·장소를 **읽어 오지 않는다**(그건 DB 가 채운다) |
| 응답에 `evidence` 로 싣는다 | 취소 기한·위약금율 같은 **수치를 뽑지 않는다**(아래 「아직 막힌 것」) |
| 0건·실패를 `note` 에 적는다 | 규정이 없다고 초안을 멈추지 않는다 |

## 실측 — 살아 있는 앱(`127.0.0.1:8042`)에 실제 HTTP

요청 서울 · 2일 · 3인 · 「아이 동반이라 비 오면 갈 만한 실내 위주로, 유모차 끌고 다녀요」

    HTTP 200 · planner llm · 모델이 고른 것 8/8 · 판정 0회 고침 통과

| scope | 조각 | 점수 | 첫 줄 |
|---|---|---:|---|
| `travel_weather` | `t_doc_04#c3` | 0.5586 | 비가 온다고 실내 전시나 실내 체험이 깨지지는 않는다… |
| `travel_access` | `t_doc_12#c3` | 0.5523 | 어린아이가 있으면 유모차 이동과 수유 공간과 연령 제한을 본다… |
| `travel_weather` | `t_doc_04#c8` | 0.5343 | 비와 바람이 같이 문제가 되는 날이 있다… |
| `travel_weather` | `t_doc_05#c2` | 0.5079 | 경보 단계가 걸리면 어린이와 노약자가 포함된 일행에게는… |
| `travel_dining` | `t_doc_07#c3` | 0.5010 | 걸어서 갈 수 있는 거리가 가장 좋다… |

다섯 건 **전부 여행 scope** 다. 고객의 말 세 갈래(비 · 아이 동반 · 실내)가 각각 잡혔다.

★**이 표는 「규정이 초안을 바꿨다」를 말하지 않는다.** 같은 요청을 규정 없이도 돌려
비교하지 **않았다** — 모델이 매번 같은 것을 고르는지조차 재지 않았다.

## 안 섞이는지 — 쇼핑몰 코퍼스

`scope` 를 여행 넷으로 못 박았다. 2026-09-22 전에는 Activity 가 쇼핑몰 `refund` 를 끌어와
여행 질의 top-8 중 7건이 쇼핑몰 환불 문서였다
([그 기록](../reports/debugs/2026-09-22_정책scope에_문서가_0건인_팀들.md)).
「환불 받을 수 있나요 배송은 언제 오나요」로 물어도 쇼핑몰 문서가 0건인 것을 시험이 본다.

## 아직 막힌 것

취소 기한·위약금율 **수치**는 이 코퍼스로도 안 나온다 — `PolicyChunk` 가 `dict` 가 아니라
`_policy_hours`·`_penalty_rate` 가 항상 `None` 이다
([미해결 기록](../reports/debugs/2026-09-22_정책청크에서_수치를_못_꺼낸다.md)).
