## 1. 타입·린트·단위

`final_project_cs/frontend/apps/web`에서 실행. 빌드 폴더는 Git 밖이라 린트에서 뺐다.

```bash
npx tsc --noEmit
npx eslint . --ignore-pattern ".next-demo/**" --ignore-pattern ".next-dev-live/**" --ignore-pattern ".next-mock/**" --ignore-pattern ".next-live/**"
npx vitest run
```

```text
tsc exit=0
eslint exit=0
 Test Files  17 passed (17)
      Tests  153 passed (153)
```

새 단위 시험 6개(`src/features/plan-check/model.test.ts`)는 처음 실행에서 2개가 실패했다.
- 실패 1 — 그리는 순서: 스냅숏을 한꺼번에 받을 때와 나눠 받을 때 날짜 목록이 정해지는 차례가 달랐다. 날짜를 읽기 끝에 정하도록 고쳤다.
- 실패 2 — 진행률 분모: 지금까지 나타난 장소만 셌다(「장소 1/1」). 읽은 줄에서 전체를 세도록 고쳤다.

고친 뒤 시험 기대값 2곳(날짜 단계 위치, 확인 중 전체 수 4·2)을 맞췄다.

## 4. demo 브라우저 전체 (회귀)

```bash
PLAYWRIGHT_CHANNEL=chrome npx playwright test
```

```text
  x   6 tests\e2e\menu.spec.ts:91:1 › 플로팅 버튼 스위치는 기본 OFF(고정 하단 탭)이고, 켜면 플로팅 버튼으로 바로 바뀌어 새로고침 뒤에도 유지된다 (20.0s)
    Error: expect(locator).toBeHidden() failed
  1 failed
  3 skipped
  65 passed (2.9m)
```

**실패 1개**
- 실패 내용: 여행 화면의 `#trip-pane-button-schedule`가 12초 안에 숨지 않았다.
- 원인 판단: 이 시험은 메뉴·여행 화면을 다루며, 이번 변경(새 화면·새 주소·색 변수 추가)과 닿는 곳이 없다.
- 같은 파일만 반복해 돌린 결과:

```bash
PLAYWRIGHT_CHANNEL=chrome npx playwright test tests/e2e/menu.spec.ts --repeat-each=3
```

```text
  9 passed (24.3s)
```

전체 실행(작업자 2개)에서만 가끔 실패하는 시험으로 기록한다.

**같은 날 앞 작업과의 차이:** 앞 작업에서 계속 실패하던 `trip-home.spec.ts`의 1개는 이번 전체 실행에서 통과했다. 그 시험의 기존 결함(시험 도우미의 경쟁 상태)은 [앞 리포트](../reports/2026-10-03_0030_온보딩_알림복구카드_이식.md)에 있다.

**건너뜀 3개:** 네이버 SDK 빌드 전용 시험이다.

## 5. 브라우저로 본 것

- 앱 내장 브라우저(375×812)에서 개발 서버로 `/preview/plan-check`를 열었다.
- 화면별로 확인한 것:
  - 읽기 화면: 줄마다 체크와 찾은 일정 표시, 진행 막대
  - 확인 화면: 지도·목록, 「장소 3/4 · 이동 2/2」 숫자
  - 결과 화면: 여행 제목, 판정 표시, 「위치 미정」 칩
- 처음 캡처에서 목록이 흐리게 보였다.
  - 원인은 창이 초당 2장만 그리고 있어(`requestAnimationFrame` 1초에 2번) 나타나는 애니메이션이 첫 장면에 머문 것이었다.
  - 애니메이션이 끝난 뒤에는 모든 항목이 불투명도 1로 보였다.
- 실제 휴대폰, Safari·Firefox, 화면 낭독기로는 확인하지 않았다.
