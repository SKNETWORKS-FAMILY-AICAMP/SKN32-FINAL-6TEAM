# 지도·카드·하단 안내 개정 계약 — 2026-10-09

## 사용자 결정

- 지도 상태막대 순서: 선택 일정 이름·종류 → 확인 필요 ! 수 → 변경 아이콘·수 → 전체 되돌리기(실제로 되돌릴 변경이 있을 때).
- 변경 글자는 제거하고 교체/변경을 나타내는 아이콘을 쓴다. 접근 가능한 이름과 hover/focus 툴팁은 유지한다.
- 카드 제목 옆 같은 줄: 자동 추천 아이콘 → 수정 아이콘 → 삭제 아이콘. 아래 중복 자동 추천/수정 단추는 제거한다.
- 아래로 더 내리면 수정안이 나온다는 안내는 첨부의 부드러운 초록색·곡선·아래 화살표·점 표시를 따른다. 목록 끝과 하단 전체 자동 추천 영역이 가까이 이어져 보인다. 클릭/밀기 동작과 저장 전 미리보기 계약은 유지한다.
- 화면 밖 거리 칩에 포함된 일정은 동일 순간 일반 마커를 숨긴다. 지도 이동으로 다시 정상 표시 범위에 들어오면 칩이 없어지고 마커가 복구된다. 좌표·경로선·선택·묶인 거리 칩의 기능은 유지한다.

## 소유권

- 루트: plan-check.tsx, plan-rows.tsx, parts.tsx, plan-check.module.css, 루트 UI 브라우저 시험·캡처·통합 보고.
- 지도 하위 작업: features/map 디렉터리, map 직접 관련 별도 브라우저 spec. 공통 mock·plan-check 파일은 수정하지 않는다.
- 전체 되돌리기 하위 작업: use-server-review.ts, 새 undo helper·관련 시험. 필요할 경우 별도 백엔드 helper/진입점 수정은 먼저 루트와 조정한다. plan-check.tsx/parts.tsx/CSS는 수정하지 않는다.

## 전체 되돌리기 동작 경계

PlanCheckActions에 undoAll?: () => Promise<void>, canUndoAll?: () => boolean을 추가할 예정이며 루트가 타입과 버튼을 맡는다. 이 접수의 고객 변경을 한 번에 되돌릴 수 있을 때만 노출한다. 최소 현재 화면에서 수행한 장소·시간·추가·삭제·이름 수정의 원래 값을 보존한다. 새 접수로 넘어가면 원판 기록을 섞지 않는다. 되돌리기 실패 또는 판 충돌이면 원판/현재 판을 부분 변경하지 않는다. 잠금/예약 보호와 기존 /edits 검증을 우회하지 않는다. 되돌릴 원값을 확보하지 못한 변경을 성공한 것으로 표시하지 않는다. 저장 전 수정안 미리보기는 저장된 변경과 구별한다.

## 확인

375px와 넓은 화면에서 순서·제목 줄바꿈·아이콘 툴팁·중복 제거·하단 경계·거리칩/마커 단일 표시를 실제 프론트 렌더링으로 확인한다. 기존 수정안 밀기/미리보기와 카드 변경 동작 회귀를 포함한다. 공개 배포는 이번 작업과 별도이며 원본을 백업한다.

## 전체 되돌리기 원자 복원 보완

단순 /edits는 장소 변경을 다시 재배치할 수 있으므로, POST /v1/web/trip-intakes/{id}/restore {revision, restore_revision}로 해당 접수의 과거 완료 판을 새 판으로 복원한다. 본인/tenant/현재판/과거판을 검증하고 잠금·예약 보호, 검사 실패의 트랜잭션 롤백을 유지한다. 복원은 원래 시각을 재배치하지 않는다. 응답은 기존 IntakeView 전체다. 원판은 최초 사용자 수정 직전의 완료 판으로 캡처하며 접수 전환 시 리셋한다. 전체 되돌리기 하위 작업의 소유권에 pipeline.py, entry/trip_api.py, lib/live/intake.ts의 신규 restoreIntake 함수와 직접 시험을 추가한다. 공통 mock 응답은 루트가 맡는다.
