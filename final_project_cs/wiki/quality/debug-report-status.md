# 과거 결함 보고서의 현재 확인 상태

과거 발견·수정 기록은 원문 그대로 보존합니다. 현재 해결 여부를 명확히 읽을 수 없는 보고서는 [현황 주석](debug-report-current-status.json)에 `unverified`로 남깁니다. 이 값은 해결·출시 승인·배포 완료를 뜻하지 않습니다.

## 표시와 확인

| 상태 | 의미 | 필요한 근거 |
|---|---|---|
| `open` | 해결되지 않은 범위를 명시함 | 남은 문제·확인 시각·원문 해시 |
| `resolved` | 명시한 범위를 검증하고 닫음 | 해결 이유·실행 근거·환경·확인 시각 |
| `unverified` | 현재 해결 여부를 다시 확인해야 함 | 미확인 범위·필요한 검증·원문 해시 |

원문에 해결·미해결 제목이 함께 있으면 임의로 첫 번째나 마지막 제목을 현재 상태로 선택하지 않습니다. 제목이 없는 보고서를 본문의 긍정 표현만으로 해결 처리하지도 않습니다. 새 현황 주석으로 판정 범위와 근거를 남기며, 근거가 부족하면 미확인을 유지합니다.

예를 들어 ‘발견 당시 미해결’과 ‘로컬 수정 완료’가 함께 있어도 운영 적용을 확인하지 않았다면 두 기록을 보존하고 환경별 검증을 추가합니다. 문서 상태 표시 검사 통과가 해당 제품 결함의 해결을 증명하지 않습니다.

## 검사 경계

[상태 검사](../../tests/unit/core/test_debug_report_status.py)는 기존에 명확한 상태 제목이 있는 보고서의 표기 검사를 유지합니다. 별도 현황 주석이 있으면 허용 상태·시간대 포함 확인 시각·설명·필요한 검증·원문 텍스트 해시를 검사합니다. 원본 바이트 해시도 확인하며, 원문이 바뀌면 다시 검토해야 합니다. 해결로 표시할 때 검증 근거가 빠지면 실패합니다.

새 보고서의 상태 누락, 주석 없는 상충 표기, 중복·없는 보고서 참조도 통과시키지 않습니다. 이 검사는 기록의 추적 가능성을 검사하며 제품 코드·DB·외부 제공처의 실제 동작을 대신 검사하지 않습니다.

2026-10-12 통합 때 기존 검사 실패 18건은 현재 코드·적용 환경을 다시 검증하지 않은 상태로 주석을 추가했습니다. 기존 보고서 원문을 고치거나 이 18개 결함을 해결로 승격하지 않았습니다. 실행 결과는 [통합 작업 보고서](../../../program/research/baseline_completion_2026-10-12/tasks/integration/report.md)에 추가합니다.
