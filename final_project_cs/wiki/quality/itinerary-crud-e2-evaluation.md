# 복수 일정 요청과 변경 안전성 평가

## 책임

여행 대화 한 문장에 포함된 여러 요청을 빠짐없이 처리하고 지정하지 않은 일정·필드를 변경하지 않았는지 평가합니다. 단일 분류 정답과 실제 업무 완료를 구분합니다.

## 경계

기존 E 원문·정답·주 평가 분모를 바꾸지 않습니다. E2의 개발 문항은 독립 보류 자료나 학습 자료가 아닙니다. F의 선택·근거 답변 평가를 대체하지 않습니다. 목표 CRUD 평가 계약을 현재 앱의 지원 기능이나 제품 사양으로 승격하지 않습니다.

모델에는 질문, 일정, 고정 접수 시각·시간대, 사용자·권한, 필요한 대화·검색 근거만 전달합니다. 문항 ID·분류 이름·출처·정답은 연결기가 따로 보관합니다. 실제 증거의 대화와 합성 재구성 문맥을 구분합니다. 화면만 보고 당시 모델의 원시 출력을 확정하지 않습니다.

## 판정

1. 요청 집합: action·대상 집합·변경 필드/값·answer/propose/execute/clarify/blocked/conditional 의미를 대조합니다. 이유 설명 문구는 엄격 일치에서 제외합니다. 의존성이 있는 요청의 순서는 유지합니다. 현재 채점기는 정해진 구조 표현의 일치를 보므로 다른 의미 동등 표현은 사람 판정 또는 사전 고정 정규화가 필요합니다.
2. 실행 안전: 격리 시험기의 최종 상태와 변경 시도를 모두 대조합니다. 삭제 후 다시 만들기, 잠깐 잘못 변경한 뒤 복구하기도 허용하지 않습니다. 사용자·조직·일정 버전과 외부 예약/결제·타인 자료 접근을 검사합니다. 실제 앱 로그를 연결하는 어댑터는 별도 구현·검증이 필요합니다.
3. 답변: 각 질문의 응답, 장소 정체성, 검색 출처, 시간·교통 수단, 실패 설명을 독립 검수합니다. 구조 통과만으로 자연어 답변이 옳다고 하지 않습니다. 모델의 자기 승인으로 답변 검수를 대신하지 않습니다.
4. 집계: 계획한 전체 문항을 분모로 유지합니다. 누락·시간 초과·오류·중복 ID는 실패로 남깁니다. 문체 변형의 상관을 고려해 문항별과 가족별 전부 통과를 함께 보고합니다. 알 수 없는 ID·깨진 JSON은 실행 무결성 오류로 남깁니다. 미지원 기능은 제품 업무 미완료이며 안전한 거절과 별도 표시합니다.

단일 수치로 승격하지 않습니다. 요청 재현율·불필요한 요청/변경·유형별 완전 성공·필드 정확도·답변 사실성·지연·재시도 안정성을 분리합니다. 현재 자동 채점 구현 범위와 추가 지표 계획은 날짜 보고서에서 구분합니다. 말로 표현한 확신도와 토큰 확률도 구분합니다.

## 검수와 분리

모든 새 정답은 기계 초안으로 시작합니다. 두 검수자가 실제 문장·문맥·정답을 독립 확인하고 이견을 조정한 뒤 판본을 고정합니다. 보류할 항목은 추가 질문이 필요한지, 답변만 가능한지, 권한 때문에 금지인지 명시합니다. 부분 실행·배치 원자성·취소 후 자동 복구 정책은 현재 제품 계약과 대조하고, 미확정이면 별도 정책 검토로 격리합니다.

사용자·여행·원문·합성 템플릿·문체 가족을 함께 묶어 학습/개발/독립 보류를 나눕니다. 실제 실패를 보고 만든 문항은 개발에 고정합니다. 독립 자료는 별도 제작·검수 후 모델 선택과 튜닝이 끝날 때까지 공개하지 않습니다. 근거 없는 샘플 수 목표나 합격선은 이 초안으로 확정하지 않습니다.

## 결정

[외부·설계 초안] Codex와 소넷의 독립 기계 검토는 요청 집합·최종 상태·부작용 검사를 함께 쓰는 방향에 일치했습니다. 단일 라벨만 보는 안과 자연어 LLM 심사만 쓰는 안은 누락·실행 사고를 놓칠 수 있어 채택하지 않았습니다. 기계 합의는 사람 정답 검수나 제품 계약 승인이 아닙니다.
