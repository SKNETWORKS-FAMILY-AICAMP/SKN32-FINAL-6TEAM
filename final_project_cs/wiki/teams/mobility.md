# Mobility 에이전트 팀 안내

**2026-10-12 지하철 웹 골든셋:** 카카오·네이버 5역쌍/6경로를 정답으로 채택했습니다. 요금6/6, 동일 범위 시간±5분5/6이며 교대 환승+8분이 남았습니다. 공항철도 공식 운임 누락을 수정해 별도 공표36쌍·양방향72/72와 관련 시험143/143을 확인했습니다. [대조 그림·실행 근거](../records/reports/2026-10-12_subway_web_golden/REPORT.md).

**2026-10-12 최신 택시 재검증:** 사후 옵션료 없이 공식5상품의 범위를 계산·웹 저장·현재 출발 재확인에 연결했습니다. 제공 서울4건은 현재 정책 재생 예산 충족4/4, 미터오차1천원 이내2/4, 미터 과소추정4/4·MAE1,125원입니다. 따라서 미터 정확도와 실사용 전체 완료는 아직 아닙니다. Python279/279·화면 단위39/39·mock 서버 화면4/4 통과, x600 서버의 cs 프로젝트 서버 응답 확인·배포는 하지 않았습니다. [최신 보고서·그래프·실행 근거](../records/reports/2026-10-12_taxi_pretrip_web/REPORT.md)를 우선 읽습니다. 아래의 기존 실제 옵션료 포함 대조·MAPE6.67%는 당시 조건의 결과이며 사전 예측 성공률로 재사용하지 않습니다.

택시 사전 상품·견적은 저장 계획과 현재 여행 조건이 같은지도 출발 직전에 대조합니다(2026-10-12). 현재 상품·해당 구간 견적·기존 옵션료 방식이 바뀌면 기존 가격으로 안내하지 않고 `needs_replan/taxi_call_pricing_changed`를 반환합니다. 현재 조건과 대조하지 못한 내부 직접 호출은 이 일치 확인을 보장하지 않습니다.

Mobility 에이전트 팀은 여행 구간의 이동 가능 여부와 이동 대안을 판정합니다. 사람 개발 담당과 실행 중인 에이전트 팀을 구분합니다.

### 직접 도보의 근거 없는 대체 계산 금지 (2026-10-12 사용자 지시)

직접 도보 계획·시간대 추정·현재 출발 재검증은 조회 실패를 직선거리×계수로 대신하지 않습니다. 경로 없음은 `no_path`, 자료·연결 장애는 `unavailable`로 구분하며 거리·도착시각을 생성하지 않습니다. 장거리 도로 밖 접근으로 `optimistic`인 응답도 검증된 보행 연결로 취급하지 않습니다. 계획은 해당 도보 후보를 제외하고, 출발 재검증의 소스 장애는 `fatal/walk_source_unavailable`로 반환합니다. 계단 시간은 유효한 보행망 내부 시간으로 유지합니다.

이번 변경 범위는 장소 사이 직접 도보입니다. 역·정류장 접근과 지도 형상 등 별도 계산의 직선 연결까지 제거되었다는 뜻은 아니며 후속 점검이 필요합니다. 웹 표본에 맞춘 거리·요금 보정값과 허용오차 확대는 하지 않습니다.

## 책임과 경계

### 도로명 일치와 실제 경로 영향의 구분 — 2026-10-12

UTIC의 도로명 일치는 사건 후보를 찾은 결과이며 고객 경로의 구간·진행 방향 중첩을 증명하지 않습니다. `read.route_events`의 기존 사건 필드는 유지하고 UTIC 사건에 `route_match.status=unverified`, `basis=road_name_only`를 추가합니다. 이 근거만 있으면 이동 조정은 `unresolved`와 `route_applicability_unverified` 사유를 반환하고 기존 일정을 유지합니다. 부분 차로·종료 시각·다른 도로의 기존 구분은 유지합니다. 사건을 정상·무영향으로 지우거나 정확한 지연시간을 생성하지 않습니다.

감시·Mobility 조정의 공통 판정 함수에 적용하며, 이미 검증한 재생 사건과 지하철 사건의 기존 입력 계약을 바꾸지 않습니다. 도로명을 공급한 호출자가 방향도 확인했다는 뜻은 아닙니다. 향후 방향 검증에는 선택 경로의 순서 있는 방향 링크와 사건 구간의 연결 근거가 필요합니다. 이 보류 장치의 통과를 방향 수용 시험 통과로 표시하지 않습니다. 변경·자체 검토는 통합 작업 담당이 겸하며 독립 검토·운영 반영 완료로 표시하지 않습니다.

이동 시간·환승·막차·경로 사건을 근거로 판정하고 제안을 반환합니다. 일정 쓰기 실행은 공통 실행 계약을 거칩니다. 코드·도구의 허용 범위는 [Team 계약](team-contract/index.md)과 [구조 계약](code-layout.md)을 따릅니다.

### 보정·직접 도보 폴백 제거와 차량 탐색 수정 (2026-10-12)

직접 도보는 조회 실패·미검증 도로 밖 접근을 임의 거리로 대체하지 않도록 바꿨고 최종 도보·추정60/60을 확인했습니다. 차량 A*의 복수 도착 후보 고정12m 가정을 실제 목표 끝점과 잔여비용으로 바꿔 합성 반례14.462→11.593초,관련58/58을 확인했습니다. 실제 도보742.65m 대 카카오672m는 여전히 불일치합니다. 최신OSM 원본은 별도 확보했으며 제품 그래프 적용 완료가 아닙니다. 역·정류장 접근 등 남은 대체 계산과 확장 회귀4건을 숨기지 않았고, 임의 보정·오차 확대·정답JSON 덮어쓰기를 하지 않았습니다. [최종 근거·실패·키 준비 안내·백업](../records/reports/2026-10-12_mobility_no_fallback/REPORT-v2.md).

### 최신 소비자 웹 골든 재생과 제품 개선 (2026-10-12)

카카오·네이버 조회값을 개발 골든셋에 채택한 최신 결과는 [종합 보고서](../records/reports/2026-10-12_mobility_web21_golden/REPORT.md)에 있습니다. 공식 예정 도착초를 연결하고 선택 열차 식별·지도 급행 종류 전달을 고친 뒤, 지하철6경로의 요금·운행종류·같은범위 시간은 각각6/6입니다. 이전 시간5/6 기록은 수정 전 근거로 보존합니다. 초 단위 보조표는 유일하게 맞는 기존 승차편만 보강하며 실시간 관측에 정적 시각을 덧씌우지 않습니다.

같은 요청 좌표의 혼합 운임3/3·빠른 환승칸/출구 내부 계산2/2, 공표 평균혼잡8208/8208·TOPIS 사건분류42/42·관측 재고3/3을 확인했습니다. 혼합 후보는 빠른 유료선만 남기던 누락을 수정하고 최종 제공 범위와 계약상 더 이른 출발 제외를 구분합니다. 혼합 옵션의 칸/출구 고객 표시, 도보 거리와 택시 점추정의 웹 불일치, 실제 cs 프로젝트 서버 HTTP/DB·휴대폰 지도 확인은 남아 있습니다. 21개 전체의 운영 완료100%를 뜻하지 않으며 [21개 기능별 근거표](../records/reports/2026-10-12_mobility_web21_golden/feature-status-v3.md)에서 분모·허용오차·대체 소스를 확인합니다.
