# Team 인스턴스의 실행·대기·재개

담당 Team이 꺼져 있거나 설치되지 않았으면 해당 업무를 실행하지 않습니다. 저장된 계획서 조회처럼 그 Team 계산이 필요 없는 기능은 계속 동작합니다. 구현 검증과 공개 배포 결과는 [2026-10-12 복구 보고서](../records/reports/2026-10-12_manager_recovery_release.md)에서 구분합니다.

## 요청 처리

고객 채팅의 업무 변경·업무 되묻기는 `trip_messages` → `case_dispatch` → `Controller` → `Team.execute`로 연결됩니다. 순수 사실·일정 조회는 읽기 처리기를 사용합니다. 공유 계산 함수는 팀 소유 hook으로 호출하며, 담당이 없을 때 업무를 대신 처리하는 우회 경로가 아닙니다.

Registry·Executor·계산 연결·Controller는 같은 조립 판을 사용합니다. 시작한 요청은 기존 판으로 끝나고 새 요청부터 새 판을 사용합니다. 새 판 준비가 실패하면 이전 판을 보존합니다. 비활성 구현을 import하지 않으며 선택 구현의 적재 실패 이유를 등록합니다.

## 대기와 재개

추가 답변이 필요한 업무는 `waiting_input`으로 질문·입력 형식·토큰을 저장합니다. 업무 완료로 처리하지 않습니다. 답변 본문은 같은 Case의 `Controller.resume`에 전달합니다. 담당 불가를 입력 반영 전에 발견하면 답변·토큰을 소비하지 않고 HTTP 503으로 거절합니다. 실행 중 발생한 필수 계산 실패는 실패 기록을 남기므로 사전 거절과 구분합니다.

명시한 Case와 재전송 식별자는 해당 업무로 연결합니다. 업무를 지정하지 않은 답변은 최근 질문의 형식에 명확히 맞을 때만 대기에 연결합니다. 새 사실 문의·새 업무 요청을 이전 대기 답변으로 삼키지 않습니다. 동시 재전송은 실행을 중복 적용하지 않습니다.

## 읽기 중단 복구

첫 해석의 복수 질문·대상·범위와 일정판을 저장해 재전송에 사용합니다. 대상 교정 후 `ROUTED.state_patch`에 교정된 decision과 읽기 스냅샷을 함께 저장합니다. SHA256은 저장 내용의 일치 검사이며 비밀키로 서명한 인증 수단이 아닙니다. 일정판 변경·다른 원문·해석 불일치는 409로 거절합니다. 위치 의존 조회는 이 자동 복구 범위에 포함하지 않습니다.

## 검증 경계

합성 DB의 상태 전이·재시도·경합 검증, mock 서버의 화면 반응, 공개 서비스 읽기 확인을 구분합니다. 재생 경로 표본은 경로 알고리즘의 실측 정확도나 독립 검증이 아닙니다. 실제 고객 일정 변경·외부 알림 발송 시험과 LLM 추천 정확도를 이번 회귀 통과로 대체하지 않습니다.
