# LangGraph 를 쓸까 — 재 보고 정한다

`[실측 2026-10-03]` 흐름 제어를 LangGraph 로 바꾸면 나아지는지 **실제로 만들어
재 봤다.** 결론부터: **지금 방식이 더 빠르고 덜 쓴다. 바꿀 이유가 안 나왔다.**

★다만 이 차이는 **고객이 느끼는 응답 시간에서는 거의 안 보인다.** 아래 「과장하지
  않기」를 먼저 읽는다.

## 왜 쟀나

`requirements.txt` 에 `langgraph==1.2.8` 이 있는데 코드에서 한 번도 부르지 않는다.
설계 문서에는 「Top-Level LangGraph 가 흐름을 정한다」고 적혀 있었고, 2026-09-10 에
그 문장을 다섯 군데에서 고쳤다. **안 쓰기로 한 결정 문서는 끝내 없었다** — 쓰기로
한 적만 있고 안 쓴 채로 굳은 것이다.

그래서 「느낌」이 아니라 **숫자로** 정하기로 했다.

## 결과

문의 한 건을 접수부터 종결까지 보내는 데 걸린 시간. **40번씩 번갈아** 쟀다.

### 직선 경로 — 접수 → 분류 → 담당 → 처리 → 종결 (전이 4회)

| | 지금 방식 | LangGraph |
|---|---|---|
| 가운뎃값 | **4.99 ms** | 18.80 ms |
| 평균 | 5.27 ms | 25.61 ms |
| 편차 | ±1.77 | ±28.73 |
| 가장 느릴 때 | 10.85 ms | 191.95 ms |

### 대기·재개가 든 경로 — 위에 「대기 → 재개」 한 번 (전이 6회)

★**LangGraph 가 자기 강점을 쓰는 자리다.** `interrupt` 로 멈추고 `Command` 로
  이어간다. 직선 경로만 재면 그쪽이 불리한 조건에서만 잰 셈이 된다.

| | 지금 방식 | LangGraph |
|---|---|---|
| 가운뎃값 | **8.23 ms** | 26.33 ms |
| 평균 | 8.13 ms | 31.47 ms |
| 편차 | ±2.05 | ±13.87 |

**강점 자리에서도 3.2배 느렸다.**

### 디스크에 쓴 양 (같은 횟수 기준)

| 지금 방식 | LangGraph |
|---|---|
| **180 KB** | 2,023 KB |

11배 차이다. 설계가 달라서 그렇다 — LangGraph 는 칸을 지날 때마다 **상태 전체**를
저장하고, 우리는 **무슨 일이 있었나**만 한 줄씩 쌓는다.

### 코드 분량 (같은 흐름을 짜는 데 든 줄 수)

| | 지금 방식 | LangGraph |
|---|---|---|
| 직선 경로 | **19줄** | 24줄 |
| 대기·재개 | **23줄** | 32줄 |

## 과장하지 않기

★**고객 응답 시간에서 이 차이는 거의 안 보인다.** 한 건에서 오래 걸리는 것은
  모델 호출과 바깥 조회이고 **초 단위**다. 여기서 아낀 18밀리초는 그 옆에서 거의
  0이다. 이 측정이 말하는 것은 「흐름 제어가 병목이 아니다」이지 「우리가 훨씬
  빠른 시스템이다」가 아니다.

★**조건이 우리에게 불리했는데도 빨랐다.** 우리 쪽은 전이마다 ①이 이동이 허용되나
  ②payload 필수 키가 다 왔나 를 검사한다. LangGraph 쪽에는 그 검사가 없다.
  일을 더 하고도 빨랐다는 뜻이다.

★**편차가 큰 쪽이 LangGraph 다.** 직선 경로에서 한 번 191ms 까지 튀었다(편차
  ±28.7). 원인은 안 봤다 — checkpoint 쓰기가 몰린 것으로 **추정**한다.

## 공정하게 하려고 한 것

| 한 것 | 왜 |
|---|---|
| 바깥 호출을 **양쪽 다 없앴다** | 모델·공공 API 가 섞이면 그날 서버가 느린지에 따라 결과가 뒤집힌다 |
| **번갈아** 쟀다(A·B·A·B), 회차마다 순서를 뒤집었다 | 한쪽을 다 재고 다른 쪽을 재면 나중 쪽이 캐시·커넥션 데움에서 손해를 본다 |
| 첫 호출은 버렸다 | 연결 열기·그래프 컴파일 비용이 섞인다 |
| **같은 PostgreSQL** 에 썼다 | 저장소가 다르면 비교가 안 된다 |
| 전용 DB(`acop_bench`)를 새로 만들었다 | 실험이 개발 데이터를 더럽히면 안 된다 |
| LangGraph 강점 경로를 **일부러 넣었다** | 직선만 재면 그쪽이 불리한 자리에서만 잰 것이 된다 |

## 동작 비교 — 속도보다 이쪽이 중요하다

`[실측 2026-10-03]` 실제로 그 상황을 만들어 봤다. 문서를 읽고 적은 것이 아니다.

### 틀린 이동을 막아 주나

갓 접수된 건에 바로 「끝났다」를 넣어 봤다. 일어날 수 없는 이동이다.

| | 결과 |
|---|---|
| 지금 방식 | **`InvalidTransition` 으로 막혔다** — (상태, 이벤트) 25개 조합만 허용한다 |
| LangGraph | **안 막는다**(실측). 상태 칸에 `"이건_존재하지_않는_상태"` 를 넣어도 받고, `update_state()` 로 바깥에서 `"resolved_인데_거친적없음"` 으로 덮어써도 그대로 들어간다 |

★그래프의 **간선**은 고정이라 노드 순서는 못 건너뛴다. 하지만 **상태 값 자체**에는
  검사가 없다. 우리 쪽은 둘 다 막는다.

### 필요한 값이 빠졌을 때

접수 이벤트에서 필수 항목(`message`) 하나를 뺐다.

| | 결과 |
|---|---|
| 지금 방식 | **`InvalidTransition` 으로 막혔다** — 이벤트마다 필수 키 목록이 있다(`REQUIRED_PAYLOAD_KEYS`) |
| LangGraph | 검사 없음 — 상태에 아무 dict 나 들어간다 |

★같은 예외 이름이지만 **다른 검사**다. 하나는 전이표(`next_status`), 하나는
  필수 키(`validate_payload`). 둘 다 `transition_case()` 안에서 돈다.

### 중간에 죽으면 어디까지 갔는지 아나

두 단계만 가고 멈춘 뒤 무엇이 남는지 봤다. **양쪽 다 남는다.**

| | 결과 |
|---|---|
| 지금 방식 | 상태 `routing` · 판 2 · 지나온 사건 `['created', 'classified']` |
| LangGraph | 일부러 터뜨렸더니 마지막 상태 `'routing'` · checkpoint 4개 남음 |

★**여기서는 LangGraph 도 제 몫을 했다.** 차이는 남는 **모양**이다 — 우리는
  「무슨 일이 있었나」가 순서대로 남고, LangGraph 는 「그때 상태가 어땠나」가
  스냅숏으로 남는다.

### 되감을 수 있나

| | 결과 |
|---|---|
| 지금 방식 | **된다.** 사건 기록만으로 다시 만든 결과가 저장된 것과 일치(`replay_case()`, 실측 `True`) |
| LangGraph | `get_state_history()` 로 과거 스냅숏을 꺼낼 수 있다. 다만 「다시 계산해서 맞는지」가 아니라 「그때 찍어 둔 것을 꺼내는 것」이다 |

### 둘이 동시에 같은 건을 고치면

낡은 판 번호를 들고 두 번째 수정이 들어오게 했다.

| | 결과 |
|---|---|
| 지금 방식 | **`StateConflict` 로 거부됐다** |
| LangGraph | 판 번호 검사가 없다 — 나중 쓰기가 이긴다 |

### 새 상태를 하나 더하려면

| | 고쳐야 할 파일 |
|---|---|
| 지금 방식 | 1개 — 상태 목록과 이동표가 같은 곳에 있다 |
| LangGraph | 1개 — 노드와 간선을 그래프 정의에 더한다 |

둘 다 한 파일이다. 다만 우리 쪽은 **전이도가 자동으로 다시 그려지고 어긋나면
시험이 막는다**(2026-10-03 추가).

### 많이 들어오면 — 처리량

`[실측 2026-10-04 · 다시 쟀다]` 처음 측정(10-03)은 **우리만 묶어 커밋**해서
기울어 있었다. 코덱스가 짚었고, **양쪽 다 건마다 저장**하도록 고쳐 다시 쟀다.

100건씩 **5쌍**, 쌍마다 순서를 뒤집었다. 평균이 아니라 **중앙값과 사분위 범위**다 —
평균 하나로 뭉치면 한 번 튄 값이 결론을 흔든다.

| | 중앙값 | 사분위 범위 |
|---|---|---|
| 지금 방식 (건마다 커밋) | **125.9건/초** | 98.5 ~ 167.2 |
| LangGraph | 34.5건/초 | 25.9 ~ 53.9 |
| 쌍별 배수의 중앙값 | **3.21배** | |

★**범위가 안 겹친다.** 우리 쪽 아래끝(98.5)이 저쪽 위끝(53.9)보다 높다.

참고로 묶어 커밋했을 때는 133.2건/초다 — 건마다 커밋(125.9)과 **크게 다르지 않다.**
즉 처음 측정이 기울긴 했어도 그것 때문에 결론이 뒤집히지는 않았다.

| 처음(10-03, 기운 조건) | 다시(10-04, 공정) |
|---|---|
| 189.4 대 57.7 = 3.28배 | 125.9 대 34.5 = **3.21배** |

★절대값이 둘 다 내려간 것은 이번에 건수를 200에서 100으로 줄이고 DB 를 비운 뒤
  쟀기 때문이다. **배수는 거의 같다.**

### 새 흐름을 하나 더하면 — 안 고친 자리를 누가 잡나

고쳐야 할 파일 수는 양쪽 다 1개다. 진짜 비용은 **빠뜨렸을 때 누가 알려 주나**다.
그래서 실제로 전이를 하나 몰래 더해 보고 무엇이 우는지 봤다.

```
전이 하나 추가 → 아키텍처 시험 162건 중 1건 실패 (13.5초)
  FAILED tests/architecture/test_state_diagram_matches_code.py
```

**전이도 관문이 잡았다.** 코드만 고치고 그림을 안 고치면 바로 막힌다. 그래서
그림이 코드보다 뒤처질 수 없다. LangGraph 쪽에는 이에 해당하는 장치가 없다 —
그래프 정의 자체가 그림이라 애초에 어긋날 일이 없는 대신, 그 그림을 사람이 볼
문서로 내보내는 일은 따로 해야 한다.

### 한 번 191ms 까지 튀던 것

`[실측 2026-10-03]` 60회로 다시 재니 **최대 55.85ms** 로 안 튀었다. 처음 40회에서
한 번 나온 191ms 는 **재현되지 않았다.** 원인은 여전히 모른다 — checkpoint 쓰기가
몰린 것으로 **추정**만 한다. 다만 LangGraph 쪽 편차가 우리보다 크다는 방향은
두 번 다 같았다(±5.92 대 ±1.26).

## ★코덱스 반박 — 내 비교가 어디서 기울었나

`[2026-10-04]` 이 비교를 **내가 혼자 설계했다.** 그래서 코덱스에 「공격해 달라」고
맡겼고, 아래는 받아들인 지적이다. 유리한 쪽만 남기지 않으려고 그대로 적는다.

### 구조적으로 기운 항목 — 여섯

| 항목 | 왜 기울었나 |
|---|---|
| 처리량 | 우리만 묶어 커밋하고 저쪽은 건마다 썼다 → **다시 쟀다**(아래) |
| 코드 줄 수 | 우리 쪽의 기존 검증·이벤트 저장·되감기 코드를 분모에서 뺐다. 같은 요구를 만족시키는 **전체 추가 코드**를 세야 공정하다 |
| 틀린 이동 거부 | **우리가 만든 검사층**을, 검사를 넣지 않은 저쪽 구현과 비교했다 |
| 빠진 필수값 거부 | 위와 같다 |
| 동시 쓰기 거부 | 우리 애플리케이션의 동시성 제어와 저쪽 **기본 동작**을 비교했다 |
| 전이도 관문 | 우리가 만든 개발 도구다. 저쪽에 같은 검사를 안 만들어 놓고 `해당 없음` 으로 뒀다 |

★**「틀린 이동을 막는다」의 정직한 표현**은 이것이다.

> 우리 구현은 도메인 전이와 payload 를 검증한다. 이번 LangGraph 구현에는 **같은
> 검증을 넣지 않았다.** 그래서 검증 없는 상태 변경을 허용했다. 이것은 LangGraph
> 에서 검증을 **구현할 수 없다**는 뜻이 아니다.

### 조건이 같아야 비교되는 항목

지연 시간과 디스크 쓰기량은 **영속화 경계와 복구 보장**이 같을 때만 비교된다.
우리가 중간 작업을 안 남기고 저쪽은 남겼다면 서로 **다른 서비스**를 잰 것이다.
같은 보장에서도 남는 차이는 실제 비용이 맞다.

### ★가장 강한 반론 — 결론 범위가 넓었다

> 이 비교가 검증한 것은 **「이미 완성된 작은 상태 기계를 LangGraph 로 갈아 끼울
> 가치」**다. 복잡한 실행 흐름의 개발·복구·운영 비용은 검증하지 않았다. 그 비용이
> 앞으로 커진다면 수십 밀리초의 저장 비용보다 틀의 가치가 클 수 있다.

**받아들인다.** 아래 결론을 그 범위로 좁혔다.

## 아직 안 잰 것

- ★**중간에 죽은 실행을 이어 가기** — 지금은 「마지막 상태가 남는다」만 봤다.
  프로세스를 **강제로 죽이고 다시 띄워** 완료까지 걸린 시간 · 다시 돈 노드 수 ·
  바깥 부작용이 두 번 일어났는지를 재야 한다. 이것이 복구 검증이다
- ★**복잡한 흐름의 구현 비용** — 병렬 분기·합류, 여러 번의 대기·재개, 실패한
  노드 재시도를 넣고 같은 인수 시험을 통과할 때까지의 작업 시간과 코드량.
  **LangGraph 가 유리할 가능성이 있는 영역**이다
- **사람이 새 흐름을 쓰는 데 실제로 걸리는 시간** — 기계가 잡아 주는지는 쟀지만
  사람 손이 얼마나 가는지는 못 쟀다. 한 사람이 양쪽을 다 쓰면 익숙함 편향도 남는다
- **건마다 커밋했을 때의 처리량** — 위 200건은 우리 쪽을 한 트랜잭션으로 묶어
  유리하게 잡혔다. 같은 조건으로 다시 재야 한다
- **191ms 가 왜 났는지** — 재현이 안 돼서 원인을 못 봤다

★이 목록은 **내가 혼자 추렸다.** 코덱스가 사용 한도에 걸려(2026-10-04 정오 해제)
  교차 검토를 못 받았다. 내가 짠 항목이 내 가설에 유리할 수 있다 — 코덱스가
  돌아오면 **항목부터 반박**시킨다.

## 그래서 어떻게 하나

1. ★**지금의 Case 상태 기계는 LangGraph 로 갈아 끼우지 않는다.** 재 본 항목에서
   더 나을 것이 없었고, 갈아 끼우는 값이 안 나온다.
   ★**「이 프로젝트에서 LangGraph 를 안 쓴다」는 뜻이 아니다.** 그것은 이 측정이
   받쳐 주는 범위를 넘는다(위 「가장 강한 반론」). 병렬 분기·합류나 여러 번의
   대기·재개가 필요한 **새 흐름**이 생기면 그때 다시 잰다.
2. **`requirements.txt` 의 `langgraph`·`langchain-core` 줄을 지운다.** 안 쓰는
   이름이 목록에 있으면 설치가 느려지고, 보는 사람이 「쓴다」로 읽는다.
   ★아직 안 지웠다 — 사용자 확인 대기.
3. **개념은 이미 들어와 있다.** LangGraph 의 열 가지 중 아홉이 우리 코드에 있다.
   아래 표 참고. 발표에서는 「라이브러리를 썼다」가 아니라 **「같은 문제를 이렇게
   풀었고 그 덕에 되감기와 동시성까지 얻었다」**로 쓰는 편이 설명할 것이 많다.

| LangGraph 의 개념 | 우리 쪽 |
|---|---|
| 상태를 칸으로 | `CaseStatus` 12개 |
| 간선(어디서 어디로) | `TRANSITIONS` 25개. 표에 없으면 거부 |
| 조건 분기 | 두 축 라우팅(객체 종류 + 요청 종류) |
| 중간 저장 | `case_events` 추가만. **되감아 복원까지 된다** |
| 멈췄다 이어가기 | `resume_token` 24시간·1회용 |
| 사람 승인 대기 | `waiting_approval` + 제안 재검증 |
| 상태 합치기 | `state_json` 병합(덮어쓰기 아님) |
| 되감기 | `replay_case()` |
| 진행 실시간 전달 | SSE (2026-10-02) |
| 하위 그래프 | 모양이 다름 — 레지스트리에 등록한 모듈 |

**우리에게만 있는 것**: 판 번호로 동시 쓰기 거부, payload 스키마 검증,
허용되지 않은 전이 거부.

**LangGraph 에만 있던 것**: 흐름을 선언으로 두고 그림으로 뽑기.
→ **2026-10-03 에 우리 쪽에도 붙였다.** `scripts/make_state_diagram.py` 가
`TRANSITIONS` 에서 그림을 뽑고, 어긋나면 시험이 막는다
([case-state-machine.generated.md](case-state-machine.generated.md)).

## 다시 재는 법

실험 사본은 `_experiments/langgraph_compare/` 에 있다. **git 에 없다** —
릴리스 대상과 섞이면 안 되기 때문이다. 사본이 사라졌으면 다시 만든다.

```
# 사본 만들기 (추적 파일만, 실제 키는 안 옮긴다)
git ls-files -z -- app config scripts tests pytest.ini requirements.txt \
  | while IFS= read -r -d '' f; do mkdir -p "$DST/$(dirname "$f")"; cp "$f" "$DST/$f"; done

# 전용 DB + 마이그레이션 + 가짜 .env (ACOP_DATABASE_URL 만 진짜)
python -m app.infrastructure.db.migrate

# 재기
python bench.py --rounds 40
```

★`.env` 는 **가짜 값**으로 만든다. 이 비교는 바깥 호출을 안 하므로 실제 키가
  필요 없다. 실제 키를 사본에 넣지 않는다.
