# 실제 여행 진행 — 2026-10-18 사용자 승인 범위

고객의 실제 도착·완료 보고는 계획 조회와 구분합니다. 해석기는 `arrive_item`, `complete_item`, `advance_trip`, `finish_day`를 반환하고 기존 채팅 변경 창구와 일정 버전 저장소를 통해 반영합니다. 기존 변경 요청도 호환됩니다. 담당·검토: 이번 변경 담당 Codex가 자체 검토하며 독립 검토 완료로 표시하지 않습니다.

- `advance_trip`: 대상 방문 종료를 요청 접수 시각으로 기록하고 다음 방문으로 지금 출발하도록 이동·시각을 재검증합니다. `arrive_item`은 도착한 대상의 실제 시작을 기록하며 다시 이동시키지 않습니다.
- `complete_item`: 실제 종료를 기록합니다. `finish_day`는 그날 현재 방문을 완료하고 미실행 항목을 건너뛰되 다른 날과 업체 거래는 보존합니다.
- `detail.execution`은 상태(`arrived`, `completed`, `skipped`)와 확인된 실제 시각·근거(`customer_report`)를 담습니다. 원래 계획은 이전 버전에 보존합니다. 같은 요청 재전송은 버전을 중복 생성하지 않습니다.
- `지금`은 같은 요청의 접수 시각을 쓰며 5분 단위 올림을 적용하지 않습니다. 완료와 다음 시작, 장소 교체와 시간 조정은 함께 검증한 한 변경으로 저장합니다.
- 명시적인 날짜 이동은 제품의 여행 일수 한도 안에서 기간 확장을 허용합니다. 고정·업체 예약은 이동하지 않으며 실행 실패는 부분 적용하지 않습니다.
- 지정 목적지는 지역·상호·업종 조건을 유지합니다. 식별 실패 시 요청 장소를 미확정 선택지로 보존하고 무관한 대안으로 요청을 대체하지 않습니다. 좌표와 영업 사실은 지어내지 않습니다.
- 장소 존재, 주간 영업시간, 임시휴무 관측, 주변 위험 조회는 독립 상태입니다. 임시휴무 관측 부재를 휴업이나 전체 일정 오류로 올리지 않습니다. 필수 자료 조회 실패는 해당 의존 판정에 남기고 완료·도착 사실 처리는 계속합니다.
- 장소를 삭제하면 연결 이동을 제거·재생성합니다. 장소 변경 후 출발 재검증 자료를 갱신하며 이전 장소의 자료를 새 장소에 사용하지 않습니다.
- 완료·건너뛴 항목은 감시·출발 안내 대상에서 제외합니다. 발송 시점에도 현재 버전과 진행 상태를 확인합니다.

구현·시험·운영 반영 상태는 날짜별 작업 기록으로 별도 확인합니다.

## 초기 일정의 마감과 기본 체류

고객이 마감 시각을 명시하면 직접 지정한 시각·체류·예약·고정은 유지한다. 시스템이 채운 체류와 시작 시각만 최소 체류 범위 안에서 줄여 마감 안에 배치한다. 불가능하면 구체적인 충돌을 남긴다. 귀가 목적지와 이동 시간이 없으면 방문 마감 준수를 귀가 도착 보장으로 표현하지 않는다.

## 즉시 출발 계산 단계

공통 이동 계산기는 선택 인자 `stage`를 받으며 기본 계획 계산은 기존 planning을 유지한다. 고객의 즉시 다음 이동과 출발 문맥 복구는 pre_departure를 사용한다. 각 단계의 여유는 이동 팀의 기존 가드레일에서 읽는다. 예상 도착과 여유를 포함한 다음 방문 시작은 구분한다.

## 직접 고른 장소의 재사용 범위

장소 이름을 다시 찾을 때 공용 장소와 현재 여행에 직접 고른 장소를 함께 읽는다. 수정 접수의 여행 번호는 고객 소유를 확인한 접수에서 얻는다. 다른 여행 전용 장소는 같은 고객의 여행이어도 포함하지 않는다. 공급자 조회 실패가 이미 저장한 이름·좌표를 없애지 않는다.

하루 종료와 함께 마지막 실제 방문을 보고하면 그 방문까지 완료로 기록한다. 계획 시각이 미래였다는 이유로 실제 방문을 건너뜀으로 기록하지 않는다. 실제 시작 시각을 알 수 없는 경우 그 사실도 남기며 체류 길이를 지어내지 않는다.

알림 발송 직전에는 해당 안내가 참조한 항목의 존재·진행 상태·시각을 대조한다. 무관한 다른 일정 변경으로 여행 버전만 올라간 경우 유효한 출발 안내를 버리지 않는다.

실제 도착 보고로 진행 중인 일반 방문이 있고 바로 다음 방문을 지금으로 옮겨 진행하라고 하면, 현재 방문을 지금 마치고 다음 방문으로 출발하는 한 동작으로 처리한다. 다음 방문의 예약·고정은 이 변환에서 제외한다. 단순 시각 수정과 실제 완료 시각의 충돌은 보존한다.

현재 이동·누락 알림 문의의 해석이 잡담·대상 미정으로 떨어져도, 질문임이 명확하고 그날 현재 또는 바로 다음 방문이 유일하면 그 방문의 저장 경로를 읽어 안내한다. 실제 위치·배달 성공을 추정하지 않으며 이 복구는 일정을 수정하지 않는다.

직전에 바꾼 방문을 고객이 바꾸기 전 제목·시각으로 다시 지칭하면 변경 이력으로 현재 항목에 연결한다. 옛 UI 문구만으로 다른 방문을 고르지 않는다.

지역 기준이 있는 검색은 전역 이름 결과와 주변 결과를 함께 검토한 뒤 하나를 선택한다. 전역에서 접두어가 맞는 가게 하나를 찾았다는 이유로 주변 검색을 생략하지 않는다. 다른 상호의 실제 도착을 식별할 때는 사용 가능한 현재 위치, 마지막으로 보고된 방문, 직전 방문 순으로 기준을 잡고 아직 가지 않은 대체 식당을 현재 위치로 간주하지 않는다.
