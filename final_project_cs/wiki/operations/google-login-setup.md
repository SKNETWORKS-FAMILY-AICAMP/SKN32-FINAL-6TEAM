# 구글 로그인 켜기 — 따라 하기

**한 줄 요약:** 구글 사이트에서 「로그인용 열쇠」 한 벌(ID와 비밀번호 같은 값)을 만들고, 그 값을 우리 설정 파일에 두 줄 넣으면 웹의 「Google로 로그인」 단추가 켜집니다.
서버 코드는 이미 있습니다([REST 명세 「소셜 로그인」](../external/rest-endpoints.md)). 이 값이 없으면 단추가 안 나오고 웹은 「설정된 로그인 방법이 없어요」라고만 말합니다.

## 먼저 답부터

| 궁금한 것 | 답 |
|---|---|
| 돈이 드나요? | **무료입니다.** 구글 로그인 자체에는 사용료가 없고 결제 카드도 필요 없습니다. 우리는 구글의 다른 서비스(메일 · 지도 등)를 부르지 않고, 이름이나 이메일도 안 받고 「이 사람의 고유 번호」만 받습니다 |
| 몇 개 만드나요? | **하나만** 만듭니다. 그 하나에 우리 주소를 **둘**(내 PC용 · 공개 서버용) 적어 둡니다 |
| 누가 하나요? | 구글 계정이 있는 사람이면 누구나(팀 공용 구글 계정을 권합니다) |
| 얼마나 걸리나요? | 10~15분 |

## 알아 둘 말 세 가지

- **클라이언트**: 구글에게 「우리 서비스가 구글 로그인 단추를 써도 된다」고 등록하는 것입니다. 등록하면 두 값이 나옵니다 — **클라이언트 ID**(긴 글자, 공개돼도 됨)와 **클라이언트 보안 비밀**(비밀번호처럼 숨겨야 함).
- **리디렉션 주소**: 사용자가 구글에서 로그인을 끝내면 구글이 그 사람을 **되돌려 보내는 우리 서버 주소**입니다. 구글은 미리 등록한 주소로만 돌려보내고, 한 글자라도 다르면 막습니다. 그래서 **우리 서버가 쓰는 주소와 글자 그대로 같아야** 합니다.
- **왜 주소가 둘인가**: 같은 열쇠를 내 PC(개발)에서도, 공개 서버에서도 쓰기 때문입니다. 서버가 두 곳이면 돌아올 주소도 두 개입니다. 열쇠 하나에 주소를 여러 개 적을 수 있어서 열쇠를 두 번 만들 필요가 없습니다.

```
웹에서 「Google로 로그인」 누름
  → 구글 로그인 화면 (사용자가 계정 고름)
  → 구글이 사용자를 「리디렉션 주소」로 돌려보냄   ← 이 주소를 구글에 미리 등록해 둔다
  → 우리 서버가 확인하고 웹 화면으로 돌려보냄 → 로그인 끝
```

## 구글에 적을 주소 두 개

주소는 모두 끝이 `/v1/web/auth/google/callback` 입니다.

| 용도 | 구글에 적을 주소 | 앞부분은 어디서 오나 |
|---|---|---|
| 내 PC | `http://127.0.0.1:8042/v1/web/auth/google/callback` | 내 PC 설정의 `ACOP_PUBLIC_BASE_URL` 기본값(`http://127.0.0.1:8042`)과 같습니다 |
| 공개 서버 | `https://<공개 서버 주소>/v1/web/auth/google/callback` | 브라우저로 우리 서비스를 열 때 **주소창에 보이는 주소**(`https://` 로 시작, 끝에 `/` 없이). 서버 설정의 `ACOP_PUBLIC_BASE_URL` 도 이 값입니다 |

## 순서

| 순서 | 구글 화면에서 할 일 | 끝나면 이렇게 보입니다 |
|---|---|---|
| 1 | 브라우저에서 `console.cloud.google.com` 을 열고 구글에 로그인합니다 | 「Google Cloud」 콘솔이 열립니다 |
| 2 | 맨 위 프로젝트 선택 상자 → **새 프로젝트** → 이름 `tripilot` → **만들기** | 맨 위에 프로젝트 이름 `tripilot` 이 보입니다. (결제 정보를 넣으라는 화면이 나오면 멈추고 알려 주세요 — 필요 없는 단계입니다) |
| 3 | 왼쪽 메뉴 **API 및 서비스 → OAuth 동의 화면**(새 화면에서는 **Google Auth Platform**)에서 **시작하기** → 앱 이름 `triPilot`, 사용자 지원 이메일은 본인 것 선택 → 대상은 **외부** → 연락처 이메일 입력 → 동의하고 **만들기** | 동의 화면 설정이 끝났다는 화면이 나옵니다. 화면 이름이 조금 달라도 이 순서입니다 |
| 4 | **사용자 인증 정보**(새 화면에서는 **클라이언트**) → **+ 사용자 인증 정보 만들기** → **OAuth 클라이언트 ID** | 만들기 양식이 열립니다 |
| 5 | 애플리케이션 유형 **웹 애플리케이션**, 이름 `tripilot-web`. 「이 클라이언트는 AI 에이전트가 쓰나요」 같은 물음(문구는 구글 화면 기준)이 나오면 **체크하지 않습니다 / 아니요** — 우리 서버가 사람 로그인에만 쓰고, AI 가 구글 계정으로 무언가를 하지 않습니다 | |
| 6 | **승인된 JavaScript 원본**은 **건드리지 않고 비워 둡니다**(우리는 서버가 처리합니다). **승인된 리디렉션 URI** 는 아래 「입력칸 모양」대로 **입력칸 하나에 주소 하나씩** 붙여넣습니다 → **만들기** | 팝업에 **클라이언트 ID** 와 **클라이언트 보안 비밀**이 나옵니다 |
| 7 | 두 값을 복사해 둡니다. **채팅 · 문서 · 커밋에는 붙이지 않습니다** | |
| 8 | 앱 상태가 **테스트**면 등록한 계정만 로그인할 수 있습니다. **대상**(Audience) 화면 → **테스트 사용자 → + 추가** 에 로그인해 볼 구글 계정(본인 · 팀원, 최대 100명)을 넣습니다 | 목록에 계정이 보입니다 |

**입력칸 모양(순서 6)** — 「승인된 리디렉션 URI」 제목 아래에 **+ URI 추가** 단추가 있고, 누를 때마다 빈 입력칸이 하나씩 생깁니다. **칸 하나에 주소 하나**를 복사해 붙여넣습니다(앞뒤 공백 · 끝의 `/` 없이).

```
승인된 리디렉션 URI
  URI 1  [ http://127.0.0.1:8042/v1/web/auth/google/callback          ]   ← 내 PC용 (이 줄 그대로)
  URI 2  [ https://<공개 서버 주소>/v1/web/auth/google/callback        ]   ← 공개 서버용 (<…> 자리에 주소창의 주소)
  [ + URI 추가 ]
```

누구나 쓰게 하려면 **앱 게시**를 누릅니다. 우리는 로그인용 기본 범위(`openid`)만 써서 보통 구글 심사가 필요 없고, 구글이 브랜드 확인을 요구하면 2~3일 걸릴 수 있습니다(역시 무료입니다).

## 값을 설정 파일에 넣기 (두 곳, 각각 두 줄)

두 곳 모두 아래 두 줄입니다(`<…>` 자리에 7번에서 복사한 값을 붙입니다).

```
ACOP_GOOGLE_CLIENT_ID=<클라이언트 ID>
ACOP_GOOGLE_CLIENT_SECRET=<클라이언트 보안 비밀>
```

| 어디 | 파일 | 그 다음 |
|---|---|---|
| 내 PC | 저장소의 `.env` (없으면 `.env.example` 을 복사해 만듭니다) | 서버를 껐다 켭니다 |
| 공개 서버 | 서버의 환경 파일(공개 서버 폴더의 `.env`) | 서버 컨테이너를 다시 시작합니다 — 어렵다면 값만 알려 주세요, 개발 세션이 넣어 드립니다(비밀 값은 화면에 찍지 않고 파일로만 옮깁니다) |

공개 서버 환경 파일 생성기(`deploy/make_server_env.py`)는 이 PC 의 `.env.apikeys` 값을 서버로 옮기지만 **구글 값은 일부러 옮기지 않습니다.** 실수로 개발용 값이 서버에 가지 않게 하려는 장치라서, 서버에는 위 두 줄을 직접 넣어야 합니다.

## 켜졌는지 확인

1. 주소창에 `<서버 주소>/v1/web/auth/providers` 를 열면 `{"providers":[{"id":"google"}]}` 가 보입니다(켜지기 전에는 `{"providers":[]}`).
2. 웹의 마이페이지 → 「소셜 계정」 → **Google 연결** → 구글 화면에서 계정을 고르면 웹으로 돌아와 「연결됐어요」가 보입니다.
3. 다른 브라우저(로그인 안 한 상태)에서 **Google로 로그인** → 같은 계정이 붙은 여행이 열립니다. 이 브라우저용 새 키가 발급되고 다른 기기의 키는 그대로입니다.

## 막혔을 때

| 화면에 보이는 것 | 원인 | 고치는 법 |
|---|---|---|
| 구글 화면에 `redirect_uri_mismatch` (리디렉션 URI 불일치) | 구글에 적은 주소와 서버가 보낸 주소가 한 글자라도 다름(`http`/`https`, 끝의 `/`, 포트 번호) | 위 「구글에 적을 주소」 표와 글자 그대로 맞춥니다. 서버가 쓰는 앞부분은 `ACOP_PUBLIC_BASE_URL` 값입니다 |
| 「액세스 차단됨: 승인 절차가 완료되지 않았습니다」 | 앱이 **테스트** 상태인데 그 계정이 테스트 사용자에 없음 | 순서 8 대로 계정을 추가하거나 앱을 게시합니다 |
| 목록이 계속 비어 있음(`{"providers":[]}`) | 두 줄 중 하나가 비었거나 서버를 다시 안 켬 | 두 줄이 모두 들어 있는지 보고 서버를 다시 시작합니다 |
| 로그인 뒤 웹으로 안 돌아오고 오류 문구가 보임 | 서버가 돌아갈 웹 주소를 모름 | 서버 설정 `ACOP_WEB_ORIGIN` 에 웹 주소를 넣거나, 비워 두면 `ACOP_WEB_ALLOWED_ORIGINS` 의 첫 값을 씁니다 |

## 되돌리기

설정 파일에서 두 줄 중 하나를 지우고 서버를 다시 시작하면 구글이 목록에서 빠집니다. 이미 연결된 계정은 DB 에 남고, 사용자가 마이페이지에서 해제하면 지워집니다.

## 지금 확인하지 못한 것

- 실제 구글과 이어 본 기록이 없습니다. 시험은 가짜 구글로 한 바퀴를 돌렸고, 구글이 돌려주는 신분 확인 값(ID 토큰)의 서명 · 발급자 · 대상 · 만료 · nonce 확인은 따로 시험했습니다. 첫 실제 로그인은 위 「켜졌는지 확인」 으로 확인합니다.
- 「무료」는 구글 로그인에 요금표가 없다는 점으로 판단했고, 구글 정책이 바뀌면 달라질 수 있습니다(구글 공식 안내: `console.cloud.google.com` 의 안내 문구와 [OAuth 클라이언트 관리 도움말](https://support.google.com/cloud/answer/6158849)).
