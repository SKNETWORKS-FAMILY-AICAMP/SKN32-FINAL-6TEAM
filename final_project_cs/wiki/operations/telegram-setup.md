# 텔레그램 알림 켜기 — 운영 절차

**결론.** 고객이 마이페이지에서 「텔레그램으로 연결」을 누르고 텔레그램에서 「시작」을 한 번 누르면 연결되는 기능의 **서버 쪽은 다 만들어 두었습니다.** 사람이 할 일은 (1) 봇 만들기 (2) 서버 환경 파일에 세 줄 넣기 (3) 배포 뒤 웹훅 등록 한 번, 그리고 (4) 사용자가 승인하면 알림 스위치 켜기입니다.
**달라지는 점.** 환경 파일에 값이 있으면 웹의 마이페이지에 텔레그램 줄이 나타납니다. 값이 없으면 줄이 통째로 숨겨지니 **지금 서비스는 아무것도 안 바뀝니다.** 일정 변경 알림을 고객이 연결한 곳(디스코드 · 텔레그램)으로 실제로 보내는 일은 스위치(`travel.notice_per_customer_enabled`, **기본 꺼짐**)를 켜야 시작됩니다 — 켜면 실제 고객에게 메시지가 나갑니다.
**할 일.** 봇 만들기 → 환경 파일 → 재시작 → 웹훅 등록 → 휴대폰으로 한 바퀴 → (승인 뒤) 스위치. 계약과 서버 동작은 [REST 명세 「텔레그램으로 알림 받기」](../external/rest-endpoints.md), 저장 표는 [마이그레이션 048](../data/migrations.md).

## 먼저 답부터

| 궁금한 것 | 답 |
|---|---|
| 돈이 드나요? | **무료.** 봇 만들기도, 봇이 고객에게 메시지를 보내는 것도 무료입니다(텔레그램 공식 FAQ). 우리 비용은 알림 문구를 옮길 때 쓰는 모델뿐이고 그건 기존 알림과 같습니다 |
| 몇 개를 만드나요? | **봇 둘** — 운영용 하나, 시험용 하나. 환경 파일도 각각 따로입니다(시험 봇 토큰은 개발 환경에만). 시험 알림이 실제 고객에게 나간 사고(2026-09-22)를 막으려고 알림은 **운영 테넌트만** 나가는 규칙이 텔레그램에도 똑같이 있습니다 |
| 얼마나 걸리나요? | 봇 만들기 봇당 3분 · 환경 파일과 재시작 5분 · 웹훅 등록 1분 |
| 고객이 봇에 글을 쓰면요? | **알림 전용**입니다. 모델을 부르지 않고 고정 문장 한 줄(「알림 전용 봇이에요 …」)로만 답하고, 글 내용은 저장도 로그도 하지 않습니다 |
| 알림이 두 곳으로 가나요? | 아니요. 알림 받는 곳은 **한 번에 한 곳**(디스코드 또는 텔레그램)이고, 고객이 **마지막에 연결한 곳**이 됩니다. 마이페이지에서 바꿀 수 있습니다 |

## 알아 둘 말

- **봇 토큰**: 봇이 메시지를 보낼 때 쓰는 열쇠입니다(`숫자:영문` 모양의 긴 글자). 비밀번호처럼 다룹니다 — 채팅 · 문서 · 커밋에 쓰지 않습니다.
- **웹훅 등록**: 텔레그램에게 「고객이 봇에 `시작`을 누르거나 봇을 차단하면 이 주소로 알려 달라」고 한 번 알려 주는 일입니다. 주소는 `{공개 주소}/v1/telegram/webhook` 이고 **https** 여야 하며 포트는 443 · 80 · 88 · 8443 만 됩니다.
- **웹훅 비밀값**: 텔레그램이 알림을 보낼 때마다 헤더에 실어 보내는 우리끼리의 암호입니다. 서버는 이 값이 맞을 때만 업데이트를 처리합니다(남이 가짜 「시작」을 보내지 못하게).

```
고객이 웹에서 「텔레그램으로 연결」 → 우리 서버가 일회용 링크를 줌(10분, 한 번만)
  → 텔레그램이 열리고 고객이 「시작」 → 텔레그램이 우리 웹훅으로 「/start 코드」를 알림
  → 서버가 코드를 확인하고 그 사용자에게 대화를 묶음 → 봇이 「연결됐어요」 인사
```

## 순서

| 순서 | 할 일 | 끝나면 이렇게 보입니다 |
|---|---|---|
| 1 | 텔레그램의 @BotFather 로 봇 둘 만들기 — 따라 하기 [봇 만들기 안내](../records/plans/2026-10-05_텔레그램_봇_만들기_안내.md) | 봇마다 **토큰**과 **아이디**(`…_bot` 으로 끝남)를 받았습니다 |
| 2 | 운영 서버의 환경 파일(git 밖)에 아래 표의 **세 줄**을 넣습니다. 시험 봇의 값은 개발 환경 파일에만 넣습니다 | 파일에 세 줄이 있습니다(값을 채팅에 붙이지 않았습니다) |
| 3 | 앱(uvicorn)을 다시 띄웁니다 | `GET /v1/web/profile` 응답의 `telegram_connect.available` 이 `true` 입니다. 셋 중 하나라도 비면 `false` 이고 웹은 텔레그램 줄을 숨깁니다 |
| 4 | **배포 뒤** 서버에서 `python -m scripts.telegram_set_webhook` 을 한 번 돌립니다 | `ok=true Webhook was set` 한 줄이 나옵니다. 주소 · 토큰 · 비밀값은 **출력에 안 찍힙니다** |
| 5 | `python -m scripts.telegram_set_webhook --info` 로 확인합니다 | `등록됨=예 처리 못 한 업데이트=0 마지막 오류=없음` |
| 6 | 휴대폰으로 한 바퀴: 마이페이지 「텔레그램으로 연결」 → 텔레그램이 열리면 「시작」 → 마이페이지 새로 고침 | 봇이 「연결됐어요 …」라고 인사하고, 마이페이지에 「연결됨」이 뜹니다. 「시험 보내기」를 누르면 봇 대화에 시험 문장이 옵니다 |
| 7 | **사용자 승인을 받은 뒤에만** `config/guardrails.yaml` 의 `travel.notice_per_customer_enabled` 를 `true` 로 | 다음 바깥함 일꾼 회차(1분마다 새로 뜹니다)부터 일정 변경 알림이 고객이 연결한 곳으로 나갑니다 |

## 서버 환경 파일에 넣는 세 줄

| 이름 | 뜻 | 값 모양 |
|---|---|---|
| `ACOP_TELEGRAM_BOT_TOKEN` | 봇 토큰 | BotFather 가 준 `숫자:영문` 모양 그대로 |
| `ACOP_TELEGRAM_BOT_USERNAME` | 봇 아이디 | **`@` 없이** `…_bot` (예: `이름_bot`). 고객이 누르는 링크 `https://t.me/<아이디>?start=…` 에 쓰입니다 |
| `ACOP_TELEGRAM_WEBHOOK_SECRET` | 웹훅 비밀값 | 우리가 정하는 무작위 글자. 영문 · 숫자 · `_` · `-` 만, 1~256자. 만드는 법: `python -c "import secrets; print(secrets.token_urlsafe(32))"` |

웹훅 등록에는 위 두 값(토큰 · 비밀값)과 `ACOP_PUBLIC_BASE_URL`(https 로 시작하는 공개 주소)이 필요합니다. 등록한 뒤 **비밀값을 바꾸면 웹훅을 다시 등록**해야 합니다(서버는 새 값을, 텔레그램은 옛 값을 보내기 때문에 모든 업데이트가 401 이 됩니다).

## 막힐 때

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| 마이페이지에 텔레그램 줄이 안 보임 | 세 값 중 하나가 비었음(`telegram_connect.available=false`) | 환경 파일 세 줄을 확인하고 앱을 다시 띄웁니다 |
| `중단: … https` | `ACOP_PUBLIC_BASE_URL` 이 https 가 아님(기본값은 로컬 주소) | 공개 주소(https)로 설정합니다. 로컬에서는 웹훅을 못 씁니다 — 시험은 업데이트를 직접 넣는 방식입니다 |
| `중단: … 포트` | 공개 주소의 포트가 443 · 80 · 88 · 8443 이 아님 | 리버스 프록시로 443 에 열고 그 주소를 씁니다 |
| `ok=false Unauthorized` | 토큰이 틀렸거나 BotFather 에서 폐기됨 | 환경 파일의 토큰을 확인하고, 새로 받았다면 갱신합니다 |
| `--info` 의 마지막 오류에 `401` | 서버의 비밀값과 텔레그램에 등록한 값이 다름 | 환경 파일의 비밀값을 확인하고 `python -m scripts.telegram_set_webhook` 을 다시 돌립니다 |
| `--info` 의 마지막 오류에 연결 실패 · 시간 초과 | 공개 주소가 인터넷에서 안 열림(방화벽 · 인증서 · DNS) | 바깥에서 `https://<공개 주소>/health` 가 열리는지 봅니다 |
| 「시작」을 눌렀는데 인사가 없음 | 웹훅이 등록되지 않았거나(순서 4) 코드가 만료됨(10분) | `--info` 로 등록을 확인하고, 마이페이지에서 연결을 다시 누릅니다 |
| 인사는 왔는데 알림이 안 옴 | 스위치가 **꺼져 있음**(기본) 또는 알림이 `skipped` | 스위치를 확인합니다. `skipped` 면 바깥함 `outbox.last_error` 에 사유가 있습니다 |
| `skipped` 사유 「연결하지 않았다」 | 그 고객이 알림 받는 곳을 연결하지 않음 | 정상입니다 — 고객은 여행계획서 링크에서 최신 상태를 봅니다 |
| `skipped` 사유 「막혀 있다」 | 고객이 봇을 차단함(프로필 상태 `blocked`) | 고객이 봇 차단을 풀고 마이페이지에서 다시 연결하면 풀립니다 |
| `skipped` 사유 「읽을 수 없다」 | 서버 `secret_key` 가 바뀌어 저장값을 못 풂 | 고객이 다시 연결해야 합니다. `secret_key` 를 바꾸지 않습니다 |
| `skipped` 사유 「보낼 대상이 아닌 테넌트」 | 시험 · 시연 테넌트의 알림 | 정상입니다 — 운영 테넌트만 나갑니다 |
| 바깥함이 `pending` 으로 계속 남음 | 텔레그램이 한도(429)를 알림 | 텔레그램이 말한 시각에 다시 시도합니다. 한 대화에 초당 1건 이하입니다 |

## 되돌리기

| 하고 싶은 것 | 방법 |
|---|---|
| 알림을 옛 방식(운영자 채널 하나)으로 | 스위치 `travel.notice_per_customer_enabled` 를 `false` 로 — 다음 일꾼 회차부터 즉시 옛 동작입니다 |
| 텔레그램 연결을 서버에서 끄기 | 환경 파일의 세 줄 중 하나를 비우고 앱을 다시 띄웁니다(마이페이지에서 줄이 숨겨집니다). 이미 연결한 고객의 저장값은 그대로 남고 알림은 `skipped` 됩니다 |
| 웹훅 등록 풀기 | `python -m scripts.telegram_set_webhook --delete` |
| 토큰이 새 나갔을 때 | BotFather 에서 토큰을 폐기하고 새로 받아 환경 파일을 바꿉니다. 새 토큰으로는 웹훅을 다시 등록합니다 |
| 고객이 연결을 풀고 싶을 때 | 마이페이지의 연결 풀기(`DELETE /v1/web/profile/telegram`) — 대화 번호가 지워지고, 알림 받는 곳은 디스코드가 있으면 디스코드로 · 없으면 비어 있게 됩니다. 알림 채널 동의를 철회해도 디스코드 웹훅과 텔레그램 대화 번호가 **함께** 지워집니다 |

## 확인한 것과 안 한 것

- **mock 서버 시험 167/167 통과** — 연결 한 바퀴 · 웹훅 · 고객별 발송(실제 바깥함 일꾼 한 바퀴 포함) · 클라이언트 · 등록 스크립트. 텔레그램과 디스코드는 가짜 응답 서버이고 DB 는 실제 개발 DB 입니다(시험 위치는 [test-map.md](../quality/test-map.md)).
- **실서버 확인: 안 했음.** 실제 봇 · 실제 텔레그램 웹훅 등록 · 휴대폰의 「시작」 단추 · 실제 알림 도착은 봇을 만든 뒤에만 확인할 수 있습니다. `[미확인]` 429 응답의 대기 시간 칸 이름(`parameters.retry_after` 로 알려져 있어 헤더와 본문을 둘 다 봅니다) · 차단된 대화의 정확한 오류 문구(상태 코드로 판정).
- 한국 고객의 텔레그램 사용률은 조사하지 않았습니다.
