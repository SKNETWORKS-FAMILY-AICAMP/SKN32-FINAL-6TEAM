# 여행 기능 장애를 확인하는 순서

먼저 실패한 환경·고객 기능·확인 시각·실행판을 기록합니다. 과거 쇼핑몰 평가 점수나 오래된 GPU 학습 실패를 현재 여행 앱 진단으로 재사용하지 않습니다.

| 증상 | 확인할 것 | 다음 절차 |
|---|---|---|
| 웹은 보이지만 여행 요청 실패 | API 오류 코드·요청 추적·DB·연결 모델·필수 자료 | [상시 운영 점검](always-on.md). HTTP 200인 업무 실패도 실패로 기록 |
| 개인 AI가 여행을 못 읽음 | 웹 사용자 키·본인 여행 소유·MCP 모듈 상태 | [여행 MCP 계약](../external/mcp-tools.md). 키 원문을 로그·보고에 붙이지 않음 |
| 안내가 늦거나 안 옴 | worker 회차·pending 나이·배달 오류·unknown | [상시 운영](always-on.md)·[unknown 확인](unknown-state.md). 같은 안내를 무조건 재전송하지 않음 |
| 정책 검색이 이상함 | 현재 여행 manifest·scope·실제 검색 근거 | [여행 코퍼스](../context/travel-corpus.md). 파일 검사와 DB 적재 상태를 구분 |
| 시험은 통과했는데 실제 요청 실패 | 해당 환경의 코드·이미지·설정·실제 실행 경로 | 시험의 mock·DB·모델·외부 호출 범위를 대조 |

로컬 시험 명령은 [실행·검증](run.md), 환경별 마지막 관측은 [운영 현황](current-state.md)이 소유합니다. 근거 자료 자체가 틀렸거나 Context Broker를 우회하면 출력 근거 검사만으로 안전성을 보장할 수 없습니다. 로그·실패 원본을 보존하고 좁게 확인한 사실을 전체 정상·불가로 확대하지 않습니다.

## 과거 기록

[수정 전 문서](../records/commerce_2026-10-11/wiki--operations--troubleshooting.md)는 당시 기록입니다. 현재 여행 제품의 사양·평가·시연·완료 증거로 사용하지 않습니다. 원문 바이트는 같은 폴더의 백업에도 보존했습니다.
