# 운영을 서버 쪽으로 옮기기

무엇이 상시로 돌아야 하는지와 지금 상태는 [always-on.md](always-on.md)가 적는다.
이 문서는 **거기서 여기로 가는 두 가지 길**과 **각각을 되돌리는 법**을 적는다.

★**이 문서를 쓰면서 시스템 설정을 하나도 바꾸지 않았다.** 서비스 등록·스케줄러 생성·
레지스트리·방화벽 어느 것도 건드리지 않았다. 아래 절차는 **사람이 실행하는 것**이고,
스크립트는 기본이 미리보기다.

★`[실측 2026-09-22]` 이 기계에 있는 것은 `schtasks` 와 `sc` 뿐이다 —
`nssm`·`winsw`·`docker`·`systemctl`·`cron` 은 **없다.** 그래서 길 ①은 작업 스케줄러와
`pg_ctl register` 만 쓴다. 없는 것에 대고 설정 파일을 미리 써 두지 않는다.

## 두 길을 고르는 기준

| | **길 ① 이 PC 에서 서비스로** | **길 ② 항상 켜져 있는 서버로** |
|---|---|---|
| 언제 | 지금 당장. 중간발표까지 이 PC 로 간다 | 상시 운영을 약속하는 순간 |
| 고치는 것 | 재부팅·콘솔 종료로 죽는 것. 죽은 뒤 알아채는 것 | 위 전부 + **PC 가 꺼져 있는 시간** |
| 못 고치는 것 | PC 를 끄거나 로그오프하면 멈춘다. 프로세스가 죽어도 **다시 안 뜬다** | (없음 — 대신 아래 「생기는 문제」가 생긴다) |
| 비용 | 0 | 서버 비용 + 옮기는 품 |
| 되돌리기 | 쉽다 — 작업·서비스만 떼면 원래대로 | 중간이다 — DB 를 어느 쪽이 정본으로 쥐고 있는지에 달렸다 |

★**둘은 배타가 아니다.** 길 ①을 먼저 하고 길 ②로 가는 것이 자연스럽다. 길 ①에서 만든
작업 목록(`scripts/ops/jobs.py`)이 그대로 길 ②의 서비스 목록이 된다.

# 길 ① 이 PC 에서 서비스로 돌리기

## 무엇을 어디에 거나

| 대상 | 무엇으로 | 관리자 권한 |
|---|---|---|
| PostgreSQL | **Windows 서비스** (`pg_ctl register`) | **필요** |
| 되잡기 작업 · 바깥함 일꾼 · 일일 집계 | **작업 스케줄러** — 창 없이(`pythonw`) 한 회차씩 | 필요 없음 |
| 앱 | 작업 스케줄러 — 로그인할 때 상주로 뜬다 | 필요 없음 |

★**왜 `--once` 를 반복해서 거는가**(상주 `--interval` 이 아니라). 상주 루프는 프로세스가
죽으면 그냥 멈춘다. 스케줄러가 매번 새로 띄우면 한 회차가 죽어도 다음 회차가 돌고,
`--once` 는 `errored` 가 있으면 **exit 1** 이라 스케줄러의 「마지막 결과」에 실패가 남는다.
「언제 도는지」도 코드가 아니라 스케줄러에 적힌다.

## 절차

**0. 먼저 본다 — 무엇이 걸릴지, 지금 무엇이 걸려 있는지.**

```powershell
python -m scripts.ops.install_services            # 미리보기. 아무것도 안 바뀐다
python -m scripts.ops.install_services --status
python -m scripts.ops.healthcheck
```

**1. 작업 넷을 건다** (관리자 권한 필요 없음).

```powershell
python -m scripts.ops.install_services --apply --only sweepers,outbox,daily_feedback,app
python -m scripts.ops.install_services --status
```

거는 즉시 도는 것은 아니다 — 다음 주기(1분)부터 돈다. 한 회차를 직접 돌려 확인하려면:

```powershell
python -m scripts.ops.tick sweepers
Get-Content var\ops\heartbeat\sweepers.json
```

**2. 앱이 뜨는지 확인한다.** `app` 작업은 **로그인할 때** 뜨므로, 지금 확인하려면
작업 스케줄러에서 한 번 실행하거나 로그오프 후 다시 로그인한다. 그다음:

```powershell
python -m scripts.ops.healthcheck
```

★`app` 줄이 실패면 **포트를 먼저 본다.** 점검이 보는 주소는 `ACOP_PUBLIC_BASE_URL` 이고,
그 값이 **고객에게 나가는 여행계획서 링크에 박히는 주소**다. 앱이 다른 포트에 떠 있으면
앱은 살아 있는데 링크는 죽는다 `[실측 2026-09-22: 앱 8043 · 설정 8042]`.

**3. DB 를 서비스로 올린다** (★관리자 PowerShell).

```powershell
python -m scripts.ops.install_services --only postgres --pgdata "<데이터디렉터리>"
# 위 출력(무엇을 할지)을 읽고 나서
python -m scripts.ops.install_services --apply --only postgres `
    --pgdata "<데이터디렉터리>" --yes-shared-cluster
```

- `<데이터디렉터리>` 값은 [local-setup.md](local-setup.md)가 갖고 있다.
- **등록만 하고 시작하지 않는다.** 지금 도는 postmaster 가 같은 디렉터리를 쥐고 있어서다.
  **효력은 다음 재부팅부터**이고, 그때 서비스로 뜬다.
- ★★**이 클러스터는 A-COP 만의 것이 아니다.** 같은 데이터 디렉터리에 옆 프로젝트 DB 가
  함께 있다([local-setup.md](local-setup.md) §「알아야 할 것」). 등록하면 **그쪽 수명도
  함께 바뀐다** — 그래서 `--yes-shared-cluster` 를 따로 받는다. **팀 합의가 먼저다.**
- 지금 당장 바꾸고 싶으면 도는 postmaster 를 **정상 종료**한 뒤 서비스를 시작한다.
  그 판단은 사람이 한다 — 옆 프로젝트가 같이 멈춘다.

**4. 확인.**

```powershell
python -m scripts.ops.install_services --status
python -m scripts.ops.healthcheck
```

`db_수명` 줄이 「서비스로 등록돼 있다」로 바뀌면 콘솔·세션과 끊긴 것이다.

## 되돌리기 (길 ①)

```powershell
# 작업만 뗀다 — 원래대로 손으로 띄우는 상태가 된다
python -m scripts.ops.install_services --remove --only sweepers,outbox,daily_feedback,app

# DB 서비스 해제 (★관리자)
python -m scripts.ops.install_services --remove --only postgres
```

- 작업을 떼도 **데이터는 아무것도 안 바뀐다.** 스케줄러 항목만 사라진다.
- DB 서비스를 해제하면 **다음 재부팅부터 다시 수동 기동**이다. 이미 서비스로 떠 있는
  DB 는 해제해도 그 세션 동안은 계속 돈다 — 실제로 내리는 것은 사람이 정한다.
- `var/ops/` 의 기록은 남는다. 지워도 되고, 남겨 두면 「그때 무엇이 돌았나」가 남는다.

## 이 길이 **못 고치는 것**

1. **PC 를 끄거나 로그오프하면 멈춘다.** 작업은 이 계정 세션에서 돈다. 로그오프해도
   돌게 하려면 계정 비밀번호를 저장해야 하는데(작업 스케줄러 「로그온 여부와 관계없이 실행」)
   **그건 이 문서가 권하지 않는다** — 비밀번호를 기계에 저장하는 결정은 사람이 따로 한다.
2. **죽은 프로세스를 다시 띄우지 않는다.** 작업 스케줄러에는 재시작 기능이 없다.
   상주인 앱이 죽으면 다음 로그인까지 죽은 채다. 되잡기·배달은 1분마다 새로 뜨므로
   이 문제를 덜 받는다.
3. **여전히 한 대에 다 있다.** 그 PC 가 곧 제품이다.
4. `Windows Defender` 와 `McAfee` 실시간 검사 둘이 DB 파일을 간섭한 흔적이 있다
   (`sharing violation` 19건 · `error code 487` 52건). 서비스로 올려도 이건 그대로다 —
   제외 설정은 보안 정책이라 사람이 정한다.

# 길 ② 항상 켜져 있는 서버로 옮기기

여기서 서버는 `<서버>` 로만 적는다. **주소·계정·별칭·키 파일 경로는 이 문서를 포함해
커밋되는 어떤 파일에도 적지 않는다** — 실제 값은 git 이 무시하는 파일과 개인 설정에만 둔다.

## 장단점

| 좋아지는 것 | 대가 |
|---|---|
| PC 를 꺼도 돈다. 재부팅·로그오프와 무관하다 | 서버 비용과 관리 품이 든다 |
| 프로세스가 죽으면 **다시 띄울 수 있다**(서비스 관리자가 있다) | 접속 경로를 새로 만들어야 한다 |
| 로그·시각이 한 곳에 모인다 | 개발 PC 에서 바로 고쳐 보는 맛이 사라진다 |
| 여행계획서 링크를 **바깥에서 열 수 있다** — 지금은 루프백뿐이다 | 바깥에 열리는 순간 보안이 생긴다(아래) |
| 안티바이러스 간섭·커밋 한도 고갈에서 벗어난다 | 옮기는 동안 DB 정본이 둘이 될 위험 |

## 옮길 것 (목록)

| 옮기는 것 | 비고 |
|---|---|
| PostgreSQL 클러스터 중 **`acop_cs` 하나** | ★클러스터 전체가 아니다. 옆 프로젝트 DB 는 이 PC 에 남는다 — `pg_dump` 로 DB 하나만 뜬다 |
| 저장소(코드) | `git clone`. 작업 트리에만 있고 커밋 안 된 것(`seed_travel.py` 등)이 있는지 먼저 센다 |
| **비밀값** `.env` · `.env.apikeys` | git 에 없다. **따로 옮긴다**(아래) |
| 상시 작업 목록 | `scripts/ops/jobs.py` 그대로 — 거는 도구만 서버 것으로 바꾼다 |
| 안내 문구틀 `var/notice_phrasebook.json` | 없으면 다시 만든다(모델 호출이 다시 든다) |
| 마이그레이션 | 재실행이 안전하다(전부 `IF NOT EXISTS`) |

## 옮기면 **생기는 문제** 셋

### 1. 접속

- **누가 어디로 붙나.** 지금은 전부 루프백(`127.0.0.1`)이라 인증 경계가 느슨하다.
  서버로 가면 앱은 바깥에서 열리고 **DB 는 절대 바깥에 열지 않는다**(같은 기계 안에서만).
- **여행계획서 링크의 주소가 바뀐다.** `ACOP_PUBLIC_BASE_URL` 이 링크에 박히므로,
  옮긴 뒤 이 값을 서버 주소로 바꿔야 **이미 나간 링크가 아니라 새 링크**가 맞게 나간다.
  ★**이미 나간 링크는 옛 주소를 가리킨 채다** — 옮기는 시점에 살아 있는 여행이 있으면
  그 여행의 고객이 보는 것이 끊긴다.
- **관리 접속은 사람이 정한 경로로만.** 이 문서에 그 경로를 적지 않는다.

### 2. 백업

- 지금은 백업이 **없다.** 옮기는 순간 「이 기계가 죽으면 끝」이 된다 — 그래서 옮기는 일과
  백업을 만드는 일은 **같이** 해야 한다.
- 최소선: `pg_dump` 를 하루 한 번, **서버 밖**으로. 되살리는 절차를 한 번은 실제로 돌려 본다.
  ★**복구를 해 보지 않은 백업은 백업이 아니다.**
- 옮기는 동안은 **정본이 둘이 되지 않게** 한다 — 옮긴 뒤 이 PC 쪽 `acop_cs` 에는 쓰지 않는다.

### 3. 비밀값

- `.env`·`.env.apikeys` 는 git 에 없다. **손으로 옮긴다.** 옮기는 경로를 채팅·이슈·커밋에
  남기지 않는다.
- ★**커밋되는 파일과 커밋 메시지에 주소·계정·별칭·키 경로·웹훅 URL 을 적지 않는다.**
  템플릿의 값 칸은 빈 표시(`<…>`)로만 둔다. 올리기 전 저장소 **전체**를 자르지 않고 검사한다:
  ```bash
  git grep -I -n -E "([0-9]{1,3}\.){3}[0-9]{1,3}|webhooks/|@[0-9]"
  ```
- 디스코드 웹훅은 **그 URL 하나가 곧 권한**이다. 옮기면서 새로 발급하고 옛 것은 지운다.
- `.env` 는 **BOM 없이** 저장한다 — PowerShell 의 `Set-Content -Encoding UTF8` 이 BOM 을
  붙여 첫 키를 못 읽게 만든 적이 있다([local-setup.md](local-setup.md) §함정 1).

## 절차 (개요)

1. **서버에 무엇을 쓸지 정한다.** OS 와 서비스 관리자(리눅스면 systemd, 윈도면 서비스)를
   정하기 전에는 배선을 미리 쓰지 않는다 — 이 저장소는 없는 것에 설정 파일을 미리 써 뒀다가
   「전부 미검증」을 문서에 적어야 했다.
2. **DB 하나를 뜬다** — `pg_dump` 로 `acop_cs` 만. 건수를 적어 둔다(뒤에서 대조한다).
3. **서버에 코드·파이썬·PostgreSQL 을 올리고** 마이그레이션을 돌린 뒤 덤프를 넣는다.
4. **건수를 대조한다.** `knowledge_documents` · `knowledge_chunks` · `customer_cases` ·
   `outbox` 를 옮기기 전후로 센다. ★**건수만 세는 검증은 이 프로젝트에서 두 번 실패했다** —
   `python -m scripts.check_env` 와 `python -m scripts.check_corpus` 를 함께 돌린다.
5. **비밀값을 옮기고** `ACOP_PUBLIC_BASE_URL` 을 서버 주소로 바꾼다.
6. **상시 작업 다섯을 서버의 서비스 관리자에 건다.** 목록은 `scripts/ops/jobs.py` 다.
7. **점검을 서버에서 돌린다** — `python -m scripts.ops.healthcheck`. 여기까지 와야 옮긴 것이다.
8. **이 PC 쪽을 멈춘다** — 작업을 떼고(길 ① 되돌리기) 이 PC 의 `acop_cs` 에는 쓰지 않는다.

## 되돌리기 (길 ②)

- **옮기는 중이라면** 쉽다 — 서버 쪽을 버리고 이 PC 를 계속 쓴다. 이 PC 를 멈추지 않았다면
  잃는 것이 없다. **그래서 8번(이 PC 정지)을 마지막에 둔다.**
- **옮긴 뒤라면** 서버 쪽 DB 가 정본이다. 되돌리려면 **서버에서 덤프를 떠서 이 PC 로
  되돌려 넣고**, `ACOP_PUBLIC_BASE_URL` 을 되돌리고, 서버의 상시 작업을 끈다.
  ★**두 쪽을 동시에 켜 두지 않는다** — 통지가 두 번 나가고 예약이 두 번 바뀐다.
- 어느 쪽이든 **되돌린 뒤 점검을 돌려** `db`·`outbox_pending`·`app` 세 줄을 확인한다.

## 아직 안 정해진 것

- **서버를 무엇으로 할지** — 정해지지 않았다. 그래서 컨테이너·systemd 배선을 미리 쓰지 않았다.
- **백업 보관 위치와 주기** — 정해지지 않았다. 위 「최소선」은 제안이다.
- **로그오프해도 도는 방식**(작업 스케줄러에 비밀번호 저장)을 쓸지 — 사람이 정한다.
