# 서비스 개선 자료 처리

2026-10-10 사용자 승인 범위: 서비스 개선용 선택 동의, 원본 보유기한 준수, 익명성 검토를 거친 합성본의 별도 활용. 로컬 구현과 운영 반영은 구분한다.

## 동의 계약

- 기존 `/v1/web/consents`에 선택 코드 `service_improvement`를 추가한다. 필수는 기존 `service_terms`, `privacy` 둘이다. 새 항목 기본값은 false이고, 이전 동의를 새 항목의 동의로 간주하지 않는다.
- 기본 약관 버전은 `2026-10-10.1`이다. 새 본문에 대해 사람이 동의해야 하며, 기록에는 본문 SHA-256과 버전이 남는다. 에이전트 키로 동의할 수 없다.
- 개선 자료의 추출은 일반 동의 게이트의 켜짐과 무관하게 필수 둘과 개선 항목 모두의 **현재 버전 동의**를 검사한다. 철회 시 다음 추출에서 제외하고 검토 대기 합성 후보를 폐기한다. 이미 익명성 검토를 마친 합성본에는 이용자 연결표가 없어 개인별 회수가 불가능하다.

## 최초 구현의 범위

현재 남아 있는 여행의 인원 수, 일정이 있는 날짜 수, 하루당 일정 개수만 읽는다. 최초 추출 대상은 최근 웹 세션 이용이 게스트 기본 유효기간과 회원 보유기간 모두 안에 있는 사용자로 좁힌다(일정 유예로 남아 있는 오래된 게스트는 포함하지 않는다). 여행·이용자 식별자는 대상 판정과 사용자당 최대 한 여행 선택에만 쓰고 출력하지 않는다. 질문·답변 원문, 제목, 장소, 좌표, 예약번호, 날짜 원값, 종교·건강·식사 제한, 동행 설명은 읽지 않는다. 합성본은 일정 구조의 품질 평가·기능 연구·모델 학습/평가에 사용하며 실제 고객 일정이나 사실 근거로 쓰지 않는다.

원본 보유기한은 늘리지 않는다. 개선 선택 동의가 있어도 삭제/탈퇴/기한 파기의 기존 경로는 그대로 실행한다. 합성 작업은 원본 파기의 선행 조건이 아니다. 기한이 지난 자료를 되살리거나 파기를 미루지 않는다. 회원 만료 대상과 게스트 만료 대상은 추출에서 제외한다.

## 합성 후보와 이용 허가

1. 사용자당 최신 여행 한 개에서 정해진 세 구간 값만 메모리에서 만든다. 대상 사용자 전체를 조회하며 인원 제한으로 잘라 민감도가 바뀌지 않게 한다.
2. 고정된 27개 조합 전체의 빈도에 두 기하분포의 차를 더한다. 공정한 암호학적 난수 비트만 사용하는 이산 잡음이며 사용자 추가/제거 기준 한 회차의 수학적 epsilon은 ln(2)이다. 같은 사용자의 값 교체 기준은 2ln(2)이다. 다만 이 수학적 구성만으로 실제 구현의 형식 검증이나 법률상 익명성을 보장하지 않는다.
3. DB의 tenant별 잠금과 누적 회차 예산으로 반복 생성의 손실을 합성한다. 실패·철회·후보 만료로 예산을 돌려주지 않는다. 예산을 기간마다 초기화하지 않는다. 회차별 원본 건수와 사용자 목록은 저장/출력하지 않는다.
4. 잡음이 더해진 값에서 고정 개수의 합성 행을 만든다. 원자료를 복사하지 않고 출력 스키마를 허용 목록으로 검사한다. 잡음 처리 후의 표본량이 정책 하한에 못 미치면 후보를 저장하지 않는다(예산은 소비).
5. 후보는 7일 이내 검토해야 한다. 후보 해시와 현재 약관 버전이 맞고, 적법한 이용 근거·재식별 공격 검토·유용성 검토의 실제 증빙 해시가 있는 경우에만 검토자가 승인한다. 기계의 스키마 검사는 법무/익명성 심의를 대신하지 않는다. 승인 전에는 내보내기/학습에 사용할 수 없다.
6. 승인된 합성본만 내보낸다. 정기 목적 적합성 재검토는 매년, 승인본의 보관 상한은 생성일부터 5년이다. 후보와 승인본의 만료 정리는 기존 웹 정리 작업에 연결한다. 원본과 이용자 연결표를 별도 보존하지 않는다.

설정 정본: `config/guardrails.yaml`의 `service_improvement`. 합성 표는 마이그레이션 `229_service_improvement.sql`에 있다. 운영 도구는 `python -m scripts.service_improvement --help`에서 확인한다. 운영 DB에 실제 자료를 추출하거나 파기하는 실행은 이번 구현 검증과 구분한다.

## 운영 도구의 입력과 결과

| 명령 | 필수 입력 | 결과·제약 |
|---|---|---|
| `--tenant <대상> prepare` | 대상 tenant | 전용 autocommit 연결에서 예산부터 확정. 후보 번호·해시·약관 버전 또는 잡음 처리 후 자료량 부족 상태만 반환. 실제 인원 수는 반환하지 않는다. |
| `--tenant <대상> approve <후보 번호>` | `--sha256`, `--reviewer`, `--lawful-basis`, `--reidentification`, `--utility` | 마지막 세 인자는 실제 심의 결과 파일 경로다. 비어 있지 않은 파일의 해시를 기록한다. 파일이 있다는 것만으로 내용이 적법하다는 판정을 기계가 내리지 않으며 실행한 검토자가 실질 검토를 책임진다. 후보 내용은 접근 권한이 있는 검토자가 DB에서 확인한다. |
| `--tenant <대상> export <후보 번호>` | `--output` 새 파일 경로 | 승인·해시·현재 약관·보관기한·연례 검토를 확인하고 합성본만 저장. 기존 파일은 덮어쓰지 않는다. |
| `--tenant <대상> prune` | 대상 tenant | 보관기한이 지난 합성 표의 자료만 정리. 원본과 누적 예산은 변경하지 않는다. |

운영 정리 작업은 DB 합성 표의 만료를 관리한다. 외부로 내보낸 사본은 자동 회수하지 않으므로, 검토자는 사본의 보관 위치·만료·연례 검토도 관리해야 한다. 새 약관과 마이그레이션의 운영 반영, 실제 자료 심의는 별도이며 기존 회원 원본 정리 설정은 아직 `dry_run`이다. [로컬 검증·한계·백업](../records/reports/2026-10-10_service-improvement-consent.md)을 함께 본다.

## 법적 근거와 확인 한계

- [개인정보 보호법 제15조·제16조·제18조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398625): 동의 목적·항목·기간·거부권 및 목적 제한. 이 구현은 법률상 모든 개선에 선택 동의가 필수라고 단정하지 않고, 별도 선택 동의를 근거로 운영한다.
- [법 제21조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0021&lsiSeq=283839&urlMode=lsScJoRltInfoR): 불필요해진 원본의 파기 의무는 별개다.
- [법 제58조의2](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1022694479): 다른 정보와 함께 보아도 개인을 알아볼 수 없는지 검토한다.
- [개인정보위 합성데이터 안내](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=10871): 안전성·유용성 검증과 평가를 구분한다.
- [NIST SP 800-226](https://csrc.nist.gov/pubs/sp/800/226/final): 기여량 제한·반복 손실·구현상의 위험을 검토하는 참고 문서다. NIST 인증이나 국내 법률 적합 판정을 받았다는 뜻은 아니다.

위치정보·민감정보를 개선에 쓰는 범위 확대는 현재 동의에 포함되지 않는다. 실제 익명성 판정·증빙 검토와 운영 배포는 코드 시험 통과와 별개다.
