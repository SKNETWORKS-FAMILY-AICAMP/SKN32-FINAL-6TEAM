# 대체 장소 점검의 내부 운영 기록

2026-10-17 사용자 지시: 뚝섬 대체 장소 실패를 확인하고 후보별 탈락 사유를 기록한다. 이 기록을 고객 앱·고객 API·알림·디스코드로 전달하지 않는다.

담당은 현재 결함 수정 채팅이며 매니저 검토는 `git commit push` 채팅에 요청한다. 독립 검토 완료로 표시하지 않는다.

감시 회차의 기존 `travel_watch_checks`에 `candidate_evaluation` 단계로 후보 하나씩 추가한다. 회차·여행·일정·Case, 검색 단계, 후보 식별자·이름, 선택/대안/탈락/중복/보류, 탈락 사유, 재검증 판정·실패 종류·도구 제한을 기록한다. 운영자 조회는 기존 `ops:introspect`와 테넌트 경계를 유지한다. 새 고객 응답 필드는 만들지 않는다. 원문 API 응답·키·접속 주소는 기록하지 않는다.

Team은 DB를 직접 쓰지 않는다. 계산 계층의 관찰 포트가 이벤트를 전달하고 감시 실행 계층이 저장한다. 감시 밖의 실행은 같은 제한된 필드를 내부 로그에 남긴다. 후보를 개별 기록하므로 목록 100개 제한 때문에 뒤 후보가 잘리지 않는다. 기록 실패는 성공으로 숨기지 않는다.

후보의 재검증이 불가능하거나 도구/회차 한도로 보류됐고 확인된 대안이 없다면 `source_failed`로 처리한다. 실제로 모든 확인된 후보가 조건에 어긋난 경우와 구별한다. 고객에게는 기존의 간단한 확인 지연 안내만 제공하며 후보별 상세 사유는 넣지 않는다. 확인하지 않은 장소를 안전하다고 추천하지 않는다.

기록은 그 회차에 실제 살펴본 후보만 증명한다. 보관되지 않은 과거 후보 목록·응답은 현재 자료로 소급 생성하지 않는다.

일정 전체 재판정의 탈락도 같은 내부 기록으로 남긴다. 기존 변경 알림에 포함되던 `fit.skipped`와 후보 이름별 탈락 설명은 고객 전달물에서 제거하고, 선택한 일정 자체의 밀도 경고만 유지한다.
