# 상시 작업 실행기 종료

구구루트의 `deploy/worker.sh`는 Python 작업 한 회차씩을 순차 실행합니다. TERM/INT에 대한 종료 처리는 바깥함의 재시도·claim·중복 제거 정책을 바꾸지 않습니다.

- 부모 실행기에 TERM 또는 INT가 전달되면 종료를 요청합니다. 이미 실행 중인 Python 명령은 신호를 전달하거나 강제 종료하지 않고 자연 종료를 기다립니다. 종료 요청 뒤에는 다음 Python 명령을 시작하지 않습니다.
- 회차 사이의 대기 sleep은 종료하고 wait로 회수합니다. 정리 중 반복된 TERM/INT가 회수를 중단하지 않도록 합니다.
- 작업 실패는 기존 구조의 job·exit·시각 로그로 남기고, 실행 중에는 다음 작업·다음 회차를 계속 시도합니다. 정상 종료 코드는0입니다. 종료하는 회차에서 작업이나 성공 표시 저장이 실패하면 마지막 실패 코드를 반환합니다. 예상하지 않은 sleep 실패는 기록 후 그 코드로 종료합니다.
- 성공 표시 저장 실패는 실행 중인 셸이 실제로 낸 코드를 보존합니다. 특정 값1로 정규화하지 않습니다. 시험은 같은 셸·같은 대상·같은 쓰기 명령의 실패 코드와 실행기 종료 코드·실패 로그가 정확히 같은지 비교합니다.
- 일일 집계가 성공한 경우 성공 표시 저장은 같은 작업의 마무리로 수행합니다. 실패하거나 종료 때문에 시작하지 않은 집계를 성공으로 표시하지 않습니다.
- 중지는 Python 명령의 경계입니다. 진행 중인 `--drain` 명령 내부의 개별 메시지 claim을 즉시 중단하지 않습니다. 작업이 끝나지 않거나 외부 종료 유예가 짧으면 실행기만으로 정상 종료를 보장할 수 없습니다. SIGKILL·직접 자식 신호·그룹 신호·작업 내부 데몬까지 보호한다고 보고하지 않습니다.

셸은 전경 명령을 기다릴 때 트랩을 명령 완료 뒤 처리하며, 비동기 자식을 wait할 때는 신호로 wait가 중단될 수 있습니다. 이 차이를 이용해 작업 완료와 대기 취소를 구분합니다. [GNU Bash 신호 문서](https://www.gnu.org/s/bash/manual/html_node/Signals.html), [POSIX 셸 신호 규칙](https://pubs.opengroup.org/onlinepubs/000095399/utilities/xcu_chap02.html).

검증은 실제 Bash에서 부모 TERM/INT, 현재 작업 자연 완료, 후속 작업 미시작, sleep 회수, 작업·대기 실패 코드, 일일 성공 표시를 확인합니다. MSYS Bash 결과와 Linux 컨테이너 PID1·dash 결과를 구분합니다. 후자는 로컬 실행 수단이 확보되기 전에는 미확인입니다.
