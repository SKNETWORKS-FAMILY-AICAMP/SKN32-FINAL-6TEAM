# 상시 작업 실행기 종료

구구루트의 `deploy/worker.sh`는 되잡기(진단 재전송 · 감시 · 일일 집계) Python 작업을 한 회차씩 순차 실행하고, `[2026-10-19]` 바깥함 배달(`scripts.run_outbox_worker --once --drain`)은 **같은 컨테이너 안에서 따로 도는 반복 하나**로 실행합니다. 배달 반복은 배달 한 번 뒤 `WORKER_DELIVERY_SLEEP`(기본 10)초 쉽니다. TERM/INT에 대한 종료 처리는 바깥함의 재시도·claim·중복 제거 정책을 바꾸지 않습니다.

- 부모 실행기에 TERM 또는 INT가 전달되면 종료를 요청하고 배달 반복에도 TERM으로 알립니다. 이미 실행 중인 Python 명령(되잡기 작업 · 배달)은 신호를 전달하거나 강제 종료하지 않고 자연 종료를 기다립니다. 종료 요청 뒤에는 두 반복 모두 다음 Python 명령을 시작하지 않습니다(알림이 닿기 직전에 띄우던 배달 하나는 끝까지 갑니다).
- 회차 사이의 대기 sleep과 배달 반복의 대기 sleep은 종료하고 wait로 회수합니다. 정리 중 반복된 TERM/INT가 회수를 중단하지 않도록 합니다. 부모는 배달 반복이 끝날 때까지 1초마다 다시 알리며 회수합니다(갓 뜬 반복이 트랩을 걸기 전에 받은 신호가 사라져도 멈추게). 배달 반복은 부모와 달리 뒤 신호를 무시하지 않고 받을 때마다 자기 대기 sleep 만 다시 끕니다 — 막 띄운 sleep 에 보낸 첫 신호가 사라져도(Git Bash 에서 40회 중 3회 재현) 다음 알림에 끝납니다. 진행 중인 발송에는 어느 신호도 보내지 않습니다.
- 작업 실패는 기존 구조의 job·exit·시각 로그로 남기고, 실행 중에는 다음 작업·다음 회차를 계속 시도합니다. 정상 종료 코드는0입니다. 종료하는 회차에서 작업이나 성공 표시 저장이 실패하면 마지막 실패 코드를 반환합니다. 예상하지 않은 sleep 실패는 기록 후 배달 반복을 회수하고 그 코드로 종료합니다.
- 배달 실패(`"job":"outbox"`)는 로그에 남기고 다음 배달에서 다시 시도합니다. 배달 실패는 실행기 종료 코드에 넣지 않습니다. 배달 반복의 대기가 실패하면(`delivery_wait`) 그 반복만 끝나고, 배달 반복이 혼자 멈추면 다음 되잡기 회차가 `"job":"delivery_loop"`로 남기고 다시 띄웁니다. 배달 반복은 한 컨테이너에 하나뿐입니다.
- 성공 표시 저장 실패는 실행 중인 셸이 실제로 낸 코드를 보존합니다. 특정 값1로 정규화하지 않습니다. 시험은 같은 셸·같은 대상·같은 쓰기 명령의 실패 코드와 실행기 종료 코드·실패 로그가 정확히 같은지 비교합니다.
- 일일 집계가 성공한 경우 성공 표시 저장은 같은 작업의 마무리로 수행합니다. 실패하거나 종료 때문에 시작하지 않은 집계를 성공으로 표시하지 않습니다.
- 중지는 Python 명령의 경계입니다. 진행 중인 `--drain` 명령 내부의 개별 메시지 claim을 즉시 중단하지 않습니다. 작업이 끝나지 않거나 외부 종료 유예가 짧으면 실행기만으로 정상 종료를 보장할 수 없습니다. SIGKILL·직접 자식 신호·그룹 신호·작업 내부 데몬까지 보호한다고 보고하지 않습니다.

`[2026-10-19]` 작업은 비동기로 띄우고 wait로 기다립니다. 셸은 전경 명령을 기다릴 때 트랩을 명령 완료 뒤 처리하므로, 그러면 되잡기 작업이 끝날 때까지 배달 반복에 멈춤을 알리지 못합니다. 비동기 자식을 wait할 때는 신호로 wait가 중단되므로, 트랩이 돈 뒤 같은 자식을 다시 기다려 그 종료 코드를 받습니다(이미 회수돼 다시 기다릴 것이 없으면 앞에서 받은 코드). [GNU Bash 신호 문서](https://www.gnu.org/s/bash/manual/html_node/Signals.html), [POSIX 셸 신호 규칙](https://pubs.opengroup.org/onlinepubs/000095399/utilities/xcu_chap02.html).

검증은 이 PC의 Git Bash(MSYS)에서 Bash(POSIX 모드)와 dash 두 셸로 부모 TERM/INT, 현재 작업 · 배달 자연 완료, 후속 작업 미시작, sleep 회수, 작업·대기 실패 코드, 일일 성공 표시, 배달이 긴 되잡기 작업 동안 계속 도는지, 배달 실패 재시도, 멈춘 배달 반복 재기동을 확인합니다. MSYS는 `exec` 도중 받은 신호를 잃으므로 시험용 sleep 대역은 exec 하지 않습니다(Linux는 보류 신호가 exec 뒤에도 남습니다). Linux 컨테이너 PID1·dash 결과는 실제 배포(x600 서버)의 기록으로 따로 확인합니다.
