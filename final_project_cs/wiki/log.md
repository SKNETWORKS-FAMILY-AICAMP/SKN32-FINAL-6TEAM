# 문서 변경 이력 (cs)

## 2026-10-06 — 업무 도메인 폴더를 칸으로 나누고, 칸끼리 규칙 위반을 0 으로 (D-CS-013) · 라우팅 재배분 (D-CS-014)

하루 동안 여행 코드의 **자리**를 바꾼 작업이다. 기능은 바꾸지 않았다(라우팅 재배분만 새 동작).

1. **폴더를 칸으로 나눴다** — 울타리 `app/modules/` → `app/domains/`, 여행 묶음 아래 68개 파일과 하위 폴더 4개를
   여섯 칸으로(`modules` 끌 수 있는 기능 · `instances` 에이전트 팀 · `components` 필수 부품 · `ports` 바꿔 끼우는
   자리 · `entry` HTTP 입구 · `scenarios`). 여행 외부 데이터 소스 28개도 `ports/data_sources/` 로 들어왔다.
   옛 `app/domain/`(Case 상태 규칙)은 `app/core/case_lifecycle/` 로 옮겨 `domain`·`domains` 겹침을 없앴다.
   → [결정 D-CS-013](decisions/D-CS-013-domain-folder-layout.md) · [계획](records/plans/2026-10-06_0040_업무도메인_폴더이동_계획.md) ·
     [0단계 리포트](records/reports/2026-10-06_0030_폴더정리_0단계_리포트.md) · [1~6단계 리포트](records/reports/2026-10-06_0300_업무도메인_폴더이동_리포트.md)

2. **칸끼리 규칙을 어기는 곳을 0 으로 만들었다** — 옮긴 날 실측 20곳(필수 부품 → 끌 수 있는 기능 4 ·
   바꿔 끼우는 자리 → … 2 · 필수 부품 → 팀 속 14). 끼움 자리 일곱을 만들어 **방향을 뒤집었다**: 부품은 자리만
   알고, 기능과 팀이 조립 때 자기 것을 꽂는다. 꽂지 않으면 그 기능이 없을 때 부품이 원래 가던 길로 간다
   (값을 지어내지 않는다). → [기능 쪽 리포트](records/reports/2026-10-06_0620_웹계정_끼움자리_전환_리포트.md) ·
     [팀 쪽 리포트](records/reports/2026-10-06_0700_팀쪽_끼움자리넷_전환_리포트.md) · [계획](records/plans/2026-10-06_0600_끼움자리_넷_전환_계획.md)

3. **라우팅이 어긋나면 한 번 더 고른다** — 받는 팀이 없으면 `escalated` 로 끝났는데, 이 제품에는 사람 운영자
   큐가 없어 그 Case 는 아무도 받지 않는다. 등록된 팀이 **실제로 받는 종류** 안에서만 고르고, 돌려받은 답도
   등록부에 **다시 물어** 확인한다. Case 당 한 번. → [결정 D-CS-014](decisions/D-CS-014-routing-reroute.md) ·
     [리포트](records/reports/2026-10-06_0800_라우팅_재배분_리포트.md)

4. **생성기 시험 10건의 컴퓨터 의존을 없앴다** — `test_trip_planner.py` 가 자기 장소 12곳만 쓰려 했지만 요식
   원장은 테넌트와 무관한 공용 표라 그 격리가 통하지 않았다(원장 자료가 있는 기계에서만 붉었다). 시험이 원장을
   끈다. 같은 리포트에 적었다.

검증 — 구조 · 계약 · 단위 · 보안 **2,789** · 통합 **404** · e2e · 시나리오 **847** 통과. 남은 실패는 RAG 8건뿐이고
이 PC 의 로컬 임베딩 서버가 꺼져 생긴 것이다. ★**실서버 확인(서버 응답): 안 했음** — 라우팅 재배분이 실제
모델로 어떤 팀을 고르는지는 x600 서버의 cs 프로젝트 서버에 배포한 뒤 본다(이 PC 는 OpenAI 크레딧이 없고
로컬 Ollama 도 떠 있지 않다).

## 2026-10-06 — 재난 시 일정 정지 · 대피 장소 안내 · 다시 시작

사용자 결정: 재난이 난 시각에 그 지역에 여행객이 있었다면 **그날 일정 정지**, 전쟁 · 활화산 폭발 같은 심각한 사건이면 **여행 전체 정지 + 근처 피난처 안내 + 안전 알림**. 앞선 「켜져 있으면 안전 사건도 바로 바꾼다」(09-24)와 「먼저 묻는다」(10-06 오전 제안)를 **대체**한다 — 둘 다 다른 곳으로 옮기는 방식이었다.
- 새로 만든 것: 재난 점검 반복(`SafetySweep` — 감시 주기 문 안에서 감시 앞에) · 분류(`planning/safety.py`) · 정지 표시표(`trip_safety_pauses` — 일정은 안 고친다) · 감시 · 안내 반복에서 정지한 여행 빼기 · 대피 장소 표(`safety_shelters`) + 적재 스크립트 · 안전 알림(안전 앞세움 · 재난문자 원문 · 대피 장소 · 다시 시작 안내) · 공식 해제 알림 · `POST …/safety/resume` · 여행 조회의 `safety` · `items[].paused` · 마이그레이션 052 · 설정 `travel.safety`.
- ★`[같은 날 오후 사용자 결정]` **아직 시작하지 않은 여행도 심각한 사건(여행 전체 정지 단계)이면 사용자가 다시 시작할 때까지 정지한다**(앞 판은 「시작 전은 안 멈춘다」였다). 그날 정지 단계 사건은 시작 전 여행을 멈추지 않는다. 시작 전 안전 알림은 대피 장소 없이 「가기 전에 공식 안내 확인」이다(`guidance.phase=upcoming` · 여행 조회 `safety.phase`). 시험 29건(시작 전 5건 추가).
- 재난문자 판정을 고쳤다: 민방위 · 화산 · 원전 · 방사능 재해구분과 본문 심각 낱말(공습경보 · 화산 …)을 이상으로 세고, 훈련 문자는 거른다(전에는 모르는 구분으로 빠지거나 거르지 않았다).
- ★**대피 장소 자료는 아직 적재하지 않았다**(공공데이터 4종 조사 — 이용허락 제한 없음 · 공공누리 1유형). 파일을 받는 것은 사용자 허락이 필요하다. 표가 비어 있으면 알림은 「자료를 아직 불러오지 못했어요 + 공식 안내」다 — 지어내지 않는다.
- 한계: 실제 위치를 모른다(일정에 적힌 장소 기준) · 재난문자 재해구분 전체 목록 `[미확인]`(낱말 규칙 병행) · 자동 재개 없음(사용자가 누름). 시험 로컬 개발 DB — 실서버 · 실제 재난문자 확인 안 함. 설계 [2026-10-06_재난_일정정지와_피난안내_설계.md](records/plans/2026-10-06_재난_일정정지와_피난안내_설계.md) · 계약 [rest-endpoints.md](external/rest-endpoints.md) 「재난 시 일정 정지」.

## 2026-10-06 — 개인 AI 입구(MCP) 읽기 도구 둘: 일정 위험 점검 · 이동 판정

사용자 요청(「지금 모니터링 도구가 mcp 호출 가능한 툴로 잡혀 있어?」 · 「이동판정기도 mcp 로 해두면 될 거 같은데」 — 다른 세션 경유)로 읽기 도구 둘을 더했다. MCP 도구는 12 → 14(읽기 5 → 7 · 쓰기 7). 읽기라 쓰기 스위치와 무관하다.
- 웹 입구가 규칙이다(MCP 는 그대로 부른다): `GET /v1/web/trips/{id}/risks` · `POST /v1/web/moves/judge`. 도구 `tripilot_check_trip_risks` · `tripilot_judge_move`.
- **일정 위험 점검** — 감시가 하는 6종 점검을 항목마다 `problem`/`clear`/`unknown` 으로(확인 불가를 문제 없음으로 말하지 않는다). ★하루 한도(D-017)를 안 깎게: 기본은 **공유 응답 캐시만 읽는** 점검기(`CacheOnlyLimiter` — 바깥에 안 나가고 한도 줄을 안 쓴다, 서버 조회 부하는 `risk_read` 로 센다), `fresh=true` 는 **낮은 우선순위**(`CallBudget.share` — 소스의 하루 · 이번 달 한도의 50% 까지만, 차감하는 같은 SQL 안에서 비교해 동시 호출도 못 넘는다 · DB 를 못 읽으면 안 부른다) · 3항목까지 · `risk_check` 로 센다.
- **이동 판정** — 이동 판정기를 직접. 결과에 근거 등급과 판정 근거(시간표 판 · 낡았는지) · 확인 시각. ★등급은 **고른 경로**로 가른다(대중교통 = `timetable`, 도보 · 택시 = `estimate` — 시간표가 아니다). 판정기가 꺼져 있으면 직선 어림만, 예외를 던지면 `unavailable`, 갈 방법이 없다고 하면 이유 그대로. 서울 밖은 판정 안 함. 출발 시각은 도착 목표를 +90/180/360분으로 넓혀 찾는다. 바깥 **유료** 소스(Places · Route Matrix)로 가는 길 없음(코드 확인 — 자체 길찾기 서버 GraphHopper 호출은 있다).
- 남용 방어 세는 작업 셋 추가(`risk_check` · `risk_read` · `move_judge`) · 설정 `travel.mcp.risk_check.*` · 이동 팀 끼움 자리(`team_hooks.legs`)에 선택 인자 `basis` 추가(옛 호출 모양 그대로 동작).
- 코덱스 + 검토 에이전트 교차 검토를 반영했다: 낮은 우선순위를 「읽고 나서 차감」(경쟁 상태 · 월 한도 무시)에서 **한 SQL 안의 몫**으로 · fresh 는 DB 오류 시 거절 · 이동 등급(고른 경로 기준 — 버스도 어림) · 판정기 예외 · 출발 시각 탐색 범위와 폴백 표시 · 못 판정(`undetermined`) · 점검 응답에서 빠진 종류와 일부만 답한 소스 · **먼 일정의 지금-상태 종류는 확인 불가** · 진행 중 항목은 지금 기준 점검 · 이유 문구 고정(환경변수 · 주소가 안 샘) · 캐시 읽기 횟수 · 동시 처리 상한 · fresh 점검기가 없으면 조용히 대신하지 않고 503.
  `[한계로 남긴 것]` 몫은 DB 로 세는 소스에만 걸리고 감시 사용량이 50% 를 넘으면 겹친다 · 캐시 부재와 소스 실패를 가르지 못한다 · 부하 시험 안 함.
- 시험: 신규 60건(e2e 17 · 단위 37 · DB 몫 6) + 기존 MCP 시험 · 남용 방어 · 구조 · 계약 · 보안 묶음 통과. 로컬 개발 DB — 점검 · 판정기는 흉내, **실제 소스 · 실제 시간표 · x600 서버 확인 안 함**. 캐시 적중 비율(감시와 키가 겹치는 정도)은 재지 않았다.

## 2026-10-06 — 로딩 중 질문: 질문 묶음 버전 · 문항 번호와 슬롯 분리 · 답 이력 (맞춤 질문 의논 §7, 화면 세션 요청)

화면(uiux) 세션이 「로딩에서 계획을 본 모델이 맞춤 질문을 만드는 방향」(하이브리드, 코덱스와 의논)을 정하며 서버가 **지금** 지켜야 할 것을 요청했다 — 나중에 갈아 끼우기만 하면 되도록.
- 문항 번호(`Question.id`)와 슬롯(`Question.slot`)을 **다른 칸**으로 나누고 선택지 번호 ↔ 값 매핑(`Option.value`)을 서버가 소유한다(웹은 `questions[]` 만 그리고 슬롯 · 값을 모른다). 질문 묶음에 버전(`QUESTION_SET_VERSION = "1"`)을 두고 접수 조회와 저장 응답의 `questions_version` 으로 내린다.
- 저장할 때 그때의 묶음 버전 · 문구 · 라벨 · 슬롯 · 해석한 값을 **추가만 하는 답 이력**(`trip_intake_survey_answers`, 마이그레이션 053)에 남기고, 등록 때는 **저장 때 해석한 값**으로 설문을 만든다 — 묶음이 바뀌어도 옛 답이 새 매핑으로 잘못 읽히지 않는다.
- 하지 않은 것: 자유 선택지 · 자유 답변 · 추정값 덮어쓰기 · 로딩 경로 모델 호출 · 프로필 `source`/`scope`/가설 설계(질문 생성 모델 · 제한 시간 · 외부 전송 정책 · 슬롯 목록이 먼저 — 서버 · RAG 몫이거나 사용자 결정).
- 시험: 설문 질문 e2e 24건(6건 추가) + 마이그레이션 재실행 · 접수 · 구조 · 계약 묶음 통과. 로컬 개발 DB — 실서버(x600 서버의 cs 프로젝트 서버) 확인 안 함, 마이그레이션 053 반영 필요.

## 2026-10-06 — 항로 지킴이(켜기 · 끄기 · 알림) · 로딩 중 질문 서버 몫

설문 방식 결정 세션(uiux)이 목업 v9 를 바탕으로 넘긴 **cs 프로젝트 서버 몫**을 만들었다(웹은 이 경로를 이 모양으로 부르도록 설계돼 있다).
- **항로 지킴이**(일정이 꼬이면 알아서 고치는 모드) `POST /v1/web/trips/{id}/guardian` — 쿠키 세션만 · 켜기 = `replace` / 끄기 = `ask_first` **명시** · 누가 · 언제 · 어디서를 추가만 하는 표에 남김(마이그레이션 050) · 여행 조회에 `guardian{enabled, since, via}` · 알림에 `guardian`(켜 둔 사용자에게 「바꿨어요」 · 꺼 둔 사용자에게 「켜기」 링크). ★건너뛰기는 값을 안 보내는 것이 아니라 `ask_first` 를 보낸다.
- **로딩 중 질문** 접수 조회의 `questions[]`(쓰는 문항 둘 — 이동 · 대체 우선순위) + `POST …/trip-intakes/{id}/survey`(한 문항씩 저장 · **같은 문항은 덮어씀** · 마이그레이션 051) — 등록할 때 설문에 합쳐진다.
- 시험 `test_trip_guardian.py` 25건 · `test_intake_survey_questions.py` 18건 + 기존 묶음 통과. **로컬 개발 DB 에서 한 시험이다 — x600 서버 반영 · 실서버 확인은 안 했다.** 계약 [rest-endpoints.md](external/rest-endpoints.md) 「설문 질문」 · 「항로 지킴이」 · [migrations.md](data/migrations.md) 050 · 051.

## 2026-09-01 (2) — 역방향 표식 완료. 양방향 잠김

cs 프로젝트가 테스트에 `# invariant:` 표식을 넣었다.

```python
# invariant: INV-CS-ARCH-001
def test_basement_layers_do_not_know_the_business_domain(): ...
```

`[실측]` 검사기 대조 결과.

| | 값 |
|---|---|
| 코드 표식 | **48개** |
| 문서 불변식 | 51개 |
| 코드에만 있는 ID | **0개** |
| 문서에만 있는 ID | 3개 |

**문서에만 있는 3개는 정상이다.** `INV-CS-TEAM-003·004·005`는 판정이 `review`라 대응 테스트가 없다.

### 이제 무엇이 잠겼나

```
문서 → 테스트   경로와 함수 실재를 검사기가 확인   117개
테스트 → 문서   표식 ID 가 카탈로그에 있는지 확인   48개
```

**한쪽만 고치면 CI가 잡는다.** 테스트를 지우면 문서가 가리키는 곳이 사라지고, 표식만 남기면 카탈로그에 없는 ID가 된다.

### 남은 것

`[미확보]` **Team 경계 3개의 자동화.** import 검사로 가능해 보인다.

```
INV-CS-TEAM-003  side effect 를 실행하지 않는다
INV-CS-TEAM-004  read 도구를 직접 호출하지 않는다
INV-CS-TEAM-005  다른 Team 을 직접 호출하지 않는다
```

`tests/architecture/test_basement_is_domain_free.py`가 이미 import 검사를 하므로 같은 방식을 쓸 수 있다.

**자동화되면 사람 판정이 3개 → 0개가 된다.**
