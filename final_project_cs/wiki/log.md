# cs wiki 변경 기록

## 2026-10-13 — 숙소 아침 이동 · 고를 때 가격 재확인 · SerpApi 월 250회 예산

묵는 날 아침 「숙소 → 그날 첫 일정」 이동을 등록 때 만들고(출발지는 그날 묵는 숙소 — `from_stay`), 일정 화면이 「○○에서 출발」 띠 아래에 그린다. 화면에서 숙소 후보를 고르기 전에 1박 값을 다시 본다(마이리얼트립 · 구글 호텔). SerpApi(구글 호텔 · 구글 항공권 한 계정)는 월 250 · 하루 8 을 DB 로 센다. 근거: [2026-10-13 숙소 아침 이동 · 재확인 · SerpApi 예산](records/reports/2026-10-13_숙소아침이동_재확인_SerpApi예산.md).

## 2026-10-13 — 숙소 항목 B안: 한 항목 = 한 숙박

체크인부터 체크아웃까지를 숙소 항목 하나로 받는다(사용자 결정). 등록 검사는 숙소를 앞뒤 일정 겹침에서 빼고, 이동 계산은 숙소를 체크인 시각에 떠나는 곳으로 본다. 접수는 「체크인」 줄과 뒤의 「체크아웃」 줄을 묶고, 일정 화면은 묵는 날마다 「○○에서 출발」 띠와 체크아웃 줄을 그린다. 아침 「숙소 → 첫 일정」 이동은 아직 없다. 근거: [2026-10-13 숙소 항목 B안 반영](records/reports/2026-10-13_숙소항목_B안_반영.md).

## 2026-10-13 — 숙소 · 항공 팀 등록 · 「다른 후보」가 일정 판을 올리지 않게

팀 `role-lodging` 의 숙소 · 항공 확장 에이전트를 role-manager 에 붙였다(develop 위에 얹은 몫만). 받은 판은 「바꿔 줘」마다 후보를 일정 항목에 실어 판이 오르고 「일정이 바뀌었어요」가 나갔다 — 식당 · 활동처럼 「선택이 필요해요」 제안으로 바꿨고, 고른 숙소는 숙소 원장이 그 여행 전용 장소로 들여놓아 지도 핀이 생긴다. 일정에 숙소 · 항공 항목을 만드는 웹 입구는 아직 없다. 근거: [2026-10-13 숙소 · 항공 role-manager 반영](records/reports/2026-10-13_숙소항공_role-manager_반영.md).

## 2026-10-13 — 활동 판정 LLM 호출 예산을 DB 로 센다(격리 사본)

판정 LLM 을 켜면 원문 해석 · 웹 검색 호출을 `external_call_budget` 의 두 줄(`activity_judge` · `activity_judge_web`)로 센다(활동 코어 전달 사항 7번). 상한은 `guardrails.yaml travel.activity_judge.budget`(웹 50/일 · 1,000/월). 전에는 웹 검색만 프로세스 안에서 세서 재기동하면 0 부터였다. 격리 시험 DB 에서 웹 51번째 호출이 막히고, 예산 객체를 새로 만들어도(재기동과 같은 상황) 막힌 채인 것을 확인했다. 같이: 대체 후보 순서 프롬프트를 등록 허용 목록에 넣고, 판정 어댑터가 호출마다 모델을 받게 했다(11번 — 활동 쪽이 아직 모델을 넘기지 않아 지금은 설정 모델 그대로).

## 2026-09-01 (2) — 역방향 표식 완료. 양방향 잠김

cs 프로젝트가 테스트에 `# invariant:` 표식을 넣었다.

```python
# invariant: INV-CS-ARCH-001
def test_basement_layers_do_not_know_the_business_domain(): ...
```

`[실측]` 검사기 대조 결과.

| | 값 |
|---|---|
| 코드 표식 | **48개** |
| 문서 불변식 | 51개 |
| 코드에만 있는 ID | **0개** |
| 문서에만 있는 ID | 3개 |

**문서에만 있는 3개는 정상이다.** `INV-CS-TEAM-003·004·005`는 판정이 `review`라 대응 테스트가 없다.

### 이제 무엇이 잠겼나

```
문서 → 테스트   경로와 함수 실재를 검사기가 확인   117개
테스트 → 문서   표식 ID 가 카탈로그에 있는지 확인   48개
```

**한쪽만 고치면 CI가 잡는다.** 테스트를 지우면 문서가 가리키는 곳이 사라지고, 표식만 남기면 카탈로그에 없는 ID가 된다.

### 남은 것

`[미확보]` **Team 경계 3개의 자동화.** import 검사로 가능해 보인다.

```
INV-CS-TEAM-003  side effect 를 실행하지 않는다
INV-CS-TEAM-004  read 도구를 직접 호출하지 않는다
INV-CS-TEAM-005  다른 Team 을 직접 호출하지 않는다
```

`tests/architecture/test_basement_is_domain_free.py`가 이미 import 검사를 하므로 같은 방식을 쓸 수 있다.

**자동화되면 사람 판정이 3개 → 0개가 된다.**
