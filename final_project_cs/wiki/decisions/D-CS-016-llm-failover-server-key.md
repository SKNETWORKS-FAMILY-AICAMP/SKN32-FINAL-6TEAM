# D-CS-016 — 모델 서버가 모두 안 되면 서버용 OpenAI 키로 자동 전환한다

`[2026-10-07 사용자 지시]` 「올라마나 외부 GPU 서버가 모두 장애면 서버키(개인키 말고)로 자동 전환돼서 동작하게 해」 — 같은 날 발표 자료 담당 세션도 「모델 서버 한 대가 죽으면 서비스 전체가 멈추는 단일 장애점」이라고 짚었다.

## 무엇이 문제였나

채팅의 할 일 고르기 · 계획 읽기 · 알림 번역 · 분류 · 규정 검색이 모두 한 대의 Ollama(x600 서버의 GPU)에 기댔다. 그 서버가 멈추면 이 기능들이 한꺼번에 「모름」으로 끝났다. 이 제품에는 사람 상담원이 고객 문제를 대신 고치는 길이 없어(D-CS-014) 고객이 보는 것은 「이해하지 못했어요」뿐이다.

## 결정

1. **경로는 Ollama(들) → OpenAI(서버용 키) 순이다.** 연결 실패 · 시간 초과 · 5xx · 429 · 빈 답이면 그 호출만 다음 경로로 넘긴다. 연속 3번 실패하면 60초 동안 그 서버를 건너뛰고 한 호출씩만 시험해 돌아온다.
2. **키는 서버용 하나뿐이다.** 개인 키로 대신하지 않는다(`INV-CS-SEC-012` · `-015`). 키 값은 오류 · 로그에 싣지 않는다(`INV-CS-SEC-013`).
3. **스위치는 기본 꺼짐이다** — 켜는 곳은 배포(운영) 환경 파일뿐. 개발 PC 에서 연결이 끊겼을 때 시험 · 측정이 조용히 유료 API 로 새고, 어느 모델의 값인지 섞이는 것을 막는다.
4. **사진 · 스캔 이미지는 기본으로 안 넘긴다** — 이름 · 예약번호를 가릴 수 없다(`INV-CS-SEC-014`). 텍스트는 `redaction.masked` 로 한 번 더 가린다.
5. **호출 상한**: API 로 넘긴 호출을 하루 2,000 · 한 달 30,000 번으로 센다. 넘으면 더 부르지 않고 실패로 올린다. 한도 표를 못 읽으면 서비스를 살리는 쪽(부른다)이고 경고를 남긴다.
6. **기본 모델 `gpt-4.1`** — 결정 단위 재생(실제 대화 66문장, 한 번씩)의 실측: `gpt-4.1` 64/66 = Gemma 4 12B 와 같은 97.0%, `gpt-4.1-mini` 55, `gpt-4o-mini` 52(엉뚱한 대상 변경 1건). 작은 모델은 이름으로 일정을 못 짚거나 엉뚱한 일정을 바꿨다.
7. **넘긴 답도 같은 검증을 거친다** — 목록 밖 번호 거부 · 분류 라벨 검사 · 번역 숫자 · 단위 대조는 모델이 달라도 그대로 돈다.

후속 `[2026-10-08 사용자 지정]` 공개 배포의 모델은 `gpt-6-luna` 로 정했고 운영 환경에 반영했다 — 이 문서의 `gpt-4.1` 은 코드 기본값이고 운영 값은 환경 파일이 정한다. 반영 기록은 [Luna 자동 전환 운영 반영](../records/reports/2026-10-08_2245_Luna_자동전환_운영반영.md).

## 버린 안

| 안 | 버린 까닭 |
|---|---|
| 개인 키로 넘긴다 | 지시가 「서버키(개인키 말고)」다. 개인 키는 개발 PC 의 것이라 배포 서버가 의존할 수 없다 |
| 항상 켠다(스위치 없음) | 개발 중 측정이 조용히 OpenAI 로 섞이고 요금이 샌다. 평소 모델 정확도를 잰 값이 무효가 된다 |
| 작은 모델(`gpt-4o-mini`)로 넘긴다 | 같은 재생에서 52/66 · 엉뚱한 대상 변경 1건 — 장애 중에 일정을 잘못 바꾸는 쪽이 더 나쁘다 |
| 이미지도 넘긴다 | 사진 속 이름 · 예약번호를 가릴 수 없다. 텍스트만 넘기는 쪽이 기본이다 |
