# D-CS-009 낮에 생기는 임시휴무는 시스템이 찾는다

`[결정 2026-09-29 사용자]` 「낮에 임시휴무 하는 경우는 시스템 구현 해야 할 부분」.

## 무엇이 바뀌나

| | 전 (팀 결정 2026-09-24) | 지금 |
|---|---|---|
| 새벽(03:00~08:00) | 구글로 그날 식사·활동이 **계획한 시각에 여는지** 한 번 확인 → 닫혔으면 근처로 교체 | 그대로 |
| 낮 | **고객 신고로만** 받는다(「문 닫았어요」 → 걸어갈 수 있는 대체 식당) | ★**시스템이 방문 전에 확인해 대체까지 한다 — 구현 대상** |

예: 12:00 점심 식당이 11:00 에 「오늘 임시휴무」를 올리면, 지금은 고객이 가게 앞에 가서야 안다.
이 결정 뒤에는 방문 전 확인이 그것을 잡아 같은 시각 근처 식당으로 바꾸고 알린다.

## 현재 채택 정책 — 2026-10-11 W09 A안

[사용자 확정] 낮에는 사용 가능한 무료 자료를 우선 사용하고, 영업 상태를 확인하지 못하면 정상 영업으로 단정하지 않고 검증 불가로 표시합니다. 구글 새벽 배치 제한은 [D-CS-010](D-CS-010-google-calls-in-dawn-batch-only.md)을 유지합니다. 자료가 확보되면 기존 일정·고객 설정으로 재검증합니다. 실패 정책은 [D-018](../../../wiki/decisions/D-018-decision15-stop-paths.md)을 따릅니다.

## 운영자 웹 앱 설정 요구·미구현 범위

운영 설정의 **장소 영업 상태 확인**에서 무료 자료 우선 정책·낮 유료 조회 허용 여부·호출 예산·방문 전 확인 주기를 변경할 수 있게 합니다. 이는 개발·QA의 정책 설정 기능이며 고객 대신 문제를 직접 고치는 상주 상담원 기능이 아닙니다. 유료 조회 스위치로 D-CS-010의 구글 호출 제한을 우회하지 않습니다.

설정 저장은 권한·변경 이유·이전 값·설정 판본을 검사·기록하고 실제 조회 작업이 저장값을 읽어야 합니다. 기존 운영 설정 화면의 존재만으로 이 기능을 완료 처리하지 않습니다. [미확보] 이 설정의 화면·저장 경로·자료 어댑터 연결·권한/비용/복구 인수 시험은 아직 완료 근거가 없습니다. 사용 가능한 무료 자료별 실제 낮 휴무 검출 범위도 검증 대상입니다.

예: 방문 전 자료를 확인할 수 없으면 해당 식당을 정상 영업으로 표시하지 않습니다. 대체 자료도 실패하면 의존하는 변경을 보류하고 고객에게 상태·확인 시각을 안내합니다.

## 이미 되는 것 (2026-09-29)

- 낮 감시(1분마다 · 90분 앞)가 **재난문자·통제·지진**으로 식사 항목이 깨졌다고 보면 식당 Team 이 근처 식당으로 바꾼다
  (`plan_dining_disrupted`, 시험 `tests/scenario/test_case_watch_dining.py`). 휴무는 이 점검이 보지 않는다.
