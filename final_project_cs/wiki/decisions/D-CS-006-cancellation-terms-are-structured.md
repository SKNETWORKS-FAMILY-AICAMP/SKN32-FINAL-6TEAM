# D-CS-006 취소 조건은 **구조화해서** 둔다

`[결정 2026-09-23]` 사용자가 「ㄱㄱ」로 이어 진행하라 해서 **내가 골랐다.**
앞서 세 갈래를 적어 두고 「결정이 나기 전에는 고치지 않는다」로 남겨 뒀던 자리다
([그 기록](../records/reports/debugs/2026-09-22_정책청크에서_수치를_못_꺼낸다.md) §6).

## 무엇이 문제였나

`activity.check_cancelable` 이 취소 기한·위약금율을 **`read.policy` 가 준 RAG 청크에서**
꺼내려 했다.

```python
for chunk in policy if isinstance(policy, list) else []:
    if isinstance(chunk, dict) and chunk.get(key) is not None:   # ← dict 를 본다
```

RAG 가 주는 것은 `PolicyChunk` 라 `isinstance(chunk, dict)` 가 **항상 거짓**이다. 즉 어떤
코퍼스를 넣어도 두 값이 언제나 `None` 이었고, 제품이 약속한 **「지금 취소하면 얼마인가」가
한 번도 답해진 적이 없다.**

★**시험이 그것을 가렸다.** `check_cancelable` 갈래에는 시험이 **0건**이었고(2026-09-23
실측), 다른 시험의 픽스처는 `read.policy` 를 `[{"cancel_deadline_hours": 24}]` 라는
**dict 목록**으로 줬다. 실제 도구가 주는 모양과 달라서, 시험은 초록인데 운영은 안 됐다.

## 고른 것과 버린 것

| | 안 | 왜 |
|---|---|---|
| ★**골랐다** | ① 구조화 정책을 따로 둔다 | 수치는 표가, 문장 근거는 RAG 가 댄다. **판정은 코드**라는 원칙이 그대로 선다 |
| 버렸다 | ② `PolicyChunk` 에 `attributes` 칸을 더한다 | 계약 변경이 Context Broker·Evidence 까지 번진다. 수치 두 개 때문에 코어 계약을 건드린다 |
| 버렸다 | ③ 산문에서 LLM 이 뽑는다 | **판정에 생성이 끼어든다.** 위약금율은 고객 돈이다 — 모델이 한 자리 틀리면 우리가 그 차액을 물거나 고객이 문다 |

## 어디에 두나 — **전역 규정이 아니라 「이 예약의 조건」이다**

같은 테넌트 안에서도 업체마다 다르고 상품마다 다르다. 그래서 설정 한 줄이 아니라
**범위를 가진 표**다(마이그레이션 023 `cancellation_terms`).

    찾는 순서:  ① 그 예약(booking) → ② 그 공급자(supplier) → ③ 그 종류(kind)

v11 **결정 15**(「값마다 대체 소스를 두고, 대체까지 안 되면 모름」)를 데이터로 구현한 것이다.
셋 다 없으면 `None`(모름)이고, 모름이면 **금액을 만들지 않는다.**

## 함께 정한 것

- **`source` 는 의무다.** 「어디서 온 값인가」가 없으면 시연용 Mock 과 실제 업체 약관이 섞이고,
  섞이는 순간 고객에게 지어낸 금액을 말하게 된다. 시드는 `seed:mock — 시연용이다. 실제 업체
  약관이 아니다` 로 적는다.
- **여러 구간에 걸리면 가장 센 율**을 고른다. 적게 받았다가 더 받으면 우리가 말을 바꾸는 것이 된다.
- **청크를 넘기면 `TypeError` 로 죽는다.** 전에는 조용히 `None` 이라 몇 달이 갔다 —
  모양이 다르면 그렇게 말한다.

## 이 결정이 **말하지 않는 것**

- 실제 업체 약관을 가져오는 길은 **아직 없다.** 지금 demo 에 깔린 값은 전부 시연용이다.
- 취소를 **실행**하는 것은 별개다 — 공급자 등급(`tier`)과 위임이 그것을 지킨다(D-CS-004 계열).
- 다른 Team(Dining·Mobility·Booking Handoff)은 아직 이 표를 안 읽는다. 읽어야 하는지는
  그 Team 의 판정이 수치를 쓰는지에 달렸고, **지금은 안 쓴다**(2026-09-23 실측).
