## 무엇인가

사람(규칙 · 프롬프트를 보지 않은 팀원)이 **고객 문장만** 쓰게 하는 카드다. 상황을 카드가 정하므로 정답은 카드를 만들 때 정해지고, 2인 검수는 불일치 확인 위주로 가볍게 끝난다.

| 파일 | 내용 | 누가 보나 |
|---|---|---|

| `bind_candidates.py` | LLM 카드에 운영 코드로 실제 후보 3곳을 붙인다(활동 원장 읽기만) | 개발 |

## LLM 카드 후보 결합 — `bind_candidates.py` (2026-10-16 실행, 로컬 DB)

★`[2026-10-16 사용자 결정]` 운영 후보 경로가 활동 원장(`activity.ac_place`)만 읽도록 바뀐 뒤 다시 붙였다(전에는 `place_catalog`). 결합 결과(58/60)는 같고, 표본 원래 장소는 원장에서 다시 뽑아 252 → 253곳이 됐다.

실행: `final_project_cs` 에서 `PYTHONPATH=. python eval/situation_cards/bind_candidates.py` → `cards_llm_bound_v0.jsonl`

| 단계 | 결과 |
|---|---|
| 1차 — 카드에 적힌 장소 그대로 | 29/60 = 48% |
| 2차 — 실패 카드만 원래 장소를 표본(300곳 중 풀이 있는 253곳)에서 다시 고름 | **58/60 = 97%** (실패 L-36 · L-44) |
| 다시 고른 카드 | 29장 — 상황 문장의 장소 · 사유가 바뀌었다(`origin_rebound_from`), `needs_review` 표시 |
| 쓴 선호도(설문 `priority`) | mobility 34 · 없음 20 · activity 4 |

**★발견 — 설문 무응답이면 LLM 순서가 바꿀 근거가 거의 없다.** 표본 원래 장소 253곳에서 선호도 None(설문 무응답)일 때
화면 3곳의 속성 초안이 서로 다른 곳은 **5/253 = 2%** 였다. 운영 코드가 후보를 원래 장소와 **같은 분류**에서 뽑기 때문이다.
그래서 「궁궐 대신 체험」 같은 다른 성질의 바람은 후보 3곳 안에 답이 없다. 다시 고른 카드 대부분은 설문 `priority=mobility`
(거리 우선 · 분류를 푼다)로 후보가 섞인 경우다.
- 단, 속성은 **분류 기준 초안**이다 — 같은 분류 안의 차이(아이 동반 · 덜 걷기 등)는 세지 않았다. 2% 는 하한에 가까운 대략치다.
- **평가 해석**: 이 카드 묶음은 「후보가 섞였을 때 LLM 이 맞게 고르는가」를 잰다. 실제 서비스에서 그런 상황이 얼마나 나오는지는
  별도 지표(취향 반영 가능 비율)로 따로 적어야 한다 — 카드 결과를 서비스 전체 효과로 읽지 않는다.

**후보 품질 주의**: 거리 우선(mobility)에서 브랜드 매장 · 생활 시설이 대체 활동으로 나온다 — 결합된 174곳 중 13곳
(다이소 · 올리브영 · 성형외과의원 등), 이런 후보가 든 카드 9장. 운영 코드의 결과 그대로라 카드에 남겼고, 라벨러가 판단한다.
활동 팀 쪽에서 후보 범위(생활 시설 제외)를 따로 검토할 거리다.
