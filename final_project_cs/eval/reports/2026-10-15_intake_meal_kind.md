# 접수 읽기 — 장소마다 식사인가 활동인가: 규칙 · 규칙+LLM · LLM 비교, 그리고 규칙에 「먹는다」 말 더하기

- 날짜: 2026-10-15 · 브랜치 `role-dining`(커밋 전)
- 자료: dev [`intake_meal_kind_v1.jsonl`](../datasets/intake_meal_kind_v1.jsonl) 문장 32 · 장소 37 / holdout [`intake_meal_kind_holdout_v1.jsonl`](../datasets/intake_meal_kind_holdout_v1.jsonl) 문장 12 · 장소 14 — 정답은 사람이 적었다(작성자 1명, 소규모)
- 러너: [`eval/runners/intake_meal_kind.py`](../runners/intake_meal_kind.py) · 모델 gpt-4o-mini(온도 0, 3회 반복 — 사용자 결정: Ollama 는 느려 OpenAI 로만) · 비용 약 $0.007
- 원본: [dev JSON](2026-10-15_intake_meal_kind_dev.json) · [holdout JSON](2026-10-15_intake_meal_kind_holdout.json)

## 1. 왜

테스트 서버 접수(cbd50b1d)에서 「오후엔 서촌 골목 좀 걷다가」가 「서촌닭갈비」가 되고 18:00 식사가 됐다. 식사인지 활동인지는 규칙(끼니 말)만 정하고 있어
「뭐 좀 먹고」 · 「맛집」 · 「한잔」 같은 말은 못 잡는다. 세 방식을 같은 자료 · 같은 모델 응답으로 비교했다(장소 위치는 정답으로 준다 — 종류 판정만 잰다).

| 방식 | 판정 |
|---|---|
| rule | 그 장소 원문 구간의 끼니 말(`rules.meal_mention`) |
| rule_llm | rule 이 식사라고 하거나, 모델이 식사라고 하며 **그 장소 구간 안** 조각을 원문 그대로 인용 |
| llm | 모델 판정만(인용이 원문에 없으면 활동) |

## 2. 결과 — 처음(규칙은 끼니 말만)

| 방식 | dev | holdout | 활동→식사 오판 | 식사 놓침 |
|---|---|---|---|---|
| rule | 24/37 = 65% | 9/14 = 64% | 1 · 0 | 12 · 5 |
| rule_llm | 34/37 = 92% (한 번 33) | 13/14 = 93% | 1 · 0 | 2~3 · 1 |
| llm | 33/37 = 89% (한 번 32) | 13/14 = 93% | 0 · 0 | 4~5 · 1 |

규칙만으로는 「먹는다」 말 0/7. LLM 을 쓰면 dev · holdout 모두 약 90%.

## 3. 결정 (가) — LLM 호출을 늘리지 않고 규칙에 「먹는다」 말을 더한다

이유: 시각 있는 줄은 규칙이 읽어 **모델에 가지 않는다**(「12:00 통인시장에서 뭐 좀 먹고」 → 활동이었다). 서버 모델(gemma)은 느리다.

- `rules.eat_mention` · `_EAT` — 먹고 · 먹자 · 먹기 … · 마시고 · 드시 · 식사 · 밥 · 맛집 · 한 끼 · 한잔 · 요기 · 브런치 · 카페 · 커피. **장소 이름 뒤**에 있을 때만, 뒤가 「나서 · 나와서 · 후 · 뒤 · 다음」이면 앞선 식사로 보고 세지 않는다. 「카페거리」 · 「커피박물관」은 아니다.
- 시각 없는 줄(`llm_spans._line_items`) · 시각 있는 줄(`rules` 의 규칙 읽기 두 곳) 모두 같은 규칙. 제목 안에서 찾으면 그 앞까지가 이름이다(「13:00 익선동 맛집」 → 「익선동」 + 식사).
- 시험: [`tests/unit/travel/test_intake_eat_words.py`](../../tests/unit/travel/test_intake_eat_words.py) 19건.

## 4. 결과 — 규칙에 「먹는다」 말을 더한 뒤(모델 응답은 2 의 것을 그대로 다시 채점 — 추가 호출 없음)

| 방식 | dev | holdout | 활동→식사 오판 | 식사 놓침 |
|---|---|---|---|---|
| rule | **33/37 = 89%** | **13/14 = 93%** | 1 · 0 | 3 · 1 |
| rule_llm | 34~35/37 = 92~95% | 13/14 = 93% | 1 · 0 | 1~2 · 1 |
| llm | 32~33/37 | 13/14 | 0 · 0 | 4~5 · 1 |

★주의: 「먹는다」 낱말 목록은 dev 문장을 보며 만들었다 — dev 숫자는 낙관적이다. holdout 은 처음 비교 때 한 번 봤고, 규칙을 만들 때는 보지 않았다(9 → 13/14). 새 미노출 holdout 은 남은 일이다.

남은 오판: 「저녁에 청계천 야경」(규칙이 「저녁에」를 끼니로 봄 — 「저녁엔 광장시장 가 보고 싶어」와 모양이 같아 규칙만으로 못 가른다) · 가게 이름만 적은 「토속촌삼계탕 가 보고」 · 「블루보틀 성수점 들렀다가」 · 「하동관 가 보고 싶어요」(규칙 · LLM 모두 놓침 — 장소 찾기가 원문과 같은 이름의 가게를 찾으면 식사로 보는 길이 따로 있다).

## 5. 확인하지 못한 것

- 서버 모델(gemma) 결과 · 실제 접수 호출 모양(줄 번호 + 조각 역할)의 LLM 결과 — 이번 LLM 숫자는 장소 목록을 주고 묻는 별도 프롬프트다.
- DB 가 필요한 e2e(로컬 PostgreSQL 꺼짐).
