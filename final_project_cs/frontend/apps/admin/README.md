# triPilot 운영자 콘솔

최신 확인: 2026-09-29 · 기준 `role-eval-ui` `38cd59d` + 이번 프론트 변경. [화면 기획](SCREEN_PLAN.md)과 와이어프레임 v1.2를 바탕으로 구현한 **프론트엔드 데모**다. 실제 운영 API·로그인·DB 저장은 연결하지 않았다. 팀의 정책 합의와 백엔드 통합 검증도 별도다.

운영 홈·사용자 목록/상세·한도/감시·사용량·서버 상태·문의함·공지/점검·운영 기록·임시 승인/위임/발송 확인, 로그인까지 11개 화면을 제공한다. Case·Trace·개발 로그는 개발자 콘솔의 범위다.

**백엔드 담당자·에이전트는 [운영 앱 API 협의](../../../wiki/external/admin-screen-api.md)부터 읽는다.** 다음 단계는 화면과 기존 백엔드를 대조해 API 계약을 먼저 합의하는 것이다. 읽을 자료, 계약 초안에 포함할 항목, 미정 정책, 화면별 연결 상태를 그 문서에서 관리한다.

## 앱 실행

Node.js 22와 npm을 사용한다. 이 폴더에서 PowerShell로 실행한다.

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

주소: **http://127.0.0.1:3300/login**. 개발·프로덕션 서버 모두 루프백에만 연다.

`NEXT_PUBLIC_ADMIN_DATA_MODE=demo`를 **명시**해야 동작한다. 누락·빈 값·다른 값이면 「연결 미설정」을 표시한다. 설정 변경 후 개발 서버를 다시 시작하거나 다시 빌드한다. `.env.local`은 Git 제외다. 이 앱에는 실제 서버 주소나 백엔드 키를 넣지 않는다.

## 팀원에게 한 파일로 보여주기

**[운영 시나리오 HTML](mockups/admin-scenario.html)** 파일 하나를 전달해 브라우저에서 연다. Node.js·서버·인터넷 연결이 필요 없다. HTML에는 앱과 같은 React 화면·CSS·데모 어댑터를 번들로 포함한다. 외부 폰트·CDN·API 요청은 없고 HTML 보안 정책도 네트워크 연결을 막는다.

1. 「데모로 들어가기 — 인증하지 않음」을 누른다.
2. 「시연 가이드」를 열어 **한도 문의 → 예외 한도 → 답변 → 공지 → 발송 확인 → 운영 기록**을 따라간다.
3. 직접 메뉴를 옮기며 검색·필터·설정·승인·위임을 체험할 수도 있다.
4. 상단 「화면 상태」에서 정상·불러오는 중·빈 목록·실패를 고른다.
5. 「데모 초기화」로 모든 변경을 되돌린다. 새로고침하거나 파일을 다시 열어도 초기 상태로 돌아간다.

실제 계정이나 비밀번호는 필요 없다. 시연 운영자는 `demo.operator`이며, 모든 수치는 가상 운영일 **2026-09-29**의 예시다. 업무 데이터는 메모리에만 있으며 파일·브라우저 저장소·서버에 저장하지 않는다. 단일 HTML은 hash 경로, 실행 앱은 일반 URL을 사용한다.

## 검증과 HTML 재생성

```powershell
npm run check                  # lint + typecheck + unit + build
npm run build:demo             # demo를 명시해 브라우저 시험용 빌드
npm run export:html            # 앱 소스로 단일 HTML 재생성
npx playwright install chromium # 최초 브라우저 설치 시
npm run test:e2e               # 3301 · 앱 + file:// 오프라인 시나리오
npm run test:unconfigured      # 3302 · 미설정 모드 별도 빌드/브라우저 시험
```

설치된 Chrome으로 시험하려면 `$env:PLAYWRIGHT_CHANNEL='chrome'`를 설정한다. 이 작업의 실제 검증 브라우저는 Chrome이다. `npm run build`는 현재 설정을 사용하며, 데모를 자동으로 켜지 않는다. 단일 HTML은 `export:html` 명령 자체가 명시적인 데모 생성 요청이다. 소스를 바꿨으면 다시 생성해야 한다.

## 구현 범위와 다음 단계

- 설정·권한 변경은 사유가 없으면 저장하지 않는다. 답변과 공지는 본문을 운영 기록에 남긴다.
- 차단은 사용자 상태로 모의 처리하며 키 폐기·재발급을 구현하지 않는다. 미계측 수치는 0으로 대체하지 않는다.
- 발송 결과 확인은 `unknown` 상태를 유지하고 확인 결론·확인자·근거만 기록한다. 재발송하지 않는다.
- 사용자별 예외 기간·감시 단계·점검 범위 등 기획서의 잠정/미정 항목은 검토용이다. 실제 운영 정책으로 확정한 것이 아니다.
- 실제 연결은 [운영 앱 API 협의](../../../wiki/external/admin-screen-api.md)에서 계약을 맞춘 후 진행한다. [기획서 §7](SCREEN_PLAN.md#7-데이터-출처--다음-단계에서-api-계약으로-만들-목록)은 요구 목록이며, 최신 백엔드와의 차이는 협의 문서에 연결된 조사 보고서를 함께 확인한다. 인증·권한 확인, 서버 중계, 영속 저장, 계측 추가는 이번 구현에 없다.
