# 관리 앱 화면 기획

작성·확인: 2026-10-03 · Codex · `role-eval-ui` `1ec6111` + 이번 프론트 변경.

사용자 지시에 따라 화면과 업무 흐름을 먼저 개선한다. 2026-09-30 [관리 시나리오 목업](mockups/management-scenario.html)의 M-01~M-03을 읽기 중심 데모로 구현하는 범위다. 실제 장애 수집·관리 API는 합의 전이며 이 문서는 백엔드의 동의를 대신하지 않는다. 기존 목업은 제안의 원본으로 보존한다.

## 사용자 흐름과 완료 조건

관리 홈에서 확인할 오류 묶음을 고르고, 참조번호·요청 추적 ID·오류 코드로 검색한 뒤 해당 발생 정보를 확인한다. 상세에서 목록으로 돌아오거나 새로고침해도 URL에 있는 검색 조건을 유지한다. 기존 팀별 테스트·코어 통합·사례 비교는 별도 메뉴로 계속 제공한다.

| 화면 | 목적 | 표시와 동작 |
|---|---|---|
| M-01 관리 홈 `/` | 먼저 살펴볼 문제 선택 | 가상 데이터의 확인 전·미해결 오류 묶음, 오류 목록 진입, 기존 시험 도구 연결 |
| M-02 오류 목록 `/?view=errors` | 원인 묶음 찾기 | 참조번호·trace ID·코드·제목 검색, 상태·심각도·출처 필터, 조건 초기화, 빈 결과 안내 |
| M-03 오류 상세 `/?view=errors&incident=…` | 특정 발생의 근거 확인 | 묶음 정보, 가상 발생 기록, 선택 발생의 참조번호·시각·가린 사용자·여행·Case·trace ID, 가상 스택·원인 후보. 실제 환경·요청 추적은 미연결 안내 |

`incident`는 앱 안의 표시용 식별자이며 HTTP API 경로가 아니다. 조회 조건과 선택 값은 URL에 보존한다. 알 수 없는 묶음·발생 식별자는 명시적으로 안내하고 다른 오류의 상세로 바꾸지 않는다.

## 데이터 표시 경계

- 명시적 `NEXT_PUBLIC_CONSOLE_DATA_MODE=demo`에서만 가상 데이터가 보인다. 미설정은 연결 미설정 상태로 표시한다.
- 가상 운영일은 목업의 2026-10-14다. 실제 오늘의 운영 수치로 표시하지 않는다.
- 집계는 샘플 데이터에서 계산한다. 전체 발생 건수와 상세로 제공하는 예시 건수가 다르면 각각 표시한다.
- 출처 필터는 오류 묶음의 관련 출처를 기준으로 한다. 묶음 대표 출처와 표시된 발생 기록의 출처를 함께 보여 주며, 상시 작업에서 발생한 참조번호가 서버 대표 묶음에 있다는 이유로 검색에서 빠지지 않아야 한다.
- 묶음별 영향 사용자 수를 더해 고유 사용자 수라고 표시하지 않는다. 0명과 미수집을 구분한다.
- 원인 후보·스택·환경은 가상 예시라는 표시를 유지한다. 실제 고객 입력·토큰·키를 넣지 않는다.
- 실제 오류 수집, 상태 변경·담당 배정, 티켓 발행, 운영앱 동기화, 재현·해결 판정은 이번 읽기 화면 범위에 없다. 준비 중인 기능을 성공으로 표시하지 않는다.

## 검증

앱의 `npm run check`와 demo 빌드의 `npm run test:e2e`로 검색·필터 조합, 잘못된 식별자, 목록 복귀·새로고침, 좁은 화면, 기존 테스트 도구의 회귀를 확인한다. 실제 API 통합 검증은 별도로 남긴다. 실행 결과는 [README](README.md)와 연결된 작업 기록을 따른다.
