# 개발팀 콘솔 개발 기준

작성일: 2026-09-21. 범위: 개발·테스트용 프론트엔드와 명시적 샘플 실행. 실제 API 통합·운영자 기능·공용 배포·모델 벤치마크 실행은 포함하지 않는다.

## 기술스택

이용자 웹에서 설치·검증한 버전을 동일하게 사용한다. Next.js 16.3.5 App Router, React 19.3.0, TypeScript 5.9.3 strict, TanStack Query 5.103.1, Zod 4.6.5, CSS Modules, Lucide React. Node.js 22·npm과 앱별 잠금 파일을 사용한다. Vitest·Playwright로 데이터 동작과 브라우저 흐름을 확인한다.

화면의 선택·입력 상태는 React가 관리하고, 실행·사례·비교 데이터는 TanStack Query가 ID별로 관리한다. 별도 전역 상태 라이브러리는 추가하지 않았다. 실행 조회는 샘플 작업이 진행 중일 때만 350ms 간격으로 갱신한다. 실제 SSE가 연결된 상태로 표현하지 않는다.

## 모듈 경계

| 위치 | 책임 |
|---|---|
| `src/app` | URL, 레이아웃, 로딩 경계, 페이지 조합 |
| `src/components/layout` | 콘솔 헤더·메뉴·샘플 모드 표시 |
| `src/components/ui` | 버튼·패널·상태·오류·제목 |
| `src/features/team-tests` | 팀별/코어 공통 입력·실행 화면, 입력 보존 |
| `src/features/runs` | 여러 화면에서 재사용하는 단계별 실행 상세·재실행·사례 저장 |
| `src/features/cases` | 사례 선택, 동일 입력 A/B 비교, 각 실행 상세 연결 |
| `src/features/connections` | 개발 환경 연결 안내 |
| `src/lib/model.ts`, `validation.ts` | 표시 계약과 입력 검증 |
| `src/lib/queries.ts` | 데이터 캐시와 진행 조회 |
| `src/lib/gateway.ts` | 데이터 연결 모드 선택 |
| `src/lib/demo` | 샘플 저장·단계 진행·판정·평가 결과 생성 |
| `src/styles` | 색상·서체·밝은/어두운 화면 토큰 |

사용자 웹을 참조해 색상과 UI 원칙을 맞췄지만, 사용자 웹 파일을 변경하거나 기존 Python 콘솔을 이식하지 않았다. 앱마다 다른 데이터 계약을 억지로 통합하지 않는다. 추후 실제로 함께 사용할 UI가 확정되면 공통 패키지로 추출한다.

## 데이터와 상태

- 화면은 `DevConsoleGateway`만 호출한다. 업무 계산은 화면 컴포넌트에 넣지 않는다. 이번 가상 시나리오 계산은 `lib/demo/scenarios.ts`에 한정한다.
- 실행 버튼을 눌렀을 때 입력 스냅샷과 새 실행 ID를 만든다. 진행 중 입력은 잠기며 이후 입력을 바꿔도 이전 결과가 바뀌지 않는다.
- 재실행은 원본 ID를 `retryOf`로 참조하는 새 실행이다. 기존 오류 기록을 성공 기록으로 덮어쓰지 않는다.
- 실행 완료/실패와 기대 결과 일치/불일치를 구분한다. 실패에는 성공 결과가 없다. 아직 실행되지 않은 단계의 관찰값과 출력은 공개하지 않는다.
- 코어 통합 샘플은 요식업·이동을 같은 구간에서 진행하며, 액티비티가 이동 결과를 받아 조건을 판단한다. 코어는 작업 연결·계약 검증·취합을 담당한다.
- A/B 비교는 선택한 사례의 스냅샷을 보관하고 버전만 변경한 두 실행을 만든다. 사례 선택을 바꿔도 이미 생성한 비교 기록은 변하지 않는다.
- 기록은 세션 저장소에 보관하며 읽기·쓰기·형식 오류를 사용자에게 알린다. 저장 실패를 성공으로 표시하거나 기존 기록을 조용히 초기화하지 않는다.
- 실행 URL, 비교 URL은 같은 브라우저 탭에서 복구된다. 새 탭·공용 보존·팀원 공유는 실제 서버 저장 기능이 필요하다.

## 실제 연동

샘플 A/B, 장소, 도구 응답과 시간 계산을 실제 서비스 규칙이나 실제 모델 성능으로 해석하지 않는다. 실제 구현에서는 코어가 반환한 단계 상태·관측값·기대 결과·출력을 그대로 표시한다. 프론트가 서버 로그를 임의로 해석해 성공이나 점수를 만들지 않는다.

현재는 실제 HTTP 어댑터와 백엔드 테스트 API가 연결되지 않았다. [API_CONTRACT.md](API_CONTRACT.md)에 표시 계약과 담당별 작업을 기록했다. 이 문서는 확정된 기존 백엔드 API 사양이 아니다. API 계약 확정 후 별도 어댑터를 추가하고 통합 검사를 수행한다.

## 검증 기준

린트·타입·단위 검사·배포 빌드와 실제 브라우저 테스트를 통과해야 한다. 핵심 검증은 입력/결과 분리, URL·새로고침 복구, 오류 기록과 재실행, 사례 보존, A/B 입력 일치, 코어 병렬 진행, 잘못된 링크, 모바일 표시다. 실제 서버 연동 완료는 이 검사로 대체하지 않는다.

2026-09-21 기준 린트·TypeScript 검사·프로덕션 빌드 통과. Vitest 42/42(100%), 설치된 Chrome으로 프로덕션 앱을 실행한 Playwright 시나리오 7/7(100%) 통과. 브라우저 검사는 세 팀, 변경된 입력과 이전 결과 구분, 새로고침, 도구 실패·새 ID 재실행·정상 회복, 저장 사례의 A/B 입력 일치와 상세 링크, 코어 병렬 구간, 잘못된 ID, 320px 화면을 포함한다. PC·모바일·밝은/어두운 화면을 시각적으로 확인했다. 실제 Core·에이전트·모델 연결과 공용 배포는 이 기록에 포함하지 않는다.
