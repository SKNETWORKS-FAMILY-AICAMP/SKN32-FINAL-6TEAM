# 관리 앱(개발자 콘솔) 목업

## 백엔드 합의용 단일 HTML

**[management-scenario.html](management-scenario.html)** — 2026-09-30. 이 파일 하나를 브라우저로 연다. 인터넷·서버·설치가 필요 없고, HTML 보안 정책이 외부 요청을 막는다.

- **용도**: 개발자 콘솔을 개발자용 **관리 앱**(문제 대응 + 검증)으로 재기획하면서, 오류 기록에 필요한 백엔드("백엔드 한 겹")를 백엔드 담당과 합의하기 위한 시나리오 목업이다. 실행 앱이 아니다.
- **시나리오**(가상 운영일 2026-10-14): 여행자가 참조번호를 봄 → 운영 콘솔 알림 → 관리 앱 홈 → 참조번호로 오류 검색 → 오류 상세 → 요청 추적 → 연결 점검 → 상시 작업 기록 → 조치(운영 콘솔 상태도 바뀜) → 시험대 재현(2차 미리보기) → 합의 정리. 위쪽 「시나리오 가이드」의 「다음」으로 따라간다.
- **합의 방법**: 화면마다 오른쪽 「백엔드 합의」 패널에 필요한 API·필드·권한과 정할 것이 있다. 항목마다 「합의 · 수정 필요 · 보류」를 누르고, 「합의 정리」 화면에서 회의 메모와 함께 **Markdown으로 복사**해 문서로 옮긴다. 결과는 메모리에만 있어 새로고침하면 지워진다.

| 화면 | 내용 | 차수 |
|---|---|---|
| 사용자 웹 · 운영 콘솔 | 같은 오류가 여행자·운영자에게 보이는 모습 (참조번호 · 코드 · 영향 · 상태) | 다른 앱 |
| M-01 홈 | 확인 전·늘어나는·미해결 오류, 영향 사용자, 연결 신호등, 최근 작업 회차 | 1차 |
| M-02 오류 목록 | 참조번호·trace_id·코드 검색(동작), 원인별 묶음 | 1차 |
| M-03 오류 상세 | 시간별 발생, 발생 목록, 가린 스택·요청 요약·환경, 상태·담당·티켓 | 1차 |
| M-04 요청 추적 | HTTP → Case → LLM 호출 → 오류 → outbox 시간순 | 1차 |
| M-05 상시 작업 기록 | `run_sweepers`·`run_outbox_worker` 회차별 숫자 | 1차 |
| M-06 연결 점검 | API·DB·Ollama·임베딩·외부 API·알림, 기능 스위치 | 1차 |
| M-08 모듈 시험대 | 오류 재현 → 사례 저장 → 회귀 시험 내보내기 → 해결 표시 | 2차 미리보기 |
| M-07 · M-09~M-12 | 자리만 둠 | 2~3차 |

## 보는 법과 한계

- **모든 값은 가상이다.** 참조번호·trace_id·사용자 키 해시·여행·Case ID·서버 판·티켓 번호는 지어낸 값이다. 실제 고객 데이터는 없다.
- **API 경로·필드·권한 이름(`/v1/dev/*`, `/v1/ops/incidents`, `/v1/web/client-errors`, `dev:read`·`dev:write`·`ops:read`)은 모두 합의 전 제안이다.** 지금 백엔드에는 없다.
- **스택의 파일 이름은 실제 코드에서 옮겼지만** 함수 이름·줄 번호는 예시다. 구현 후 실제 값으로 바뀐다.
- 원인 후보로 든 "모델 콜드 스타트 > 타임아웃 60초"는 2026-09-29 로컬 실측(첫 호출 103초)을 바탕으로 만든 가상 사례다. 실제로 발생한 장애 기록이 아니다.
- 검색·상태·담당·티켓·재현·해결 표시·합의 표시는 동작하지만, 필터 선택 상자는 모양만 있다.
- 밝은·어두운 화면을 모두 지원하고, 좁은 창에서는 메뉴가 가로로 바뀐다. 색은 이 앱의 [디자인 토큰](../src/styles/tokens.css)을 따른다.
