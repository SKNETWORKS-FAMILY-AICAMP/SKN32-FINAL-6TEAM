# 웹 MVP 1차 개발 기준

작성일: 2026-09-21. 사용자 승인 범위: 로그인·회원가입·서비스 결제 없는 5개 화면. 이번 문서는 실제 프론트 구현 기준이며, 전체 앱·웹 확장 기획을 대체하지 않는다.

수정일: 2026-09-24. 사용자 지시로 2026-09-23 목업 [`tripilot-intro-animated-nav-switch.html`](tripilot-intro-animated-nav-switch.html)을 기준선으로 전환했다. 소개·온보딩(약관·여행 취향) 화면과 한/영 전환, 설정 사이드바를 더했고 5개 화면의 디자인을 목업에 맞췄다. 이후 화면 변경은 이 앱에서 한다. 기준선 파일은 원본(11MB)의 내장 이미지를 같은 폴더의 이미지 파일 참조로 바꾼 사본이며 내용은 같다.

## 기술스택

Next.js 16 App Router + React 19 + TypeScript strict. Node.js 22와 npm을 사용하고 정확한 의존성은 `package-lock.json`으로 고정한다. CSS Modules와 공통 디자인 토큰으로 기존 목업의 색상·간격·배치를 유지한다. TanStack Query가 비동기 여행 데이터·캐시·진행 조회를 소유하고, Zod가 어댑터 데이터와 입력을 검증한다. 로컬 탭·선택·입력 상태는 React로 관리한다. 한 개 입력창을 위해 추가 폼/전역 상태 라이브러리를 도입하지 않는다.

공식 참고: [Next.js 설치](https://nextjs.org/docs/app/getting-started/installation), [TanStack Query 설치](https://tanstack.com/query/latest/docs/framework/react/installation).

## 화면과 개발 순서

1. 공통 레이아웃·버튼·입력·상태 표시와 여행 데이터 계약을 먼저 정의한다.
2. `/`: 소개 3장(스크롤 스냅·등장 모션). 넓은 화면에서는 402px 기기 틀, 720px 이하에서는 전체 화면.
3. `/start`: 온보딩. 약관은 끝까지 읽어야 동의할 수 있고, 여행 취향 9문항은 좌우로 넘기는 카드다.
4. `/trips/new`: 큰 텍스트 입력창, 입력 보존·예시 계획(한/영)·데모 시나리오, 온보딩에서 고른 취향 표시.
5. `/trips/[tripId]/verification`: 4단계·퍼센트·재시도·결과 이동.
6. `/trips/[tripId]/results`: 요약 통계·확인 필요 항목 우선·일차 탭·상세 펼침. 확인 필요 항목이 있으면 관리 시작을 막는다.
7. `/trips/[tripId]`: 일정·방문 순서(지도)·채팅을 한 번에 한 칸씩 보여 주고 하단 고정 탭 또는 플로팅 버튼으로 바꾼다.

디자인 출처는 [2026-09-23 목업](tripilot-intro-animated-nav-switch.html)이다. 목업의 내비게이션 비교 스위치 대신 오른쪽 위 메뉴의 설정 사이드바에서 언어와 여행 화면 내비게이션(기본 고정 하단 탭)을 고른다. 목업은 실제 지도 대신 방문 순서 개념도를 보이지만, 앱은 지도 제공자 설정을 유지하고 `demo`일 때 개념도를 보인다. 이전 디자인 출처(A-COP `8ed3548`의 `tripilot-intake-wireframe.html`)와 기존 HTML 시연 파일은 보존한다. 상태 오류·실패·없는 여행 안내는 각 화면 내부 상태로 처리한다.

## 코드 경계

- `src/app`: URL·공통 레이아웃·페이지 조합.
- `src/components/ui`, `src/components/layout`: 실제로 재사용되는 UI. `layout`에는 기기 틀·여정 틀·풍경 배경·설정 사이드바가 있다.
- `src/features/intro`, `src/features/onboarding`: 소개 화면과 약관·취향 온보딩.
- `src/lib/i18n.ts`, `src/lib/settings.ts`: 한/영 문구 함수와 언어·내비게이션 설정.
- `src/features/trip-registration`: 입력 UI와 입력 상태.
- `src/features/verification`: 검증 진행과 결과 UI.
- `src/features/trip`: 여행 홈·화면용 타입·공통 여행 조회.
- `src/features/map`: 공통 지도 표시 계약·지도 선택·네이버/Google 지도 컴포넌트.
- `src/lib/gateway.ts`, `src/lib/demo`: 데이터 연결 인터페이스와 분리된 데모 구현.
- `src/styles`: 색상·서체와 공통 토큰.

여행 데이터는 `TripGateway`로 요청하고 서버 데이터는 여행 ID·언어별 Query 캐시에 보관한다. 모든 게이트웨이 호출은 읽는 사람의 언어를 넘기고, 게이트웨이가 만든 문구(검증 단계·결과 이유·오류·채팅 답변)는 그 언어로 돌아온다. 데모 저장소는 결과를 문구 대신 이유 코드로 저장해 언어를 바꾸면 같은 결과를 다시 쓴다.

언어(기본 English)와 여행 화면 내비게이션(기본 고정 하단 탭)은 브라우저 `localStorage`의 `tripilot.web.settings.v1`에 저장한다. 서버 렌더링은 기본값으로 그리고 브라우저에서 저장된 값으로 바꾼다. 온보딩 답변(약관 동의·취향)은 약관 문구대로 페이지 메모리에만 두며 새로고침하면 초기화된다. 지도 제공자의 SDK 로딩·핀 표시는 `features/map` 안에서 처리한다. 업무 판정·실제 시간 계산·예약 변경을 UI에서 구현하지 않는다. 데모를 위한 일정 파싱과 응답 생성은 `lib/demo`에 한정한다.

## 실제 연동 경계

현재 체크아웃의 `final_project_cs/app/presentation/api/cases.py`에는 인증된 Case 등록·조회·중단 재개 API만 있다. 여행 접수·검증 단계/퍼센트·여행 결과·여행별 접근 토큰·일반 여행 채팅 API는 확인되지 않았다. 따라서 이 프론트는 **명시적인 데모 모드**로 제공한다. 실제 API 실패에 데모 결과를 대신 반환하지 않는다.

`Trip`은 프론트 표시 계약이며 기존 Case 응답 계약이 아니다. 실제 연동 전 백엔드와 다음을 합의한다: 여행 접수/조회 및 토큰 권한·만료, 검증 작업 ID/상태/진행률/이벤트 순서, 다중 결과와 시작 차단 조건, 재시도·멱등성, 관리 시작과 메시지 계약. 실제 SSE 연결이 존재한다고 가정하지 않으며 현재 진행 조회는 데모 어댑터의 주기 조회다. 백엔드 scope API 키를 `NEXT_PUBLIC_*`나 브라우저 코드에 넣지 않는다.

데모 저장은 같은 브라우저 탭의 세션 범위다. 다른 사람에게 여행 URL을 공유하는 기능이나 서버 보존을 제공하지 않는다. 지도는 기본 시연 배치와 교체 가능한 네이버/Google 구현을 분리했다. 실제 지도에는 웹용 키 설정과 일정의 유효한 좌표가 필요하다. 실제 길찾기·현재 위치 기능은 포함하지 않는다. 백엔드가 전달할 좌표·방문 시간·일정 ID와 후속 이동 구간 계약, 설정 방법은 [지도 연동 문서](MAP_INTEGRATION.md)를 따른다. 실제 제공자 키 인증은 아직 확인하지 않았다.

## 완료 기준

`npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run test:e2e`로 확인한다. 주요 확인 항목은 소개·온보딩(약관 열람 후 동의·취향 9문항)과 5개 화면 이동, 언어·내비게이션 설정 유지, 입력/새로고침 보존, 다중 결과와 여행 일정 일치, 검증 실패·재시도, 미완료 상태의 관리 시작 차단, 잘못된 여행 링크, 모바일 표시와 키보드 조작이다. 실제 API 통합·배포는 별도 완료 항목이며 데모 화면 통과로 대체하지 않는다.

## 1차 구현 검증 기록

2026-09-21 기준 5/5 화면을 구현했다. 린트·TypeScript 검사·프로덕션 빌드가 통과했고 Vitest 단위 테스트 21/21, Chrome에서 프로덕션 빌드를 실행한 Playwright 시나리오 8/8이 통과했다. 브라우저 검증에는 PC 1440px과 모바일 375px·320px, 지도에서 선택한 일정으로 이동·포커스, 키보드 일차 전환, 저장 실패 후 메시지 재전송을 포함한다. 밝은 화면·어두운 화면의 실제 렌더링도 확인했다. 실제 API 통합과 배포 검증은 포함하지 않는다.

같은 날 지도 모듈 추가 후 단위 검사 40/40(100%), 네이버·Google SDK 대역 브라우저 검사 6/6(100%), 기존 화면 회귀 검사 8/8(100%)가 통과했다. 지도 제공자별 빌드와 기본 데모 빌드도 통과했다. 지도 어댑터는 키 설정 후 사용하며, 실제 계정 인증·지도 타일 검증은 아직 수행하지 않았다. 실행 방법과 검증 경계는 [지도 연동 문서](MAP_INTEGRATION.md)에 기록했다.
