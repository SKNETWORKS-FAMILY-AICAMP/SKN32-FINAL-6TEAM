# 이용자 웹 1차 화면 구현 및 데모 흐름 연결

작성일: 2026-09-21. 작업 브랜치: `role-eval-ui`. 담당: 최상욱.

현재까지 구현한 이용자 화면의 범위와 검증 결과를 정리한다.

## 목적

이용자가 여행 계획을 등록하고 검증 결과를 확인한 뒤 여행 홈에서 일정·지도·대화를 살펴볼 수 있도록 실행 가능한 웹 화면을 구현했다. 이번 완료 범위는 브라우저 내 데모이며 실제 여행 서비스 연동 완료를 뜻하지 않는다.

## 구현 내용

| 화면 | 주소 | 구현된 동작 |
|---|---|---|
| 랜딩 | `/` | 서비스 소개와 여행 등록 진입 |
| 계획 등록 | `/trips/new` | 텍스트 입력, 입력 검증, 예시 계획, 작성 내용 보존 |
| 검증 중 | `/trips/[tripId]/verification` | 4단계 진행과 퍼센트 표시, 실패 안내 및 재시도 |
| 검증 결과 | `/trips/[tripId]/results` | 결과 요약, 일차별 목록, 변경 전후 확인, 미완료 상태에서 관리 시작 차단 |
| 여행 홈 | `/trips/[tripId]` | 일정·지도 선택 연결, 데모 대화와 전송 재시도, 모바일 탭 |

- Next.js 16·React 19·TypeScript로 앱을 구성하고 공통 UI, 기능별 화면, 데이터 연결 코드를 분리했다.
- 여행과 대화는 같은 브라우저 탭의 저장소에 보관해 새로고침 후에도 유지한다.
- 데모·네이버지도·Google Maps를 설정으로 선택할 수 있게 구현했다. 실제 지도에는 명시적인 좌표와 웹용 인증 설정이 필요하다. 좌표 누락과 지도 오류를 안내한다.
- 실행 설정 예시, 의존성 잠금 파일, 개발 기준, 지도 연결 및 백엔드 전달 계약을 문서화했다.
- 기존 단일 HTML 발표 목업은 보존했다.

## 완료 판정과 검증

- [x] 5/5개 화면(100%)의 경로와 구현이 존재한다.
- [x] 린트, TypeScript 검사, 프로덕션 빌드가 통과한다.
- [x] 단위 테스트 40/40개(100%)가 통과한다.
- [x] Chrome에서 프로덕션 빌드의 브라우저 회귀 검사 8/8개(100%)가 통과했다. 등록·검증·결과·관리 시작·대화, 실패 재시도, 미완료 차단, 입력 보존, 잘못된 링크, 모바일·키보드 동작을 확인했다. 지도 제공자 전용 검사 3개는 기본 데모 빌드 조건에 따라 건너뛰었다.
- 지도 제공자별 모의 SDK 검사는 기존 개발 기록에서 네이버 3/3개와 Google 3/3개 통과를 확인했다. 실제 지도 인증 검증과는 구분한다.

## 후속 범위

실제 여행 접수·조회·검증·대화 API 및 에이전트 연결, 서버 영구 저장, 여행 링크 공유·접근 권한, 로그인·회원가입·서비스 결제, 실제 지도 계정 인증·지도 타일 확인, 길찾기·현재 위치, 배포는 이번 완료 범위에 포함하지 않는다.

## 처음 보는 사람을 위한 말풀이

- 데모: 실제 서비스 대신 시연용 여행 데이터와 응답으로 화면 흐름을 확인하는 모드다.
- 데이터 어댑터: 화면의 데이터 요청을 실제 서버 또는 시연 데이터에 연결하는 코드다. 현재 `TripGateway` 경계에서 분리했다.
- SDK 대역: 지도 서비스의 브라우저 개발 도구를 테스트용 구현으로 대신해 화면과 지도 사이의 호출을 검사하는 방법이다.
- 회귀 검사: 이미 동작하던 기능이 변경 후에도 유지되는지 확인하는 테스트다.
