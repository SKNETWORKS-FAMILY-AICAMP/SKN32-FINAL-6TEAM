# 이용자 웹 구현 현황

작성일: 2026-09-21 · 최신 확인: 2026-09-29 · SKN32 `develop` `fc1ac0a` · 원본 최신화 `ST4F-170` · API 협업 문서 `ST4F-172`.

화면별 협의·연결 상태는 [공유 연동 문서](../../../wiki/external/web-screen-api.md)를 따른다.

현재 앱은 Next.js 16·React 19·TypeScript로 구현돼 있다. `[2026-10-03 사용자 지시]` 데모(모방) 모드는 없앴고 앱은 `/v1/web/*`에 연결하는 live 하나다. 이번 개정은 원본 문서와 코드를 대조한 것이며 새 API 협의안·wiki 이관·운영 검증은 포함하지 않는다.

## 현재 구현 내용

| 화면 | 현재 동작과 제한 |
|---|---|
| 소개 `/` | 3장 소개, 한/영 선택, 최근 여행 3개와 전체 목록 진입, 이용 방법 카드 |
| 온보딩 `/start` | 선택 이메일 초안·약관·취향 6문항, 기본사항/여행 방식 완료 카드. 답은 페이지 메모리에 유지 |
| 등록 `/trips/new` | 입력 칸 셋(직접 입력 · 파일 선택 · 계획 짜 주기 (테스트)) — 마지막에 고른 칸만 접수·짜기로 보내고 사람 확인(설정 시) |
| 접수 확인 `/intakes/[intakeId]` | live 읽기 상태·계획 확인 화면(항목 수정/삭제·확인 등록). 읽은 일정이 없으면 짧은 안내와 등록 화면 링크 |
| 검증 진행·결과 | 따로 보는 화면은 없다 — 옛 주소는 그 여행 화면으로 보낸다(서버가 등록할 때 판정, 확인은 계획 확인 화면) |
| 여행 `/trips/[tripId]` | 일정·지도·채팅. live 서버 상담·제안 선택·경고·알림·이력, 이동 출발 시각을 다음 일정에 표시 |
| 내 여행 `/trips` | 목록 조회. 개별·선택 삭제는 서버 `POST /v1/web/trips/{id}/delete` 에 연결(서버에 아직 없어 「지원하지 않아요」라고 말함) |
| 마이페이지·수정 | 토큰 보기·복사, live 토큰 가져오기·재발급. 닉네임/이메일 입력 검증만 가능하고 저장·이미지 변경은 비활성 |

## 데이터와 남은 연결

live는 브라우저의 `X-User-Key`로 사용자의 여행을 조회한다. 여행 원본과 대화는 서버에서 읽고, 방금 주고받은 대화만 탭 저장소에 잠깐 보관한다. 개인 설정·사용자 키는 브라우저 저장소, 온보딩은 페이지 메모리라 보존 범위가 다르다.

설문은 온보딩 완료 시 live 확인·계획 생성 요청으로 전달한다. 일정 변경 방식·여행 밀도와 이동 선호 일부의 소비 코드를 확인했다([설문 대응](PREFERENCES_CONTRACT.md)). 선택 언어·복구 이메일은 현재 서버로 보내지 않는다. 프로필 저장과 live 여행 삭제도 미연결이다([프로필 현황](PROFILE_CONTRACT.md)).

지도는 OpenStreetMap(기본)·Naver·Google 중 설정으로 선택한다. 실제 지도는 서버 `items[].lat/lon`을 변환한 좌표를 사용하고, 좌표 없는 일정에는 임의 핀을 만들지 않는다. 경로 선·현재 위치는 구현하지 않았다([지도 문서](MAP_INTEGRATION.md)).

`POST /v1/web/warmup` 서버 라우트는 `fc1ac0a`에서 추가됐다. 웹 화면·가짜 서버 시험 성공을 모든 서버 계약이나 실제 모델 예열의 성공으로 볼 수 없다. 로그인·회원가입·서비스 결제는 현재 웹 범위 밖이다.

### 이용자 웹 1차 화면 구현 및 데모 흐름 연결 (2026-09-21 기록)

작성일: 2026-09-21. 작업 브랜치: `role-eval-ui`. 담당: 최상욱.

현재까지 구현한 이용자 화면의 범위와 검증 결과를 정리한다.

#### 목적

이용자가 여행 계획을 등록하고 검증 결과를 확인한 뒤 여행 홈에서 일정·지도·대화를 살펴볼 수 있도록 실행 가능한 웹 화면을 구현했다. 이번 완료 범위는 브라우저 내 데모이며 실제 여행 서비스 연동 완료를 뜻하지 않는다.

#### 구현 내용

| 화면 | 주소 | 구현된 동작 |
|---|---|---|
| 랜딩 | `/` | 서비스 소개와 여행 등록 진입 |
| 계획 등록 | `/trips/new` | 텍스트 입력, 입력 검증, 예시 계획, 작성 내용 보존 |
| 검증 중 | `/trips/[tripId]/verification` | 4단계 진행과 퍼센트 표시, 실패 안내 및 재시도 |
| 검증 결과 | `/trips/[tripId]/results` | 결과 요약, 일차별 목록, 변경 전후 확인, 미완료 상태에서 관리 시작 차단 |
| 여행 홈 | `/trips/[tripId]` | 일정·지도 선택 연결, 데모 대화와 전송 재시도, 모바일 탭 |

- Next.js 16·React 19·TypeScript로 앱을 구성하고 공통 UI, 기능별 화면, 데이터 연결 코드를 분리했다.
- 여행과 대화는 같은 브라우저 탭의 저장소에 보관해 새로고침 후에도 유지한다.
- 데모·네이버지도·Google Maps를 설정으로 선택할 수 있게 구현했다. 실제 지도에는 명시적인 좌표와 웹용 인증 설정이 필요하다. 좌표 누락과 지도 오류를 안내한다.
- 실행 설정 예시, 의존성 잠금 파일, 개발 기준, 지도 연결 및 백엔드 전달 계약을 문서화했다.
- 기존 단일 HTML 발표 목업은 보존했다.
