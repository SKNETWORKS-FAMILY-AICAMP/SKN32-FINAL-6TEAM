# 사용자 웹

최신 확인: 2026-09-29 · SKN32 `develop` `fc1ac0a` 코드 기준. 화면별 요구·사용 API·협의와 연결 상태는 [공유 연동 문서](../../../wiki/external/web-screen-api.md)에서 관리한다.

Next.js 16 App Router + React 19 + TypeScript로 구현한 웹 MVP 1차다. 로그인·회원가입·서비스 결제 없이 다음 화면을 제공한다. 2026-09-24부터 [2026-09-23 목업](mockups/tripilot-intro-animated-nav-switch.html)을 디자인 기준선으로 쓴다.

| 화면 | URL | 주요 기능 |
|---|---|---|
| 소개 | `/` | 3장 스크롤 소개 — 첫 장 언어 선택 카드와 내 여행 카드(최근 3개, 4개 이상이면 `전체일정 보기`), 둘째 장 이용 방법 캡처 카드(옆으로 밀기·PC 마우스 끌기·버튼으로 넘김), 셋째 장 일정 시작 진입 |
| 온보딩 | `/start` | 선택 입력 복구용 이메일(형식 검사만, **저장·인증 없음**), 약관 열람·동의, 설문 안내 카드와 여행 취향 6문항(백엔드 설문 D-020 기준 · 여행자 구성 `기타` 직접 입력 · 분야·세부 순위 카드 · 이동수단·내국인 여부 문항은 뺌) |

| 검증 결과 | `/trips/[tripId]/results` | demo: 요약·확인 필요 항목·일차 탭·변경 전후·관리 시작. live: 안내 후 여행 화면으로 이동 |

모든 화면 오른쪽 위 메뉴에서 마이페이지와 여행 목록을 열고, 언어(홈과 같은 펼침 카드, 기본 English)와 `플로팅 버튼 사용`(끄면 고정 하단 탭, 기본 꺼짐)을 바꾼다. 왼쪽 로고는 어느 화면에서든 소개 첫 장으로 돌아간다. 소개 첫 장의 언어 카드에서도 같은 언어 설정을 바꿀 수 있다. 설정은 이 브라우저에 저장된다. 기술스택 선택과 컴포넌트·기능·데이터 연결의 책임은 [개발 기준](DEVELOPMENT.md)에 정리했다.

## 실행

Node.js 22와 npm을 사용한다. 이 폴더에서 실행한다.

★**웹은 실제 서버로 돈다.** 먼저 triPilot 서버(고객용 8042)를 띄운다(`final_project_cs` README 의 실행 절). 그다음 이 폴더에서:

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

[개발 서버](http://127.0.0.1:3100)를 연다. 예시 설정은 `NEXT_PUBLIC_DATA_MODE=live`(실제 서버 `NEXT_PUBLIC_API_BASE=http://127.0.0.1:8042`) · `NEXT_PUBLIC_MAP_PROVIDER=osm`(무료 지도, 키 없음)이다.
- `.env.local`이 이미 있으면 덮어쓰지 말고 **`NEXT_PUBLIC_DATA_MODE=live` 인지** 확인한다. ☆2026-09-29 팀원 실행에서 화면이 데모로 떴다 — 옛 예시가 `demo` 였고, 설정이 없으면 개발 모드 기본값도 데모였다. 지금은 설정이 없으면 데모로 떨어지지 않고 「실제 서버 연결이 설정되지 않았어요」라고 말한다.
- `NEXT_PUBLIC_*` 값은 바꾼 뒤 **`npm run dev` 를 다시 켜야** 반영된다.
- 서버 주소를 바꾸면 서버의 `ACOP_WEB_ALLOWED_ORIGINS` 에 웹 주소(기본 `http://127.0.0.1:3100`·`http://localhost:3100`)가 있어야 한다. 없으면 브라우저가 서버 응답을 막는다.
- 확인: 화면 위쪽에 데모 안내가 없고, 여행 채팅 제목 옆에 「데모」 표시가 없으면 실제 서버로 도는 것이다.
- `demo` 는 디자인 팀 화면 시험(`test:e2e`)용 브라우저 안 모방 데이터다. 앱 실행에 쓰지 않는다.

```powershell
npm run check
npm start
```

`check`는 린트·타입 검사·단위 테스트·프로덕션 빌드를 순서대로 실행한다. `start`는 빌드 결과를 3100 포트에서 제공하므로 개발 서버와 동시에 실행하지 않는다.

## 브라우저 검증

프로덕션 빌드를 만든 뒤 실행한다. Playwright는 테스트 서버를 3101 포트에 띄운다.

```powershell
npx playwright install chromium
npm run test:e2e
```

이미 설치된 Chrome으로 실행할 때는 PowerShell에서 `$env:PLAYWRIGHT_CHANNEL="chrome"`을 설정하고 `npm run test:e2e`를 실행한다. 소개·온보딩, 설정 저장, 등록·진행·결과·관리 시작·채팅, 실패 재시도·미완료 차단, 입력 보존·새로고침, 모바일·키보드 동작을 확인한다. 프로덕션 빌드는 `.env.local`의 `NEXT_PUBLIC_DATA_MODE=demo`로 만들어야 한다.

## 데이터 연결 상태

`[2026-09-27]` **실제 연결(`NEXT_PUBLIC_DATA_MODE=live`)이 생겼다.** `NEXT_PUBLIC_API_BASE`(기본 `http://127.0.0.1:8042`)의 triPilot 서버 `/v1/web/*` 에 붙는다.
- 등록 화면: 글(붙여 넣은 일정·채팅처럼 쓴 계획)과 파일(사진·PDF·워드·엑셀, 최대 5개)을 **계획 읽기**(`/v1/web/trip-intakes`)로 보낸다.
- 확인 화면 `/intakes/[intakeId]`(`src/features/intake-review/`): 읽는 동안 기다린 뒤, 항목마다 배지(원문 그대로 · 규칙으로 배치 · 조회로 확인 · 확인 필요)와 원문 줄을 보이고, 장소·날짜·시각을 고치거나 뺀 뒤 「등록하고 관리 시작」으로 등록한다.
- 「일정 짜 줘」가 읽히거나 읽은 일정이 없으면 확인 화면에 **일정 짜기** 칸이 나온다 — 첫날·일수·인원(읽은 값으로 미리 채움)을 확인하고 「이 조건으로 짜서 등록」.
- 여행 화면: 서버의 여행을 읽고(서울 시각), 채팅은 서버의 여행 상담(Case)으로 간다. 답 문장은 서버가 준 것만 쓰고 지어내지 않는다. 이동 항목은 목록에 섞지 않고 다음 일정 메모의 「몇 시 출발」로 보인다.
- 내 여행 `/trips`: 서버 목록(`GET /v1/web/trips`)의 제목·등록 시각을 보인다. 저장된 사용자 키가 없으면 서버를 부르지 않는다(부르면 새 키가 발급된다). 여행 날짜·상태·미확인 제안 수는 목록 응답에 없어 아직 보이지 않는다.
- 브라우저에는 **사용자 키 하나**(`X-User-Key`)만 둔다(localStorage). 서버용 scope 키는 넣지 않는다. 키가 거절되면 조용히 새 사용자로 바꾸지 않고 알린다.
- 서버의 `ACOP_WEB_ALLOWED_ORIGINS` 가 이 앱의 출처(기본 3100)를 포함해야 한다. 관광공사 출처 표시가 확인 화면·여행 화면 아래에 붙는다.
- 연결 코드 `src/lib/live/`(시험 `gateway.test.ts`).
- `[2026-09-28]` **서버가 주는 나머지도 화면에 이었다.** 시작 화면 「내 여행 이어보기」(`GET /v1/web/trips`, 저장된 사용자 키가 있을 때만), 여행 화면 위쪽 「선택이 필요해요」(서버가 기다리는 다른 안 고르기 `/proposals`·`/choose`, 「지금 일정 그대로 두기」 포함), 「살펴볼 점」(서버 `warnings`), 「받은 알림」(`/notices`, 서버가 보낸 문장 그대로), 「변경 이력」(`history`). 일정 카드에는 고객이 고정한 일정 표시와 서버가 남겨 둔 「다른 안」 이름이 붙는다. 화면은 문장을 지어내지 않는다 — 서버가 문장을 안 준 자리는 서버의 이유 코드를 그대로 보이고, 목록을 자르면 「전체 N개 중 M개는 화면에 없어요」를 적는다. 데모 모드에는 나오지 않는다.
- 지도: `NEXT_PUBLIC_MAP_PROVIDER`로 demo·osm·naver·google을 선택한다. 저장소 예시는 demo이며, 개인 `.env.local` 값이나 외부 인증 성공을 이 문서의 공통 실행 전제로 삼지 않는다. ★`[2026-09-29]` **개발 기본값은 무료 지도 `osm`**(OpenStreetMap 표준 타일, Leaflet, 키 없음). 구글 지도(`google`)는 제공자별 브라우저용 키·Google Map ID가 필요하고, 지도를 열 때마다 **서버에 먼저 허락을 묻고**(`POST /v1/web/map-load`, 하루 312 · 월 9,688 — 서버 DB 가 모든 사용자를 같이 센다, 운영 설정 `web.map_provider` 가 osm 이면 묻기만 하고 무료 지도) 거절·한도·무응답이면 무료 지도로 보인다. 구글 키·Map ID 는 브라우저에 실리는 값이라 배포 전에는 웹 주소로 제한한 키와 우리 Map ID 로 바꿔야 한다.
  - OSM 타일 정책(operations.osmfoundation.org/policies/tiles, 2026-09-29 읽음): 출처 표시 필수(지도 오른쪽 아래), https 만, 보이는 범위 밖 미리 받기·「오프라인 저장」 금지, 캐시 우회 헤더 금지, Referer·User-Agent 를 가리지 않기, **서비스 보장 없음(많이 쓰면 예고 없이 막힐 수 있다)**. 그래서 개발·시연용이고, 많은 사용자가 쓰는 서비스에는 자체 타일 서버나 유료 타일 제공자가 필요하다. 타일 주소는 `NEXT_PUBLIC_OSM_TILE_URL` 로 바꿀 수 있다.
- `[2026-09-28]` **사용자 키 화면**(D-020 약속, D-021 §4): 키가 새로 발급되면 서버가 준 안내 문장과 함께 **한 번** 보여 주고 복사할 수 있다(「따로 보관했어요」로 닫는다). `[2026-09-28 사용자]` 토큰에 관한 것은 **마이페이지 한 곳**에 모았다 — 「발급된 토큰」(보기·복사) 아래 「토큰 관리」에서 다른 기기의 토큰으로 열 수 있고(서버가 아는 키만 받는다, 틀리면 저장된 키를 그대로 둔다), 샜을 때 키를 다시 발급받을 수 있다(옛 키는 바로 무효라 확인 단계를 한 번 거친다). 이메일 재발급은 D-021 의 나머지로 서버 작업이 먼저다.
- live 에서 검증 진행·결과 화면은 「검증 단계가 따로 없다」는 안내로 바뀐다 — 서버가 등록할 때 판정하고, 살펴볼 점·알림·이력은 여행 화면에 나온다(데모의 지어낸 0을 보이지 않는다). 여행 화면의 「일정 수정」은 live 에서 「새 계획 올리기」다(실제 수정은 채팅과 다른 안 고르기).
- `[2026-09-28]` 온보딩 설문은 **실제 연결에서도 보낸다.** 온보딩을 마친 경우에만 계획 읽기의 확인(`/confirm`)·일정 짜기(`/plan`) 요청에 `survey`(서버 `TripSurvey` 판 `2026-09-24.v1`, 선택)로 싣고, 서버가 틀린 설문은 422 `invalid_survey`로 거절한다. 온보딩 답은 페이지 메모리에만 있어 새로고침하면 사라진다([설문 대응](PREFERENCES_CONTRACT.md)).

데모 모드에서는 여행 데이터를 **명시적인 데모 어댑터**로 실행한다. 검증 진행·결과·채팅은 시연 데이터이며 실제 에이전트·예약 API에 연결되어 있지 않다. 지도는 기본 `demo`이며 네이버지도·Google Maps 컴포넌트를 선택할 수 있다. 등록 화면의 데모 옵션에서 완료·확인 필요·실패 상황을 선택할 수 있다. 여행 및 대화는 같은 탭의 `sessionStorage`에 보관되므로 새로고침으로 유지되지만 다른 사용자에게 링크를 공유하거나 서버에 영구 보존하는 기능은 없다. 온보딩 답변은 페이지 메모리에만 있어 새로고침하면 초기화된다. 온보딩을 마쳤으면 취향 답을 여행 등록 요청에 백엔드 설문(`constraints.survey`)으로 싣는다. 데모 모드는 백엔드와 같은 규칙으로 검사만 하고 저장하지 않는다([설문 대응](PREFERENCES_CONTRACT.md)). 검증 시연 입력 형식은 등록 화면의 예시 계획을 참고한다.

현재 연결은 `src/lib/live/{client,intake,gateway,extras}.ts`에 구현돼 있다. `TripGateway`는 여행 조회·목록·대화를 맡고, 접수·확인·계획 생성과 제안·알림은 별도 live 함수가 맡는다. 실제 API 오류를 데모 성공으로 바꾸거나 서버 scope 키를 브라우저에 노출하지 않는다.

남은 연결 제약(기준 커밋 정적 확인):

- 여행 삭제: live 게이트웨이에 `deleteTrip`이 없고 서버에도 웹 여행 DELETE 라우트가 없다. 데모 삭제 성공은 서버 삭제 구현의 근거가 아니다.
- 닉네임·복구 이메일·프로필 이미지 저장 및 이메일로 토큰 복구: 미연동. 토큰 가져오기·재발급은 구현돼 있다.
- 한/영 설정은 화면 문구용이다. 접수·확인·계획 생성 요청에 선택 언어를 보내지 않고, 서버 접수 조립과 계획 생성은 `locale="ko"`를 사용한다. 서버가 준 문장을 자동 번역하지 않는다.
- 채팅 사전 준비: `POST /v1/web/warmup`은 `fc1ac0a`에서 서버에도 추가됐다. 여행 화면의 호출은 연결돼 있지만 결과·실패 안내 UI는 없고 실제 모델 예열 성공은 별도 검증이 필요하다. [명세와 연결 상태](../../../wiki/external/web-screen-api.md)를 따른다.

## live 전체 시험

```powershell
npm run test:mock
```

서버 계약(`/v1/web/*`)을 그대로 흉내 낸 **테스트용 모방 서버**(실제 서버 아님)(`tests/mock-api/test-mock-server.mjs`)를 띄우고, live 모드로 빌드한 화면을 실제 브라우저로 끝까지 눌러 본다(첫 방문 → 키 발급 안내 → 계획 접수 → 확인 → 등록 → 여행 화면 → 선택·채팅·키 화면, 그리고 서버 500·409·429·연결 불가·읽기 실패). ★실서버 대신 테스트용 모방 서버를 쓰는 이유: 실서버에서 등록·확인을 누르면 **디스코드 통지가 팀 채널로 나가고** 서버에 데이터가 남는다. 화면이 서버로 실제 무엇을 보냈는지(설문·request_id·key 값)는 모방 서버가 받은 요청 기록으로 검사한다. 별도 빌드 폴더(`.next-mock`)를 쓰므로 돌아가는 개발 서버와 부딪히지 않는다. 설치된 브라우저 버전이 다르면 `PLAYWRIGHT_CHANNEL=msedge` 를 붙인다.

## 실서버 종단 시험

```powershell
$env:REAL_SERVER_E2E="1"; $env:PLAYWRIGHT_CHANNEL="msedge"; npm run test:real
```

모방 서버 없이 **실제 서버**(`NEXT_PUBLIC_API_BASE`)와 `npm run dev`(3100, live 모드)에 붙어 첫 방문 → 설문 → 계획 접수·읽기 → 확인·등록 → 여행 화면 → 채팅 4문답 → 구글 지도까지, 그리고 일정 짜기(08:00 아침 식사로 시작)를 끝까지 눌러 본다. ★부작용이 있어 `REAL_SERVER_E2E=1` 이 없으면 시작하지 않는다 — 등록마다 **디스코드 통지가 팀 채널로 나가고**, 장소 조회·모델 호출이 쓰이며, 시험 고객과 여행이 DB 에 남는다. 서버는 **한 주소에서 한 시간에 새 키 20개**까지만 내주므로(429 `too_many_sessions`) 시험은 순서대로 돌며 첫 시험의 키를 이어 쓴다. 관광공사 조회가 한도에 걸리면(`tour_api: rate_limited`) 일정 짜기가 422 로 거절되니 1분쯤 뒤 다시 돌린다.

## 사람 확인(Cloudflare Turnstile)

`[현재 기준: 2026-09-29 · fc1ac0a]` 프론트의 선택적 확인 표 전송 코드는 있지만, 이 develop 기준의 키 발급·접수 라우트에는 서버 검증이 연결돼 있지 않다. 아래 2026-09-28 시험 기록은 당시 결과로 보존하며 현재 서버의 방어 기능이 적용됐다는 근거로 사용하지 않는다. [현재 API 명세](../../../wiki/external/rest-endpoints.md#web-api)를 따른다.

live 에서 `NEXT_PUBLIC_TURNSTILE_SITE_KEY` 를 넣으면 계획 올리기 화면에 사람 확인이 붙는다. ★새 사용자의 첫 계획 올리기는 표를 **두 번** 받는다 — 먼저 키 발급(`POST /v1/web/session`, JSON `{"turnstile_token"}`)에, 그다음 새 표로 계획 올리기에(표는 한 번만 확인된다). 평소엔 보이지 않고 Cloudflare 가 의심할 때만 체크 상자가 뜬다. 받은 확인 표는 계획 올리기 요청(`POST /v1/web/trip-intakes`, multipart)의 `turnstile_token` 칸으로 간다. 확인 표가 오기 전에는 보내지 않고 「사람 확인이 끝나면 보낼 수 있어요」를 보인다. 한 번 보낸 표는 다시 못 쓰므로 실패하면 새 표를 받는다. 값이 비면 꺼지고 지금과 같다.

- 개발: Cloudflare 공개 시험 키 `1x00000000000000000000AA`(항상 통과). 배포: Cloudflare 에서 사이트를 등록해 받은 사이트 키.
- 서버가 확인 표를 Cloudflare 에 검증한다(`ACOP_TURNSTILE_SECRET`, 계약 `final_project_cs/wiki/external/rest-endpoints.md` 「남용 방어」). 비밀키가 없는 개발 서버는 건너뛰고 응답에 `human_check: "skipped"` 를 싣는다. 2026-09-28 Cloudflare 공개 시험 비밀키로 확인: 항상 통과 키 → 키 발급 `human_check: passed` · 계획 읽기까지 통과, 항상 실패 키 → 키 발급 403 `human_check_failed`, 화면은 서버 문장을 보이고 키를 저장하지 않는다.
- 한도에 걸리면(`429 usage_limit` · `503 service_daily_cap` · `429 too_many_sessions`) 서버 문장 뒤에 「(3시간 20분 뒤에 다시 할 수 있어요.)」처럼 다시 되는 때를 붙인다(`retry_after_seconds` 또는 `Retry-After`).
- 빈 키 정리 문구는 **넣지 않는다**(2026-09-29 사용자 결정 — 키는 그 사용자를 알아보는 유일한 식별 토큰이라 지우면 사람이 사라진다. 서버도 정리를 기본 꺼짐으로 바꿨다).
- live 전체 시험(`npm run test:mock`)은 테스트용 모방 서버만 쓰므로 이 값을 비워 빌드한다(`tests/mock-api/serve.mjs`).

## 지도 선택과 백엔드 전달

`.env.local`의 `NEXT_PUBLIC_MAP_PROVIDER`를 `osm`(무료, 키 없음) · `naver` · `google`로 지정하고 해당 서비스의 웹용 인증 정보를 설정한다. 개발 서버 재시작/배포 재빌드 후 선택한 지도를 사용한다. 두 지도는 같은 일정 ID·좌표·방문 시간을 받으며 기존 일정 선택 동작을 공유한다.

키 발급·허용 도메인 설정, 필요한 `coordinates` 형식, 이동 경로와의 책임 구분, 데모 좌표 입력 예시는 [지도 연동 · 백엔드 전달 계약](MAP_INTEGRATION.md)에 정리했다. 이번 문서 개정에서는 실제 키 인증을 재검증하지 않았으며, 좌표가 없는 일정에 임의 핀을 만들거나 지도 오류를 데모로 숨기지 않는다.
