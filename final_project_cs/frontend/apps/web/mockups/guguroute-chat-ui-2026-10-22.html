채팅 칸 개편 목업

2026-10-22 작성 · 상태: 검토용 / 실제 API 미연결 · 기준 코드 role-manager 825ce970 · 장소 · 시각 · 답 문장은 예시 자료

여행 화면 채팅 칸에서 ① 입력칸 위 단추 줄과 ② 서버 답 모양을 따로 고를 수 있게 나눴습니다. 위에서 두 가지를 하나씩 고르면 오른쪽 휴대폰이 바뀌고, 왼쪽은 지금 앱 그대로입니다. 단추 · 칩 · 선택지는 눌러 볼 수 있습니다(답은 미리 적어 둔 예시, 자유 입력에는 「목업 응답」).
답 문장 · 진행 단계 · 되묻기는 서버 코드의 실제 문장 틀로 만들었습니다(아래 「서버 답 대조」). 장소 이름 · 시각 · 원문 값은 예시입니다.

점선 단추 = 서버가 보내지 않고 화면이 만든 것(되묻기 빠른 답) · ⓑ 카드와 같은 내용의 서버 글 줄은 뺀다(「흐리게」를 누르면 점선 밑줄로 보임) · 「(예시)」 = 서버가 계산해 보낼 값의 자리

구현 체크리스트 — 작업 때 빠뜨리지 말 것

2026-10-22 사용자 결정 · 요청을 모았다. 고른 안은 ② 상황 칩 + ⓑ 결과 카드, 서버 수정 없이 프론트만 먼저.

★ 칩 줄 옆으로 밀기 (10-22 요청 — 목업 휴대폰에서 칩 줄을 끌어 보면 된다)

  • 칩은 한 줄 가로 스크롤 — 손가락은 브라우저 스크롤 그대로(touch-action: pan-x pinch-zoom · overscroll-behavior-x: contain), 마우스는 끌기와 세로 휠(→ 가로), 키보드는 Tab 으로 칩을 옮기면 그 칩이 보이게.
  • 채팅 칸의 「오른쪽으로 밀면 일정 칸」(trip-screen.tsx:349 useDayGestures)이 칩 줄에서 시작하지 않게 줄에 data-no-swipe — 그 훅이 이 표시를 비켜 간다(use-day-gestures.ts:93, 시간 휠 time-wheel.tsx:225 과 같은 방식). 칩 줄 밖(대화)에서 밀면 지금처럼 일정 칸으로. 목업도 같게 흉내 냈다(대화를 오른쪽으로 끌면 안내, 칩 줄은 줄만 움직임).
  • 끌다 놓을 때 칩이 눌리지 않게 — 6px 넘게 움직였으면 그 누름은 무시.
  • 더 있는 쪽 끝만 흐리게, 끝에 닿으면 흐림 없음. 칩 내용이 바뀌면(고른 일정 · 새 답 · 되묻기) 줄은 맨 앞에서 시작.
  • ⓑ 대안 카드 줄(옆으로 넘기는 카드)도 같은 규칙.
  • 서버 선택지(혹시 이런 뜻이었나요? · 다음 중 하나인가요?)는 칩 줄에 넣지 않는다 — 답 카드 아래에 줄을 바꿔 전부 보인다(10-22 사용자 결정: 줄에선 잘렸다). 칩 줄에는 하루 요약 · 선택 일정 · 다음 일정 · 가는 길 · 예약 표시 · 지금 다음 일정 · 예보 주의 · 빠른 답 · 위치 단추만.
  • 지금 앱의 칩 줄(.prompts)은 줄바꿈이라 이 문제가 없었다 — 한 줄로 바꾸면서 생기는 일이다.

ⓑ 겹친 줄 빼기 (10-22 결정)

  • 카드가 실제로 그려졌고, 서버 줄이 카드 값으로 만든 서버 문장과 글자까지 같을 때만 뺀다(지도 링크 줄은 주소가 그 일정의 mapUrl 과 같을 때). 하나라도 아니면 남긴다.
  • 「마음에 안 드시면 「되돌려 줘」라고 말씀해 주세요.」는 되돌리기 단추가 그려진 동안만 뺀다.
  • 카드의 「상세 보기」(앱 문구 · 옛 「지도에서 보기」 자리)는 그 일정의 상세 보기 화면으로 — 채팅 칸에서 setDetailId, ← 로 채팅 칸에 돌아온다(10-22 사용자 결정). 바꾼 일정 카드는 바뀐 일정의 상세 보기로.
  • 화면 단위 시험에 서버 문장 틀 예시(상세 · 운영시간 · 주소 · 하루 요약 · 시각 바꾸기)와 「값이 다르면 남는다」를 둔다. 서버가 구조화 칸을 주면 걷어낸다.

그 밖에

  • 되묻기 빠른 답(15분이요 · 30분이요 · 1시간이요)은 응답의 required_input_schema 에 minutes 칸이 있을 때만, 한 번 쓰면 사라짐. 서버 선택지가 오면 그것이 먼저.
  • 예보 제안은 대안 0개로 시작 → 「예보에 맞게 일정 변경」 → 대안 카드.
  • 진행 단계는 SSE 단계를 쌓아 목록으로, 답이 오면 「진행 과정 · n단계 · n초」로 접기.
  • 다른 기기 · 새 탭에서 다시 읽은 대화는 머리표 · 전후 비교 없이 글만(지금 되돌리기와 같은 기준).
  • 「채팅으로 일정을 바꾸면 …」 안내는 입력창 아래 짧은 한 줄 + 「자세히」(10-22 사용자 결정 · 조사: ChatGPT 웹 · M365 Copilot 이 입력창 아래 한 줄). 짧은 문구 「숙소 · 항공 · 예약한 일정은 「일정 수정」에서 바꿔요」(새로 지음)는 375px 에서 한 줄. 「자세히」를 누르면 전체 문장이 입력 막대 위에 뜨고, 그 창 밖 아무 곳이나 누르거나 Esc 로 닫힌다(창 밖을 누른 단추의 동작은 그대로) — 다시 「자세히」를 눌러도 닫힌다. 화면 읽기는 입력칸에 짧은 문구를 aria-describedby 로 연결. 숙소 · 항공 · 예약을 바꿔 달라는 요청엔 서버 거절 답 아래 「일정 수정」 길(맥락 안내)이 함께 간다.
  • 실서버(라이브)에서 확인: 자유 질문 장소 카드가 뜨는 때(대화 기록의 reply.focus) · 「다음 일정 알려 줘」 해석 · 휴대폰 실기기 칩 밀기.
  • 서버 협의(나중, 백엔드 담당): 보내기 응답 · 대화 기록에 status · focus, 사실 질문의 단계 이름, 「되돌려 줘」 꼬리, 카드용 구조화 칸, 선택지 짧은 이름.

서버 답 대조 — 목업 문장이 어디서 왔나

2026-10-22 기준 코드(role-manager 825ce970)를 읽고 문장 틀을 옮겼다. 장소 이름 · 시각 · 원문 값은 예시이고, 실서버에 보내 받은 답은 아니다. 모델이 직접 쓰는 답(규정 질문 · 잡담 등)은 그때그때 다르다.

지금 화면에서 바꾸려는 점

  • 시트 기본 높이(440px)에서 대화 칸이 아주 좁다 — 머리(80px) · 입력 막대(84px) · 단추 줄(약 52px) · 안내 두 줄(약 45px)을 빼면 대화가 보이는 칸이 160px 안팎이다(휴대폰 위 숫자는 이 목업에서 잰 값).
  • 단추 넷이 늘 같은 자리에 같은 이름이다. 일정을 안 고르면 둘이 흐린 채 남고, 직전 답에 서버가 준 「혹시 이런 뜻이었나요?」 선택지는 대화 속 답 아래에 따로 생긴다.
  • 서버 답 · 알림 · 대안 선택이 모두 같은 회색 말풍선이고, 되돌리기 · 직접 고르기 · 위치 단추와 안내 줄이 말풍선 밖에 차례로 쌓인다. 무엇이 바뀌었는지(전 → 후)는 글로만 나온다.
  • 기다리는 동안은 한 줄 글자(「장소 정보를 확인하는 중이에요… (3초)」)만 바뀐다 — 지나온 단계는 남지 않는다.
