    「맞는지 확인」 카드 — 먼저 고칠 것 (2026-10-19 오라클 화면 지적)

    원인 1 — 누를 것이 없다. 서버는 애매한 장소를 장소 검사 줄의 문장으로만 보낸다(장소 값의 needs_review → review.py 의 「… · 맞는지 확인해 주세요」 주의 줄 → 일정이 「확인 필요」). 고를 거리(선택지)가 오지 않아 화면은 글자만 그리고, 확인 필요 일정은 잠금도 막혀 있어(lock_needs_confirmed_item) 「맞아요」로 끝낼 길이 없다.

    원인 2 — 「이전」이 카드와 다르다. 「바뀜 · 이전 …」은 장소 이름을 먼저 쓴다(plan-check.tsx wasText = item.place || item.title). 카드 제목은 원문 「광장시장」이었는데 서버가 고른 장소 「순희네빈대떡」이 「이전」으로 나왔다.

    • 지금 계약 · 웹만고르기 상자 — 「지금 값 — 맞아요」는 지금 장소를 고른 장소로 다시 보낸다(POST …/edits place {name, latitude, longitude, source}, 웹의 itemEdit.placePicked) → 서버가 고객 값으로 받아 확인 필요가 풀린다(바꾼 것이 아니라 「바뀜」 표시 없음). 「광장시장 구경」은 한 요청에 kind: activity + place {name: "광장시장"}. 「직접 수정」은 지금 「바꾸기」 화면(후보 · 검색), 「삭제」는 removed: true.
    • 웹만「바꾸기」 화면의 「지금 일정」 카드에도 「이대로 두기 — 맞아요」 단추(아래 그림).
    • 웹만「이전」 = 카드에 보이던 이름 — 「바뀜 · 이전 광장시장 · 순희네빈대떡」(제목 + 아래 「찾은 곳」 줄). 바꾼 뒤 제목은 고른 곳, 아래 「원문 「광장시장」」(지금과 같음).
    • 제안 · 웹만확정 전 카드 머리에 「찾은 곳 「순희네빈대떡」」 한 줄새 문구 — 접힌 카드만 봐도 무엇을 확인하라는지 보인다. 확정하면 제목이 그 가게가 되고 「원문 「광장시장」」.
    • 참고「광장시장 → 시장 안 가게 하나」 오독 자체는 role-manager 7c255f38(10-19 — 대표 장소 정답표, 시장 · 거리 · 동네는 구역)에서 고쳤다. develop(오라클 자동 배포)에는 아직 없어 오라클 화면에 남아 있다. 그래도 같은 이름 지점 · 별칭 · 오타 · 가까운 곳 임시 고르기는 계속 「맞는지 확인」이 되므로 위 단추는 필요하다.

    애매한 판단을 고객이 정하는 방식 — 의견

    원칙. 「확인 필요」는 막다른 길이 되면 안 된다 — 모든 확인 필요 줄에는 그 자리에서 끝낼 단추가 있어야 한다(최소 「맞아요」와 「다른 걸로」). 애매함은 질문 하나 + 선택지 2~3개로 묻고, 선택지마다 보낼 고치기(/edits)가 정해져 있어야 한다.

    누가 무엇을. 모델은 정하지 않고 알린다 — 원문 근거(인용)와 해석 후보를 낸다. 코드는 후보를 실제로 찾아 검사(장소 조회 · 운영시간 · 이동)하고, 고객이 고른다. D-025 의 「모델은 분류, 코드는 사실 검사」를 묻는 자리까지 잇는 것이다.

    애매함예묻는 말 → 선택지
    장소 종류(구경 · 식사)「12:30 광장시장」이 시장 안 식당이 됨 · 「서촌 골목 걷다가」가 닭갈비집이 됨「광장시장」을 식당 「순희네빈대떡」으로 찾았어요 → 식사 — 맞아요 · 광장시장 구경 · 직접 수정 · 삭제
    장소(어느 곳)같은 이름 여러 지점 · 별칭 · 오타로 찾음 · 가까운 곳 임시 고름「○○」 맞나요 → 맞아요 · 후보 2~3 · 직접 고르기
    시간「저녁」 · 「오후」만 적음 · 「7시」를 오후로 봄몇 시인가요 → 20:00 맞아요 · 20:30 · 21:00 · 시간 고치기
    고객만 아는 것첫날 날짜 · 예약한 숙소 · 가게 이름읽는 동안 묻기(로딩 설문 자리 — 매니저 f6e50405 「빈 칸만 묻기」)

    덜 묻기. 정답표 · 정확히 같은 이름은 묻지 않는다. 같은 오독이 되풀이되면 표 · 규칙으로 고친다(「시장 = 구역」처럼). 고객이 고친 이름은 이미 별칭으로 쌓인다(다음 계획에서 안 묻는다). 「끝 시각이 없어 60분」 같은 기본값은 묻지 않고 ✎(채움)로 둔다.

    단계. ① 지금 계약 · 웹만장소 「맞아요」 · 「구경으로」 · 「직접 수정」 · 「삭제」 상자, 「이전」 표시, 바꾸기 화면 「이대로 두기」 — 서버를 바꾸지 않고 된다. ② 서버 협의애매함을 모양으로 보내기 — 검사 줄 또는 일정에 ask: {kind, quote, options: [{label, edits}]}(또는 prefill.questions[] 확장)를 실어, 웹이 문장을 읽어 짐작하지 않고 단추를 그리게 한다. 확정했을 때의 문장(「확인한 곳이에요」)과, 시간 짐작(지금 ✎ 「…두었어요 · 다르면 고쳐 주세요」)을 확인 필요로 올릴지도 같이 정한다.

    서버 · 계약

    • 지금 계약멈추는 기준 = 검사 결과의 review.items[].status: "review"(화면의 「확인 필요」). 「여행 등록」이 켜지는 ready(= 확인 필요 0)와 같은 기준이라, 끝까지 고르고 고치면 등록 버튼이 바로 켜진다.
    • 지금 계약고르기 · 고치기는 지금 호출 그대로 — POST …/edits(장소 {name} · 고른 장소 {name, latitude, longitude, source} · 「장소 없음」 {none:true} · 종류 · 시각 · 삭제), 후보 GET …/candidates, 자동 추천. 응답이 새 판의 전체 검사라, 뒤에 아직 안 그린 카드도 새 판 값으로 이어 그린다.
    • 협의 필요서버가 뒤 일정을 아직 확인하는 중(status: reading)이면 /edits 는 409 intake_not_editable 다. 안 1(화면만): 고른 값을 들고 있다가 서버 확인이 끝나면 바로 보낸다(「서버 확인이 늦을 때」 스위치). 안 2(서버): 읽는 중에도 이미 확인한 일정은 고칠 수 있게 연다.
    • 협의 필요위 「의견」의 ② — 애매함을 모양(ask)으로, 확정 문장, 시간 짐작의 확인 필요 여부. 목업의 남산서울타워 시간 줄(!)은 이 제안을 넣은 모습이고, 지금 서버는 ✎ 로 보내 멈추지 않는다(「지금 흐름」에서 확인).
    • 화면만멈춤 · 이어가기는 화면의 재생 조절(use-reveal.ts)이다. 서버가 검사하는 순서 · 내용은 그대로다.
    • 제안이동 구간만 「확인 필요」(예: 도착이 늦음)면 그 구간이 닿는 다음 카드에서 함께 멈춘다. 장소를 몰라 「–」인 구간은 멈추지 않고, 카드를 고치면 같이 다시 잰다.

    결정할 것

    1. 멈추는 기준 — 「확인 필요」 전부(✕ 고쳐야 함 · ! 주의) / ✕ 만. 목업은 전부(등록 조건과 같음).
    2. 고르지 · 고치지 않고 넘어가기 — 멘토 피드백대로면 막는다(목업 기본). 열어 두면 「이대로 두고 다음으로」새 문구 → 그 카드는 확인 필요로 남고 끝난 뒤 다시 고친다.
    3. 메뉴의 「애니메이션 건너뛰기」를 켠 사람 — 한 번에 다 그린 뒤 첫 「확인 필요」 카드로 옮겨 멈춘다(제안).
    4. 서버 확인이 화면보다 늦을 때 — 위 「협의 필요」 안 1 / 안 2.
    5. 멈춘 동안 다른 동작 — 지도 · 다른 카드 · 「전체 자동 추천」은 눌리지 않게(목업).
    6. 확정 전 카드 머리 — 원문 제목 + 「찾은 곳 「…」」 한 줄(목업) / 찾은 가게 이름을 제목으로 + 「원문 「…」」.
    7. 시간 짐작도 멈춰 물을지 — 「저녁」 · 오후로 본 「7시」 같은 것. 묻는다면 서버가 확인 필요로 올려야 한다(협의).
