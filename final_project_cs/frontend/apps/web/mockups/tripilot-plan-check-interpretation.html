계획 확인 C안 — 해석 확인 질문(P6)

계획서의 한 줄을 읽기 AI 가 일정이 아닌 것(빈 시간 · 추천 요청 등)으로 읽었을 때 서버가 내는 「해석 확인 질문」을, 첫 검사 재생이 그 줄의 시각 자리에 닿았을 때 카드 없는 질문 칸으로 멈춰 묻는다. 고르는 방식 · 다시 확인 · 흐리게 · 위 안내는 지금 앱의 멈추고 고르기(C안)와 같다.

휴대폰 화면은 실제 앱(f3604074)을 테스트용 모방 서버에 띄워 뜬 것이다(지도 바탕 그림은 뺐다). 바꾼 것은 질문 칸 · 예시 문장 · 예시 값뿐이다.

동작

  • 질문은 읽는 동안 서버에서 오지만(실시간 진행 interpretation), 묻는 때는 재생이 그 줄의 시각에 닿을 때다. 그동안 서버는 1안으로 계산을 이어 간다.
  • 멈춤 순서는 시각 순 — 장소 질문 · 늦은 도착 질문과 같은 줄에 선다. 앞 카드까지 그리고 멈추며, 다른 카드는 흐리게 · 위 안내는 고정.
  • 1안(AI 의 읽기 · 맨 위 · 서버가 이미 적용한 안): 답만 저장(POST …/interpretations — 판 안 만듦) → 질문 칸이 접히고 다음 일정으로.
  • 2안(가게 일정으로 넣기): 서버가 새 판(그 일정을 되살림) → 그 자리에 카드가 생기고 검사 줄을 다시 긋는다. 문제가 있으면 같은 카드에서 장소 · 도착 질문으로 다시 멈춘다.
  • 「이름 그대로 찾기」 · 「직접 선택」: 일정으로 넣고 바꾸기 화면의 장소 검색을 query 로 연다 → 고르면 ②처럼 다시 확인.
  • 질문 칸에 「삭제」는 없다(아직 일정이 아니다). 되돌리기도 없다(C안 규칙). 실패하면 기존처럼 남는 경고 + 질문 칸 다시 열기.
  • 「애니메이션 건너뛰기」여도 멈춘다. 검사가 끝난 접수를 다시 열면 결과 화면(멈추지 않음 — 10-20 재결정) · 답하지 않은 해석 질문은 묻지 않고 1안 그대로(아래 ①).

문구

  • 새 문구(앱에는 한국어 · 영어로 넣고 꼬리표 없음): 안내 「이 줄을 어떻게 읽을지 먼저 골라 주세요」 · 「고르면 다음 일정을 이어서 확인해요 · 남은 일정 n곳」 · 종류 칩 「읽은 뜻」 · 「추천」 · 「직접 선택」(계약의 단어).
  • 서버 문장 그대로: 질문(「계획서의 「…」를 어떻게 이해할까요?」) · 선택지 이름 · 이유(1안만) · 고르면 — 목업의 문장은 서버 코드(interpretations.py options_of · view)가 만드는 틀에 예시 값(원문 줄 · 가게 이름 · 시각)을 넣은 것이다. 1안은 AI 의 읽기 종류마다 다르다(빈 시간 · 식당을 추천받을 끼니 · 추천받을 활동 시간 · 추천 요청 · 질문 · 일정이 아닌 말). 장소를 못 찾았으면 2안은 「「정도」 11:00 일정」 하나(고르면: 일정으로 넣고 장소는 직접 골라요)뿐이다.
  • 기존 문구 그대로: 「다시 확인하는 중이에요 · 잠시만요」 · 「확인하는 중…」 · 바꾸기 화면.

정한 것 (2026-10-21 사용자)

  • ① 재생을 보지 않고 다시 연 접수(결과 화면)에서 답하지 않은 해석 질문은 묻지 않는다 — 서버가 적용해 둔 1안 그대로.
  • ② 1안에 「추천」 표시를 넣는다(서버 recommended).
  • ③ 1안을 고른 뒤 그 줄의 흔적은 결과 화면에 남기지 않는다(일정이 아니다).
