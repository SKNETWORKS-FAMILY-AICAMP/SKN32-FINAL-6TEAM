계획 확인 — 시나리오 목업

화면은 개정 6과 같다. 시나리오 7개를 단계별로 재생하면서, 단계마다 화면이 어떻게 바뀌고 서버와 무엇을 주고받아야 하는지 적었다. 백엔드 작업의 기준 화면으로 쓴다.

「지금 계약」은 팀 명세 final_project_cs/wiki/external/rest-endpoints.md의 「계획 읽기」(2026-09-27)와 서버 코드 app/modules/travel_ops/intake/를 2026-10-02에 읽고 적었다. 「협의 필요」와 「제안」은 작성자 제안이고 아직 합의하지 않았다. 장소·시각·거리는 예시 값이다.

시나리오 — 단계를 누르면 그 단계부터 재생

    애니메이션 재생 방식 — 제안

    1. 이 목업 — 단계 단위 재생 — 시나리오를 단계로 나누고 단계마다 누가(서버·사용자) 무엇을 하는지 적었다. 「재생」은 단계를 이어서 보이고, 「이전」·「다음」은 한 단계씩, 목록의 단계를 누르면 그 직전 상태를 움직임 없이 만든 뒤 그 단계만 움직인다. 사용자 단계는 누르는 자리(파란 원)를 보인 뒤 실제 버튼을 눌러 같은 코드가 돈다 — 직접 눌러 볼 때와 결과가 같다. 재생 중에 결과 화면을 직접 누르면 재생이 멈춘다.
    2. 실제 앱 — 서버는 순서, 화면은 속도 — 서버는 진행 결과를 이벤트로 순서대로 보내기만 한다. 화면은 받은 이벤트를 차례 줄에 쌓고 최소 표시 시간(예: 검사 한 줄 0.3초)을 두고 하나씩 그린다. 한꺼번에 와도 차례로 보이고, 늦게 오면 그때 그린다. 백엔드는 시간 간격을 맞출 필요 없이 이벤트의 순서와 내용만 맞추면 된다.
    3. 새로고침·다시 연결 — 지금 상태부터 — 지금까지의 결과를 한 번에 받아(접수 조회 GET) 움직임 없이 그리고, 그 뒤에 오는 이벤트부터 움직인다. 목업에서 단계를 눌러 바로 가는 것과 같은 방식이다.
    4. SSE 합의 전 — GET 재조회로 — 재조회 결과를 앞 결과와 비교해 새로 읽힌 줄·새 카드·새 검사만 같은 차례 줄에 넣으면 같은 화면이 된다. 지금 계약으로 할 수 있고, 조회 간격만큼 늦게 보인다.
    5. 움직임 줄이기 설정 — 움직임 없이 결과만 바로 그린다. 이 목업도 그 설정이면 재생하지 않고 시나리오 1의 마지막 화면으로 시작한다.

    진행 이벤트 예시 제안 — 이벤트 이름과 칸은 작성자 제안이다.

    event: stage   {"stage":"checking","label":"장소·운영시간 확인"}
event: line    {"source_id":"s1","no":3,"read":true,"found":{"index":1,"day":1,"starts_at":"11:00","title":"올리브영"}}
event: item    {"index":1,"day":1,"starts_at":"11:00","ends_at":"12:00","title":"올리브영","place":null}
event: check   {"index":1,"row":"place","result":"bad","text":"지점이 여러 곳이라 정하지 못했어요"}
event: move    {"from":0,"to":1,"mode":"walk","minutes":12,"km":0.8,"depart":"11:30","result":"warn","text":"11:42 도착 · 일정보다 42분 늦어요"}
event: done    {"stage":"review","revision":1,"needs":{"items":1,"moves":1}}

    result — ok ✓ 통과 · filled ✎ 채움 · warn ! 주의 · bad ✕ 고쳐야 함 · unknown – 아직 모름. row — 장소 place · 시간 time · 운영시간 hours · 휴무일 closed(이동은 경로 route · 수단 mode · 도착 arrival).

    백엔드에 필요한 것 — 한눈에 — 숫자를 누르면 그 시나리오

    화면에 필요한 것지금시나리오
    접수 · 진행 단계 · 읽은 줄지금 계약 접수 POST /v1/web/trip-intakes, 조회 GET …/{intake_id}의 stage · lines[].read · items[]
    지도 핀 좌표지금 계약 items[].fields.place.value의 latitude · longitude(찾은 장소만)
    「장소·운영시간 확인」 단계협의 필요 지금 단계 값은 received · transcribing · reading · review
    장소별 검사 결과(장소 · 시간 · 운영시간 · 휴무일 + 한 줄 문구)협의 필요 지금 check는 등록을 막는 문제(no_place 등)만 준다. 운영시간 · 휴무 · 겹침은 등록 때 판정한다
    장소 사이 이동(수단 · 소요 · 출발 · 도착 여유)협의 필요 지금 응답에 없다
    진행 이벤트(SSE)협의 필요 경로 · 이벤트 형식 미정. 합의 전에는 GET 재조회로 같은 화면을 만들 수 있다
    이름이 모호한 장소(예: 올리브영)협의 필요 지금 서버는 종류가 맞는 후보 중 앞뒤 일정에 가장 가까운 곳을 바로 고르고 확인 필요(needs_review)로 둔다. 후보 이름은 근거의 chosen_from에만 남는다. 이 화면은 「지점 미정」으로 두고 사용자가 고르게 했다
    대체 후보(1~3순위 · 거리 · 후보별 판정)협의 필요 지금 응답에 없다
    장소 검색 · 장소 사진협의 필요 지금 응답에 없다
    장소 · 시각 바꾸기, 삭제지금 계약 POST …/edits {revision, edits:[{source_id, field, value}]} — items[n].place({"name":…}, 서버가 다시 찾음) · starts_at · ends_at · removed. 새 판을 준다. 못 찾으면 422 place_not_found, 낡은 판은 409 stale_revision
    잠금(반드시 포함)협의 필요 수정 칸에 없다. 참고로 여행에는 예약 보호 protected_reason: booked가 있다
    검증을 끝낸 대체 일정을 한 번에협의 필요 적용은 수정 계약으로 보낼 수 있다
    재검증(저장 없이 판정만)협의 필요 지금 판정은 등록 때만 한다
    여행 등록지금 계약 POST …/confirm {revision} — 다시 조립 · 판정한 뒤 등록, 막히면 422 intake_incomplete

    서버로 보낼 값 — 재생하거나 직접 누를 때마다 쌓이는 예시, 실제로 보내지 않음

    1. 아직 없음 — 시나리오 3~7을 재생하거나 결과 화면에서 잠금·자동 추천·바꾸기·삭제를 눌러 보세요
    설계 노트 — 바뀐 점 · 작성자 가정 · 변경 기록

    S1에서 바뀐 점

    1. 일직선 진행 바 — 단계 칩 4개 대신 한 줄 위의 점 4개. 한 단계가 끝날 때마다 초록 머리가 다음 점으로 이동해 체크한다. 단계 안에서도 읽은 줄·확인한 곳 수만큼 바가 조금씩 나아간다.
    2. D화면으로 전환 — 「장소·운영시간 확인」이 시작되면 원문 카드가 사라지고 지도가 나타난다. 위쪽은 뒤로 가기와 진행 바만 남긴 얇은 막대로 줄어 지도 위에 떠 있고, 화면의 중심은 아래 시트다.
    3. 시트 안에서 스트림 — 아래 시트에서 S1처럼 장소 카드가 하나씩 생기고 검사 행이 ✓·✕로 채워진다. 장소가 확인되면 지도에 핀이 떨어지고, 지점을 못 정한 곳은 「위치 미정」으로 뜬다.
    4. 끝나면 접기 — 모두 확인되면 열려 있던 카드가 접혀 D화면처럼 닫힌 카드(시각·이름·상태)만 남는다. 이후 카드·핀을 누르면 서로 표시된다.
    5. 장소 사이 이동 — 같은 날 앞뒤 장소 사이 빈 공간에 카드가 아닌 한 줄로 최적 경로(수단·시간·구간)가 뜬다. 레일은 점선으로 바뀌어 이동 구간임을 보이고, 시각 칸에는 출발 시각(작은 점 + 「출발」)이 들어간다. 확인 단계에서 장소처럼 「찾는 중 → ✓·!」로 체크되고, 끝난 뒤 누르면 그 줄이 넓어지며 경로·수단·도착 체크리스트가 펼쳐지고 지도의 해당 구간이 파랗게 표시된다.
    6. 끝나면 여행 제목 — 카드가 모두 접히면 위 막대의 진행 바가 사라지고 D화면처럼 여행 제목(「10월 서울 여행」)이 자리를 잡는다. 「다시 올리기」는 뒤로 가기로 갈 수 있어 넣지 않았다.

    개정 4 — 결과 카드 조작과 수정 화면 — 시나리오 2~6

    1. 닫힌 카드 — 왼쪽은 잠금, 오른쪽은 상태 글자(유지·조정·확인 필요 — 와이어프레임 H와 같은 모양)와 수정·삭제 아이콘. 확인 필요 일정의 잠금은 꺼져 있다.
    2. 잠금 — 켜면 그 일정은 수정·자동 추천·삭제가 막히고, 서버에 「반드시 포함」을 알린다. 설명 아래 「서버로 보낼 값」에 예시로 쌓인다.
    3. 펼친 카드 — 맨 아래 왼쪽 「자동 추천」은 대체 후보 1순위로 바로 바꾸고 다시 확인한다. 오른쪽 「수정」은 수정 화면을 연다.
    4. 수정 화면 — 지도와 시트는 그대로 두고 내용만 바뀐다. 위 막대는 장소 검색창이 되고, 지도에는 저장된 일정 핀이 회색으로 고정되며 지금 장소와 대체 후보 핀(A·B·C)만 누를 수 있다.
    5. 옆으로 넘기는 카드 — 지금 일정(체크리스트) → 대체 후보 A → B → C. 넘기면 지도의 핀이 함께 표시되고, 시트를 위로 올리면 그 장소에 등록된 사진이 아래에 보인다.
    6. 검색 — 검색창에 쓰면 시트가 검색 결과 목록으로 바뀐다. 고른 곳은 카드로 들어가 「이 장소로 바꾸기」를 누를 수 있다.

    개정 5 — 결과 화면 맨 아래 버튼 — 시나리오 7

    1. 전체 자동 추천(왼쪽) — 사용자가 확인해서 바꿔야 하는 항목을 서버가 검증한 대체 일정으로 한 번에 바꾼다. 확인 필요 장소는 후보 1순위부터 운영시간·휴무·앞뒤 이동을 맞춰 보고 맞는 첫 곳으로, 늦게 닿는 구간은 시각을 앞뒤 이동에 맞춰 줄인다. 고정한 일정은 건드리지 않는다. 버튼의 숫자는 고칠 항목 수다.
    2. 다음 동작(오른쪽) — 확인할 항목이 남아 있으면 「재검증」이 무조건 꺼져 있다. 고친 것이 있으면 「재검증」, 고칠 것이 없고 그대로 진행할 수 있으면 「여행 등록」이다. 꺼진 버튼을 누르면 이유를 알려 준다.
    3. 재검증 → 여행 등록 — 재검증은 일정을 차례로 다시 확인하고, 통과하면 버튼이 「여행 등록」으로 바뀐다. 등록하면 「등록 완료」가 되고 이 화면의 조작은 닫힌다.

    작성자 가정 — 지시가 없어 정한 것, 바꿀 수 있음

    • ①② 단계에 보일 내용은 올린 원문의 줄이 읽히는 모습으로 채웠다. 라이브 접수 조회의 「읽은 줄」(lines[].read)에 대응한다.
    • 시트 카드 테두리는 확인 중 회색 → 끝나면 초록, 문제가 있으면 노랑으로 했다(스케치의 초록·회색). 모두 접힌 뒤에는 D처럼 기본 테두리로 돌리고 확인 필요만 노랑으로 남겼다.
    • S1의 「결과 보기」 버튼은 스트림이 결과 화면으로 바로 이어져 뺐다.
    • 스케치에 맞춰 모바일만 만들었다. PC는 같은 흐름을 D안 PC(지도 위에 떠 있는 패널)로 옮길 수 있다.
    • 장소·주소·원문·운영시간은 예시 값이고 지도는 위치 개념도다.
    • 이동 경로·소요시간·체크 항목(경로·수단·도착)은 예시 값이다. 지점이 미정인 올리브영은 가장 가까운 지점 기준으로 임시 경로를 내고 「!」로 표시했다. 다른 날로 넘어가는 이동(숙소 등)은 넣지 않았다.
    • 이동 줄은 끝난 뒤에만 펼칠 수 있게 했다(장소 카드와 같은 규칙).
    • 출발 시각은 앞 장소가 끝나는 시각으로 잡았다(경복궁 1시간 반 관람 → 11:30, 광장시장 도착 여유를 둔 12:00). 올리브영이 11:00인데 11:30 출발이라 순서가 어긋나 보이는 것 자체가 문제를 드러내도록 노랑으로 뒀다.
    • (개정 4) 자동 추천 1순위는 2차본 규칙대로 같은 종류 중 같은 날 앞뒤 일정에서 가까운 순이다. 앞뒤에 장소가 없으면 지금 장소를 기준으로 한다.
    • (개정 4) 장소를 바꾸면 상태를 「조정」으로 두고 바뀐 카드와 앞뒤 이동 줄만 다시 확인한다(S6과 같은 방식). 다시 낸 이동 줄은 거리로 계산한 예시다(1.2km 이하 도보, 그 밖은 지하철).
    • (개정 4) 잠금은 유지·조정 일정에만 켤 수 있고, 확인 필요 일정은 먼저 고쳐야 한다. 이동 줄에는 잠금·수정·삭제를 넣지 않았다(지시 범위가 장소 카드).
    • (개정 4·6) 삭제는 휴대폰 화면 가운데 알림창으로 한 번 더 묻는다(제목 「… 일정을 삭제하시겠습니까?」, 아래에 일차·시각, 버튼 취소·삭제). 처음 초점은 「취소」에 두고, 바깥을 누르거나 Esc를 눌러도 취소로 본다. 바꾸기·삭제 뒤에는 「되돌리기」를 준다.
    • (개정 4) 수정 화면 지도는 후보가 화면 밖에 있을 때만 모두 보이게 넓힌다(핀이 부드럽게 옮겨 간다). 넓히지 않아도 되면 회색 핀은 제자리에 있다.
    • (개정 4) 사진은 예시 그림이고, 검색은 목업 안의 장소 표(2차본 예시 장소 18곳)에서 찾는다.
    • (개정 4) 닫힌 카드의 펼침 표시(⌄)는 자리가 모자라 뺐다. 이름을 누르면 펼쳐진다.
    • (개정 5) 「사용자가 확인해야 하는 항목」은 머리 요약과 같은 기준이다. 확인 필요 장소와 확인 필요 이동 구간을 함께 센다.
    • (개정 5) 전체 자동 추천은 시각까지 맞춘다(예: 올리브영 → 광화문점 11:45–12:15, 앞뒤 이동에 맞춰 30분). 카드 하나의 「자동 추천」은 개정 4 지시대로 장소만 바꾼다.
    • (개정 5) 잠금은 수정으로 치지 않아 재검증이 필요 없다. 장소 바꾸기·삭제·전체 자동 추천은 수정으로 친다. 되돌리기로 이전 상태로 돌아가면 수정 여부도 함께 돌아간다.
    • (개정 5) 재검증은 모든 일정을 차례로 다시 확인하는 모습으로 보였다. 여행 등록 뒤에는 이 화면의 조작을 막는다(실제로는 여행 화면으로 넘어감).
    • (개정 7) 시나리오를 고르면 첫 단계부터 바로 재생한다. 「⏸ 멈춤」은 지금 단계를 끝까지 보인 뒤 멈춘다.
    • (개정 7) 단계로 바로 가면 앞 단계를 움직임 없이 다시 만든 뒤 그 단계만 움직인다. 그래서 앞 단계에서 뜬 알림이 잠시 남아 있을 수 있다.
    • (개정 7) 재생 중 결과 화면을 직접 누르면 재생이 멈춘다. 그 뒤 「다음」은 다음 단계의 시작 상태를 다시 만든다.
    • (개정 7) 「서버로 보낼 값」은 수정 계약 모양으로 쌓는다. source_id s1은 예시 원본 id이고, 보낼 때마다 revision이 하나씩 는다고 가정했다.

    변경 기록

    • 2026-10-02 개정 7 — 시나리오 목업으로 바꿨다. 화면은 개정 6과 같고, 시나리오 7개(계획 확인 진행 · 결과 보기 · 자동 추천 · 수정 화면 · 잠금 · 삭제 · 전체 자동 추천 → 재검증 → 여행 등록)를 단계 단위로 재생한다(재생 · 이전 · 다음 · 단계로 바로 가기 · 누르는 자리 표시 · 화면만 보기). 단계마다 서버와 주고받을 값을 「지금 계약 · 협의 필요 · 제안 · 화면만」으로 나눠 적고, 애니메이션 재생 방식 제안과 「백엔드에 필요한 것」 표를 더했다. 「서버로 보낼 값」을 수정 계약 모양({revision, edits:[{source_id, field, value}]})으로 맞췄다. 위 막대의 단계 버튼, 「단계별 화면」, 「API 메모」, 「해 볼 것」은 시나리오와 표로 옮겼다.
    • 2026-10-02 개정 6 — 삭제 확인을 카드 안의 확인 줄(「이 일정을 뺄까요?」 취소·빼기)에서 휴대폰 화면 가운데 알림창으로 바꿨다. 「○○ 일정을 삭제하시겠습니까?」와 일차·시각을 보이고 취소·삭제로 정한다. 휴지통 이름·삭제 뒤 알림·막힘 안내·「서버로 보낼 값」의 이름도 「삭제」로 맞췄다.
    • 2026-10-02 개정 5 — 결과 화면 맨 아래에 왼쪽 「전체 자동 추천」, 오른쪽 다음 동작 버튼을 넣었다. 확인할 항목이 있으면 재검증이 꺼지고, 고쳤으면 「재검증」, 고칠 것이 없으면 「여행 등록」이다. 재검증 → 여행 등록 → 등록 완료 흐름과 「다시 확인 중」 상태를 여러 카드에 함께 쓰도록 바꿨다.
    • 2026-10-02 개정 4 — 모바일에서 만든 개정 3을 기준으로 이어 작업했다. 닫힌 카드에 잠금·상태 글자·수정·삭제를, 펼친 카드에 자동 추천·수정 버튼을 넣었다. 같은 화면 안의 수정 화면(검색창, 회색 고정 핀과 대체 후보 핀, 옆으로 넘기는 후보 카드, 시트를 올리면 보이는 사진)을 만들었다. 바꾸기·빼기·되돌리기와 「서버로 보낼 값」 예시 기록을 더했다.
    • 2026-10-02 개정 3 — 이동 줄의 시각 칸에 출발 시각을 넣었다(장소 시각보다 작고 옅게, 레일에 작은 점). 경로를 찾은 뒤 나타나고, 늦는 구간은 노랑으로 보인다.
    • 2026-10-02 개정 2 — 카드가 접힌 뒤 위 막대를 진행 바 대신 여행 제목으로 바꿨다(D화면 참고, 「다시 올리기」 제외). 장소 사이 빈 공간에 이동 최적 경로 줄을 넣고, 누르면 넓어지며 이동 체크리스트가 보이게 했다. 진행 바·시트 머리 개수에 이동 구간을 포함했다.
    • 2026-10-02 개정 1 — 진행 바 아래의 상태 문구 줄(「정리 완료 · 4곳 중 1곳만…」 등)을 없앴다. ③부터 위에 떠 있는 부분을 한 줄(뒤로 + 진행 바)로 줄였다(높이 약 120px → 42px). 줄인 만큼 시트 기본 높이를 390px → 440px로 키웠다.
