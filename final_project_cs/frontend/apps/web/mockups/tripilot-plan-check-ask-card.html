계획 확인

이유 · 고르면 원칙(지금 서버 값만)

  1. 이유는 사실이라 서버 값만 — 서버 문장(검사 줄 · 후보 조회의 reason)은 그대로, 숫자 · 이름은 서버 칸에서만 끼운다. 서버 값이 없으면 이유 줄을 뺀다(짓지 않는다).
  2. 고르면은 그 단추가 하는 일 — 프론트가 정한 고정 문장. 「바꾸고 · 다시 확인해요」까지만 말하고 결과(영업시간이 맞는다 등)는 약속하지 않는다 — 결과는 다시 확인한 뒤 검사 줄이 말한다. 앱에 있는 문장을 먼저 쓴다.
  3. 질문은 원인별 고정 틀 + 서버 값(원문 제목 · 찾은 이름 · 날짜 · 후보 수). 못 찾은 장소만 서버 질문 문장 그대로.
  4. 카드 안 형식에서는 바로 위 검사 줄과 같은 이유를 숨긴다(같은 말이 두 번 나오지 않게). 아래 시트 형식은 검사 줄이 안 보이므로 보인다.
  5. 후보 이유는 후보 조회 응답이 와야 보인다 — 그동안 「찾는 중」, 후보가 0곳이면 서버 notes 대로 안내(지금 바꾸기 화면과 같음). 서버 문장(검사 줄 · 후보 이유)이 영어 화면에서 영어로 오는지는 계약에 없다(협의).

두 판의 차이

지금 서버 값만서버 협의안(ask)
질문 · 선택지를 정하는 쪽프론트 — 확인 필요 원인(구조 값)마다 정해 둔 틀서버 — 일정마다 ask(질문 · 원문 인용 · 선택지 · 이유 · 고르면 · 추천 · 보낼 요청)
다른 해석(빈 시간 · 장소)못 한다 — 서버가 해석 하나만 정해 보낸다. 모델이 빈칸으로 읽은 흔적(understanding.gaps)이 있어도 「그 시간대 채우기」 요청이 없어 「준비 중」된다 — 버린 해석도 선택지로 온다
추천 · 나머지는 추천대로없음 — 서버가 추천을 정해 보내지 않는다. 「지금 값으로 두기」로 대신하면 오타 · 임시 고름을 묻지 않고 확정하게 된다된다
이유 · 고르면이유 = 서버 문장 · 서버 값만(없으면 뺌), 고르면 = 프론트 고정 문장서버가 보낸다
서버 변경없음(지금 계약)접수 응답에 ask 칸 추가 · 「빈 시간 채우기」 요청 하나 추가(협의)

조사 결과 — 「오후 13시~16시 정도」

  1. 규칙 읽기가 이 줄을 제목 「정도」 · 13:00~16:00 일정으로 읽는다(「정도」(쯤)를 장소 이름으로 봄, 제목에 확인 표시 없음). 서버 코드 실행rules.read_plan
  2. 장소 찾기가 「정도」를 요식 원장 「정돈 대학로본점」과 오타로 일치시킨다(자모 거리 0.17 ≤ 기준 0.2). 관광공사 · 카카오보다 먼저라 서버 키와 상관없다. 서버 코드 실행places.resolve · 로컬 시험 DB(원장 1,888곳)
  3. 이해 에이전트가 이 줄을 「빈 시간」(free_slot)으로 읽어도, 빈칸 인용 안에 그 일정 제목이 들어 있으면 서버는 「이름을 적은 자리」로 보고 빈칸을 버린다(prefill._item_for_quote). 흔적은 sources[].understanding.gaps에만 남는다.
  4. 의견 이미지의 「식당 「정도」에서 13시 식사」는 만들 수 없는 선택지다 — 원장에 「정도」라는 가게가 없어, 그 이름으로 다시 찾으면 같은 오타 결과가 나온다. 두 판 모두 뺐다.
  5. 근본 원인은 「정도 · 쯤 · 경 · 즈음」 같은 말을 장소 이름으로 읽는 것이다 — 규칙 읽기에서 빼는 것은 서버 몫(협의).

프론트가 원인을 가르는 기준(지금 서버 값)

  • 물어볼지: 일정의 review.items[].status === "review" 만 쓴다. 칸의 needs_review 는 쓰지 않는다 — 오라클 실서버 기록(10-12)에서 「광화문 근처 한식」→「광화문」은 칸이 true 인데 일정은 통과였다.
  • 무엇을 물을지: rereads(두 읽기) → prefill.questions 의 place_not_found(못 찾음 — role-manager 에만 있고 develop 에는 아직 없음) → place_state(picked_nearest 여러 곳 중 임시 · needs_choice/needs_name 이름 없는 줄) → 장소 줄 주의 + 근거 evidence.method(typo 오타 · tried 의 alias: 별칭 · 그 밖 원문과 다른 이름) → closed/hours 줄(휴무 · 운영시간) → 이동 status(늦게 닿음) 순.
  • 시간 짐작(「오후로 봤어요 — 다르면 고쳐 주세요」)은 지금 ✎(채움)로 와서 확인 필요가 아니다 — 묻지 않는다.

결정할 것

  1. 어느 판으로 — 「지금 서버 값만」을 먼저 웹에 넣고 ask 는 서버 협의 뒤 / 처음부터 ask 로.
  2. 「빈 시간」 안 — 지금 판에서 「준비 중」으로 보일지(목업) / 뺄지.
  3. 「직접 선택」 · 「직접 수정」 — 하나로(목업은 「직접 수정」 = 지금 「바꾸기」 화면: 후보 · 검색 · 이름 · 날짜 · 시각).
  4. 「나머지는 추천대로 두기」 — 멘토 피드백(먼저 고치고 넘어가기)과 부딪친다. 둘지, 협의안에서도 뺄지.
  5. 형식 — 카드 안(목록 그 자리에서 펼침 · 앞뒤 일정과 시각이 같이 보임) / 아래 시트(질문이 크게 보임 · 목록은 위에 조금만 보임).
  6. 멈추고 고치기와 합칠 때 — 카드 안 형식이면 검사 재생이 멈춘 카드에 이 선택지를 그대로 넣는다. 아래 시트 형식이면 멈춘 카드를 밝게 두고 시트를 올린다.
