등록 후 채팅 배치 비교

작성일 2026-10-06 · 개정 2026-10-07(C안 추가) · 상태: 검토용 비교안 / 실제 API 미연결. 장소·시각·이동·답변은 예시 값이고 지도는 위치 개념도다. 세 휴대폰 모두 「여행 등록」을 누르면 같은 화면에 머물고, 하단 버튼 줄 대신 오른쪽 아래 채팅 버튼이 뜬다.

A일정 자리에 채팅

채팅 버튼을 누르면 아래 시트의 타임라인 자리가 채팅으로 바뀐다. 지도와 일차 칩은 그대로 보이고, 핀을 누르면 물어볼 일정이 바뀐다.

B채팅 화면으로 이동

채팅 버튼을 누르면 채팅 화면이 옆에서 들어온다. 뒤로 가면 보던 일차·선택 그대로 일정 화면으로 돌아오고, 답에 나온 장소는 「지도에서 보기」로 돌아가 확인한다.

C채팅 막대 + 옆으로 넘기기

채팅 버튼을 누르면 버튼이 옆으로 늘어나 입력 막대가 된다 — 일정을 보면서 바로 보내고, 보내면 답을 보러 채팅으로 넘어간다. 일정 목록을 옆으로 밀면(또는 머리의 「일정 | 채팅」) 같은 시트 안에서 채팅으로 넘어간다.

세 안 공통

확인된 사실 — 지금 앱(2026-10-06, 091a4b9)

  • 「여행 등록」 뒤 하단 버튼이 「✓ 등록 완료」 링크로 바뀌고, 누르면 여행 화면(/trips/[id])으로 넘어간다.
  • 여행 화면은 일정·지도·채팅 탭(하단 메뉴)과 살펴볼 점·받은 알림·변경 이력, 여행계획서 열기·내려받기, 새 계획 올리기를 가진다.

이 목업의 제안

  • 등록해도 화면을 넘기지 않는다. 하단 버튼 줄을 없애고 오른쪽 아래에 채팅 버튼을 띄운다. 시트 제목은 「등록 완료」, 카드의 고정·수정·삭제는 흐리게 둔다(지금 등록 뒤와 같다).
  • 받은 알림·변경 이력은 시트 맨 위 한 줄로 접어 둔다 — 자리는 가정이며, 채팅 비교에 영향이 없게 세 안을 같게 했다.
  • 채팅 버튼이 마지막 카드의 삭제 버튼을 가리지 않게 등록 뒤 목록 아래에 여백(88px)을 둔다.
  • 채팅 연결: 지금 계약의 여행 대화(POST /v1/web/trips/{id}/messages)와 알림(GET /v1/web/trips/{id}/notices)을 등록으로 받은 여행 ID로 부르면 된다고 본다 — 구현 때 확인한다. 목업의 답은 미리 적어 둔 예시다.

미정 — 정해야 할 것

  • 여행 화면에만 있는 것의 자리: 여행계획서 열기·내려받기, 새 계획 올리기, 일정 펼침 상세(주소·전화·영업시간), 지도 앱 길찾기.
  • 「내 여행」 목록에서 다시 열 때(/trips/[id])도 이 화면으로 열지.
  • 채팅에서 일정을 바꾼 뒤(되돌리기·선택지) 타임라인과 지도를 언제 다시 그릴지.

A안 · 일정 자리에 채팅

좋은 점

  • 지도를 보면서 묻는다. 핀을 누르면 물어볼 일정이 바뀌고, 답에 나온 장소를 누르면 지도에 바로 표시된다.
  • 등록 전과 같은 지도·시트·일차 칩 구조가 끝까지 유지된다.

걱정되는 점

  • 대화 칸이 좁다. 이 목업(390×820)에서 대화 기록 칸은 약 240px(B안은 약 570px)이고, 휴대폰 키보드가 올라오면 더 줄어든다(실기기 미확인).
  • 시트 끌기·일차 넘기기 몸짓과 대화 스크롤이 같은 영역에서 겹친다. 구현 때 몸짓 범위를 나눠야 한다.

B안 · 채팅 화면으로 이동

좋은 점

  • 대화 칸이 넓고(이 목업에서 약 570px) 키보드 처리가 단순하다. 지금 여행 화면의 채팅 구성(빠른 질문 4개·입력·되돌리기·선택지)을 거의 그대로 옮길 수 있다.
  • 일정 시트의 몸짓과 분리된다.

걱정되는 점

  • 대화 중에는 지도를 못 본다. 장소는 「지도에서 보기」로 돌아가 확인한다.
  • 화면 이동이 하나 생긴다. 새 주소로 둘지, 같은 주소 위 덮개로 둘지에 따라 브라우저 뒤로 가기 동작이 달라진다(미정).

C안 · 채팅 막대 + 옆으로 넘기기

좋은 점

  • 일정을 보면서 바로 묻는다. 막대가 일정 위에 떠 있어 화면을 바꾸지 않고 입력하고, 보내면 답을 보러 채팅으로 넘어간다.
  • 지도는 그대로 남고 일정 ↔ 채팅을 손가락 한 번으로 오간다. 머리의 「일정 | 채팅」으로도 넘긴다(밀기를 모르는 사람·키보드용).
  • 입력칸이 막대 하나라 일정 쪽과 채팅 쪽 입력이 어긋나지 않는다.

걱정되는 점

  • ★지금 앱의 계획 확인 화면은 일정 목록을 옆으로 밀면 다음 날로 넘어간다(「옆으로 밀면 2일차 일정이 나와요」, use-day-gestures). 같은 몸짓이라 겹친다 — 「마지막 날에서 한 번 더 밀면 채팅」, 「머리줄을 밀어야 채팅」, 「일차는 칩으로만 넘기기」 중 하나를 정해야 한다. 이 목업은 일차 넘기기를 넣지 않았다.
  • 대화 칸은 A안처럼 시트 안이라 좁다(이 목업에서 약 220px — A안 약 240px, B안 약 570px). 막대가 시트 아래를 덮어 목록·대화 끝에 여백이 필요하다.
  • 막대를 편 채 일정을 보면 휴대폰 키보드가 일정 절반을 가린다(실기기 미확인).
