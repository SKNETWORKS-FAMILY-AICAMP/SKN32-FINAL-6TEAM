  - 프론트는 화면·동작과 데이터 계약(`model.ts`의 `PlanCheckView`, `plan-check.tsx`의 `PlanCheckActions`)을 둔다.

계획 등록(`/trips/new`)에서 「계획 확인하기」를 누른 뒤의 흐름이 이 화면이다(실제 경로 `/intakes/[intakeId]`).
- **누르는 순간 곧바로 이 화면으로 넘어간다** `[2026-10-03 사용자 지시]` — 서버의 답을 등록 화면에서 기다리지 않는다.
  1. 등록 화면이 보내기를 시작하고(`lib/live/intake-start.ts`의 `beginIntake`) `/intakes/starting` 으로 간다.
  2. 거기서는 같은 진행 화면에 **올린 글의 줄**(`sendingOf` — 서버와 같은 줄 번호, 읽힌 것 없음)과 「계획을 서버로 보내는 중이에요…」(파일이면 「올리는 중」)를 보인다.
  3. 서버가 접수 번호를 주면 접수를 한 번 읽어 두고(불러오기 화면이 한 번도 뜨지 않게) `/intakes/[번호]` 로 바꿔 간다. 거기서 서버의 진행 알림(SSE)이 막대와 줄·장소·검사를 이어서 그린다.
  4. 서버가 거절하면 등록 화면으로 돌아가 서버 문장을 보이고, 쓴 글과 올리려던 파일(「계획 짜 주기」였다면 고른 조건)은 그대로다. 보내는 중 뒤로 가면 보내기를 멈추고(고른 칸·파일·조건은 돌려준다), 새로고침하면(보내던 계획은 메모리에만 있다) 등록 화면으로 돌아간다.
  - 사람 확인(Turnstile)을 쓰는 서버에서 키가 없는 새 고객만 키 발급과 새 확인표를 위해 등록 화면에서 잠깐 기다린다(두 확인 모두 그 화면에 있다).
- **계획 짜 주기(등록 화면의 세 번째 칸)는 읽을 계획이 없어서 다른 진행 화면으로 간다** `[2026-10-03 사용자 지시]` — 같은 `/intakes/starting` 이 「일정을 짜는 중이에요」(`features/plan-check/planning-progress.tsx`)를 보인다.
  1. 접수를 만든다. 글은 「원하는 여행」(선택, 비우면 빈 글)뿐이다 — 쓴 글·고른 파일은 가지 않는다.
  2. 서버가 그 글을 다 읽을 때까지 기다린다(읽는 중이면 1.5초마다 다시 묻고 서버가 말하는 읽는 단계를 그대로 보인다. 5분이 넘으면 문장으로 알린다). 서버는 읽기가 끝난(`review`) 접수에만 짜기를 받는다(아니면 409 `intake_not_ready`).
  3. 그 판(`revision`)으로 `POST …/plan` 을 스트림으로 부른다 — `{start_date, days, party_size, keep_read_items: false, survey?}`. 서버가 말하는 단계 `planning` → `checking`(읽은 일정과 합칠 때만) → `registering` 을 그대로 보이고, 막대는 서버가 말한 단계에 서 있다(지어낸 진행률 없음).
  4. 끝나면 여행 목록 캐시를 지우고 여행 화면으로 간다. 서버가 거절하면(접수든 짜기든) 등록 화면으로 돌아가 서버 문장을 보이고, 고른 칸 · 조건 · 쓴 글이 그대로 남는다.
  - 요청이 나간 뒤(짜는 동안)에는 뒤로 가는 화살표를 두지 않는다 — 끊어도 서버는 등록을 끝낼 수 있다. 접수·읽기 중에는 뒤로 갈 수 있고, 그러면 짜 달라는 요청은 나가지 않는다.
  - 「서버가 답하는 데 시간이 걸리고 있어요」(4초 · 15초) 안내는 **접수 번호를 받기 전**에만 맞는 말이다. 짜기에 들어가면 서버가 말하는 단계가 우선한다.
- **옛 목록형 접수 확인 화면은 없앴다** `[2026-10-03 사용자 결정]` — 카드를 펼쳐 고치던 화면, 「읽은 일정이 없어요 — 대신 짜 드릴까요?」 칸, 「읽은 원문 전체 보기」, 결과 맨 아래의 「이전 확인 화면 열기」가 함께 사라졌다. `features/intake-review/` 에는 접수 화면의 틀(`intake-review.tsx`)·진행 화면(`intake-starting.tsx`)·데이터 변환(`model.ts` · `stream-model.ts` …)만 남는다.
  - **일정 짜기는 등록 화면의 세 번째 칸 「계획 짜 주기 (테스트)」가 한다** — 첫날 · 일수(1~7) · 인원(1~4) + 원하는 여행을 적는 선택 글. 등록 화면의 입력은 세 칸이고(직접 입력 · 파일 선택 · 계획 짜 주기) **마지막에 고른 칸만 보낸다**. 고른 칸이 비어 있으면 「계획 확인하기」가 꺼지고 이유를 한 줄로 말한다.
  - **서버가 글을 읽었는데 일정이 하나도 없으면** 결과 화면 대신 짧은 안내(「읽은 일정이 없어요. 원문을 확인해 다시 올리거나, 등록 화면의 「계획 짜 주기」를 써 보세요」)와 등록 화면으로 가는 링크 하나만 나온다. 글에서 「짜 달라」는 요청을 읽었으면 안내가 「계획 짜 주기」에서 첫날 · 일수 · 인원을 고르라고 말한다. ★고객이 일정을 **모두 지운** 경우는 이 안내가 아니라 결과 화면의 「남은 일정이 없어요」다(읽은 일정이 있었으니까). 일정이 읽혔는데 글에 「짜 달라」는 말도 있으면 결과 화면 위에 한 줄로 그 사실을 알린다. 이미 여행으로 등록한(짜서 등록한) 접수에 일정이 없으면 그 여행으로 가는 링크를 준다.
  - 옛 화면에 있던 「장소 정보 출처 : ⓒ한국관광공사 · 저작권 정책」 줄은 새 확인 화면의 **목록 맨 아래**로 옮겼다(`[2026-10-03]` — 루트 「출처 표시 유지」). 후보·검색 카드의 출처 이름표와 사진 설명의 「ⓒ한국관광공사」는 그대로다.

## 2. 화면이 하는 일

**받은 순서대로, 화면 속도로 그린다**
- 화면은 `PlanCheckView` 스냅숏만 받는다.
- 앞 스냅숏과의 차이를 한 번에 하나씩 그린다. `[2026-10-04]` 확인 표시는 **한 줄에 0.3초**(알아볼 속도 — 앞 판은 4초 안에 끝내려고 0.035초까지 줄여 후루룩 지나갔다). 큰 계획은 줄 단위가 아니라 **카드 단위**로 그려 전체가 14초 안에 끝난다(줄 간격은 0.2초 밑으로 줄이지 않는다). 아래 개정 1 참고. ~~★한꺼번에 많이 밀리면 간격을 줄여 전체가 약 8초 안에 그려진다(최소 0.035초)~~ — 실서버가 14곳 검사를 한 번에 내면 0.28초로는 한 분 가까이 뒤처졌다. 순서: 읽기 시작 → 줄 → 날짜 → 확인 시작 → 하루 순서대로 장소·이동(나타남 → 검사 한 줄씩 → 판정) → 정리 완료 → 제목.
- 서버가 한꺼번에 보내도 나눠 보내도 같은 순서로 보인다(단위 시험). 「움직임 줄이기」 설정이면 바로 그린다.
- 바꾼 일정을 다시 확인할 때도 같다: 그 일정과 앞뒤 이동이 「확인 중」이 되고 검사 줄이 다시 채워진다.
- **그리는 동안 목록이 새 항목을 따라 내려간다** `[2026-10-03 사용자]` — 읽는 화면은 읽는 줄을, 확인 시트는 가장 새로 생긴 일정·이동 줄을 보이는 자리로 부드럽게 따라간다(`use-follow-scroll.ts`). 손으로(휠·터치·키·스크롤바) 위로 올리면 따라가기를 멈추고 목록 맨 아래에 「확인 중인 곳으로」 단추가 뜬다. 바닥 근처로 돌아오거나 그 단추를 누르면 다시 따라간다. 「움직임 줄이기」 설정이면 부드럽게 하지 않고 바로 간다. 실서버로 잰 26줄 계획에서 맨 아래 위치가 줄이 늘 때마다 함께 내려갔다.

**결과 화면(시나리오 2)**
- 카드 머리(제목 버튼)를 누르면 펼쳐진다. 한 번에 하나, 이동 줄도 같다.
- 카드를 고르면 지도에 그 날과 핀이 선택되고, 핀을 누르면 그 카드가 펼쳐진다.
- 일차 머리를 누르면 그 날 지도로 바뀐다. 손잡이는 누르면 시트를 중간 → 높게 → 낮게 돌린다.
- **목록 높이는 잡고 끌어 원하는 높이로 맞출 수 있다** `[2026-10-03 사용자]` — 손잡이나 머리를 잡고 위아래로 끌면 그 높이(최소 120px, 지도 위 64px까지)로 따라오고(끄는 동안은 부드럽게 늦추지 않는다), 키보드 위·아래 화살표는 40px씩. 끌고 난 뒤 손잡이를 누르면 눈금(중간)으로 돌아간다.
- **목록 끝에서 한 번 더 밀면 "권장 수정안이 반영된 모습"으로 넘어간다** `[2026-10-03 사용자]` — 목록 맨 아래의 안내(「계속 내리면 …」, 누를 수도 있다)가 밀수록 차오르고(마우스 휠 약 110px, 터치로 끌어 올리면 110px), 차면 서버의 전체 자동 추천을 한 번 불러 목록이 아래에서 올라오듯 바뀐다. 바뀐 일정에는 「바뀜 · 이전 ○○」, 맨 위에 「권장 수정안을 반영한 모습이에요 · N곳이 바뀌었어요 [원래대로]」. 맨 위에서 위로 한 번 더 밀거나 [원래대로]를 누르면 되돌린다(전체 되돌리기). 끝에 닿은 직후의 관성(휠이 스스로 굴러가는 것)과 목록 중간에서 시작한 터치는 밀기로 세지 않는다. ★서버에 미리보기 호출이 없어 지금은 「적용 → 되돌리기」로 대신한다(백엔드 제안: `autofix` 의 `dry_run`).
- 시트 머리: `[2026-10-04]` 문장이 아니라 표시 — 「! 2」(확인 필요 2곳) · 「✎ 1」(바뀐 곳 1곳) · 「✓」(고칠 곳 없음) · 「2/4」(다시 확인 중) · 「등록 완료」. 누르면 그것만 모아 보인다. 제목은 수정안을 보는 동안 「수정안」.

**카드 도구(시나리오 3·5·6)**

**삭제(시나리오 6)** `[2026-10-04 사용자 지시]` — 확인창은 없앴다. 휴지통을 누르면 **지우지 않고** 카드가 회색이 되고(「삭제 예정」, 지도 핀도 회색) 휴지통 자리에 「되돌리기」가 선다.

**하단 버튼(시나리오 7)**

**공통**

    - **되돌리기와 초기화**: 처음 화면을 열었을 때와 시간이 다른 일정에는 수정·삭제 앞에 「되돌리기」가 붙고(그 일정만 처음 시간으로, 필요하면 앞뒤를 밀어 자리를 낸다), 시트 머리에 「시간 초기화」가 생겨 바꾼 시간을 한 번에 모두 처음으로 돌린다. 범위는 **시간뿐**이다 — 장소를 바꾼 것·삭제 표시는 건드리지 않는다.
    - 끝이 시작보다 빠르면 서버에 보내기 전에 화면이 먼저 막는다. 그 밖의 맞고 틀림(운영시간 등)은 서버가 다시 확인한다.
10-1. **여유부터 줄이고 · 다 쓰면 한 번 멈춰 안내 · 더 끌면 밀기** `[2026-10-05 사용자 지시 「좋아 그 방식으로」]`: 시간을 늦추거나 당길 때 **일정 사이의 여유부터** 쓴다 — 여유 안에서는 아무도 안 움직인다(`time-plan.ts` `ownRange`). 여유가 0분이 되는 자리에서 끌개가 **한 번 멈추고**(`holdAtLimit` — 그 뒤로 10분 거리 `DETENT_MINUTES` 더 끌어야 풀린다) 지금 쓰는 알림(토스트)으로 「여유를 다 썼어요 · 더 늦추면 뒤 일정이 밀려요」(당길 때는 「앞 일정과 붙었어요 · 더 당기면 앞 일정이 당겨져요」)를 **한 번만** 알린다 — 알림이 떠 있는 3.5초 동안은 다시 안 뜬다. 멈춤을 넘어 계속 끌면 다음 일정이 필요한 만큼만 차례로 밀린다(`moveStop` 의 밀기, 잠금·예약 일정은 벽). 「−5분」「+5분」 단추와 화살표 키도 같다 — 여유 끝에서 한 번 멈춰 알리고 **다음 누름**부터 민다. 「앞뒤 일정도 함께 밀기」를 끄면 멈춤 없이 여유 끝이 범위의 끝이다.
    - **이동 줄의 「출발」 시각도 같은 방식**: 왼쪽의 출발 시각(`10:30 출발`)을 누르면 그 자리에 편집기가 열린다(`use-time-edit.ts` `kind: "depart"`). 고치는 것은 **앞 일정의 끝**(= 떠나는 시각; 이 화면의 미리 그림 `withTimes` 가 출발을 `시작 + 머무는 시간` 으로 그린다)이고, 늦게 나서면 여유가 줄고, 여유를 다 쓰면 멈춘 뒤 다음 일정이 밀린다(`moveEnd` · `endRanges`). 일찍 나서면 여유가 늘 뿐 아무도 안 움직인다. 서버에는 다른 시간 고치기와 같은 `/edits` 한 번(앞 일정 `ends_at` + 밀린 일정의 `starts_at`·`ends_at`)으로 간다. ★서버가 이동의 「출발」을 독립 값이 아니라 계산값(다음 일정 시작 − 이동 − 여유)으로 둔다면 앞 일정의 끝을 바꿔도 서버가 다시 그리는 「출발」이 안 변할 수 있다 — **실서버 확인 안 함**(등록된 여행에는 아직 시각을 받는 입구가 없다 — cs 세션이 「일정 안 항목 편집」 계약 하나로 접수).
    - **끄는 동안 하루 미니맵**(`time-drag-overlay.tsx` · `day-minimap.ts`): 끌개를 잡고 있는 동안 지도 위쪽에 겹쳐서 — 무엇을 얼마나(「시작 09:00 → 09:15 (+15분)」) · 여유를 다 썼다는 안내 · **그날 일정 전체를 한 줄 띠로**(점선 테두리 = 원래 자리, 채움 = 지금 놓일 자리; 끄는 일정은 초록, 밀리는 일정은 주황, 잠근 일정은 흐리게) · 「다른 일정 N곳이 움직여요 · 가장 많이 +n분 · 하루 끝 a → b · 여유 m분」을 보인다. 손가락이 끌개에 있으므로 터치를 받지 않는다. 손을 떼면 사라진다.
10-2. **일정 상자 · 이동 줄 · 내 여행 칩** `[2026-10-05 사용자 선택 — 일정 상자 안 B · 내 여행 칩 안 A]`:
    - **시간 열 고정**: 시간(44px) · 원(18px) · 상자가 모든 줄에서 같은 자리에서 시작하고 간격은 8px 로 같다. 시간은 계획을 확인한 뒤 단추가 되는데 단추가 글자를 줄 한가운데로 내려 원 아래로 처지던 것을 고쳤다(위에 붙이고 한 줄 18px 의 가운데를 원의 가운데에 맞춤).
    - **이동 줄은 한 줄**: 「지하철 3호선 9분 · 0.6km  여유 21분」 — 수단 이름 · 시간 · 거리와 여유를 같은 줄에 보인다(수단 이름을 다시 보인다). 여유는 15분 이상일 때만 말하고, 모자라면 같은 자리에 「N분 늦어요」(주황). 일정 사이 간격이 여유만큼 벌어지는 것은 그대로(글자 없는 빈 간격 `freeGap`).
    - **내 여행 칩**: 계획 이름 칩은 글자 길이만큼(최대 11.5em)만 차지하고 로고 바로 옆 왼쪽에 선다. 누르면 오른쪽으로 길어져 이름 전체와 연필이 보이고, 이름을 한 번 더 누르면 바로 입력칸이 열려 키보드가 뜬다(연필은 같은 동작의 다른 길).
10-3. **스크롤 끝 — 권장 수정안이 없을 때** `[2026-10-05 사용자 선택 — 안 A]`:
    - 서버가 「바꿀 곳이 없다」고 한 계획이면(화면이 열릴 때 미리 받아 둔 확인에서 알아낸다 — `hasRecommendation`) 목록 맨 끝의 「계속 내리면 권장 수정안이 …」 표시는 **처음부터 꺼져 있고** 「권장 수정안이 없어서 더 보여 드릴 게 없어요」라고 말한다.
    - 그래도 더 밀거나 그 표시를 누르면 **화면은 그 자리에 있고**(고칠 곳으로 끌고 가지 않는다) 목록이 옆으로 살짝 흔들리며 「권장 수정안이 없어요 · 확인이 필요한 곳은 직접 고쳐 주세요」 알림이 **한 번만** 뜬다 — 알림이 떠 있는 동안(과 그 직후)의 또 밀기·누르기는 무시한다.
    - 일정이 바뀌면(`planKey`) 「없다」는 기억이 낡아 표시가 다시 켜진다. 아래 「전체 자동 추천」 단추는 전과 같다 — 못 바꾸면 사용자가 직접 고쳐야 하는 첫 곳으로 데려간다(2026-10-03 결정).
10-4. **시간 조정 합친 안** `[2026-10-05 사용자 선택 — 시간 조정 안 C]`:
    - **바로 끌기**: 일정 시간(또는 이동의 「출발」 시각)과 그 옆 원을 **탭 없이 잡고** 위아래로 끌면 시간이 바뀐다(위 = 일찍, 아래 = 늦게, 10px = 5분 · 여유부터 줄이고 다 쓰면 한 번 멈추는 규칙은 그대로). 6px 넘게 움직이면 끌기, 움직이지 않으면 탭(전처럼 폼이 열린다). 끄는 동안 폼은 열리지 않아 목록이 밀리지 않고, 하루 미니맵 안내만 뜬다. 놓으면 한 번에 저장되고, 보낼 수 없는 값이면 그때 폼이 열려 이유를 말한다. 고정·예약·삭제 예정 일정의 시간은 잡아도 움직이지 않는다(누르면 이유).
    - **탭하면 폼**: 시작·끝 숫자가 크게(19px) 팝업처럼 나타나고(숫자를 누르면 시·분 직접 입력), 아래 줄에 끌개와 「−5 · +5」 알약 단추와 가능한 시각, 맨 아래 한 줄에 **아이콘 단추**(되돌리기 · 취소 ✕ · 적용 ✓)가 선다. 되돌리기는 바꾼 시간이 있을 때만 보인다.
    - 터치에서 시간·원 위로 시작한 손가락은 목록을 스크롤하지 못한다(`touch-action: none`) — 그 좁은 자리(시간 44px · 원 주변 26px)만이다. 실기기 엄지 조작은 아직 확인하지 못했다.
10-5. **지도 단추 · 거리 눈금 · 화면 밖 일정 칩 · 첫 시점** `[2026-10-05 사용자 선택]`:
    - **단추는 세 지도(무료 · 구글 · 네이버)가 같다** — 지도 SDK 의 자체 단추를 끄고 화면이 직접 그린다(`map-controls.tsx`). 순서는 ＋ · **거리 눈금** · － · 모든 일정 보기 · 내 위치로(위치 동의가 있을 때만 — 동의가 없으면 단추도 말도 없다). 배율 숫자 대신 눈금이 「이 막대가 약 200m」를 말한다(지도가 화면에 담은 모서리 좌표만으로 계산 — `map-geometry.ts`; 이 값을 못 주는 SDK 빌드에서는 눈금·칩이 빠지고 꾸며 내지 않는다).
    - **접기 · 가로 펼침**: 맨 위의 작은 탭으로 접으면 탭 하나만 남고(접은 상태는 이 브라우저가 기억), 높이가 넉넉하면 세로, 목록 창을 크게 열어 지도가 낮으면 같은 단추가 **가로 한 줄**(− 눈금 + 순서), 가로도 안 들어가면 탭만 남는다. 평소에는 지도를 가리지 않게 흐리게 숨고(2026-10-03 결정) 접은 탭만 늘 남는다.
    - **화면 밖 일정 칩(안 B)**: 지금 화면 밖(또는 위쪽 바 · 아래 시트 밑)에 있는 일정은 가장자리에 「→ 3 · 1.3km」 칩으로 서서 방향과 거리를 말한다(가까운 일정끼리는 한 칩). 누르면 그 일정이 골라지고 지도가 그곳으로 간다(배율은 그대로).
    - **첫 지도 시점(안 C)**: 날을 처음 보여 줄 때 그날 전체가 보이게 맞추고, 카메라가 멈춘 뒤 **첫 일정의 핀이 두 번 두근거린다**(번호 물방울이 부풀고 고리가 퍼짐 — 움직임 줄이기 설정이면 없음).
    - 구글·네이버는 SDK 계약 대역(`maps.spec.ts`)으로만 확인했다 — 실제 SDK 에서의 시야 값(`getBounds`)과 단추 동작은 아직 못 봤다.
10-6. **날짜 전환 · 두 손가락 확대** `[2026-10-05 사용자 요청 — 추천대로 둘 다 만듦]` (`use-day-gestures.ts`):
    - **손가락을 따라 움직임 · 함께 밀림**: 하루씩 볼 때 목록을 옆으로 끌면 목록이 손가락을 그대로 따라오고, 옆 날이 함께 밀려 들어온다(오른쪽 날 = 다음, 왼쪽 날 = 이전). 8px 넘게 옆으로 움직여야 끌기이고 위아래가 먼저면 목록 스크롤이다. 마우스 끌기도 같다(입력칸 · 시간을 잡는 곳에서 시작한 누름은 제외).
    - **기준선**: 폭의 28%를 넘게 끌면 「놓으면 2일차」 알림이 켜지고(짧은 진동), 거기서 놓으면 날이 바뀐다. 모자라게 놓으면 제자리로 돌아간다. 멈췄다 뗀 손가락은 「휙 쓸기」가 아니다(휙 쓸어야 기준선 앞에서도 넘어간다: 0.45px/ms).
    - **칩 이동**: 날짜 칩 아래의 짙은 표시가 칩 사이를 손가락과 함께 미끄러지고(날을 눌러 바꿀 때도 미끄러진다), 놓은 뒤 켜진 칩이 바뀐다. 칩 줄은 켜진 칩이 보이게 따라 움직인다.
    - **끝 고무줄**: 첫날 · 마지막 날에서 더 끌면 손가락의 30%만(최대 88px) 밀리고 「마지막 날이에요 / 첫날이에요」가 보이며, 놓으면 돌아간다.
    - **두 손가락 확대·축소**: 오므리고 벌리는 만큼 목록 글자·간격이 같이 커지고 작아진다(0.8~1.3배, 놓은 크기는 이 브라우저가 기억 — CSS `zoom` 이라 Firefox 126 미만은 크기는 안 바뀐다). 끝까지 오므리면(0.7배 이하) 전체 일정 개요로, 개요에서 크게 벌리면(1.45배 이상) 하루 보기로 부드럽게 바뀐다.
    - 시간·원(`data-grab`)에서 시작한 누름도 **옆으로** 움직이면 날 넘기기다(위아래가 먼저면 시간 끌기) — 왼쪽 끝 44px 에서 시작하는 「이전 날로 쓸기」가 막히지 않게(2026-10-06 진짜 터치 시험에서 찾음).
    - 시험: 포인터 이벤트로 흉내 낸 손가락(`day-gestures.spec.ts`)에 더해 **브라우저의 터치 입력 통로(CDP)로 보낸 손가락**(`touch-gestures.spec.ts` — 모바일 화면 설정에서 `touch-action` 처리까지 지나간다)으로 날 넘기기 · 세로 스크롤 · 두 손가락 확대 · 시간 끌기를 본다(mock 서버 시험). 실제 휴대폰의 손가락 크기·떨림·관성 스크롤·운영체제 뒤로가기 제스처는 아직 못 봤다.
11. **일정 사이 간격** `[2026-10-04 사용자 지시]`: 앞 일정과 다음 일정 사이가 **비는 시간만큼** 벌어진다. 여유 = 다음 시작 − (앞 시작 + 머무는 시간 + 이동 시간). 간격(px)은 `14 + 66(1 − e^(−여유/60))` — 여유가 없거나 모자라면 14px(모자란 만큼은 「N분 늦어요」), 30분이면 약 40px, 한 시간이면 약 56px, 2시간이면 약 71px 이고 아무리 많아도 80px 에서 멈춘다(한 일정이 화면을 밀어내지 않게). 여유가 15분 이상이면 이동 줄 밑에 「여유 1시간 42분」을 한 번 연하게 적는다. 「N시 출발」은 앞 카드에 붙여 두고 여유 글자는 따로 둔다 — 목업에서 「10:30 출발」이 9시 카드 쪽에 붙어 보였던 것은 카드 높이는 그대로 두고 빈 틈만 늘려서였고, 시간 비례로 그린 것이 아니라서다.

12. **바뀐 곳**: 자동 추천·장소 바꾸기·시간 고치기를 한 일정은 파란색으로 강조되고(「변경 완료」·「바뀜 · 이전 ○○」), 머리의 「✎ 개수」를 누르면 바뀐 것만 모아 본다. 「다시 제출」을 누르면 바뀐 일정의 확인 표시가 다시 하나씩 켜지고(재생) 강조가 풀린다.
13. **(계획 단계 — 아직 구현 안 함) 이동수단 고르기**: 이동 칸을 펼치면 맨 위에 「이동 수단」 선택박스 — 지하철·버스·택시(·걸음) 단일 후보를 보이고, 다음 일정 시작 안에 닿는 수단만 고를 수 있으며 안 닿는 수단은 「늦어요 ○분」과 함께 회색. 설계: `wiki/records/plans/2026-10-05_이동수단_선택_화면_계획서.md`. 서버 계약은 이동 세션이 확정한다.

## 4. 연결 자리 — 서버와 이어진 곳 `[2026-10-03 갱신]`

화면은 `PlanCheckActions`의 함수와 `PlanCheckView`의 칸만 본다. 함수가 없으면 단추는 남고 「준비 중」이라고 말하며, 칸이 비면 그 부분이 비어 보인다(지어내지 않음).

**서버의 확인 결과(`review`)가 있으면**(서버 [확인 화면 검사 계약](../../../wiki/external/rest-endpoints.md) — 접수 응답의 `review`, 읽는 동안은 내용 이벤트) 아래가 모두 연결된다.
변환은 [from-review.ts](src/features/plan-check/from-review.ts), 동작은 [use-server-review.ts](src/features/plan-check/use-server-review.ts), 둘을 거는 곳은 `intake-review.tsx`다.
**`review` 가 없으면**(`review: null` + `review_error`, 또는 `review` 를 모르는 옛 서버) 예전처럼 `from-intake.ts` 가 읽은 값만 말하고, 아래에서 「확인 결과가 있어야」 표시한 칸은 비거나 「준비 중」이다.

| 연결 자리 | 화면이 기대하는 것 | 서버 | 상태 |
|---|---|---|---|
| 읽기 진행 | `readingOf` ← 접수 `stage` · `sources[].lines[]` · `items[].line`, 진행 SSE `GET …/events` | 있음 | **연결함** |
| 확인 단계(장소·운영시간) | `stage: "checking"` 동안 항목·이동이 하나씩 채워짐 — 내용 이벤트 `line` · `item` · `check` · `move` · `done` 을 `reduceStream` 으로 모은 `streamingViewOf` | 있음(2026-10-03) | **연결함**(확인 결과가 있어야) |
| 결과 항목·판정 | `resultOf`(읽은 값) 또는 `reviewResultOf`(서버 `review` 의 항목 · 판정 · 검사 줄) | 있음 | **연결함** |
| 운영시간·휴무일 검사 | `PlanItem.checks` 의 `hours` · `closed` 줄 — 서버가 낸 문장 그대로 | `review.items[].rows` | **연결함**(확인 결과가 있어야) |
| 이동 | `PlanCheckView.moves` ← `review.moves`(수단 · 요약 · 경로·수단·도착 줄). 끝에 장소가 없는 구간(`waiting`)은 확인할 것이 없는 구간으로 둔다 | 있음 | **연결함**(확인 결과가 있어야) |
| 장소 바꾸기 | `replace(id, {candidate} 또는 {name})` — 후보·검색 결과는 서버가 준 좌표째 보내고(서버는 다시 찾지 않는다), 좌표가 없으면 이름으로 보낸다 | `/edits` `items[n].place` | **연결함** |
| 대체 후보 | `candidates(id)` ← `GET …/candidates`(순위 · 거리 · 기준 일정 · 검사 줄), 앞 3곳은 사진도 | 있음 | **연결함**(확인 결과가 있어야) |
| 장소 검색 | `search(id, 검색어)` ← `GET …/place-search` | 있음 | **연결함**(확인 결과가 있어야) |
| 장소 정보·사진 | `PlanCandidate.info`(분류 · 주소 · 사진). 관광공사 번호(`tour:<번호>`)가 있는 곳만 `GET /v1/web/places/photos`, 출처 「ⓒ한국관광공사」를 사진 설명에 붙이고 http·https 주소만 쓴다. 사진은 저장하지 않는다 | 있음 | **연결함**(번호가 있는 곳만) |
| 자동 추천(한 곳) | `autoRecommend(id)` — 후보 중 시간이 맞는 첫 곳을 좌표째 보낸다 | `candidates` + `/edits` | **연결함**(확인 결과가 있어야) |
| 전체 자동 추천 | `previewRecommendAll()` ← `POST …/autofix {revision, dry_run: true}`(저장 없이 바뀔 모습) → `applyRecommended()` ← `POST …/autofix {revision}`(저장) · `discardPreview()`(버리기, 서버 호출 없음) | 있음 | **연결함**(확인 결과가 있어야) `[2026-10-03]` 누르거나 목록 끝에서 한 번 더 밀면 **미리 보기만** 그리고, 「적용하기」를 눌러야 저장한다 |
| 잠금 | `lock(id, locked)` — 혼자 보낸다(다른 수정과 함께 보내면 422) | `/edits` `items[n].locked` | **연결함**(확인 결과가 있어야) |
| 되돌리기 | `undo()` — 직전 변경(삭제 · 장소 바꾸기 · 자동 추천)의 반대 수정. **전체 자동 추천은 모두 되돌릴 수 있을 때만** 되돌린다(이전 장소가 없던 곳이 있으면 되돌릴 수 없다고 말한다 — 일부만 되돌리고 「되돌렸다」 하지 않는다) | `/edits` `removed: false` · 이전 장소 | **연결함**(확인 결과가 있어야) |
| 재검증 | `recheck()` ← `POST …/revalidate`(저장 없이 판정만), 기다리는 동안 일정을 차례로 보인다. 고친 뒤에는 `dirty` | 있음 | **연결함**(확인 결과가 있어야) |
| 1순위 후보 이름 | `PlanItem.suggestion` | 후보를 불러와야 알 수 있음 | 아직 안 함(자동 추천은 누르면 첫 후보로 간다) |
| 삭제 | `remove(id)` | `/edits` `items[n].removed: true` | **연결함** |
| 직접 고치기(이름·날짜·시각·장소 없음) | `edit(id, draft)` | `/edits` `title` · `date` · `starts_at` · `ends_at` · `place {none:true}` | **연결함** |
| 여행 첫날·인원 | `editTrip(field, value)` | `/edits` `trip.first_day` · `trip.party_size` | **연결함** |
| 여행 등록 | `registration` — 서버 `review.ready` 가 켜져야 열린다 | `/confirm` | **연결함** |

낡은 판(409 `stale_revision`)으로 보낸 수정·자동 추천·재검증은 거절되고, 화면은 접수를 다시 읽는다. 고정한 일정을 바꾸려 하면 서버가 409 `item_locked` 로 거절하고 그 문장이 알림으로 뜬다.
지도는 `TripMap`(무료 OpenStreetMap + Leaflet)이다 — 구글 지도는 서버가 허락할 때만 쓴다([MAP_INTEGRATION.md](MAP_INTEGRATION.md)).
무료 지도는 칸 크기가 바뀌면(시트가 오르내릴 때) 사용자가 지도를 직접 움직이기 전까지 핀에 다시 맞춘다.
