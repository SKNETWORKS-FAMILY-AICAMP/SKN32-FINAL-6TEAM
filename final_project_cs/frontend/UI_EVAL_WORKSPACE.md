## 개발·배포 우선순위

2026-09-14 사용자 지시에 따라 **웹 1순위 → Personal Agent / MCP 2순위 → 모바일 앱 3순위**로 진행한다. 웹은 사용자 웹·필요한 관리자 웹과 PC·모바일 브라우저 대응을 포함한다. 외부 Personal Agent 접점은 웹 이후 연결하며, 웹 기능에 필요한 백엔드 Agent Runtime은 웹 개발 범위에서 함께 연결한다.

앱은 배포 시 개발자 등록 문제로 이번 초기화·개발·스토어 배포 범위에서 제외한다. 프로젝트 종료까지 적용하지 않을 가능성이 높으며 재개 여부·시점은 미정이다. 앱 전용 화면·인증·푸시·딥링크 작업은 보류하고, 기존 폴더와 기술 선택은 참고로 보존한다.

## 작업 경계

- 서비스 프론트는 로그인·여행·채팅·공유·운영 화면을 제공한다. 인증·권한·결제 확정·업무 상태 변경의 최종 판정은 백엔드가 한다.
- 개발자 콘솔은 시스템 구성·Composer·실행 추적·평가 근거를 보여준다. 기존 콘솔의 재사용·개편 범위는 구현 시 결정하며, 이번 준비에서 다른 프레임워크로 전환하지 않았다.
- 평가 프로그램은 시나리오 실행·지표 계산·회귀 검사를 수행한다. 콘솔은 평가 결과를 읽어 표시할 수 있다.
- API 응답 형식, 인증, 오류, 스트리밍 이벤트를 백엔드 담당과 맞춘다. 모의 응답과 실제 API 연동 상태를 구분한다.
- `final_project_cs`와 `final_project_ui`를 수정할 때는 해당 폴더의 `CLAUDE.md`·`RULE.md` 등 적용 규칙을 먼저 확인한다. 브랜치에 파일이 포함되어 있다는 이유만으로 백엔드 내부를 함께 재구성하지 않는다.

개인 기획 자료는 이번 작업에서 복제하지 않았다. 새 프론트의 웹 우선 방향과 기존 `role-core1`의 v11 접점 사양은 작성 시점이 다르다. 이번 변경은 프론트 개발·배포 순위를 반영하며, 기존 백엔드 계약이나 v11 사양이 변경·구현됐다는 뜻은 아니다. 새 화면을 구현할 때 필요한 API의 실제 제공 여부를 확인한다.

## 변경을 주고받는 방법

`develop`의 후속 커밋은 이 브랜치에 자동으로 반영되지 않는다. 작업 내용을 저장한 뒤 원격 변경을 가져와 확인하고, 필요한 시점에 병합하여 UI·API·평가 연결을 검증한다.

시작 브랜치가 최종 PR 대상까지 자동으로 정하지는 않는다. PR 대상은 팀이 정한 통합 브랜치를 따른다. 공유한 브랜치 이력을 임의로 강제 갱신하지 않는다.

## 준비 완료 범위

브랜치 생성과 전환, 프론트 작업 폴더, 담당·작업 경계 안내, 프론트 산출물 제외 규칙을 마련했다. 기존 백엔드·개발자 콘솔·평가 코드는 수정하지 않았다.
