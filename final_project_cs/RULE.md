# triPilot — 작업 절차

현재 사양은 wiki의 후속 확정 결정·계약이 정본입니다. 과거 계획 번호나 동결 handoff에 현재 구현을 억지로 맞추지 않습니다. 도메인 안전 규칙은 [AGENTS.md](AGENTS.md)를 따릅니다.

## 작업 순서

1. 관련 wiki 계약·코드·호출부를 읽고 문제·현재 조건·영향받는 기능·검증 방법을 정합니다. 확인하지 않은 사실은 확정하지 않습니다.
2. 공유 계약은 구현보다 먼저 wiki를 고치고 [개발 역할의 검토 절차](../wiki/delivery/roles.md)를 적용합니다. 내부 정리에 계약 버전을 임의로 올리지 않습니다.
3. 필요한 최소 변경을 구현합니다. 경로·모델·비밀값·가드레일 수치를 하드코딩하지 않고, 조용한 폴백·사용하지 않는 선행 기능을 만들지 않습니다. 기존 문서·생성물은 덮기 전에 백업합니다.
4. 변경에 맞는 계약·단위·통합·보안 시험과 관찰 가능한 로그를 확인합니다. DB·화면·모델 호출을 확인하지 않았으면 그 범위를 명시합니다. 실패·건너뜀을 분모에서 빼지 않습니다.
5. 날짜·시각·문제·수정·실행 명령·결과·남은 한계가 있는 보고서를 `wiki/records/reports/`에 추가합니다. wiki에는 결론 한 줄과 링크를 남깁니다. 결함은 검증 증거가 있을 때만 닫습니다.

## 통합 규칙

병합 전에는 아래 관문을 실행하고 결과를 기록합니다. 현재 여행 관문이며, 옛 쇼핑몰 평가 러너·데이터는 실행하지 않습니다.

```powershell
python -m scripts.verify_dod_v11
python -m pytest tests/contract -q
python -m pytest tests/security -q
```

이 명령의 이름에 v11이 있어도 현재 제품 사양 정본이 v11이라는 뜻은 아닙니다. 관문 결과와 wiki의 후속 계약을 함께 확인합니다. 기능 동결 이후에는 승인된 범위의 결함 수정을 우선합니다.

## 이력·협업·보류

- 현재 담당·공유 계약 검토는 [개발 역할](../wiki/delivery/roles.md)과 [코드 경로](wiki/teams/code-layout.md)를 따릅니다. 병렬 작업은 파일 경계를 정하고 다른 변경을 덮지 않습니다. 검수 없이 전체 변경을 커밋하지 않습니다.
- 과거 기록은 추가 기록으로 보완합니다. 현재 사양을 과거 evidence·history·동결 계획에 소급 반영하지 않습니다.
- 이번 범위에서 미루는 신규 요구는 현재 백로그에 이유·도입 조건·예상 비용·폐기 조건을 기록합니다. 관측 근거가 없는 수치를 확정 일정으로 만들지 않습니다.
- 보고할 때 문서 수정, 코드 검증, 해당 환경 반영을 나눕니다. 자동화가 만들어 낸 집계는 생성기로 갱신합니다.
